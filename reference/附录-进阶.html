卡住的时候查

A 是报错速查——先分清是谁报的错，再逐个词对照检查，最后整条读一遍； B 是 cmake 速查表——最小模板、常用命令、常用变量、命令行， 还有「课里没讲过、但以后会遇到」的那几条； C 是容器速查——六个容器各支持哪些操作、报错对照查询； D 是新特性速查——智能指针、移动、结构化绑定这批写法， 忘记写法时查阅； E 是串口速查——波特率、8N1、帧格式、CRC 参数、常见错误与伪终端用法。 平时不用读：报错了、忘了怎么写、想不起来那个名字、读代码遇见没学过的写法、 写串口程序要核对参数，查阅对应那一节。

A编译与链接报错速查

基础课那份附录的 A 节，讲的是「你在一个文件里写错了」。 这一份接着往下讲：文件多起来、又套上 cmake 之后， 屏幕上出现的信息多了好几种类型。

先看是谁报的错

0.2 讲过，从一份 .cpp 到能运行的程序，中间有四步： 预处理、编译、汇编、链接。前一步出错，后一步就无法执行， 所以屏幕上那段话是谁说的，可以直接区分：

开头长这样谁在说，说的事是什么
main.cpp:1:10: fatal error: … 编译器（前三步）。有文件名、行列号，底下还画着尖号—— 这种是你代码里写错了。需要修改的位置由尖号指出
/usr/bin/ld: … 链接器（第四步）。没有行列号，也没尖号—— 这种不是你语法写错了，而是「符号没有提供完整」。 别再回去抠代码，去看该编的文件列全了没有（1.4、1.5）
CMake Error at CMakeLists.txt:6 (message): cmake（配置那一步）。Error 头一个字母大写， 后面括号里写着「是这条命令出的事」—— 连是哪条命令都替你点出来了（2.4）
make: *** … make（编译那一步的工头）。三颗星是它的记号。 它说的往往只是「这一步没做成」，真原因在它上面几行（2.1、2.3）

一句话的判据：有行列号和尖号的，是你的代码；没有的，是「符号没有提供完整」或者「配置写错」。 这条判据能省下大量来回。

看报错的第一件事：抬头

不是先读那句话，是先看谁在说。同一个「找不到 stats.h」， 在 g++ 嘴里是 fatal error（你少写了 -I）， 在 cmake 嘴里是 CMake Error（你少写了 target_include_directories）—— 读错了人，就改错了地方。

英文词对着查

左边这一列是你在屏幕上会看到的。找到它，右边两列告诉你说的是什么事、 该回去查阅哪一课。这些报错都是这份材料里的程序实际运行得到的， 一个字母没动过。

报错里的词它在说什么你多半写了什么
fatal error: stats.h: 没有那个文件或目录 编译器说：被 #include 的那个文件，我找不着 头文件不在这儿、名字拼错、或者没告诉它去哪儿找（1.2、2.3）
In file included from main.cpp:2: 「这段内容是从 main.cpp 第 2 行的 #include 插入的」 报错出在头文件里，可源头是插入它的那一行。它甚至记录了是哪一次插入（1.2）
redefinition of ‘int twice(int)’ 「同一定义，我这里出现了两次」——编译器说的 头文件里写了函数的定义，又被插入了两次。卫士用于解决这个问题（1.2）
multiple definition of `twice(int)'; … first defined here 「两份 .o 里各带一份」——链接器说的 函数的本体写进了头文件。头文件里只放承诺，兑现放 .cpp（1.2）
undefined reference to `readScores(int)' 「有人要用它，可没人定义它」——链接器说的 少列了一个 .cpp，或者只写了声明没写定义（1.4、1.5）
collect2: error: ld returned 1 exit status 链接这一步的结束语：「它没干成，我就到这儿了」 它自己不是原因——真原因在它上面那条，从那儿读起（1.5）
CMake Error at CMakeLists.txt:6 (message): cmake 说：第 6 行那条 message 报错了 括号里已经点出是哪条命令，下面几行会说明哪一组参数不正确（2.4）
-- Configuring incomplete, errors occurred! 「配置没有完成」——cmake 结束时必定输出的一句 它上面一定有一条 CMake Error。先改那条，其他先不要处理（2.2）
Makefile:2: *** 缺失分隔符。 停止。 make 说：这一行的开头该是一个 Tab，不是空格 手写 Makefile 时的常见问题。缩进在视觉上相同，字符并不相同（2.1）
make: *** [Makefile:91：all] 错误 2 make 往上汇报的最外层那句 那个 91 是生成的 Makefile 的行号，不是你写的任何代码的行号（2.3）
The target name "报表" is reserved or not valid 「这个名字不能当 target 名」 target 名不能是中文——add_executable、add_library、 add_custom_target 都一样（2.3）
Invalid character ('�') in a variable name: '' 「变量名里有个我不认识的字」 变量名不能用中文。注意它指的是「用它」的地方， 不是 set 那一行（2.4）

注意最后那两行：它们不是编译器说的，是 cmake 说的， 所以格式和大写都对不上前面那些——这正是 A.1 那条判据的用处。

一条完整的链接报错

链接报错里最常见的一条，1.5 遇到过：两个 .cpp 只编了一个。 真原文，一个字没动： 

/usr/bin/ld: main.o: in function `main':
main.cpp:(.text+0x29): undefined reference to `readScores(int)'
/usr/bin/ld: main.cpp:(.text+0x35): undefined reference to `printReport(std::vector<int, std::allocator<int> >&)'
collect2: error: ld returned 1 exit status

从下往上阅读，比从上往下更快：

  1. 最后一行是结束语，它只说明「没有完成」。跳过它。
  2. 中间那两行才是正题。undefined reference to 后面引号里是它要找的符号——名字和参数都在里面。 两行就是两个都在找，一次给你列全。
  3. 每行前面那一段说明的是「谁在查找」。 main.cpp:(.text+0x29) 是「main.cpp 编译生成的代码里， 有一处需要使用它」；0x29 是那段代码里的位置， 每台机器都不一样，不用管。
  4. 开头 /usr/bin/ld: 说明报错的是链接器—— 你的语法一个字符都没有错，不要回头修改代码。 去看「该编译的文件都列上了吗」：手动输入的命令里是否少了一个 .cpp， 或者 CMakeLists.txt 里 add_executable 那行少没少一个名字（2.3）。

它为什么这么冗长？因为链接器执行的操作就是核对： 每个 .o 都会提供一份「需要什么、提供什么」的记录， 它逐个核对。核对不上时，它就把「谁需要什么」清楚地报告出来—— 这是所有报错里最容易阅读的一种：不进行推测，直接指出名称。

头文件包含两遍的两种错误

同一件事——「那份定义出现了两次」——会因为插入方式不同， 由不同的阶段报告出来。1.2 两种都遇到过：

第一种：同一个 .cpp 里插入了两次。 两次都在同一份要编译的文件里，编译器自己就能看出来： 

In file included from main.cpp:2:
util.h:1:5: error: redefinition of ‘int twice(int)’
    1 | int twice(int x) {
      |     ^~~~~
In file included from main.cpp:1:
util.h:1:5: note: ‘int twice(int)’ previously defined here
    1 | int twice(int x) {
      |     ^~~~~

第二种：两个 .cpp 里各包含了一遍。 各自包含，都没有重复；要等到链接那一步， 两份 .o 放在一起时，问题才暴露： 

/usr/bin/ld: other.o: in function `twice(int)':
other.cpp:(.text+0x0): multiple definition of `twice(int)'; main.o:main.cpp:(.text+0x0): first defined here
collect2: error: ld returned 1 exit status

两种错，一个词之差，识别时有一个简单的方法：看有没有尖号。 有尖号、有行列号的，是编译器在同一个文件里发现的（redefinition）； 只有 /usr/bin/ld: 打头的，是链接器在最后一步核对出来的 （multiple definition）。

所以头文件里到底能放什么

放承诺：函数的声明、类的定义、常量的声明—— 「存在这样一个声明，形式如下」。 不放兑现：函数体、全局变量的定义—— 「它是这样实现、它是这个值」。 声明包含几遍仍然是同一个声明，定义包含两遍就成了两份，链接时一定报错。

经过 cmake 之后，报错形式发生变化

错误本身没变，变化的是它外围的几层信息。 同一条「找不到头文件」，手动输入 g++ 的时候只有一句， 走 cmake 之后前面多一行、后面多三行： 

[ 33%] Building CXX object CMakeFiles/report.dir/main.cpp.o
main.cpp:1:10: fatal error: stats.h: 没有那个文件或目录
    1 | #include "stats.h"
      |          ^~~~~~~~~
compilation terminated.
make[2]: *** [CMakeFiles/report.dir/build.make:79：CMakeFiles/report.dir/main.cpp.o] 错误 1
make[1]: *** [CMakeFiles/Makefile2:87：CMakeFiles/report.dir/all] 错误 2
make: *** [Makefile:91：all] 错误 2

需要直接认出中间那几行没有变化——文件名、行列号、尖号，和你自己输入时完全相同。 剩下的都是新增加的外层信息：

这一层它在说什么
[ 33%] Building CXX object … make 报「我正在做哪一步」。它是 g++ 那句话前面的「我开始了」—— 别把它当报错
make[2]: *** … 错误 1 最深的一层，说的才是真事：编 main.cpp.o 这一步没做成
make[1]: *** … 错误 2 往上一级：「那个目标没做成」
make: *** [Makefile:91：all] 错误 2 最外层：「我这一步没干成」。那个 91 是生成的 Makefile 的行号， 不是你写的任何一份文件的行号——别去自己的文件里找第 91 行

读法反过来：从最深那层往上看。 make[2] 那句点名了是哪个 .o； 再往上两行就是编译器原话。上面那几层只是「没做成」逐层向上报告了三遍。

另一类是新出现的：cmake 自己说的话，前面 A.1 那张表里有两句 （target 名、变量名）。它们的格式和编译器完全不同—— CMake Error at 打头、括号里带命令名， 而且经常错在两处之外的地方：比如中文变量名，报的是「用它」的第 6 行， 不是「写它」的第 5 行（2.4）。

配置没成，就别急着 make

cmake 那一步没有完成（屏幕上最后一句是 -- Configuring incomplete, errors occurred!）， build/ 里就没有可用的 Makefile。 这时运行 make，它会返回一句 make: *** 没有指明目标并且找不到 makefile。 停止。—— 这句话和你的代码一点关系都没有，它只是说明「还没有配置」。 回去把上面那条 CMake Error 改掉，重新 cmake ..。

查不到，怎么办

按这个顺序来，四步：

  1. 先看是谁报的错。编译器、链接器、cmake、make， 四者报错的样式各不相同（A.1）。这一步看错，后面都会跟着出错。
  2. 再找「名字」。引号、尖引号包起来的那几组， 都来自你自己的代码——变量名、函数名、文件名、target 名。 返回去找到它，答案通常就在那里。
  3. 只读最上面那一条。底下的多半是它连带的。 改完再运行一遍，剩下几条常常自然消失—— 基础课那份附录里也是这么说的，这一条在文件多起来之后更有效。
  4. 还不明白，就用基础课 7.1 那套：把程序缩减到最小。 多文件工程里缩减的方法是「把 add_executable 那行只留一个 .cpp，把别的先注释掉」——缩减到报错只剩一条，问题就会暴露出来。

最后一句和基础课那份一样：无法理解的报错，先原样保留，不要急于随意修改。 有了 build/ 之后尤其要忍住一件事—— 别靠 rm -rf build 来「重新开始」。 那会把 cmake 记着的设置一起删掉，症状换了，线索也断了。 真要从头配，先看看 CMakeCache.txt 里那些设置是不是你要的。

Bcmake 速查表

这张表是当字典查的，不是用来读的。 课里讲过的（2.2–2.5），这儿只留一句；课里没讲的， 末了标一个「附录」，是这一节实际运行过一遍、确认了效果的。 两边都只写到「长什么样、干什么用」，真要展开，回课里那一节。

写法那栏里，名字、demo、main.cpp 这些是占位符，换成你自己的。

最小模板

一个程序，一个文件（2.2 那份，四行）： 

cmake_minimum_required(VERSION 3.16)
project(demo LANGUAGES CXX)
set(CMAKE_CXX_STANDARD 17)
add_executable(demo main.cpp)

一个程序，几个文件，头文件在子目录（2.3 那份，多了最后两行）： 

cmake_minimum_required(VERSION 3.16)
project(统计表 LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)

add_executable(report main.cpp stats.cpp)

target_include_directories(report PRIVATE include)

再往下，把一部分代码做成库、放进子目录（2.4 那份， 子目录里另有一份 CMakeLists.txt 写 add_library）： 

cmake_minimum_required(VERSION 3.16)
project(命令桌 VERSION 1.2.0 LANGUAGES CXX)

add_subdirectory(工具库)

add_executable(desk main.cpp)
target_link_libraries(desk PRIVATE tools)

三份模板的骨架是一样的：头两行、语言标准、然后「编什么」。 多文件是往「编什么」那行加名字，加头文件目录是加一行， 拆成库是再创建一个目录、写一份——工程就是这样逐步扩展的。

常用命令

命令作用
cmake_minimum_required(VERSION 3.16) 第一行，写「至少要多新的 cmake」。数字不能乱写老—— 比 3.5 小，现在直接报错（2.2）
project(名字 VERSION 1.2.0 LANGUAGES CXX) 工程名、版本号、什么语言。名字可以是中文（它只是个标签）； 版本号后面 configure_file 要用（2.2、2.4）
set(名字 值) 定义一个名字并保存值，使用时写 ${名字}。 名字只能是 ASCII，值可以是任意内容（2.4）
message(STATUS "…") 配置的时候输出一句。STATUS 那一档前面会加 --（2.4）
option(名字 "说明" ON) 一个开关，第二个位置是默认值。配置的时候可以用 -D名字=OFF 改（2.4）
if(名字) … else() … endif() 配置的时候按条件走。认的是变量的名字，写成 if(${名字}) 在某些情况下会读歪（2.4）
add_executable(目标 源文件…) 编一个可执行文件。源文件全列在这行，头文件不列。 目标名只能 ASCII（2.2、2.3）
add_library(库名 STATIC 源文件…) 把几个 .o 打成一个静态库， 就是 lib库名.a（2.4）
target_include_directories(目标 PRIVATE 目录) 告诉这个目标「头文件去哪儿找」。 PUBLIC 是「用我这个库的人也得去那儿找」（2.3、2.4）
target_link_libraries(目标 PRIVATE 库…) 链接的时候链谁。库可以是子目录建的，也可以是 Threads::Threads 这种找来的（2.4）
add_subdirectory(目录) 把子目录那份 CMakeLists.txt 也拉进来一起配（2.4）
add_compile_options(-Wall) 给这个目录底下所有编译命令加参数。它只认它下面写的 target， 放在 add_subdirectory 后面就管不着子目录（2.4）
find_package(Threads REQUIRED) 在本机查找现成的库，找到后会提供一个 Threads::Threads 这样的名字拿来链（2.4）
configure_file(模板 生成到哪儿 @ONLY) 拿模板生成一个文件，@名字@ 会被换成变量值。 生成的通常在 build/ 里，不是源码目录（2.4）
install(TARGETS 目标 DESTINATION bin) 说明「安装到其他目录」时复制哪些文件、复制到哪个子目录（2.4）
target_sources(目标 PRIVATE 源文件…) 附录。给已经建好的目标补源文件。 add_executable 那行太长时的另一种写法
target_compile_definitions(目标 PRIVATE 名字=值) 附录。给这个目标加 -D 宏， 等于在代码里替它 #define。 值可以是中文，运行得到的程序照常输出中文
file(GLOB 变量 通配符) 附录。按通配符收集一批文件，存入变量。 得到的是绝对路径。cmake 自己的说明书上写着 「不推荐拿 GLOB 去收集源文件列表」——新加了文件它不会知道， 因为它只看 CMakeLists.txt 变没变
aux_source_directory(目录 变量) 附录。把那个目录里所有源文件的名字收进变量（像 ./main.cpp 这样）。和 GLOB 同一个毛病： 新加的文件它不知道
include_directories(目录) 附录。给这个目录底下所有目标加头文件目录。 老写法——cmake 自己的说明书上写着「请改用 target_include_directories()」
link_directories(目录) 附录。加一个「去哪儿找库」的目录。 说明书上的原话是「这条命令很少有必要，能避开就避开」
find_library(变量 库名) 附录。去本机找一个库文件，找到就把 完整路径存进变量。试出来的是 /usr/lib/x86_64-linux-gnu/libm.so 这种
find_path(变量 头文件名) 附录。去本机找一个头文件搁在哪个目录， 试出来的是 /usr/include 这种
add_custom_command(OUTPUT… COMMAND…) 附录。自己定一条「生成某个文件」的命令。 和下面那条成对用：一个说「怎么生成」，一个说「它是个目标」
add_custom_target(名字 DEPENDS 文件) 附录。把那件自己定的事做成一个目标。 名字也只能是 ASCII——写成中文，报的错和 add_executable 那条一模一样
add_dependencies(目标 另一个目标) 附录。让前者等后者做完再编。 典型用法：编程序之前，先等着「生成头文件」那件事做完

常用变量

它们不用你声明，cmake 配的时候就填好了。右边那列是这份材料里真见过的样子。

变量是什么
PROJECT_NAME / PROJECT_VERSION project() 里写的名字和版本号。 版本号写 1.2.0，@PROJECT_VERSION@ 换出来就是 1.2.0（2.4）
CMAKE_CXX_STANDARD 用哪版 C++。写 17，编译器那行上是 -std=gnu++17—— 多出来的 gnu 是「带 GNU 扩展」的意思（2.2）
CMAKE_CXX_EXTENSIONS 写成 OFF，上面那个就变成 -std=c++17，一点扩展都不带。 课程里的代码不用它，写出来是因为你在别处会看见（2.2）
CMAKE_CURRENT_SOURCE_DIR 正在配的这份 CMakeLists.txt 所在的源码目录（2.4）
CMAKE_CURRENT_BINARY_DIR 对应的 build/ 里的那个目录。 configure_file 生成的文件十有八九搁在这儿（2.4）
PROJECT_SOURCE_DIR / PROJECT_BINARY_DIR 本工程的源码目录／构建目录。和上面那两个的区别： 子目录里配的时候，这两个还是最外层那个（2.5 那份真实文件里出现过）
CMAKE_BUILD_TYPE 配置的时候给：不设，编译器参数是空的； Debug 给 -g； Release 给 -O3 -DNDEBUG。 三个都是实际运行得到的
CMAKE_CXX_FLAGS 「最后都会加上的那串参数」。编译目标的时候， cmake 会把标准、编译选项那些合起来写进 flags.make 里的一行（2.2、2.4）
CMAKE_INSTALL_PREFIX 安装到哪个目录。cmake --install . --prefix 路径 能把这一次的改掉（2.4）
Threads_FOUND / CMAKE_THREAD_LIBS_INIT find_package(Threads) 找完之后填的： 是否找到、是否需要额外链接。这台机器上后者是空的—— 因为线程相关的实现就在标准库中，不用额外链（2.4）

命令行

命令作用
cmake --version 查看安装的是哪一版。这份材料里运行得到的是 cmake version 4.1.2（0.1 让学生逐个查过）
mkdir -p build → cd build → cmake .. 配置：在源码目录旁边创建一个 build/， 进入之后把生成的文件都放在这里（2.2）
cmake .. -D名字=值 配置的时候就给一个值，比如 -DEXTRA_LINE=OFF。 值变了要重新配，不用删 build/（2.4）

cmake --build build 不用切换目录就能编译，和进入目录运行 make 效果相同
cmake --install . --prefix 路径 按 install() 说的那些，复制到你指定的位置（2.4）

C容器速查

第 3 部分那六种容器，名字、功能、性质各不相同，放在一起容易忘。 这一节按「你想做的操作」查：忘了哪个操作叫什么，查阅对应那一小节。

六个容器速览

一共两栏要先记住：它是什么、要 #include 哪个头文件。 漏掉那句 #include，编译器会说 ‘vector’ is not a member of ‘std’——不是你没写对名字， 是没告诉它上哪儿找。

写的要 include它是什么、什么时候用（在哪一课）
std::vector<int> <vector> 连续排列的一块内存，按「第几个」取。顺序就是你放进去的顺序，重复的也留着（3.1）
std::string <string> 一组字符，专门存放文本。可以连接、比较、截取一段（3.2）
std::map<K, V> <map> 一张表：给一个键，得到一个值。键不重复、自动排好（3.4）
std::set<T> <set> 只有键的 map：不重复、自动排好。只问「有没有」（3.5）
std::queue<T> <queue> 队：先进先出。按来的先后办事（3.5）
std::stack<T> <stack> 栈：后进先出。最近的先办（3.5）

有三件事六个容器都会，名字还都一样，先记这一组：

想做的操作怎么写
有几样 v.size()——六个都有
空没空 v.empty()——六个都有。 size() == 0 也是一个意思，但 empty() 更顺眼
全倒掉 v.clear()——vector、string、map、set 有； queue、stack 没有（它们只能一个一个 pop 掉）
size() 返回的数，跟 int 不是同一种

它是「不带符号」的数。用它和 int 比较大小 （for (int i = 0; i < v.size(); i++) 那种）， 会产生一条 -Wsign-compare 警告。

看见警告就加 int()：int(line.size()) - 1—— 3.2 和 3-5 那两处都是这么处理的。

每个容器会哪些动作

下面六小块，一块一个容器。斜体那几句是「不返回元素」或者「会创建元素」的易错点， 其余都是直接用法。

std::vector（3.1）

想做的操作怎么写
创建一个空的std::vector<int> v;
创建 N 个元素std::vector<int> v(N);——圆括号是「要几个」
一次给几个数std::vector<int> v = {90, 85};
后面加一个v.push_back(90);
取第 i 个v[i]——下标从 0 数
改第 i 个v[i] = 90;
删除最后一个v.pop_back();——不返回元素
逐个遍历for (int x : v)（副本，只读）／ for (int& x : v)（原对象，可修改）
声明二维表std::vector<std::vector<int>> grid; ——外层存放行、内层存放该行的元素；每行可以有长有短（3.1）
取得一行／取得一个元素grid[i] 是第 i 行，它自己还能 .size()；grid[i][j] 是第 i 行第 j 列 ——先选择行，再选择该行中的第几个元素
逐行添加内层 push_back 填满一行，再把整行 push_back 到外层——外层仍为空的时候， grid[i] 取不到元素

std::string（3.2）

想做的操作怎么写
创建一个std::string s = "abc";
后面接一段s = s + "def"; 或 s += "def"; ——加号两边至少要有一个是 std::string
有几个字节s.size()——中文一个字三个字节
取第 i 个字节s[i]——拿出来是一个 char
判断是否相等a == b——比较的是其中存放的那串字符，不是地址
比先后a < b——一个字节一个字节比
读一整行std::getline(std::cin, s); ——前面刚用过 >> 的话，先 std::cin.ignore();
查找一段字符串的位置s.find("score=")——返回的是位置； 找不到是 std::string::npos
截取一段s.substr(2)（从 2 到最后）／ s.substr(0, 2)（从 0 起两个）
逐个字符遍历for (char c : s)

std::map（3.4）

想做的操作怎么写
开一张空表std::map<std::string, int> m;
放一个／改一个m["apple"] = 3;——本来没有就新建，本来有就改掉
取一个m["apple"]——没有这个键的话，它会立即创建一个
在不在m.count("apple")——1 就是有，0 就是没有。 问在不在只用这个，别用中括号
有几个键m.size()
删除一个m.erase("apple");
遍历for (const auto& kv : m)—— kv.first 是键（改不了），kv.second 是值（能改）
数数m[w]++;——没有就先建一个（值 0）再加一， 这是利用中括号创建元素这一特性的地方

std::set（3.5）

想做的操作怎么写
创建一个std::set<int> s;
插入一个s.insert(5);——如果已经存在就不插入 （所以插入后 size() 不一定变大）
在不在s.count(5)——1 或 0
有几个s.size()
删除一个s.erase(5);
遍历for (int x : s)／for (const std::string& w : s) ——出来的是排好的

std::queue（3.5）

想做的操作怎么写
创建一个std::queue<std::string> q;
排到队尾q.push("小明");
查看队头q.front()——只查看，不取出
弹出队头q.pop();——只删除，不返回值
按顺序遍历while (!q.empty()) { ...q.front()...; q.pop(); }

std::stack（3.5）

想做的操作怎么写
创建一个std::stack<std::string> st;
放入栈顶st.push("主页");
查看栈顶st.top()——front() 在这儿叫 top()， 只有这一处名称不同
弹出栈顶st.pop();——同样不返回值
反向遍历while (!st.empty()) { ...st.top()...; st.pop(); }

两个值组合：pair

std::pair 是最小的容器：不多不少正好两个。 遍历 map 时得到的每一项，都是这种类型。

想做的操作怎么写
要 include 什么<utility>—— 遍历 map 的时候不需要处理，那种 pair 是 map 自己带的
创建一个std::pair<std::string, int> p("apple", 3); ——尖括号里两个类型，圆括号里两个值，按位置对应
另一种写法std::pair<std::string, int> q = {"banana", 5}; ——含义相同，大括号写法更短
取第一个p.first
取第二个p.second
改p.first = "pear";——两个位置都能改（map 里那个键不能）

选择哪一个：四句话

不是记住各个容器，而是问自己四个问题（3.6 那四句）：

问自己回答后即可确定
按「第几个」取得，还是按名称取得？第几个 → vector；按名字 → map
同一个值会出现两次吗？要保留每一次出现 → vector；只要「有哪几种」 → set
是否需要自动排序？要 → map、set；不要 → vector（插入顺序就是存放顺序）
先到的先处理，还是最近的先处理？先到的先处理 → queue；最近的先处理 → stack

最容易混淆的三组：

分不清的问自己一句
vector 还是 set 重复的要不要留着？要 → vector；只想知道有哪些 → set
map 还是 set 是否需要为每个键关联一个值？需要 → map；不需要 → set
queue 还是 stack 先到的先处理，还是最近的先处理？先到的先处理 → queue；最近的先处理 → stack

拿不准就先用 vector——它最直接， 其他几种容器支持的操作它都支持，只是要自己多写几行。 写到后来发现「我在反复查找某个元素是否存在」， 那就是该换 set 或者 map 的判断依据了。

容器上常见的报错

报错里的词它在说什么你多半写了什么
passing ‘const std::vector<int>’ as ‘this’ argument discards qualifiers 「你传入的这个 this 是只读的，可这个方法要修改它」 在一个 const 的参数／对象上动了手：push_back、 drain、kv.first.clear() 都是这句（3.3、3.4）
passing ‘const Battery’ as ‘this’ argument discards qualifiers 同上，只是这回的只读对象是你自己定义的类 拿 const 的对象叫了一个没写 const 的成员函数——报错底下那条 note 会把它指给你（3.3）
assignment of read-only variable ‘N’ 「往一个只读的变量里赋值」 给一个 const 的变量重新赋值。跟上一句是同一件事， 只是上一句说的是引用、这句说的是变量（3.3）
void value not ignored as it ought to be 「一个 void 类型的值本应被忽略，却在这里被使用」 int x = q.pop();——pop() 只删除元素、 不返回元素。先用 front()／top() 取得元素再 pop（3.5）
invalid operands of types ‘const char [4]’ and ‘const char [4]’ to binary ‘operator+’ 「两个 const char 数组不能相加」 "abc" + "def"——两个双引号不能直接加。 加号两边至少要有一个是 std::string（3.2）
warning: comparison of integer expressions of different signedness 「这两种数不是同一种，无法保证比较结果」——这是警告，不是错误 把 int 和 size() 混合比较。 加 int()：int(line.size()) - 1（3.2、3-5）

还没教的，先作初步认识

真实代码里还会遇到下面这些。这一部分没教，大多在第 4 部分讲—— 列在这儿不是让你现在用，是让你遇见的时候知道 「这是尚未学到的内容」，而不是「我遗漏了学习内容」。

会遇到的它是什么
v.begin()、v.end() 表示「某一个位置」的对象，叫迭代器。 3.6 说过：想删中间那个、想往中间插一个，都得先有它。 第 4 部分专门讲
std::sort(v.begin(), v.end()) 把一组元素排好。vector 自己不会排，需要调用它， 还要 #include <algorithm>
m.find(k) map 的另一种「查在不在」。这一部分一律用 count， 因为 find 要用它返回的值与 m.end() 比较—— end() 是什么，第 4 部分讲
std::unordered_map、std::unordered_set 也是表、也是集合，只是不排序。 代价和优点，第 4 部分那个「快慢」的话题里一并说
std::list、std::deque 另外两种顺序容器。名字认得就行，这一门课用不到它们

容器的事，C 里齐了。 C 里查不到的，多半是上面那张「先认识一下」——那些在后面的课里。

D新特性速查

这一节收的是一批新写法：这些年陆续添进 C++ 的， 真实工程里到处都是，这门课大多在第 5 部分讲过了 （5.4、 5.5）。 列在这儿当速查。

智能指针

先看它能办什么事：「这个对象不用了，谁负责销毁」。 容器里的元素不需要你管理——std::vector<std::string> 存放的那几个字符串，由容器自己销毁。可真实代码里还有另一种对象： 用 new 创建出来的（5.1、5.2 讲），创建它、销毁它都得有人管理。 智能指针把这份责任写进了类型里：它一消失， 对象跟着销毁，不用谁记着写 delete。

会遇到的它在办什么事
std::unique_ptr<Counter>
std::make_unique<Counter>(...)		 独占：这个对象只有一个持有者。 持有者不能复制给其他对象，只能移动； 持有者销毁后，对象随之销毁
std::shared_ptr<Counter>
std::make_shared<Counter>(...)		 共用：可以有多个持有者，每增加一个引用计数加一； 最后一个持有者销毁后，对象才销毁
std::weak_ptr<Counter> 「只观察，不持有一份」——用来查询「那个对象是否仍然存在」。 使用场合较少，作初步认识即可

两个 make_ 开头的是「直接创建一个对象，交给智能指针管理」的 简写，比先创建再包装一层更简洁，也更不容易写错。 头文件是 <memory>。怎么用、什么时候选哪一种， 第 5 部分讲过了 （5.4）。

移动与就地构造

3.1 里说过：往容器里添加元素，常常是复制一份进去的。 下面这两条针对的是「能不复制就不复制」——对象仍然是同一个对象， 只是转移了存放位置。

会遇到的它在办什么事
v2 = std::move(v1); 移动：v1 里的元素整批转移进 v2， 不复制第二份；v1 随之变空。 「副本」的反面就是它
v.emplace_back(90); 在末尾直接创建一个，结果跟 v.push_back(90) 一样。对象复杂时，它省掉一次「先创建、再复制进去」

std::move 这个名字容易引起误解：它本身不移动， 只是把「这一份可以移动」告知编译器——真正执行移动的是构造过程。 头文件是 <utility>；emplace_back 不用另加头文件，它就在 <vector> 里。 这两条第 5 部分也讲过了 （5.5）。

简洁的写法

下面两条不改变程序干什么，只改变写在纸上的样子—— 同一个意思，另一种写法。

会遇到的它是什么
for (const auto& [k, v] : m) 结构化绑定：3.4 里遍历 map 要写 kv.first、kv.second； 这种写法直接定义两个名称——k 是键、 v 是值。遍历存放 pair 的 vector 也同样适用
Counter* p = nullptr; 空指针：这个写法基础课 6.3 教过。真实代码里还会遇见 老的两种写法——NULL 和 0， 跟 nullptr 是一个意思，见到就知道是空的

结构化绑定是写法，不用加头文件；auto 前面那个 & 和 3.1 的副本、原对象是同一件事—— 加 & 是为了不复制那一份。

std::array

定长的数组——基础课 4.1 那个数组，加上容器那一套功能。 元素个数从头到尾固定，数量固定不变；但它和 vector 一样 知道自己有几个、能遍历、能整个复制给别人。 元素个数写代码的时候就定下来、又想要容器那些操作的地方， 真实工程会用它。

会遇到的它是什么
std::array<int, 3> a = {1, 2, 3}; 三个数，数量固定。尖括号里第二个数是「几个」—— 在 vector 那儿这个数写在圆括号里（(3)），别写混
a.size()、a[i]、 for (int x : a) 跟 vector 一个样子——这一行的动作，照 vector 那套理解就行

头文件是 <array>。这门课不专门讲它， 第 5 部分 5.5.5 已经介绍过，了解即可。

8N1 要设的项

8N1 指 8 位数据位、无校验位（none）、1 位停止位。 整套设置写在 struct termios 里，最后用 tcsetattr(fd, TCSANOW, &t) 生效。逐项对照：

VMIN 与 VTIME 放在 t.c_cc 数组里， 决定 read 何时返回。常用组合：

设置read 的行为
VMIN = 1、VTIME = 0 至少读到 1 个字节才返回；没有数据就一直等
VMIN = 0、VTIME = 10 最多等 10 × 0.1 = 1 秒；有数据就返回，超时返回 0
VMIN = n、VTIME = 0 一直等到读满 n 个字节

设置完成后，可以在终端里用 stty -F /dev/ttyUSB0 -a 查看同一个设备的当前设置，与程序读回的值对照。

帧格式

帧（frame）是一段字段固定的字节。本课用的格式如下， 所有多字节字段低字节在前（小端）：

偏移字段长度说明
0SOF1 帧头，固定为 0xA5
1data_length2 只数 data 段的字节数，不含命令码与两段 CRC
3seq1 帧序号
4CRC81 校验第 0 字节到第 3 字节
5cmd_id2 命令码
7datadata_length 数据段，长度可以为 0
7 + data_lengthCRC162 校验第 0 字节到 data 段末尾

整帧长度 = data_length + 9。 一帧完整的例子： 

A5 02 00 00 8C 01 00 12 34 D9 34

这一帧 data_length = 0x0002，seq = 0， CRC8 = 0x8C，cmd_id = 0x0001， data = 12 34；帧尾两字节 D9 34， 即 CRC16 的值 0x34D9，低字节在前。

串口按 8 位数据位、1 位停止位、无校验位、无硬件流控工作。 本课例题的命令码 0x0001、0x0002、0x0003 是课程自编的示例，不对应任何官方业务命令。

CRC8 与 CRC16

CRC8CRC16
多项式 x^8 + x^5 + x^4 + 1，反射写法 0x8C 反射多项式 0x8408
初值 0xFF 0xFFFF
校验范围 帧的第 0 字节到第 3 字节 帧的第 0 字节到 data 段末尾，不含帧尾两字节
标准算例 "123456789" 得 0x0B "123456789" 得 0x6F91
上例帧上的值 0x8C 0x34D9，帧尾写 D9 34

两个算法结构相同：每处理一个字节，先与校验值异或，再重复 8 次—— 最低位为 1 就右移一位后异或多项式，最低位为 0 就只右移。 CRC16 的结果占两个字节，低字节在前。 校验不过的帧整帧丢弃，不交给后续处理。

常见错误与处置

打开或读写串口失败时，程序里的 errno 是判断依据。 下面是这些错误在 C 语言库里的原文：

错误含义处置
No such file or directory
（ENOENT）		 设备文件不存在 板子没有插好，或者设备名不对。先确认 /dev/ttyUSB0、/dev/ttyACM0 中哪一个存在； 伪终端要使用 /dev/pts/ 下的路径
Permission denied
（EACCES）		 当前用户没有打开这个设备的权限 查看设备文件的属主与权限；串口设备通常属于 dialout 组
Device or resource busy
（EBUSY）		 设备已经被另一个程序打开 关掉占用的程序，例如串口终端或另一个调试进程，再重新运行
Input/output error
（EIO）		 打开成功，读写时出错 USB 转串口设备被拔出，或者伪终端的主端已经关闭； 重新连接后再试
Interrupted system call
（EINTR）		 系统调用被信号打断，这一次没有读走或写走数据 重新执行一次 read 或 write， 不算真正的失败

终端的工具软件在中文界面下会把这些句子译成中文，措辞可能不同； 判断时看 errno 的宏，不要按整句文字匹配。 程序自己的提示建议写成固定的中文，例如「打开失败」加设备路径， 不要直接把 strerror 的整句拼进输出，换一台机器输出就可能变。

伪终端与模拟板怎么用

没有板子时，用伪终端（pseudo terminal，简称 pty）练习。 一段程序调用 posix_openpt 创建主端， 再用 grantpt、unlockpt 与 ptsname 取得从端路径，然后按普通设备文件 open 从端。两端之间传递的字节与串口一致； 从端路径形如 /dev/pts/3，每次运行都可能不同。

第 7 部分配套的模拟板是 fake_board.py，用 Python 标准库 pty 创建伪终端，扮演串口的另一端。两种用法： 

python3 fake_board.py
python3 fake_board.py --run ./demo

第一种是手动模式：模拟板打印从端路径，最多等待 60 秒； 在另一个终端里用这个路径运行 C++ 程序。 第二种是自动模式：模拟板启动 ./demo，把从端路径作为参数 交给它，校验请求的两段 CRC，把应答分成 3 字节与 8 字节两批写出， 最后检查程序是否以退出码 0 结束。成功时模拟板自己不打印内容。

伪终端只传递字节：它接受波特率设置并返回成功，但不按对应的速率限制发送， 也不模拟校验位与电气信号。收发流程、组帧、CRC、半包处理与超时分支 可以在电脑上验证；真实波特率下的时序与电气层的连接质量， 要接上板子才能确认。伪终端是 Linux 的功能， Windows 上的 COM 口使用另一套 API。
