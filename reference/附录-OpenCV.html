B常见错误

每条按“现象、原因、处理”排列。现象只摘录关键一行，省略编译器的安装路径； 处理给最小复现或判断方法。命令都在 示例代码 目录下执行， 素材路径以该目录为基准。

编译与链接

1. 找不到 OpenCV 头文件

现象

fatal error: opencv2/core.hpp: No such file or directory

原因：编译命令没有给出 OpenCV 头文件目录。系统包通常安装在 /usr/include/opencv4，源码安装通常在 /usr/local/include/opencv4，两者都不在编译器默认搜索路径中。

处理：用 pkg-config --cflags opencv4 取得 -I 参数，并把它放进编译命令。最小复现：对任意包含 #include <opencv2/core.hpp> 的源文件执行 g++ -std=c++17 main.cpp -o main，出现同一错误；加上 $(pkg-config --cflags opencv4) 后错误消失。

2. 链接时 undefined reference

现象

/usr/bin/ld: x.cpp:(.text+0x2a): undefined reference to `cv::imread(std::string const&, int)'
collect2: error: ld returned 1 exit status

原因：编译命令只加了 --cflags，没有加 --libs； 或者库参数写在源文件前面。链接器从左到右扫描，库出现在未定义符号之前时， 该符号不会被记录。

处理：把 $(pkg-config --cflags --libs opencv4) 放在命令 末尾。最小复现：先执行 g++ -std=c++17 main.cpp -o main $(pkg-config --cflags --libs opencv4)， 再执行 g++ -std=c++17 $(pkg-config --cflags --libs opencv4) main.cpp -o main， 前者成功、后者报同一错误。统一写法见 0.2。

3. cannot find -lopencv_world

现象

/usr/bin/ld: cannot find -lopencv_world

原因：编译命令手写了库名。opencv_world 只在部分构建中 存在；Ubuntu 的模块化安装把它拆成 opencv_core、 opencv_imgproc 等若干个库。

处理：不手写 -l 参数，改用 pkg-config --libs opencv4 的输出。判断方法：该命令列出的库名 与已安装的库一致，直接把它们放进编译命令即可。

Mat 与内存

4. imread 返回空图，后续处理或显示报错

现象

error: (-215:Assertion failed) !_src.empty() in function 'cvtColor'
error: (-215:Assertion failed) size.width>0 && size.height>0 in function 'imshow'

原因：路径错误、工作目录不对、文件不存在或解码失败。imread 不抛异常，失败时返回空 Mat；空 Mat 进入 cvtColor 或 imshow 才触发断言。

处理：读入后立即检查 image.empty()，并打印实际路径。 从 示例代码 目录运行，素材使用 ../素材/...。 最小复现： 

cv::Mat image = cv::imread("missing.png");
cv::Mat gray;
cv::cvtColor(image, gray, cv::COLOR_BGR2GRAY);

5. ROI 越界

现象

error: (-215:Assertion failed) 0 <= roi.x && 0 <= roi.width && roi.x + roi.width <= m.cols && 0 <= roi.y && 0 <= roi.height && roi.y + roi.height <= m.rows in function 'Mat'

原因：Rect(x, y, w, h) 超出源图边界，即 x+w > cols 或 y+h > rows。

处理：取 ROI 前检查四个边界，或用 rect & cv::Rect(0, 0, src.cols, src.rows) 求交集。 最小复现：在 640×480 的图上取 Rect(600, 400, 100, 100)。

6. at<T> 的元素类型不匹配

现象：程序不报错，读出的像素值与预期不符；三通道图用 at<uchar> 只读到第一个通道。

原因：at<T> 的 T 必须与矩阵的元素类型 一致。CV_8UC3 的元素是 cv::Vec3b， CV_8UC1 的元素是 uchar。

处理：先打印 image.type() 与 channels()； 三通道用 at<cv::Vec3b>(r, c) 取元素，再用 [0]、[1]、[2] 访问 B、G、R 分量；灰度用 at<uchar>(r, c)。判断方法：遍历一行， 比较读出的值与 imwrite 后重新读入的值。

7. 浅拷贝或 ROI 修改了原图

现象：修改 roi 或赋值得到的矩阵后，原图的像素也改变。

原因：cv::Mat b = a 只复制矩阵头，两个对象共享同一块 像素；a(rect) 返回的是原图的视图，不是独立副本。

处理：需要独立副本时用 a.clone() 或 a.copyTo(b)；只读访问用 const cv::Mat&。 判断方法：比较 a.data == b.data，相等即为共享。

图像处理与轮廓

8. findContours 的输入不是单通道

现象

error: (-210:Unsupported format or combination of formats) [Start]FindContours supports only CV_8UC1 images when mode != CV_RETR_FLOODFILL otherwise supports CV_32SC1 images only in function 'cvStartFindContours_Impl'

原因：传入的是 BGR 三通道图或浮点图；findContours 要求 8 位单通道二值图。

处理：先 cvtColor(..., COLOR_BGR2GRAY)，再用 threshold 或 inRange 得到 CV_8UC1。 判断方法：mask.type() == CV_8UC1。最小复现：把 CV_8UC3 矩阵直接传给 findContours。

9. 掩码与图像尺寸不一致

现象

error: (-215:Assertion failed) (mtype == CV_8U || mtype == CV_8S) && _mask.sameSize(*psrc1) in function 'binary_op'

原因：掩码在缩小图上生成，或图像经过 resize 后掩码没有 同步缩放；bitwise_and 等按位运算要求掩码与输入同尺寸。

处理：让掩码与输入保持相同的 rows 与 cols； 在缩略图上检测时，用 resize(mask, mask, src.size(), 0, 0, INTER_NEAREST) 把掩码放回原尺寸，或按比例换算轮廓坐标。判断方法： mask.size() == src.size()。最小复现：480×640 的图像配 120×240 的掩码。

10. HSV 色相使用 0–360

现象：inRange 不报错，掩码全黑；红色、粉色等目标检测不到。

原因：OpenCV 的 8 位 HSV 把色相压缩到 0–179，不是 0–360 度。按角度填写上限会超出实际范围。

处理：把角度值除以 2；跨过 0 点的颜色拆成 两段范围并按位或，写法见 10.1。判断方法：打印目标像素的 H 分量，确认落在 0–179。

11. approxPolyDP 后顶点数不是 4

现象：轮廓明明是矩形，approxPolyDP 返回 5–8 个点， 后续四边形判断全部失败。

原因：轮廓边缘有噪声，epsilon 取得过小；或轮廓本身 有缺口、不闭合。

处理：epsilon 取周长的 1%–2%；先做开闭 运算平滑边缘；判断前打印 poly.size() 与 isContourConvex(poly)。最小复现：在带噪声的矩形轮廓上用 0.001 * arcLength(contour, true) 逼近，顶点数明显多于 4。

视频、显示与标定

12. VideoCapture 打开或读取失败

现象：cap.isOpened() 为假，或第一帧 frame.empty()；循环一次也不执行。

原因：相对路径以运行目录为基准，不以源文件所在目录为基准；文件 不存在、编码不受支持或相机编号不对。

处理：打开后检查 isOpened()，读取后检查 frame.empty()，并打印 get(CAP_PROP_FRAME_COUNT)。从 示例代码 目录运行。 判断方法：帧数大于 0 且首帧非空。最小复现： cv::VideoCapture cap("missing.mp4");。

13. VideoWriter 输出 0 字节或无法播放

现象：writer.isOpened() 为真，程序正常结束，输出文件 很小或播放器打不开。

原因：write 的帧尺寸与构造时的 frameSize 不一致，写入被忽略；或 fourcc 与文件扩展名不匹配。

处理：构造前取 frame.size()，所有写入帧保持同一尺寸； mp4v 配 .mp4。写完后用 VideoCapture 回读，确认帧数与写入数一致。最小复现：声明 640×480，实际写入 320×240 的帧，文件不可读。

14. 棋盘格角点找不到

现象：findChessboardCorners 始终返回 false， corners 为空。

原因：patternSize 传的是方格数，函数要的是内角点数； 或图像模糊、棋盘不完整、黑白对比不足。

处理：patternSize 使用内角点数。例如 9×6 个方格的棋盘，内角点为 8×5。先用 imshow 检查 图像，再用 drawChessboardCorners 显示检测结果。判断方法： 返回 true 且 corners.size() == patternSize.area()。 最小复现：在空白图上检测 Size(9, 6)，返回 false。

15. 卡尔曼滤波的类型混用

现象

error: (-215:Assertion failed) C.type() == type in function 'gemm'

原因：KalmanFilter 的状态与各矩阵使用 CV_32F， 而测量值或噪声矩阵使用 CV_64F；correct 内部的 矩阵乘法要求类型一致。报错位置在 gemm，不直接指向卡尔曼代码。

处理：状态、转移矩阵、观测矩阵、过程噪声、观测噪声与测量值统一为 CV_32F 或统一为 CV_64F。判断方法：逐个打印 type()。最小复现：CV_32F 的滤波器调用 correct 时传入 cv::Mat_<double> 的测量值。
