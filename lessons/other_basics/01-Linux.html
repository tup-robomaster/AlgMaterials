Linux 文件结构与基础命令

这一部分的目标是「会用」，不是背命令。七课覆盖日常最常用的操作： 认清目录、找文件、看内容、改权限、管进程、接管道、打包与远程传输。 每一课都有可以照着输入的「跟着做」，输出是这台机器上的真实结果。 命令里的练习目录统一放在 /tmp/other-basics 下，不会碰读者自己的文件。

1.1Linux 的目录结构

Linux 的文件系统是一棵树，最上面是根目录 /。 所有文件、目录、设备都挂在这棵树上；没有 Windows 那样的盘符。 这一课先认清树的形状，再分清绝对路径与相对路径。

从根目录开始

列出根目录下一层的内容：

Ubuntu 24.04 上还会看到 bin.usr-is-merged、lib.usr-is-merged 和 sbin.usr-is-merged 这三项。它们是系统把 /bin、/sbin 合并到 /usr 之后留下的记录， 不需要处理。不同发行版、不同安装方式下，根目录的条目会略有差异； 下面这些是常见且稳定的。

每个目录放什么

  • /——根目录，整棵树的起点。
  • /home——普通用户的主目录。用户名 alice 的主目录通常是 /home/alice，也就是 ~ 展开后的位置。
  • /etc——系统和软件的配置文件。改配置之前先备份。
  • /usr——安装的程序、库、头文件和文档。 可执行文件通常在 /usr/bin，库在 /usr/lib。
  • /var——运行中不断变化的数据：日志在 /var/log， 缓存、数据库、邮件队列也在这里。
  • /dev——设备文件。串口通常是 /dev/ttyUSB0 或 /dev/ttyACM0， 相机通常是 /dev/video0。这些文件由内核维护，不要手动创建或删除。
  • /proc——内核和进程信息的虚拟文件系统，内容在内存里， 不占磁盘。进程目录以进程号命名，例如 /proc/1234。
  • /tmp——临时文件。任何用户都可以写，重启后通常会被清空。 练习目录放在这里，正是因为它不影响正式文件。
  • /opt——额外安装的第三方软件，通常一个软件一个子目录。
  • /root——root 用户的主目录，不在 /home 下。
  • /boot——启动用的内核与引导文件，不要随意改动。
  • /media、/mnt——挂载点。U 盘、移动硬盘、 网络文件系统通常挂在这两个目录下面。

初学时最常打交道的三个位置是：自己的主目录 ~、 放代码的项目目录、以及 /tmp 下的临时目录。 /etc 和 /var 多数时候只需要读，不需要改。

绝对路径与相对路径

以 / 开头的路径是绝对路径，它从根目录开始，和当前所在位置无关。 不以 / 开头的路径是相对路径，它从当前目录开始算。

波浪号、点与点点

三个符号在路径里反复出现：

  • ~——当前用户的主目录。shell 在把命令交给程序之前， 会先把 ~ 展开成实际路径，所以程序本身通常看不到这个符号。
  • .——当前目录。例如 ./demo 表示当前目录下的 demo。
  • ..——上一层目录。../.. 表示上两层。

cd . 不会移动位置，pwd 仍显示同一个目录： 

cd /tmp/other-basics/示例代码/1.1-目录与路径/demo
cd .
pwd
/tmp/other-basics/示例代码/1.1-目录与路径/demo

运行当前目录下的程序时必须写 ./，因为当前目录默认不在 PATH 里；这一点在 1.4 讲脚本执行权限时还会遇到。

你现在能做什么：说出根目录下常见目录的用途， 分清绝对路径与相对路径，用 pwd、cd、 ~、.、.. 在目录树里移动。

1.2路径与文件操作

这一课处理文件和目录本身：查看、创建、复制、移动、删除、建立链接。 所有操作都在练习副本里进行，可以放心试。

看清当前位置

先进入本课的目录： 

cd /tmp/other-basics/示例代码/1.2-路径与文件
pwd
ls -1
/tmp/other-basics/示例代码/1.2-路径与文件
data
notes.txt

ls 列出目录内容；-1 表示一行一个。 加上 -a 会显示以点开头的隐藏文件，以及 . 和 .. 这两个特殊目录： 

ls -1a
.
..
data
notes.txt

ls 的其他常用选项：-l 长格式（1.4 讲每一列）、 -h 把大小显示成 K、M， -R 递归列出子目录。

建目录、复制、移动

mkdir backup
cp notes.txt backup/
cp -r data backup/
ls -1 backup
data
notes.txt

mkdir 建立目录；cp 复制文件； 复制目录要加 -r（递归）。mv 既是移动，也是改名： 

mv backup/notes.txt backup/notes-copy.txt
ls -1 backup
data
notes-copy.txt

mkdir -p a/b/c 会一次建立多层目录，已经存在的目录不报错。 cp 默认覆盖同名文件；加 -i 会在覆盖前询问。

删除

rm 删除文件，rm -r 删除目录及其内容。 删除操作不进回收站，终端里也没有撤销： 

rm backup/notes-copy.txt
rm -r backup
ls -1
data
notes.txt
删除前确认路径

rm -rf 会递归删除并且不询问确认。执行之前先用 pwd 确认当前位置，再把命令里的路径读一遍。 不要对 /、~ 或者自己不确定的目录使用 rm -rf。想先看一眼会删什么，可以把 rm 换成 ls 执行一遍。

链接

符号链接（软链接）是一个指向另一个路径的特殊文件： 

ln -s notes.txt link.txt
ls -1
readlink link.txt
data
link.txt
notes.txt
notes.txt

readlink 显示链接指向的路径。通过链接读文件，读到的是目标文件的内容： 

cat link.txt

第二行：复制、移动、删除

ln -s 目标 链接名 创建软链接；不加 -s 创建硬链接。 软链接可以跨文件系统，目标被移动或删除后会失效；硬链接不能跨文件系统， 删除其中一个名字，文件内容仍然存在，直到所有硬链接都被删除。 日常使用中，软链接更常见。

rm 删除符号链接时，只删除链接本身，不会删除它指向的文件： 

rm link.txt
ls -1
cat notes.txt

空格与通配符

文件名里可以有空格。有空格时，路径要用引号括起来，否则 shell 会把它拆成两个参数： 

echo "带空格的文件名" > "my note.txt"
ls -1

带空格的文件名

隐藏文件以点开头，普通 ls 不显示：

ls -1

通配符由 shell 展开，常见的三个是：* 匹配任意长度的字符， ? 匹配一个字符，[abc] 匹配括号里的任意一个字符。 

touch a1.txt a2.txt b1.txt
ls -1 a*.txt
ls -1 ?1.txt

通配符只匹配当前目录下符合条件的名字，不递归进入子目录。 给 grep、find 这类命令传模式时， 通常要用引号防止 shell 先展开；这一点在 1.3 会看到。 

rm a1.txt a2.txt b1.txt

你现在能做什么：用 pwd、ls、cd 在目录里定位，用 mkdir、cp、mv、 rm 管理文件，建立软链接，处理带空格的文件名与通配符。

1.3查看、搜索与统计

文件找到之后，下一步是看内容、在内容里找东西、统计结果。 这一课的命令经常和管道一起用，管道本身在 1.6 展开。

查看整个文件

cd /tmp/other-basics/示例代码/1.3-查看与搜索

cat 把文件内容整个打印到屏幕，适合短文件。 文件很长时用 less： 

less scores.txt

less 打开后，用方向键或 PageUp、PageDown 翻页，按 / 输入要搜索的词，按 q 退出。 它不会把整个文件一次打印出来，读日志和长文档时更合适。

只看头尾

head -n 2 scores.txt
tail -n 2 scores.txt

香蕉 5

香蕉 1

head 看开头，tail 看结尾；不带 -n 时 默认各显示 10 行。tail -f 会持续跟踪文件末尾， 程序一边写日志，屏幕一边刷新；按 Ctrl+C 停止。 查正在运行的程序出了什么问题时，这个用法很常见。

按内容搜索

grep 苹果 scores.txt
grep -n 苹果 scores.txt
grep -c 苹果 scores.txt
苹果 3
苹果 2
1:苹果 3
3:苹果 2
2

grep 按行搜索，匹配的行整行打印。-n 带行号， -c 只输出匹配的行数。默认区分大小写， -i 忽略大小写，-v 反向匹配（打印不匹配的行）。

在目录里递归搜索，并带上文件名和行号： 

grep -rn 启动 logs | sort
logs/app.log:1:启动服务
logs/error.log:1:启动服务

-r 递归搜索目录，-n 显示行号。 后面接 | sort 是为了让输出顺序固定：不加时， 文件遍历的顺序由文件系统决定，不同机器上可能不同。

grep 的退出码表示有没有找到：找到返回 0，没找到返回 1， 出错返回 2。脚本里常用这个特性判断某个配置项是否存在。

按名字和类型查找

find . -name "*.log" | sort
find . -type f | sort
./logs/app.log
./logs/error.log
./logs/app.log
./logs/error.log
./names.txt
./scores.txt

find 起始目录 条件 动作 是它的基本形状。-name 按名字匹配，模式要加引号，否则 shell 会先展开 *； -type f 只要普通文件，-type d 只要目录。 不加动作时，默认把找到的路径打印出来。

查一个命令在哪儿： 

which python3
which git
file scores.txt
/usr/bin/python3
/usr/bin/git
scores.txt: Unicode text, UTF-8 text

which 在 PATH 列出的目录里找可执行文件， 找到就打印完整路径。同一台机器上装了多个版本时，它告诉你当前会运行哪一个。 file 根据文件内容判断类型，不看扩展名； 拿到一个不认识的文件时，先用它看一眼。

wc -l 数行数，-w 数单词，-c 数字节。 sort 按字典序排序；uniq 去掉相邻的重复行， 所以通常先 sort 再 uniq。 uniq -c 在每行前面加上出现次数。

1.4权限、用户与 sudo

Linux 里每个文件都有所有者、所属组和一组权限位。 权限决定谁能读、谁能在文件里写、谁能把它当作程序执行。

ls -l 的每一列

cd /tmp/other-basics/示例代码/1.4-权限
ls -l
总计 8
-rw-rw-r-- 1 alice alice 34 3月 14 09:20 data.txt
-rw-rw-r-- 1 alice alice 67 3月 14 09:20 hello.sh

每一行从左到右是：

  1. 类型与权限——第一个字符是类型：- 普通文件、 d 目录、l 符号链接。后面九个字符每三个一组， 分别是所有者、所属组、其他人的读（r）、写（w）、 执行（x）权限；没有权限的位置写 -。
  2. 硬链接数——普通文件通常是 1，目录至少是 2。
  3. 所有者与所属组——这里是示例名 alice 和同名的组； 实际显示的是读者自己的用户名和组名。
  4. 大小——字节数。
  5. 修改时间——这里是示例时间；实际显示的是文件最后一次修改的时间。 超过半年的文件会显示年份。
  6. 文件名。

ls -l 的输出里，用户名、组名和时间每次都可能不同。 只想看权限位和八进制数值时，用 stat： 

stat -c "%A %a %n" hello.sh data.txt
-rw-rw-r-- 664 hello.sh
-rw-rw-r-- 664 data.txt

三种权限

对普通文件：

  • r（读）——可以查看内容。
  • w（写）——可以修改、截断、追加内容。
  • x（执行）——可以把它当作程序运行。

对目录，这三个字母的含义不同：

  • r——可以列出目录里的名字。
  • w——可以在目录里创建、删除、重命名文件。
  • x——可以进入目录，访问里面的文件。

所以一个目录只有 r 没有 x 时，能看见名字， 但打不开里面的文件；只有 x 没有 r 时， 知道完整路径就能访问，但列不出目录内容。

chmod 的两种写法

符号写法用 u（所有者）、g（组）、o（其他人）、 a（所有人）加上 +、-、=： 

chmod +x hello.sh
stat -c "%A %a %n" hello.sh
chmod 644 hello.sh
chmod u+x hello.sh
stat -c "%A %a %n" hello.sh
-rwxrwxr-x 775 hello.sh
-rwxr--r-- 744 hello.sh

第一条 chmod +x 给所有人加执行权限，权限从 664 变成 775。 为了单独看 u 的作用，第三条先用 chmod 644 把权限设回「所有者读写，组和其他人只读」，这个写法下一段展开； 第四条 chmod u+x 只给所有者加执行权限，权限是 744。 符号写法适合「在现有权限上增减」。

八进制写法直接把三组权限写成三个数字。读是 4，写是 2，执行是 1， 每组把需要的值相加： 

chmod 644 hello.sh
stat -c "%A %a %n" hello.sh
chmod 600 data.txt
stat -c "%A %a %n" data.txt
-rw-r--r-- 644 hello.sh
-rw------- 600 data.txt

常用组合：644 普通文件（所有者可写，其他人只读）、 755 可执行文件或目录（所有者可写，其他人可读可执行）、 600 只有所有者能读写的私密文件。 777 表示所有人都能读、写、执行，除非有明确理由，不要使用。

chmod -R 会递归修改目录下所有内容，使用前先确认范围。 chown 改所有者，chgrp 改所属组； 普通用户通常只能改自己的文件，改别人的文件需要 sudo。

脚本为什么需要执行权限

脚本文件前面通常有一行 #!/bin/bash，叫做 shebang， 告诉内核用哪个解释器运行它。没有执行权限时，直接运行会被拒绝： 

chmod 644 hello.sh
./hello.sh
/bin/bash: 行 1: ./hello.sh: 权限不够

退出码是 126。此时可以用解释器显式运行，不需要执行权限： 

bash hello.sh
脚本开始运行
当前目录：/tmp/other-basics/示例代码/1.4-权限

加上执行权限后，./hello.sh 就能直接运行： 

chmod +x hello.sh
./hello.sh
脚本开始运行
当前目录：/tmp/other-basics/示例代码/1.4-权限

这里写 ./hello.sh 而不是 hello.sh， 是因为当前目录默认不在 PATH 里。这样设计是为了防止 当前目录里一个同名的恶意脚本被误执行。

用户、组与 sudo

每个进程都以某个用户身份运行。查看当前用户和所属组： 

id -un
id -gn
umask
alice
alice
0002

这里的用户名和组名用 alice 代替；实际运行时会显示读者自己的 用户名和组名。这里的 umask 是 0002， 表示新建文件时从默认权限里去掉「其他人写」这一位， 所以新文件是 664、新目录是 775；如果 umask 是 0022， 新文件就是 644、新目录是 755。

sudo 让普通用户以 root 身份执行一条命令。 第一次使用时会要求输入当前用户的密码；输入时屏幕上不显示字符， 这是正常的。例如更新软件包索引： 

sudo apt update

sudo 的权限很大，使用原则是：只在确实需要改系统文件、 安装软件、管理服务时使用；日常编辑代码、复制文件不需要 sudo。 用 sudo 创建的文件所有者是 root， 之后普通用户可能改不动，遇到这种情况要用 sudo chown 把所有者改回来。

你现在能做什么：读懂 ls -l 的每一列， 说出读、写、执行权限对文件和目录分别意味着什么， 用符号写法和八进制写法改权限，判断一个脚本为什么不能直接运行， 并且知道什么时候该用 sudo、什么时候不该用。

1.5进程、前后台与信号

程序运行起来之后就是一个进程。这一课看进程号、把任务放到后台、 在前后台之间切换，以及用信号结束进程。

进入这一课的目录，先给后面要用到的脚本加上执行权限： 

cd /tmp/other-basics/示例代码/1.5-进程
chmod +x count.sh

进程与进程号

每个进程有一个进程号（PID）。启动一个 sleep 放到后台， 再查看它： 

sleep 300 &
jobs
ps -o pid,ppid,stat,cmd -C sleep
kill %1
jobs
[1] 1333857
[1]+  运行中               sleep 300 &
    PID    PPID STAT CMD
1333857 1333852 S    sleep 300
[1]+  已终止               sleep 300

PID 是进程号，PPID 是父进程号， STAT 是状态（S 表示可中断的睡眠， R 表示正在运行，Z 表示僵尸进程）， CMD 是启动命令。进程号和父进程号每次不同，是正常现象。

这一段最后用 kill %1 结束了这个任务，后面的例子从空的任务列表开始。 kill 在信号一节详细讲，这里只需要知道它能按任务号结束后台任务。

ps 不带选项时只显示当前终端相关的进程； ps aux 显示所有用户的进程，ps -ef 是另一种常见写法。 top 或 htop 会持续刷新，按 CPU 或内存排序； 在 top 里按 q 退出。

后台运行

命令末尾加 &，shell 会把它放到后台，立即返回提示符： 

sleep 300 &
jobs
kill %1
[1] 1333858
[1]+  运行中               sleep 300 &
[1]+  已终止               sleep 300

jobs 列出当前 shell 的后台任务，方括号里的数字是任务号。 jobs -l 还会显示进程号。fg %1 把 1 号任务调回前台， bg %1 让暂停的 1 号任务在后台继续运行。 这一段末尾同样用 kill %1 清掉了任务，接下来的操作从空的任务列表开始。

前台任务会占住终端，直到它结束；后台任务不会。长时间运行的训练、 采集、服务通常放到后台，或者用 nohup、终端复用工具管理。

暂停与切回

三个键盘操作要分清：

  • Ctrl+C——给前台进程发送 SIGINT， 通常让它立即结束。
  • Ctrl+Z——给前台进程发送 SIGTSTP， 让它暂停，回到 shell。进程没有结束，只是停住了。
  • Ctrl+D——输入结束（EOF），不是信号； 在空行按它通常会退出当前 shell。

一个暂停的任务可以用 jobs 看到，状态显示「已停止」； 用 bg %1 让它转到后台继续，或用 fg %1 调回前台。例如运行一个每秒打印一行的脚本，按 Ctrl+Z 暂停： 

./count.sh
计数：1
计数：2
^Z
[1]+  已停止               ./count.sh
jobs
[1]+  已停止               ./count.sh
bg %1
[1]+ ./count.sh &
fg %1
./count.sh
计数：3
计数：4
计数：5
计数结束

上面这一段是终端里的操作示意；^Z 是按 Ctrl+Z 之后终端显示的字样，不是要输入的字符。实际的任务号和进程号会不同。

信号

kill 的名字容易误解：它不只是「杀死」，而是给进程发一个信号。 常用信号的名字和编号： 

kill -l 2
kill -l 15
kill -l 9
INT
TERM
KILL
  • SIGINT（2）——中断，通常由 Ctrl+C 发出。 进程可以捕获并做清理。
  • SIGTERM（15）——终止请求，kill PID 默认发这个信号。进程可以捕获，先保存数据再退出。
  • SIGKILL（9）——强制终止，进程无法捕获或忽略。 只在进程不响应 SIGTERM 时作为最后手段。

kill 1234 给进程号 1234 发 SIGTERM； kill -9 1234 发 SIGKILL。 对后台任务也可以写 kill %1，这里的 %1 是任务号，不是进程号。按名字结束进程用 pkill 名字 或 killall 名字，使用前先用 pgrep 确认匹配到了哪些进程。

启动一个后台任务，再按任务号结束它： 

sleep 300 &
kill %1
jobs
[1] 1333859
[1]+  已终止               sleep 300

nohup 与退出终端

关闭终端时，shell 会给它启动的后台任务发送 SIGHUP， 很多程序收到这个信号就退出。nohup 让命令忽略 SIGHUP，从而在终端关闭后继续运行： 

nohup ./count.sh > count.log 2>&1 &
[1] 1333860

这条命令把标准输出和标准错误都写进 count.log， 再把任务放到后台。如果不写重定向，nohup 会把输出追加到 当前目录的 nohup.out。之后可以用 tail -f count.log 看运行情况。

nohup 只解决「终端关闭后不退出」，不解决「多个任务怎么管理」。 需要长期运行、随时切回查看的任务，通常用 tmux 或 screen 这类终端复用工具；它们不在本课范围内，需要时自行搜索。

你现在能做什么：用 ps 看进程号和状态， 用 &、jobs、bg、fg 管理前后台任务，分清 Ctrl+C、Ctrl+Z、Ctrl+D 的作用，用 kill 发送常见信号，知道 nohup 解决什么问题。

1.6管道、重定向与环境变量

这一课把命令接起来：前一条的输出变成后一条的输入， 或者把输出写进文件、把错误单独接住。最后看环境变量与退出码。

管道

竖线 | 把左边命令的标准输出接到右边命令的标准输入： 

cd /tmp/other-basics/示例代码/1.6-管道与重定向
sort words.txt | uniq -c
      2 apple
      3 banana
      1 orange

左边 sort 的输出没有打印到屏幕，而是直接交给 uniq -c。两条命令同时运行，数据一边产生一边消费。 管道可以接很多段，但段数越多越难读；超过三四段时， 通常值得写成脚本。

| 是管道；|| 是逻辑「或」，表示前一条命令失败时 才执行后一条。两个符号不要混用。

输出重定向

> 把标准输出写进文件，文件原有的内容会被清空； >> 追加到文件末尾： 

grep banana words.txt > banana.txt
cat banana.txt
echo "grape" >> banana.txt
cat banana.txt
banana
banana
banana
banana
banana
banana
grape

重定向只影响标准输出，错误信息仍然打印在屏幕上。 想把错误也写进文件，见下一节。

输入重定向

< 把文件内容接到命令的标准输入： 

wc -l < words.txt
6

和不加重定向、直接把文件名交给命令的写法相比，输出里少了文件名， 因为 wc 只知道自己读的是标准输入。脚本里常用这种写法 把文件内容喂给命令。另一种常见写法是 here-document： 命令 <<EOF，从下一行开始读，直到单独一行 EOF。

错误流

每个进程默认打开三个文件描述符：0 标准输入、1 标准输出、2 标准错误。 2> 把标准错误写进文件： 

LC_ALL=C ls no-such-file 2> err.txt
cat err.txt
ls: cannot access 'no-such-file': No such file or directory

这里的 LC_ALL=C 把这一次命令的语言环境临时设为 C， 让错误信息显示成英文。日常使用时通常不写它；课里写它， 是为了让不同语言环境的读者看到同一段文字。

把标准输出和标准错误都写进同一个文件： 

LC_ALL=C ls no-such-file > out.log 2>&1
cat out.log
ls: cannot access 'no-such-file': No such file or directory

2>&1 的意思是「把标准错误指向标准输出当前指向的地方」。 顺序很重要：> out.log 2>&1 先打开文件、再把错误指过去， 两者都进文件；反过来写成 2>&1 > out.log， 错误会先指向终端，再改标准输出，错误仍然留在屏幕上。 Bash 还支持简写 &> out.log。

tee

tee 把标准输入同时写到屏幕和文件： 

echo hello | tee tee.txt
cat tee.txt
hello
hello

第一行 hello 是 tee 打印到屏幕的，第二行是 cat 从文件里读出来的。tee -a 追加而不是覆盖。 需要一边看输出一边留记录时用它。写需要 sudo 的文件时， 常见写法是 echo ... | sudo tee /path/file， 因为 sudo echo ... > file 里的重定向仍由普通用户执行。

环境变量

环境变量是进程启动时继承的一组键值。用 export 设置， 用 $名字 读取： 

export GREETING=你好
echo $GREETING
env | grep GREETING
你好
GREETING=你好

export 让变量进入环境，之后启动的子进程也能读到； 不写 export 的变量只存在于当前 shell。 这个设置只在当前终端有效，关闭终端就消失。 需要每次登录都生效时，把 export 那行写进 ~/.bashrc，再执行 source ~/.bashrc。

PATH 是最常用的环境变量之一：它是一串用冒号分隔的目录， shell 在这些目录里按顺序查找命令。输入 python3 时， shell 并不是在任意位置找，而是按 PATH 的顺序找第一个匹配。 用 echo $PATH 可以查看，内容随机器和安装方式不同。 把新目录加到前面，写成 export PATH="$HOME/bin:$PATH"，不要覆盖掉原来的值。

退出码与命令替换

每条命令结束时返回一个退出码，保存在 $? 里。 0 表示成功，非 0 表示失败： 

false; echo $?
true; echo $?
1
0

&& 表示前一条成功才执行后一条， || 表示前一条失败才执行后一条。脚本里常见的写法是 命令 || exit 1，失败就停止。 set -e 让脚本在任意命令失败时退出， set -u 让使用未定义变量时报错， set -o pipefail 让管道中任意一段失败都算整个管道失败。

$(命令) 先把命令的输出取出来，再放进当前命令： 

echo "今天是 $(echo 星期五)"
今天是 星期五

命令替换也可以写成反引号 `命令`，但嵌套时容易混乱， 现代写法统一用 $(...)。

你现在能做什么：用 | 把命令接起来， 用 >、>>、<、2>、 2>&1 控制输入输出，用 tee 同时留记录， 设置和读取环境变量，用 $?、&&、|| 与命令替换写出简单的脚本逻辑。

1.7软件安装、压缩包与远程连接

这一课的三组内容经常一起出现：在新机器上装工具、把工程打包传到另一台机器、 通过 SSH 登录过去继续操作。软件安装与远程连接需要网络和账号， 课里只给命令与说明；压缩包部分可以完整地跟着做。

软件包管理

Ubuntu 用 apt 管理软件包。常用命令： 

sudo apt update
sudo apt install 包名
sudo apt remove 包名
apt search 关键字
apt show 包名
  • apt update 刷新软件包索引，不升级已安装的软件； 它需要联网，通常放在安装之前执行。
  • apt install 安装软件包，apt remove 卸载； apt purge 连配置文件一起删除。
  • apt search 按关键字查找，apt show 查看版本、 依赖和说明。

查看 apt 的版本： 

apt --version
apt 2.8.3 (amd64)

本课不要求安装新软件；上面的安装命令只是常用写法。 需要安装时，优先用发行版的包管理器，不要把来源不明的二进制文件 直接放进系统目录。安装前先看清包名，apt 会列出将要安装、 升级和删除的包，确认后再输入 y。

tar

tar 把多个文件打成一个归档文件，常与 gzip 一起用。 先进入本课目录，打包再解包： 

cd /tmp/other-basics/示例代码/1.7-压缩与远程
ls -1
tar -czf project.tar.gz project
ls -1
project
project
project.tar.gz

-czf 三个字母分别是：c 创建归档， z 用 gzip 压缩，f 后面紧跟归档文件名。 查看归档里有什么，用 t： 

tar -tzf project.tar.gz
project/
project/README.md
project/src/
project/src/main.py

解包到指定目录： 

mkdir unpack
tar -xzf project.tar.gz -C unpack
find unpack -type f | sort
unpack/project/README.md
unpack/project/src/main.py

x 表示解包，-C 指定解包目录。 解包前先看一眼归档内容，确认里面没有指向系统目录的绝对路径； 来源不明的归档不要直接解到当前目录。其他压缩格式： .tar.bz2 用 -j，.tar.xz 用 -J。

zip 与 unzip

zip 在 Windows 与 Linux 之间交换文件时更常见： 

zip -qr project.zip project
unzip -q project.zip -d unzip-test
find unzip-test -type f | sort
unzip-test/project/README.md
unzip-test/project/src/main.py

zip -r 递归打包目录，-q 安静模式； unzip -d 指定解压目录，-l 只列出内容。 zip 默认不保留 Linux 的权限位，跨平台传递脚本时要重新确认执行权限。

ssh

ssh 登录远程机器，在对方的 shell 里执行命令： 

ssh 用户名@主机地址
ssh -p 2222 用户名@主机地址
ssh 用户名@主机地址 "ls -1"

第一次连接某台机器时，SSH 会显示对方的公钥指纹，询问是否继续； 核对来源后输入 yes。之后会把对方记进 ~/.ssh/known_hosts。

更常用的登录方式是密钥认证。生成一对密钥： 

ssh-keygen -t ed25519 -C "你的邮箱或备注"

命令会在 ~/.ssh/ 下生成私钥 id_ed25519 和公钥 id_ed25519.pub。私钥不能发给任何人；公钥可以交给服务器。 把公钥登记到远程机器的 ~/.ssh/authorized_keys 里， 常用命令是 ssh-copy-id 用户名@主机地址。 之后登录不再输入密码，而是用私钥验证；生成时可以给私钥设置口令。

查看本机 SSH 版本： 

ssh -V
OpenSSH_9.6p1 Ubuntu-3ubuntu13.20, OpenSSL 3.0.13 30 Jan 2024

频繁连接的机器可以写进 ~/.ssh/config，给主机起一个短名字； 这个文件的权限应当是 600。Git 通过 SSH 访问远程仓库时， 也用同一套密钥，ssh -T git@主机 可以测试连接。

scp 与 rsync

scp 在本地和远程之间复制文件，语法与 cp 类似： 

scp 本地文件 用户名@主机:/远程目录/
scp -r 本地目录 用户名@主机:/远程目录/
scp 用户名@主机:/远程文件 .

-r 递归复制目录。远程路径写在冒号后面， 冒号前是主机，冒号后是路径；只写文件名表示当前目录。

rsync 更适合反复同步大目录：它只传有变化的部分， 支持断点续传和排除规则： 

rsync -av project/ 用户名@主机:/远程目录/project/
rsync -avn project/ 用户名@主机:/远程目录/project/

-a 保留权限、时间等属性，-v 显示过程， -n 只演练、不实际传输。源路径末尾的斜杠有意义： project/ 表示复制目录里的内容，project 表示连目录本身一起复制。加 --delete 会删除目标端多余的文件， 使用前一定先用 -n 看一遍。 

rsync --version | head -n 1
rsync  version 3.2.7  protocol version 31

scp 与 rsync 都通过 SSH 传输，需要网络和账号。 课里不连接真实主机；读者有服务器或开发板时，把示例里的用户名、 主机和路径换成自己的即可。

你现在能做什么：用 apt 查找、安装、卸载软件包， 用 tar、zip 打包与解包， 用 ssh 登录远程机器、生成并登记密钥， 用 scp、rsync 在本地与远程之间传输文件。
