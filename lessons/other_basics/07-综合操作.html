第 7 部分

综合操作

这一部分把前面几部分串起来，做两组综合操作，不设练习，也不设答案。 7.1 在一个空目录里建立一个可以运行的小工程，并用 Git 记录第一次提交； 7.2 在这个工程上按队内分支规范走功能分支、发布分支与紧急修复， 一直走到发布版 V1.1。两组操作都只使用本机文件、Python 标准库与 Git， 不连接相机，不联网，也不需要管理员权限。

安全边界与练习目录

本部分的练习目录是 ~/tup-practice/camera-demo。下面的命令 只在这个目录及其子目录里执行；不要对主目录、桌面或其他项目目录执行删除、 覆盖或 chmod。Git 只在本机操作：不执行 git push， 不配置远程仓库，不读取 SSH 密钥。示例身份为「练习者 / practice@example.com」；执行仓库级设置时，它只写进练习仓库的本地配置， 不写入课程文件以外的位置。

7.1从空目录到小工程

这一课从空目录开始，建立一个只做一件事的小工程。相机 A 的分辨率、像元尺寸 与焦距取第 5 部分的算例。整个过程不需要相机、SDK 或网络；Python 只使用 标准库，启动脚本只调用本机的 python3。

这一课要完成什么

这一课建立一个很小的相机参数工程：读取一台相机的参数，计算水平与垂直 视场角、单帧图像占多少字节，以及每秒产生多少数据，最后把输入与结果一起 写成一份 JSON 报告。完成之后，用 Git 记录第一次提交。

工程完成后，结构如下。<用户> 是当前用户名；左侧的竖线、 横线与反引号只是表示层级的连接符号，行尾的注释说明文件用途，两者都不是 文件名的一部分： 

/home/<用户>/tup-practice/
`-- camera-demo/
    |-- camera.json    # 相机参数，换相机时主要改这里
    |-- compute.py     # 读取参数，计算并写出 report.json
    |-- run.sh         # 切换到工程目录后调用计算脚本
    |-- README.md      # 工程用途与运行方法
    `-- .gitignore     # 不提交报告与 Python 缓存

运行后还会多出一个 report.json。它由脚本生成，每次运行都会重写， 不属于工程源码，所以不列在上面的结构树里，也不提交到 Git。 .gitignore 以点开头，部分文件管理器默认不显示；在终端里执行 ls -a 就能看到。

接下来的顺序是：建立目录与 Git 仓库，写参数文件，写计算脚本，写启动脚本与说明， 运行并检查，最后完成第一次提交。

写参数文件

用编辑器在工程目录里新建 camera.json，内容如下： 

{
  "name": "camera A",
  "width": 1280,
  "height": 1024,
  "pixel_um": 10.0,
  "focal_mm": 8.0,
  "fx": 800.0,
  "fy": 800.0,
  "cx": 640.0,
  "cy": 512.0,
  "fps": 30,
  "bits_per_pixel": 8
}

各字段的含义：width 与 height 是像素数； pixel_um 是像元边长，单位微米；focal_mm 是焦距， 单位毫米；fx、fy、cx、cy 是内参；fps 是帧率；bits_per_pixel 是每个像素的位数。 这台相机的主点是图像中心，因此 cx = 1280 / 2 = 640、 cy = 1024 / 2 = 512。像元为 10 µm 即 0.01 mm，焦距 8 mm 折算成像素是 8 / 0.01 = 800，与 fx、fy 一致。

JSON 不允许注释，字段名与字符串必须使用双引号。这个文件只保存参数， 不保存计算结果；计算结果由后面的脚本生成。

写计算脚本

在同一个目录里新建 compute.py： 

#!/usr/bin/env python3
# 读取 camera.json，计算视场角、单帧大小与数据量，写入 report.json。

import json
import math
import sys
from pathlib import Path


def load_camera(path):
    """读取并检查相机参数。"""
    try:
        data = json.loads(Path(path).read_text(encoding="utf-8"))
    except OSError as error:
        raise SystemExit(f"无法读取 {path}：{error.strerror}")
    except json.JSONDecodeError as error:
        raise SystemExit(
            f"{path} 不是有效的 JSON：第 {error.lineno} 行"
            f"第 {error.colno} 列"
        )

    required = [
        "name", "width", "height", "pixel_um", "focal_mm",
        "fx", "fy", "cx", "cy", "fps", "bits_per_pixel",
    ]
    missing = [key for key in required if key not in data]
    if missing:
        raise SystemExit("缺少字段：" + "、".join(missing))
    for key in required[1:]:
        value = data[key]
        if not isinstance(value, (int, float)) or value <= 0:
            raise SystemExit(f"字段 {key} 必须是正数")
    return data


def compute(camera):
    """由分辨率、像元、焦距与帧率计算四项结果。"""
    pixel_mm = camera["pixel_um"] / 1000
    sensor_width_mm = camera["width"] * pixel_mm
    sensor_height_mm = camera["height"] * pixel_mm
    horizontal_fov = 2 * math.atan(
        sensor_width_mm / (2 * camera["focal_mm"])
    )
    vertical_fov = 2 * math.atan(
        sensor_height_mm / (2 * camera["focal_mm"])
    )
    frame_bytes = (
        camera["width"] * camera["height"]
        * camera["bits_per_pixel"] // 8
    )
    bandwidth = frame_bytes * camera["fps"]
    return {
        "sensor_width_mm": round(sensor_width_mm, 4),
        "sensor_height_mm": round(sensor_height_mm, 4),
        "focal_px": round(camera["focal_mm"] / pixel_mm, 4),
        "horizontal_fov_deg": round(math.degrees(horizontal_fov), 6),
        "vertical_fov_deg": round(math.degrees(vertical_fov), 6),
        "frame_bytes": frame_bytes,
        "frame_mib": round(frame_bytes / (1024 * 1024), 4),
        "bandwidth_bytes_s": bandwidth,
        "bandwidth_mib_s": round(bandwidth / (1024 * 1024), 4),
    }


def main():
    path = Path(sys.argv[1] if len(sys.argv) > 1 else "camera.json")
    camera = load_camera(path)
    result = compute(camera)
    report = {**camera, **result}
    target = path.resolve().with_name("report.json")
    target.write_text(
        json.dumps(report, ensure_ascii=False, indent=2) + "\n",
        encoding="utf-8",
    )

    print(f"相机：{camera['name']}")
    print(f"分辨率：{camera['width']} × {camera['height']}")
    print(f"像元：{camera['pixel_um']:.1f} µm")
    print(f"焦距：{camera['focal_mm']:.1f} mm")
    print(
        f"焦距折算：{result['focal_px']:.1f} px"
        f"（fx={camera['fx']:.1f}，fy={camera['fy']:.1f}）"
    )
    print(f"水平视场角：{result['horizontal_fov_deg']:.2f}°")
    print(f"垂直视场角：{result['vertical_fov_deg']:.2f}°")
    print(
        f"单帧：{result['frame_bytes']} 字节"
        f"（{result['frame_mib']:.2f} MiB）"
    )
    print(
        f"{camera['fps']} fps 数据量："
        f"{result['bandwidth_mib_s']:.2f} MB/s"
    )
    print(f"已写入 {target.name}")


if __name__ == "__main__":
    main()

脚本分成三段。load_camera 读取 JSON，检查必需字段是否齐全， 并拒绝非正数；compute 由像元尺寸与焦距计算视场角， 由分辨率与位深计算单帧字节数，再乘以帧率得到每秒数据量； main 把参数与结果合并写入 report.json， 并在终端打印一份可读的结果。

计算视场角使用 2 × arctan(传感器边长 / (2 × 焦距))。 水平方向用传感器宽度，垂直方向用传感器高度。单帧字节数按 宽 × 高 × 位深 / 8 计算；这里是 1280 × 1024 × 8 / 8 = 1,310,720 字节，也就是 1.25 MiB。30 fps 时每秒为 37.50 MiB。 本课输出的单位先写成 MB/s；7.2 会把发布后发现的这个 单位问题作为紧急修复，改成 MiB/s。数值本身按 1024 进制折算。

写启动脚本与说明

新建启动脚本，内容如下： 

#!/usr/bin/env bash
set -eu

cd "$(dirname "$0")"
python3 compute.py camera.json

第一行指定用 Bash 执行；set -eu 让脚本在命令失败或使用未定义 变量时立即退出；cd "$(dirname "$0")" 切换到脚本所在目录， 因此无论从哪个目录调用，camera.json 都能被找到。 最后一行调用计算脚本。

给启动脚本加上执行权限： 

chmod +x run.sh

chmod +x 只增加执行位，不改变文件内容。之后可以直接运行 启动脚本；如果不加执行权限，则需要用 bash 加上脚本名调用。 第 1 部分的权限一课讲过 chmod 与权限位的读法，这里不再展开。

7.2从功能分支到 V1.1

7.1 的工程只有 master 与一次提交。这一课在它上面按 2.6 的 分支规范走一遍：develop 汇集开发，功能分支只做一件事， 发布分支准备版本，紧急修复处理发布后的问题，最后得到 V1.0 与 V1.1 两个附注标签。所有操作都在本机仓库里，不推送，也不配置远程仓库。

开始前确认当前在工程目录、工作区干净： 

cd ~/tup-practice/camera-demo
git status --short
git log --oneline --decorate -1
0054672 (HEAD -> master) feat: 建立相机参数小工程

git status --short 没有输出，表示没有未提交的改动。 后面的提交号与合并结果都会因读者机器上的时间、身份与 Git 版本不同， 但分支名、标签名与每一步的文件变化应当一致。

先建开发分支

从 master 拉出开发分支： 

git switch -c develop
Switched to a new branch 'develop'

develop 与 master 现在指向同一个提交， 工程文件没有变化。这条分支用来汇集内部版本；功能分支从它拉出， 完成后再合回它。查看分支： 

git branch
* develop
  master

功能分支：12 mm 焦距

从开发分支拉出功能分支： 

git switch -c feature/focal-12mm
Switched to a new branch 'feature/focal-12mm'

这一条分支只做一件事：把焦距从 8 mm 改为 12 mm。焦距改变后， fx 与 fy 也要随之改变，否则内参与焦距不一致。 用 sed -i 直接修改三行： 

sed -i 's/"focal_mm": 8.0/"focal_mm": 12.0/' camera.json
sed -i 's/"fx": 800.0/"fx": 1200.0/' camera.json
sed -i 's/"fy": 800.0/"fy": 1200.0/' camera.json
grep -E '"(focal_mm|fx|fy)"' camera.json
  "focal_mm": 12.0,
  "fx": 1200.0,
  "fy": 1200.0,

sed -i 会在原文件上替换匹配到的文本，不产生备份文件。 三条命令分别替换焦距、fx 与 fy；模式里的空格 与引号必须与文件一致。若文件已经被其他编辑改动过，sed 可能找不到匹配，这时用编辑器改这三个值，结果相同。

切回开发分支并合并。使用 --no-ff 保留一条明确的合并提交， 这样历史里能看出功能分支曾经独立存在： 

git switch develop
git merge --no-ff feature/focal-12mm -m "合并功能分支 feature/focal-12mm"
Switched to branch 'develop'
Merge made by the 'ort' strategy.

 1 file changed, 3 insertions(+), 3 deletions(-)

查看合并后的历史： 

git log --graph --oneline --decorate --all
*   5236f68 (HEAD -> develop) 合并功能分支 feature/focal-12mm
|\
| * 622827d (feature/focal-12mm) feat: 试用 12 mm 焦距

合并提交在 develop 上，功能分支的提交在右侧；两条线在 初始提交处汇合。--no-ff 的作用是即使可以快进也生成合并提交， 保留分支结构。功能分支已经合入开发分支，按 2.6 的约定立即删除： 

git branch -d feature/focal-12mm
Deleted branch feature/focal-12mm (was 622827d).

-d 只删除已经合并的分支；如果分支还有未合并的提交， Git 会拒绝删除。这里不使用 -D，因为那会丢弃尚未合并的内容。

发布分支与 V1.0

功能集成后，从开发分支拉出发布分支： 

git switch -c release/v1.0
Switched to a new branch 'release/v1.0'

发布分支只做发布前的准备与修补，不再加入新功能。这里在说明文件末尾 补一段发布说明： 

cat >> README.md <<'EOF'

## V1.0 发布说明

- 相机 A 的焦距改为 12 mm，`fx` 与 `fy` 同步改为 1200。
- 视场角与数据量由 `compute.py` 重新计算。
EOF

>> 表示追加，<<'EOF' 表示把下面到 EOF 为止的文本交给 cat；单引号让内容按原样写入， 不展开变量。提交这次修改： 

git add README.md
git commit -m "docs: 补充 V1.0 发布说明"
[release/v1.0 119829f] docs: 补充 V1.0 发布说明
 1 file changed, 5 insertions(+)

发布分支测试通过后，切到主分支合入，并打附注标签： 

git switch master
git merge --no-ff release/v1.0 -m "合并发布分支 release/v1.0"
git tag -a v1.0 -m "发布 V1.0：12 mm 焦距版本"
git tag -n
Switched to branch 'master'
Merge made by the 'ort' strategy.
 README.md   | 5 +++++
 camera.json | 6 +++---
 2 files changed, 8 insertions(+), 3 deletions(-)
v1.0            发布 V1.0：12 mm 焦距版本

git tag -a 创建带说明的附注标签；git tag -n 显示标签及其说明。标签指向的是主分支上的这次合并提交，不是发布分支的 末端。发布分支上的修补还要合回开发分支： 

git switch develop
git merge --no-ff release/v1.0 -m "同步发布分支的修改"
Switched to branch 'develop'
Merge made by the 'ort' strategy.
 README.md | 5 +++++
 1 file changed, 5 insertions(+)

发布分支的内容已经同时进入主分支与开发分支，可以删除： 

git branch -d release/v1.0
Deleted branch release/v1.0 (was 119829f).

紧急修复与 V1.1

发布之后发现一个单位问题：输出里的数据量按 1024 进制折算， 却写成了 MB/s。线上问题要从主分支拉紧急修复分支， 修完合回主分支，再同步到开发分支。先切到主分支： 

git switch master
git switch -c hotfix/unit-label
Switched to branch 'master'
Switched to a new branch 'hotfix/unit-label'

只改输出单位，不动计算： 

sed -i 's|MB/s|MiB/s|' compute.py
grep -n 'MiB/s' compute.py
92:        f"{result['bandwidth_mib_s']:.2f} MiB/s"

最终只剩下 develop 与 master 两条长期分支， 两个附注标签都在主分支的历史上。两条分支的文件内容应当一致， 但两条分支上的提交历史不同；用下面的命令比较内容： 

git diff master..develop

这条命令没有输出，说明两条分支的最终文件内容没有差异。 如果输出不为空，先检查是否还有未合并的提交，不要直接删除分支或覆盖文件。

  • 功能分支从 develop 拉出，合回 develop 后删除；
  • 发布分支从 develop 拉出，合入 master 并打 v1.0，再同步回 develop 后删除；
  • 紧急修复从 master 拉出，合入 master 并打 v1.1，再同步回 develop 后删除；
  • 最终两条长期分支内容一致，工作区干净，没有远程仓库与推送操作。

你现在能做什么：按队内分支规范建立开发分支、功能分支、 发布分支与紧急修复分支，使用 --no-ff 合并，打附注标签， 在合并后删除分支，并从最终的分支、标签与工作区状态核对发布流程。
