7.1把脚本拆成包

当一个脚本同时负责读文件、计算统计量和打印结果时，任何一处改动都可能 影响其他环节。工程化的第一步是按职责拆分：读取放在一个模块，计算放在 另一个模块，入口只负责组织流程。拆分后，读取与计算可以单独导入、单独 测试，命令行入口也更容易替换。

这一课建立一个测量报告工程：数据文件放在 data 目录，包目录 里放包的说明、读取模块、统计模块与入口模块。最后从工程目录用 python3 -m 运行，观察包内导入与路径解析。

工程目录

本课建立的包（package）是带 __init__.py 的目录。这个文件 可以为空，也可以放包的说明与公开接口；它的存在让 Python 把目录当作包 处理。入口模块（entry module）名为 __main__.py，用 python3 -m 包名 运行时，Python 会找到并执行这个文件。

例子把工程分成四部分：depth_report/__init__.py 说明包， depth_report/io.py 读取 CSV，depth_report/stats.py 计算汇总与筛选，depth_report/__main__.py 组织输出。数据文件 单独放在 data/measurements.csv，与代码分离，便于替换数据而 不改程序。

包的导入

包内模块之间用相对导入：from .io import read_measurements 里的点表示当前包，from .stats import near, summarize 同理。 相对导入要求模块作为包的一部分被导入；直接执行 python3 depth_report/__main__.py 时，入口文件被当成顶层 脚本，没有包上下文，相对导入会失败。

正确方式是在工程目录执行 python3 -m depth_report。这时 Python 把当前目录加入模块搜索路径，找到 depth_report 包， 执行包内的 __main__.py，相对导入可以解析。工程目录应当是 包目录的上一级，而不是包目录本身。

入口与路径

入口模块用 Path(__file__).resolve().parent.parent / "data" / "measurements.csv" 定位数据文件。__file__ 是当前模块 的文件路径，resolve() 转成绝对路径并解析符号链接， parent 从入口文件所在目录向上两级，得到工程目录，再拼出 数据路径。

这种写法不依赖当前工作目录：无论从哪里启动，只要包能被导入，数据路径 都指向工程内的文件。打印结果时只输出数据内容与统计值，不输出绝对路径， 输出更简洁，也不会暴露运行环境的目录结构。

数据与容错

read_measurements 先读表头，再逐行读取。空行跳过；字段数 不是三段的行跳过；深度或面积不能转成浮点数的行也跳过。表头必须正好是 name,depth,area，否则抛出 ValueError，让格式 问题尽早暴露。

summarize 接收行列表，返回行数、平均深度与最大面积；空列表 返回计数 0 与两个 0.0，避免除零。near 按深度阈值筛选名字。 读取与统计分开后，统计函数可以直接用构造的列表测试，不需要准备文件。

例题 · 分解测量报告

题目：建立一个测量报告包，包内分读取、统计、入口三个模块；数据文件包含表头、五行记录与一个空行；从工程目录用模块方式运行，打印记录数、平均深度、最大面积与深度不超过 12 的样本名。

包说明文件：

"""按深度与面积汇总测量记录的示例包。"""

读取模块：

def read_measurements(path):
    rows = []
    with open(path, encoding="utf-8") as handle:
        header = handle.readline().strip().split(",")
        if header != ["name", "depth", "area"]:
            raise ValueError("unexpected header")
        for line in handle:
            line = line.strip()
            if not line:
                continue
            parts = line.split(",")
            if len(parts) != 3:
                continue
            name, depth_text, area_text = parts
            try:
                depth = float(depth_text)
                area = float(area_text)
            except ValueError:
                continue
            rows.append((name, depth, area))
    return rows

统计模块：

def summarize(rows):
    if not rows:
        return {"count": 0, "mean_depth": 0.0, "max_area": 0.0}
    depths = [row[1] for row in rows]
    areas = [row[2] for row in rows]
    return {
        "count": len(rows),
        "mean_depth": sum(depths) / len(depths),
        "max_area": max(areas),
    }


def near(rows, limit):
    return [row[0] for row in rows if row[1] <= limit]

7.2命令行入口与子命令

包把读取与统计拆开之后，入口仍然是一段固定流程：数据文件写死，输出 只有一种。换文件、换阈值或只取一部分结果时，仍然要改源码。这一课在 包内增加命令行入口，由入口解析子命令与选项，再调用包里的函数；包保持 不变，入口负责选择与输出。上一课的 __main__.py 保留为固定 报告，本课的 cli.py 是同一包内另一个入口，按子命令调用 同一组读取与统计函数。

入口与包的分工

命令行入口写成包内的 cli.py，从工程目录用 python3 -m depth_report.cli 运行。模块方式让 cli.py 仍在包的上下文里，开头的 from .io import read_measurements 这类相对导入可以解析； 直接执行文件路径时，模块被当成顶层脚本，相对导入会失败。

入口只承担建立解析器、解析命令行与分派三项职责。参数声明、类型转换与 帮助文本交给 argparse，读取与统计仍留在 io.py 和 stats.py；调整统计规则不必改动入口，增加子命令也不必 复制读取代码。

子命令与分派

add_subparsers(dest="command", required=True) 建立子命令 （subcommand）层：dest 把子命令名存进 args.command，required=True 要求必须给出一个 子命令。每个 sub.add_parser 拥有自己的参数与帮助； set_defaults(handler=...) 把处理函数（handler）绑到解析 结果。 

parser = argparse.ArgumentParser(prog="tool")
sub = parser.add_subparsers(dest="command", required=True)
hello = sub.add_parser("hello")
hello.add_argument("name")
hello.set_defaults(handler=run_hello)

解析完成后调用 args.handler(args) 即可分派。主流程不必写 if args.command == ... 的长链；增加子命令时，只需注册新的 解析器与处理函数。

共享选项与路径

两个子命令都要读同一个 CSV，公共选项 --data 写进一个 add_help=False 的父解析器（parent parser），再通过 parents=[common] 传给每个子命令。父解析器只提供参数定义， 不单独解析命令行；add_help=False 让它不生成 -h，子命令各自保留帮助，避免选项冲突。 

common = argparse.ArgumentParser(add_help=False)
common.add_argument("--data", type=Path, default=DATA)
sub.add_parser("summary", parents=[common])
sub.add_parser("near", parents=[common])

两个子命令都接受 --data，省略时取父解析器里的默认值。 实际工程中这个默认值用 Path(__file__).resolve().parent.parent / "data" / "measurements.csv" 按模块位置定位，不依赖当前工作目录； type=Path 把命令行文本转成路径对象，后续可以直接用 .name 取文件名。用户给出的相对路径按当前目录解析，绝对 路径按原样使用。

退出码与错误边界

summary 成功返回 0；near 没有匹配记录返回 1； 数据文件缺失或表头不符时，包里的 OSError 与 ValueError 会向上抛出，入口捕获后把错误写到标准错误并 返回 3。参数错误仍由 argparse 以 2 结束。调用者据此区分「输入有问题」 「没有结果」与「参数写错」。

错误在入口这一层统一处理：业务函数遇到无法继续的输入就抛出异常，由 main 转成一条错误信息与退出码。调用者只要检查返回值， 不必解析输出文本。

例题 · 测量记录工具

题目：为上一课的测量报告包增加命令行入口 cli.py，提供 summary 与 near 两个子命令；summary 打印文件名、记录数、平均深度与最大面积，near 按深度上限筛选样本；两个子命令共享 --data 选项，默认读取工程内的数据文件；从工程目录用模块方式运行 summary。

完整程序：

import argparse
import sys
from pathlib import Path

from .io import read_measurements
from .stats import near, summarize


DATA = Path(__file__).resolve().parent.parent / "data" / "measurements.csv"


def run_summary(args):
    report = summarize(read_measurements(args.data))
    print("%s: %d rows, mean depth %.2f, max area %.1f"
          % (args.data.name, report["count"], report["mean_depth"],
             report["max_area"]))
    return 0


def run_near(args):
    names = near(read_measurements(args.data), args.limit)
    print("near %.1f: %d" % (args.limit, len(names)))
    if names:
        print(", ".join(names))
    return 0 if names else 1


def build_parser():
    parser = argparse.ArgumentParser(prog="depth-report",
                                     description="inspect measurement records")
    common = argparse.ArgumentParser(add_help=False)
    common.add_argument("--data", type=Path, default=DATA,
                        help="CSV file with name, depth and area")
    sub = parser.add_subparsers(dest="command", required=True)

    summary = sub.add_parser("summary", parents=[common],
                             help="print count and depth/area statistics")
    summary.set_defaults(handler=run_summary)

    nearby = sub.add_parser("near", parents=[common],
                            help="list samples within a depth limit")
    nearby.add_argument("--limit", type=float, default=12.0)
    nearby.set_defaults(handler=run_near)
    return parser


def main(argv=None):
    args = build_parser().parse_args(argv)
    try:
        return args.handler(args)
    except (OSError, ValueError) as error:
        print("error:", error, file=sys.stderr)
        return 3


if __name__ == "__main__":
    raise SystemExit(main())

7.3单元测试 unittest

单元测试（unit test）把函数放在受控输入下运行，检查结果是否符合预期。 测试不依赖完整工程，也不需要手工打开文件；它可以反复执行，在修改后 快速发现回归。这一课用标准库 unittest 测试平均值函数， 覆盖正常值、单值与空列表三种情况。

测试函数与测试类

测试类继承 unittest.TestCase，测试方法名以 test_ 开头。运行器只收集这些方法，并按方法名排序执行。 每个测试方法应当独立：自己准备输入、调用被测函数、写断言，不依赖其他 测试留下的状态。

一个测试只检查一个行为。平均值函数的正常输入、单元素输入与空输入可以 写成三个方法，失败时能直接看出是哪一类情况出错。测试方法内部通常不 打印，结果由断言与运行器汇总。

断言与异常

assertEqual 检查两个值相等，assertAlmostEqual 检查浮点数在给定小数位内相等。浮点运算可能有微小误差，比较 4.0 这类结果时用 assertAlmostEqual 更稳妥。

with self.assertRaises(ValueError): 检查代码块是否抛出指定 异常。空列表求平均值应当抛出 ValueError；如果函数没有抛出， 这个测试会失败。断言异常类型，而不是只捕获所有异常，可以避免把其他 错误当成预期行为。

运行器与结果

unittest.defaultTestLoader.loadTestsFromTestCase 从测试类 收集所有 test_ 方法， unittest.TextTestRunner(...).run(suite) 执行并返回结果对象。 结果对象的 testsRun 是执行数量，failures 与 errors 分别是断言失败与异常错误，skipped 是跳过 数量，wasSuccessful() 返回整体是否通过。

失败与错误不同：断言不成立进入 failures，测试代码抛出未 预期的异常进入 errors。两者都表示测试没有通过，但排查方向 不同。结果对象还保存每个失败的文本说明，默认运行器会把它打印出来。

可重复的测试输出

默认运行器会打印一行 Ran 3 tests in 0.001s，其中的耗时随 机器与负载变化，不能逐字核对。把 stream 指向 io.StringIO，运行器把详细输出写进内存；脚本只取报告的 第一行，再自己打印数量与通过状态。

这样输出只包含报告第一行、数量与布尔结果，重复运行保持一致。真实项目 通常让运行器直接输出到终端，能完整看到报告；本课为了让输出可逐字核对， 才把报告捕获后重新组织。

例题 · 平均值测试

题目：为一个求平均值的函数写三个测试，分别覆盖正常列表、单元素列表与空列表；空列表应抛出 ValueError；用文本运行器执行测试，把报告写入内存，打印执行数、失败数、错误数、跳过数、整体结果与报告第一行。

完整程序：

import io
import unittest


def mean(values):
    if not values:
        raise ValueError("empty")
    return sum(values) / len(values)


class MeanTests(unittest.TestCase):
    def test_typical(self):
        self.assertAlmostEqual(mean([2, 4, 6]), 4.0)

    def test_single(self):
        self.assertEqual(mean([7]), 7.0)

    def test_empty(self):
        with self.assertRaises(ValueError):
            mean([])


def run_suite():
    suite = unittest.defaultTestLoader.loadTestsFromTestCase(MeanTests)
    stream = io.StringIO()
    result = unittest.TextTestRunner(stream=stream, verbosity=2).run(suite)
    print("tests run:", result.testsRun)
    print("failures:", len(result.failures))
    print("errors:", len(result.errors))
    print("skipped:", len(result.skipped))
    print("ok:", result.wasSuccessful())
    print("first line:", stream.getvalue().splitlines()[0])


if __name__ == "__main__":
    run_suite()

import unittest


def median(values):
    if not values:
        raise ValueError("empty")
    ordered = sorted(values)
    middle = len(ordered) // 2

    return (ordered[middle - 1] + ordered[middle]) / 2.0

import io
import unittest


def clamp(value, low, high):
    if low > high:
        raise ValueError("bad range")
    return max(low, min(value, high))


class ClampTests(unittest.TestCase):

    def test_high(self):
        self.assertEqual(clamp(20, 0, 10), 10)

    def test_bad_range(self):
        with self.assertRaises(ValueError):
            clamp(5, 10, 0)

7.4断言、性能与剖析

程序正确之后才值得比较快慢。这一课先用断言核对两种写法的结果一致， 再用性能剖析（profiling）查看函数调用次数，最后用基准计时（benchmark） 比较循环与公式，并只输出稳定的判断结果。

断言

assert condition, message 在条件为假时抛出 AssertionError，并带上说明文字。断言适合检查程序内部的 不变量，例如“两种算法的结果必须相同”“循环结束后累计值不为负”。它把 假设写进代码，出错时立即停在违反假设的位置。

断言不是用户输入校验。Python 以 -O 运行时移除 assert 语句，依赖断言的检查会消失；来自文件、命令行或网络 的输入应当用 if 加异常处理。例子只在内部结果对照处使用 断言。

调用次数与 cProfile

cProfile.Profile() 建立剖析器，enable() 开始 记录，disable() 停止。剖析结果可以用 pstats.Stats(profiler) 读取；stats.stats 是以 (文件名, 行号, 函数名) 为键的字典，值的前两项是原始调用 次数与总调用次数。

原始调用（primitive call）不计递归产生的重复进入；总调用（total call） 包含递归。普通函数被调用一次时两者都是 1；递归函数的总调用次数会明显 大于原始调用。例子只打印调用次数，不打印耗时，因为耗时随机器与负载 变化。

基准计时 timeit

timeit.timeit("表达式", globals=globals(), number=2000) 把 表达式执行指定次数并返回总秒数。globals 让表达式能访问 当前模块的函数；number 要足够大，使计时不受单次调度的 偶然波动影响，又不能让脚本等待过久。

比较两种写法时，分别计时，再比较两个总时间。脚本只打印哪一方更快， 不打印具体秒数；这样输出在不同机器上仍可逐字核对。若两者差距很小， 应增加次数或重复多轮，而不是根据一次结果下结论。

优化顺序

合理的顺序是：先确认结果正确，再用剖析找调用热点，再换算法或数据结构， 最后用计时验证。把循环换成公式属于算法层面的改变，通常比微调语法更 有效；在数据量很大时，还可以考虑向量化或使用更合适的容器。

每次优化后重新运行断言与测试，确保结果没有变化。只比较时间而不检查 结果，可能把错误实现当成更快版本。例子在计时前用断言核对循环与公式的 结果，再输出调用次数与快慢判断。

例题 · 循环与公式

题目：用循环与公式分别计算 0 到 999 的平方和；用断言确认两者相等；用剖析器统计循环函数的调用次数；用 timeit 各执行 2000 次，打印结果、原始调用次数、总调用次数、重复次数与更快的一方。

完整程序：

import cProfile
import pstats
import timeit


def sum_squares_loop(n):
    total = 0
    for value in range(n):
        total += value * value
    return total


def sum_squares_formula(n):
    return (n - 1) * n * (2 * n - 1) // 6


def profile_loop(n):
    profiler = cProfile.Profile()
    profiler.enable()
    result = sum_squares_loop(n)
    profiler.disable()
    stats = pstats.Stats(profiler)
    calls = 0
    primitives = 0
    for func, values in stats.stats.items():
        if func[2] == "sum_squares_loop":
            primitives, calls = values[0], values[1]
    return result, primitives, calls


result, primitives, calls = profile_loop(1000)
assert result == sum_squares_formula(1000)
number = 2000
loop_time = timeit.timeit("sum_squares_loop(1000)", globals=globals(),
                          number=number)
formula_time = timeit.timeit("sum_squares_formula(1000)", globals=globals(),
                             number=number)
print("result:", result)
print("primitive calls:", primitives)
print("calls:", calls)
print("repeats:", number)
print("faster:", "formula" if formula_time < loop_time else "loop")

循环与公式的结果都是 332833500，断言通过后才进入计时。循环函数在 剖析期间被调用一次，原始调用与总调用都是 1。两种写法各执行 2000 次， 公式更快，因此最后一行是 formula。

脚本没有打印具体秒数，只打印快慢判断，输出不随机器速度变化。若在 其他数据规模下公式不再占优，判断会相应改变，但结果断言仍会保护正确性。
