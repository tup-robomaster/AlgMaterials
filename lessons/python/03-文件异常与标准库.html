3.1文件读写与 with

文件是程序与磁盘之间的边界。读文件要把字节按某种编码解释成文本，写文件 要把文本编码回字节；打开的文件用完必须关闭，否则数据可能留在缓冲区里。 这一课从 with 与逐行读取开始，最后处理编码与换行带来的差异。

打开与关闭

open(path, mode, encoding) 返回文件对象。文本模式用 "r" 读、"w" 写、"a" 追加， "x" 只在文件不存在时创建；二进制模式在字母后加 b，读写的是 bytes，不接受 encoding。 写模式会截断已有文件，追加模式保留原内容并在末尾写入。 

with Path("素材/synth_notes.txt").open(encoding="utf-8") as handle:
    text = handle.read()

with open(...) as handle: 在代码块结束时关闭文件，即使块内 抛出异常也会关闭。手工调用 close() 一旦中途返回或报错就容易 漏掉，因此文件操作一律用 with。文件对象关闭后再读写会抛出 ValueError。

逐行读取

文件对象可以直接放进 for 循环，每次得到一行，行尾保留 \n。逐行处理的内存占用与单行长度相关，不随文件总大小增长， 适合读日志与表格。read() 一次读回整个文件， readline() 读一行，readlines() 把所有行读成 列表；文件很大时这三种写法都会占用较多内存。 

with Path("素材/synth_notes.txt").open(encoding="utf-8") as handle:
    lines = [line.rstrip() for line in handle]

行首行尾的空白用 strip() 去掉，需要保留行内空格时用 rstrip("\n")。表头通常先读一次再进入循环： next(handle) 取走第一行，后面的循环从数据行开始。 空行也会被当成一行，处理前要判断 if not text:。

写入与追加

handle.write(text) 返回写入的字符数，不会自动补换行； 需要分行时自己写 "\n" 或用 writelines 传入 带换行的字符串列表。Path.write_text(text, encoding="utf-8") 是一次性写入的简写，内部同样会打开、写入并关闭文件，适合结果不大的场合。 

path = Path("note.txt")
path.write_text("alpha\n", encoding="utf-8")

with path.open("a", encoding="utf-8") as handle:
    handle.write("beta\n")

写入前要确认父目录存在。Path("out").mkdir(parents=True, exist_ok=True) 会创建缺失的各级目录，已存在时不报错。覆盖原文件 之前先确认路径；需要保留旧结果时改用追加模式或带序号的新文件名。

编码与换行

文本模式必须约定编码，课程统一使用 UTF-8，并在每次打开时显式写出。 编码不一致时，读入的中文会变成乱码，或者抛出 UnicodeDecodeError。二进制文件不要用文本模式打开， 图像、压缩包与自定义协议都按字节处理。 

text = "分数表"
data = text.encode("utf-8")
print(data.hex())
print(data.decode("utf-8"))
try:
    data.decode("ascii")
except UnicodeDecodeError:
    print("ascii failed")
e58886e695b0e8a1a8
分数表
ascii failed

不同系统的换行符不同，Python 读文本时默认做换行转换。处理 CSV 时应写 open(..., newline="")，把换行交给 CSV 模块管理，避免多出 空行。自己写文本时统一写 \n，读回后用 splitlines() 拆行，它不保留行尾换行符。

例题 · 读取分数表

题目：逐行读取 素材/synth_scores.csv，跳过表头、空行与格式不对的行，统计有效行数、跳过数、总分与平均分，并把汇总写到 out_summary.txt。

完整程序：

from pathlib import Path

source = Path("素材/synth_scores.csv")
rows = []
skipped = 0
with source.open(encoding="utf-8") as handle:
    next(handle)
    for line in handle:
        text = line.strip()
        if not text:
            skipped += 1
            continue
        parts = text.split(",")
        if len(parts) != 3:
            skipped += 1
            continue
        name, subject, score_text = parts
        try:
            score = int(score_text)
        except ValueError:
            skipped += 1
            continue
        rows.append((name, subject, score))

total = sum(score for _, _, score in rows)
summary = [
    f"rows: {len(rows)}",
    f"skipped: {skipped}",
    f"total: {total}",
    f"mean: {total / len(rows):.2f}",
]
text = "\n".join(summary)
Path("out_summary.txt").write_text(text + "\n", encoding="utf-8")
print(text)
print("wrote:", Path("out_summary.txt").name)

3.2异常与错误处理

程序遇到无法继续的情况时抛出异常（exception），调用栈逐层向上寻找处理 代码。没有处理就打印回溯（traceback）并退出。这一课讲清常见异常类型、 try 的四个分支、自定义异常与批处理中的跳过策略。

常见异常

所有内置异常都继承自 BaseException，日常处理的是 Exception 这一支。ValueError 表示值不合适， 例如 int("oops")；TypeError 表示类型不支持该 操作；KeyError 是字典缺少键；IndexError 是序列 下标越界；FileNotFoundError 是文件不存在； ZeroDivisionError 是除数为零。

回溯从下往上读：最后一行是异常类型与消息，上面是抛出位置与调用链。 定位问题时先看最后一行，再看最靠近自己代码的那一帧。 FileNotFoundError 属于 OSError， KeyError 与 IndexError 都属于 LookupError；捕获父类会连带捕获子类，范围要按需要收窄。

try 的分支

try 包住可能出错的语句，except 捕获指定异常， else 在没有异常时执行，finally 无论是否出错都 执行。else 用来放“只有成功后才做”的后续步骤， 避免把无关语句也放进 try 而被同一个 except 误捕；finally 用来关闭资源或记录收尾。 

try:
    value = int("12x")
except ValueError as error:
    print("bad:", error)
else:
    print("ok:", value)
finally:
    print("done")
bad: invalid literal for int() with base 10: '12x'
done

捕获时写出具体类型并绑定异常对象：except ValueError as error:。 裸 except: 会连键盘中断与程序退出一起吞掉，也会掩盖真正的 编程错误。捕获后要么处理，要么用 raise 重新抛出；吞掉异常 再继续，问题会以更远的形式出现。

抛出与自定义异常

raise ValueError("score must be 0..100") 主动抛出一个异常， 消息要写清哪个值、违反了哪条规则。需要区分“输入格式不对”与“程序内部 错误”时，可以定义自己的异常类： class ScoreError(ValueError): pass。继承 ValueError 让调用方既能按自定义类型捕获，也能按值错误统一 处理。 

class ScoreError(ValueError):
    """分数行格式不对。"""


def parse_score(text):
    if "," not in text:
        raise ScoreError("expected name,score")
    name, score = text.split(",")
    return name, int(score)


def parse_int(text):
    try:
        return int(text)
    except ValueError as error:
        raise ScoreError("score is not an integer") from error


print(parse_score("alpha,92"))
try:
    parse_score("alpha")
except ScoreError as error:
    print(type(error).__name__, error)
('alpha', 92)
ScoreError expected name,score

在 except 中抛出另一种异常时写 raise ScoreError(...) from error，保留原始异常作为原因， 回溯里会同时显示两层。若只是想补充上下文，可以重新抛出原异常； 若已经能处理，就不要抛出。

批处理与退出码

批量处理数据时，单行失败不应终止整个任务。把每行的解析放进 try，成功加入结果列表，失败记录行号与原因，循环继续。 最后打印成功与失败数量，读者能判断这批数据是否可用。 finally 可以逐行打印进度或清理临时状态。

整个程序失败时用 sys.exit(1) 或让异常冒泡，退出码非零， 调用脚本的上层程序才能察觉。全部成功返回 0；参数错误通常用 2。 退出码与日志消息一起看，才知道失败发生在哪一步。

例题 · 逐行校验分数

题目：定义 ScoreError，校验“名字,分数”行：字段数、空名字、整数转换与 0 到 100 的范围；逐行处理五条输入，记录成功与失败，并在每行结束时打印检查进度。

完整程序：

class ScoreError(ValueError):
    """分数行格式不对。"""


def parse_score(line):
    parts = line.split(",")
    if len(parts) != 2:
        raise ScoreError(f"expected 2 fields, got {len(parts)}")
    name, text = parts
    name = name.strip()
    if not name:
        raise ScoreError("empty name")
    try:
        score = int(text)
    except ValueError as error:
        raise ScoreError(f"score is not an integer: {text.strip()}") from error
    if not 0 <= score <= 100:
        raise ScoreError(f"score out of range: {score}")
    return name, score


lines = ["alpha,92", "beta,oops", "", "gamma,105", "delta,66"]
ok = []
failed = []
for number, line in enumerate(lines, start=1):
    try:
        ok.append(parse_score(line))
    except ScoreError as error:
        failed.append((number, str(error)))
    finally:
        print("checked:", number)

print("ok:", ok)
print("failed:", len(failed))
for number, message in failed:
    print(" ", number, message)
print("counts:", len(ok), len(failed))

3.3pathlib 与目录遍历

pathlib 把路径表示成对象，拼接、取文件名、判断类型与遍历 目录都变成方法调用，不必手动拼字符串。这一课用 Path 遍历 素材目录，按后缀分组、打印大小，并把清单写到结果目录。

构造与拼接

Path("素材") 创建相对路径，Path("/tmp") 创建 绝对路径。路径之间用斜杠拼接：Path("素材") / "synth_notes.txt"， 斜杠由 pathlib 按当前系统处理，代码里不必区分分隔符。 Path.cwd() 是当前工作目录，Path.home() 是用户 主目录，resolve() 把相对路径转成绝对路径并消除 .. 与符号链接。 

root = Path("素材")
path = root / "synth_notes.txt"

相对路径按当前工作目录解析，而不是按脚本文件所在目录解析。从不同目录 运行同一个脚本，相对路径可能指向不同位置；需要固定基准时，用 Path(__file__).parent 取脚本所在目录，再拼出素材路径。

查询属性

exists() 判断路径是否存在，is_file() 与 is_dir() 区分文件与目录。路径本身的组成部分用 name（带扩展名）、stem（去掉最后一个扩展名）、 suffix（最后一个扩展名，带点）、parent （上一级目录）读取；suffixes 返回全部扩展名。 

path = Path("素材/synth_notes.txt")
path.name
path.stem
path.suffix
path.parent

stat() 返回文件状态，st_size 是以字节为单位的 大小，st_mtime 是修改时间。目录本身也有状态，取大小前先用 is_file() 筛掉目录。路径可以不指向真实文件，查询属性不会 因为不存在而报错；真正读写时才会抛出 FileNotFoundError。

遍历与筛选

iterdir() 逐项列出目录内容，glob(pattern) 按 通配符筛选当前目录，rglob(pattern) 递归筛选子目录。 三者都返回迭代器，顺序由文件系统决定，输出前应 sorted， 否则同一份素材在不同机器上的打印顺序可能不同。 

for path in sorted(Path("素材").glob("*.txt")):
    name = path.name
    size = path.stat().st_size

筛选通常写成生成器表达式： sorted(path for path in root.iterdir() if path.suffix == ".png")。 只要文件时加 path.is_file()；要按名字排序时用 key=lambda path: path.name。遍历大目录时不要一次转成列表， 边遍历边处理可以降低内存占用。

创建与改名

3.4CSV、JSON 与 YAML 配置

表格常用 CSV，结构化配置常用 JSON 或 YAML。三种格式都只是文本，读进来 之后要自己转换类型、补默认值并校验范围。这一课用成绩表与一份 YAML 配置 走完读取、合并、校验与写出的全过程。

CSV 读写

csv.reader 把每行拆成字符串列表，csv.DictReader 用第一行作表头，把每行变成字典。所有字段都是字符串， "92" 需要 int 转换后才能比较大小；空行通常被 跳过，字段数多于表头时多出的部分放在键 None 下。 

with Path("素材/synth_scores.csv").open(encoding="utf-8", newline="") as handle:
    rows = list(csv.DictReader(handle))

写入用 csv.writer 或 csv.DictWriter。打开文件时 写 newline=""，把换行交给 CSV 模块处理，否则在部分系统上会 多出空行。字段顺序由 fieldnames 决定，写表头用 writeheader()。字段里含逗号、引号或换行时，模块会自动加 引号并转义，不要自己拼分隔符。

JSON 读写

json.load(handle) 从文件读，json.loads(text) 从字符串读；json.dump 与 json.dumps 负责写出。 JSON 支持对象、数组、字符串、数字、布尔与 null，读进 Python 后分别对应字典、列表、字符串、整数或浮点数、布尔与 None。 

text = json.dumps({"fps": 30, "width": 640}, ensure_ascii=False)
data = json.loads(text)

写出中文时加 ensure_ascii=False，否则中文会被转成 \uXXXX 转义；加 indent=2 便于人读， sort_keys=True 让键顺序稳定，便于比较两次输出。JSON 不允许 注释与尾随逗号，格式错误会抛出 json.JSONDecodeError。

YAML 读取

YAML 用缩进表示层级，支持映射、列表与标量，写起来比 JSON 简洁。读取用 yaml.safe_load(text)，它只构造字典、列表、字符串、数字、 布尔与空值这些安全类型，不执行配置里的任意对象构造。不要使用不带 Loader 的 yaml.load()，也不要开启自定义标签。 

text = Path("素材/synth_config.yaml").read_text(encoding="utf-8")
data = yaml.safe_load(text)

缩进必须一致，冒号后要有空格，列表项以短横线加空格开头。一份配置读进来 通常是一个字典，顶层键对应各个配置段。YAML 的数字与布尔会保留类型， 例如 false 读成 False，0.55 读成浮点数，这一点与 CSV 全为字符串不同。

校验与默认值

配置文件来自外部，字段可能缺失、类型可能不对。先准备一份默认配置，再把 读到的字典逐层合并：字典键递归更新，标量直接覆盖。合并后检查必需字段是否 存在、类型是否正确、数值是否落在允许范围；发现问题时抛出带键名的 ValueError，让使用者知道改哪一项。

校验通过后再写出摘要。摘要里保留完整配置与统计结果，用 json.dumps(..., ensure_ascii=False, indent=2, sort_keys=True) 写文件，屏幕上也打印一份便于核对。默认值与读入值分开保存，下次调整默认值 时不会把用户配置一起改掉。

3.5argparse 与命令行工具

命令行工具把输入、筛选条件与输出位置交给使用者选择，而不是改源码。 argparse 负责声明参数、解析命令行、生成帮助并在参数错误时 给出提示。这一课把上一课的成绩表读入改成带参数的工具。

建立解析器

argparse.ArgumentParser(description="...") 创建解析器， add_argument 逐个声明参数，parse_args() 读取 sys.argv 并返回一个命名空间对象。位置参数直接写名字， 可选参数以 -- 开头；解析结果用 args.input、 args.top 这样的属性读取。 

parser = argparse.ArgumentParser(description="统计分数表")
parser.add_argument("--top", type=int, default=2)
args = parser.parse_args()

省略 --top 时 args.top 取默认值 2，写成 --top 5 时为整数 5。

prog 指定帮助里显示的程序名，help 给每个参数写 一句说明，description 说明工具做什么。参数名里的短横线在 属性名中变成下划线：--min-score 对应 args.min_score。

参数类型与默认值

命令行参数默认是字符串，需要整数时写 type=int，需要浮点数 时写 type=float。转换失败时解析器打印用法并以退出码 2 结束。 default 指定省略参数时的值，choices 限定取值 范围，nargs="+" 让一个参数接收多个值。 

parser = argparse.ArgumentParser()
parser.add_argument("--top", type=int, default=2)
parser.add_argument("--mode", choices=["fast", "full"], default="fast")
parser.add_argument("--input", nargs="+")

store_true 适合开关，省略时为 False，出现时为 True。默认值应写成使用者无需额外输入也能得到合理结果的取值； 需要强制给出的参数不要设默认值，让解析器在缺失时报错。

main 与退出码

把参数解析与业务逻辑放进 main(argv=None)，argv 为 None 时读取真实命令行，传入列表时读取该列表，测试与演示 都不必改 sys.argv。函数成功返回 0，失败返回非零整数。

文件末尾写 if __name__ == "__main__": raise SystemExit(main())。 SystemExit 把返回值交给解释器作为进程退出码，模块被导入时 则不执行。业务函数与命令行入口分开后，其他脚本可以直接导入并调用 main(["--top", "2"])。

帮助与错误

--help 由解析器自动生成，列出用法、位置参数、可选参数与 默认值，执行后以 0 退出。缺少必需参数、类型转换失败或取值不在 choices 中时，解析器把用法与错误写到标准错误，并以 2 退出。

测试错误分支时可以传入 parse_args 一个列表，并用 contextlib.redirect_stderr 捕获错误文本，再用 SystemExit 的 code 属性核对退出码。这样不会 真的终止当前程序，也不会在终端里留下多余的帮助信息。

例题 · 统计工具

题目：把成绩统计写成命令行工具，支持 --input、--top、--min-score 与 --output；读取 CSV，筛选达到最低分的记录，按分数取前几名，把结果写到指定文件。

import argparse
import csv
from pathlib import Path


def build_parser():
    parser = argparse.ArgumentParser(description="统计分数表")
    parser.add_argument("--input", default="素材/synth_scores.csv")
    parser.add_argument("--top", type=int, default=2)
    parser.add_argument("--min-score", type=int, default=60)
    parser.add_argument("--output", default="out_stats.txt")
    return parser


def read_scores(path):
    scores = []
    with Path(path).open(encoding="utf-8", newline="") as handle:
        for row in csv.DictReader(handle):
            try:
                scores.append((row["name"], int(row["score"])))
            except (TypeError, ValueError):
                continue
    return scores


def main(argv=None):
    args = build_parser().parse_args(argv)
    scores = read_scores(args.input)
    passed = [(name, score) for name, score in scores if score >= args.min_score]
    top = sorted(passed, key=lambda item: item[1], reverse=True)[:args.top]
    lines = [f"input: {Path(args.input).name}", f"passed: {len(passed)}"]
    lines += [f"{name}:{score}" for name, score in top]
    text = "\n".join(lines)
    Path(args.output).write_text(text + "\n", encoding="utf-8")
    print(text)
    print("output:", Path(args.output).name)
    return 0


if __name__ == "__main__":
    raise SystemExit(main())

3.6logging 与调试输出

print 适合让人当场看见结果，日志（logging）适合记录程序 运行过程中发生了什么。日志带级别、时间与来源，可以同时写到终端和文件， 也可以按级别过滤。这一课用批处理任务演示控制台与文件两个输出目的地。

级别与记录器

日志级别从低到高是 DEBUG、INFO、 WARNING、ERROR、CRITICAL。 记录器（logger）设置的级别是门槛，低于它的记录直接丢弃；处理器 （handler）还有自己的级别，可以进一步过滤。两级门槛同时生效， 最终是否输出取更严格的那一个。 

import logging


logging.basicConfig(level=logging.INFO,
                    format="%(levelname)s %(message)s")
logging.debug("细节")
logging.info("开始处理")
logging.warning("跳过一行")
INFO 开始处理
WARNING 跳过一行

用 logging.getLogger("batch") 取具名记录器，名字通常用模块名 __name__。记录器默认把记录交给父记录器，最终到达根记录器； 自己挂了处理器之后，把 propagate 设为 False， 避免同一条记录被打印两次。setLevel 只在记录器上设置一次， 不要在每次调用前重复设置。

处理器与格式

StreamHandler(sys.stdout) 写到标准输出， FileHandler(path, encoding="utf-8") 写到文件。每个处理器 可以有自己的级别与格式器（formatter）。格式串里的 %(levelname)s、%(name)s、%(message)s 分别填入级别名、记录器名与消息；需要时间时加 %(asctime)s，并在格式器里给出日期格式。 

logger = logging.getLogger("batch")
handler = logging.FileHandler("out_run.log", encoding="utf-8")
handler.setFormatter(logging.Formatter("%(levelname)s %(message)s"))
logger.addHandler(handler)
logger.setLevel(logging.DEBUG)
logger.info("start")

一条记录会依次经过记录器与各级处理器，处理器再调用格式器排版。文件处理器 默认追加写入，需要每次运行重新开始时传 mode="w"。程序结束前 调用 logging.shutdown() 刷新并关闭所有处理器，否则文件末尾 可能缺少最后几行。

延迟格式化

记录日志时把参数单独传给记录方法： logger.info("count=%d", count)。字符串格式化要等到记录确实 会被输出时才执行；级别被过滤掉时，这部分工作完全省去。用 f-string 先把 消息拼好再传进去，即使日志被丢弃，拼接也已经发生。

logger.debug("count=%d", count)
logger.info("count=%d", count)
INFO:batch:count=3

消息模板里的占位符数量要与参数一致，否则格式化阶段会抛出异常。需要记录 多个值时按顺序传参，或者用 %s 接收任意对象。日志消息面向 排错，写清动作与关键数值即可，不要把整份数据倒进一行。

记录异常

在 except 块里调用 logger.exception("...")， 会以 ERROR 级别记录消息，并自动附上当前异常的完整回溯。 它等价于 logger.error("...", exc_info=True)，只能用在异常 处理块内。回溯写入日志文件后，终端可以只留一行简短消息，细节去文件里查。 

logger = logging.getLogger("batch")
try:
    int("12x")
except ValueError:
    logger.exception("parse failed")

日志里不写个人路径、账号与主机名，也不把密码或令牌写进消息。需要定位 文件时写相对路径或文件名；需要标识一次运行，用任务名或批次号，而不是 当前用户的主目录。日志文件同样要控制大小，长期运行的工具应轮转或定期 清理。

例题 · 批处理日志

题目：处理四个文件名，跳过非 Python 文件，记录一次读取失败；控制台只显示消息，文件里保留级别与异常回溯，最后打印成功数、跳过数与日志的首尾行。

import logging
import sys
from pathlib import Path

LOG_PATH = Path("out_run.log")


def process(logger, file_logger, names):
    ok = skipped = 0
    for name in names:
        if not name.endswith(".py"):
            logger.warning("skip %s", name)
            skipped += 1
            continue
        if name == "bad.py":
            try:
                raise ValueError("cannot read bad.py")
            except ValueError as error:
                logger.error("failed %s: %s", name, error)
                file_logger.exception("failed %s", name)
            continue
        logger.info("ok %s", name)
        ok += 1
    return ok, skipped


def main():
    console = logging.StreamHandler(sys.stdout)
    console.setLevel(logging.INFO)
    console.setFormatter(logging.Formatter("%(levelname)s %(name)s %(message)s"))
    file_handler = logging.FileHandler(LOG_PATH, mode="w", encoding="utf-8")
    file_handler.setLevel(logging.DEBUG)
    file_handler.setFormatter(logging.Formatter("%(levelname)s %(message)s"))

    logger = logging.getLogger("batch")
    logger.setLevel(logging.DEBUG)
    logger.handlers[:] = [console, file_handler]
    logger.propagate = False

    file_logger = logging.getLogger("batch.file")
    file_logger.setLevel(logging.DEBUG)
    file_logger.handlers[:] = [file_handler]
    file_logger.propagate = False

    ok, skipped = process(logger, file_logger, ["a.py", "notes.txt", "bad.py", "b.py"])
    logger.info("done ok=%d skipped=%d", ok, skipped)
    logging.shutdown()

    lines = LOG_PATH.read_text(encoding="utf-8").splitlines()
    print("ok:", ok, "skipped:", skipped)
    print("log first:", lines[0])
    print("log last:", lines[-1])
    print("traceback logged:", any(line.startswith("Traceback") for line in lines))


if __name__ == "__main__":
    main()

3.7选学：二进制数据与帧解析

这一课是选学内容，处理不经文本编码的字节流。串口、网络与传感器协议通常 按固定字段排列字节，再用校验值确认传输没有出错。课程只使用合成字节， 不连接真实设备；读完后应能看懂帧头、长度、载荷与校验各自占哪几个字节。

字节与整数

bytes 是不可变的字节序列，bytearray 可变， memoryview 在不复制的前提下查看同一段内存。字节序列的每个 元素是 0 到 255 的整数，索引得到整数而不是长度为 1 的字符串； data.hex() 把它显示成十六进制字符串，便于抄写与比较。

多字节整数有字节序问题。int.from_bytes(data, "little") 按小端 解释，低字节在前；"big" 相反。 total.to_bytes(4, "little") 把整数写成固定长度。文本编码是 另一回事："A".encode("utf-8") 得到字节，解码失败会抛出 UnicodeDecodeError；二进制协议不经过这一步，直接按字段宽度 切分。 

data = bytes([0x07, 0x2C])
data.hex()
int.from_bytes(data, "big")
(70000).to_bytes(4, "little").hex()

data 的十六进制是 072c，按大端读成 1836； 70000 写成四字节小端是 70110100。

struct 打包

struct.pack(format, *values) 按格式串把数值排成字节， struct.unpack(format, data) 反向拆开，返回元组； struct.calcsize(format) 给出格式占用的字节数。常用格式字符 有 B（无符号 1 字节）、H（无符号 2 字节）、 I（无符号 4 字节）与 f（4 字节浮点数）。

格式串开头的 < 指定小端并取消对齐填充，> 指定大端。不加前缀时使用本机字节序，还可能插入填充字节，同样的字段在 不同机器上长度不同。协议文档写明字节序时，格式串也要写明； unpack 要求输入长度与 calcsize 完全一致， 多一个字节或少一个字节都会抛出 struct.error。 <BHIf 四个字段依次占 1、2、4、4 字节，共 11 字节。 

payload = struct.pack("<BHIf", 1, 300, 70000, 1.5)
struct.unpack("<BHIf", payload)
struct.calcsize("<BHIf")

校验与帧结构

CRC（cyclic redundancy check，循环冗余校验）把一段字节压成一个短校验值。 课程使用 CRC8，多项式 0x07，逐字节异或后处理 8 位； 同样的字节总得到同样的结果，任意一位改变通常会让结果不同。CRC 只负责 发现传输错误，不负责纠错，也不提供加密。 

def crc8(data):
    value = 0
    for byte in data:
        value ^= byte
        for _ in range(8):
            if value & 0x80:
                value = ((value << 1) ^ 0x07) & 0xFF
            else:
                value = (value << 1) & 0xFF
    return value


print(crc8(bytes([2, 1])))
45

合成帧的结构是：帧头 0xA5、载荷长度、命令字、载荷、CRC8。 长度字段只数载荷字节，整帧长度等于 4 + 长度。计算 CRC 的 范围是长度、命令与载荷，不包括帧头，也不包括校验字节本身。解析时先核对 长度，再核对 CRC，两项都通过才返回命令与载荷。

缓冲区与半包

接收端一次读到的字节数不固定：一帧可能分几次到达，也可能几帧连在一起。 解析器维护一个 bytearray，每次把新数据追加到末尾，然后循环 处理：找到帧头，丢掉帧头之前的噪声；不足两个字节时等待长度字段；不足整帧 长度时等待剩余字节；凑齐一帧就取出、解析并从缓冲区删除。

循环要一直跑到缓冲区里没有完整帧为止，剩余半帧留在缓冲区等下一次输入。 校验失败时记录错误并继续找下一帧，不能因为一帧坏掉就清空整个缓冲区。 缓冲区长期不增长需要设置上限，防止对端持续发送噪声导致内存占用上升。

HEADER = 0xA5


def crc8(data):
    value = 0
    for byte in data:
        value ^= byte
        for _ in range(8):
            if value & 0x80:
                value = ((value << 1) ^ 0x07) & 0xFF
            else:
                value = (value << 1) & 0xFF
    return value


def build_frame(command, payload):
    body = bytes([len(payload), command]) + payload
    return bytes([HEADER]) + body + bytes([crc8(body)])


def parse_frame(frame):
    length = frame[1]
    command = frame[2]
    payload = frame[3:3 + length]
    checksum = frame[3 + length]
    if len(frame) != 4 + length:
        raise ValueError("length mismatch")
    if crc8(frame[1:3 + length]) != checksum:
        raise ValueError("crc mismatch")
    return command, payload


class FrameParser:
    def __init__(self):
        self.buffer = bytearray()

    def feed(self, data):
        self.buffer.extend(data)
        frames = []
        while True:
            start = self.buffer.find(HEADER)
            if start < 0:
                self.buffer.clear()
                break
            if start:
                del self.buffer[:start]
            if len(self.buffer) < 2:
                break
            total = 4 + self.buffer[1]
            if len(self.buffer) < total:
                break
            raw = bytes(self.buffer[:total])
            del self.buffer[:total]
            try:
                frames.append(parse_frame(raw))
            except ValueError as error:
                frames.append(("error", str(error)))
        return frames

整帧共 7 字节，前两次追加后分别只有 2 与 5 字节，不足 4 + 长度，因此打印等待的字节数。第三次补齐剩余字节， 缓冲区凑满一帧，解析出命令 2 与三个载荷字节，并用 CRC8 核对通过。 缓冲区在取出整帧后被清空，不会影响下一帧。 

HEADER = 0xA5


def crc8(data):
    value = 0
    for byte in data:
        value ^= byte
        for _ in range(8):
            if value & 0x80:
                value = ((value << 1) ^ 0x07) & 0xFF
            else:
                value = (value << 1) & 0xFF
    return value


def build_frame(command, payload):
    body = bytes([len(payload), command]) + payload
    return bytes([HEADER]) + body + bytes([crc8(body)])


def parse_frame(frame):
    length = frame[1]
    command = frame[2]
    payload = frame[3:3 + length]
    return command, payload


buffer = bytearray()
frame = build_frame(0x02, b"\x01\x02\x03")

for part in (frame[:2], frame[2:5], frame[5:]):
    buffer.extend(part)
    total = 4 + buffer[1]
    if len(buffer) >= total:
        raw = bytes(buffer[:total])
        del buffer[:total]
        print(parse_frame(raw))
        print("crc ok:", crc8(raw[1:-1]) == raw[-1])
    else:
        print("waiting:", len(buffer))
