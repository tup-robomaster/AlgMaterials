开始

这一部分把练习目录、脚本运行、报错阅读与一个完整工具走通： 读完以后，读者应当能在命令行运行一个 Python 脚本，读懂 traceback 里 指向自己代码的那一帧，用 pathlib 遍历素材目录、用 OpenCV 读取图片尺寸，并把结果写入文件；同时知道从 C++ 带来的哪些习惯要改。

前置

课程假设读者已经会写基本的 C++ 程序：变量、循环、函数与数组， 能在命令行编译并运行一个源文件。

代码与输出约定

课里的 Python 代码块都标着语言与文件名，例如 data-name="0.2-hello.py"。页面上贴出的正文与 示例代码 中同名文件一致；文件开头可以有一段说明性注释， 页面上从第一条可执行语句开始贴。

代码块后面紧跟的输出块有两种标签。真实输出 是本机运行这份程序 得到的标准输出，逐字抄录；预期输出 是练习应当得到的结果。 比对时按行比较，行末空格不参与，行数与字符必须一致。若你的输出与 页面不同，先检查工作目录与素材路径，再逐行对照。

练习要求自己写一份脚本，文件名写在题目里，例如 0-1.py。 写完后在课程根目录运行 python3 0-1.py，把输出与页面上的 预期输出对照。答案放在 示例代码/答案 中，页面上折叠显示； 先独立完成，再展开对照。

终端代码块中的命令都从课程根目录开始执行。以 $ 开头的行 表示提示符，不需要输入。

0.2第一个脚本

这一课运行第一个脚本，并说明一个 Python 文件的最小结构。

写出并运行

新建一个文本文件，写入下面三行输出。文件名使用 0.2-hello.py； Python 习惯用 .py 作为扩展名，文件名中间可以出现点号。

例题 · 第一个脚本

题目：打印问候，计算 3 + 4 与 7 / 2。程序放在一个函数里，由文件末尾的判断调用。

完整程序：

def main():
    print("hello, TUP")
    print("3 + 4 =", 3 + 4)
    print("7 / 2 =", 7 / 2)


if __name__ == "__main__":
    main()

运行：

python3 示例代码/0.2-hello.py
hello, TUP
3 + 4 = 7
7 / 2 = 3.5

print 用逗号分隔多个参数，输出时在每个参数之间补一个空格。 3 + 4 是整数加法，结果是 7； 7 / 2 是浮点除法，结果是 3.5，不是 C++ 整数相除得到的 3。

脚本结构

上面的文件分三段。第一段 def main(): 定义一个函数； 函数体缩进四个空格，函数在定义时并不执行。第二段 if __name__ == "__main__": 判断当前文件是不是被直接运行： 直接运行时条件成立，调用 main()；被别的文件导入时条件不成立， 只提供函数，不产生输出。第三段是空行，用来分隔顶层语句。

缩进是语法的一部分。同一个代码块必须使用相同的缩进量，通常统一用四个 空格；不要混用制表符与空格。行尾不需要分号，语句结束就是换行。 # 之后到行尾是注释，解释器忽略。

运行与退出码

在终端运行脚本后，可以用 echo $? 查看退出码。 正常结束时退出码为 0；解释器抛出未捕获的异常时退出码非 0。 

python3 示例代码/0.2-hello.py
echo $?
hello, TUP
3 + 4 = 7
7 / 2 = 3.5
0

退出码是脚本与外部工具约定成功或失败的方式。后面的检查脚本会同时看 标准输出与退出码；练习程序应当正常结束并返回 0。

0.3报错与调试

Python 的报错信息比 C++ 编译器的短，但结构固定。学会从最后一行往前读， 多数错误可以在一分钟内定位。这一课看四种最常见的错误：找不到文件、 缩进不一致、名字未定义与类型不匹配。

读 traceback

未捕获的异常会打印一段 traceback。最后一行是异常类型与消息， 它说明出了什么事；上面的 File "…", line N, in … 说明出事时正在执行哪个文件的第几行。从下往上找第一帧属于自己的文件， 那一行就是需要修改的位置。

紧随其后的源码行与 ^ 标记指出具体位置。标准库内部的帧 可能有多层，初学时不必逐层读懂；先看最后一行的异常类型，再看自己文件 的那一帧。

找不到文件

下面这段程序打开 素材/missing.png。文件不存在，解释器在 open 处抛出 FileNotFoundError：

例题 · 文件不存在

题目：打开素材目录中的一张图片并读取全部字节。文件不存在时，观察 traceback 怎样指出出错的行与路径。

完整程序：

with open("素材/missing.png", "rb") as file:
    data = file.read()
print(len(data))

运行：

python3 示例代码/0.3-err-file.py
Traceback (most recent call last):
  File "示例代码/0.3-err-file.py", line 1, in <module>
    with open("素材/missing.png", "rb") as file:
         ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
FileNotFoundError: [Errno 2] No such file or directory: '素材/missing.png'

最后一行给出异常类型与出错路径。路径是相对当前目录解析的；在课程根目录运行时，它找的是 /tmp/python-course/素材/missing.png。文件名拼错、目录层级不对、或忘了先复制素材，都会得到同一种异常。

处理这类错误时先确认当前目录，再确认文件名的拼写与大小写。 Path("素材/missing.png").exists() 可以提前判断文件是否存在； 读取图片时 cv2.imread 在失败时返回 None， 不抛异常，需要单独检查。

缩进、名字与类型

缩进不一致会在解析阶段失败，程序一行都不会执行。下面的 return 比循环体少缩进两个空格，解释器无法判断它属于哪一层： 

def total(values):
    result = 0
    for value in values:
        result += value
      return result

print(total([1, 2, 3]))
  File "示例代码/0.3-err-indent.py", line 5
    return result
                 ^
IndentationError: unindent does not match any outer indentation level

这类错误没有 Traceback 开头，因为解释器在编译源码时就已经 停下。把 return 改成与 for 对齐的四个空格即可。

名字错误发生在运行时。下面的程序调用 average，但这个名字 从未定义： 

scores = [88, 92, 79]
print(average(scores))
Traceback (most recent call last):
  File "示例代码/0.3-err-name.py", line 2, in <module>
    print(average(scores))
          ^^^^^^^
NameError: name 'average' is not defined

拼写错误、忘记先定义、或在函数内部使用了没有声明的外部名字，都会得到 NameError。检查报错那一行的名字，再搜索它在哪里定义。

类型错误同样在运行时出现。下面把字符串 "3" 与整数 4 相加： 

count = "3"
total = count + 4
print(total)
Traceback (most recent call last):
  File "示例代码/0.3-err-type.py", line 2, in <module>
    total = count + 4
            ~~~~~~^~~
TypeError: can only concatenate str (not "int") to str

+ 对两个字符串表示拼接，对两个数字表示加法，两者不能混用。 先用 int(count) 把字符串转换成整数，再相加。 这类错误在 C++ 里由编译器提前发现，在 Python 里要等到那一行真正执行。

调试顺序

遇到报错时按下面的顺序处理，通常比反复改动代码更快：

  1. 读最后一行，确认异常类型与消息。
  2. 从下往上找第一帧属于自己的文件，记下行号。
  3. 检查那一行的输入：变量是什么类型、值从哪里来、路径是否存在。
  4. 在出错行之前插入临时 print，把关键变量的值与类型打印出来。
  5. 修改后重新运行；确认修复后再删掉临时输出。

不要一次改很多处。每次只改一个假设，再运行一次，才能知道是哪一处起了作用。

0.4第一个完整工具：批量读取图片尺寸

这一课写一个小工具：遍历素材目录中的所有 PNG，打印文件名、宽、高、 通道数与像素类型，并把同样的信息写入 out_sizes.txt。 它把路径遍历、图片读取与文件写入串在一起，是后面视觉脚本的常见骨架。

任务与数据

素材目录中有三张 PNG：synth_balls.png 与 synth_shapes.png 都是 640×480 的彩色图， synth_grid.png 是 320×240 的灰度图。工具不假定文件数量 与顺序，而是扫描目录，按文件名排序后逐个处理。

输出分两部分：屏幕上是一张对齐的表，文件里是逗号分隔的记录。 前者供人阅读，后者供其他脚本继续处理。两者使用同一批数据， 避免手工抄写出错。

遍历素材目录

pathlib.Path 把路径封装成对象。 Path("素材") 表示相对当前目录的素材文件夹， .glob("*.png") 返回其中所有以 .png 结尾的文件。 sorted() 按路径的字符串顺序排序，保证每次运行顺序一致。

path.name 只取文件名，不含目录。Path.glob 不递归进入子目录；素材目录只有一层，够用。若以后要递归，改用 rglob。

读图与尺寸

cv2.imread(str(path)) 读入图片，返回一个 NumPy 数组。 默认参数把图片读成三通道 BGR，即使原文件是灰度 PNG，返回的仍是三通道， 所以下面三张图的 channels 都是 3。读入失败时返回 None，程序先检查再取尺寸。

image.shape 的顺序是“高、宽、通道数”，不是“宽、高”。 程序写成 height, width = image.shape[:2]，再用 image.shape[2] 取通道数。image.dtype 是像素类型，8 位无符号整数显示为 uint8。

写结果文件

程序把每张图拼成一行 名字,宽,高,通道,类型，用 "\n".join(lines) 连接，再在末尾补一个换行。 Path.write_text 的 encoding="utf-8" 明确写出编码，换一台机器也不会因默认编码不同而写出乱码。

结果文件写在当前目录，不写进素材目录。这样重复运行不会污染只读素材， 删除结果也不会影响输入。

运行结果

例题 · 批量读取图片尺寸

题目：扫描 素材 中的 PNG，按文件名排序，打印对齐的尺寸表，并写入 out_sizes.txt。

完整程序：

from pathlib import Path

import cv2


def main():
    rows = []
    for path in sorted(Path("素材").glob("*.png")):
        image = cv2.imread(str(path))
        if image is None:
            print("读入失败:", path.name)
            continue
        height, width = image.shape[:2]
        channels = image.shape[2] if image.ndim == 3 else 1
        rows.append((path.name, width, height, channels, image.dtype))

    for name, width, height, channels, dtype in rows:
        print(f"{name:<18}{width:>4}x{height:<4} channels={channels}  {dtype}")

    lines = [f"{name},{width},{height},{channels},{dtype}"
             for name, width, height, channels, dtype in rows]
    Path("out_sizes.txt").write_text("\n".join(lines) + "\n", encoding="utf-8")
    print(f"{len(rows)} images -> out_sizes.txt")


if __name__ == "__main__":
    main()

看答案

遍历时先读入图片，读入失败就跳过；shape 的前两项是 高与宽，判断宽度是否达到 640 后再加入结果列表。路径已按名字排序， 输出顺序固定。 

from pathlib import Path

import cv2

wide = []
for path in sorted(Path("素材").glob("*.png")):
    image = cv2.imread(str(path))
    if image is None:
        continue
    height, width = image.shape[:2]
    if width >= 640:
        wide.append((path.name, width, height))

print(f"{len(wide)} wide images")
for name, width, height in wide:
    print(f"{name} {width}x{height}")

0.5从 C++ 到 Python：要改的习惯

Python 的变量、对象与函数参数传递规则和 C++ 不同。若照 C++ 的直觉写， 程序往往能运行，结果却与预期不符。这一课集中处理五个最容易沿用的习惯： 变量是名字而不是存储位置、列表赋值不复制、函数可以修改传入的列表、 除法默认得到浮点数、空容器的真值为假。

名字是标签

Python 的赋值语句把名字绑定到对象上，不复制对象。写成 b = a 之后，a 与 b 是同一个列表的 两个名字；通过任意一个名字修改列表，另一个名字读到的内容也会变。 这与 C++ 的引用相似，但不需要在类型上写 &， 也无法通过重新赋值让另一个名字跟着改变。

要得到独立副本，使用切片 a[:]、list(a) 或 copy.copy(a)。这三种写法都只复制第一层；列表中若还有 列表，内层仍是共享的，需要 copy.deepcopy。

可变对象与函数

函数参数同样按名字传递。函数收到的是对象本身，不是副本； 在函数里调用 values.append(1) 会修改调用者的列表。 若函数体内对参数重新赋值，例如 values = [0]， 只是让局部名字指向新对象，调用者的列表不变。

列表、字典与集合是可变对象；整数、浮点数、字符串与元组不可变。 对不可变对象“修改”时，解释器实际创建新对象并重新绑定名字， 因此函数内部无法通过参数改变外部的整数或字符串。

除法与真值

/ 总是得到浮点数，即使两个操作数都是整数； // 是向下取整的除法，% 取余。 负数上的 // 向负无穷取整，与 C++ 的截断方向不同： -7 // 2 是 -4，不是 -3。

条件判断接受任意对象。空列表、空字符串、空字典、0、 0.0 与 None 为假，其余为真。 判断“有没有内容”直接写 if values:，不必先求长度。 判断“是不是 None”用 is None，不要用 == None。

例题 · 别名、复制、函数修改与除法

题目：用一段程序依次演示列表赋值、切片复制、函数内修改、真除法与整除、以及空容器的真值。

完整程序：

def add_one(values):
    values.append(1)


a = [1, 2, 3]
b = a
b.append(4)
print("alias:", a)

c = a[:]
c.append(5)
print("copy:", a)
print("copy:", c)

add_one(a)
print("mutated:", a)

print("7 / 2 =", 7 / 2)
print("7 // 2 =", 7 // 2)
print("bool:", bool([]), bool([0]), bool(""))

x = None
print("none:", x is None)

运行：

python3 示例代码/0.5-demo.py
alias: [1, 2, 3, 4]
copy: [1, 2, 3, 4]
copy: [1, 2, 3, 4, 5]
mutated: [1, 2, 3, 4, 1]
7 / 2 = 3.5
7 // 2 = 3
bool: False True False
none: True

b = a 之后修改 b，a 也变成四个元素；c = a[:] 得到独立列表，追加 5 只影响 c。add_one 修改的是调用者的列表，因此 a 末尾多出 1。空列表为假，包含 0 的列表为真，空字符串为假。
