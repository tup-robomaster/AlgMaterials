第 2 部分

让程序做判断和重复

上一部分的程序是一条道走到黑的：每一行都走，从头走到尾。 这一部分给它装上岔路口——有的路走，有的路不走；有的路走一遍，有的走一百遍。

2.1判断：让程序选一条路走

到 1.6 为止，程序都是一行不落地从头走到尾的。你写十行，它就执行十行。

可真实的问题不长这样。真实的说法是「及格才打及格」—— 有一个条件在那儿管着，条件成立才走那几句。

程序第一次分岔

一个判分数的程序。58 分： 

#include <iostream>

int main() {
    int score = 58;

    if (score >= 60) {
        std::cout << "及格" << std::endl;
    }

    std::cout << "看完了" << std::endl;

    return 0;
}
看完了

注意到没有：程序里写着「及格」那三个字，但屏幕上没有。

它没坏，这就是它该干的事。因为有一道闸门挡在那儿：score >= 60。 58 不满足这个条件，闸门关着，那两句就走不到。

把 58 改成 75 再编译再跑一次，你会看到： 

及格
看完了

闸门开了。同一个程序，一行代码没改，只换了一个数，走的路就不一样了。 这就是「分岔」。

最后那行「看完了」为什么两次都在

因为它不在闸门里面。它写在 if 那对大括号的外面， 所以不管闸门开不开，它都照走。

「哪几句归闸门管、哪几句不归」是这一课最要紧的一件事。 下面还会专门讲一次。

三个部件

把刚才那道闸门拆开看，它有三个部件： 

if (score >= 60) {
    std::cout << "及格" << std::endl;
}
  1. if 这个词。它是 if（如果）的缩写，意思是 「下面这句话是有条件的」。
  2. 一对圆括号，里面是条件：(score >= 60)。 括号里那句话要能判出真假——不是真就是假，没有第三种。
  3. 一对花括号，里面是要走的那几句。 条件成立，大括号里从头到尾走一遍；条件不成立，整块跳过。

if 后面没有分号。这是个容易手滑的地方，滑了之后是这样： 

if (score >= 60);
{
    std::cout << "及格" << std::endl;
}

多了一个分号。程序照样编译（只警告一句），跑起来 58 分也打「及格」。

因为那个分号把 if 的话说完了——1.4 说过，分号是「一句话说完了」的记号。 if 后面跟了一个空句子，闸门管的是那个空句子。 下面那对大括号已经站在闸门外面了，成了普通的一块，不管条件成不成立都走。

编译器警告的原话是 this ‘if’ clause does not guard...， 意思是「这个 if 谁也没管住」。if 这句还没说完，自然不能有分号。

两条路：else

上面那个程序只处理了「及格」的情况。不及格的时候什么都不说—— 可生活里这时候该说「不及格」。

else 就是干这个的。读作「否则」： 

#include <iostream>

int main() {
    int score = 58;

    if (score >= 60) {
        std::cout << "及格" << std::endl;
    } else {
        std::cout << "不及格" << std::endl;
    }

    return 0;
}
不及格

加上 else 之后，性质变了一点：两条路必走一条，而且只走一条。

注意 else 后面没有圆括号。它不需要条件—— 「上面那个不成立」本身就是它的条件。

else 不能单独出现

它必须紧跟着一个 if。单独写一个 else， 编译器会问你「否则什么？」，然后报 error: ‘else’ without a previous ‘if’。

三条以上：else if

两条路不够的时候——比如成绩分优秀、及格、不及格三档——在中间插 else if： 

#include <iostream>

int main() {
    int score = 58;

    if (score >= 90) {
        std::cout << "优秀" << std::endl;
    } else if (score >= 60) {
        std::cout << "及格" << std::endl;
    } else {
        std::cout << "不及格" << std::endl;
    }

    return 0;
}
不及格

把 score 改成 75 会打「及格」，改成 95 会打「优秀」。

怎么走的？从上往下，一个一个问，问到哪个成立就走哪个， 走完就出这一整块，后面的问都不问了。

  • 95 分：第一个问「≥ 90 吗」——是，打「优秀」，走人。≥ 60 那句问都不问。
  • 75 分：第一个问「≥ 90 吗」——不是；第二个问「≥ 60 吗」——是，打「及格」，走人。
  • 58 分：两个都不是，落到 else，打「不及格」。
所以顺序不能随便调

把上面两个条件调个个儿，先问 ≥ 60、再问 ≥ 90： 95 分第一个问题就通过了，直接打「及格」走人——「优秀」永远轮不到。

这不是理论。这种「宽的条件写在前面，把窄的挡住了」是 else if 最常见的错。写的时候从最严的条件往下排。

花括号能不能省

大括号里只有一句话的时候，C++ 允许你把大括号省掉： 

if (score >= 60)
    std::cout << "及格" << std::endl;

这行得通。但这一课我建议你永远别省。原因看下面这个程序—— 它想干的事是：58 分一个字都不打，及格了才打「恭喜」。 

#include <iostream>

int main() {
    int score = 58;

    if (score >= 60)
        std::cout << "及格" << std::endl;
        std::cout << "恭喜" << std::endl;

    return 0;
}
恭喜

58 分，没及格，可「恭喜」还是打出来了。

看第二句的缩进——它比 if 深了一层，写的人以为它归 if 管，手也就这么缩进去了。可编译器只认语法，不认缩进： 省掉大括号之后，if 只管它后面那一句。 第二句 std::cout << "恭喜" 已经站在闸门外面了， 不管条件成不成立它都走。

最要命的是：它照样编译通过了。编译器确实说了句话， 但那句话是警告，不是错误——它没拦住你： 

2.1-warn-brace.cpp:19:5: warning: this ‘if’ clause does not guard... [-Wmisleading-indentation]
   19 |     if (score >= 60)
      |     ^~
2.1-warn-brace.cpp:21:9: note: ...this statement, but the latter is misleadingly indented as if it were guarded by the ‘if’
   21 |         std::cout << "恭喜" << std::endl;
      |         ^~~

读一遍：「这个 if 不管着这一句」。 后面那句 note 说得更直白——「这一句缩进得像是归 if 管，其实不归」。它把你想干的事看得清清楚楚。

可警告拦不住程序。编译照样过，跑起来照样打「恭喜」—— 你要是不读它，它等于没说。 这就是 warning 和 error 的区别，也是 0.1 让你一直带着 -Wall 的原因：不带着它，这句话它根本不会说出口。

所以养成习惯：哪怕只有一句话，也把大括号写上。 写上之后，「哪几句归这个 if 管」是写在代码里的—— 不靠缩进，也不靠你记；以后往里头加第二句，更不用回头补。

括号里放的是什么

前面一直在说「条件成立」「不成立」。那「成立」到底是个什么东西？

看这个程序。它拿五个东西往 if 的括号里塞： 

#include <iostream>

int main() {
    if (0) {
        std::cout << "0 是真" << std::endl;
    }

    if (1) {
        std::cout << "1 是真" << std::endl;
    }

    if (-1) {
        std::cout << "-1 是真" << std::endl;
    }

    if (3 - 3) {
        std::cout << "3-3 是真" << std::endl;
    }

    if (10 > 3) {
        std::cout << "10>3 是真" << std::endl;
    }

    return 0;
}
1 是真
-1 是真
10>3 是真

数一下：五句里走了三句。没走的是 0 和 3 - 3。

规律很清楚：括号里那个东西等于 0，就是假；不等于 0，就是真。

3 - 3 算出来是 0，所以是假。-1 不等于 0，所以是真—— 负数也是真，这一点跟很多人想的不一样。

而 10 > 3 这种比较算式，本身就是算出一个数： 成立算出 1，不成立算出 0。if 拿到这个 1 或 0，判断真假。

这句话记住，2.2 整课都靠它： if 的括号里放的不是「一句判断」，是一个数。0 是假，别的都是真。

例题 · 奇数还是偶数

你手上已经有 if 了，1.3 那个取余 % 也还在。 两个合起来，能判断一个数的奇偶： 

#include <iostream>

int main() {
    int n = 7;

    if (n % 2 == 0) {
        std::cout << n << " 是偶数" << std::endl;
    } else {
        std::cout << n << " 是奇数" << std::endl;
    }

    return 0;
}
7 是奇数

n % 2 是 7 除以 2 的余数，也就是 1。1 不等于 0，所以走 else——打出「奇数」。

注意 == 是两个等号。为什么不能写一个等号，下一课开头就讲。

练习

练习 2-1

读一个整数，判断它是正数、负数还是零。

输入 -7 时： 

-7
负数

提示：三档，所以要用 else if。 三种情况分别是什么，先在纸上写清楚再动手。

看答案

三档，两个条件，从上往下排： 

#include <iostream>

int main() {
    int n = 0;
    std::cin >> n;

    if (n > 0) {
        std::cout << "正数" << std::endl;
    } else if (n < 0) {
        std::cout << "负数" << std::endl;
    } else {
        std::cout << "零" << std::endl;
    }

    return 0;
}

最后那个 else 是不带条件的—— 前面两个都不成立，剩下的只能是零，不用再问一遍。

写成 else if (n == 0) 也对，但那是白问。 能把「剩下的那种情况」交给 else，就别再写条件。 少写一个条件，就少一个写错的机会。

练习 2-2

读两个整数，打出其中较大的那个。

输入 4 9 时： 

4 9
9

提示：读两个数和 1.5 那个一次读三个数的写法一样， 一个 std::cin 连着写两个 >>。

看答案

两个数比大小，一条岔路口就够了： 

#include <iostream>

int main() {
    int a = 0;
    int b = 0;
    std::cin >> a >> b;

    if (a >= b) {
        std::cout << a << std::endl;
    } else {
        std::cout << b << std::endl;
    }

    return 0;
}

std::cin >> a >> b; 一句读两个数， 和 1.5 那个一次读三个数的是一个写法。

有人会想写成两个 if：「a 大就打 a，b 大就打 b」。 也行，但这一版更省事——不是 a 大，那就一定是 b 大， 一件事问一次就够。

这题看着没什么用，其实它是 4.3「在数组里找最大值」的种子： 那时候要做的事就是这一句，只不过要重复很多遍。

练习 2-3

读一个整数，判断它能不能被 3 整除。

输入 17 时： 

17
17 不能被 3 整除，余 2

提示：能不能整除，就是问余数是不是 0——1.3 那个 %。 注意最后那个 2 是算出来的，不是写死的。

看答案

能不能整除，就是问余数是不是 0： 

#include <iostream>

int main() {
    int n = 0;
    std::cin >> n;

    if (n % 3 == 0) {
        std::cout << n << " 能被 3 整除" << std::endl;
    } else {
        std::cout << n << " 不能被 3 整除，余 " << n % 3 << std::endl;
    }

    return 0;
}

n % 3 在程序里出现了两次：一次问它是不是 0， 一次打进结果里。两次算的是同一个东西，所以不用另开一个盒子存它。

顺带说一件容易混的事：「能不能被 3 整除」和「除以 3 得多少」是两回事。 前者用 %，后者用 /。 想判断整除却写成 n / 3 == 0 就错了—— 17 / 3 是 5，根本不等于 0。1.3 那个整数除法的坑，在这儿又露了一次头。

练习 2-4（找错）

一个 75 分的程序，想打「及格」。它也确实编译通过了， 可打出来的是两行： 

及格
不及格

出问题的就是这一段（score 是 75）： 

    if (score >= 60)
        std::cout << "及格" << std::endl;
    std::cout << "不及格" << std::endl;

先别看答案——错在哪儿？

提示：这不是语法问题，编译器一声都没吭。 回到 2.1 讲「花括号能不能省」那一段，看看 if 到底管住了哪一句。

看答案

那段程序完整长这样： 

#include <iostream>

int main() {
    int score = 75;

    if (score >= 60)
        std::cout << "及格" << std::endl;
    std::cout << "不及格" << std::endl;

    return 0;
}

错在少了一对花括号。if (score >= 60) 后面没有大括号， 所以它只看得见紧跟着的一句。第二句 std::cout << "不及格" 已经站在门外， 不管条件成不成立都走。75 分的时候闸门开了走第一句， 走到门外再走第二句——两句都打了。

把大括号补上，两句都圈进 if 里，就成了正常的 if / else： 

    if (score >= 60) {
        std::cout << "及格" << std::endl;
    } else {
        std::cout << "不及格" << std::endl;
    }

当然，这道题只问「原版为什么两句都打」，答案就在那个大括号上。 （上面那一小块只是示意，答案里那份是那个错的样子—— 它就是留给你对着找错的。）

这题真正要你记住的是「编译器没吭声」。 没有报错，没有警告，编译通过，跑起来也算「成功」。 它只是没干你想让它干的事。 这一类错没人替你兜着，只能靠那对大括号防住—— 这就是 2.1 里说「哪怕只有一句话也写上大括号」的原因。

2.2条件怎么写

2.1 学会了分岔，但条件一直是 >= 这一种。 这一课把条件本身讲完——它是基础课里最容易写错的地方， 而且错起来大多不报错。

六个比较运算符

比大小一共六个符号，先看它们各自算出什么： 

#include <iostream>

int main() {
    int a = 5;
    int b = 3;

    std::cout << (a == b) << std::endl;
    std::cout << (a != b) << std::endl;
    std::cout << (a > b) << std::endl;
    std::cout << (a < b) << std::endl;
    std::cout << (a >= b) << std::endl;
    std::cout << (a <= b) << std::endl;

    return 0;
}
0
1
1
0
1
0

一行一行对：

  • a == b：5 等于 3 吗？不等，算出 0（假）。
  • a != b：!= 读作「不等于」。5 不等于 3，算出 1（真）。
  • a > b：5 大于 3，1。
  • a < b：5 小于 3？不，0。
  • a >= b：>= 是「大于或等于」。5 大于 3，成立，1。
  • a <= b：5 小于等于 3？不，0。

打出来的是 0 和 1，不是 true 和 false——因为 std::cout 把真假当数打（1.4 讲 bool 那一段就是这个）。 数本身是没问题的：你拿它当条件用，1 就是真、0 就是假。

那对圆括号不能省

上面每一行都有括号：std::cout << (a == b)。 不写会怎样？std::cout << a == b 会被当成 (std::cout << a) == b—— 先把 a 打出去，然后拿「刚才那个打印动作」去和 b 比大小。 编译器不干，直接报错。

这就是 1.4 说的「一个 << 只做一件事」。 把比较算式用括号圈起来，告诉它「这块先算」。

= 和 ==

这一课最贵的一个字。

1.1 就说过：= 不是「等于」，是「把右边的放进去」。 判断相不相等用的是两个等号 ==。 道理谁都懂，但手上会滑。看滑了之后发生什么： 

#include <iostream>

int main() {
    int a = 5;

    if (a = 0) {
        std::cout << "进来了" << std::endl;
    } else {
        std::cout << "没进来" << std::endl;
    }

    std::cout << "a 现在是 " << a << std::endl;

    return 0;
}
没进来
a 现在是 0

它编译通过了。编译器只警告了一句，然后放你过去了： 

2.2-warn-assign.cpp:10:11: warning: suggest parentheses around assignment used as truth value [-Wparentheses]
   10 |     if (a = 0) {
      |         ~~^~~

读一遍这句话：「拿赋值当条件用，建议你加个括号」。 编译器看出你想干的事有点怪，但它不拦你——因为语法上没毛病。

程序为什么走 else？拆一遍：

  1. a = 0 是「把 0 放进 a」。这一句的结果就是放进去的那个 0。
  2. if 拿到这个 0 当条件——2.1 说了，0 是假。
  3. 假，走 else。

于是 a 被改成了 0，条件永远是假，else 里那句永远执行。 你想问「a 是不是 0」，结果变成了「把 a 改成 0」。

怎么写才不会滑

有个老办法是把两边调过来写：if (0 == a)。 这样手滑写成一个等号就是 0 = a， 而 0 是不能被赋值的，编译器直接报错，你当场就发现了。

但更实在的办法是：看见那句 warning 就停下。 -Wall 会替你盯着这个坑，前提是你别把警告当没看见。 0.3 讲过怎么读警告，这里就是它救命的场合。

连起来：&& || !

一个条件不够用的时候，把几个条件连起来。三个符号：

  • && 读作「并且」。两边都真，结果才真。
  • || 读作「或者」。有一边真，结果就真。
  • ! 读作「不」。把真变假，把假变真。一个就够，写在前面。
#include <iostream>

int main() {
    int score = 85;
    int age = 19;

    if (score >= 60 && age >= 18) {
        std::cout << "两个都满足" << std::endl;
    }

    if (score >= 90 || age >= 18) {
        std::cout << "至少满足一个" << std::endl;
    }

    if (!(score >= 60)) {
        std::cout << "没及格" << std::endl;
    } else {
        std::cout << "及格了" << std::endl;
    }

    return 0;
}
两个都满足
至少满足一个
及格了

逐句看：

  • 第一句：85 ≥ 60 并且 19 ≥ 18。两个都真，整体真，打出来了。
  • 第二句：85 ≥ 90 是假，但 19 ≥ 18 是真。 || 只要一个真就够，所以整体真，也打出来了。 「或者」不要求两个都满足。
  • 第三句：score >= 60 是真，! 把它翻成假， 所以走 else，打「及格了」。

注意 ! 后面那一对括号：!(score >= 60)。 括号是必须的，原因和 2.2 开头那对一样—— 得先把整个比较算式圈起来，再让 ! 去翻它。

&& 比 || 紧

一句话里同时有 && 和 || 的时候， && 先算，就像乘除比加减先算一样。

这会让「长得几乎一样」的两句话干出不同的事。看： 

#include <iostream>

int main() {
    int a = 1;
    int b = 9;

    if (a == 1 || a == 2 && b == 3) {
        std::cout << "没括号的：进来了" << std::endl;
    } else {
        std::cout << "没括号的：没进来" << std::endl;
    }

    if ((a == 1 || a == 2) && b == 3) {
        std::cout << "有括号的：进来了" << std::endl;
    } else {
        std::cout << "有括号的：没进来" << std::endl;
    }

    return 0;
}
没括号的：进来了
有括号的：没进来

两句的字符几乎完全一样，就差一对括号，走的路正好相反。编译器也警告了： 

2.2-warn-precedence.cpp:11:26: warning: suggest parentheses around ‘&&’ within ‘||’ [-Wparentheses]
   11 |     if (a == 1 || a == 2 && b == 3) {
      |                   ~~~~~~~^~~~~~~~~

「|| 里夹着 &&，建议你加括号」—— 它看出这句话有歧义。

拆一遍就明白了。a 是 1，b 是 9：

  • 没括号的那句，因为 && 先算，实际是 a == 1 || (a == 2 && b == 3)。 a == 2 是假，后面 && 整个是假； 但左边 a == 1 是真，|| 有一个真就够—— 整体真。
  • 有括号的那句是 (a == 1 || a == 2) && b == 3。 括号里是真，可 b == 3 是假（b 是 9）， && 要求两个都真——整体假。
别去背优先级，加括号

上面这套推导看懂了很好，但实际写代码的时候不要依赖它。 你写 a && b || c，下一个读你代码的人（包括三个月后的你自己） 得停下来想一下——这就是成本。

写成 (a && b) || c，一眼就懂，还不用背表格。 多打两个字符，省下的是别人和你自己的脑力。

连写的不等式

数学课上写「x 在 1 到 100 之间」是这样的：1 <= x <= 100。 这个写法搬进 C++ 会出事，而且是那种不出声的事： 

#include <iostream>

int main() {
    int x = 42;

    if (1 <= x <= 100) {
        std::cout << "42：" << "在范围里" << std::endl;
    } else {
        std::cout << "42：" << "不在范围里" << std::endl;
    }

    x = 999;

    if (1 <= x <= 100) {
        std::cout << "999：" << "在范围里" << std::endl;
    } else {
        std::cout << "999：" << "不在范围里" << std::endl;
    }

    x = 0;

    if (1 <= x <= 100) {
        std::cout << "0：" << "在范围里" << std::endl;
    } else {
        std::cout << "0：" << "不在范围里" << std::endl;
    }

    return 0;
}
42：在范围里
999：在范围里
0：在范围里

999 和 0 都在「范围里」。这个条件等于没写。

编译器其实说得很直白： 

2.2-warn-chain.cpp:11:16: warning: comparison of constant ‘100’ with boolean expression is always true [-Wbool-compare]
   11 |     if (1 <= x <= 100) {
      |         ~~~~~~~^~~~~~
2.2-warn-chain.cpp:11:11: warning: comparisons like ‘X<=Y<=Z’ do not have their mathematical meaning [-Wparentheses]
   11 |     if (1 <= x <= 100) {
      |         ~~^~~~

一句读作「拿 100 和一个真假值比大小，结果永远是真」； 另一句读作「像 X<=Y<=Z 这样连着写的比较， 和你数学里那个意思不是一回事」。说的是同一件事。

为什么？C++ 是按从左往右算的：

  1. 1 <= x 先算。x 是 999，不成立，算出 0。
  2. 算式变成 0 <= 100。这当然成立，算出 1。

所以整个式子永远是真。x 是 42、999、还是 0，都一样—— 第一个比较的结果是 0 或 1，而 0 和 1 永远小于等于 100。

正确的写法

把它拆成两个比较，用 && 连： 

if (1 <= x && x <= 100)

这才是「x 不小于 1 并且 x 不大于 100」。 数学里的连写不等式，在 C++ 里一律拆成两半用 && 连。

例题 · 在不在范围里
#include <iostream>

int main() {

    if (x >= 1 && x <= 100) {
        std::cout << x << " 在范围里" << std::endl;
    } else {
        std::cout << x << " 不在范围里" << std::endl;
    }

    return 0;
}
42 在范围里

把 x 改成 999 或 0，它就会老实地打「不在范围里」。

练习 2-6

提示：1900 能被 4 整除，但也能被 100 整除，所以不是闰年—— 这一条正好是拿来试你写对没有的。

两年规则之间是「或者」的关系，用 || 连。 哪一段该加括号，想清楚。

看答案

两条规则，一条用 &&（「并且」）， 两条之间用 ||（「或者」）： 

#include <iostream>

int main() {
    int year = 0;
    std::cin >> year;

    if ((year % 4 == 0 && year % 100 != 0) || year % 400 == 0) {
        std::cout << year << " 是闰年" << std::endl;
    } else {
        std::cout << year << " 不是闰年" << std::endl;
    }

    return 0;
}

括号是关键。把它拿掉写成 year % 4 == 0 && year % 100 != 0 || year % 400 == 0 会怎样？因为 && 比 || 先算 （2.2 讲的），前半截正好是 (A && B) || C—— 这次碰巧跟你想要的一样，结果没错。

但「碰巧对」不是「对」。下一回换个式子未必还碰巧， 读代码的人也得停下来想一遍。2.2 那句话在这儿就用上了： 别去背优先级，把括号写上。

拿 1900 试一下：1900 % 4 == 0 是真， 但 1900 % 100 != 0 是假，&& 那一整块就是假； 再看 1900 % 400 得 300，也不等于 0。两个都假，所以不是闰年。 换成 2000 就对了——它能被 400 整除。

一、比的是单引号的 'a'。 双引号那个是另一回事——1.2 里 char c = "A"; 编译不过，就是踩的这个。单引号包一个字符，双引号包一串字符， 在 C++ 里是两个完全不同的东西。

练习 2-8（找错）

一个程序，a 本来是 3，想判断「a 是不是等于 5」。 出口在 if 那个括号里：

        std::cout << "a 是 5" << std::endl;

        std::cout << "a 不是 5" << std::endl;

a 是 5
a 现在是 5

先别看答案——a 明明是 3， 为什么程序认为它是 5？连 a 自己的值都被改了。

提示：数一数 if 括号里那个符号的等号有几个。 顺便想一想：编译器为什么没拦它？

看答案

那段程序完整长这样： 

#include <iostream>

int main() {
    int a = 3;

    if (a = 5) {
        std::cout << "a 是 5" << std::endl;
    } else {
        std::cout << "a 不是 5" << std::endl;
    }

    std::cout << "a 现在是 " << a << std::endl;

    return 0;
}

出问题的就是那一行：if (a = 5)， 里面那个符号只有一个等号。它该是两个： 

    if (a == 5) {

就这一个字符之差，干的事完全反了。

编译器其实看出来了，它说的是： 

2-8-warn.cpp: In function ‘int main()’:
2-8-warn.cpp:10:11: warning: suggest parentheses around assignment used as truth value [-Wparentheses]
   10 |     if (a = 5) {
      |         ~~^~~

「拿赋值当条件用，建议你加个括号」。注意这是 warning，不是 error—— 它不拦你，程序照样编出来，照样跑。

拆一遍 if (a = 5) 发生了什么：

一、a = 5 是「把 5 放进 a」， 这一句的结果就是放进去的那个 5。 所以 a 被改了——本来 3，现在 5。

二、if 拿这个 5 当条件。2.1 说了，0 是假、别的都是真， 所以 5 是真。

三、真，走 if，打「a 是 5」。

你想问「a 是不是 5」，程序干的是「把 a 改成 5，然后说真」。 两个结果看着一样，可只要 a 原来是别的数， 它就永远打「a 是 5」——连 7 进来也打这句。

怎么防

老办法是把两边调过来写：if (5 == a)。 这样手滑写成一个等号就是 5 = a， 而 5 是不能被赋值的，编译器直接报 error，当场就发现了。

更实在的办法：看见那句 warning 就停下。 -Wall 会替你盯着这个坑，前提是你别把警告当没看见。 0.3 讲过怎么读警告，这儿就是它救命的场合。

2.3循环：让程序把同一件事做很多遍

2.1 给了程序岔路口。这一课给它回头路——同一段代码， 走一遍不算完，走回去再走一遍。

没有循环的时候

#include <iostream>

int main() {
    std::cout << 1 << std::endl;

    std::cout << 5 << std::endl;

五行，只有中间那个数字不一样，别的字一模一样。

这种「同一件事做很多遍，每遍只有一点点不同」的需求， 靠手写是解决不了的。得让程序自己回头。

while 长什么样

刚才那五行，塌成三行： 

#include <iostream>

int main() {
    int i = 1;

    while (i <= 5) {
        std::cout << i << std::endl;
        i = i + 1;
    }

    return 0;
}

输出和手写那五行一模一样。但这一版把 5 改成 100 就真会打一百行—— 大括号里那两句一个字都不用动。

while 的形状，和 if 长得很像： 

while (条件) {
    要重复的那些行
}

圆括号里是条件，花括号里是要重复的话。和 if 一样， 后面没有分号。

差别在一个字上：

  • if：条件成立，大括号里走一遍，然后往下走，不回头。
  • while：条件成立，大括号里走一遍，走完回到 while 那一行， 再问一次条件。还成立就再走一遍。问到不成立为止，才往下走。

所以 while 那句 (i <= 5) 会被问很多次， 每次都问同一个问题，问的是同一个盒子 i， 只不过盒子里的数一直在变。

必须有的三件事

一个能停下来的循环，身上一定有三件事。拿刚才那个程序对：

  1. 起点：int i = 1;——循环开始之前， 那个盒子得先有个值。
  2. 条件：i <= 5——什么时候继续，什么时候停。
  3. 让条件会变的那一步：i = i + 1;—— 每转一圈把 i 往前推一格。没有这一步，条件永远不变，循环永远停不下来。

第三件事是新手最常漏的。为什么漏了就停不下来？ 因为条件问的是 i，而 i 一直是 1，条件永远成立。

怎么知道自己写对了？用纸笔跟一遍。下面这个程序就是「跟一遍」的机器版—— 它把每一圈里头发生了什么全打出来： 

#include <iostream>

int main() {
    int i = 1;

    while (i <= 3) {
        std::cout << "进循环时 i = " << i << std::endl;
        i = i + 1;
        std::cout << "加完 1 之后 i = " << i << std::endl;
    }

    std::cout << "循环结束后 i = " << i << std::endl;

    return 0;
}
进循环时 i = 1
加完 1 之后 i = 2
进循环时 i = 2
加完 1 之后 i = 3
进循环时 i = 3
加完 1 之后 i = 4
循环结束后 i = 4

数一数：大括号里那两句，一共走了三遍（1、2、3 各一遍）。

注意最后一行：循环结束后 i 是 4，不是 3。 因为第三遍的时候 i 是 3，条件成立，进去走完一遍，i 变成 4， 回到 while 再问——4 ≤ 3 不成立——才停。

循环停下来的时候，那个盒子里的数通常比你想的「多一格」。 这个细节以后很常用（4.2 遍历数组会再撞上它）。

写循环的时候可以真的这么干

跟自己过不去的时候，就把上面那两句 std::cout 临时加进你自己的循环里，跑一遍看数对不对，看完删掉。 这比盯着代码空想快得多——第 7 部分会专门讲这个办法。

这不是打个五六行就完事。在写这一课的这台机器上，放开跑 2 秒， 它打了 3611662 行——两秒钟三百六十多万行，而且还在继续。 不管它的话，它会一直打到你把终端关掉。

卡住了怎么停下来

在跑着它的那个终端里，按住 Ctrl 不放，再按一下 C。 程序会当场死掉，命令行回到你手上。

这个组合键是「打断」的意思，什么程序卡住了都能用。 记住它，你现在有会写死循环的能力了。

看到满屏一模一样的数在滚，第一件事就是找第三步。 问自己一句：这圈走完，哪个盒子变了？ 如果所有盒子的值都和上一圈一样，那下一圈一定也一样，永远一样。

攒一个总数

循环最常见的用法不是「打多少行」，是一边转一边攒。 比如 1 加到 100： 

#include <iostream>

int main() {
    int i = 1;
    int sum = 0;

    while (i <= 100) {
        sum = sum + i;
        i = i + 1;
    }

    std::cout << sum << std::endl;

    return 0;
}

关键是 sum = sum + i; 这一句。它看着别扭—— 一个东西怎么能等于它自己加别人？1.1 说过，= 不是「等于」，是「放进去」。 所以这句读作：

「把 sum 现在的值，加上 i，算出来，再放回 sum。」

sum 这个盒子被反复改写。头几圈是这样：

isum = sum + i 之前之后
101
213
336
4610

一直攒到 i 是 100，sum 就是 5050。

这个套路叫累加（accumulate）。攒东西的盒子，起点要选对： 加法从 0 开始（加 0 不影响结果），乘法就得从 1 开始（乘 0 会把一切都变成 0）。 练习 2-10 就是乘法那一版。

    int i = 1;
    int fact = 1;

    while (i <= n) {
        fact = fact * i;
        i = i + 1;
    }

    std::cout << n << "! = " << fact << std::endl;

    return 0;
}

那个 int fact = 1;。

2.3 求和的时候起点是 0，因为加 0 不影响结果。 这回攒的是乘法，起点就得是 1——乘 0 会把一切都变成 0。 写成 int fact = 0;，不管 n 是几，结果永远是 0。

这是累加那个套路最容易翻车的一处：先问一句「这个盒子的起点， 放进运算里会不会把结果带坏」。 加法从 0 起，乘法从 1 起，找最大值从第一个数起（4.3 会讲）。

练习 2-11

读一个正整数，数出它一共有几位。

输入 12345 时： 

12345
5 位

提示：想想 1.3 的整数除法。12345 / 10 得多少？ 再 / 10 一次呢？它什么时候会变成 0？

循环的条件就是拿这个当的：只要它还大于 0，就继续除。

看答案

每除一次 10 就少一位，数到它变成 0 为止： 

#include <iostream>

int main() {
    int n = 0;
    std::cin >> n;

    int count = 0;

    while (n > 0) {
        n = n / 10;
        count = count + 1;
    }

    std::cout << count << " 位" << std::endl;

    return 0;
}

12345 / 10 是 1234（1.3 讲的：整数除法把小数点后面丢掉）， 再除是 123、12、1，最后 1 / 10 得 0。 一共除了 5 次，所以是 5 位。

这题有个地方值得多想一秒：n 一边当着循环条件， 一边又在大括号里被改小。这很常见，也是对的—— 它和 i 扮演的是同一个角色：那个「让条件会变」的东西。 2.3 说的三件事，第三件在这儿是 n = n / 10;，换了副面孔而已。

顺带说一句边界：输入 0 会打出「0 位」。 严格说 0 是一位数。这一题只要求正整数，所以不用管—— 但知道自己写的程序在边界上是什么行为，是个好习惯。

练习 2-12（找错）

一个程序，想打 1 到 5。它编译通过了，跑起来也打了数， 可打完就没了下文。循环部分长这样： 

    int i = 1;

    while (i < 5) {
        std::cout << i << std::endl;
        i = i + 1;
    }

跑出来是：

1
2
3
4

先别看答案——5 去哪儿了？

提示：像 2.3 那个「跟一遍」的程序一样，在心里把每一圈走一遍， 写下每圈开始时 i 的值。 然后问：i 是 5 的那一圈，到底进没进去？

看答案

那段程序完整长这样： 

#include <iostream>

int main() {
    int i = 1;

    while (i < 5) {
        std::cout << i << std::endl;
        i = i + 1;
    }

    return 0;
}

条件写错了一个字符：是 <=，不是 <。 

    while (i <= 5) {

改成这样才能打到 5。

原版为什么少了 5？照 2.3 那个「跟一遍」的办法，一圈一圈数：

进循环时 ii < 5 成立吗走不走
1成立走，打 1
2成立走，打 2
3成立走，打 3
4成立走，打 4
5不成立不走

i 是 5 的那一圈，条件 5 < 5 不成立， 门就没开——5 压根没进去。

这个错有个名字，叫「差一个」（off-by-one）。 它不是哪个人粗心，是所有人第一次写循环都会撞上的东西。 防的办法不是「下次小心点」，是每次都把最后一圈单独想一遍： 「i 到边界那个值的时候，进得去吗？我想让它进去吗？」

你现在能写什么：程序不再是「一条道走到黑」了。 你能让它看情况办事，也能让它把同一件事做一万遍—— 而且第一次有了「写三行、干一百行的活」的感觉。 下一课把「回头」这件事写得更紧凑一点：把起点、条件、第三步三件事 全塞进一行里。

2.4for：把三件事写在头上

2.3 说一个能停下来的循环身上有三件事：起点、条件、让条件变的那一步。 那三件事在 while 里是散着的——起点在循环前面， 条件在括号里，第三步在大括号里，跟干活的那句混在一起。

这一课把散着的三件事抓起来，摆到同一行上。

三件事散在三处

拿 2.3 那个数到 5 的程序，我把它那三件事标出来： 

#include <iostream>

int main() {
    int i = 1;                    // ① 起点

    while (i <= 5) {              // ② 条件
        std::cout << i << std::endl;
        i = i + 1;                // ③ 让条件变的那一步
    }

    return 0;
}

三件事离得挺远。③ 尤其别扭：它跟 std::cout 挤在一个大括号里， 一个是「干活」，一个是「管循环」，看起来是一伙的，其实不是。

看它一眼，你说不出「这循环走几圈」。 你得先把眼睛扫到 ①、再扫到 ②、再钻进大括号找到 ③， 在脑子里拼一遍，才知道它从 1 数到 5。

for 就是干这个的。同一个循环： 

#include <iostream>

int main() {
    for (int i = 1; i <= 5; i = i + 1) {
        std::cout << i << std::endl;
    }

    return 0;
}
1
2
3
4
5

输出一个字没变。变的只是三件事的位置——它们现在全在 for 后面那对括号里，一行看完。

那三件事在 for 里是怎么排的？跟 while 版一一对上： 

for ( ①起点 ; ②条件 ; ③让条件变的那一步 ) {
    干活的那几句
}

顺序和 while 版里出现的顺序一样：先起点，再条件，最后第三步。 不用记新东西——for 不是新循环，是老循环换了个摆法。

头上那三个格子

我习惯把这仨叫三个格子。它们之间用分号隔开 （注意：是分号 ;，不是逗号）。

一个格子具体写什么，跟 while 版里那一句一模一样：

格子写什么这个例子里是什么时候执行
第 1 格起点——把循环变量建出来、给个初值 int i = 1 整个循环只执行一次
第 2 格条件——什么时候继续 i <= 5 每一圈开始前问一次
第 3 格让条件变的那一步 i = i + 1 每一圈走完大括号之后

看第四列。三格都在同一行上，但它们不是一起执行的—— 第 1 格只在开头走一次，第 2、3 格要来回走很多次。 这是新手看 for 最容易犯迷糊的地方：一行代码，不是执行一次。

三个格子的走动顺序

下面这个动画把 for 拆成三行写——三个格子各占一行。 这是合法的 C++，跑出来一模一样，只是为了看清每一格在哪。

按「下一步」，盯住高亮的那一行怎么跳。

跳的路线是这样的： 

第 1 格 --> 第 2 格 --> 大括号 --> 第 3 格
              ^                        |
              |                        |
              +------------------------+
              一直转回去，直到第 2 格说「不成立」

数一数这 19 步里，每一格被走到几次：

走了几次为什么
第 1 格1只在开头建一次盒子，之后再也不碰
第 2 格6每次进大括号前问一次，最后还要多问一次才停
第 3 格5每转完一圈加一次，转 5 圈加 5 次
大括号里5条件成立几圈，就走几遍

看出来了吗：三个格子次数不一样。 第 1 格 1 次、第 2 格 6 次、第 3 格 5 次——写在同一行上，走起来完全不是一回事。

第 2 格为什么是 6 次？因为第 5 圈走完之后还得回去再问一次—— 6 <= 5 不成立，这才停。第 2 格永远比大括号多走一次。

最后一行动画里 i 是 6，不是 5。跟 2.3 那个 「循环停下来的时候，盒子里通常比你想的多一格」是同一件事， 只是这次你能亲眼看着它多出来的。

为什么值得专门看一遍

以后循环写错了，你要在脑子里跑一遍才知道错在哪—— 而脑子里跑的就是这个顺序。先知道顺序，才能跑。

2.3 教的「用纸笔跟一遍」跟这是同一件事：纸上的每一行， 对应的就是一个格子被走到的那一下。

两个分号，一个都不能少

三格之间是两个分号。写错了编译器不会猜，它会当场停下。

把第一个分号写成逗号，是最常见的一种： 

    for (int i = 1, i <= 5; i = i + 1) {

2.4-err-comma.cpp:9:22: error: expected ‘;’ before ‘<=’ token

      |                      ^~~
      |                      ;
2.4-err-comma.cpp:9:23: error: expected primary-expression before ‘<=’ token
    9 |     for (int i = 1, i <= 5; i = i + 1) {
      |                       ^~

读这一行：error: expected ';' before '<=' token——「 在 <= 前面，我等着一个分号」。

更值钱的是下面那两行——编译器把那个分号画出来了： 

      |                      ^~~
      |                      ;
                             ↑ 它说的分号，就画在这个位置

报错里的 ^ 指着哪儿，就盯哪儿看。 这一招 0.3 讲过，这里是最好的例子：它不光告诉你错了， 还告诉你该在那儿补个什么。

少写一格也一样。只写两个格子： 

    for (int i = 1; i <= 5) {
2.4-err-one-semi.cpp: In function ‘int main()’:
2.4-err-one-semi.cpp:8:27: error: expected ‘;’ before ‘)’ token
    8 |     for (int i = 1; i <= 5) {
      |                           ^
      |                           ;

before ')' token——括号要关了，它还等着一个分号。

这个错还有个隐蔽的地方：它看着像「只想写两格」。 写完 i <= 5 手一停，括号就关了。记住—— for 头上永远三格、两个分号，一格都不能省。

第三格空着，就是死循环

那要是故意留空呢？for (int i = 1; i <= 5;) { ... } 是合法的，编译器一个字都不说。

但它跑起来和 2.3 那个「忘了让条件变」的 while 一模一样： i 一直是 1，条件永远成立，一行一行地打 1 停不下来。 按住 Ctrl 再按一下 C 掐掉。

规则很简单：for 头上没有第二格或者第三格，先当自己写错了。 合法不等于写对了。

还有一处会撞墙——出了循环还想用 i： 

    for (int i = 1; i <= 5; i = i + 1) {
        std::cout << i << std::endl;
    }

    std::cout << "循环完了，i 是 " << i << std::endl;    // 这行过不去
2.4-err-scope.cpp: In function ‘int main()’:
2.4-err-scope.cpp:13:39: error: ‘i’ was not declared in this scope
   13 |     std::cout << "循环完了，i 是 " << i << std::endl;
      |                                       ^

'i' was not declared in this scope——「这个名字我不认识」。

奇怪的是 i 明明刚在头上建出来。因为第 1 格建的那个盒子， 只活在循环里。循环一结束，盒子就没了，外面的人看不见它。

循环完了还想知道 i 是几，就把盒子建到循环外面去： 

    int i = 0;                          // 建在外面，循环完了还在
    for (i = 1; i <= 5; i = i + 1) {    // 头上的第 1 格只写 i，不写 int
        std::cout << i << std::endl;
    }
    std::cout << "循环完了，i 是 " << i << std::endl;   // 现在是 6

「活在哪个范围里」这件事有个正式名字叫作用域（scope）， 第 3 部分会专门讲。现在只要记住一条：

for (int i = ...) 里的 int 是「在这儿新建一个盒子」。 外面的循环完了看不见它——这不是毛病，是好事， 盒子用得越少，越不容易互相打架。

用 for 还是 while

两个都能干一样的事，那到底用哪个？

一个简单的判断：你事先知道走几圈吗？

  • 知道——「1 到 n」「第 1 个到第 5 个」——用 for。 三件事写在一行，读的人一眼就看见圈数。
  • 不知道——「一直读，读到 0 为止」「一直除，除到它变成 0」——用 while。 这种循环没有「第几圈」的概念，硬凑一个 for 反而绕。

回头看 2.3 那几道题，你就明白为什么它们大多是 while：

  • 「数出 12345 有几位」——你不知道要除几次，while。
  • 「打 n 的阶乘」——你知道要乘到 n，for 更合适。
  • 「1 加到 100」——知道是 100 圈，for 更合适。

这不是规矩，是习惯。用反了程序照样跑，只是读的人得多花两秒钟。 不过有一件事是确定的：以后看别人的代码， for 一出现，你第一件事就是去头上找那三格。 把圈数交代清楚，是 for 存在的全部理由。

起点和步子都能改

那三个格子里的东西不是固定的。先看起点不写 1——从 0 数起： 

#include <iostream>

int main() {
    int n = 0;
    std::cin >> n;

    for (int i = 0; i < n; i = i + 1) {
        std::cout << i << std::endl;
    }

    return 0;
}

1
2

圈数还是 3 圈，但打出来的数变成了 0、1、2。 从 0 起，条件就得从 <= 改成 <， 不然会多打一个 3——三格是一套的，改一个就得改另一个。

这个「从 0 数到 n-1」的写法，是 C++ 里最常用的一种数法。 现在看着别扭，是因为你还没见过数组。到了 4.2 你会知道： 数组里第一个东西的编号就是 0，所以「第 i 个」天生就是从 0 起的。 先在这儿混个脸熟。

再看第三格不写加 1——每次加 2：

#include <iostream>

2.3 例题那个倒着数的 while 版，换成 for 就是这样。 三件事一起往下走：起点最大，条件跟着反过来， 第三步变成减——只改一半，就是死循环或者一圈都不走。

例题 · 1 加到 n

2.3 用 while 算过 1 加到 100。换成 for， 读完一个 n 再加： 

#include <iostream>

int main() {
    int n = 0;
    std::cin >> n;

    int sum = 0;
    for (int i = 1; i <= n; i = i + 1) {
        sum = sum + i;
    }

    std::cout << sum << std::endl;

100
5050

练习 2-15

算出 1 到 100 之间所有偶数的和（2 + 4 + 6 + … + 100）。 

2550

看答案

第三格每次加 2： 

#include <iostream>

int main() {
    int sum = 0;

    for (int i = 2; i <= 100; i = i + 2) {
        sum = sum + i;
    }

    std::cout << sum << std::endl;

    return 0;
}

起点从 2 开始（第一个偶数是 2，不是 0）， 第三步 i = i + 2，条件 i <= 100。

顺带说一句：这条规矩在实际代码里挺重要。循环是程序里最耗时间的地方， 少转一圈就是快一点。

练习 2-16

这一题第一次在循环里读键盘。

先读一个 n，再读 n 个数，打出它们的和。

输入 4，接着四个数是 3 1 4 1： 

4
3 1 4 1
9

提示：循环转 n 圈，每一圈从键盘拿一个数进来， 就加进 sum。你不需要记住这 n 个数分别是几—— 算完就扔，这是累加最省事的地方。

看答案

cin 写在大括号里： 

#include <iostream>

int main() {
    int n = 0;
    std::cin >> n;

    int sum = 0;
    for (int i = 1; i <= n; i = i + 1) {
        int x = 0;
        std::cin >> x;
        sum = sum + x;
    }

    std::cout << sum << std::endl;

    return 0;
}

每一圈 x 都被重新建一次。 第 1 圈拿到 3，第 2 圈拿到 1—— 拿到 1 的那一刻，上一圈的 3 已经没了，但它早就加进 sum 里了。

这就是「算完就扔」的意思：x 只负责把数递进来， 真正攒住东西的是 sum。 想让 x 一直活着也行（建到循环外面去），但没必要—— 盒子用得越少，越不容易打架。

顺带说一句：这段程序对输入里的空格和换行完全不挑。 上面那四个数，写成 3 1 4 1 一行、还是 3 1 4 1 各占一行， 结果都是 9。这是 1.5 讲的：>> 是「拿一个数」， 不是「拿一行」。

练习 2-17

读一个 n，判断它是不是质数 （质数 = 除了 1 和它自己，没有别的数能整除它）。

输入 9 时：

9 不是质数

提示：质数的意思就是在 2 到 n-1 里，一个能整除 n 的数都没有。 那就用 for 把这些数挨个试一遍—— 每试一个就问一句「n % i 是不是 0」。

问题来了：试到一个能整除的，说明它「不是质数」—— 这件事要记在哪儿？ 1.2 讲过一种专门用来存「是 / 不是」的盒子。

看答案

用一个 bool 记住「有没有找到过约数」： 

#include <iostream>

int main() {
    int n = 0;
    std::cin >> n;

    bool isPrime = true;

    for (int i = 2; i < n; i = i + 1) {
        if (n % i == 0) {
            isPrime = false;
        }
    }

    if (isPrime) {
        std::cout << n << " 是质数" << std::endl;
    } else {
        std::cout << n << " 不是质数" << std::endl;
    }

    return 0;
}

bool isPrime = true; 这句读作：先假设它是质数。 然后挨个试约数，只要逮着一个能整除的，就把这个假设推翻。 循环走完，isPrime 还立着，那它真的是质数。

这个套路叫「打旗子」（flag）： 先立一面旗，找到反例就把旗放倒。以后遇到「这一堆里有没有满足条件的」 基本都是它。4.3 找最大值会用到另一种旗子。

这一题把三样东西凑一块儿了：for 负责挨个试， if 负责判断，bool 负责记住结果—— 第 2 部分学到这儿，你已经能把它们拼起来了。

说个边界：输入 1，它会打出「1 是质数」。 严格说 1 不算质数。这段程序没管这事， 因为题目只要求判断正数——但跟 2.3 那道「0 位」一样， 自己写的程序在边界上是什么行为，心里要有数。

看答案

那段程序完整长这样： 

#include <iostream>

    for (int i = 1; i <= 5; i = i + 1) {

为什么圈数没错却是错的？把每一圈的 i 列出来：

圈i打出来的
第 1 圈00
第 2 圈11
第 3 圈22

五圈，一圈不少；但 i 是从 0 开始的， 所以打出来的是 0 到 4。

  2. 看值：每一行的那些数，对不对？（不对，从 0 起）

你现在能写什么：循环有两种写法，你都会了。 三件事写在一行上的时候，读代码的人一眼就能看见圈数—— 你从现在开始写循环，可以先问自己一句「我事先知道走几圈吗」， 然后挑一个写着顺手的。 下一课是这一部分最需要动手的一课：把循环套进循环。

2.5嵌套循环：循环里面还有循环

到这里，一个循环能干的事你都见过了。这一课说一件听着吓人、其实很朴素的事： 循环里可以再放一个循环。

它有一个正式名字叫嵌套（nest）——就是一个套一个。 实际用起来，能画成表格的东西，基本都得靠它。

一个循环套一个循环

先是这个形状：一个花括号里面，又写了一个完整的 for。 

#include <iostream>

int main() {
    for (int i = 1; i <= 2; i = i + 1) {
        for (int j = 1; j <= 3; j = j + 1) {
            std::cout << "外 " << i << " 内 " << j << std::endl;
        }
    }

    return 0;
}
外 1 内 1
外 1 内 2
外 1 内 3
外 2 内 1
外 2 内 2
外 2 内 3

先看两个名字的习惯：外面那个循环变量叫 i，里面那个叫 j。 再往里面还有一层就叫 k。这不是规矩，但是全世界都这么写， 你照着来，别人一眼就分得清哪个是哪个。

然后看输出，有个地方很关键： 外 1 那三行走完，才轮到 外 2。 不是「外 1、外 2、外 1、外 2……」，也不是两个循环轮流走。

这句话是这一课的全部：

外圈走一步，内圈就从第一步走到最后一步，走完一整轮。 然后外圈再走一步，内圈又从头走一整轮。

为什么是内圈整轮走完？因为内圈那个 for 就老老实实待在外圈的大括号里。对外圈来说， 里面那些东西——包括内圈的整个头和结尾——全都只是「大括号里的内容」， 外圈一次执行一整套，执行完才回去看自己的条件。

外圈走一步，内圈走一整轮

光看输出还是有点抽象。下面这个动画把两个 for 都拆成三行写—— 每一格各占一行，这样高亮才能指到具体是哪一格在走。 （2.4 那个动画也是这么拆的；拆行是合法的 C++，跟上面那段程序跑出来一模一样。）

按「下一步」，重点盯两件事：

  1. 外圈的 i 是什么时候变的；
  2. 外圈第二圈开始时，内圈的 j 是几。

走到第 17 步的时候，你应该看到 j 又变成 1 了—— 不是接着上一轮走完的 3 继续往下数，是重新建了一次，从 1 开始。 （嫌一下一下点得累，就按「自动播放」。）

因为 int j = 1; 写在内圈的第 1 格里， 而内圈整个待在外圈的大括号里。外圈每转一圈，都把它从头执行一遍。

这里是最容易想错的地方

很多人第一次会以为 j 是「接着数」的—— 外圈第二轮，内圈就从 4 开始，一路数到 6。 毕竟变量建过一次之后，不就一直在那儿吗？

不是。2.4 讲过一句话，在这儿正好用上： for (int j = ...) 里的 int 是「在这儿新建一个盒子」。 内圈每重新开始一轮，都新建一个 j，值是 1。 盒子只活在它那两个大括号之间——动画第 15 步你会看见 j 的盒子没了， 下一步它才又冒出来。

数一数走了几遍

从那个动画里也能数出来：外圈转 2 圈，内圈每圈转 3 次， 最里面那句一共走了 2 乘 3 = 6 遍——屏幕上正好 6 行。

验证一下。加一个盒子专门数它： 

#include <iostream>

int main() {
    int count = 0;

    for (int i = 1; i <= 2; i = i + 1) {
        for (int j = 1; j <= 3; j = j + 1) {
            count = count + 1;
        }
    }

    std::cout << "里面那句一共走了 " << count << " 遍" << std::endl;

    return 0;
}
里面那句一共走了 6 遍

这个数一定是乘出来的：外圈转 1 次，内圈转满 3 次； 外圈转 2 次，内圈就转满 2 轮 3 次。

记住这个乘法，以后有用。下一课要打的乘法表是 9 乘 9， 最里面那句就要走 81 遍——81 个结果，一个都不能手写。

用纸笔跟一遍

前面讲 while 的时候说过「用纸笔跟一遍」。 嵌套循环是这件事最该用、也最值的地方—— 因为光凭眼睛看，嵌套循环会骗你。

办法很土，四步：

  1. 画两列，一行算一圈。第一列写外圈的 i， 第二列写这一轮里内圈会走过的 j。
  2. 从外圈的第 1 格开始，一行一行往下写。 不要跳，觉得「这我懂了」的地方恰恰会错。
  3. 碰到内圈，就把内圈整轮写完再往外走。 内圈没走完就回去动外圈，是手跟的时候最常见的错。
  4. 写完和预期输出对一遍。对不上，错的那一行就在你眼前—— 比盯着代码空想快得多。

拿上面那个 2 乘 3 的程序，跟出来就是这样：

外圈第几轮i这一轮内圈走过的 j打出来的
第 1 轮11、2、3外 1 内 1 / 外 1 内 2 / 外 1 内 3
第 2 轮21、2、3外 2 内 1 / 外 2 内 2 / 外 2 内 3

看第三列第二个格子：又是 1。 跟上面那个动画说的是同一件事。

这张表还有一个用处：它同时就是预期输出。 你把表写完了，程序该打什么你也知道了。 跑出来不一样，那就是程序错了，不用怀疑自己。

内圈的上限，常常是外圈那个数

前面两个循环的圈数都是写死的（2 和 3）。 真正好用的嵌套循环里，内圈的圈数是跟着外圈变的—— 内圈的条件里会出现 i。

比如「第 1 行打 1 个星号、第 2 行打 2 个、第 3 行打 3 个」： 

    for (int i = 1; i <= n; i = i + 1) {
        for (int j = 1; j <= i; j = j + 1) {    // 上限是 i，不是 n
            std::cout << "*";
        }
        std::cout << std::endl;
    }

j <= i——这一处就是整段程序的灵魂。 外圈现在是第几行，内圈就打几个。

还有一件事得说清楚：那个 std::cout << std::endl; 写在内圈外面、外圈里面。

它的位置决定了「什么时候换行」。写在那个位置，意思是 「内圈整轮打完了，换一行」——一行一行就是这么来的。 要是手滑把它写进内圈的大括号里，就变成每打一个星号换一行， 三角形会竖过来变成一条线。

2.6【综合练习一】9×9 乘法表

第 2 部分到这儿收尾。这一课把前面五课的东西凑一块儿，做一道综合练习。

先说一句：这道题你现在已经会了。它的骨架就是上一课那个直角三角形。 新就新在一点：它不告诉你怎么写——只说清要什么， 再甩一张输出样式给你，剩下的自己看着办。这正是以后所有题的样子。

题目

综合练习一 · 9×9 乘法表

题目的原话是：「使用 C++ 输出 9*9 乘法表（分别使用 for 与 while 实现）」， 后面跟着一张输出样式（这里只截了头四行和最后一行）。 

1×1= 1
1×2= 2 2×2= 4
1×3= 3 2×3= 6 3×3= 9
1×4= 4 2×4= 8 3×4=12 4×4=16
……
1×9= 9 2×9=18 3×9=27 4×9=36 5×9=45 6×9=54 7×9=63 8×9=72 9×9=81

题目全部加起来就这两句话，一个字没改， 可要读出来的东西至少三件：

  1. for 一版、while 一版，两版都得有。 「分别使用 for 与 while 实现」，意思不是「随便挑一个」。
  2. 要打出去的乘号是 ×，不是代码里敲的那个 *。 题目文字里写的是「9*9 乘法表」，输出样式里却是 1×1= 1—— 以样式为准。
  3. 每个算式的长短得一样齐。看这两个： 1×1= 1 等号后面有个空格，9×9=81 后面没有。 为什么会这样、要怎么写才能这样——题目一个字没提， 全藏在这张样式里。

它就是 2.5 那个三角形

先别急着写代码，看形状。

1×1 一行，1×2 2×2 一行，1×3 2×3 3×3 一行…… 一行比一行多一个。

2.5 的例题是什么？「第 1 行打 1 个星号、第 2 行打 2 个、第 3 行打 3 个」。 一模一样。

2.5 例题这一题
外圈管什么第几行第几行
内圈管什么这一行打几个这一行打几个算式

为什么漂？因为每个格子的长度不一样：

你自己写的时候也会撞上这个：只要每格宽度不固定，右边就一定对不齐。

把宽度定死

毛病找到了：格子有长有短。那治它的办法就只有一个—— 让每个格子一样长。

1.6 学过工具：printf 的宽度，%2d 是「至少占两格」。 

printf("%d×%d=%2d ", j, i, i * j);

这一行里有三处讲究，挨个看。

一、那个 %2d。乘法结果这一格，不管是一位数还是两位数，都占满两格： 

1×1= 1      ← 1 前面补了一个空格，凑够两格
9×9=81      ← 本来就两格，一个都不补

这样一来，每个算式的长度就固定成 6 个字符了： j 一格、× 一格、i 一格、= 一格、结果两格。 后面再跟一个空格当间隔，一格就是 7 个字符—— 列的位置从此一动不动。

引号里的 × 不是乘号

1.3 说过：在代码里算乘法要写 a * b，不能写 a × b。 这句没错，现在也还是这样——这个 × 跟算乘法一点关系都没有。

看这一行里两个东西的位置： 

printf("%d×%d=%2d ", j, i, i * j);
         ↑                    ↑
      引号里面            引号外面
      要打出去的字符        才是算乘法

引号里的 ×，是「把 × 这个字符打到屏幕上」的意思， 跟引号里的 =、%d 是一路货。 真正算 i 乘 j 的，是引号外面那个 i * j。

上面那张输出样式里，乘号就是这个 ×。 你打一个 * 上去，两边就不一样了——所以这里得照着样式敲。

行第 2 列第 3 列第 4 列
第 2 行8——
第 3 行815—
第 4 行81522
第 5 行81522
第 9 行81522

从头到尾一个数都不变。这就是对齐。

为什么写 2 就够了

1.6 说过 %2d 是「至少」两格，不是「正好」两格。 那万一来了三位数怎么办？整列还是会被顶歪。

这一题里不会：乘法表最大的积是 9 乘 9 = 81，两位数封顶。 所以 2 够了。

两个地方和 2.5 的例题不一样，其余一模一样：

  1. 换成 printf，结果是 %2d。 std::cout 也有办法对齐，但要额外写东西； 1.6 就说过，要定宽度就用 printf，它是为这个来的。 注意 printf 里不能用 std::endl， 换行写 "\n"——也是 1.6 讲的。
  2. 算式里 j 在前面、i 在后面。 第 i 行里的第 j 个算式写成 j*i， 这样一行里第一个因数正好是 1、2、3……顺着排。 写成 i*j 乘积一样，但一整行都是 3×1= 3 3×2= 6， 看着累。

再用 while 写一版

题目要的正是「for 和 while 各来一版」， 所以这一版不能省。同一张表，while 版： 

#include <cstdio>

int main() {
    int i = 1;
    while (i <= 9) {
        int j = 1;                      // ← 这一句不能挪到循环外面去
        while (j <= i) {
            printf("%d×%d=%2d ", j, i, i * j);
            j = j + 1;
        }
        printf("\n");
        i = i + 1;
    }

    return 0;
}

打出来的东西和 for 版一个字符都不差。

两版摆在一起，正好能看出 2.4 讲的那件事——三件事散在三处：

for 版while 版
起点头上第 1 格进循环之前那句 int i = 1;
条件头上第 2 格while (i <= 9)
步子头上第 3 格循环体最后一句 i = i + 1;

现在说那个注释。int j = 1; 必须写在外圈的大括号里面、 内圈的前面。

写成 for 版的时候这件事是自动的：int j = 1 就在内圈头上， 外圈每转一圈都重新执行一遍。 换成 while 就得自己想着——写漏了，它就变成这样： 

1×1= 1
2×2= 4
3×3= 9
4×4=16
5×5=25

每一行只剩一个了。因为 j 一直没重新数： 外圈第二圈开始时 j 还是上次停下的 3， 内圈那句话 j <= i 一进门就不成立，一次都不走。

这是把 for 改写成 while 时最容易丢的一处。 改的时候别一句一句搬，先问自己：原来那些「每轮重新建一次」的盒子，都还在它们该在的大括号里吗？

int main() {

    int i = 1;

            printf("%d×%d=%2d ", j, i, i * j);
            j = j + 1;

        printf("\n");

为什么写成斜线了？把每一轮列出来：

外圈第几轮i进内圈时 j 是几j <= i 吗这一行
第 1 轮11成立1×1= 1
第 2 轮22（上一轮停在这）成立一次就完2×2= 4
第 3 轮33成立一次就完3×3= 9
第 9 轮99成立一次就完9×9=81

j 一次都没重新数过。第一轮走完，j 停在 2； 第二轮一进门，条件 j <= i 就是 2 <= 2—— 成立，但只成立这一次，打完 2*2 就 j 变 3 出局了。 所以每一行正好剩一个 i*i，摞起来就是那条斜线。

和 2.6 正文里 for 版对比着看，这个错就更清楚了： for 版把 int j = 1 写在内圈头上， 那句话在外圈的大括号里，外圈每转一圈都重新走一遍， 所以你不用操心。while 版把起点挪到了循环外面， 「每轮重新来一次」就没人替你做，得自己写。

这一题的意义不在这一行代码，在「for 改 while 要改什么」。 改的时候逐句看，别整段搬：

  1. 头上三格，分别搬到哪三处去了？
  2. 哪几个盒子原来是「每轮新建一次」的？现在还在该在的大括号里吗？

第二问就是这一题。漏了它，程序照样编译、照样跑、照样不报错， 只是答案悄悄变成错的——这种错最难逮，纸笔跟一遍才看得见。
