第 5 部分

自己造类型

前面四部分，用的全是 C++ 已经给你准备好的东西：int、 double、string、数组、vector。 这一部分反过来——你自己造类型。 把几样东西捆成一样，给它起个名字，然后像用 int 一样用它。

5.1struct：把几个东西捆在一起

4.6 收尾那份程序里，一个 vector<int> 装了一堆成绩。 可成绩只是一样东西。真要记一个人，你得记三样： 叫什么、学号多少、考了多少分。 这一课就干这一件事——把三样捆成一样。

一个人，三样东西

名单上三个人。用第 4 部分学的东西，最直接的写法是开三排盒子： 

std::string names[3] = {"小明", "小红", "小刚"};
int ids[3] = {101, 102, 103};
int scores[3] = {90, 85, 95};

「小明」的三样东西分别住在 names[0]、ids[0]、 scores[0]。它们之间什么关系都没有—— 全靠一件事撑着：你记得它们下标一样。

现在换个位置。老师说按成绩重排一下，你把第 0 个和第 2 个换过来： 

#include <iostream>
#include <string>

int main() {
    std::string names[3] = {"小明", "小红", "小刚"};
    int ids[3] = {101, 102, 103};
    int scores[3] = {90, 85, 95};

    std::string t1 = names[0];
    names[0] = names[2];
    names[2] = t1;

    int t2 = scores[0];
    scores[0] = scores[2];
    scores[2] = t2;

    // ids[0] 和 ids[2] 忘了换

    for (int i = 0; i < 3; i++) {
        std::cout << names[i] << " " << ids[i] << " " << scores[i] << std::endl;
    }

    return 0;
}

编译干净，一个警告都没有，退出码 0。打出来是： 

小刚 101 95
小红 102 85
小明 103 90

看出来了吗——小刚的学号是 101，小明的学号是 103。 这两个学号都错了，它们是从换之前那儿剩下来的。 换名字的时候换了两个盒子，换成绩的时候换了两个盒子，学号那一排没动， 于是它就跟名字那一排错开了。

程序不知道这三排盒子是一伙的。在它眼里那就是三个互不相干的数组， 你在第二个数组里少写两行，它凭什么管你。

「一个人」这个东西，在你的程序里根本不存在。 存在的是三排分开的盒子，是你脑子里那个「它们下标一样」的约定 在替它们维持关系。约定这种东西，写的时候记得，改的时候就忘了。

把它们捆成一个盒子

C++ 有一个办法，能让你真的造出「一个人」这样东西： 

struct Student {
    std::string name;
    int id;
    int score;
};

struct 是「造一个新类型」的意思。这三行读作：

有一种东西，叫 Student；它里面装着三样： 一样叫 name，是 string； 一样叫 id，是 int； 一样叫 score，是 int。

末尾那个分号别忘。它不是可有可无的装饰——大括号后面那个 ; 是整个定义的一部分。漏了的话，报错会指到你后面好几行去， 看着像别的地方出了问题（0.3 里见过这种「指着别处」的报错）。

造出来之后，它用起来和 int 是一回事： 

#include <iostream>
#include <string>

struct Student {
    std::string name;
    int id;
    int score;
};

int main() {
    Student a;

    a.name = "小明";
    a.id = 101;
    a.score = 90;

    std::cout << a.name << " " << a.id << " " << a.score << std::endl;

    return 0;
}
小明 101 90

新东西只有一个：那个点。 a.name 读作「a 的 name」。 点号左边是一个 Student，右边是它里面装着的那样东西。

整个程序里最重要的其实是第 9 行那句 Student a;—— 它跟 int a; 是同一个句式。 你现在有了一个自己造的类型，而且它跟 int 平起平坐。

一排盒子，每盒装一整份

既然 Student 和 int 平起平坐， 那第 4 部分那些写法就全都用得上。比如开一排： 

Student s[3];      // 三个学生

访问里面某一个人的某一样东西，就是两个点号的事： 

s[0].name = "小明";
s[0].id = 101;

s[1].name = "小红";
s[1].id = 102;

s[0] 先取出第 0 个学生， s[0].name 再取出他的姓名。 顺序是「先找到人，再找他的东西」，别反过来。

还有一件第 4 部分留下来的好东西，在这儿照样管用： 

Student a = s[0];      // 整个复制过去

4.4 讲交换两个元素的时候，你用的是「多开一个盒子先存着」。 当时那个盒子里装的是 int。现在装 Student—— 三个盒子还是那三个盒子，写法一个字都没变。 这是 struct 最值钱的地方：盒子里装的东西变大了， 可操作它们的写法不用跟着变。

例题 · 一张三个人的名单

把上面几样凑一起——struct 加数组加遍历： 

#include <iostream>
#include <string>

struct Student {
    std::string name;
    int id;
    int score;
};

int main() {
    Student s[3];

    s[0].name = "小明";
    s[0].id = 101;
    s[0].score = 90;

    s[1].name = "小红";
    s[1].id = 102;
    s[1].score = 85;

    s[2].name = "小刚";
    s[2].id = 103;
    s[2].score = 95;

    for (int i = 0; i < 3; i++) {
        std::cout << s[i].name << " " << s[i].id << " " << s[i].score << std::endl;
    }

    return 0;
}
小明 101 90
小红 102 85
小刚 103 95

跟这一课开头那份反例摆在一起看，差别在这儿： 

三排数组版              捆起来之后
------------------      ------------------
names[i]                s[i].name
ids[i]                  s[i].id
scores[i]               s[i].score

想拿一个人的全部，    想拿一个人的全部，
得写三个下标           写一个 s[i] 就够了

三个下标的意思是你得同时记住三件事。一个下标的意思是只要记住一件。

还有一个不那么明显的好处：现在「一个学生」能整个递出去了。 三排数组那会儿，你想把「一个学生」递给别的地方， 得递三个参数，还得保证它们仨不错位。 现在它就是一样东西，像递一个 int 那样递它就行。 这一点在 5.2 会变得很重要。

练习

练习 5-1

定义一个 struct Point，里面装两个 int： x 和 y。 然后开一个 Point，把它的 x 设成 3、 y 设成 4，打出来。 

3 4

提示：这题就是本课那个 Student 的简化版—— 两样东西，全是 int。

看答案

两个 int，装进一个叫 Point 的盒子里：

#include <iostream>

struct Point {
    int x;
    int y;
};

int main() {
    Point p;

    p.x = 3;
    p.y = 4;

    std::cout << p.x << " " << p.y << std::endl;

    return 0;
}

看 main 那四行：p 是一个盒子， p.x 是它里面那一格。 跟用一个 int 没什么两样，只是名字前面多了个 p.

练习 5-2

先读一个整数 n，表示有几个人； 接着读进来 n 个人的姓名、学号、成绩； 最后按读进来的顺序，一行一个，原样打出去。 

3 小明 101 90 小红 102 85 小刚 103 95
小明 101 90
小红 102 85
小刚 103 95

提示：读的时候是三样一起读： std::cin >> s[i].name >> s[i].id >> s[i].score;。 每一段之间用空格隔开就行，cin 自己会跳过去。

看答案

读的时候也是三样连着读：

#include <iostream>
#include <string>

struct Student {
    std::string name;
    int id;
    int score;
};

int main() {
    int n;
    std::cin >> n;

    Student s[100];

    for (int i = 0; i < n; i++) {
        std::cin >> s[i].name >> s[i].id >> s[i].score;
    }

    for (int i = 0; i < n; i++) {
        std::cout << s[i].name << " " << s[i].id << " " << s[i].score << std::endl;
    }

    return 0;
}

一句 cin 读三样，中间的空格它自己跳过去—— 跟单读一个 int 时一样，你不用管空格。

注意循环里那三处是 s[i].name、s[i].id、 s[i].score：先找到第 i 个盒子，再点它里面那一格。 两个下标是同一个 i，所以名字和学号不可能错开—— 这正是 5.1 开头那三排数组做不到的事。

练习 5-3

名单还是那三个人（小明 90、小红 85、小刚 95）， 找出成绩最高的那个，只把他的姓名打出来。 

小刚

提示：这就是 4.3 那个擂台，一个字都不用改思路—— 只是擂台上站的不再是一个分数，是一整个学生。

看答案

跟 4.3 那个擂台摆在一起看，只有一处换了：

#include <iostream>
#include <string>

struct Student {
    std::string name;
    int id;
    int score;
};

int main() {
    Student s[3];

    s[0].name = "小明";
    s[0].id = 101;
    s[0].score = 90;

    s[1].name = "小红";
    s[1].id = 102;
    s[1].score = 85;

    s[2].name = "小刚";
    s[2].id = 103;
    s[2].score = 95;

    int best = 0;
    for (int i = 1; i < 3; i++) {
        if (s[i].score > s[best].score) {
            best = i;
        }
    }

    std::cout << s[best].name << std::endl;

    return 0;
}

4.3 里比的是 a[i] > a[best]， 这里比的是 s[i].score > s[best].score。 擂台上站的不再是一个分数，是一整个学生；比的还是分数那一样。

最后打的是 s[best].name—— 记住的是位置，想要哪一样，就从那个位置上取哪一样。

练习 5-4

名单还是那三个人。把第 0 个和第 2 个学生整个换过来， 然后把三个人打一遍。

小红 102 85
小明 101 90

三个盒子照样用，只是这回盒子里装的是整个学生：

#include <iostream>
#include <string>

struct Student {

int main() {
    Student s[3];

    s[0].name = "小明";

    s[1].name = "小红";

    s[1].score = 85;

    s[2].name = "小刚";

Student t = s[0]; 这一句就把名字、学号、成绩 三样一起搬走了。

要是还像 5.1 开头那样分三排存，换两个人就得换三遍， 每一遍都得自己记着下标别写歪。捆成一个盒子之后， 这些东西自己跟着走。

你现在能写什么：你能自己造一个类型了，而且能把它当 int 用—— 开一个、开一排、整个复制、整个递出去。 再碰上「这几样东西总是一起出现」的场面，你会想到给它们造个盒子， 而不是开三排数组、靠下标硬对齐。 下一课把这个盒子往前推一步：让它自己会干活。

5.2class：让盒子自己会干活

5.1 那份名单程序里，打印那一行挺长： 

std::cout << s[i].name << " " << s[i].id << " " << s[i].score << std::endl;

写一遍还行，写三遍就烦了。3.2 教过办法——把它包成一个函数：

打印这件事，该住在哪儿

#include <iostream>
#include <string>

struct Student {
    std::string name;
    int id;
    int score;
};

void printStudent(Student s) {
    std::cout << s.name << " " << s.id << " " << s.score << std::endl;
}

int main() {
    Student a;
    a.name = "小明";
    a.id = 101;
    a.score = 90;

    printStudent(a);

    return 0;
}

能用。但看调用那一行： 

printStudent(a);

你得把 a 递进去。函数住在盒子外面， 它要看盒子里的东西，只能你递给它。而且 3.4 讲过， 这么递进去的是一个复印件——函数里改 s，外面的 a 不会变。

可「打印一个学生」这件事，除了学生它什么都不干。 那它为什么不能住在学生里面？

函数能住进盒子里

能。把那个函数原样搬进 struct 的大括号里面就行： 

#include <iostream>
#include <string>

struct Student {
    std::string name;
    int id;
    int score;

    void print() {
        std::cout << name << " " << id << " " << score << std::endl;
    }
};

int main() {
    Student a;
    a.name = "小明";
    a.id = 101;
    a.score = 90;

    a.print();

    return 0;
}
小明 101 90

跟上面那份比，两处不一样，都在 struct 那一段里：

一、void print() 这四行现在写在大括号里面了。

二、函数体里写的是 name、id、score， 前面没有 s.。

第二点是这一课真正的新东西。print() 不用接收一个学生—— 它自己就是那个学生的一部分。 它读的 name，就是它所在那个盒子里装着的 name。

调用也跟着变了： 

printStudent(a);      →      a.print();

一个是「打印学生 a」——把 a 递出去，交给外人办。 一个是「a，打印你自己」——让盒子自己动手。 右边那个读起来，主语从函数变成了盒子。

名字也跟着换了：a.print() 和 b.print() 写起来一模一样， 可干的事不一样——打的是各自盒子里的东西。 同一个 print()，它在哪个盒子里，就打印哪个盒子。

这有个正式名字：成员函数（member function）。 住在大括号里面的函数，就是这个类型的一个成员。 name、id、score 是成员， print 也是成员——成员就是「这个盒子里装着的东西」， 不管它是数据还是函数。

struct 和 class，差的到底是什么

到现在为止用的都是 struct。可你翻别人的 C++ 代码， 见到的基本都是 class： 

class Student {
    ...
};

这两个词在 C++ 里只差一条。把上面那份里的 struct 换成 class，别的什么都不动： 

#include <iostream>
#include <string>

class Student {
    std::string name;
    int id;
    int score;
};

int main() {
    Student a;

    a.name = "小明";

    std::cout << a.name << std::endl;

    return 0;
}

编译不过了： 

5.2-class-err.cpp: In function ‘int main()’:
5.2-class-err.cpp:13:7: error: ‘std::string Student::name’ is private within this context
   13 |     a.name = "小明";
      |       ^~~~
5.2-class-err.cpp:5:17: note: declared private here
    5 |     std::string name;
      |                 ^~~~
5.2-class-err.cpp:15:20: error: ‘std::string Student::name’ is private within this context
   15 |     std::cout << a.name << std::endl;
      |                    ^~~~
5.2-class-err.cpp:5:17: note: declared private here
    5 |     std::string name;
      |                 ^~~~

报错里那句话拆开读： 

‘std::string Student::name’ is private within this context
  ^^^^^^^^^^^ ^^^^^^^ ^^^^^^
  它的类型     属于谁  哪一样      私有

意思是：name 是 Student 的私有成员， 你（main）没资格碰。下面那句 note 更直接—— declared private here，尖号指着第 5 行， 说的是「它就是在这一行被定成私有的」。

可你哪儿也没写 private 啊。

这就是 struct 和 class 唯一的差别： 

struct   里面默认全是 public  （公开的，谁都能碰）
class    里面默认全是 private （私有的，只有自己人能碰）

注意是「默认」。你没写，它就按默认的来。 写 struct 的时候默认是公开的，所以 5.1 一路畅通； 换成 class，默认反过来，当场就拦。

那就把默认改回来——在开头写一行 public:： 

#include <iostream>
#include <string>

class Student {
public:
    std::string name;
    int id;
    int score;

    void print() {
        std::cout << name << " " << id << " " << score << std::endl;
    }
};

int main() {
    Student a;
    a.name = "小明";
    a.id = 101;
    a.score = 90;

    a.print();

    return 0;
}
小明 101 90

这次过了，输出跟 struct 那版一模一样。

public: 后面那个冒号别漏。它不是一句命令，是一个标签—— 「从这儿往下，都是公开的」。它一直管到下一个标签出现为止 （后面还会见到 private:，写法一样）。

那到底该写哪个

两个都能用，写出来的程序都能跑，这一课到这里为止它们没有区别。

实际写 C++ 的时候：只是把几样数据凑一块儿的， 比如「一个点」「一条边」，写 struct 的不少； 带一堆函数、要管住自己数据的，基本都写 class， 然后在开头来一行 public:。

你以后看别人的代码，见到的会是 class。 所以后面几课我们都写 class。

例题 · 打印的时候顺便说一句

名单上三个人，打出来的时候顺便标一句及格没有： 

#include <iostream>
#include <string>

class Student {
public:
    std::string name;
    int id;
    int score;

    bool isPass() {
        return score >= 60;
    }

    void print() {
        std::cout << name << " " << score << " ";
        if (isPass()) {
            std::cout << "及格" << std::endl;
        } else {
            std::cout << "不及格" << std::endl;
        }
    }
};

int main() {
    Student s[3];

    s[0].name = "小明";
    s[0].score = 90;

    s[1].name = "小红";
    s[1].score = 55;

    s[2].name = "小刚";
    s[2].score = 77;

    for (int i = 0; i < 3; i++) {
        s[i].print();
    }

    return 0;
}
小明 90 及格
小红 55 不及格
小刚 77 及格

两个地方值得停一下。

一、成员函数也能交回东西。bool isPass() 跟 3.2 学的函数一样： 括号里收什么、前面写交回什么，规矩完全没变，只是它住在盒子里。

二、print() 里写了 isPass()， 前面也没有 s.。 它俩住在同一个盒子里，互相说话不用点名—— print() 里的 isPass()，说的就是「我这个盒子的 isPass()」。

这就是「把数据和操作它的函数捆在一起」的具体样子： score 住在盒子里，isPass() 也住在盒子里， print() 也在。它们离得最近，谁也不用把谁递进来。

前面两课里，Student 都是这么用的：

这里有条分界线，先记下来：上面那些垃圾数，全是 int 打出来的。 盒子里那个 name 要是也打出来，你会发现它每次都是空的、 一点都不随机——std::string 是个类，它自己带着一个 「出生的时候先把自己收拾干净」的办法，没人碰它，它也不会是垃圾。 基本类型没这个待遇，类类型有。 这条线后面讲 this 的那一节会明说，到时候回来对一下。

你可能觉得「那我记得填不就行了」。 可这跟 5.1 开头那个「三排数组靠下标对齐」是同一种毛病—— 全靠你记得。名单上有三十个人，你就得记得三十遍。

这事儿不该让我们操心。

构造函数：出生时自动跑的那一段

C++ 有个办法：在类里写一个跟类同名、前面什么交回类型都不写的函数。 

#include <iostream>
#include <string>

class Student {
public:
    std::string name;
    int id;
    int score;

    Student(std::string n, int i, int s) {
        name = n;
        id = i;
        score = s;
    }

    void print() {
        std::cout << name << " " << id << " " << score << std::endl;
    }
};

int main() {
    Student a("小明", 101, 90);

    a.print();

    return 0;
}
小明 101 90

这个函数叫构造函数（constructor）。三件事记住：

一、名字跟类名一模一样，叫 Student。

二、前面不写交回什么——连 void 都不写。 它不是 void print() 那种句式，它就是光秃秃一个 Student(...)。

三、你不主动调用它。

第三条是关键。看 main 里那一行： 

Student a("小明", 101, 90);

它跟 5.1 里那个 Student a; 是同一个句式，只是后面多了个括号。 括号里递进去的东西，就是给构造函数的参数。 它在你写下这一行的那一刻自动跑一遍——你没写 a.Student(...)，也写不出来这么一句。

所以构造函数的写法和调用都跟普通函数不一样。它只干一件事： 保证这个盒子被造出来的时候，里面不是空的。

对象死的时候：析构函数

构造函数管出生。反过来，C++ 里还有一个函数管死亡，叫 析构函数（destructor）。

写法跟构造函数几乎是照镜子：类名前加一个 ~， 不写交回类型，也不收参数。 

class Student {
public:
    std::string name;

    Student(std::string n) {      // 出生时跑的那一段
        name = n;
        std::cout << name << " 报到" << std::endl;
    }

    ~Student() {                  // 死的时候跑的那一段
        std::cout << name << " 走了" << std::endl;
    }
};

两个名字就差一个 ~（键盘左上角那个波浪号）： Student 是构造函数，~Student 是析构函数。

它什么时候跑？对象活到头的时候。 局部对象（在一个函数里开的盒子）活到那个函数结束。看这份： 

#include <iostream>
#include <string>

class Student {
public:
    std::string name;

    Student(std::string n) {
        name = n;
        std::cout << name << " 出生了" << std::endl;
    }

    ~Student() {
        std::cout << name << " 没了" << std::endl;
    }
};

void speak() {
    Student t("临时同学");

    std::cout << t.name << " 说了一句话" << std::endl;
}

int main() {
    Student a("小明");
    Student c("小刚");

    speak();

    std::cout << "main 要结束了" << std::endl;

    return 0;
}
小明 出生了
小刚 出生了
临时同学 出生了
临时同学 说了一句话
临时同学 没了
main 要结束了
小刚 没了
小明 没了

八行，从上往下对着看：

前三行：main 里开了 a 和 c， speak() 里开了 t。 三个盒子都在，其中「临时同学」是最后出生的。

第四、五行：speak() 里那句话打完，函数体走完， t 就地销毁。你没写过任何一句「删掉 t」——它到点了，自己走。

第六行：main 打出「main 要结束了」。

最后两行：main 也到头了。 c 比 a 晚出生，却比 a 先走—— 同一个函数里开的盒子，死的顺序跟出生正好倒过来。

「临时同学」排在所有人前面走，是因为它生在 speak() 里面： 谁生在里层，谁先走。

跟构造函数一样，它也不是你叫的，是 C++ 自己在那一刻叫的。 （硬写一句 a.~Student(); 语法上确实能过， 但那等于趁人还活着就把葬礼办了，等它真到点的时候 C++ 还会再办一次。 没人这么写。）

两条跟构造函数不一样的地方：

一、析构函数不收参数，所以一个类里只有一个析构函数。 构造函数可以有好几个版本（收三个参数的、收两个的），析构函数不行。

二、你不写，编译器就给你补一个空的。 5.1 到现在那些类一个都没写，照样好好的，就是这么回事。

那什么时候要自己写？对象活着的时候从外面拿了东西的时候。 比如问系统要了一块内存、打开了一个文件。这些东西不在盒子里面， 盒子没了它们也不会跟着没——得有人在盒子消失之前把它们还回去。 这种「拿的时候记一笔，走的时候还回去」的事，就写在析构函数里。

（要内存那件事得用到 6.3 的指针，到时候你会回来找这一段。）

把数据藏起来

现在回头收拾 5.2 留下的一件事。 5.2 说过 class 里面默认是私有的，我们当时加了一行 public: 把默认改回来，然后就接着往下写了。

能不能反过来用？把数据设成私有的，不给外面碰。 

#include <iostream>
#include <string>

class Student {

    std::string name;
    int score;

public:
    Student(std::string n, int s) {

        score = s;

int main() {

    std::cout << a.getScore() << std::endl;

    a.score = 100;

}

那这道门留着干嘛？看这一份： 

#include <iostream>
#include <string>

class Student {
private:
    std::string name;
    int score;

public:
    Student(std::string n, int s) {
        name = n;
        score = s;
    }

    int getScore() {
        return score;
    }

    void addScore(int d) {
        score = score + d;
        if (score > 100) {
            score = 100;
        }
    }
};

int main() {
    Student a("小明", 95);

    a.addScore(10);

    std::cout << a.getScore() << std::endl;

    return 0;
}
100

小明原来 95 分，加了 10 分平时分——95 + 10 该是 105。 可成绩最高就是 100，addScore 里那句 if (score > 100) { score = 100; } 把它封住了。

这就是 private 值钱的地方。成绩藏起来以后， 外面想改它只有一条路：走 addScore。 而这道门是你写的，你想在里面加什么检查就加什么检查。

要是 score 是公开的，外面来一句 a.score = 105;， 谁也拦不住——而且写那一行的人可能是三个月后的你自己。 你管得住今天写的代码，管不住以后随手改的那一下。

这一套有个名字，叫封装（encapsulation）： 数据藏起来，只留几道门，门由盒子里自己管。 外面想知道成绩，走 getScore()；想加分，走 addScore()。

名字重了：this

写构造函数的时候，很容易起这样的参数名： 

#include <iostream>
#include <string>

class Student {
private:
    std::string name;
    int score;

public:
    Student(std::string name, int score) {
        name = name;
        score = score;
    }

    void print() {
        std::cout << "[" << name << "] " << score << std::endl;
    }
};

int main() {
    Student a("小明", 90);

    a.print();

    return 0;
}

看着挺对，其实什么也没干。编译干净，一个警告都没有。连跑四遍： 

[] -1701915728
[] 2009293792
[] -740887328
[] -774683600

名字是空的，分数那几位数字每遍都不一样。 两个格子看起来都空着，可空的原因不一样。 先说分数：它跟这一课开头那份是同一种东西， 那个格子从来没人往里放过东西。

名字那个格子，是被管过的。 std::string 是个类，它自己带一个默认构造函数。 Student 一出生，它就跑了一遍，把 name 稳稳装成一个空字符串——换哪台机器、哪个编译器，它都是空的，不会崩。 int score 就没这个待遇：基本类型没有构造函数，没人管它， 读出来才是内存里剩下的旧东西。 这正好就是这一课在讲的那件事本身：构造函数会自己跑，你不写它也在。

为什么？两个名字重了。参数叫 name，成员也叫 name， 函数体里那个 name 说的是近的那个，也就是参数。 所以 name = name; 是「参数赋给参数」， 成员那个 name 从头到尾一个字都没被碰过。 （3.3 讲过的同名遮蔽，在这儿又出现了一次。）

加三个字符就分开了： 

    Student(std::string name, int score) {
        this->name = name;
        this->score = score;
    }

箭头左边是「我这个盒子的」，右边是递进来的参数： 

this->score = score;
^^^^^ 左边的   ^^^^^ 右边的
我这个盒子的   参数

上面那份错的，改对一共要动两处：构造函数里这两行， 还有 print() 里那对中括号——那份错的名字是空的， 不加中括号，空名字打出来就是行首多一个空格，看不出来。 跑出来是： 

小明 90

this 就是「这个盒子自己」。 this->score 读作「我自己的 score」。 加了箭头，两样东西就分得开了。

在你现在用得到的范围里，this 就是干这个的： 分清楚说的是哪一个。 参数名跟成员名不起冲突的时候，你根本不用写它—— 所以你在别人代码里见到的 this-> 也不多。

写完之后在 main 里加一句 p.x = 5; 试试， 报的就是 5.3 里那三行：is private within this context。 看完把那句删掉。

getX() 短得只有一句 return，看着像白写的。 它值钱的地方不在今天，在以后—— 哪一天你想在「读坐标」这件事上加一句话，有一道门可以改； 没有门，就得去找散在程序各处的每一个 p.x。

练习 5-11

给 Student 加一个 addScore(int d)， 要求它守两条规矩：传进来的负数直接不理， 加完超过 100 就封顶。

小明原来 80 分。先 addScore(-50)，打一次； 再 addScore(30)，再打一次。 

80
100

提示：这题的重点不是语法，是门该开在哪儿。 分数藏在 private 里，外面就只能走这一道门， 两条规矩也就绕不过去。

看答案

两条规矩都写在门里：

#include <iostream>
#include <string>

class Student {
private:
    std::string name;
    int score;

public:
    Student(std::string name, int score) {
        this->name = name;
        this->score = score;
    }

    int getScore() {
        return score;
    }

    void addScore(int d) {
        if (d < 0) {
            return;
        }
        score = score + d;
        if (score > 100) {
            score = 100;
        }
    }
};

int main() {
    Student a("小明", 80);

    a.addScore(-50);
    std::cout << a.getScore() << std::endl;

    a.addScore(30);
    std::cout << a.getScore() << std::endl;

    return 0;
}

负数那句是 return;。 一个前面写 void（不交回东西）的函数，想提前走， 写这么一句就行——交回值的那种才需要 return 值;。

重点在这句：score 藏在 private 里， 外面想改分数只有 addScore 一条路。 两条规矩摆在这条路上，就再也绕不过去了。

class GradStudent : public Student {
                    ^
                    冒号，读作「是一种」

写完之后，GradStudent 自动就有了 Student 里的每一样东西：三个成员、构造函数、print()。 一个字都不用抄。

所以 printAll() 里那句光秃秃的 print() 才叫得出来—— 它就是 Student 那个，是继承来的。 你先在自己家里找，找不到就往上问一层。 （3.3 讲作用域、5.3 讲 this 时，说的「近的那个先」，是同一套规矩。）

父类那部分，谁来装

上面那份里还有一处没讲。构造函数长这样： 

    GradStudent(std::string n, int i, int s, std::string adv)
        : Student(n, i, s) {
        advisor = adv;
    }

研究生出生的时候，盒子里装着两摊东西： 「学生那部分」和「导师那部分」。 导师那部分归 GradStudent 自己（advisor = adv;）， 学生那部分归 Student 管——得有人去叫它的构造函数。

冒号后面那句 Student(n, i, s) 就是干这个的。 它排在函数体前面，先跑。

不写会怎样？有人觉得「继承都继承了，父类那部分应该自动就装好了吧」， 于是写成这样： 

    GradStudent(std::string n, int i, int s, std::string adv) {
        name = n;
        id = i;
        score = s;
        advisor = adv;
    }

为什么会想造一个不收参数的？因为每个对象出生前， 父类那部分总得先装好，而你没告诉它该递什么进去， 它就按最省事的来：什么都不递。 可 Student 偏偏没有「什么都不用递」的那个版本，于是卡住。

出生有先后，死亡也有先后

上一段那份报错的根子，其实是件很简单的事： 父类那部分得先装好，子类那部分才有地方长。

所以出生是有顺序的：先父类，后子类。 上一段那句 Student(n, i, s) 排在函数体前面先跑， 就是这件事的写法。

死亡是这个顺序倒过来：先子类，后父类。 道理也一样——子类那部分是搭在父类那部分上面的， 拆的时候只能从上面往下拆。

光说没用，让程序自己打出来看：

这份里 GradStudent 的构造函数没写冒号后面那句。 为什么能省？因为这里的 Student 有一个不收参数的构造函数。 上一段那份报错喊的「找不到」，找的就是这样一个函数——父类有了它， 子类不写那句也接得上，编译器自己会去叫。

读一遍那句话：「Print() 标着 override， 可它谁也没盖住。」

override 是写给编译器的一句交代：「我这是在盖父类那个函数， 你替我核一下。」 编译器一核，发现父类里没有叫 Print 的虚函数，当场把这一处指出来。

区别就在时候：不写 override，这个错要等到你盯着输出 怀疑人生的时候才发现；写了它，这个错在按下编译的那一秒就送到你眼前。

这两份摆在一起，就是 override 的全部意义： 它不改变程序干什么，它让「没改成」这件事没法悄悄溜过去。

#include <iostream>

#include <iostream>

练习 5-16

写一个 Employee：有 name 和 monthly（月薪），annualSalary() 交回年薪 （月薪 × 12）。

造一个普通员工（8000）和一个经理（8000，奖金 50000）， 年薪各打一行。

146000

看答案

经理的年薪，是在父类那份上再加奖金：

#include <iostream>
#include <string>

class Employee {
public:
    std::string name;
    int monthly;

    Employee(std::string name, int monthly) {
        this->name = name;
        this->monthly = monthly;
    }

    int annualSalary() {
        return monthly * 12;
    }
};

class Manager : public Employee {
public:
    int bonus;

    Manager(std::string name, int monthly, int bonus)
        : Employee(name, monthly) {
        this->bonus = bonus;
    }

    int annualSalary() {
        return Employee::annualSalary() + bonus;
    }
};

int main() {
    Employee e("小明", 8000);
    std::cout << e.annualSalary() << std::endl;

    Manager m("小红", 8000, 50000);
    std::cout << m.annualSalary() << std::endl;

    return 0;
}

Manager::annualSalary() 里那句 Employee::annualSalary()，就是「爸，你那份先算一遍」。 那十二个月的乘法一次都没重抄。

5.5【综合练习二·类版】把找最小值装进 MyClass

这一部分是收尾。4.5 那道题你已经会做了——散着的数组和循环。 这一课把它整个装进一个类里。

先把题目看清楚

题目

成员函数：编写类 MyClass，定义成员函数 fun， 实现查找数组最小值，并将最小值与数组末尾元素互换位置。 主函数中录入数组长度与数组数据，实例化类对象调用该成员函数， 最终分别打印输出交换前后的数组

测试样例：5, 34, 1, 2, 56, 4
输出样式：34, 4, 2, 56, 1

题目就这几句话，可它每一句都在派活。拆开看： 

编写类 MyClass                       →  盒子叫这个名字
定义成员函数 fun                     →  动作叫这个名字
实现查找数组最小值
并将最小值与数组末尾元素互换位置     →  这个动作要干的事

主函数中录入数组长度与数组数据       →  main 读输入
实例化类对象调用该成员函数           →  main 里造一个、调一下
最终分别打印输出交换前后的数组       →  main 打两行

先看前两句。MyClass 和 fun 这两个名字， 是题目直接给的，照抄。 不管你平时习惯把这种动作叫 findMinToLast 还是别的， 交上去的东西必须叫 fun——这类题点名要的就是它。 名字对不上，活儿全干对了也是白干。

再看最后一句，这是真正的坑：要打两份。 交换前的数组一行，交换后的数组一行，一共两行。 4.5 那道题只要求打一份，这道题多要了一份，别照搬。

剩下那个逗号。题目里输入输出都写成 5, 34, 1, 2, 56, 4， 那个逗号是文档排版用的分隔符。输入那行肯定是—— std::cin >> n 读到 5 就停，逗号它读不进去。 所以课里统一用空格隔开，跟 4.5 一样。你要是想在输出里加逗号也行， 那就自己拿定一个，别一半一半。

版本一：照题目写

题目的分工写得很明白：读输入、打输出是 main 的事， fun 只管「找最小 + 和末尾交换」这一件事。 那就照这个分工写： 

#include <iostream>

class MyClass {
public:
    void fun(int a[], int n) {
        int minIdx = 0;
        for (int i = 1; i < n; i++) {
            if (a[i] < a[minIdx]) {
                minIdx = i;
            }
        }

        int t = a[minIdx];
        a[minIdx] = a[n - 1];
        a[n - 1] = t;
    }
};

int main() {
    int a[100];
    int n;

    std::cin >> n;

    for (int i = 0; i < n; i++) {
        std::cin >> a[i];
    }

    // 交换前
    std::cout << a[0];
    for (int i = 1; i < n; i++) {
        std::cout << " " << a[i];
    }
    std::cout << std::endl;

    MyClass m;
    m.fun(a, n);

    // 交换后
    std::cout << a[0];
    for (int i = 1; i < n; i++) {
        std::cout << " " << a[i];
    }
    std::cout << std::endl;

    return 0;
}

输入（就是题目给的那组样例）： 

5 34 1 2 56 4
34 1 2 56 4
34 4 2 56 1

第二行和题目底下那行「输出样式」34, 4, 2, 56, 1 是不是一个数不差？第一行是题目要的「交换前」， 拿它跟第二行对着看，交换干了什么一眼就明白。

main 里那两段打印，长得一模一样。 先别嫌它啰嗦——这是故意的：把「打印」原样写两遍， 中间夹一个 m.fun(a, n)，前后一对比，变化就看出来了。 下面版本二会把这个重复收掉。

再看 fun 的签名，这儿有个新东西： 

void fun(int a[], int n)

数组当参数传进去，函数里改了它，外面那个数组真的会变。 你可能想起 3.4 那句「值传递：函数里改了外面不变」—— 那条规矩没错，但它说的是 int 这种单个变量。 到现在为止你见过的类型里，数组是唯一一个例外： a 传进去不会复制一整份（一百个盒子，复制太贵）， 函数里拿到的就是外面那个数组本身。

凭什么这样，第 6 部分会讲透（一句话预习：数组名递过去的时候， 真正传的是第一个盒子的地址）。现在只要认一件事： 这份程序能跑对，全靠它。 fun 在里头换完了，main 打出来的就是换过的那一串—— 上面第二行输出就是证据。

回过头再看 fun 里那十来行，跟 4.5 的解法是同一套东西： 记住下标的找最小（4.3）、三行交换（4.4）、 a[n - 1] 是最后一个（4.2）。 一个字都没变，只是换了住的地方。

版本二：数据也住进盒子里

题目没规定 fun 收什么参数。所以还有另一种装法—— 把数组和个数也存进盒子，那 fun() 就一个参数都不用收了： 它们就在自己家里，直接看得见。 

#include <iostream>

class MyClass {
private:
    int a[100];
    int n;

public:
    MyClass() {
        n = 0;
    }

    void read() {
        std::cin >> n;

        for (int i = 0; i < n; i++) {
            std::cin >> a[i];
        }
    }

    void fun() {
        int minIdx = 0;
        for (int i = 1; i < n; i++) {
            if (a[i] < a[minIdx]) {
                minIdx = i;
            }
        }

        int t = a[minIdx];
        a[minIdx] = a[n - 1];
        a[n - 1] = t;
    }

    void print() {
        std::cout << a[0];
        for (int i = 1; i < n; i++) {
            std::cout << " " << a[i];
        }
        std::cout << std::endl;
    }
};

int main() {
    MyClass m;

    m.read();
    m.print();
    m.fun();
    m.print();

    return 0;
}

同一份输入，输出和版本一一个字都不差： 

34 1 2 56 4
34 4 2 56 1

好处在 main 里一眼看得出来。版本一那两段重复的打印， 在这儿成了三句： 

m.print();
m.fun();
m.print();

「打一遍、换、再打一遍」——三行连着读下来就是这句话。 这就是 3.1 那句「main 不该太长」一路走到头的样子。

两种装法摆一起看：

                        版本一              版本二
                        ------------------  ------------------
数组 a 和个数 n 住在哪  main 里             盒子里
fun 收几个参数          两个（a[] 和 n）    零个
打印那两行谁来打        main 里的 cout      m.print()
main 里有几句           一长串              四句

两种都对。题目没把话说死，交哪一份都行。 要紧的是名字——MyClass 和 fun 不能改。

有个常见的错法值得点一下：版本一的 fun 收两个参数， 版本二那个 一个都不收。 把版本一的 m.fun(a, n) 原样搬到版本二上，编译就过不去。 签名不一样，调法就不一样，跟哪一份「更好」没关系。

自己给自己出几组输入

题目就给了一组样例。可 4.5 的练习和 5.4 都教过同一件事： 样例过了，不等于对。 下面这几组是自己该动手喂的，每一组都盯着一个特定的地方。 表里只列「交换后」那一行（「交换前」就是你输进去的那串数，原样打一遍）： 

输入           这一组在试什么      交换后
-------------  ------------------  -------------
5 34 1 2 56 4  题目给的那组        34 4 2 56 1
5 4 9 1 7 3    最小值在中间        4 9 3 7 1
5 4 9 3 7 1    最小值就在最后一个  4 9 3 7 1
5 4 2 8 2 6    有两个一样小的      4 6 8 2 2
1 7            只有一个数          7

第二行和第三行的输出长得一样，不是巧合： 那串数本来就已经是 4 9 3 7 1，最小值在最后一个， 交换等于没换。可它照样值得跑—— 要是程序把别的格子当成了最小值，这一组就未必还一样。

第四行试的是「有两个一样的数」。 4 2 8 2 6 里有两个 2，程序认的是靠前那个（编号 1）， 和末尾的 6 换，于是 6 落到了第二位。 你这组要是打出来不一样，先别怀疑自己，把下标一个个念出来对。

最后一行更要紧。只有一个数的时候最容易出事—— a[n - 1] 和 a[minIdx] 是同一个格子， 交换那三行等于自己和自己换。这组过了， 说明你没把「至少有两个数」当成理所当然。

二、int minIdx = 0;——从第 0 个开始当候选。 写成 1 就是找错那道题（练习 5-20）。

三、交换走的是 a[n - 1]，不是 a[n]。 最后一个格子的下标是 n - 1（4.2 那条规矩： 下标是「从开头数第几个」，从 0 数）。

还有一件不在代码里的事：那两行都打出来了吗？ 「交换前」一行、「交换后」一行。只打一行，是这道题最常见的错法。

练习 5-18

接着上一题，给盒子加一个动作 sum(int a[], int n)， 交回这串数的总和。在「交换后」那一行底下再打一行总和。 

5 34 1 2 56 4
34 1 2 56 4
34 4 2 56 1
97

提示：sum 跟 fun 是兄弟，住在同一个盒子里。 它也要收 a[] 和 n——数据在 main 那儿， 不递进去它看不见。

看答案

加一个动作，跟 fun 并排住：

#include <iostream>

class MyClass {
public:
    void fun(int a[], int n) {
        int minIdx = 0;
        for (int i = 1; i < n; i++) {
            if (a[i] < a[minIdx]) {
                minIdx = i;
            }
        }

        int t = a[minIdx];
        a[minIdx] = a[n - 1];
        a[n - 1] = t;
    }

    int sum(int a[], int n) {
        int total = 0;
        for (int i = 0; i < n; i++) {
            total = total + a[i];
        }
        return total;
    }
};

int main() {
    int a[100];
    int n;

    std::cin >> n;

    for (int i = 0; i < n; i++) {
        std::cin >> a[i];
    }

    // 交换前
    std::cout << a[0];
    for (int i = 1; i < n; i++) {
        std::cout << " " << a[i];
    }
    std::cout << std::endl;

    MyClass m;
    m.fun(a, n);

    // 交换后
    std::cout << a[0];
    for (int i = 1; i < n; i++) {
        std::cout << " " << a[i];
    }
    std::cout << std::endl;

    std::cout << m.sum(a, n) << std::endl;

    return 0;
}

sum 也得收 a[] 和 n—— 数据住在 main 那儿，不递进去它看不见。 这是版本一那种装法必然要付的代价： 谁想碰这串数，谁就得先把它接过来。

（版本二里数据在盒子里面，sum() 才能一个参数都不收。）

调用那行 m.sum(a, n) 写在最后，所以总和排在 「交换后」底下。换位置不改总和，那三行的先后其实随便。

练习 5-19

把 fun 里那个「找最小」改成「找最大」， 其它的一个字都别动（包括函数名）。 

5 34 1 2 56 4
34 1 2 56 4
34 1 2 4 56

提示：位置那套写法（记住下标的那个变量）一个字都不用动—— 找最大和找最小是同一件事，只是那个小于号朝哪边。

看答案

只改了两处：比较的方向，和那个变量名。

#include <iostream>

class MyClass {

    }

    }

    std::cout << a[0];

        std::cout << " " << a[i];

    std::cout << std::endl;

maxIdx 的初始化、那个循环、交换那三行， 跟找最小那份一个字都没差。 找最大和找最小本来就是同一件事，只是那个大于号朝哪边。

函数名没动，还是 fun。 题目把名字定死了——换的是它干的活，不是它的名字。

交换后是 34 1 2 4 56：题目那组数里最大的是 56 （编号 3），和最后一位的 4 换了。

5 1 9 3 7 4

病根是第 0 个格子被排除在候选之外了。 本来该先认定第 0 个最小，再拿后面每一个去挑战它； 写成 1 之后，第一个格子从头到尾没人比过。

这一类错最坑，也最常见：样例过了不等于对。

你现在能写什么：给你一个类名、一个动作名、一句要求， 你能把它填成一个能跑的程序， 数据在里面还是在外面，两种装法你都写得出来。 给你一个名字，你能让那个名字底下真长出东西来。 往回想一遍：5.1 把三样东西捆起来，5.2 让盒子自己会干活， 5.3 管住出生和规矩，5.4 让一个盒子站在另一个肩上， 5.5 把这件事装了进去。你自己造类型这件事，到这儿就够用了。 下一部分换一个方向：变量到底住在哪儿，以及怎么把地址递来递去。
