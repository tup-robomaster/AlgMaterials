第 7 部分

自己会发现错

前六部分教你写程序。这一部分教你一件更值钱的事：写错了怎么办。 程序不对是常态，不是意外——真写代码的人，大半时间花在这儿。 好消息是它有固定动作：先比输出、再砍半、一次只改一处。 照着走，比盯着屏幕瞎改快十倍。

7.1程序不对时，按什么顺序找

这一课要给你的是一套顺序。不是「多想想」，是三步一步都不能跳的顺序。

先把「不对」分成三种

「不对」不是一件事，是三种。三种的找法完全不同，所以第一件事是分清你碰上的是哪一种。

哪一种，长什么样第一步做什么
编译不过　编译器不让你跑，屏幕上全是红字 读最上面那条 error——0.3 讲过怎么读。三种里最省事
结果不对　跑完了，但打出来的东西不是你要的 比输出，找第一个不一样的地方（这一课的正文）
跑着崩了　冒出 段错误 或者 Segmentation fault 先去看你碰了哪些盒子：越界了没有？指针是不是空的？

第三种的两个来源你都学过：第 4 部分的数组越界写，第 6 部分的空指针。 它们不是「运气不好」，是两个具体动作：往不存在的格子里写、顺着空门牌号找过去。

这一课剩下讲的全是第二种。它最费时间，也最常见。

第一步永远是比输出

碰上结果不对，绝大多数人的第一反应是：从头把代码读一遍，看看哪儿写错了。

这一招基本没用。你已经盯着这段代码看了半小时，能看出来的早看出来了。 而且代码越长越没用——二十行的循环，你读到第八行就忘了前面是什么。

要比的不是代码，是结果。把程序打出来的东西，和你想要的东西，一行一行并排看。 看到第一个对不上的地方，就停下。

例题 · 五个人的平均分

题目：五个人的分数是 80 91 76 88 65，打印总分和平均分。

下面这份程序，编译一声没吭，跑也跑完了。可它打出来的数不对： 

#include <iostream>

int main() {
    int scores[5] = {80, 91, 76, 88, 65};
    int sum = 0;

    for (int i = 0; i < 4; i++) {
        sum = sum + scores[i];
    }

    int avg = sum / 5;

    std::cout << "总分：" << sum << std::endl;
    std::cout << "平均分：" << avg << std::endl;

    return 0;
}

你要的，和它打的，摆在一起： 

总分：400
平均分：80
总分：335
平均分：67

第一行就对不上了。那就不用往下看了——第二行是错的，但它是被第一行带错的。

顺着「总分是谁算出来的」往回找，就找到上面那个循环。 数一数它跑了几圈：i 从 0 开始，条件是 i < 4， 所以跑的是 0、1、2、3 四圈。scores[4] 那个 65 从头到尾没被加进去。

这就是全部。把 i < 4 改成 i < 5，两行全对： 

#include <iostream>

int main() {
    int scores[5] = {80, 91, 76, 88, 65};
    int sum = 0;

    for (int i = 0; i < 5; i++) {
        sum = sum + scores[i];
    }

    int avg = sum / 5;

    std::cout << "总分：" << sum << std::endl;
    std::cout << "平均分：" << avg << std::endl;

    return 0;
}
总分：400
平均分：80

回头看这个过程，值钱的地方在这儿： 「平均分也错了」这条信息，一点用都没有。 它是总分错的结果，不是另一个病。 你要是先盯着平均分看，会怀疑除法——说不定还去查了整数除法、去查了 int 和 double，白花半小时。

一个错地方，会让后面好几行都跟着不对。 所以找第一个，别管后面的。

第一处不一样的地方，不等于病根

上面那题里，「总分」那一行就是病根露头的地方，往回一步就找到了。 但有时候要多走几步。

比如一个函数该把外面那个盒子改掉，实际上没改。那么第一个不一样的地方， 是你最后打印它的那一行——可那一行本身一点错都没有， 它老老实实把盒子里的东西打了出来。错的是「这个盒子为什么会是那个值」。

所以准确的问法不是「这一行写错了什么」，而是： 这一行的值，是从哪儿来的？ 顺着这个「哪儿」往回找一步。要是那一步也没错，再往回一步。

两种错，名字不一样

一种是这行代码本来就写错了（i < 4）； 另一种是这行代码没错，可它拿到的值已经是错的（打印 a 的那行）。 前者要改这一行，后者要往回走。 分不清这两种，就会干出「把打印语句改了又改」这种事。

砍半：把程序砍到最小

第一处不一样的地方找到了，可它归哪一段代码管，还是看不清——程序太长， 中间隔着三四个函数，数据绕来绕去。

这时候用砍半：把跟那一行无关的代码，一段一段删掉。 删完还编译、还能跑出同一个错，就说明删掉的那部分跟这个错没关系，扔了不心疼。

接着删。一直删到删不动为止——再删一行，错就不见了或者程序跑不起来了。 剩下的那十几行，就是完整的一份「能重现这个错」的最小程序。

上面那个平均分的例子，砍完就是这样： 

#include <iostream>

int main() {
    int scores[5] = {80, 91, 76, 88, 65};
    int sum = 0;

    for (int i = 0; i < 4; i++) {
        sum = sum + scores[i];
    }

    std::cout << sum << std::endl;

    return 0;
}
335

打印、平均分、那两句中文，全删了，错照样在。 九行。毛病就摆在明面上。

砍半还有第二个好处：砍完的这份，你要是实在看不出来，可以直接拿去问人。 「这一份打 335，我以为是 400」——比贴四十行过去有用得多。

一次只改一处

到最后一步了，改的时候守两条规矩。

第一条：一次只改一处，改完立刻跑。 一次改五处，跑完还是不对，你就不知道是哪一处没改对—— 甚至不知道刚才那五处里有没有一处改对了。本来只要试两次的事，会变成试三十次。

第二条：改之前，你得说得出「我觉得是这儿，因为……」。 说不出这个「因为」，就说明你还在猜。 猜也不是完全不行，但猜的时候你心里要清楚：我在猜，不是在找。 一件事猜过三次还没中，就别猜了，回到上面第一步重新比输出。

有一种错，第一步比不了

有些程序一会儿对一会儿错——同样的输入，跑两遍结果不一样。 第 4 部分那两个越界读的例子里，多出来的那个数每次都不同，就是这个样子。 碰上这种，先想办法让它稳定地错：换个数组大小、换个输入、 反复跑上十几遍，直到它每次都能错出来。 重现不出来的错，改完你也不知道好没好。

练习

下面每一份都是能编译、能跑，只是结果不对的那种。 按 7.1 的顺序来：先比输出，找到第一处不一样的地方，再往回找病根。

练习 7-1（找错）

它打 总和：40，可你要的是 总和：100。 先别编译，说清楚病根在哪一行、为什么，该怎么改。 

#include <iostream>

int main() {
    int a[4] = {10, 20, 30, 40};
    int sum = 0;

    for (int i = 0; i < 4; i++) {
        sum = a[i];
    }

    std::cout << "总和：" << sum << std::endl;

    return 0;
}
总和：100

提示：输出只有一行，所以「第一处不一样」就是这一行的值。 往回问一句：sum 最后装的是谁？

看答案

改好的版本是这样：

#include <iostream>

int main() {
    int a[4] = {10, 20, 30, 40};
    int sum = 0;

    for (int i = 0; i < 4; i++) {
        sum = sum + a[i];
    }

    std::cout << "总和：" << sum << std::endl;

    return 0;
}

病根是那一行：

sum = a[i];

它没有「加上」，只有「换成」。第 0 轮跑完 sum 是 10， 第 1 轮被 20 盖掉，第 2 轮被 30 盖掉，第 3 轮被 40 盖掉—— 循环一跑完，sum 里只剩最后一个数。

左边那个 sum 一个字都不能少： sum = sum + a[i]; 的意思是「把 sum 和 a[i] 加起来， 结果放回 sum」。等号不是「等于」，是「放进去」， 1.1 那句「先算右边，再放进左边」在这儿又用上了。

练习 7-2（找错）

它打 最小值：0，可这五个数里最小的明明是 3。 病根在哪一行、为什么？ 

#include <iostream>

int main() {
    int a[5] = {7, 3, 9, 4, 6};
    int mn = 0;

    for (int i = 0; i < 5; i++) {
        if (a[i] < mn) {
            mn = a[i];
        }
    }

    std::cout << "最小值：" << mn << std::endl;

    return 0;
}
最小值：3

提示：这一行的值是谁算出来的？那个 if 里的条件， 五轮里成立过几回？

看答案

改好的版本是这样：

#include <iostream>

int main() {
    int a[5] = {7, 3, 9, 4, 6};
    int mn = a[0];

    for (int i = 0; i < 5; i++) {
        if (a[i] < mn) {
            mn = a[i];
        }
    }

    std::cout << "最小值：" << mn << std::endl;

    return 0;
}

病根是那一行：

int mn = 0;

五个数全是正数，而 0 比它们都小。 所以 if (a[i] < mn) 五轮里一次都没成立过， mn 从头到尾没人碰过，最后打出来的就是它一开始那个 0。

改成 a[0] 之后的意思是：先认定第 0 个最小， 再拿后面每一个来挑战它。这才是 4.3 那个找最值的走法。

顺带一句：这一题要是一直盯着最后那行打印看，会一直看不出来—— 那一行没错，它只是把 mn 原样打了出来。 往回走一步，才走到那个 0 上。

练习 7-3（找错）

它打 a = 5，可你要的是 6。 这道题的病根，不在你以为是的那一行。 

#include <iostream>

void addOne(int x) {
    x = x + 1;
}

int main() {
    int a = 5;

    addOne(a);

    std::cout << "a = " << a << std::endl;

    return 0;
}
a = 6

提示：第一处不一样就在这一行，但病根不在这一行—— 这一行只是把 a 打了出来，它没错。错的是 a 为什么会是 5。

看答案

改好的版本是这样（只多了一个 &）：

#include <iostream>

void addOne(int& x) {
    x = x + 1;
}

int main() {
    int a = 5;

    addOne(a);

    std::cout << "a = " << a << std::endl;

    return 0;
}

这一题的重点不是那个 &， 是「第一处不一样的地方，不等于病根」。

第一处不一样的就是打 a 的那一行。可它没错： a 里装的确实就是 5，它老老实实打了出来。 错的是「a 为什么还是 5」——往回走一步，走到 addOne(a);。

那行也没写错，它确实调了。再往回一步，走到函数里那句 x = x + 1;，它也确实跑了。 三行都没错，那错在哪儿？——错在参数表上那个 int x： 它收的是一份抄件，改的也是抄件，函数一走完就扔了。

加上 & 之后，x 不再是抄件， 而是 a 的另一个名字（3.5 和 6.2 都讲过），改它等于改 a。

练习 7-4（找错）

想把 a 和 b 换个位置，结果两个都成了 2。 

#include <iostream>

int main() {
    int a = 1;
    int b = 2;

    a = b;
    b = a;

    std::cout << "a = " << a << "，b = " << b << std::endl;

    return 0;
}
a = 2，b = 1

提示：想想 4.4 那个第三个盒子。这一题要加两行、动一行， 但按规矩，还是一处一处来，改完就跑。

看答案

改好的版本是这样：

#include <iostream>

int main() {
    int a = 1;
    int b = 2;
    int t = 0;

    t = a;
    a = b;
    b = t;

    std::cout << "a = " << a << "，b = " << b << std::endl;

    return 0;
}

病根是少了一个盒子：

a = b;
b = a;

第一句跑完，a 里原来那个 1 就没了——被 2 盖掉了。 第二句 b = a; 里的 a 已经是 2 了， 所以 b 也成了 2。两个都成了 2。

这就是 4.4 那个「为什么需要第三个盒子」：换之前得有个地方先放 1， t 就是那个地方。

至于「一次只改一处」——这一题要动三行，顺序还不能反。 真写的时候可以这么拆：先把 a = b; 改成 t = a; 跑一遍 （这时候 a 还是 1、t 是 1、b 是 2，看着没变就对了）， 再往下加一句，一句一句来。

练习 7-5（找错）

前三个答案都对，第四个该是 3.5，它打了 3。 病根只有一行，而且改完之后，前三行得照样对。 

#include <iostream>

int main() {
    int a = 7;
    int b = 2;

    std::cout << "和：" << a + b << std::endl;
    std::cout << "差：" << a - b << std::endl;
    std::cout << "积：" << a * b << std::endl;
    std::cout << "商：" << a / b << std::endl;

    return 0;
}
和：9
差：5
积：14
商：3.5

提示：前三行都对上了，第一处不一样在第四行。病根只有一行， 而且改完之后前三行得照样对。

看答案

改好的版本是这样（只动了第二行）：

#include <iostream>

int main() {
    int a = 7;
    double b = 2;

    std::cout << "和：" << a + b << std::endl;
    std::cout << "差：" << a - b << std::endl;
    std::cout << "积：" << a * b << std::endl;
    std::cout << "商：" << a / b << std::endl;

    return 0;
}

病根是这一行：

int b = 2;

b 是 int，a 也是 int， 两个整数相除，结果一定是整数——1.3 那个坑。 7 / 2 交回来的是 3，小数那位直接扔了。

改成 double b = 2;，那么 a / b 就是 7 除以 2.0，交回来 3.5。

有意思的是前三行：a + b 这时候算出来是 9.0， 可 std::cout 打出来还是 9—— 所以「改完之后前三行得照样对」这条要求，自动就满足了。 这一题要你先看清「第一处不一样在第四行」，也是在提醒你： 病根在前面的第二行，症状出现在后面的第四行。

你现在能写什么：程序不对的时候，你手里有顺序了—— 先分清是三种里的哪一种，再一行一行比输出、找到第一处不一样的地方， 顺着「这个值是从哪儿来的」往回走，必要时把程序砍到最小。 改的时候一次只改一处，改完立刻跑。 这套动作比「把代码再读一遍」有用得多，而且它不靠灵感。

7.2打印调试：把中间结果打出来看

7.1 的第二步是「顺着值往回找」。可有时候你往回走不了——程序跑到一半， 你不知道某个盒子里装的是几，也没有一行输出能让它露出来。

这时候只剩一招，也是最土的一招：把那个值打出来。

最土的一招，也最好用

先看一份不对的程序。它要算四个数的和，该打 14，它打 4： 

#include <iostream>

int main() {
    int a[4] = {3, 5, 2, 4};
    int sum = 0;

    for (int i = 0; i < 4; i++) {
        sum = 0;
        sum = sum + a[i];
    }

    std::cout << "总和：" << sum << std::endl;

    return 0;
}
总和：4

这一份你盯着看，也可能看出那句 sum = 0;——但先假装没看出来。 按 7.1 的走法：只有一行输出，第一处不一样就是它。 往回找，找到循环。然后卡住了：循环里发生了什么，屏幕上一点都看不见。

那就让它现出来。一个字都不改，只往循环里加一句 std::cout： 

#include <iostream>

int main() {
    int a[4] = {3, 5, 2, 4};
    int sum = 0;

    for (int i = 0; i < 4; i++) {
        std::cout << "第 " << i << " 轮：加之前 sum = " << sum;
        sum = 0;
        sum = sum + a[i];
        std::cout << "，加完 " << a[i] << " 之后 sum = " << sum << std::endl;
    }

    std::cout << "总和：" << sum << std::endl;

    return 0;
}
第 0 轮：加之前 sum = 0，加完 3 之后 sum = 3
第 1 轮：加之前 sum = 3，加完 5 之后 sum = 5
第 2 轮：加之前 sum = 5，加完 2 之后 sum = 2
第 3 轮：加之前 sum = 2，加完 4 之后 sum = 4
总和：4

看第二行：加之前是 3，加完 5 之后是 5。3 加 5 应该是 8。 第三行也一样：5 加 2 变成 2。第四行：2 加 4 变成 4。

每一轮「加之前」的那个数，跟上一轮「加完」的对得上； 可「加完」之后，就只剩这一轮的 a[i] 了。 这说明两件事：加之前 sum 是接着上一轮的；中间那句把它清成了 0，然后才加的。

病根就是这么找到的。看见之后，删掉两句打印、拿掉那一行 sum = 0;： 

#include <iostream>

int main() {
    int a[4] = {3, 5, 2, 4};
    int sum = 0;

    for (int i = 0; i < 4; i++) {
        sum = sum + a[i];
    }

    std::cout << "总和：" << sum << std::endl;

    return 0;
}
总和：14

打印调试和「凭感觉改」的区别就在这儿： 凭感觉改是「我猜是这句，删了试试」；打印是我给程序装了一只眼睛， 让它自己告诉我它干了什么。改之前你已经知道答案了。

打什么：值，加上它叫什么

新手打印，常犯一个错：只打值，不打名字。 

    std::cout << sum << std::endl;

屏幕上出来一个 335。这时候你只知道「有个东西是 335」—— 是你想的那个盒子吗？是这一轮的吗？中间隔了三行打印，回头就对不上号了。

所以每一句打印都要带标签：打的是谁、在哪一轮、什么时候。 刚才那份加好的打印就是标准样子： 

    std::cout << "第 " << i << " 轮：加之前 sum = " << sum << std::endl;

它把三样东西装在了一行里：轮次（i）、盒子的名字（sum）、 盒子的值。单独看某一行也读得懂，这是好打印的标准。

打标签这件事，1.4 早就埋好了

1.4 那句「std::cout 只打你让它打的东西，一个字符都不多打」—— 名字你没送进去，它就是不在，赖不着别人。 调试打印是同一个道理，只不过看的人是你自己， 而且是半小时以后的你。

打在哪：卡在「以为」和「实际」中间

加打印的位置，有一个特别省事的判断法：

找那句「我以为这里是 A，可实际是 B」，把打印加在 A 和 B 中间。

拿刚才那份说：「我以为加完是 8，实际是 5」。这两件事中间隔着 sum = 0; 和 sum = sum + a[i]; 两行。 所以打印加在这两行的两头：一句话打「加之前」，一句话打「加完」。 中间那两行干了什么，一眼就看出来了。

如果一条缝不够，就把打印往里挪：在缝的正中间再插一句， 看这一句打出来的值，跟 A 像还是跟 B 像。 每一句打印，只负责回答一个问题。别一次打八个值， 那样屏幕会变成一团，你还是得猜。

崩掉的程序，怎么加打印

程序跑着跑着崩了（段错误），屏幕上没有哪一行是「不对」的， 只有一行是「打到这儿为止」。这时候打印的作用反过来： 在几处地方各打一句话，看最后打出来的是哪一句。 崩掉的地方，就在那两句打印中间。 再往这两句中间插，几次就缩小到一行了——和 7.1 的砍半是一回事， 只不过砍的是「范围」，不是代码。

打印了却看不见

有一种情况能让人卡很久：你明明加了打印，可屏幕上没有它。

这不是错觉。看这一份——它故意崩（空门牌号那个动作，第 6 部分见过）： 

#include <iostream>

int main() {
    int* p = nullptr;

    std::cout << "endl 这句" << std::endl;
    std::cout << "换行符这句" << "\n";

    std::cout << *p << std::endl;

    return 0;
}

跑的时候把输出存进文件（判题机就是这么干的）： 

./a.out > out.txt
endl 这句

第二句没了。它不是没执行——它执行了，字也送到了，只是还停在缓冲区里没刷出去。 程序一崩，缓冲区跟着一起没了。

1.4 说过：std::endl 除了换行，还多做一件事——催一下， 让字立刻出去。那一课还说「平时你感觉不到，因为本来就立刻就出来了」。

崩掉的这一次，你就感觉到了。

所以调试打印的规矩很简单：每一句都用 std::endl 收尾。 等你哪天为了赶时间把整份程序改成 "\n"，记住这条： 正在查错的那几句，先留着 std::endl。

打完记得删

毛病找到、改完之后，那些打印要删掉。不删会怎么样，看这份： 

#include <iostream>

int main() {
    int a[3] = {2, 4, 6};
    int sum = 0;

    for (int i = 0; i < 3; i++) {
        std::cout << "DEBUG i=" << i << std::endl;
        sum = sum + a[i];
    }

    std::cout << "总和：" << sum << std::endl;

    return 0;
}
DEBUG i=0
DEBUG i=1
DEBUG i=2
总和：12

数是对的，可输出里多了三行。在你自己的屏幕上，这只是难看； 交出去的程序，这就是错的——判题机比的是整份输出，多一个字符都不算过。

所以有条规矩：毛病一好，马上把打印删掉。别想着「先留着，等下再一起清」—— 你等下会忘。要是舍不得删（怕待会儿还要查），就把它注释掉，或者干脆存成另一份文件。

练习

这一组练的是「问程序一个问题」。每一题先想清楚：我要知道什么？ 该在哪一行加打印？打哪几个东西？想好了再动手。

练习 7-6（加打印）

它打 及格人数：1，可五个分数 60 55 72 60 48 里， 60 分和 60 分也该算及格，一共 3 个。

说清楚：打印加在哪一行后面？打哪几个东西？ 然后加进去跑一遍——打印会自己告诉你病根在哪。 

#include <iostream>

int main() {
    int scores[5] = {60, 55, 72, 60, 48};
    int pass = 0;

    for (int i = 0; i < 5; i++) {
        if (scores[i] > 60) {
            pass = pass + 1;
        }
    }

    std::cout << "及格人数：" << pass << std::endl;

    return 0;
}
及格人数：3

提示：打印加在 if 那句后面——这一轮拿到的是几分、 加完它之后 pass 是几，都打出来。

看答案

打印加在 if 那句后面——这一轮拿到几分、 加完它之后 pass 是几，都在一行里： 

#include <iostream>

int main() {
    int scores[5] = {60, 55, 72, 60, 48};
    int pass = 0;

    for (int i = 0; i < 5; i++) {
        if (scores[i] >= 60) {
            pass = pass + 1;
        }
        std::cout << "第 " << i << " 个是 " << scores[i]
                  << "，加完它之后 pass = " << pass << std::endl;
    }

    std::cout << "及格人数：" << pass << std::endl;

    return 0;
}

这一份是改对之后的。改之前，同样这句打印打出来是这样：

第 0 个是 60，加完它之后 pass = 0
第 1 个是 55，加完它之后 pass = 0
第 2 个是 72，加完它之后 pass = 1
第 3 个是 60，加完它之后 pass = 1
第 4 个是 48，加完它之后 pass = 1
及格人数：1

第 0 个是 60，可 pass 还是 0。一看就知道这个 60 没被算进去。 第 3 个又是 60，pass 还是没动。两个 60 分，一个都没进去。

病根就是那一行的 >—— 「大于 60」和「大于等于 60」差着一个字，差着两个人。 改成 >= 之后，同一句打印就变成： 

第 0 个是 60，加完它之后 pass = 1
第 1 个是 55，加完它之后 pass = 1
第 2 个是 72，加完它之后 pass = 2
第 3 个是 60，加完它之后 pass = 3
第 4 个是 48，加完它之后 pass = 3
及格人数：3

注意打印放在了 if 后面，不是前面： 放前面打的是「还没算这个数」的 pass， 你会先看到 0，反而要多想一步才知道是谁没进去。 打印放在哪一行，本身也是要挑的。

练习 7-7（从打印里读病根）

这一份作者自己加了打印，跑出来是这样： 

#include <iostream>

int main() {
    int a[5] = {4, 7, 1, 9, 3};
    int sum = 0;

    for (int i = 0; i < 4; i++) {
        std::cout << "第 " << i << " 轮：加上 " << a[i] << std::endl;
        sum = sum + a[i];
    }

    std::cout << "总和：" << sum << std::endl;

    return 0;
}
第 0 轮：加上 4
第 1 轮：加上 7
第 2 轮：加上 1
第 3 轮：加上 9
总和：21

这些打印够你看出来了：病根在哪一行？该打的应该是 24。 

总和：24

提示：数一数打印有几行，再看最后一行的编号是几。 五个格子，编号该到几？

看答案

改好的版本是这样（打印留着没动，只改了一个数字）：

#include <iostream>

int main() {
    int a[5] = {4, 7, 1, 9, 3};
    int sum = 0;

    for (int i = 0; i < 5; i++) {
        std::cout << "第 " << i << " 轮：加上 " << a[i] << std::endl;
        sum = sum + a[i];
    }

    std::cout << "总和：" << sum << std::endl;

    return 0;
}

改之前那份的打印已经把话说完了：

第 0 轮：加上 4
第 1 轮：加上 7
第 2 轮：加上 1
第 3 轮：加上 9
总和：21

最后一行打印的编号是 3。五个格子，编号该到 4—— a[4] 那个 3 从头到尾没被加过。21 加上 3 正好是 24，对得上。

病根是 i < 4 那个 4。 循环从 0 数到 3，走了四圈；要五个格子都走到，上限得写 5。

上限改成 5 之后，打印会多出第 4 轮那一行：

第 0 轮：加上 4
第 1 轮：加上 7
第 2 轮：加上 1
第 3 轮：加上 9
第 4 轮：加上 3
总和：24

这一题最能说明打印调试好在哪儿：你根本不用去数循环—— 程序自己把「我走了几轮」打给你看了。 光看代码，i < 4 和 i < 5 长得差不多； 看输出，一眼就分得清。

练习 7-8（加打印）

它要找出最大的数，还有它在第几个。数找错了，位置也找错了。

先想好：要看清什么，打印该加在哪？加完跑一遍， 打印会直接告诉你哪一句漏了东西。 

#include <iostream>

int main() {
    int a[5] = {12, 45, 7, 33, 28};
    int mx = a[0];
    int idx = 0;

    for (int i = 1; i < 5; i++) {
        if (a[i] > mx) {
            idx = i;
        }
    }

    std::cout << "最大值：" << mx << std::endl;
    std::cout << "它在第 " << idx << " 个" << std::endl;

    return 0;
}
最大值：45
它在第 1 个

提示：在循环里打一句 mx，看看它有没有变过。

看答案

打印加在循环开头——每一轮进 if 之前， 先把 a[i] 和 mx 摆出来： 

#include <iostream>

int main() {
    int a[5] = {12, 45, 7, 33, 28};
    int mx = a[0];
    int idx = 0;

    for (int i = 1; i < 5; i++) {
        std::cout << "第 " << i << " 轮：a[" << i << "] = " << a[i]
                  << "，mx = " << mx << std::endl;
        if (a[i] > mx) {
            mx = a[i];
            idx = i;
        }
    }

    std::cout << "最大值：" << mx << std::endl;
    std::cout << "它在第 " << idx << " 个" << std::endl;

    return 0;
}

这一份是改对之后的。改之前，同样这句打印打出来是这样：

第 1 轮：a[1] = 45，mx = 12
第 2 轮：a[2] = 7，mx = 12
第 3 轮：a[3] = 33，mx = 12
第 4 轮：a[4] = 28，mx = 12
最大值：12
它在第 4 个

四轮的 mx 全是 12。45 比 12 大，33 比 12 大， 28 也比 12 大——可 mx 一次都没变。 这说明 if 里头改了别的东西，没改 mx。

病根在 if 里面：只写了 idx = i;， 把「第几个」记下来了，却没把「多大」记下来。补上 mx = a[i]; 就对了。

最后那个「它在第 4 个」是怎么来的？mx 一直是 12， 凡是比 12 大的都算「赢」，idx 就一路被改写， 停在最后一个赢家身上。mx 错，idx 就跟着错—— 又一个「一个错地方带歪两行输出」的例子。

补上 mx = a[i]; 之后，同一句打印变成：

第 1 轮：a[1] = 45，mx = 12
第 2 轮：a[2] = 7，mx = 45
第 3 轮：a[3] = 33，mx = 45
第 4 轮：a[4] = 28，mx = 45
最大值：45
它在第 1 个

第 1 轮打的还是 mx = 12，看着像没改对—— 因为打印摆在 if 前面，打的是这一轮「还没比」的时候。 45 是这一轮比完才放进 mx 的，所以从第 2 轮起它才变成 45。 这也是 7.2 那句「打印放在哪一行，本身也是要挑的」的另一面： 看到的值是「哪个时刻」的，得看打印站在哪儿。

练习 7-9（找错）

这份程序，数算对了。它还有哪儿不对？该怎么弄？ 

#include <iostream>

int main() {
    int a[3] = {2, 4, 6};
    int sum = 0;

    for (int i = 0; i < 3; i++) {
        std::cout << "DEBUG i=" << i << std::endl;
        sum = sum + a[i];
    }

    std::cout << "总和：" << sum << std::endl;

    return 0;
}
总和：12

提示：先问一句：那个数本身对不对？数对了，那多出来的是什么？

看答案

把三行 DEBUG 删掉，就是这份：

#include <iostream>

int main() {
    int a[3] = {2, 4, 6};
    int sum = 0;

    for (int i = 0; i < 3; i++) {
        sum = sum + a[i];
    }

    std::cout << "总和：" << sum << std::endl;

    return 0;
}

数没错。2 + 4 + 6 = 12，它老老实实算对了—— 所以这一题不是「找错」，是「找出不该留的东西」。

错在把调试用的打印留在了程序里。你自己在终端里跑， 顶多觉得难看；可这份东西一旦交出去，那边是拿整份输出去比的， 多一行 DEBUG i=0 就是一个字符都对不上。

规矩就一句：毛病一好，马上把打印删掉。 舍不得删就注释掉，或者另存一份文件—— 反正不能让它在正式跑的时候出现。

顺带一个习惯：那三行都以 DEBUG 开头，不是随手打的。 这样等你回头找它们的时候，一眼就能认出来。 调试打印带个记号，免得跟正式输出混在一起分不清。

练习 7-10（加打印）

它要算 1 到 5 的和，打出来是 10——少了一个 5。 循环看着明明没写错，那就别猜了，让程序自己说它每轮是几。 

#include <iostream>

int main() {
    int n = 5;
    int sum = 0;
    int i = 1;

    while (i < n) {
        sum = sum + i;
        i = i + 1;
    }

    std::cout << "1 到 5 的和：" << sum << std::endl;

    return 0;
}
1 到 5 的和：15

提示：在循环里打一句 i，看它走到几就停了。 你要的是 1 到 5，5 进过循环吗？

看答案

打印加在循环开头，看每一轮的 i 是几：

#include <iostream>

int main() {
    int n = 5;
    int sum = 0;
    int i = 1;

    while (i <= n) {
        std::cout << "这一轮 i = " << i << std::endl;
        sum = sum + i;
        i = i + 1;
    }

    std::cout << "1 到 5 的和：" << sum << std::endl;

    return 0;
}

这一份是改对之后的。改之前，同样这句打印打出来是这样：

这一轮 i = 1
这一轮 i = 2
这一轮 i = 3
这一轮 i = 4
1 到 5 的和：10

最后一句是 i = 4，5 从来没出现过。 你要的是 1 到 5，可 5 压根没进过循环。

病根是那个条件：i < n，而 n 是 5。 i 走到 5 的时候，5 < 5 不成立，循环就停了。 要它走到 5，得上 i <= n。

改成 i <= n 之后，打印就多了一行：

这一轮 i = 1
这一轮 i = 2
这一轮 i = 3
这一轮 i = 4
这一轮 i = 5
1 到 5 的和：15

「从 1 开始、到 n 为止」和「从 0 开始、到 n 之前」是两种数法， 混着用就会少一个数。 0 起头配 <，1 起头配 <=——这一题是后面那种。

你现在能写什么：看不清的地方，你能让程序自己说话—— 在「以为」和「实际」中间加一句带标签的打印，一次只问一个问题， 崩了的程序就用几句打印把范围夹出来。 你还知道 std::endl 那一下「催」是什么意思， 也知道调试打印用完必须删。 这一招不高级，但真写代码的人天天在用。

7.3读别人的代码：从哪一行开始看

最后一课。前面六部分里的程序，全是你自己写的——每一行当时为什么那么写， 你心里都有数。可往后你要读的代码，大部分不是你写的： 同学写的、网上抄来的、你自己三个月前写的。

读别人的代码有一件事得先说清楚：它不是从第一行读到最后一行。 那样读，读到第十行就迷路了，因为你还不知道这些盒子是干什么用的。

从 main 开始，不从第一行开始

一个程序里，所有事情都是从 main 开始的——这件事 0.2 就讲过， 现在要用它当入口。

main 常常不在文件开头（函数一般写在前面）， 所以第一步是往下找到 int main()，从那儿开始读。

然后在 main 里看三样东西，按这个顺序：

  1. 它开了哪几个盒子——名字和初值，是理解全部代码的线索。
  2. 它调了哪几个函数——先别进去，只记下「调了谁、给了什么、结果放进哪个盒子」。
  3. 它打了什么——输出是这份代码的「目的」。看完这三样，你大概就知道这个程序在干什么了。

这时候再回头去看那些函数。而且是带着问题去看的： 「x 是 f1(s, n) 交回来的，那 f1 到底算了个什么？」

现场读一份没名字没注释的代码

下面这份是「别人的代码」的标准长相：名字没头没脑，一句注释都没有。 

#include <iostream>

int f1(int a[], int n) {
    int m = a[0];

    for (int i = 1; i < n; i++) {
        if (a[i] < m) {
            m = a[i];
        }
    }

    return m;
}

int f2(int a[], int n, int t) {
    int c = 0;

    for (int i = 0; i < n; i++) {
        if (a[i] == t) {
            c = c + 1;
        }
    }

    return c;
}

int main() {
    int s[8] = {72, 58, 91, 58, 66, 43, 80, 43};
    int n = 8;

    int x = f1(s, n);
    int y = f2(s, n, x);

    std::cout << x << std::endl;
    std::cout << y << std::endl;

    return 0;
}
43
2

按上面的顺序走一遍。

第一步，找到 main。它在最下面。里面开了四个盒子： s 是八个分数，n 是 8，还有两个空的 x 和 y。

第二步，看它调了什么。两次： x = f1(s, n); 和 y = f2(s, n, x);。 两次都给了一样的开头两样东西（s 和 n）， 第二次还多塞了一个 x 进去。

第三步，看它打了什么。两行，一行 x，一行 y。 所以这个程序的目的就是算出这两个数——现在只剩一个问题：它们各是什么。

带着这个问题进 f1。int f1(int a[], int n)： 收一个数组和它的个数，交回来一个 int。 里面是一个 m，一开始是 a[0]；然后从 i = 1 开始走一遍， 谁比 m 小就把 m 换掉。 这不就是 4.3 学的找最小值吗？只是名字起成了 f1。

八个分数里最小的是 43，所以 x 是 43。输出第一行对上了。

再看 f2。int f2(int a[], int n, int t)： 一样的数组和个数，第三个是个 t。 里面是一个 c，从 0 开始；走一遍，谁等于 t 就把 c 加一。

t 是什么？看调用那行：f2(s, n, x)——是刚才算出来的 43。 所以 y 是「这八个数里有几个等于 43」，数出来 2 个。第二行也对上了。

整份程序干的事：找出最低分，再数出有几个人是这个分。 逐行读名字没用的那种代码，读到最后是读懂了。

名字烂这件事，本身也是信息

f1、f2、x、y、m、c—— 这些名字一个线索都不给。可线头从来没断过：f1 里 return 的那个 m， 和 main 里接它的那个 x，是同一个值。 顺着这条线走，名字起成什么样都不影响。

读函数：先看签名

「签名」就是那一行 int f1(int a[], int n)—— 返回什么、要什么、几个。读函数先读这一行，读完这行你常常就不用往里看了。

看这几个：

签名不用看里面就知道
int f1(int a[], int n)给它一堆数和个数，它交回来一个整数
void printAll(int a[], int n)给它一堆数，它什么都不交回来——那它多半是往屏幕上打的
void addOne(int& x)参数里有个 &：它要的是盒子本人，不是抄件——所以它能把外面那个盒子改掉（3.5 讲的）
bool isSorted(int a[], int n)交回来一个 bool——问它一个是非题

有个名字起得好的函数，比什么都省事。void printAll 一眼就知道是「全打出来」； f2 得读进去才知道是「数个数」。

所以你自己写函数的时候，名字起好一点。 三个月以后回来读这份代码的人，是你自己。

读循环：先看边界，再看里面

循环是代码里最容易藏错的地方。读的时候分两步，别一上来就钻进循环体。

第一步，只看那一行 for。问三件事：

  1. 从哪儿开始：i = 0 还是 i = 1？
  2. 到哪儿停：i < n 还是 i <= n？
  3. 每一轮挪多少：i++ 还是别的？

三个答案凑起来，循环跑几圈就定死了。上面那份代码里 for (int i = 1; i < n; i++)，n 是 8—— 从 1 开始，到 7 结束，七圈，格子 0 没走。 它这样写是对的（m 已经是 a[0] 了，不用跟自己比）， 可你得先算出来，才知道它是对的。

第二步，才看循环体里干什么。这时候你心里已经有底了： 一共七轮，每轮拿 a[i] 去跟 m 比一下。

7.1 那份平均分的程序，错就错在这一步的顺序上——没算圈数，直接读里面去了。

读不懂的写法，先跳过去

读别人的代码一定会遇到你没学过的写法。这时候别停下来死磕—— 先跳过，继续往下读。

这不是偷懒。一份代码里，你认识的部分通常占九成； 把那一成不认识的东西先当成一个黑盒子（「它大概是干这个的」）， 九成读懂之后，剩下那一成的意思往往自己就浮出来了。

真到要弄明白的时候，用 7.2 那一招：把它单独抠出来，加一句打印，跑一遍。 跑一遍看到的，比盯着看十分钟管用。

其实 7.1 到 7.3 是一件事的三面： 7.1 是「先找哪里不一样」，7.2 是「看不清就打印」， 7.3 是「从入口顺着数据走」。三条路都通向同一句话—— 别猜，去看。

练习 7-11（预测输出）

先别编译、先别看答案。读完它，说出它打什么。 然后编译一遍，对一下你读得对不对。 

#include <iostream>

int main() {
    int a[6] = {3, 1, 4, 1, 5, 9};
    int k = 0;

    for (int i = 0; i < 6; i++) {
        if (a[i] > a[k]) {

        }

}
5 9

提示：盯住 k。它装的不是最大的数，是最大的那个数的编号。 读完加一句打印，看它依次是几。

看答案

它打 5 9。加一句打印，看 k 是怎么一格一格挪的：

#include <iostream>

int main() {
    int a[6] = {3, 1, 4, 1, 5, 9};
    int k = 0;

    for (int i = 0; i < 6; i++) {
        if (a[i] > a[k]) {
            k = i;
        }
        std::cout << "i = " << i << " 时，k = " << k << std::endl;
    }

    std::cout << k << " " << a[k] << std::endl;

    return 0;
}
i = 0 时，k = 0
i = 1 时，k = 0
i = 2 时，k = 2
i = 3 时，k = 2
i = 4 时，k = 4
i = 5 时，k = 5
5 9

k 装的不是「最大的数」，是「最大的那个数的编号」。 搞清楚这一点，后面全通了。

比较那一行写的是 a[i] > a[k]—— 拿当前这个跟目前冠军比。谁赢谁当冠军，k 记下它的编号。 打印里看得清清楚楚：编号 2 的 4 赢了 3，编号 4 的 5 赢了 4， 编号 5 的 9 赢了 5，冠军最后停在 5。

输出那句打的是「编号」和「那个编号上的数」，所以是 5 9。 要是没看清 k 装的是编号，很容易只答一个 9。

练习 7-12（读代码）

只看这个函数，不用跑，说清楚两件事： 它是干什么用的？给它 {4, 7, 2, 9, 6} 和 5，它交回来几？ 

int g(int a[], int n) {
    int s = 0;

    for (int i = 0; i < n; i++) {
        if (a[i] % 2 == 0) {
            s = s + a[i];
        }
    }

    return s;
}
12

提示：看 return 交回来的那个 s 是怎么攒起来的—— 哪些数被加进去了，哪些被跳过去了。

看答案

它是把所有偶数加起来。给它 {4, 7, 2, 9, 6}， 交回来 12——4 + 2 + 6，7 和 9 是奇数，跳过去了。

补一个 main 叫它一次，就能跑给你看：

#include <iostream>

int g(int a[], int n) {
    int s = 0;

    for (int i = 0; i < n; i++) {
        if (a[i] % 2 == 0) {
            s = s + a[i];
        }
    }

    return s;
}

int main() {
    int a[5] = {4, 7, 2, 9, 6};

    std::cout << g(a, 5) << std::endl;

    return 0;
}

读它的顺序：先看 return 交回来的是 s， 再看 s 是怎么攒起来的——只有进得了 if 的才加。 那个 if 的条件是 a[i] % 2 == 0， 也就是「这个数除以 2 余 0」，即偶数。

% 是 1.3 学的取余。这一题没有循环边界上的坑， 五圈一圈不少，也不越界——它是拿来练「怎么把一段代码读明白」的， 不是找错的。

留个对照：这里的 a[i] % 2 == 0 问的是「这个数是偶数」， 7-14 那道 i % 2 == 0 问的是「这个编号是偶数」。 一个字母之差，问的是两回事。

提示：两个 cin 里，第一个读进来的是数还是「有几个数」？ 后面那个循环跑几圈？

看答案

它打 最大的是 30。

#include <iostream>

int main() {
    int n = 0;
    std::cin >> n;

    int a[20];
    for (int i = 0; i < n; i++) {
        std::cin >> a[i];
    }

    int mx = a[0];
    for (int i = 1; i < n; i++) {
        if (a[i] > mx) {
            mx = a[i];
        }
    }

    std::cout << "最大的是 " << mx << std::endl;

    return 0;
}

第一个 cin 读进来的不是数据。 它读进 n，而 n 的意思是「接下来有几个数」—— 这一行 5 12 7 30 4 19 里，5 是说「后面还有 5 个数」。

后面那个循环就是拿 n 当圈数用的： for (int i = 0; i < n; i++) 跑五圈， 把 12、7、30、4、19 装进 a[0] 到 a[4]。 然后才轮到找最大值，走的还是 4.3 那个路子。

「第一个数是长度」这个写法，4.5 那道真题里见过—— 当时它是当陷阱用的。读别人的代码碰见它， 第一件事就是分清「哪个数是数据、哪个数是数据的个数」。

练习 7-14（预测输出）

读它，说出打出来的数是什么，再说清它是哪几个格子加起来的。 别一眼扫过去就答——这一题就是给「一眼扫过去」准备的。 

#include <iostream>

int main() {
    int a[6] = {2, 4, 6, 8, 10, 12};
    int s = 0;

    for (int i = 0; i < 6; i++) {
        if (i % 2 == 0) {
            s = s + a[i];
        }
    }

    std::cout << s << std::endl;

    return 0;
}
18

提示：i % 2 == 0 问的是「编号是不是偶数」。 编号 0、1、2、3、4、5 里，哪几个会被加进去？

看答案

它打 18。加进去的是编号 0、2、4 三个格子：2 + 6 + 10 = 18。

加一句打印，把每一轮的 i 和 s 都摆出来：

#include <iostream>

int main() {
    int a[6] = {2, 4, 6, 8, 10, 12};
    int s = 0;

    for (int i = 0; i < 6; i++) {
        if (i % 2 == 0) {
            s = s + a[i];
        }
        std::cout << "i = " << i << " 时，s = " << s << std::endl;
    }

    std::cout << s << std::endl;

    return 0;
}
i = 0 时，s = 2
i = 1 时，s = 2
i = 2 时，s = 8
i = 3 时，s = 8
i = 4 时，s = 18
i = 5 时，s = 18
18

关键在那个条件：i % 2 == 0，判断的是 i， 不是 a[i]。 所以它挑的是「编号是偶数」的格子——0、2、4； 而不是「值是偶数」的那些（这一份里六个数全是偶数，两种读法特别容易混）。

打印里看得最清楚：s 只在第 0、2、4 轮往上跳， 第 1、3、5 轮一动不动。

想验一验自己读得对不对，换个数组最省事：把六个数改成有奇有偶 （比如 {1, 4, 3, 8, 5, 12}）再跑一遍—— 如果它挑的是编号，结果还是 1 + 3 + 5 = 9； 要是挑的是值，那会变成 4 + 8 + 12 = 24。 换个输入再跑一遍，是「读懂了」最硬的证据。

练习 7-15（读代码，里面有个错）

这一份是别人写的，里面有个错。「总和」那一行是对的，「平均」那一行不对。 找出错在哪儿。 

#include <iostream>

int f1(int a[], int n) {
    int s = 0;

    for (int i = 0; i < n; i++) {
        s = s + a[i];
    }

    return s;
}

int main() {
    int a[5] = {10, 20, 30, 40, 50};

    std::cout << "总和：" << f1(a, 5) << std::endl;
    std::cout << "平均：" << f1(a, 4) / 4 << std::endl;

    return 0;
}
总和：150
平均：30

提示：两行调的是同一个函数，参数却不一样——先把这两行并排看一遍。

看答案

改好的版本是这样（第二行那两处 4 都改成 5）：

#include <iostream>

int f1(int a[], int n) {
    int s = 0;

    for (int i = 0; i < n; i++) {
        s = s + a[i];
    }

    return s;
}

int main() {
    int a[5] = {10, 20, 30, 40, 50};

    std::cout << "总和：" << f1(a, 5) << std::endl;
    std::cout << "平均：" << f1(a, 5) / 5 << std::endl;

    return 0;
}

先看那个函数：f1 本身一点错都没有。 它收几个数就把前几个加起来，循规蹈矩。

病根在调用它的地方。两行并排看：

std::cout << "总和：" << f1(a, 5) << std::endl;
std::cout << "平均：" << f1(a, 4) / 4 << std::endl;

第一行传 5，第二行传 4——同一个函数、同一份数组， 两次却给了不同的个数。4 个数的和是 100，除以 4 得 25； 5 个数的和是 150，除以 5 得 30。

这一题要练的是读代码时的一个动作：看见同一个函数被调用两次， 就把两次的参数并排看一眼。 函数体里翻不出毛病的时候，错多半就藏在调用那一行上—— 因为读函数的时候，人会默认「调用方给的东西是对的」。

你现在能写什么：别人写的代码，你知道从 main 进去， 先看数据、再看调了谁、最后看输出；读函数先读签名； 读循环先算圈数；认不出来的写法先当黑盒子放着。 读不懂的地方，你能用 7.2 的办法把它跑起来看。 这一部分三课其实是一句话：别猜，去看。
