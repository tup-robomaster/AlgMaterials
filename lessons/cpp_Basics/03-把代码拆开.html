第 3 部分

把代码拆开

前两部分的程序，都是一路往下堆的：变量、判断、循环，全堆在 main 里。 这一部分教你把这一堆剪成几块，一块装一个盒子，盒子上贴个名字。 治的就是「所有代码都塞在 main 里」。

3.1为什么 main 不该太长

先说清楚：这一课不教新语法，一行新语法都没有。 它只让你看见一件你已经干过的事——把好几道题写在一个 main 里， 然后跟你算一算，这么写要付什么代价。

一份交上来的作业

先看一份东西。这不是我编出来当反面教材的——作业里最常见的就是这个样子： 把几道练习的答案写在一个文件里，全塞进 main。 

#include <iostream>
#include <cstdio>

int main() {
    int i = 1;
    int j = 1;

    // ── 第一件：打一个星号直角三角形（2.5 的例题） ──
    i = 1;
    while (i <= 4) {
        j = 1;
        while (j <= i) {
            std::cout << "*";
            j = j + 1;
        }
        std::cout << std::endl;
        i = i + 1;
    }

    std::cout << "----" << std::endl;

    // ── 第二件：1 加到 100（2.4 的例题） ──
    int sum = 0;
    i = 1;
    while (i <= 100) {
        sum = sum + i;
        i = i + 1;
    }
    std::cout << "1 到 100 是 " << sum << std::endl;

    std::cout << "----" << std::endl;

    // ── 第三件：9×9 乘法表（2.6 那道综合练习） ──
    i = 1;
    while (i <= 9) {
        j = 1;
        while (j <= i) {
            printf("%d×%d=%2d ", j, i, i * j);
            j = j + 1;
        }
        printf("\n");
        i = i + 1;
    }

    return 0;
}

三件都出来了，一个字没错。 所以这一课要说的不是「哪里写错了」——它没写错。

它其实做了三件事

数一数这个 main 里装了几件事：

  1. 打一个星号三角形
  2. 把 1 加到 100
  3. 打一张 9×9 乘法表

三件事互相没关系：第二件跟三角形没关系，乘法表跟加法也没关系。 可它们全挤在一个盒子里。

main 这个名字的意思是「主函数」——程序从它开始跑。 名字里有「主」，是因为它是入口， 不是因为它该装下所有东西。

这三件事长得也很像：每一件都是「先 i = 1;，再一个 while」。 像归像，它们是三件事—— 改乘法表的时候不该动到加法，讲加法的时候不该扯上三角形。

想单独跑其中一件

假设同学问你：「你那个 1 加到 100 是怎么写的？给我看看。」

你只能这么回答：「从第 22 行开始看，看到第 29 行，前面那些别管。」 乘法表那段是第 33 行到第 43 行。

或者，你想单独把加法跑一遍看看数对不对：得把第一件和第三件都注释掉， 跑完，再一句句取消注释。取消的时候漏了一行，文件就废了。

这就是第一个代价：想单独动一件，得先碰另外两件。 一件事该能单独跑、单独看、单独改——挤在一起的时候就做不到。

件与件之间会串味

还有第二个代价，比第一个隐蔽。看那几句 i = 1;。

第一件开头有一句，第二件开头有一句，第三件开头还有一句。 同一个动作抄了三遍——为什么要抄三遍？

因为 i 是三件共用的一个盒子。第一件用完了它， i 停在 5；第二件接手的时候不拨回 1，就得从 5 开始加。 所以每开一件，都得先把共用的盒子拨回原位。

少拨一次会怎么样？真的少拨一次给你看——那就是练习 3-2。

每一件都该有自己的名字

想让第一件单独跑，不用注释别的行； 想让同学看加法那一段，不用报行号； 想让 i 别跟别人抢—— 办法只有一个：把每一件从 main 里剪出来，单独装进一个盒子，盒子上贴个名字。

那个盒子就叫函数（function）。下一课就造它。

#include <cstdio>

int main() {

    int j = 1;

    while (i <= 9) {

        while (j <= i) {

开头那两句和原文不一样：原文是 int i = 1; int j = 1; 之后再补一句 i = 1;， 这里是声明的时候直接放在 1 上。

为什么能省掉那句？因为这两个盒子现在是它自己的—— 不像原文那样要跟另外两件共用。新开的盒子本来就该从 1 开始， 不用再拨一遍。

这就是拆开的第一个好处：想跑它，直接跑。 不用先注释掉另外两件，跑完再一句句取消注释。

#include <iostream>
#include <cstdio>

int main() {

        printf("\n");
        i = i + 1;
    }

为什么乘法表整个不见了？跟着 i 走一遍就清楚了。

第一件走完，i 停在 5。 第二件开头那句 i = 1; 把它拨回 1，从 1 加到 100， 走完的时候 i 是 101—— 最后一次是加完 100 之后又执行了一句 i = i + 1， 条件要再问一次才发现不成立。

第三件开口就问：i <= 9 吗？ 可 i 已经是 101 了——不成立，一次都不进去。 所以第二个 ---- 底下什么都没有。

编译不报错、跑起来也不崩，就是少了一块。 这种错最难逮：它不像少个分号那样有人喊你， 它就是安安静静地少做一件事。

还记得 2.6 的练习 2-26 吗？同一个病： 盒子是共用的，忘了拨回去，下一件就从错的地方接着走。 这就是「件与件之间会串味」。

你现在能写什么：没有新东西，但你能看懂一份「全都塞在 main 里」的作业了， 能说出它做了几件事、哪几件在抢同一个盒子。 这三件事本身你都会写——卡住你的从来不是语法。 下一课给每一件造一个盒子：函数。

3.2函数：参数和返回值

这一课只有一个新东西：函数（function）—— 把一件事包起来，起个名字，需要的时候叫它。

你早就在叫函数了

main 是函数。你写 printf("%d", x) 的时候， printf 也是函数——只不过它是别人写好的，你只管叫。

叫一个函数的样子永远是名字加一对括号：printf(...)、 main()。括号里放的是要递给它的东西。

这一课要做的，就是自己造一个——名字自己起，括号里放什么自己定。

自己造一个

把 3.1 那份作业里的第一件（星号三角形）剪出来，装进盒子： 

#include <iostream>

void printTriangle(int n) {
    for (int i = 1; i <= n; i = i + 1) {
        for (int j = 1; j <= i; j = j + 1) {
            std::cout << "*";
        }
        std::cout << std::endl;
    }
}

int main() {
    printTriangle(2);
    std::cout << "----" << std::endl;
    printTriangle(4);
    return 0;
}

看盒子的第一行，它是四个东西拼起来的：

写的意思
void 它干完活不交回东西。void 就是「空」。干了就完了。
printTriangle 名字。你自己起，起成「它干的那件事」。
(int n) 递进来的东西：一个整数，在这个盒子里叫 n。

到这儿你可能已经看出来：这不是新语法，是「把已经会的东西挪个地方」。 挪出来之后多了三样：名字、括号、开头那个词。

括号里那个 int n

把 n 想成这个函数自己的盒子。 谁叫它，谁就往里放一个数： printTriangle(2) 就是把 2 放进去，盒子里的 n 就是 2； printTriangle(4) 就是 4。

所以同一个函数，叫两次，打出来的东西不一样： 一次 2 行，一次 4 行。 会变的那部分（打几行）留给你填，不变的那部分（怎么打）写在函数里。

放进括号的那个东西，正式的名字叫实参（argument）， 函数这边接住它的那个 n 叫形参（parameter）。 平时两个都叫「参数」，分不清也没关系——这一课你只要记住它是函数自己的盒子。

还有一件事现在就得说清楚：每次叫它，这个盒子都是新开的。 叫第一遍放下 2，叫第二遍放下 4，两次互不影响。 为什么会这样，3.3 专门讲。

要带回一个结果

打三角形是「干完就完了」。可很多事是要交结果的：算个和、比个大小。 

#include <iostream>

int doubleIt(int x) {
    return x * 2;
    std::cout << "这一行永远打不出来" << std::endl;
}

int main() {
    std::cout << doubleIt(3) << std::endl;
    std::cout << doubleIt(10) << std::endl;
    return 0;
}

和上一个比，两处不一样：

  • 开头的 void 换成了 int—— 它要交回一个整数。这个地方写什么类型，就得交回什么。
  • 里面出现了 return——要交回去的东西写在它后面。

跑一遍： 

6
20

注意输出里没有「这一行永远打不出来」这句话。 它写在程序里，可是从来没执行到过。

return 干两件事：把结果交回去，然后当场走人。 它底下那行代码不是「等一下再执行」，是「永远不会执行」。

而且——刚才这次编译一声没吭，-Wall 也不报这个。 编译器不管你写了多少句永远轮不到的代码。 这种事只能你自己知道，或者靠跑一遍对输出。

交回来的东西，要有人接。上面是直接打出来： std::cout << doubleIt(3)。 也可以先接住、再用： 

#include <iostream>

int doubleIt(int x) {
    return x * 2;
}

int main() {
    int result = doubleIt(3);
    std::cout << result + 1 << std::endl;
    return 0;
}
7

doubleIt(3) 交回 6，result 就接到 6， 加 1 打出来是 7。 到这一步，函数交回的东西和普通变量没区别了—— 它就是个值，跟 3 + 5 算出来的 8 一样。

函数要写在 main 上面

把函数挪到 main 底下去，试试： 

#include <iostream>

int main() {
    printTriangle(2);
    return 0;
}

void printTriangle(int n) {
    for (int i = 1; i <= n; i = i + 1) {
        for (int j = 1; j <= i; j = j + 1) {
            std::cout << "*";
        }
        std::cout << std::endl;
    }
}

编译器立刻不认： 

3.2-order-err.cpp: In function ‘int main()’:
3.2-order-err.cpp:4:5: error: ‘printTriangle’ was not declared in this scope
    4 |     printTriangle(2);
      |     ^~~~~~~~~~~~~

读那行：「printTriangle 在这个范围里没有声明过」。

编译器是从上往下读的。读到第 4 行那句 printTriangle(2) 的时候， 它还没见过这个名字——底下写了不算。

规矩就一句：要用它，先定义它。 所以这门课里的程序，函数都写在 main 上面。

例题 · 及格线

2.1 那道判分数的程序，这次写成一个函数： 

#include <iostream>

bool isPass(int score) {
    if (score >= 60) {
        return true;
    }
    return false;
}

int main() {
    int score = 58;
    if (isPass(score)) {
        std::cout << score << " 分：及格" << std::endl;
    } else {
        std::cout << score << " 分：不及格" << std::endl;
    }

    score = 91;
    if (isPass(score)) {
        std::cout << score << " 分：及格" << std::endl;
    } else {
        std::cout << score << " 分：不及格" << std::endl;
    }

    return 0;
}
58 分：不及格
91 分：及格

三样东西值得看：

  • 返回类型写的是 bool——它交回来一个 true 或 false，就是 1.2 学的那个类型。
  • if (isPass(score))：函数叫在条件的位置上。 它交回 true，if 就走及格那一路。这是最常见的用法之一。
  • 及格线只写了一份。 以后要把它从 60 改成 55，改函数里那一个数字就行， 不用满程序找哪儿还判断过及格。

顺便说：isPass 里那四行还能压成一行： return score >= 60;—— 2.2 说过，比较自己就算出一个 true 或 false， 直接交回去就行了。两种写法都对，先把上面那种写熟。

一行星号，一个循环就够——不需要两层： 

#include <iostream>

void printStars(int n) {
    for (int i = 1; i <= n; i = i + 1) {
        std::cout << "*";
    }
    std::cout << std::endl;
}

int main() {
    printStars(8);
    printStars(3);

    return 0;
}

和 3.2 的 printTriangle 比，少的就是外面那层。 外层管「打几行」，这一题没得选，只打一行—— 那一层直接不要了，n 交给剩下的那层循环。

这也是「函数该包多大」的第一次练习： 包进来的这件事，得说得出是一件事。 「打一行星号」是一件事，「打一个三角形」也是一件事， 但「打一行星号」和「打一个三角形」不是一个盒子里的东西—— 一个是另一个的零件。

练习 3-5

写一个函数 int sumTo(int n)，交回 1 + 2 + ... + n 的结果。

在 main 里打出 sumTo(10) 和 sumTo(100)： 

55
5050

提示：2.3 那个「攒一个总数」的循环，原样搬进函数里， 最后把攒出来的那个数 return 出去。 开工前想一句：那个装总和的盒子，该开在哪儿？

看答案

2.3 那个攒总和的循环搬进来，最后把攒出来的数交回去： 

#include <iostream>

int sumTo(int n) {
    int sum = 0;
    for (int i = 1; i <= n; i = i + 1) {
        sum = sum + i;
    }
    return sum;
}

int main() {
    std::cout << sumTo(10) << std::endl;
    std::cout << sumTo(100) << std::endl;

    return 0;
}

两个地方值得说：

一、那个装总和的盒子开在函数里面。 提示里问的就是这个。它得开在函数里——main 根本看不见它， 也不需要看见。函数在门里把它算完，只交出一个数。

二、return sum; 交的是那个数，不是那个盒子。 函数一走完，sum 这个盒子就没了（下一课讲这个）， 交出来的 55 是它的值。 所以 main 接到的是 55 这个值，照样能打、能算、能存。

3.3变量能活多久：作用域

3.2 最后留了一句话没往下讲：每次叫函数，它括号里那个盒子都是新开的。 这一课把这句话讲透。

要讲的东西，正式的名字叫作用域（scope）。名字唬人，说的其实是件很朴素的事： 一个盒子，只活在声明它的那对大括号里。 大括号一关，盒子就没了——不是「值归零」，是这个盒子不存在了。

一个盒子只在它的地盘里活着

看这个程序。两个函数，各声明了一个变量： 

#include <iostream>

void show() {
    int local = 7;
    std::cout << "show 里 local = " << local << std::endl;
}

int main() {
    int a = 3;
    show();
    std::cout << "main 里 a = " << a << std::endl;
    return 0;
}
show 里 local = 7
main 里 a = 3

程序里一共出现过两个盒子：

  • a 声明在 main 的大括号里，活在那一对括号之间。
  • local 声明在 show 的大括号里，活在那一对括号之间。

各活各的。local 出生的时候 a 已经在； local 死掉的时候 a 还好好的。

跟着动画走一遍

这一课的重点不在值，在盒子什么时候冒出来、什么时候没。 按「下一步」，盯住下面那排盒子，尤其是走到大括号那两步。

三步值得回头看：

  1. 进 show 那一步：屏幕上多了一个盒子 local。 a 还在，但 show 里叫不出这个名字——它不归 show 管。
  2. 走到 show 的 } 那一步：local 变灰。 程序还没执行完，但它的命到头了。
  3. 回 main 那一步：local 没了，a 一动没动，还是 3。

大括号就是地盘

不是只有函数的大括号才算数。随便哪一对大括号，都圈出一块地盘： if 的、for 的、while 的，或者光秃秃一对也行。 

#include <iostream>

int main() {
    int a = 1;

    {
        int b = 2;
        std::cout << "大括号里面：a = " << a << "，b = " << b << std::endl;
    }

    std::cout << "大括号外面：a = " << a << std::endl;

    return 0;
}
大括号里面：a = 1，b = 2
大括号外面：a = 1

外面那行只打了 a，没打 b——因为写到那儿的时候， b 已经没了，写不出来。

外面能看见里面，里面也能看见外面。 大括号里的代码能读 a（那是外面声明的）， 但外面读不到 b（那是里面声明的）。 一句话：谁在里谁是后来的，后来的能看见先来的，先来的看不见后来的。

出了地盘，编译器直接拦

上面是「不写」，这次故意写出来试试： 

#include <iostream>

int main() {
    {
        int b = 2;
        std::cout << "里面 b = " << b << std::endl;
    }

    std::cout << "外面 b = " << b << std::endl;
    return 0;
}

大括号里面那行好端端的，出来这行编译器立刻不让： 

3.3-out-err.cpp: In function ‘int main()’:
3.3-out-err.cpp:16:33: error: ‘b’ was not declared in this scope
   16 |     std::cout << "外面 b = " << b << std::endl;
      |                                 ^

这句话在 3.2 见过一次（那次是函数写在了 main 底下）， 所以你现在应该能直接读出来：「b 在这个范围里没有声明过」。

scope 就是「范围」。编译器说的 in this scope， 意思就是「在我现在站的这块地盘上，没这个名字」。 它不是在骂你，是在告诉你 b 住哪——住上面那对大括号里，你走出来太远了。

这个报错其实是好事：它当场就把你拦住了。 要是编译器不拦，这种「用了一个已经没了的盒子」的错， 要到程序跑起来、跑出个莫名其妙的数，你才发现。

两个同名的盒子

既然每个函数有自己的地盘，那两边各起一个同名的盒子会怎样？ 

#include <iostream>

void show() {
    int n = 7;
    std::cout << "show 里 n = " << n << std::endl;
}

int main() {
    int n = 3;
    show();
    std::cout << "main 里 n = " << n << std::endl;
    return 0;
}
show 里 n = 7
main 里 n = 3

两个 n，两个盒子，谁也不认识谁。 show 里那个 n 是 7，main 里这个还是 3。

这件事有个名字叫遮蔽（shadow），但你现在不用记这个词，记住现象就行： 名字是给同一块地盘里的人用的。出了这块地盘，这个名字跟你没关系。

顺手说一句：写代码的时候别故意这么起名。 人是会看糊涂的——读到 n 的时候还得往上翻，看这是哪个 n。 函数里那个变量，起个跟外面不一样的名字，比如 result、count， 读的人省事，你自己过两天回来看也省事。

这一课最该记住的一句话

盒子跟着大括号走：进括号开，出括号关。

这一句话能解释你后面会撞上的一连串事：

你看到的为什么
函数里算出来的数，外面拿不到 那个盒子随函数的 } 一起没了
循环里声明的 i，循环外不能用 for 的 i 住在 for 那对括号里
两个函数里的变量可以重名 两块地盘，两个盒子
想留在外面的东西，为什么必须在外面声明 因为它得有个活到那时候的盒子装

下一课讲一件看上去差不多、其实更要命的事： 你把一个盒子递给函数，函数收到的是什么？

练习 3-7

下面这个程序编译不过去。先别看答案，自己读一遍， 说出是哪一行、为什么。 

#include <iostream>

int main() {
    int total = 0;

    {
        int n = 5;
        total = total + n;
    }

    std::cout << "外面：total = " << total << std::endl;
    std::cout << "外面：n = " << n << std::endl;
    return 0;
}

说完了，再把它改成能跑的：n 和 total 两个都要打出来。

改完的预期输出是： 

里面：n = 5，total = 5
外面：total = 5

里面那一行说 n 是 5、total 是 5， 外面那一行说 total 还是 5。

提示：total 那行不用动——它声明在外面，本来就活到最后。 要挪的是另一行。

看答案

错在最后一句：std::cout << "外面：n = " << n。 n 是在那对大括号里面声明的，走出大括号它就没了， 外面这一行叫不出这个名字。

编译器说的是： 

3-7-err.cpp: In function ‘int main()’:
3-7-err.cpp:12:34: error: ‘n’ was not declared in this scope
   12 |     std::cout << "外面：n = " << n << std::endl;
      |                                  ^

这句话你前面见过两次了（3.3 那个报错框、 3.2 那个函数写反顺序的）。「not declared in this scope」= 这块地盘上没这个名字。

抬头看报错给的行号 12——它指的正好是用 n 的那一行，不是声明 n 的那一行。 这是条很有用的经验： 「没声明」的报错，指的永远是用它的地方，因为问题出在那儿。

改法：把要用 n 的那句话搬进大括号里。 total 那行不用动——它声明在外面，本来就活到最后。 

#include <iostream>

int main() {
    int total = 0;

    {
        int n = 5;
        total = total + n;
        std::cout << "里面：n = " << n << "，total = " << total << std::endl;
    }

    std::cout << "外面：total = " << total << std::endl;
    return 0;
}

打出来是两行：里面那行 n 和 total 都看得见， 外面那行只剩 total。

注意外面那行打出来的 total 还是 5。 total 是在外面声明的，大括号里那句 total = total + n; 改的是外面那个盒子—— 因为 total 的名字在大括号里也看得见（3.3 那节说的： 里面能看见外面）。 能看见，所以能改；改的是同一个盒子，所以出去还在。

这一条和 n 那条摆在一起看，就是 3.3 的全部： 在里面声明的，出去就没了；在外面声明的，里面也看得见、也能改。

自己写一个程序，要求：

  • 一对大括号里，声明 int step = 5;，然后 total = total + step;， 打完一行 第一次之后 total = ?

第一次之后 total = 5

看答案

两个 step 都是新的盒子，各装各的： 第一个装 5，用完就没了；第二个装 7，跟第一个毫无关系。 能把两个数都记住的，只有 total 一个——它声明在最外面。 

#include <iostream>

int main() {

这一题最容易写错的地方，是想让两个大括号共用一个 step—— 比如把第二个写成 step = 7;（不带 int）， 心里想着「改一改再用」。

那样写会怎样？第一对大括号里确实能用，但第二对里的 step 已经没了，编译器会说 not declared in this scope—— 跟练习 3-7 一模一样的错。

想清楚这件事，这一课就算过了：盒子的命跟着大括号走， 想让一个值活过好几块地盘，就得把它声明在那些地盘外面。

你现在能写什么：你能说出一个变量活到哪儿为止了。 再看到「用了没声明的名字」这种报错，你能一眼认出是出界，而不是别的问题—— 这是新手卡得最久的一类错。下一课讲递参数：你把盒子递出去，函数收到的是什么。

3.4传参（上）：值传递

3.3 讲的是盒子什么时候没。这一课讲它从哪来。

两课合起来就一句话：函数括号里那个盒子，是新开的， 而且装的是抄过来的一份。

复印件，不是原件

叫函数的时候，你写 addOne(a)。 很多人心里想的是「把 a 递进去」——听着没错，其实差了一层。

真实发生的是：把 a 里装的值抄一份，交给函数。 函数收到的是一个新盒子，装着一份抄来的值。 你在函数里改来改去，改的都是那份复印件。

这个规矩有个名字叫值传递（pass by value）。 「值」就是「值」，传的是值，不是那个盒子。

跟着动画走一遍

这次盯住两个盒子：main 里的 a，和函数里的 x。 按到中间那一步，看看改了 x 之后 a 变没变。

整个程序的输出是两行： 

函数里 x = 4
回来 a = 3

第二行是这一课的全部。x 都变成 4 了，回来一看 a 还是 3。

一个不声不响的失败

上一段那个程序，还只是「改了没用」。 下面这个更典型——写的时候是真心以为它能成的： 

#include <iostream>

void swapTwo(int x, int y) {
    int t = x;
    x = y;
    y = t;
}

int main() {
    int a = 1;
    int b = 2;

    swapTwo(a, b);

    std::cout << a << " " << b << std::endl;
    return 0;
}

函数名叫 swapTwo，交换两个数。函数里那三行确实换成了： 

int t = x;      // t 拿到 1
x = y;          // x 变成 2
y = t;          // y 变回 1
                // 到这里，x 是 2、y 是 1，换好了

编译一声不吭。跑一下： 

1 2

一动没动。

现在你应该能自己讲出原因了：x 和 y 是复印件。 函数里那三行把两张复印件换了个遍，原件 a 和 b 从来没被碰过。 函数一结束，连复印件都跟着没了（3.3 讲的）， 就像这件事压根没发生过。

编译器为什么一声不吭

这是新手最难接受的一点：编译器不管你想干什么，只管你写得合不合语法。

swapTwo(a, b) 这一句，语法上完全没问题： 参数是两个 int，递进去两个 int，对得上。 函数体那三行，语法也没问题。整份文件挑不出一个错。

错的不是语法，是想法——你以为递进去的是 a 和 b 本身， 其实递进去的是它们的值。

这一类错，编译器一个都拦不住。 它只能靠你自己知道这条规矩，或者靠跑一遍、对着输出看。 这就是为什么这门课每段代码都要你亲手跑—— 不是走过场，是因为有些错只有跑起来才现形。

写到这儿该问自己一句什么

以后你写函数，写到「想让外面发生点变化」的时候， 停下来问自己一句：

「我这个函数，是只算个数交回去，还是要改外面那个盒子？」

你想干的事该怎么做
算个数交回去（求和、比大小、判断及格） 值传递就够了——3.2 的 return 就是干这个的
改外面那个盒子（交换、累加、把结果填进去） 值传递做不到，下一课讲怎么办

大部分函数是第一种，所以值传递不是缺点，它就是默认规矩。 只在你真的想改外面的时候，才需要别的东西。

看答案

预期输出是： 

函数里 x = 12
回来 a = 6

第一行是 12，第二行是 6——不是 12。 

#include <iostream>

void doubleIt(int x) {
    x = x * 2;
    std::cout << "函数里 x = " << x << std::endl;
}

int main() {
    int a = 6;
    doubleIt(a);
    std::cout << "回来 a = " << a << std::endl;

}

原因就是 3.4 那个动画里的那一步： doubleIt(a) 递出去的是 a 的值（6）的抄件。 函数里那个 x 是新盒子，装的是抄来的 6。 x = x * 2 把它改成 12—— 改的是那个抄件，main 里的 a 从头到尾没被任何一行代码碰过。

把这段和 3.4 的 addOne 摆一起看，两个程序的骨架一模一样， 输出也一个道理。换了个函数名、换了道算法，规矩没变。

有个地方值得多想一秒：函数里那句 std::cout << "函数里 x = " << x 打的是 12。 这一行没骗你——函数里 x 确实是 12。 错的是「那外面也变成 12 了吧」这个想当然。

你现在能写什么：你能说清楚一个函数能改什么、不能改什么了。 更重要的是，你知道了有一类错编译器不会告诉你—— 以后程序跑出来不对劲，你会想到先去看「是不是改了个复印件」。 下一课给这个毛病开方子。

3.5传参（下）：引用传递

上一课那个交换失败的程序，改法小得让人意外：参数表上补一个字符。

一个 & 的区别

先看一个最简单的对比。左边是 3.4 的程序，右边只多了一个 &： 

void addOne(int x) {            void addOne(int& x) {
    x = x + 1;                      x = x + 1;
    ...                             ...
}                               }

左边那份，输出是 函数里 x = 4 / 回来 a = 3（3.4 讲过）。 右边这份，输出是： 

函数里 x = 4
回来 a = 4

只差最后一行。3 变成了 4。

函数体一个字没改。改的只有括号里：int x 变成 int& x。

那个交换，加上 & 就对了

回到上一课那个不声不响的失败。函数体还是那三行，还是同样的顺序： 

#include <iostream>

void swapTwo(int& x, int& y) {
    int t = x;
    x = y;
    y = t;
}

int main() {
    int a = 1;
    int b = 2;

    swapTwo(a, b);

    std::cout << a << " " << b << std::endl;
    return 0;
}
2 1

换过来了。

跟 3.4 那份摆在一起看，两份文件只差一个字符——参数表上多了两个 &。 这件事值得你自己动手跑一遍：把两份都编译了，先后运行，看着输出从 1 2 变成 2 1。 比读十遍文字都有用。

注意是两个都要加。只加一个的话，那个还是复印件， 换到一半就断了——你可以自己试试，看会打出什么来。

& 到底干了什么

int& x 读作「x 是一个 int 的引用」。

引用（reference）不是新盒子，是给原来那个盒子起的另一个名字。

拿人打比方：你大名叫「张三」，熟人平时叫你「三儿」。 两个名字，一个人。叫哪个，回头的都是你。

所以 int& x 的意思是： x 不是新开的盒子，它就是外面那个 a 的另一个名字。 往 x 里写，就是往 a 里写。改哪个名字都一样，因为是同一个人。

值传递
int x		引用传递
int& x
函数收到的是新盒子，装着抄来的值外面那个盒子的另一个名字
函数里改 x改复印件，外面不动改的就是外面那个盒子
函数结束后复印件连同盒子一起没了外面的盒子还在，带着新值
正式叫法pass by valuepass by reference

什么时候用，什么时候别用

回到 3.4 最后那张表，现在能填满了：

  • 只算个数交回去的——用值传递（int x）。 这是绝大多数情况。函数干净，谁调它都不会把自己的盒子弄脏。
  • 要改外面那个盒子的——用引用（int& x）。 交换、累加、把算出来的结果填回到传进来的地方，都是这一类。

有一条经验值得你现在就记下： 一个函数，最好只干上面两件事里的一件。

要么它算个数交回来（有 return，参数都是值的）， 要么它改传进来的东西（参数用引用，不需要 return）。 两样都干，叫它的人就得猜「这个函数到底会不会动我的东西」—— 猜错一次就够你找半天的。

还有一件事：用了引用，外面传进来的就不能是算出来的数了。 addOne(3) 是编译不过的——3 是个数字，不是盒子，没名字可起。 必须是能装东西的变量。报错大意是 「把常量当引用传」，你见到的时候能认出来就行。

3.6动手拆：把乘法表拆成函数

这一课不教新东西。把 3.2 到 3.5 学的全用上，回去收拾 2.6 那道综合练习。

回到 2.6 那张表

这是 2.6 写出来的那份： 

#include <cstdio>

int main() {
    for (int i = 1; i <= 9; i = i + 1) {
        for (int j = 1; j <= i; j = j + 1) {
            printf("%d×%d=%2d ", j, i, i * j);
        }
        printf("\n");
    }

    return 0;
}

它跑得没错。但按 3.1 那把尺子量一下——这里面有几件事？

两件：打一行，和打整张表。 外面的 i 循环是「哪几行都要打」，里面的 j 循环是「一行怎么打」。

拆成两块

把这两件事各起一个名字： 

#include <cstdio>

// 打一行：第 i 行，从 1×1 打到 i×i
void printRow(int i) {
    for (int j = 1; j <= i; j = j + 1) {
        printf("%d×%d=%2d ", j, i, i * j);
    }
    printf("\n");
}

// 打整张表：把 1 到 9 行都交给 printRow
void printTable() {
    for (int i = 1; i <= 9; i = i + 1) {
        printRow(i);
    }
}

int main() {
    printTable();
    return 0;
}

内圈原封不动搬进了 printRow，连 %2d 和那个空格都没碰。 外圈变成了 printTable，只是本来写在内圈里的那几行， 换成了一句 printRow(i)。

注意 printRow 收了一个 int i—— 「打第几行」这件事会变，所以它得从外面进来。 而 printTable 不用收任何东西：它干的活是固定的，就是把 1 到 9 行都打一遍。

这一条要记住：拆函数不改变结果。 拆完跑出来的东西跟拆之前不一样，那一定是你哪一步抄错了—— 这是件好事，因为你有一个现成的办法检验自己拆对没有：跑一遍，对输出。

拆的时候脑子里在想什么

拆代码不是随便找几行剪下来。有一个能用的想头：

  1. 先问「这里面有几件事」。像 3.1 那样一件一件数出来。
  2. 每件事起个名字。名字要是动词——printRow、printTable、 swapTwo。念一遍这个名字，就知道它干什么。
  3. 问这件事要什么才能干。「打第 i 行」得知道 i 是几，所以参数是 int i。 「打整张表」不需要知道任何事，所以参数是空的。
  4. 问这件事要不要交结果回来。这两件事都是「打完就完了」，所以都是 void。 要是「算个和」，那就得有 return。

第 3 步和第 4 步，就是 3.2 讲的那两件事： 括号里写什么，开头的类型写什么。

这四步问下来，函数的架子自己就出来了。剩下的是把原来的代码搬进去—— 搬的时候一个字都别改，改了就不知道是自己搬错了还是原本就错。
