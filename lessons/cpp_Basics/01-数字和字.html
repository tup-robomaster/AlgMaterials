第 1 部分

数字和字

程序归根到底就干三件事：记住一些数、算一算、把结果弄出来。 这一部分讲前两件——怎么把数放进程序里，怎么让它算。

1.1变量：给一个盒子起名字

程序要算数，就得有地方放数。那个地方叫变量（variable）。

先看一个完整的程序。它开了三个盒子，算了点东西，然后把结果打印出来。 

#include <iostream>

int main() {
    int a = 3;
    int b = 5;
    int c = a + b;

    a = 10;              // 改 a，看看 c 会不会跟着变

    std::cout << a << std::endl;
    std::cout << b << std::endl;
    std::cout << c << std::endl;

    return 0;
}

先别急着运行。下面这个动画把这个程序一步步走一遍，你可以点「下一步」慢慢看， 也可以点「自动播放」。注意中间那一排盒子，和右边屏幕上出现的东西。

一行一行读

int a = 3; —— 这句话做了三件事：

  • int 说明这个盒子放的是整数（integer）。先不管它，1.2 专门讲。
  • a 是给这个盒子起的名字。
  • = 3 是把 3 放进去。末尾那个 ; 别忘了，每句话都要有。

int c = a + b; —— 这句话看着像一步，其实是两步： 先算右边，把 a 和 b 的值读出来（3 和 5），加起来得到 8； 再把 8 放进 c。

= 不是「等于」

这是新手最容易栽的一个地方。

数学里 = 表示「左右两边相等」，是个陈述。C++ 里不是—— C++ 的 = 是一个动作：把右边的东西放进左边的盒子。

所以 a = 10; 读作「把 10 放进 a」，不是「a 等于 10」。

按这个读法，下面这句话就不奇怪了： 

a = a + 1;

数学上这句话不可能成立。C++ 里它完全正常，读作： 「把 a 现在的值读出来，加 1，再放回 a」。 a 原来是 10 的话，做完这句就是 11。

为什么现在讲这个

因为 = 读错了，后面每一课都会读错。1.3 会专门练这个。

盒子之间没有牵连

回到前面那个动画。最后一步是 a = 10;，把 a 从 3 改成了 10。

c 没有跟着变。它还是 8。

为什么？因为在 int c = a + b; 那一瞬间，程序把 a + b 算完了， 把结果 8 抄进了 c 这个盒子。从那一刻起，c 和 a、b 就没有任何关系了。 后面再改 a、改 b，c 都不知道。

这是很多人第一次写代码会想错的地方——以为 c 是「a 加 b」这个公式， 会一直跟着变。不是的。c 里面就是一个死数字，8。

换个说法

int c = a + b; 不是把 a、b 连到 c 上，是算一次、抄一份。 想让它重新算，你得再写一遍 c = a + b;。

名字怎么起

规则例子
只能用字母、数字、下划线count sum_1 maxX
不能数字开头1st ✗   first1 ✓
区分大小写。a 和 A 是两个不同的名字num 和 Num 互不相干
不能用 C++ 自己占着的词int return if 都不能当名字
起能看懂的名字sum 比 s 好，count 比 c 好

最后一条你现在看不出有什么必要。等你的程序超过 50 行就懂了—— 那时候回头看自己一周前写的 a、b、t， 你会不知道它们是什么。

坑

名字起成 l（小写 L）、O（大写 o）、I（大写 i） 这种，在等宽字体里和 1、0 长得一样。 编译器分得清，你分不清。别用。

例题 · 开三个盒子，算一次加法

题目：一份外卖 25 元，一杯奶茶 18 元。把这两个数放进变量，算出总价，打印出来。

完整程序——注意它的样子，和你从 0.2 起就熟悉的骨架一模一样，只是多开了三个盒子： 

#include <iostream>

int main() {
    int meal = 25;              // 开一个盒子叫 meal，放 25
    int tea = 18;               // 开一个盒子叫 tea，放 18
    int total = meal + tea;     // 先算右边（25+18=43），再放进 total

    std::cout << total << std::endl;

    return 0;
}
43

盒子的名字是我自己起的。meal、tea、total 都不是 C++ 规定的词，换成 a、b、c 照样能跑。 可一周以后回头看，total 比 c 好懂得多—— 这就是上面那张表里最后一条的意思。

还有，int total = meal + tea; 是先算右边、再放进左边， 和动画里 int c = a + b; 走的是同一步。

1.2类型：int、double、char、bool

1.1 里我们一直写 int a = 3;。int 是什么？

它是类型（type）。类型决定了这个盒子能装什么、装多大。 装整数的盒子装不了小数，装字符的盒子装不了整数——就像鞋盒装不下被子。

四种类型

最常用的就四种，一次认全。 

#include <iostream>

int main() {
    int    n = 42;       // 整数
    double d = 3.14;     // 小数
    char   c = 'A';      // 一个字符
    bool   b = true;     // 真 / 假

    std::cout << n << std::endl;
    std::cout << d << std::endl;
    std::cout << c << std::endl;
    std::cout << b << std::endl;

    return 0;
}

3.14
A
1
类型装什么写的时候长这样
int整数，没有小数点int age = 19;
double小数double h = 1.75;
char一个字符，用单引号char c = 'A';
bool真或假，只有两个值bool ok = true;
最后一行为什么是 1

bool 存的是「真」和「假」，但 std::cout 默认把它们打成 1 和 0。 1 就是 true，0 就是 false。 记住这个对应关系，以后看到 1 不要当成数字。

char 的三个细节

一、单引号，不是双引号。'A' 是一个字符，"A" 是一串字符。 写错了编译器会报错，练习里有一道专门找这个。

二、只能装一个字符。char c = 'AB'; 是错的。

三、它其实是一个很小的整数。这是最反直觉的一点。看例子： 

char c = 'A';

std::cout << c << std::endl;          // 直接打，是个字母
std::cout << c + 1 << std::endl;      // 加 1 再打 —— 加号把它当成了数字
char next = c + 1;          // 结果放回 char 盒子
std::cout << next << std::endl;       // 又变回字母了

int code = c;               // 把 c 的值放进一个 int 盒子
std::cout << code << std::endl;
A
66
B
65

看出来了吗：每个字符在计算机里都有一个编号。'A' 是 65，所以 'A' + 1 是 66， 而编号 66 对应的字符是 'B'。小写 'a' 是 97。

同一份数据，你用什么类型去看它，它就是什么。这就是「类型」这个词的意思。

补充一：double 存不准

这一条会颠覆你的直觉。看： 

double a = 0.1;
double b = 0.2;

std::cout << a + b << std::endl;
std::cout << (a + b == 0.3) << std::endl;
std::cout << (a + b > 0.3) << std::endl;
0.3
0
1

第二、三行里的 == 读作「相等吗」，> 读作「大于吗」—— 这两个第 2 部分才正式讲，现在你只要看结果：

  • 第一行打出来是 0.3——看着像 0.3
  • 第二行说它和 0.3 不相等（0 就是假）
  • 第三行说它比 0.3 大（1 就是真）

一个东西既「看着等于 0.3」又「比 0.3 大」，只能说明一件事：它根本不是 0.3。

原因是计算机用二进制存小数，0.1 和 0.2 都存不准， 加起来是一个很接近 0.3 但不等于 0.3 的数。 只是 std::cout 默认只打 6 位有效数字，把它显示成了 0.3。

所以

不要用 == 去比较两个算出来的小数。 真要比较，就比差值——两个数相差小于 0.000001 就当作相等。 现在先记住结论，以后你会明白得更透。

补充二：int 装不下

int 能装的整数有上限，最大是 2147483647。再加 1 会怎样？ 

int a = 2147483647;      // int 能装的最大值
std::cout << a << std::endl;

a = a + 1;               // 再加 1
std::cout << a << std::endl;
2147483647
-2147483648

它绕回来了，变成最小的负数。这个现象叫溢出（overflow）。 你可以理解成：盒子装满还想再塞，就从另一头冒出来了。

说得准确一点：超出范围之后该是什么，C++ 并没有规定。 你上面看到的是这台机器上编译器实际干的事，不是标准保证的。所以：

  • 别指望溢出之后一定是某个固定的数
  • 更要紧的是：编译器不会提醒你。上面那个程序编译时一句警告都没有，它觉得自己完全没问题

这就是 0.1 里说的「编译过了，结果不对」—— 编译器不知道你想要什么，它只知道语法对不对。

练习 1-7（找错）

1.3运算：加减乘除、取余

盒子会开了，现在让它们算。

五个运算符

int a = 7;
int b = 2;

整数除法：这一课最大的坑

看这四行。只差一个小数点，结果就不一样。先自己猜四行分别输出什么，再往下看。

规则只有一条：两个整数相除，结果一定是整数。

把这一条背下来

「整数除以整数」是新手最常踩的坑，而且编译器一句话都不会说。 你写 average = sum / count;，心里想的是平均值， 程序给你的是一个砍掉了小数的整数——语法完全正确，结果完全不对。

1.4输出：std::cout 怎么把东西打到屏幕上

前三课每一课都在用 std::cout，但一直没停下来讲过它。 这一课把它讲清楚——因为从今往后你写的每一个程序，都要靠它跟你说话。

一个 << 只做一件事

std::cout 读作「C out」，意思是标准输出——就是你的终端窗口。 << 这个符号本身的意思是「往这边流」。

所以 std::cout << 8; 这一句读作：把 8 送到终端上去。 左边的 std::cout 是终点，右边才是要送的东西。

那一串是怎么接起来的？看这句： 

std::cout << "3+5=" << 3 + 5 << std::endl;

它其实是三次「送」：

  1. 把 "3+5=" 送到终端
  2. 把 3 + 5 算出来的 8 送到终端
  3. 把 std::endl 送到终端

三次是从左往右挨着做的，所以屏幕上就是 3+5=8。 每送完一次，std::cout 自己就准备好接下一次——这就是它能一路串下去的原因， 串多长都行。

右边怎么什么都能放

上面第二样东西是个算式，第三样是个 std::endl， 根本不是一个品种，但 << 都收。 现在不用管它内部怎么做到的，只要记住：<< 右边可以放值、放算式、放 std::endl。

空格是你自己打的

这是新手第一个遇到的事：std::cout 只打你让它打的东西，一个字符都不多打。 两个值中间想要的空格，得你自己输进去。 

int a = 3;
int b = 5;

std::cout << a << b << std::endl;              // 中间什么都没有
std::cout << a << " " << b << std::endl;       // 自己插一个空格进去
std::cout << "和是" << a + b << std::endl;
35
3 5
和是8

第一行打出的是 35——不是 3 和 5，也不是 3 加 5， 就是两个字紧挨在一起。 第二行里那个 " "，是一对双引号中间夹一个空格， 它本身就是一个「东西」：一个只装了一个空格的字符串。

第三行你可能觉得别扭：和是8，8 前面没空格。 中文里写「和是 8」是习惯，但程序不知道这个习惯——想要就得自己加， 写成 "和是 "（引号里带个空格）就对了。

引号里原样打，引号外算完再打

上面出现过的 "3+5=" 和 3 + 5，是两种完全不同的东西。 这一条弄混了，后面每一课都会写错。 

#include <iostream>

int main() {
    std::cout << "3+5" << std::endl;            // 引号里：原样打
    std::cout << 3 + 5 << std::endl;            // 引号外：先算，打结果
    std::cout << "3+5=" << 3 + 5 << std::endl;  // 一半一半

    return 0;
}
3+5
8
3+5=8

双引号里面的东西，程序一个字都不动。 "3+5" 就是三个字符：3、+、5。 它不会去算，也不会管它长得像不像算式。

双引号外面的东西，会先算完，再把结果送出去。 3 + 5 算成 8，送到屏幕上的就是 8。

第三行最有用：引号里和引号外可以挨着放。 「3+5=」这几个字是死的，后面那个 8 是现算的——拼在一起， 就是一句「算式和答案都摆给你看」的话。 2.6 要打的 3×5=15 那样的乘法表，用的就是这个写法。

它怎么知道该打什么

凭什么 std::cout << a 的时候，它知道该打数字还是该打字母？ 答案是：它看你送过来的是什么类型，然后按那个类型的规矩打。 1.2 学的四种类型，在这儿各有一副面孔。 

#include <iostream>
#include <string>

int main() {
    int n = 65;
    double d = 3.0;
    char c = 'A';
    bool b = true;
    std::string s = "A";

    std::cout << n << std::endl;
    std::cout << d << std::endl;
    std::cout << c << std::endl;
    std::cout << b << std::endl;
    std::cout << s << std::endl;

    return 0;
}
65
3
A
1
A

一行一行对：

  • int 65 → 65，正常。
  • double 3.0 → 3。小数点和小数位全没了。
  • char 'A' → A，打的是字母，不是 65。
  • bool true → 1，不是 true 这个词。
  • std::string "A" → A。

第二行和第四行是重点。它图省事：3.0 后面全是 0，那就不打了；true 就是 1，那就打 1。 1.2 那两个提醒在这儿应验了——盒子里的东西，和打出来的样子，不是一回事。

平时这样挺好，省事。可一旦要对齐（比如打一张价格表），这一省就出事了。 1.6 整整一课都在治这个毛病。

给一段文字起个名字

上面那五行里有个生面孔：std::string s = "A";。 它一点不新鲜——它就是 1.1 那个盒子，只不过装的是文字。 

std::string name = "小航";

意思是：开一个叫 name 的盒子，把「小航」这两个字放进去。 有两点和前面四种类型一模一样：

  • 写全 std::string，不是光写 string。 理由和 std::cout 一样——它住在 std 里（0.3 那个 std:: 讲的就是这件事）。
  • 文件开头要多一行 #include <string>，和 #include <iostream> 并排放。

引号再复习一遍（1.2 那道 char c = "A"; 的找错题就是考这个）： char 装一个字符，用单引号；std::string 装一串字符，用双引号。

这个盒子能装多少

int 有装不下的数（1.2 见过 1410065408 那个）， std::string 却几乎不会满——你放多少字，它自己就跟着变多大。 怎么做到的，第 4 部分讲 std::vector 的时候一起说。

endl 和 "\n"

到这儿为止，每句话末尾都跟着 std::endl。它的作用是换行： 把它送到屏幕，光标就挪到下一行的开头。

换行还有另一种写法："\n"。这是一个字符串，里面只装了一个字符。 那个 \n 是「换行」的意思——反斜杠和 n 两个字符打在一起，代表一个换行符。 

#include <iostream>

int main() {
    std::cout << "第一行" << std::endl;
    std::cout << "第二行" << "\n";
    std::cout << "第三行" << std::endl;

    return 0;
}
第一行
第二行
第三行

跑出来一样是三行。两个都能换行，现在你随便用哪个。

差别在这儿：std::endl 除了换行，还多做一件事—— 催一下，让字立刻出现在屏幕上。平时你感觉不到， 因为本来就立刻就出来了。

以后会看到 "\n"

同一件事重复做很多遍的时候（第 2 部分讲了循环就有了）， std::endl 那一下「催」会拖慢程序。所以实际代码里，赶时间的那些地方， 末尾大多是 "\n"。 现在不用纠结，先用 std::endl——它的名字好记。

题目：一个名字、一个年龄、一个身高，打成一整句话，最后换行。 名字是文字，年龄是整数，身高是小数——三种类型一起上。 

#include <iostream>

要是写成 std::cout << "3+5=8" << std::endl;， 屏幕上看着一模一样——但那是你算的，不是程序算的。 差别在哪儿？数一换，写死的那行就错了，写算式的那行永远对。

这不是小题大做。第 2 部分那个乘法表，每一行的数都得靠程序算出来—— 九乘九八十一个结果，一个都写不得。

练习 1-15（找错）

下面这一行想打出 和是8，但它编译不过。 先别看答案——说说问题出在哪儿。 

std::cout << “和是” << a + b << std::endl;

提示：把屏幕上这一行放到最大，一个字符一个字符地看。 特别是那对引号。

这题和 1.2 那道 char c = "A"; 是同一种毛病： 看着差不多，不是一个东西。

看答案

问题出在输入法。那对引号是全角的「弯引号」， 不是你键盘上英文输入法下的直引号。完整程序长这样： 

#include <iostream>

int main() {
    int a = 3;
    int b = 5;

    std::cout << “和是” << a + b << std::endl;

    return 0;
}

编译一下：

1-15-err.cpp:11:18: error: extended character “ is not valid in an identifier
   11 |     std::cout << “和是” << a + b << std::endl;
      |                  ^
1-15-err.cpp:11:18: error: extended character ” is not valid in an identifier
1-15-err.cpp: In function ‘int main()’:
1-15-err.cpp:11:18: error: ‘“和是”’ was not declared in this scope
   11 |     std::cout << “和是” << a + b << std::endl;
      |                  ^~~~~~

三条 error，一条都不像人话。但第一行给了线索： 

extended character “ is not valid in an identifier

翻译过来：「这个字符不能出现在名字里」。 编译器压根没把 “ 当成引号——它以为你在给一个变量起名字， 而起名字允许用的字符里，没有这种怪符号。

最后一条更有意思：‘“和是”’ was not declared in this scope—— 它把 “和是” 整个当成了一个名字， 然后说「没听说过这个名字」。

怎么改：把那对引号删掉，切到英文输入法，重新打一对 "。 1.2 那道 char c = "A"; 犯的是同一种毛病—— 看着像，不是一个东西。

写代码前先看一眼输入法

中文输入法下，引号、逗号、分号、括号打出来全是全角的， 代码里一个都不认。养成习惯：一进编辑器就切英文， 只有要写引号里那句中文的时候才切回来，写完立刻切回去。

练习 1-16

下面这个程序会打出几行？每行是什么？先写在纸上，再编译。 

std::cout << "A";
std::cout << "B" << std::endl;
std::cout << "C";
std::cout << "D" << std::endl;
std::cout << "E";
std::cout << "F" << std::endl;
AB
CD
EF

提示：std::endl 只做换行，不做别的事。 没有 std::endl 的时候，下一个字打到哪儿去了？

看答案

六行 std::cout，三行输出。关键是看清每个 std::endl 落在哪一句上： 

#include <iostream>

int main() {
    std::cout << "A";
    std::cout << "B" << std::endl;
    std::cout << "C";
    std::cout << "D" << std::endl;
    std::cout << "E";
    std::cout << "F" << std::endl;

    return 0;
}

一行一行走：

  1. "A" 送到屏幕上。光标停在 A 后面，没有换行。
  2. "B" 紧挨着 A 打出来，然后 std::endl 换行。屏幕上这一行是 AB。
  3. "C" 打在新一行的开头，光标停在 C 后面。
  4. "D" 紧挨着 C，然后换行。这一行是 CD。
  5. "E"、"F" 同理，凑成 EF。

所以字不是一行一行「打出来」的，是一个一个「接上去」的。 std::endl 管的只有一件事：把光标挪到下一行开头。 没有它，下一个字就接着上一个字往下写。

最容易错的地方是数行数：六行代码，三行输出。 代码的行数和屏幕上打出来的行数没有关系——等第 2 部分学了循环， 这个差别会大得离谱（三行代码打出八十一行，一点都不奇怪）。

你现在能写什么：能让程序把值、算式和文字拼成一句话打出来， 也知道打出来的是圆是扁、是 3 还是 3.0，全看盒子的类型。 下一课反过来——让程序停下来，等你敲数给它。

1.5输入：std::cin 读进来的是什么

到上一课为止，程序里的数全是你自己写在代码里的。 别人拿到你的程序，想换个数算，只能来改你的代码、重新编译。

这一课让程序开口要数：跑起来停一下，等你敲，敲完它接着算。

程序第一次停下来等你

先不写代码，先看它跑起来是什么样。下面这一段，是你屏幕上会出现的全部内容—— 带下划线的那些是你敲的，其余是程序打的。 

第一个数：
19
第二个数：
23
和是 42

三件事：

  • 程序打到「第一个数：」就停住了，光标在那儿闪，等你。
  • 你敲 19 按回车，它才接着走，打出「第二个数：」，又停住。
  • 两个数都给了，它算出 42 打出来，然后自己结束了，回到命令提示符。

这个程序就是下面的例题，代码一会儿看。先把上面这张图记住—— 以后凡是程序要读东西，屏幕上就是这个样子。

从这一课起，输入和输出分开看

课里的例题有时会把整段会话贴出来：带下划线的行是你敲进去的， 终端把它回显在屏幕上，不是程序打的；程序自己打出来的， 只有不带下划线的那几行。

练习题从这一课起把两样东西分开写：输入单独放一个「样例输入」块， 程序打出来的放一个「预期输出」块。对照时只看「预期输出」块， 不必再分下划线。

>> 的方向是反的

输出用的是 <<，输入用的是 >>。 方向正好相反——因为东西流动的方向相反。

输出是「从程序流到屏幕」，箭头朝外： 

std::cout << a;      // 把 a 送出去，送到屏幕上

输入是「从键盘流进程序」，箭头朝里： 

std::cin >> a;       // 从键盘收一个进来，装进 a

std::cin 读作「C in」，标准输入，就是你的键盘。 箭头左边是来源，右边是目的地，照着「东西往哪边流」记，就不会记反。

记反了会怎样

记反了就是 std::cin << a; 或者 std::cout >> a;。 两个都编译不过，编译器会直接告诉你： 

1.5-reverse-err.cpp:5:14: error: no match for ‘operator<<’ (operand types are ‘std::istream’ {aka ‘std::basic_istream<char>’} and ‘int’)
1.5-reverse-err.cpp:6:15: error: no match for ‘operator>>’ (operand types are ‘std::ostream’ {aka ‘std::basic_ostream<char>’} and ‘int’)

抓两个词就够：no match，「没有能对上的」； operand types are，后面列出来的是「你递过去这两样东西分别是什么类型」。 std::istream 是 std::cin 的正式类型名， std::ostream 是 std::cout 的—— 它一眼就认出你把谁当成谁了。 （括号里 {aka …} 那半截是它的另一个名字，先不用管。）

它不会悄悄照你的意思反过来做。这一点可以放心。

没有提示语会怎样

把例题里那两句「第一个数：」删掉，程序干的活一模一样，可看起来完全变了： 

#include <iostream>

int main() {
    int a;
    int b;

    std::cin >> a;
    std::cin >> b;

    std::cout << a + b << std::endl;

    return 0;
}

还是输入 19 和 23，屏幕上只有这三行： 

19
23
42

前两行还是你自己敲的（终端回显的），程序自己只说了一个字：42。 没有提示语，屏幕上连一句「要你干什么」都没有。

第一次跑这种程序，很容易以为它卡死了——它没卡，它在等你。可你看不出来。

写给人用的程序，先打一句提示语

要人敲什么，就先打一句话说清楚。这句话不是给程序看的， 是给坐在电脑前的那个人看的。例题里那两句「第一个数：」「第二个数：」就是干这个的。

注意「打提示语」和「读数」是两句不同的话： 用 std::cout 打提示语，用 std::cin 读数。 两句都得写——少写提示语，人看不懂；少写 std::cin， 盒子就是空的，程序拿一个不知道是什么的数去算。

一次读几个，空格和回车都算数

#include <iostream>

int main() {
    int a;
    int b;
    int c;

    std::cin >> a >> b >> c;        // 一串 >> 读完三个

    std::cout << a + b + c << std::endl;

    return 0;
}

下面两种输入，跑出来一模一样。第一种，三个数敲在一行： 

1 2 3
6

第二种，一行一个： 

1
2
3
6

两种都是 6。为什么？因为 >> 不认「行」，只认「空白」—— 空格、Tab、回车，在它眼里全是同一件事：一个数的结束，也是下一个数的开始。 它按这个把你敲的东西切成一块一块，再按顺序往盒子里放。

那一串 >> 又是怎么回事？和输出一个道理： 一次 >> 只收一个数，收完 std::cin 就准备好收下一个。 所以 std::cin >> a >> b >> c; 和写成三行是一回事。

读进来的是什么

这一课标题里那个问题，答案在这儿。 下面这个程序，你跑的时候敲 3.7： 

#include <iostream>

int main() {
    int n;

    std::cin >> n;
    std::cout << n << std::endl;

    return 0;
}
3.7
3

你敲的是 3.7，它打出来是 3。

不是你敲错了，也不是程序坏了。原因还是 1.2 那一条： int 这个盒子装不下小数。 往 int 盒子里装东西的时候，>> 只认整数那一段—— 读到 . 就停了，3 塞进去，剩下的 .7 留在那儿没人要。

所以这一条要记牢： >> 不是「把你敲的照原样搬进去」，而是「按盒子的类型， 从你敲的东西里认出它能要的那部分，搬进去」。 想要小数，盒子就得是 double： 

double x;
std::cin >> x;      // 这个盒子才装得下 3.7

同一件事还有另一个方向。往 std::string 里读的时候，>> 读到空白就停。 下面这个程序，你跑的时候敲 小航 19： 

#include <iostream>
#include <string>

int main() {
    std::string word;

    std::cin >> word;
    std::cout << "读到的是：" << word << std::endl;

    return 0;
}
小航 19
读到的是：小航

它只要了「小航」。因为 >> 是按空白切块的（刚才说的那条）， 一段文字里只要有空白，它就认为这段到头了。 那个 19 还留在输入里，谁也没去拿。

那想读一整行（带我名字里那个空格）怎么办

有专门的办法，叫 std::getline。 现在先不学——你要用的时候自然会想找它，那时候记着来这儿翻一下就行。

例题 · 读两个数，把和打出来

这一课开头那张屏幕，就是这个程序跑出来的。完整代码： 

#include <iostream>

int main() {
    int a;
    int b;

    std::cout << "第一个数：" << std::endl;
    std::cin >> a;

    std::cout << "第二个数：" << std::endl;
    std::cin >> b;

    std::cout << "和是 " << a + b << std::endl;

    return 0;
}
第一个数：
19
第二个数：
23
和是 42

四种句子凑齐了，这一课就这么点东西：

  • 开盒子：int a;——先声明，暂时不放东西。
  • 打提示语：std::cout << "第一个数：" << std::endl;
  • 读数：std::cin >> a;——程序停在这一行等你。
  • 算：a + b，两个盒子里的东西加起来，和 1.3 那些算式没区别。

顺序很重要。提示语必须打在 std::cin 前面—— 要是两句调个个儿，程序先停在那儿等你，等你敲完了才打出「第一个数：」， 那可就不是提示了，是马后炮。

还有一点：int a; 这一句不能省。 盒子得先开出来，>> 才有地方放东西。 这和 1.1 说的「先声明再赋值」是同一条规矩，只是这里的「赋值」变成了「从键盘读」。

练习 1-17

写一个程序：读两个整数，把它们乘起来打出来。 

6 7
42

提示：这一课标题说的是「读进来的是什么」—— 先想清楚你读进来的这两个盒子是什么类型。

看答案

两个 int 盒子，一次读两个，乘起来： 

#include <iostream>

int main() {
    int a;
    int b;

    std::cin >> a >> b;
    std::cout << a * b << std::endl;

    return 0;
}

这题要读的输入是 6 7—— 这两个数敲在一行还是分两行，跑出来都是 42（1.5 讲的「空白都算数」）。

顺带说一句乘法在编程里的写法：是 a * b，不是 a × b， 也不是 a·b。键盘上没有那个乘号，C++ 里一律用星号。

记着这一条，2.6 会翻回来用它一次：那时候要打出去的字符可以是 ×，可算乘法还是只能写 *——两回事，别混。

练习 1-18

写一个程序：读两个词，然后按 第一个|第二个 的格式打出来—— 中间那个竖线是你自己打的。 

hello world
hello|world

提示：装词用 std::string。 这题的考点在 >> 怎么切块——想一下它遇到空格会干什么。

看答案

两个 std::string，中间那个竖线是打出来的，不是读进来的： 

#include <iostream>
#include <string>

int main() {
    std::string first;
    std::string second;

    std::cin >> first >> second;
    std::cout << first << "|" << second << std::endl;

    return 0;
}

这题的考点就一个：>> 遇到空格就停。 输入 hello world，它先把 hello 交给 first， 停在空格上；下一次 >> 跳掉那个空格，把 world 交给 second。

所以 空格在 >> 眼里不是「文字的一部分」， 是「分隔符」。要是你读进来的词本身带空格（比如「张 三」）， 这么读就只能读到「张」。那种情况要用的东西 1.5 提过一句， 叫 std::getline，用到的时候再回来看。

练习 1-19

读一个秒数，把它换算成「几分几秒」打出来。 

250
250 秒 = 4 分 10 秒

提示：换算是 1.3 那道 250 分钟的题，一模一样的算法，只是那个 250 现在要从键盘读。 注意打在最后一行里的那个 250 是读进来那个数，不是你写死的。

看答案

算法和 1.3 那道 250 分钟一模一样，只是 250 现在是从键盘读进来的： 

#include <iostream>

int main() {
    int total;
    std::cin >> total;

    int m = total / 60;
    int s = total % 60;

    std::cout << total << " 秒 = " << m << " 分 " << s << " 秒" << std::endl;

    return 0;
}

250 / 60 整出 4 分，250 % 60 留下 10 秒。 两个式子的原料都是刚读进来的 total。

注意最后那行 total 是变量，不是写死的 250。 你要是写成 "250 秒 = "，程序读 300 进来就会打出 「300 秒 = 5 分 0 秒」里的前半句是假的。 敲进去的数，就得从变量里打出来。

练习 1-20

读三个整数，打出它们的平均数。 

1 2 4
2.33333

提示：三个数的和是 7。7 除以 3 该得多少？ 再想一下 1.3 那个整数除法的坑——这一题会踩进去的人不少。

看答案

三个数加起来是 7，7 除以 3 得多少？看住那个 3.0： 

#include <iostream>

int main() {
    int a;
    int b;
    int c;

    std::cin >> a >> b >> c;

    std::cout << (a + b + c) / 3.0 << std::endl;

    return 0;
}

坑在这儿：要是写成 (a + b + c) / 3，那就是 整数除以整数——1.3 讲了一整课的那个坑，结果是 2， 小数部分直接砍掉。

写成 3.0，除号两边就有一个是小数了，结果才是小数。 而且注意：括号不能省。写成 a + b + c / 3.0 的话， 先算的是 c / 3.0，加出来的完全是另一个数。 1.3 讲优先级那段说的就是这个。

你现在能写什么：能让程序停下来问你要数了。 程序会算、会问、会答——一个真正能用的程序该有的三件事，你已经凑齐了。 下一课解决最后一块：怎么让打出来的数字排整齐。

1.6格式输出：printf 与 %d、%f、%2d

这一课讲一个最容易写错的东西。 它本身不难，就是几个符号，但没人专门讲，很多人一直用到毕业都是猜着写的。

先看毛病

三个价格，一个一行，用 1.4 学的 std::cout 打出来： 

#include <iostream>

int main() {
    std::cout << 12.5 << std::endl;
    std::cout << 3.0 << std::endl;
    std::cout << 118.75 << std::endl;

    return 0;
}
12.5
3
118.75

能看，但难受。两个毛病：

  • 小数点不在一条竖线上。12.5 的小数点在第三个字符，118.75 的在第四个。一眼扫下去比不了大小。
  • 3.0 变成了 3。1.4 说过的那件事——它觉得后面全是 0，就不打了。可价格写成 3，看着像个整数。

问题出在：打出来什么样，全是 std::cout 说了算。 你只能决定「打什么」，决定不了「打成什么样」。

这一课就是把这件事的决定权拿回来。拿回来的工具叫 printf。

printf 长什么样

printf 是 C 语言传下来的打印函数，读作「print f」。 用之前要换个头文件： 

#include <cstdio>

（iostream 管 std::cout，cstdio 管 printf。 两个可以同时写，一个程序里两种都能用。）

它的写法和 std::cout 完全不一样，头一次见会觉得怪： 

int a = 7;

printf("a 是 %d\n", a);
a 是 7

拆成三块看：

  1. 一个双引号包着的「格式串」："a 是 %d\n"。 要打的字就写在里面，和 1.4 一样。
  2. 格式串里的 %d。它是个坑位—— 意思不是「打出 %d 这四个字符」，而是「这儿留个洞，等下有个数要填进来」。
  3. 逗号，然后是 a。这是要填进坑里的值。 有几个坑，后面就跟几个值，按顺序一个一个对上。

所以整句读作：打「a 是 」，遇到坑就把 a 填进去，最后换行。

末尾的换行要写 \n

printf 里不能用 std::endl——那个是给 std::cout 用的。 要换行就在格式串末尾写 \n，和 1.4 讲的 "\n" 是同一个东西。

忘写 \n 不会报错，只是下一个 printf 的内容会接着这一行往下写。 这一课给的例子每个都带 \n，你自己写的时候别漏。

%d 和宽度

%d 里的 d 是 decimal，十进制整数。 整数用它。

关键是这个 % 和 d 中间还能塞一个数字—— 塞几，就表示「这个数至少要占几格」。不够就在左边补空格。 

#include <cstdio>

int main() {
    printf("|%d|\n", 7);
    printf("|%2d|\n", 7);
    printf("|%4d|\n", 7);
    printf("|%-4d|\n", 7);

    printf("|%4d|\n", 128);
    printf("|%2d|\n", 128);

    return 0;
}
|7|
| 7|
|   7|
|7   |
| 128|
|128|

每行左右各有一个 |，是特意加的——没有它们，补出来的空格你根本看不见。

  • |7|：光写 %d，占几格算几格。
  • | 7|：%2d，至少两格，7 只占一格，左边补一个空格。
  • | 7|：%4d，至少四格，左边补三个，右边的 | 就对齐了。
  • |7 |：%-4d，前面多一个减号，改补右边（左对齐）。
  • | 128|：%4d 打 128，三格够用，补一个空格。
  • |128|：%2d 打 128——它没有把 128 砍成一个字符，原样打出来了。

最后一行是这一课最容易想歪的地方，单独说：

宽度是「至少」，不是「正好」

%2d 的意思是最少占两格，不是最多两格。 数本身比两格长，它就原样打出来——宁可撑破，绝不砍数。

这一点很要命：你写 %2d 以为能对齐，结果来了个三位数， 整列就歪了。宽度宁可写大一点。

%f 和 %.2f

小数用 %f。它和 %d 有一个大差别： %f 不用你说，默认就给你留六位小数。 

#include <cstdio>

int main() {
    double pi = 3.14159265;
    double price = 7.5;

    printf("%f\n", pi);
    printf("%.2f\n", pi);
    printf("%.3f\n", pi);

    printf("%f\n", price);
    printf("%.2f\n", price);

    printf("|%8.2f|\n", price);

    return 0;
}
3.141593
3.14
3.142
7.500000
7.50
|    7.50|

一行一行看：

  • %f 打 3.14159265 → 3.141593，六位小数，最后一位四舍五入了。
  • %.2f → 3.14。那个点加上数字，就是「小数点后留几位」。
  • %.3f → 3.142。
  • %f 打 7.5 → 7.500000。它老老实实补齐六位。 1.4 里 std::cout 打 7.5 就是 7.5——两者在这儿正好相反。
  • %.2f → 7.50。这才是价格该有的样子：两位小数，一分钱都不含糊。
  • %8.2f → 宽度和小数位一起用，下面说。

宽度加小数位：%8.2f

%8.2f 是这一课最该记住的一个。拆开看： 

% 8 . 2 f
  | |   |
  | |   +-- 小数点后留 2 位
  | +------ 整个数（连小数点带符号）至少占 8 格
  +-------- 「这儿有个坑」

|%8.2f| 打 7.5 得到 | 7.50|： 7.50 占 4 格，不够 8 格，左边补 4 个空格。

为什么要这样？因为补空格是从左边补的，所以小数点自然就对齐了—— 所有 %8.2f 打出来的数，小数点都在从右往左数第 3 格。 小数点对齐了，一列数才好比较。

1.6 开头那三个价格，用上它是什么样，就是下面那道例题。

百分号，和那个最容易少的点

先说百分号。格式串里的 % 有特殊意思（它是「坑」的开头）， 所以你想打一个真的百分号，得写两个。 顺便看看「一次填几个坑」是怎么回事： 

#include <cstdio>

int main() {
    printf("正确率 85%%\n");

    printf("%d 个人里有 %d 个及格，占 %d%%\n", 50, 45, 90);

    return 0;
}
正确率 85%
50 个人里有 45 个及格，占 90%

两件事：

  • %% 打出来就是一个 %。写一个不行——见下面那个提醒。
  • 第二行有三个坑，后面就跟三个值。 50 填进第一个 %d，45 填第二个，90 填第三个， 从左往右，一个一个对上。最后那两个 %% 打出百分号，不占坑。

顺序错了，数就填错了。要是写成 printf("%d %d\n", b, a);， 填进去的确实是 b 和 a——但坑的顺序没变，所以打出来就是反的。 printf 不会替你核对，它只管按顺序填。

只写一个 % 会怎样

g++ 给你一个警告，然后照样编译通过： 

1.6-one-percent-warn.cpp:4:23: warning: unknown conversion type character ‘\x0a’ in format [-Wformat=]
    4 |     printf("正确率 85%\n");
      |                       ^~

\x0a 就是换行那个字符（ \n 的另一个写法，打出来看不见，编译器只好这么写它）。 它说的是：「格式里跟在这个 % 后面的字符，我不认识」—— 它以为你又要填一个坑，可后面跟的是换行，不是 d 也不是 f。

这份程序跑起来碰巧还是对的，因为那个 % 后面紧跟着的正好是换行， 没有东西可填。但那是碰巧，不是规矩。 想打百分号就写两个——别去研究什么情况下能蒙对，那是白费工夫。

再说那个最容易少的点。看这两行，差别只有一个点： 

printf("%.2f\n", 19.9);
printf("%2f\n", 19.9);
19.90
19.900000

第一行想留两位小数，第二行少写了一个点，结果六位小数全回来了。

为什么？因为 %2f 里的那个 2 被当成了宽度， 不是小数位数。19.900000 本来就比 2 格长，宽度这个「至少」直接不起作用—— 于是你写的 2 等于白写，而小数位回到了默认的六位。

这个错编译器不会提醒你

%2f 语法完全合法，编译一个警告都没有， 程序跑起来也顺顺当当，就是打出来的东西不是你要的。 这种错最难查——没有任何东西告诉你错了，只有你自己盯着输出看。

所以养成习惯：写 %.2f 的时候，回头看一眼那个点在不在。

例题 · 对齐一张小票

把开头那三个价格重新打一遍。上半段还是 std::cout，下半段换成 printf， 数字一个都没变，只换了打法。 

#include <cstdio>
#include <iostream>

int main() {
    std::cout << "用 cout 打：" << std::endl;
    std::cout << 12.5 << std::endl;
    std::cout << 3.0 << std::endl;
    std::cout << 118.75 << std::endl;

    std::cout << "用 printf 打：" << std::endl;
    printf("%8.2f\n", 12.5);
    printf("%8.2f\n", 3.0);
    printf("%8.2f\n", 118.75);

    return 0;
}
用 cout 打：
12.5
3
118.75
用 printf 打：
   12.50
    3.00
  118.75

下半段三行，小数点一竖排对齐了，而且每个数都是两位小数， 3.0 也老老实实打成 3.00——看着就像个价格了。

对一下宽度：118.75 连小数点一共 6 个字符， %8.2f 让每个数至少占 8 格，所以 118.75 前面补 2 个空格， 3.00 前面补 4 个，12.50 前面补 3 个。

为什么这样就对齐了？因为每个数都是「补空格 + 两位小数」， 尾巴一样长，头都顶在右边。所以 数越宽，补的空格越少，小数点自然落到同一列上。

一个程序里 std::cout 和 printf 是可以混着用的—— 上面这份就混着用了。要看齐的地方用 printf， 只想打一句话的地方用 std::cout，各取所长。

练习

练习 1-21

用 printf 和上一课那个 %8.2f，把这三个价格打成一小列—— 小数点必须对齐，每个数都要两位小数： 

    5.60
  128.00
   42.45

三个数是 5.6、128.0、42.45。

提示：三行 printf，格式串一模一样，只有后面那个数不一样。 打完了数一下每行开头有几个空格，和上面那份对一下。

看答案

三行 printf，格式串一模一样，只有后面那个数换： 

#include <cstdio>

int main() {
    printf("%8.2f\n", 5.6);
    printf("%8.2f\n", 128.0);
    printf("%8.2f\n", 42.45);

    return 0;
}

数一下每行开头补了几个空格：128.00 占 6 格，补 2 个； 42.45 占 5 格，补 3 个；5.60 占 4 格，补 4 个。 每行连空格一起都是 8 格，所以小数点都落在同一竖排上。

这就是 %8.2f 的全部本事：数越宽，补的空格越少， 尾巴自然就对齐了。你不用去算每个数该补几个——8.2 帮你算。

练习 1-22

有一个 double pi = 3.14159265;，用 printf 打出这样一行： 

圆周率约等于 3.14

要求：3.14 必须是 pi 算出来的， 不许把 "3.14" 直接写进格式串里。

提示：想清楚 pi 那个坑该写 %d、%f 还是别的。

看答案

pi 是 double，所以坑要写 %f； 要两位小数，就在中间点上那个点： 

#include <cstdio>

int main() {
    double pi = 3.14159265;

    printf("圆周率约等于 %.2f\n", pi);

    return 0;
}

写成 %.2f，3.14159265 就变成 3.14—— 多余的部分四舍五入，不是砍掉。

想验证一下「四舍五入」到底怎么算：把 pi 改成 3.145， %.2f 打出 3.15——进位了。 再改成 3.135，打出来的却是 3.13，没进位。

这不是 printf 糊涂了。3.135 存进 double 的时候，就比 3.135 小那么一点点（1.2 讲过 0.1 + 0.2 那件事）—— 一个比 3.135 小的数，留两位小数当然进不上去。 你写的是十进制，盒子装的是二进制，那点误差就是从这儿冒出来的。

练习 1-23（找错）

有个人想把 19.9 打成两位小数，写了这两行。 结果第一行对了，第二行打出来一堆小数位。 

printf("%.2f\n", 19.9);
printf("%2f\n", 19.9);

先别看答案，说说这两行为什么不一样。 这个错编译的时候一声都不响，所以只能靠你眼睛。

看答案

这两行差别只有一个点，但那个点在的位置不一样，管的事就不一样： 

#include <cstdio>

int main() {
    printf("%.2f\n", 19.9);
    printf("%2f\n", 19.9);

    return 0;
}

跑起来是这样：

19.90
19.900000

%.2f 里的 .2 是小数点后留几位。 %2f 里没有点，那个 2 就被当成了宽度—— 也就是 1.6 讲的「至少占几格」。

而 19.900000 本来就比 2 格长得多， 「至少两格」这个要求它早就满足了。于是你写的 2 等于白写， 小数位回到 %f 默认的六位。

编译器不会提醒你

%2f 语法完全合法。编译一个警告都没有，程序跑起来也顺顺当当， 就是打出来的东西不是你要的。这种错最难查—— 没有任何东西告诉你错了，只能靠你自己盯着输出看。

所以养成习惯：写完 %.2f，回头看一眼那个点还在不在。

顺手记一下括号里的那件事：%2f 不是没用， 写成 %12f 就有用了——它会让这个数至少占 12 格。 只是「宽度」和「小数位」是两件事，别把它们挤在一个地方写。

练习 1-24

用 printf 打出这样两行： 

折扣 85%
应付 12.75 元

要求：第二行那个 12.75 要从一个 double price = 12.75; 打出来， 保留两位小数。第一行那个 % 是真的百分号。

提示：这题要用上这一课两个不同的 % 写法—— 一个是「打百分号」，一个是「留两位小数」。别搞混。

看答案

两个不同的 % 写法，各管各的： 

#include <cstdio>

int main() {
    printf("折扣 85%%\n");
    printf("应付 %.2f 元\n", 12.75);

    return 0;
}

第一行里 85%% 打出 85%—— 两个百分号，出一个。

第二行 %.2f 打的是那个 double。 写死 12.75 不行（题里要求从变量来）， 写 %f 也不行——那会打出 12.750000。

这题的两个符号挨得很近：%% 和 %.2f， 开头都是 %。分清楚的办法是看后面跟的是什么： 跟着另一个 %，就是打一个百分号； 跟着数字和 f，就是留几位小数。

你现在能写什么：能让数字长成你要的样子了——补几位、空几格、小数点在哪一列， 都是你说了算。第 1 部分到这儿结束。 下一部分开始让程序自己做判断、自己重复：那才是程序真正开始像程序的地方。
