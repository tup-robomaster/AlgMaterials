第 4 部分

一堆数据

前面三部分，一个盒子装一个数。要装十个，就开十个盒子——还得挨个起名字。 这一部分讲怎么把一堆数装进一排盒子里：怎么挨个走一遍， 怎么在里面挑出最大最小的那个，怎么把两个换位置。

4.1数组：一排盒子

这一课没有弯弯绕，就一件新东西：怎么一次开出很多盒子，还不用挨个起名字。

一个盒子装一个数，那如果是五个呢

先看一份你可能会写的程序。它装五个成绩，一个成绩一个盒子： 

#include <iostream>

int main() {
    int score1 = 90;
    int score2 = 85;
    int score3 = 77;
    int score4 = 60;
    int score5 = 95;

    std::cout << score1 << std::endl;
    std::cout << score2 << std::endl;
    std::cout << score3 << std::endl;
    std::cout << score4 << std::endl;
    std::cout << score5 << std::endl;

    return 0;
}

看着还行——五个而已。但你已经在第 3 部分见过这种写法要付什么代价了：

一是名字得挨个起。起五个还能忍，起五十个呢？而且 score1 到 score50，中间哪个是哪个，你自己过两天也记不住。

二是改一处，得改十处。想把每个成绩都加 5 分，你得写五十行； 想只打及格的，五十个 if。

三是真要命的那条：盒子的个数，你说不出来。 上面那份程序里，五个是你数出来的——因为你看着数据数了一遍。 要是这堆数是从键盘读进来的呢？读进来之前，你知道有几个吗？

不知道。所以照这个写法，程序根本没法写下去。

一排盒子，共用一个名字

换个写法： 

#include <iostream>

int main() {
    int score[5] = {90, 85, 77, 60, 95};

    std::cout << score[0] << std::endl;     // 第一个
    std::cout << score[2] << std::endl;     // 第三个

    score[2] = 88;                          // 把第三个改成 88

    std::cout << score[2] << std::endl;     // 再打一次，变了

    return 0;
}

跑出来是这样：

90
77
88

一个新东西都没多，就是多了两处方括号。但这一排盒子和刚才那五个， 有三个地方不一样：

一、它们共用一个名字。五个盒子都叫 score， 靠方括号里的数字区分。名字只起了一次。

二、方括号里的数字，是「第几个」。score[0] 是第一个， score[2] 是第三个。读和写都用它——score[2] = 88; 就是在往第三个盒子里放 88。

三、个数是你写的一个数字，不是抄出来的。int score[5] 那个 5 说的是「开五个」。这句话只有一处——后面想在数组上做什么， 写一遍循环就行，不用把同一件事抄五遍。下一课就讲那个循环。

这个新东西叫数组（array）。中文的「数组」和英文的 array， 你两个都得认得——报错信息里出现的是英文那个词。

方括号里写的是「几个」

有一处特别容易搞混，第一次写就会撞上： 

int score[5]

这个 5 是盒子的个数，不是「最大的编号」。 五个盒子，编号是 0、1、2、3、4——从 0 数到 4，正好五个。 所以最后一个盒子的编号是 4，不是 5。

为什么要从 0 开始数？这不是谁拍脑袋定的，是有原因的， 而且那个原因下一课就会讲——讲完你会觉得挺自然。 现在先记住这条规矩，以及它的后果：个数的数字，和最后一个编号， 永远差一个。五个盒子、编号到 4；十个盒子、编号到 9。

写完数组，先在心里数一遍

int a[5] 写下去的那一刻，就顺手把两个数字都念一遍： 「五个盒子，编号 0 到 4」。这件事念顺了，下一课那个循环的边界 就不用背——它自己就出来了。

还有一件小事：初始化的时候，大括号里的数是一个一个挨着放进去的， score[0] 拿第一个、score[1] 拿第二个， 一路排下去。所以写的时候数一遍位置，别放错了。

例题 · 一组成绩

五个成绩装在一排里，改其中一个、打其中一个： 

#include <iostream>

int main() {
    int score[5] = {90, 85, 77, 60, 95};

    std::cout << "第一个：" << score[0] << std::endl;
    std::cout << "第四个：" << score[3] << std::endl;

    score[3] = 66;

    std::cout << "改过之后：" << score[3] << std::endl;

    return 0;
}

跑出来：

第一个：90
第四个：60
改过之后：66

注意最后两行打的是同一个编号 score[3]，出来的数却不一样—— 因为中间那一行把它改过了。编号是门牌号，里面的东西会变。

还有：score[3] 是第四个盒子。写「第四个」这三个字的时候， 脑子里得自动减一——这跟你数楼层有点像，只是它从 0 层起。

那个 5 是上限，越过去会怎样

int score[5] 写下去的那一刻，就是给这一排钉死了五个格子。 那要是成绩有六个呢？先把第六个也塞进大括号里试试： 

#include <iostream>

int main() {
    int score[5] = {90, 85, 77, 60, 95, 88};

    std::cout << score[0] << std::endl;

    return 0;
}

编译器当场就拦住了，程序根本跑不起来： 

4.1-too-many-err.cpp: In function ‘int main()’:
4.1-too-many-err.cpp:4:43: error: too many initializers for ‘int [5]’
    4 |     int score[5] = {90, 85, 77, 60, 95, 88};
      |                                           ^

它指的第 4 行，就是多放了那个 88 的一行。尖号落在收尾的大括号上， 意思是「到这儿为止，已经装不下了」。报错里印出来的 [5]， 就是你写的那个 5，它原样还回来了。

编译器为什么数得出来？因为这两边都是写死的：格子的个数写在方括号里， 数的个数写在大括号里，它一眼就能比出来。这也是它唯一管得住的情形。

那要是运行的时候才想塞呢？比如那个成绩是算出来的，你写代码的时候还不知道 它是几。这时候就不是「大括号里放不下」了，是「往第六个格子里放」： 

#include <iostream>

int main() {
    int score[5] = {90, 85, 77, 60, 95};

    score[5] = 88;                    // 想塞第六个

    std::cout << "第一个 " << score[0] << std::endl;

    return 0;
}

这一份编译干净，一个警告都没有。跑起来也正常收场，退出码 0， 屏幕上什么异常都没有： 

第一个 90

什么都没发生——这才是它最坏的地方。没有报错、没有崩溃、没有奇怪的数字。 score[5] 那块地方根本不属于这个数组，它是内存里紧挨着的 另一块地方；你往那儿写了个 88，然后就没有然后了。 你从任何地方都看不出来刚才那一行干了件不该干的事。

它也可以当场把程序弄死

同一件事，往下再多写一格，结果就完全不同。在上面那份里加一行： 

    score[5] = 88;
    score[6] = 99;                    // 只多了这一行

它照样编译干净。跑起来先把 第一个 90 打出来，然后终端上多一行： 

*** stack smashing detected ***: terminated

程序自己被中止了，退出码 134。多写的那一格压到了编译器放在栈上的 一个哨兵，程序收尾的时候发现了，就把自己结束了。 （终端多半还会跟一句「已中止（核心已转储）」。）

同一件事，一个悄无声息，一个当场毙命。哪一次碰上哪种，事先不知道—— 跟你写在第几格、编译器怎么排的内存都有关系。

所以这一节要记住的就一句：int score[5] 里的 5 是「最多五个」， 不是「建议五个」。这个上限是死的。大括号里写多了编译器会拦， 运行的时候塞多了它不管——而真正写代码时，第二种才是常事。

上面这件事有个正式名字，它为什么会这样、写循环的时候怎么绕开， 下一课整节都在讲这些。

练习 4-1

声明一个装 5 个整数的数组，一开始就放上 3 1 4 1 5， 然后把第 1 个和第 5 个打出来。

练习 4-3

声明一个装 3 个 double 的数组，放三个身高： 1.75、1.62、1.80。 把中间那个改成 1.68，然后把三个都打出来。 

1.75
1.68
1.8

提示：最后一行为什么是 1.8 而不是 1.80—— 1.4 见过这件事。

看答案

三个 double，中间那个改掉：

#include <iostream>

int main() {
    double h[3] = {1.75, 1.62, 1.80};

    h[1] = 1.68;

    std::cout << h[0] << std::endl;
    std::cout << h[1] << std::endl;

最后一行出来是 1.8，不是 1.80—— cout 默认不管末尾那个 0，1.4 见过这件事。 它是同一个数，只是打出来的样子不同。要 1.80 那个样子得请 1.6 的 printf 出马。

4.2遍历数组，和下标越界

这一课做两件事：把数组和循环接上，然后讲一个编译器不会提醒你的坑。 第二件事更重要——它花的时间会更多。

用循环挨个走一遍

4.1 那份程序里，五个 std::cout 只有一个字不一样。 第 2 部分讲过这种场面怎么处理：把不一样的那个字，变成循环变量。 

#include <iostream>

int main() {
    int score[5] = {90, 85, 77, 60, 95};

    for (int i = 0; i < 5; i++) {
        std::cout << score[i] << std::endl;
    }

    return 0;
}

跑出来就是五个成绩，一个一行：

90
85
77
60
95

把方括号里的数字换成 i，这件事就完了。 i 从 0 走到 4，正好把五个合法编号走了一遍——一个不多，一个不少。

这种「挨个把每个元素都碰一次」的动作有个名字，叫遍历（traverse）。 后面所有在数组上做的事，几乎都是从它开始的：求和是遍历着加， 找最大是遍历着比，打印是遍历着打。

再看一遍那个条件：i < 5。是小于号，不是小于等于。 为什么？因为编号只到 4。i <= 5 会让 i 走到 5—— 而 5 不是一个合法的编号。这一课后半截全在讲这件事。

遍历搭上 2.3 那个攒总和的盒子，就能求和了： 

#include <iostream>

int main() {
    int score[5] = {90, 85, 77, 60, 95};

    int sum = 0;

    for (int i = 0; i < 5; i++) {
        sum = sum + score[i];
    }

    std::cout << sum << std::endl;

    return 0;
}
407

和 2.3 那道 1 加到 100 是一个套路，只有一处不一样： 加进来的东西，从「循环变量」换成了「数组里第 i 个」。

注意 sum 开在循环外面，i 开在循环头上。 2.5 讲过这个规矩：每一圈都得留着的东西开在外面，一圈用完就扔的 开在里面。sum 是前者，i 是后者。

跟着动画走一遍

遍历这件事，眼睛看着比读文字快。下面是那五个盒子， 点「下一步」，看 i 怎么一个个走过去：

看两件事：

一、i 是编号，不是内容。i 走到 3 的时候， 取出来的是 score[3]，也就是 60。这两个数没有任何关系—— i 是「第几个」，score[i] 是「那个盒子里装的」。

二、最后一个合法编号是 4。走完 4，循环就该停。 再多走一步，取的就是 score[5]——那已经是盒子外面了。 动画最后那一步专门停在那儿给你看。

下标是「离开头第几个」

现在回答 4.1 欠下的那个问题：编号为什么从 0 开始数？

因为方括号里那个数字，本来就不是「第几个」，而是 「离开头有多远」。它有个名字，叫下标（index）， 但它的意思更接近偏移量（offset）： 

score[0]  →  离第一个盒子 0 个
score[1]  →  往右挪 1 个
score[2]  →  往右挪 2 个
score[4]  →  往右挪 4 个

第一个盒子就在开头，所以它「离开头」0 个。这就是 0 的来历。

换个说法你可能更熟：就像尺子。你要量一段长度，尺子的 0 刻度 在起点上，不是 1 刻度。score[3] 就是「从起点往右挪 3 格」 的那个盒子。

这么理解有个好处：「合法的下标到哪儿为止」这件事一下就清楚了。 五个盒子占的是 0、1、2、3、4 这五个位置。 「往右挪 5 格」是什么？那是第 6 个位置——这个数组里没有那个位置。

走出去了，编译器一声不吭

那么，真让 i 走到 5，会发生什么？看这份： 

#include <iostream>

int main() {
    int score[5] = {90, 85, 77, 60, 95};

    int i = 5;                          // 循环多转了一圈，i 就到了 5

    std::cout << score[i] << std::endl;

    return 0;
}

编译干净，一个警告都没有。跑起来正常结束，退出码 0。 屏幕上打出来一个数——一个不该存在的数。

这个数是什么？不知道。 我连跑了五遍，五次都不一样： 

30918
32229
30001
30410
32155

这不是随机数。那是因为 score[5] 这块地方根本不属于这个数组—— 它是内存里紧挨着的另一块地方，当时恰好放着什么，就打出来什么。 跟你之前跑过什么、系统忙不忙，都有关系。

这种事有个名字，叫下标越界（out of bounds）： 下标走到了数组的合法范围之外。也可以叫「数组越界」「越界访问」， 说的都是同一件事。

越界最坏的地方：它不一定崩

你可能会想：「出个怪数而已，我看见就知道错了。」

问题在于，它也可以什么都不输出就崩掉，或者输出个看着挺正常的数， 或者把你另一个变量的值悄悄改掉。这三种结果都可能出现， 而且同一个程序换台机器、换个编译选项，就从一种变成另一种。

「跑出来了」不等于「对了」。这一课要你记住的就是这句。

再看一眼上面那份程序：真正吓人的是编译器什么都没说。 少了分号它有话说，类型对不上它有话说，函数参数不够它也有话说—— 可下标越界，它一声不吭。

为什么不说？因为 score[i] 里的 i 是个变量。 写代码的时候，编译器不知道 i 会是几——它只知道 「运行到那一行的时候，i 里装着一个数」。等它真知道的时候， 程序已经在跑了。

有一处例外，但别指望它

编译器确实偶尔会开口，只是条件不成规律。我拿四种写法各试了一遍， 都带 -Wall： 

                     不加优化选项  加 -O2
读 下标写死          一声不吭      警告
写 下标写死          一声不吭      一声不吭
读 循环里走到 5      一声不吭      一声不吭
写 循环里走到 5      一声不吭      警告

看出来了吗——它开口的时机基本是反的：下标写死的时候， 它管「读」不管「写」；换成循环，又变成管「写」不管「读」。

这里头没有一条能背下来的规则。它开不开口，取决于它当时算不算得出 那个下标、正在做什么优化——这两样你都控制不了。所以「编译器没说话」 不能当成「这段代码没问题」的证据。

你在 0.1 学的编译命令不带优化选项（那正是平时该用的）， 上面这四行，你一行都不会见着它吭声。

真正靠谱的办法只有一条：写完循环，自己把边界想一遍。 下一段就讲怎么想。

最后看一遍那个错是怎么长出来的。下面这份程序想打印五个成绩， 却多打了一行： 

    for (int i = 0; i <= 5; i++) {
        std::cout << score[i] << std::endl;
    }

i <= 5 里的等号，就是那个越界的入口。跟 2.3 那道 「少打了一个 5」是同一个位置上的错——只是那一回少打了一个数， 这一回多打了一个不存在的数。哪一种更坏，你现在知道了。

写完循环，把最后一圈单独想一遍

2.3 说过一次，这里再说一次，因为它现在变得更重要了：

不要背「小于还是小于等于」，去问自己两句话——

「最后一圈，i 是几？」「我想让它走到几？」

五个盒子、编号 0 到 4，你想让每个盒子都被碰到一次， 那最后一圈 i 得是 4。条件是 i < 5—— 它在 i 变成 5 的时候停，正好。

往外面写：看着全对

上面那个错落在「读」的那一边——屏幕上好歹多蹦出来一个怪数，算个线索。 把同一个错挪到「写」的那一边，连这点线索都没了。

任务很简单：给五个盒子依次填上 60 到 64。 很自然会写成这样： 

#include <iostream>

int main() {
    int score[5] = {0, 0, 0, 0, 0};

    for (int i = 0; i <= 5; i++) {      // 五个盒子，编号到 5 为止
        score[i] = 60 + i;
    }

    for (int i = 0; i < 5; i++) {
        std::cout << score[i] << std::endl;
    }

    return 0;
}

那句注释就是 <= 的来路：把「五个」当成了「编号到五」。 4.1 里量过，五个盒子的合法编号只到 4。

这份程序编译干净，一个警告都没有，退出码 0，屏幕上打出来： 

60
61
62
63
64

五个数，一个不多一个不少，每个都对。 这是这一课里我看着最正常的一份程序。 可它跟上面那份读越界，犯的是同一个错：最后一圈 i 是 5， 这一圈里执行的其实是 score[5] = 65;—— 往数组外面那一格，写了个 65。

上面读越界那份，那个怪数好歹还打在屏幕上给你看； 这一次写进去的 65，屏幕上你一个地方都找不着它。 它照样编译、照样跑完、照样打印正确结果——你不盯着循环条件看， 就永远不会知道它发生过。4.1 里手写 score[5] = 88; 是这种错， 这回是循环把下标算出去的，同一种。

那 65 写哪儿去了

写在 score 后面那一格上。那块内存不属于这个数组， 在程序里是给别人用的——可能是另一个变量，可能是别的东西。你没法预知。

我试着在数组后面再开一个盒子： 

int score[5] = {0, 0, 0, 0, 0};
int total = 1000;                   // 开在数组后面

    score[i] = 60 + i;
}

std::cout << "total = " << total << std::endl;

打出来还是 total = 1000，没被改坏。但这是碰巧，不是保证。 编译器把哪个变量放在哪块地方是它自己定的；变量多一个少一个、 前后换个顺序、换个编译器，结果就可能是另一个样子。

再往外多写一格，程序还会当场死掉。把上面那个 5 改成 6： 

    for (int i = 0; i <= 6; i++) {      // 只改了这一个数字

它照样编译干净，照样先把五个数打得整整齐齐，然后才多出来一行： 

*** stack smashing detected ***: terminated

退出码 134。跟 4.1 那份一样，是压到了编译器放在栈上的哨兵， 程序收尾的时候自己发现的。（终端后面多半还会跟一句「已中止（核心转储）」。）

但别记成「越界会崩」——上面两份都没崩，只有这一份崩了。 差别只在写到了第几格、编译器在那块地方放了什么。

上面这两份都在 示例代码/ 文件夹里，想自己跑就跑。

所以同一件越界的事，你这一课见过三种样子：读出去蹦个怪数（本节开头）、 写出去什么痕迹都没有（刚才这份）、写出去当场崩掉（那个框里）。 三种都可能出现，事先挑不了。

上面那个办法在这儿照样管用，而且现在更要紧了——填进去的那一圈， 也得数进「最后一圈」里：「最后一圈 i 是几？」 「我想让它写到第几个盒子？」五个盒子想全填上，最后一圈 i 得是 4， 条件就是 i < 5，跟读的那份一模一样。

例题 · 数一数有几个不及格

遍历、判断、计数，三样凑一块儿： 

#include <iostream>

    int fail = 0;

    for (int i = 0; i < 6; i++) {
        if (score[i] < 60) {
            std::cout << "第 " << i << " 个不及格：" << score[i] << std::endl;
            fail = fail + 1;
        }
    }

    std::cout << "一共 " << fail << " 个" << std::endl;

    return 0;
}
第 1 个不及格：55
第 3 个不及格：48
一共 2 个

那个记数的盒子 fail 开在循环外面——理由和 sum 一样，每一圈都得留着。开在里面的话，盒子的命跟着大括号走（3.3 那条）， 循环外面那句 std::cout 根本编译不过； 就算把它挪进循环里打印，每一圈都从 0 重新开始，永远只会是 1。

4.3在数组里找最大 / 最小值

遍历是「每个都碰一次」。这一课在碰的时候顺手做个判断：谁最大？

摆一个擂台

这件事照着打擂台想最省事：台子上站一个，剩下的挨个上来打， 赢了就留在台上，输了就下去。全打完，台上站着的就是最能打的。

翻成代码，就是「开一个盒子记着目前最大的，遍历一遍，见一个比一个」： 

#include <iostream>

int main() {
    int score[5] = {90, 85, 77, 60, 95};

    int maxScore = score[0];

    for (int i = 1; i < 5; i++) {
        if (score[i] > maxScore) {
            maxScore = score[i];
        }
    }

    std::cout << maxScore << std::endl;

    return 0;
}
95

这个骨架跟 4.2 那个求总和长得很像——都是「开个盒子在外面，遍历着往里塞」。 只有两处不一样：

一、这次不是「加」，是「比」。总和是把每个都收进来； 最大值是挑，多数时候那个 if 是不进去的。

二、循环从 i = 1 起，不是从 0。因为第 0 个已经在台上了。 让它再上来跟自己打一场，score[0] > score[0] 永远是假， 白转一圈。写成 i = 0 也不会错，但那是没想清楚。

擂主一开始是谁

上面那行 int maxScore = score[0]; 里，有一点特别值得盯着看： 台子上第一个人，是从数组里请的。

不这么写的人，十个里有八个会写成这样： 

int maxScore = 0;

理由听着也顺：「最大的数肯定比 0 大嘛，从 0 开始往上找。」 先看它跑出来什么。下面这份数组里的五个数全是负的： 

#include <iostream>

int main() {
    int score[5] = {-90, -85, -77, -60, -95};

    int maxScore = 0;

    for (int i = 0; i < 5; i++) {
        if (score[i] > maxScore) {
            maxScore = score[i];
        }
    }

    std::cout << maxScore << std::endl;

    return 0;
}
0

打出来一个 0。可这个数组里一个 0 都没有。

编译干净，跑起来正常。它甚至算不上「算错了」—— 0 一上台就再也没下来过：数组里全是负数，没有谁比 0 大， 那个 if 一次都没进去，台上站到最后的还是那个 0。

病根不在哪个符号写反了，在于候选人名单里混进了一个没参赛的人。 程序老老实实回答了「谁是最大的」，只是它把 0 也当成了选手。

台子上第一个人，一定得从数组里请

int maxScore = score[0]; 的意思是 「先假定第 0 个就是最大的」。它一定是数组里的一个元素， 所以不管数组里装的是什么，它都有资格站在台上。

int maxScore = 0; 的意思是「先假定 0 是最大的」。 0 是不是这个数组里的元素？看运气。

找最小值同理：int minScore = score[0];， 不能写成 0——那样一份全是正数的数组会打出个 0 来。

「那要是数组里一个元素都没有呢？」

int score[5] 开出来就是五个，空不了，所以这句话现在不用操心。 以后 4.6 那个 vector 是真的可以空的—— 空的时候这一句会出问题，到时候再说，这里先留个记号。

要的是位置，不是值

上面那个程序回答的是「最大的是几」。可很多时候你要的不是几， 是第几个——比如 4.5 那道题要拿它去跟最后一个元素交换， 交换得知道位置。

改法很小：台子上记的不再是分数，是编号。 

#include <iostream>

int main() {
    int score[5] = {90, 85, 77, 60, 95};

    int maxIdx = 0;

    for (int i = 1; i < 5; i++) {
        if (score[i] > score[maxIdx]) {
            maxIdx = i;
        }
    }

    std::cout << "最大的在第 " << maxIdx << " 个：" << score[maxIdx] << std::endl;

    return 0;
}
最大的在第 4 个：95

看清那个 if 里的两半：拿分数比，记的是编号。 

if (score[i] > score[maxIdx]) {   // 比的是分数：第 i 个 比 台上那个大吗
    maxIdx = i;                    // 记的是编号：把台上的编号换成 i
}

台子上站的还是「目前最大的那个」，只不过现在它不是那个数本身， 而是那个数的门牌号——score[maxIdx] 才取到分数。

这一手先记住，4.5 就得靠它。名字里的 Idx 是英文 index 的缩写，以后看别人的代码，Idx 结尾的变量基本都是干这个的。

例题 · 找最小的，并说出它在第几个

把上一个程序的 > 换成 <，就是找最小的： 

#include <iostream>

int main() {
    int a[6] = {7, 3, 9, 3, 8, 4};

    int minIdx = 0;

    for (int i = 1; i < 6; i++) {
        if (a[i] < a[minIdx]) {
            minIdx = i;
        }
    }

    std::cout << "最小的是 " << a[minIdx] << "，在第 " << minIdx << " 个" << std::endl;

    return 0;

最小的是 3，在第 1 个

慢着——这个数组里有两个 3，第 1 个和第 3 个。为什么报的是第 1 个？

因为条件是严格的小于号：第 3 个那个 3 不比台上的 3 更小， 所以它上不去，台上的第 1 个 3 站住了。

把 < 改成 <=，答案就变成第 3 个—— 相等的时候也让挑战者上来，最后占台的就是后来那个。

两个都对。题目没说的话，你自己先定下来是哪一个， 然后保证整份程序里都按这个来。

「并列的时候要哪个」是个真问题

这不是抠字眼。两个 95 分一样高的时候，「最大的在第 1 个」和 「最大的在第 4 个」就是两个不同的答案。要拿它去交换，结果更是两样。

4.4交换两个元素

这一课只干一件事：把两个盒子里的数对调。 就这么点事，但它是 4.5 那道综合练习的一半，而且 第一次写的人几乎都会写错——还错得很不显眼。

直接互相赋值会怎样

两个盒子装 1 和 2，想让它们变成 2 和 1。最直白的写法： 

#include <iostream>

int main() {
    int a[2] = {1, 2};

    a[0] = a[1];
    a[1] = a[0];

    std::cout << a[0] << " " << a[1] << std::endl;

    return 0;
}

「把第 1 个的抄进第 0 个，再把第 0 个的抄回第 1 个」——听着挺对。 跑出来是： 

2 2

两个都成了 2。不是 2 1。

而且这份程序一点都不像错的：两行赋值都执行了，一行没漏； 编译干净，一个警告都没有；跑起来正常结束。

盯着第一行看： 

a[0] = a[1];   // 这一行执行完，a[0] 里那个 1 就已经没了

a[0] = a[1]; 干的事是「把 a[1] 里的东西抄一份，盖在 a[0] 上」。 盖上去之后，a[0] 里原来装的 1 就不在了—— 它没被搬到哪儿去，它是被盖掉的。

第二行再去拿 a[0]，拿到的是刚写下去的 2， 于是把 2 又抄给了 a[1]。白抄一趟。

你以为你在做「1 和 2 换个位置」。 程序在做的是「把 2 复制一份到左边，再把自己复制回去」。

跟着动画走一遍

上面这段文字，用眼睛走一遍会清楚得多——特别是 1 消失的那一步：

特别注意写 a[0] 的那一步：1 是在这一步没的， 就在 2 被盖上去的那一瞬间。它不是被搬走了，是被盖住了。

所以问题的根子是：盖之前，得先给 1 找个地方待着。

第三个盒子

多开一个盒子，先把要盖掉的那个存进去： 

#include <iostream>

int main() {
    int a[2] = {1, 2};

    int t = a[0];
    a[0] = a[1];
    a[1] = t;

    std::cout << a[0] << " " << a[1] << std::endl;

    return 0;
}
2 1

换过来了。就多了一行 int t = a[0];。

这三行顺序不能换，念一遍就明白为什么： 

int t = a[0];   // 先把 1 存进 t —— 留个底
a[0] = a[1];    // 再把 2 搬进 a[0] —— 这时候 1 没了，但 t 里有
a[1] = t;       // 最后把 t 里那个 1 倒进 a[1]

先存、再搬、最后倒回来。换任何一步的顺序， 就又变回上面那份 2 2 了。

这个 t 是英文 temporary（临时的）的首字母。 临时用一下就扔的盒子，习惯上都叫这个名字。

这三行你见过

3.5 那个 swapTwo 函数，肚子里装的就是这三行： 

void swapTwo(int& x, int& y) {
    int t = x;
    x = y;
    y = t;
}

一模一样。当时它交换的是两个普通变量，现在交换的是两个数组元素—— 函数体一个字都不用改。这也是练习 4-13 要你做的事。

真的「搬走」了吗？

没有。上面说的「搬」「存」「倒」，说的都是复制： 把一份内容抄到另一个盒子里，原来那份被盖掉。 C++ 里 = 永远是复制，从来没有「搬走」这回事。

（先记住这句话，第 6 部分讲指针的时候它还会回来。）

例题 · 把第一个和最后一个换过来

跟刚才是一模一样的事，只是编号从 0、1 换成了 0、4： 

#include <iostream>

int main() {
    int a[5] = {10, 20, 30, 40, 50};

    int t = a[0];
    a[0] = a[4];
    a[4] = t;

    std::cout << a[0];
    for (int i = 1; i < 5; i++) {
        std::cout << " " << a[i];
    }
    std::cout << std::endl;

    return 0;
}
50 20 30 40 10

三个地方值得看一眼。

一、a[4] 是最后一个。五个元素，编号 0 到 4， 最后一个就是 4。a[5] 不是最后一个，是越界。

二、中间那三个没动。20、30、40 打的还是原来的位置， 谁也没碰它们。交换只动两个盒子。

三、那个打印的循环。它先单独打了 a[0]，再从 i = 1 起打「空格 + 元素」。绕这一下，是为了 保证最后没有多余的空格——上面那串 50 20 30 40 10， 末尾干干净净。

为什么非要绕这一下

要是顺手写成 std::cout << a[i] << " ";， 打出来末尾会多一个空格。人眼看不出差别，但 拿输出跟标准答案对的时候，它是错的—— 很多判题的地方就是一个字符一个字符地比，差一个空格也算差。

这是「输出一整串数」的固定写法，后面还会用： 先单打第一个，再从第二个起每个前面补一个空格。

练习

练习 4-11

数组 {10, 20, 30, 40, 50}，把第 2 个和第 4 个交换， 然后把五个数打出来（按上面那个不带多余空格的写法）。 

10 40 30 20 50

提示：「第 2 个」的编号是 1，「第 4 个」的编号是 3。 先把编号想清楚再动手，这一题错基本都错在这儿。

看答案

先把编号定下来：第 2 个是 a[1]，第 4 个是 a[3]。

#include <iostream>

int main() {
    int a[5] = {10, 20, 30, 40, 50};

    int t = a[1];
    a[1] = a[3];
    a[3] = t;

交换那三行跟 4.4 一模一样，只是把 0、1 换成了 1、3。这种题错基本都错在编号上—— 动手之前在草稿上标一句「第 2 个 = 1」，比什么都管用。

打印用的是 4.4 例题那个写法：先单打 a[0]， 再从 1 起每个前面补一个空格。末尾干干净净，不带尾巴。

练习 4-12（找错）

下面这份程序想把 1 和 2 换过来，跑出来却是 2 2。 找出问题，改对。 

#include <iostream>

int main() {

改对之后，输出应该是：

2 1

提示：不是把哪一行删掉，是要加一行。

看答案

不是删，是加一行——加在两句赋值的前面：

#include <iostream>

int main() {
    int a[2] = {1, 2};

    int t = a[0];
    a[0] = a[1];
    a[1] = t;

    std::cout << a[0] << " " << a[1] << std::endl;

    return 0;
}

a[0] = a[1]; 一执行，a[0] 里原来那个 1 就被盖掉了。所以盖之前得先把它存进一个临时盒子—— 这就是那三行的第一行。

这三行顺序不能换：先存、再搬、最后倒回来。 把 int t = a[0]; 挪到中间或者末尾，跑出来就又是 2 2。

练习 4-13

把 3.5 那个 swapTwo（带 & 的那一版） 写到程序最上面，然后在 main 里用它交换数组的两个元素。

数组 {1, 2, 3, 4, 5}，交换第一个和最后一个， 打出来。 

5 2 3 4 1

提示：swapTwo(a[0], a[4])——把数组元素当普通变量传进去就行。 函数体一个字都不用改，3.5 写的那三行原样搬过来。

写完之后看一眼：这一题用函数比直接写三行更短了吗？ 没有。那函数的好处是什么？（3.1 讲过一条——想不起来就回去翻一眼。）

看答案

函数体原样搬 3.5 那三行，调用的时候把两个数组元素传进去：

#include <iostream>

void swapTwo(int& x, int& y) {
    int t = x;
    x = y;
    y = t;
}

int main() {
    int a[5] = {1, 2, 3, 4, 5};

    swapTwo(a[0], a[4]);

    std::cout << a[0];
    for (int i = 1; i < 5; i++) {
        std::cout << " " << a[i];
    }
    std::cout << std::endl;

    return 0;
}

参数上的 & 是关键。没有它，函数里换的是两个副本， 外面的 a[0]、a[4] 一动不动—— 3.4 讲的就是这件事（同一个 swapTwo，加不加 & 差出一个 1 2 和 2 1）。

再说那个问题：这一题用函数没有让程序变短， 直接写那三行还省得往上翻。那好处是什么？

3.1 给过一条：能单独跑，能单独看。这里还多一条—— 名字。swapTwo(a[0], a[4]) 一读就知道在干什么； 三行裸赋值，读的人得停下来想一遍才敢确定是谁换谁。 写得短是顺手的事，写得一眼能看懂才是目的。

4.5【综合练习二】找最小值并和最后一个交换

第 4 部分到这儿收尾。这一课把前三课凑一块儿：遍历、找最小值、交换。

先说一句：这三件事你已经分别会了。这一课的难点不在写代码， 在读题——题目第一句里藏着一个东西，第一遍读十有八九会看漏。

题目

综合练习二 · 找最小值并和最后一个交换

输入一串整数。开头的第一个数是这串数的个数， 后面跟着的就是那串数本身。

把其中最小的那个找出来，和最后一个数交换位置， 然后交换前后各打一行，数之间用一个空格隔开。

最后这条，题目的原话是 「最终分别打印输出交换前后的数组」。少打一行就少一半。

样例输入：

5 4 9 1 7 3

样例输出（第一行是交换前，第二行是交换后）：

4 9 1 7 3
4 9 3 7 1

题目就这些字。跟 2.6 那道一样，它不告诉你用什么写—— 可这一回卡人的地方不是语法，是第一句话。

先把样例看明白。5 4 9 1 7 3 是六个数字， 但它们不是六个数据： 

5  →  这串数有几个。它是个计数，不是数据。
4 9 1 7 3  →  真正的数据，一共五个。

这里面最小的是 1。把它和末尾那个 3 对调：

4 9 1 7 3     →     4 9 3 7 1

4 9 3 7 1，就是样例输出的第二行。 第一行 4 9 1 7 3 是交换前的原样—— 这两行，就是交换这件事的前后两张照片。

题目里那个「第一个数是长度」

现在看一份很常见的写法。它的思路是：拿到 5 4 9 1 7 3， 一眼看过去是六个数，那就照着六写个循环。 

#include <iostream>

int main() {
    int a[100];

    for (int i = 0; i < 6; i++) {
        std::cin >> a[i];
    }

    int minIdx = 0;
    for (int i = 1; i < 6; i++) {
        if (a[i] < a[minIdx]) {
            minIdx = i;
        }
    }

    // 交换前
    std::cout << a[0];
    for (int i = 1; i < 6; i++) {
        std::cout << " " << a[i];
    }
    std::cout << std::endl;

    int t = a[minIdx];
    a[minIdx] = a[5];
    a[5] = t;

    // 交换后
    std::cout << a[0];
    for (int i = 1; i < 6; i++) {
        std::cout << " " << a[i];
    }
    std::cout << std::endl;

    return 0;
}
5 4 9 1 7 3
5 4 9 3 7 1

编译干净，跑起来正常，打出来也是两排数。看着挺像回事—— 可它是错的。

把它和样例输出摆一起，一眼就看出来了： 

样例输出：  4 9 1 7 3   /   4 9 3 7 1
这份输出：  5 4 9 1 7 3 /   5 4 9 3 7 1

正好在开头多贴了一个 5。那个 5 从头到尾坐在第一个格子里 没动过——因为它本来就不是参赛选手，它是个计数。

病根不在那个写死的 6，在 「数出来的个数」这件事本身：

拿到样例的时候，你数了一眼，六个数，写了个 6。 换一组输入呢？个数就变了，而你写死的那个 6 不会跟着变。 数据少一个就少读一个，多一个就装不下。

题目把个数摆在开头，就是让你别去数——让程序去读。

读走它只要一句话： 

int n;
std::cin >> n;         // 第一个数是长度

读进来之后放在 n 里，后面所有要写「几个」的地方都写 n。 换多少组输入都对。

「我数一遍不就行了」

数一遍，对样例来说没问题。问题是你交上去的程序面对的不是样例， 是别人准备好的、你没见过的输入——你可能根本不知道它有几个数。

凡是题目把「个数」写进输入里的，都是在说同一句话： 别写死，读出来。以后见到这种题目，第一件事就是把那个数读进 一个变量。

拆开看，就三件事

剩下的都是你已经会的。整道题拆开： 

第一件：把数读进来     —— 先读走 n，再读 n 个数
第二件：找出最小的是第几个 —— 4.3 那个记编号的写法
第三件：把它和最后一个对调 —— 4.4 那三行

第二件为什么要记编号而不是值？因为第三件要交换， 交换得知道位置。这就是 4.3 那一小节存在的理由。

「最后一个」的编号是 n - 1——个数减一， 这条规矩从 4.1 讲到现在了。

正解

#include <iostream>

int main() {
    int a[100];
    int n;

    std::cin >> n;                      // 第一个数是长度

    for (int i = 0; i < n; i++) {
        std::cin >> a[i];
    }

    int minIdx = 0;
    for (int i = 1; i < n; i++) {
        if (a[i] < a[minIdx]) {
            minIdx = i;
        }
    }

    // 交换前
    std::cout << a[0];
    for (int i = 1; i < n; i++) {
        std::cout << " " << a[i];
    }
    std::cout << std::endl;

    int t = a[minIdx];
    a[minIdx] = a[n - 1];
    a[n - 1] = t;

    // 交换后
    std::cout << a[0];
    for (int i = 1; i < n; i++) {
        std::cout << " " << a[i];
    }
    std::cout << std::endl;

    return 0;
}
4 9 1 7 3
4 9 3 7 1

对着题目数一遍，三件事都在里面，一件不多一件不少。

把 n 那几处单独拎出来看——i < n、 a[n - 1]——全部都是 n， 一个写死的数字都没有。这就是那一句话的差别： 「数出来的 6」和「读出来的 n」。

再确认一件小事：假如最小值本来就在最后一个位置上呢？ 那这三行是 

int t = a[n - 1];
a[n - 1] = a[n - 1];
a[n - 1] = t;

自己跟自己换，换完还是原样。答案照样是对的， 不需要为这种情况单独写一个 if。 （4.4 那个三行交换法在这里又省了一件事。）

打印还是 4.4 那个写法：先单打 a[0]，再从 1 起每个前面补空格。 题目要求「用一个空格隔开」，末尾多一个空格就不是一个空格隔开了。

这一段一共出现了两次，一模一样：一次在交换那三行之前， 一次在之后。这就是题目里那句「分别打印输出交换前后的数组」。

两次打印之间只隔着三行交换，别的什么都没有——数组被改动的只有 交换那一瞬间，所以第一行是原样、第二行是换完的样子。

这两行为什么值得占一个框

很多人写完交换就直接打，只打一行。自己跑一遍觉得没问题， 因为那一行确实是「答案」。

可题目要的是两份：它想看的是你真的交换了， 而不是「凑出了最后那串数」。只打一行， 批改的人没法判断中间那步你到底做了没有。

这也是最容易白忙一场的地方——逻辑全对，输出少一半。 所以从现在起养成习惯：题目里凡是出现「分别」「前后」 「各自」这种词的，先在纸上数清楚要打几行，再动手写。

这道题里唯一一处将就

int a[100];——这个 100 是猜的。

题目没说 n 最大是多少，而 n 是从输入里来的， 写代码的时候根本不知道。所以只能挑一个「应该够大」的数写上。

下一课把这个将就解决掉。

写这道题，按这个顺序

一、先把样例抄下来，在纸上手算一遍（就是上面那个 4 9 1 7 3 → 4 9 3 7 1）。 算出正确结果再动手，不然写完对着一个错答案也不知道错在哪。

二、把三件事分开写，写完一件跑一次。先只读入、把读到的打出来看对不对； 对了再加找最小；再加交换。

三、最后才管打印格式。先能打出 4 9 3 7 1， 再纠结那两个空格。打两行这件事一开始就分两个位置写—— 中间夹着交换那三行，不要等逻辑全写完了再回头补。

练习

4.6vector：会自己变长的数组

上一课那句 int a[100];，写的时候你可能犹豫了一下。 这一课把它解决掉，顺便把 1.5 欠下的一个问题还上。

4.5 里那个「将就」

把那一行单独拎出来看： 

int a[100];

100 是哪儿来的？猜的。

题目只说「第一个数是这串数的个数」，没说这个个数最大是多少。 80？100？1000？你不知道，写代码的时候也不可能知道—— 它是从输入里来的，得等程序跑起来才有。

所以只能挑一个「应该够大」的数写上去。这就叫将就，而它两头都不舒服：

写小了，测试数据一大，后面几个数就装不进去，越界。 而且像 4.2 讲的那样，它不一定崩——可能安安静静地算出一个错答案。

写大了，程序占着一大块根本用不上的地方。开 int a[1000000]; 就是四兆内存，为一个可能只有五个数的输入。

这一课要的东西就是：要几个开几个。不用猜，也不用将就。

说加就加

它叫 vector。开的时候一个字都不用说「几个」： 

#include <iostream>
#include <vector>

int main() {
    std::vector<int> v;                 // 一个都还没有

    v.push_back(90);                    // 塞进来一个，现在有 1 个
    v.push_back(85);                    // 2 个
    v.push_back(77);                    // 3 个

    std::cout << v.size() << std::endl; // 几个？问它
    std::cout << v[0] << std::endl;
    std::cout << v[2] << std::endl;

    v[2] = 88;                          // 改一个，和数组一样
    std::cout << v[2] << std::endl;

    for (int i = 0; i < int(v.size()); i++) {
        std::cout << v[i] << std::endl;
    }

四处新东西，一个一个说。

一、#include <vector>。 vector 不是语言自带的，它是一个「现成的工具」。要用就得在文件顶上写这一行。 <iostream> 是「我要打字」，这个是「我要用 vector」。

二、std::vector<int> v;。 念作「一个装 int 的 vector，叫 v」。尖括号里写的是它装什么—— 要装小数就写 <double>，要装字符就写 <char>。 注意：这一行里从头到尾没有「几个」。

三、v.push_back(90);。 「往里加一个 90」。push 是推，back 是后面，合起来就是「从后面塞进去」。 这就是它跟数组最大的区别：数组开出来就那么大，vector 是塞一个长一个。

四、下标访问一模一样。v[0] 是第一个， v[2] 是第三个，v[2] = 88; 也照样能改。

所以前面四课学的那一套——遍历、找最大最小、交换—— 一个都不用重学。把方括号前面的名字从数组换成 v，就完了。 它其实是「数组，加上会长」。

1.5 欠你的那个答案

1.5 里说过：std::string 放多少字就自己变多大， 不像 int 那样有装不下的时候。当时说「第 4 部分讲 vector 的时候一起说」。

就是这儿。std::string 背后用的正是这一套： 不预先定死多大，用多少长多少。vector 和 string 是一家人—— 一个装数，一个装字符。

越界这件事，vector 一样有

v 里只有 3 个元素的时候去读 v[5]， 和数组越界是同一回事：编译器不管，打出来的数看运气。

4.2 那条规矩在这儿照样管用：合法下标是 0 到「个数减一」。

几个？问它

数组的个数是你自己写下去的那个数字，忘没忘心里有数。 vector 的个数是长出来的，你得问它： 

v.size()

size() 就是「你现在有几个」。写遍历的时候条件那一格用它， 这样不管你往里塞过几个，循环都是对的。

不过这儿有个小坎，第一次写基本都会撞上。条件写成这样： 

    for (int i = 0; i < v.size(); i++) {

编译器会跟你说一句话：

4.6-vector-size-warn.cpp:20:23: warning: comparison of integer expressions of different signedness: ‘int’ and ‘std::vector<int>::size_type’ {aka ‘long unsigned int’} [-Wsign-compare]
   20 |     for (int i = 0; i < v.size(); i++) {
      |                     ~~^~~~~~~~~~

先看清楚：它说的是 warning，不是 error。 这份程序照样编译出来、照样跑对，输出还是那三个数。 所以见到它不必慌——它不是错的。

但这句话得读懂，不然下次见到只能干瞪眼。

那个 int()

最后那一截 [-Wsign-compare] 是这句警告的名字， 翻过来就是「有符号和无符号的东西在比大小」。

这两个词这一课是头一回出现，其实很直白：

有符号（signed）就是能装负数的那些盒子：int、 double、char。1.2 讲的都是这一类。 i 是 int，所以它是有符号的。

无符号（unsigned）是只装 0 和正数的那些。 因为不用留地方给负号，能装的正数范围就大一倍。 v.size() 给出来的数是这一种——编译器那句话里写得很清楚： size_type {aka ‘long unsigned int’}， 意思是「它的正式名字叫 size_type，实际上就是个无符号的长整数」。

它为什么要提醒你？因为它怕你手滑。 一个能装负数的数去跟一个不能装负数的数比大小，是经典事故现场： i 如果是 -1，跟无符号的数一比， 会被当成一个极大的正数，比出来的结果跟你以为的正好相反。 （这个坑第 6 部分还会细讲，现在只要知道编译器在防这个。）

你这份程序里 i 从 0 开始往上走，永远到不了负数， 所以真跑起来一点问题都没有。编译器不知道这件事，它只管提醒。

让它闭嘴的办法，是在前面加一个 int()：

    for (int i = 0; i < int(v.size()); i++) {

int(某样东西) 的意思是「把它当成 int 来看」。 v.size() 本来是无符号的，套上 int() 就变成普通的 int， 两边一样了，警告就没了。

这就是 1.6 那道 char 的题里答应过要讲的东西。 当时想看一眼 'a' 的编号，要写的就是 int(c)——同一份数据，换一个身份去看它，它就是个整数。

这件事有个正式名字叫类型转换（cast）， int() 这种写法叫显式转换。

它不改数据，只改「用什么身份看」

int(v.size()) 没有把那个数变成另一个数， 它只是告诉编译器：这一格请按 int 来算。

1.3 讲整数除法的时候是反过来的那种情况——两个 int 相除， 它不给你算小数。要算小数得先让其中一个变成 double， 那也是一种转换，第 6 部分一起讲。

还有另一条路，但先别走

也可以直接把 i 声明成无符号的，两边一样了，警告也没了。 初学阶段不推荐：无符号的数有个「减到 0 再减一下，就变成一个天文数字」 的毛病，比这个警告麻烦得多。

就用 int()。这一层括号你以后会写很多遍，写顺手了就是肌肉记忆。

那个装数据的盒子，为什么开在循环里面

注意读取那个循环里，装数据的盒子 x 开在循环里面。
