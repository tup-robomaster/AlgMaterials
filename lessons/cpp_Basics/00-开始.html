第 0 部分

开始

这三课不教语法。它们只解决一件事：让你的屏幕亮起来。 上完这三课，你能写出、编译、运行、并在出错时自己看明白报错的程序。 没有这一步，后面全是纸上谈兵。

0.1让第一个程序跑起来

目标很简单：屏幕上出现一行 Hello, C++!。

先花 5 秒确认一件事

打开 VS Code 的终端（菜单 Terminal → New Terminal，或者按 Ctrl + Shift + 反引号键），敲： 

g++ --version

如果它打印出版本号（类似 g++ (Ubuntu 13.3.0-6ubuntu2~24.04) 13.3.0），说明编译器装好了，往下走。

如果它说 未找到命令（英文系统上是 command not found）， 说明编译器没装。在终端里敲这一条装上： 

sudo apt install g++

会问你要密码。输密码的时候屏幕上什么都不会显示——不打星号，光标也不动。这是正常的， 照常输完按回车就行。装完再敲一次 g++ --version 确认。

这一步没通，后面所有课都上不了，所以先把它解决掉，别的都往后放。

三步跑出第一行字

第一步：建一个文件夹，在里面建一个文件。

文件夹叫什么随便，就叫 cpp课 吧。别用鼠标点来点去，回终端敲，更快也更不容易错： 

mkdir -p ~/cpp课
cd ~/cpp课
touch hello.cpp

三条命令分别做的事：建文件夹、进入这个文件夹、建一个叫 hello.cpp 的空文件。 （~ 是「你的主目录」的意思。）

然后让 VS Code 打开这个文件夹： 

code .

code 后面那个点表示「当前这个文件夹」。如果它说 未找到命令， 用菜单 File → Open Folder 选到 cpp课 也一样。

坑

文件名必须是 hello.cpp，扩展名不能少、也不能多。 如果存成了 hello.cpp.txt，编译时会说找不到 hello.cpp。

在终端里敲 ls，就能看见当前文件夹里到底有哪些文件、名字到底是什么。 与其猜，不如看一眼。看见 hello.cpp.txt 就说明存错了。

第二步：在 VS Code 里把下面这段敲进去。 

#include <iostream>

int main() {
    std::cout << "Hello, C++!" << std::endl;
    return 0;
}

第三步：在终端里敲两条命令。 

g++ -Wall hello.cpp -o hello

中间那个 -Wall 先原样照抄，以后每一次编译都带着它。 它是「把该说的话都说给我听」的意思（W 是 warning 警告，all 是全部）。 为什么非带不可，0.3 讲警告的时候你就知道了——不带着它， 编译器有些话会瞒着你，而那些话往往正是你要的。

敲完这一条，如果什么都不打印，那是好事——编译器没话说就表示成功了。 然后敲第二条： 

./hello

（./ 的意思是「当前文件夹里的」。Linux 不会直接执行当前文件夹里的东西， 前面必须写 ./，只敲 hello 会说不认识这个命令。这一条新手最容易漏。）

屏幕上应该出现： 

Hello, C++!

编译和运行，是两件事

很多人以为「运行代码」就是一个动作。不是的，中间隔着一步：

命令干什么不成功会怎样
g++ -Wall hello.cpp -o hello 编译。把 hello.cpp 这段给人看的文字，翻译成机器能直接执行的程序，存成 hello 翻译不过去，终端里刷一片红色的 error。这时候根本没有程序存在，谈不上运行
./hello 运行。执行刚才编译出来的那个程序 程序会跑，但可能跑出你不想要的结果

分清这两件事很重要，因为它们的「错」完全不是一回事：

  • 编译不过——你的代码写得不符合 C++ 的语法。编译器直接告诉你哪儿不对，有行号。0.3 专门讲。
  • 编译过了，结果不对——语法没问题，是你想错了。编译器不会帮你发现这种错， 它根本不知道你想要什么。这是后面每一课真正要练的东西。

常见卡点

你看到的什么意思
bash: g++: 未找到命令 编译器没装。回到本节开头敲 sudo apt install g++
bash: code: 未找到命令 VS Code 的命令行入口没注册。不影响学习，用菜单 File → Open Folder 打开文件夹就行
bash: hello: 未找到命令
（注意：hello 前面没有 ./）		 忘了 ./。bash 只会在系统的命令目录里找，不会在当前文件夹里找， 所以它不认识 hello。要敲 ./hello
bash: ./hello: 没有那个文件或目录 这里确实没有叫 hello 的文件。多半是上一步编译就没成功（往上翻， 看有没有 error），或者你不在放代码的那个文件夹里。敲 ls 看这里有什么
cc1plus: fatal error: hello.cpp: 没有那个文件或目录 当前文件夹里没有 hello.cpp。多半是文件建在别处了。
敲 ls 看这里有什么，敲 pwd 看你现在在哪个文件夹
敲了 g++ ... 之后什么都没发生 这是对的。你还要再敲 ./hello 才会看到输出
出来几行 warning，可没看到 error 警告。程序照样生成了，接着敲 ./hello 就行。 但别把它划过去——先读完它说了什么。0.3 教你怎么读
一大堆 error 代码写错了。下一课就是讲这个

注意上面这几行是中文的。bash 和编译器的启动部分会跟着你系统的语言走， 所以中文系统上就是中文（上面写的都是中文系统的真实样子）。 你装的要是英文系统，同样的错会写成 bash: g++: command not found、 cc1plus: fatal error: hello.cpp: No such file or directory—— 意思一模一样，认一个就行。至于真正的 C++ 报错，永远是英文的。

例题 · 改一句话

题目：把屏幕上那一行 Hello, C++! 改成 Hello, World!。

要动的只有一处——双引号里面的那几个字。程序里其他每一个字符都别碰。 

#include <iostream>

int main() {
    std::cout << "Hello, World!" << std::endl;
    return 0;
}

然后重新编译一遍，再运行： 

g++ -Wall hello.cpp -o hello
./hello
Hello, World!

五行里只有引号中间的字变了，其他全是原样。 后面所有的课，都是在这同一副骨架上加东西—— 骨架本身你以后不用再想，手会自己写出来。

练习

练习 0-1

把 Hello, C++! 换成你自己的名字，重新编译运行一遍。

注意：改完代码要重新编译（再敲一次 g++ -Wall hello.cpp -o hello）， 不然你跑的还是上一次那个程序。这一点新手经常忘。 

Hello, 张三!
看答案

跟你自己那份只差引号里的几个字：

#include <iostream>

int main() {
    std::cout << "Hello, 张三!" << std::endl;
    return 0;
}

换成你自己的名字当然也行。这题没别的意思，就是让你把 「改代码 → 重新编译 → 再跑」这个循环走顺——顺带说一句， 课里每道练习的答案程序都在 示例代码/答案/ 里， 文件名就是练习号，懒得敲的时候可以直接编译它。

练习 0-2

让程序输出两行，第二行是你的专业。比如： 

Hello, 张三!
我是飞行器设计专业的

要加一行 std::cout。注意每一行末尾的 ; 别忘。

看答案

一行一个 std::cout，一行的末尾一个分号：

#include <iostream>

int main() {
    std::cout << "Hello, 张三!" << std::endl;
    std::cout << "我是飞行器设计专业的" << std::endl;
    return 0;
}

第二行末尾那个分号也别落下。这两行是两句话，不是一句—— 少一个分号，编译器就不知道该在哪儿断句。

你现在能写什么：能写出程序、编译它、运行它，知道编译不过和结果不对是两回事。

0.2程序的骨架

上一课那个程序，除了 Hello, C++! 之外还有五行。这五行到底是什么？ 

#include <iostream>

int main() {
    std::cout << "Hello, C++!" << std::endl;
    return 0;
}

逐行看

#include <iostream> —— 借工具。

iostream 是「input output stream」的缩写，输入输出流。 屏幕上打字的那个 cout，就是从这个文件里借来的。 不写这一行，程序不认识 cout，编译就会报错。

std:: —— 名字住在哪儿。

注意上面那行 std::cout：cout 前面挂着一个 std::。

C++ 自带的东西（打印、算数、字符串……）都住在一个叫 std 的 命名空间（namespace）里，std 是 standard（标准）的缩写。 :: 读作「的」，所以 std::cout 读成「std 里的 cout」。

它像个路标，告诉你这个名字是从哪儿来的。程序长到几百行以后， 你会看到一个 sort——有没有 std::，决定了它是标准库的，还是你自己或者别人写的。

现在你只要照写：凡是 C++ 自带的东西，前面都加 std::。 少写了会编译不过，而且编译器会直接告诉你该补什么——0.3 里有一个例题专门讲这个。

拓展：你可能会看到别人这么写

有些教材和别人的代码，会在开头写一行 using namespace std;。 它的意思是「下面我提到的名字，都先去 std 里找一遍」—— 写了它，就能省掉所有的 std::，直接写 cout。

但我们不这么写。省下的是五个字符，代价是 std 里成百上千个名字 一股脑倒进你的程序：你自己起的名字跟它们相同时，报错会变得莫名其妙； 读代码的人也分不清 count 是你写的还是标准库的。

出了这门课，你会在别人的代码里见到它。见到认识就行，自己不要写。

int main() { ... } —— 程序的入口。

程序从 main 开始跑。花括号里面的东西，就是要干的事。 一个程序必须有 main，而且只能有一个。

std::cout << "Hello, C++!" << std::endl; —— 往屏幕上打东西。

cout 读作「C out」，意思是「往外送到屏幕」。 两个 << 像两个箭头，把右边的内容送进 cout： 先送 "Hello, C++!"，再送 std::endl。

endl 是「end line」，换行。不写它，下一次输出会接着这一行往后挤。

return 0; —— 告诉系统「我正常结束了」。

说实话，这一行不写也能编译能跑。C++ 规定 main 不写 return 时自动返回 0。 但建议写——别人读你的代码时，一眼就知道这里是正常结束。

要不要背

不用背。这五行你接下来一个月天天见，写到手酸。到时候手比脑子先写出来。

骨架里最重要的一件事：从上往下，一行一行

程序就是一行一行往下执行的。先说第一行，做完做第二行，再做第三行。 没有「跳回去」，没有「同时做」。

这句话现在看着是废话，但它其实是后面所有东西的地基—— 循环是「跳回去再来一遍」，函数是「跳到别处做完再跳回来」， 判断是「满足条件就跳过某几行」。 全都建立在「默认是一行一行往下走」之上。

例题 · 让屏幕出三行

题目：让程序在屏幕上打三行字——第一行、第二行、第三行。

一行 std::cout 管一行。要三行，就写三句： 

#include <iostream>

int main() {
    std::cout << "第一行" << std::endl;
    std::cout << "第二行" << std::endl;
    std::cout << "第三行" << std::endl;
    return 0;
}
第一行
第二行
第三行

三句话长得一模一样，只有引号里的字不同。这就是「一行一行往下走」的样子： 先执行第一句，再第二句，屏幕就按这个顺序出三行。

每句末尾的 std::endl 管换行，不写它，三行会挤成一行。 另外注意每一句末尾的分号——少一个就编译不过（0.3 整课都在讲这个）。

练习

练习 0-3

在上面基础上加第四行输出 第四行。 

第一行
第二行
第三行
第四行
看答案

加一行，就是在 return 0; 前面再插一句一模一样的 std::cout：

#include <iostream>

int main() {
    std::cout << "第一行" << std::endl;
    std::cout << "第二行" << std::endl;
    std::cout << "第三行" << std::endl;
    std::cout << "第四行" << std::endl;
    return 0;
}
练习 0-4

把「第三行」和「第一行」那两句调换位置（注意：整句一起换）。 输出会变成什么？先写下来，再跑。 

第三行
第二行
第一行

这题没什么难度，但它证明了一件事：输出的顺序就是你写代码的顺序。 程序不会帮你整理。

看答案

对调的是整整两行——从 std::cout 到分号，一个字符不漏地换位置：

#include <iostream>

int main() {
    std::cout << "第三行" << std::endl;
    std::cout << "第二行" << std::endl;
    std::cout << "第一行" << std::endl;
    return 0;
}

只换引号里的字、不换整行，跑出来是一样的。但整行换更像你以后真会做的事： 要挪动一段逻辑，挪的就是一整句。

你现在能写什么：能看懂一个最基本的 C++ 程序的每一行在干什么， 知道程序是从上往下一行一行跑的。

0.3报错怎么读

这是第 0 部分最重要的一课。

新手看到一堆红字就慌，然后去搜「这个报错什么意思」。 其实报错本身就是写给你看的，它有固定的格式，读懂了不用问任何人。

报错的格式

文件名:行号:列号: error: 具体信息

就这四段。比如 hello.cpp:4:18: error: ‘count’ was not declared in this scope， 意思是：hello.cpp 的第 4 行、第 18 列，有一个错误—— 那里用了一个叫 count 的名字，而编译器不认识它。

别被引号绊住

上面 count 外面那对引号是弯的（‘ ’），不是你键盘上那个直的（' '）。 编译器用的是弯引号。你的键盘打不出来，也不用打——那是它打印给你看的，不是你敲进去的。

三条读报错的规矩

一、先看第一个 error，后面的常常是连锁反应

这条规矩要对着真东西才看得懂。下面这个程序，故意删掉了 #include <iostream> 那一行， 别的一个字符都没动——整个程序就三行： 

int main() {
    std::cout << "你好" << std::endl;
    return 0;
}

它编译不过。这是编译器说的话： 

0.3-err-c-no-include.cpp: In function ‘int main()’:
0.3-err-c-no-include.cpp:2:10: error: ‘cout’ is not a member of ‘std’
    2 |     std::cout << "你好" << std::endl;
      |          ^~~~
0.3-err-c-no-include.cpp:1:1: note: ‘std::cout’ is defined in header
      ‘<iostream>’; did you forget to ‘#include <iostream>’?
  +++ |+#include <iostream>
0.3-err-c-no-include.cpp:2:33: error: ‘endl’ is not a member of ‘std’
    2 |     std::cout << "你好" << std::endl;
      |                                 ^~~~
0.3-err-c-no-include.cpp:1:1: note: ‘std::endl’ is defined in header
      ‘<ostream>’; did you forget to ‘#include <ostream>’?

源码三行，报错十行。把这两段并排看一眼，就知道新手为什么一看到红字就慌了。

数一下：两个 error，两个 note。可你只犯了一个错——忘了 #include。 两条报错，一个原因。

第一条 error 说 ‘cout’ is not a member of ‘std’，字面意思是 「std 里面没有叫 cout 的东西」。这话看着别扭——cout 明明就是标准库的。

别扭在哪：#include <iostream> 那一行的作用，是把「标准库里有这些东西」的名单交给编译器。 你把名单也一起删了，它当然说没有。

第二条 endl 的错，同样出自这一个原因。

这里有个陷阱

第二个 note 建议你补 #include <ostream>。别照做。 你真正缺的是 <iostream> 那一个——补上它，两个错一起消失， 因为 <iostream> 本来就把 <ostream> 包含在里面了。

如果你去改第二个错，就会在一个根本不该动的地方加一行。这正是 「只改第一个 error」的原因：后面那些错的修法，往往是错的。

所以：从最上面那个 error 开始改，改完重新编译，让报错重新来一遍。 不要试图一口气改完所有的错。

二、注意看 note

回头看上面那个例子，第一个 note 直接把答案说出来了： 「std::cout 定义在 <iostream> 里，你是不是忘了 #include <iostream>？」 下面那行 +++ |+#include <iostream> 更直接——它把该补的那一行都替你写好了。

编译器不只告诉你错了，还顺手告诉你怎么改。看到 note 就一定要读。

（上面那个 note 在终端里其实是很长的一行，是终端自己折行的。 课里为了让你读得下，也把它折开了。你在自己屏幕上看到的不一定断在同一个位置—— 那不是两条 note，是一条。）

三、报错的行号，不一定是出错的行号

这是最容易把人卡住的一条。源码先摆出来——你先自己找找，哪一行有问题： 

#include <iostream>

int main() {
    int a = 3
    int b = 5;
    std::cout << a + b << std::endl;
    return 0;
}

编译器的反应是： 

0.3-err-d-wrongline.cpp:5:5: error: expected ‘,’ or ‘;’ before ‘int’
    5 |     int b = 5;
      |     ^~~
0.3-err-d-wrongline.cpp:6:22: error: ‘b’ was not declared in this scope
    6 |     std::cout << a + b << std::endl;
      |                      ^

它说第 5 行有问题。可第 5 行 int b = 5; 本身一点毛病都没有—— 真正的问题在第 4 行末尾，少了一个分号。

为什么？因为编译器读到第 5 行的 int 时才发现 「等等，上一句话好像还没说完」。 它报的是「我在这里发现不对」，不是「你在这里写错了」。

顺便把规矩一也用上了：第二条 ‘b’ was not declared 是真的连锁反应—— 分号一少，int b = 5; 这句就没被读进去，后面用到 b 自然就不认识了。 两条报错，还是同一个分号的事。

所以

报错指向某一行、而你看那一行怎么看都没错的时候—— 往上翻一行，看上一行的末尾有没有少分号、少括号、少逗号。 这一招能解决新手遇到的很大一部分报错。

几个必认识的词

报错里的话意思
error错误。必须解决，否则编译不过，程序根本不会生成
warning警告。程序还能编译，但这里有隐患。别养成无视它的习惯——0.1 让你一直带着 -Wall，就是为了让这些话能说出来
note提示。编译器在帮你，一定读
expected ...「这里应该有一个……」。expected ‘;’ = 这里该有分号
... was not declared
... is not defined		用了一个不存在的名字。要么拼错了，要么忘了定义，要么忘了 #include，要么忘了写 std::
... is not a member of ‘std’std 里没有这个东西。多半是忘了 #include 对应的头文件
did you mean ...?「你指的是不是这个？」编译器直接给出它猜的正确写法，照它改
in this scope「在这个范围里」——配合上一行用，说明这个名字在这里看不见
没有那个文件或目录
（英文系统：No such file or directory）		找不到文件。这不是说你代码写错了，是文件名写错或路径不对。最常见的就是 #include 里的头文件名打错

你代码的报错永远是英文的，改不了。但常用的就这些词，见几次就认识了。 （最后一条是系统在说话，不是编译器在说话，所以它会跟着系统语言走。）

还有一个例子：缺分号，但这次编译器指对了

同样是少一个分号，源码： 

#include <iostream>

int main() {
    std::cout << "你好" << std::endl
    return 0;
}

编译器这次的反应是： 

0.3-err-a-semicolon.cpp:4:37: error: expected ‘;’ before ‘return’
    4 |     std::cout << "你好" << std::endl
      |                                     ^
      |                                     ;
    5 |     return 0;
      |     ~~~~~~

这次它说第 4 行，问题确实在第 4 行末尾。注意那个孤零零的 ;—— 编译器把该补的东西都替你画出来了。最后两行是把第 5 行的 return 0; 整个划了出来，意思是「我是在读到这儿才发现前面不对的」。

每段报错开头那行是什么

你会发现上面三个例子的第一行都是同一个样子： 

0.3-err-a-semicolon.cpp: In function ‘int main()’:

这一行没有行号，它说的是「下面这些错，都发生在 main 这个函数里」。 程序大了、函数多了以后，这一行能帮你快速知道是哪个函数出的问题。 现在你只有一个 main，所以它看起来像是废话，跳过它往下看就行。

对比一下这两个例子你就能感觉到：报错的质量参差不齐，有的很准，有的会指偏。 所以不能死盯着行号，要结合「这个地方按语法说不说得通」来判断。

例题 · 忘了写 std:: —— 用三条规矩读一遍

题目：下面这个程序是照着 0.2 的骨架写的，但漏了东西。先自己找一遍，再看下面的报错。 

#include <iostream>

int main() {
    cout << "你好" << endl;
    return 0;
}

漏的是两处 std::。编译一下，编译器是这样说的： 

0.3-err-e-no-std.cpp: In function ‘int main()’:
0.3-err-e-no-std.cpp:4:5: error: ‘cout’ was not declared
      in this scope; did you mean ‘std::cout’?
    4 |     cout << "你好" << endl;
      |     ^~~~
      |     std::cout
0.3-err-e-no-std.cpp:4:23: error: ‘endl’ was not declared
      in this scope; did you mean ‘std::endl’?
    4 |     cout << "你好" << endl;
      |                       ^~~~
      |                       std::endl

（上面那两条 error 在终端里各是很长的一行，课里折开了——和规矩二里说的一样。 真实的报错在这后面还有几行，指到系统头文件里的具体位置，路径里带着编译器的版本号， 那几行现在不用看。有用的是上面这两条。）

规矩一——只看第一条：‘cout’ was not declared in this scope， 「这个范围里没有叫 cout 的东西」。

规矩二——这条 error 自己就把答案说了：did you mean ‘std::cout’? 「你指的是不是 std::cout？」下面那行 std::cout， 是编译器替你把该写的样子摆了出来。照它改就行。

规矩三——这次行号是准的，就是第 4 行，cout 和 endl 都在这一行上。

补上两处 std::，重新编译，两条报错一起消失。 这就是 0.2 里那句话的意思：凡是 C++ 自带的东西，前面都加 std::。 漏了它不算什么大事——编译器不但会告诉你，还会顺手把该写的样子给你看。

练习

练习 0-5

把 0.2 那个程序的任意一行末尾的分号删掉，重新编译。 把报错信息完整抄下来，然后自己判断： 它指的是哪一行？真正出错的是哪一行？两者一样吗？

改完记得把分号加回去，重新编译确认恢复正常。

看答案

我删的是第一行末尾那个分号（整个文件的第 4 行）。改完是这样：

#include <iostream>

int main() {
    std::cout << "第一行" << std::endl
    std::cout << "第二行" << std::endl;
    return 0;
}

编译器说的话：

0-5-err.cpp: In function ‘int main()’:
0-5-err.cpp:4:39: error: expected ‘;’ before ‘std’
    4 |     std::cout << "第一行" << std::endl
      |                                       ^
      |                                       ;
    5 |     std::cout << "第二行" << std::endl;
      |     ~~~

读一遍：expected ‘;’ before ‘std’，字面意思是 「在 std 前面该有个分号」。它指的第 4 行，就是真正出错的那一行。 下面那个孤零零的 ; 是它替你画出来的——告诉你补在哪儿。

你屏幕上显示的文件名和我的不一样

上面每行开头的 0-5-err.cpp，是你的文件名。 你那份叫什么，那里就显示什么——除此之外一个字都不差。

但这题的重点在下半句：报的行号不总是这么准。 0.3 里那个 int b = 5 缺分号的例子，编译器指的就是下一行。 所以真正的判断方法不是看行号，是问自己一句： 「这一行按语法说得通吗？」 第 4 行末尾少个分号，这一行读不通，答案就在这一行。

你删的那一行如果跟我不一样，报的行号也会不一样，这很正常—— 把上面这套读法套上去就行。

练习 0-6

下面这段代码有一处错。先别编译，自己找出来，然后猜编译器会说什么， 最后再编译验证你的猜测。 

#include <iostream>

int main() {
    int a = 3;
    int b = 5
    std::cout << a + b << std::endl;
    return 0;
}

提示：想想上一题你抄下来的报错长什么样。

这题的重点不是改对，是「猜到编译器会说什么」。 猜对了，说明你已经开始会用编译器的眼睛看代码了。

看答案

错在第 5 行：int b = 5 末尾少一个分号。补上就好：

#include <iostream>

int main() {
    int a = 3;
    int b = 5;
    std::cout << a + b << std::endl;
    return 0;
}

补上之后输出：

8

回头看那个错的样子——这是这道题真正要你看见的东西：

0-6-err.cpp: In function ‘int main()’:
0-6-err.cpp:6:5: error: expected ‘,’ or ‘;’ before ‘std’
    6 |     std::cout << a + b << std::endl;
      |     ^~~
0-6-err.cpp:4:9: warning: unused variable ‘a’ [-Wunused-variable]
    4 |     int a = 3;
      |         ^
0-6-err.cpp:5:9: warning: unused variable ‘b’ [-Wunused-variable]
    5 |     int b = 5
      |         ^

三件事，一件一件看：

一、它报的是第 6 行，出错的是第 5 行。 为什么这回指到下一行去了？因为少分号的是一句声明（int b = 5 这句还没说完）， 编译器读到第 6 行的 std::cout 才发现「上一句没收尾」。 0-5 那题少分号的是一句输出，它就在那一行断的。 两题合起来才是这条规矩的全貌：它报的是「我在这里发现不对」。

二、那两条 unused variable 警告是假的。 a 和 b 明明都用到了——只是因为在编译器眼里这两句声明压根没成立， 它才觉得「定义了没用」。它们不是新问题，是那一个分号的连锁反应。

三、改的时候只动第 5 行。去第 6 行加东西、或者删掉那两句声明， 都只会把事情弄得更乱。

你现在能写什么：能写出、编译、运行程序； 遇到报错能自己读出是哪一行、什么毛病，而不是复制粘贴去问别人。 这一条比记住十个语法点有用得多。
