第 6 部分

指针与引用

前五部分有个词一直在用，可从来没说清过：盒子。 「开一个盒子」「把值放进盒子」「盒子里装的是抄件」—— 那盒子到底在哪儿？ 这一部分就去那个地方看一眼：内存。 看一眼你会发现，每个盒子都有个门牌号，而 & 和 * 这两个符号干的事， 说到底就是「问门牌号」和「顺着门牌号找过去」。 3.5 那个神奇的 int& x、4.x 那个「数组一进函数就能被改」的怪事， 到这一部分全都会有答案。

6.1变量住在内存里：地址是什么

先回想一个你已经用了很久的说法：int a = 3; 是「开一个盒子叫 a，把 3 放进去」。

从第一部分开始，我们一直这么讲。可有个问题从来没回答过： 这个盒子在哪儿？

一排有编号的小格子

说「盒子」其实是打了比方。内存的真实样子是一整排小格子， 一格挨着一格，排得整整齐齐，从左到右一直排下去。

每一格装一个字节（byte），每一格有一个编号。 编号从 0 开始，往后一格一号，一直排到很大很大。

你开的每一个盒子，都住在其中几格里。 int a = 3; 的意思是：找几格空着的（int 要 4 格）， 把 3 装进去，然后把那几格的编号记在 a 这个名字上。

那几格的编号，就叫这个盒子的地址（address）。

「地址」这个词不是打比方

它跟门牌号是同一个意思，而且比门牌号更实在：门牌号是人编的， 内存地址是机器真的要用的东西。 你说「a」，编译器把它翻成「第 140733…号那几格」， CPU 拿着这个号去内存里找。 名字是给你看的，编号才是 CPU 认的。

& 是「你住在哪儿」

想知道一个盒子住在哪儿，在它名字前面写一个 &： 

#include <iostream>

int main() {
    int a = 3;

    std::cout << "a 里装的   " << a << std::endl;
    std::cout << "a 的地址   " << &a << std::endl;
    std::cout << "a 占几格   " << sizeof(a) << std::endl;

    return 0;
}

&a 读作「a 的地址」，那个 & 叫取地址运算符。

跑一下，第一行和第三行你都知道是什么，中间那行是这样： 

a 里装的   3
a 的地址   0x7ffeb31296b4
a 占几格   4

那个「0x 开头的一串」就是地址。 0x 是「后面这串是十六进制」的意思（1.6 讲 printf 的时候见过 %x，是一回事）， 剩下的十三四个字符就是那几格的编号。

这个数你每次跑都不一样。

再跑一遍，a 的地址 那一行就变了——可能变成 0x7ffe3a91d594，也可能变成别的。 这不是出错，也不是随机数，是操作系统每次都挑个新地方给你放。 别人电脑上跑，跟你也不一样。

所以：课上凡是出现具体地址的地方，你都对不上，这是正常的。 能对上的是「占几格」和「两个地址差多少」——那些才是稳定的。

同一个 &，两种用法

3.5 里见过 int& x，那儿的 & 写在 类型后面，意思是「引用」。 这里的 &a，& 写在 变量前面，意思是「取地址」。

同一个符号，位置不同，干的事完全不同。 怎么分？看它挨着谁：挨着 int 那种类型名，是引用； 挨着一个现成的变量名，是取地址。

一排盒子是挨着放的

4.1 说数组是「一排盒子」。那这一排在内存里是怎么摆的？把三个元素的地址都打出来看看： 

#include <iostream>

int main() {
    int a[3] = {10, 20, 30};

    std::cout << &a[0] << std::endl;
    std::cout << &a[1] << std::endl;
    std::cout << &a[2] << std::endl;

    return 0;
}
0x7ffffb584dbc
0x7ffffb584dc0
0x7ffffb584dc4

三个地址，一个比一个大，而且每次正好大 4。

盯着最后两位看：dbc → dc0 → dc4。 十六进制里 c 是 12，c + 4 = 16，进一位写成 0； 再 0 + 4 = 4。就是加了 4。

为什么是 4？因为一个 int 占 4 格，三个元素就得占 12 格， 它们背靠背站着，中间一格都不空。

这就是 4.2 那个下标的真面目。 当时说「a[i] 就是从头往后数第 i 个」， 现在能说清楚了：a[i] 住在从 &a[0] 往后数 第 i 个 int 的地方。

换成编号来说，就是「&a[0] 那个编号，加上 i 乘 4」——每个 int 占 4 格，往后挪一个就加 4。

「4」这个数是从哪来的

因为一个 int 占 4 格。换成 double 数组， 每个就占 8 格，相邻两个元素的地址差 8。

元素占几格，相邻地址就差几。就这么简单。 （下一节就讲每种类型占几格。）

越界的危险也从这儿来：a[5] 算出来的地址，是那一排外面的地方。 写进去，改的就是别人的盒子。4.1 那两个越界的例子之所以那么邪门，原因就在这一行。

每种类型占几格

既然地址是按格算的，那每种类型占几格就很重要了。写个程序问一下： 

#include <iostream>

int main() {
    std::cout << sizeof(char)   << " "
              << sizeof(bool)   << " "
              << sizeof(int)    << " "
              << sizeof(double) << std::endl;

    return 0;
}
1 1 4 8

sizeof 是「这个类型占几格」。 注意它不用加括号调用，它是个运算符，跟 +、- 一样， 只不过写起来像函数调用。

所以 int 和 double 的盒子长得不一样大： double 要 8 格，是 int 的两倍。

这几个数字，是这台机器上的

char 和 bool 恒为 1，int 在几乎所有现代机器上都是 4——这两条可以放心记。 但 double 不是：有些机器上是 4，有些是 8。 想确认，就自己写一行 sizeof 打出来。 反正一句话的事。

例题 · 一排 double 占几格

一排四个 double，一共占多少格、装得下几个盒子？ 不用手算，让程序自己说： 

#include <iostream>

int main() {
    double price[4] = {9.9, 19.9, 29.9, 39.9};

    std::cout << "整排占几格    " << sizeof(price) << std::endl;
    std::cout << "一个盒子几格  " << sizeof(price[0]) << std::endl;
    std::cout << "一共几个盒子  " << sizeof(price) / sizeof(price[0]) << std::endl;

    std::cout << "第一个的地址  " << &price[0] << std::endl;
    std::cout << "第二个的地址  " << &price[1] << std::endl;

    return 0;
}
整排占几格    32
一个盒子几格  8
一共几个盒子  4
第一个的地址  0x7ffe6b46f310
第二个的地址  0x7ffe6b46f318

前两行是 sizeof 直接给的：整排 32 格，一个盒子 8 格。 除一下就是盒子的个数，32 ÷ 8 = 4—— 所以这个写法能问出「一排有几个盒子」，不用自己去数。

后面两行照着前面学过的读法看：两个地址差 8， 因为一个 double 占 8 格，第二个就住在第一个往后 8 格的地方 （这一节前面那三个 int 每回差 4，是同一个道理）。 地址本身每次跑都换，末几位你那儿多半跟这儿不一样，不用去对；能对上的是差多少。

练习 6-2

开一个 int a[3] = {10, 20, 30};，然后一行打三样东西， 中间用空格隔开：

一、数组名 a 和首元素地址 &a[0] 一样吗； 二、&a[2] 比 &a[0] 大吗； 三、整个数组占几格。 

1 1 12

提示：前两样是在比两个地址，直接写成 (a == &a[0]) 和 (&a[2] > &a[0]) 就能打进 cout。 第三样是 sizeof(a)。

看答案

三个式子，一行打出来：

#include <iostream>

int main() {
    int a[3] = {10, 20, 30};

    std::cout << (a == &a[0])    << " "
              << (&a[2] > &a[0]) << " "
              << sizeof(a)       << std::endl;

    return 0;
}

前两个打出来都是 1——在 C++ 里，真就是 1， 假就是 0（2.2 讲过）。

第一个 1 说明：数组名 a 和首元素的地址 &a[0] 是同一个地址。这件事 6.5 要专门讲。

第二个 1 说明：越靠后的元素地址越大，它们是挨着放的。

第三个 12：3 个 int，每个 4 格。 注意它跟前面两个不是一回事——sizeof(a) 量的是整个数组占的地方，不是第一个元素占的地方。

你现在能写什么：你能把「盒子在哪儿」打出来了。 一句话解释「地址是什么」，说清 & 是干什么的， 也知道自己每次跑出来的数跟课里不一样是正常的。 更重要的是：4.2 那个「下标就是偏移量」， 现在你看见它的真身了——三个 int 挨着站，每个差 4。

6.2引用：还有三条规矩

3.5 讲过的，和没讲的

3.5 你已经学过引用了。当时它长这样： 

void addOne(int& x) {
    x = x + 1;
}

引用（reference）不是新盒子，是给原来那个盒子起的另一个名字。 你大名叫「张三」，熟人叫你「三儿」，两个名字一个人。这句话 3.5 说过。

但 3.5 只在一个地方用过它——函数的参数表。 所以很容易留下一个错觉，以为引用是参数表专用的东西。

不是。参数表只是一个地方，引用可以写在任何地方： 

#include <iostream>

int main() {
    int a = 1;
    int& r = a;      // 可以在这儿写，不用非在函数参数里

    r = 9;           // 改 r，就是改 a

    std::cout << a << std::endl;
    return 0;
}
9

这跟参数表上那个 int& x 是同一个东西，一个字都没变。 只是这次它站在 main 里，看起来有点陌生。

换个地方站，就要多守三条规矩。这三条 3.5 都没讲——因为参数表那个位置 天生就满足它们，你根本碰不到。现在它站在普通语句里，就得自己守。

一出生就得绑上

规矩一：引用必须在出生那一刻就绑好。

普通变量可以先开空盒子，过一会儿再放东西： 

int a;      // 先开一个盒子
a = 3;      // 过一会儿再放

引用不行。它压根不是盒子，是一个名字。 名字不能是空的——起了个名字却没人叫这个名字，那不叫名字。 

int& r;      // 错
r = 3;

编译器当场拦下：

6.2-ref-nobind-err.cpp: In function ‘int main()’:
6.2-ref-nobind-err.cpp:4:10: error: ‘r’ declared as reference but not initialized
    4 |     int& r;
      |          ^

「r 被声明成了引用，但没初始化」—— declared as reference but not initialized。

规矩二：只能绑一个盒子，不能绑一个值。

这样也不行： 

int& r = 5;      // 错
6.2-ref-value-err.cpp: In function ‘int main()’:
6.2-ref-value-err.cpp:4:14: error: cannot bind non-const lvalue reference of type ‘int&’ to an rvalue of type ‘int’
    4 |     int& r = 5;
      |              ^

这句话长，抓住两个字就够：cannot bind，「绑不上」。

为什么不给绑？因为 5 不是一个盒子，它就是一个数。 引用是「某个盒子的另一个名字」，可 5 没有盒子—— 5 就在你眼前，你能叫它什么名字？给了名字，改它又改谁去？

报错里那两个怪词不用记

lvalue 和 rvalue 是 C++ 里的正式说法， 大意是「能站住、有地方的东西」和「只是个值的东西」。 你现在不用背定义，碰到报错认得这两件事就行： 「not initialized」——忘了绑； 「cannot bind」——绑的东西不是盒子。 两条都是「引用没绑到盒子上」，改法一样：给它一个变量名。

所以引用最讲究的就是那一行： 

int& r = a;      // 出生，同时绑上 a。这一行管到底

绑上了就换不了

规矩三：绑上之后换不了。

这条最容易骗人，因为它不报错——它照常编译，照常运行， 只是干的事不是你以为的那件。 

#include <iostream>

int main() {
    int a = 1;
    int b = 2;

    int& r = a;

    r = b;          // 把 b 的值写给 r（也就是写给 a），不是让 r 改去指 b

    std::cout << "a = " << a << std::endl;
    std::cout << "b = " << b << std::endl;
    std::cout << "r 还跟着 a 吗  " << (&r == &a) << std::endl;

    return 0;
}

跑出来： 

a = 2
b = 2
r 还跟着 a 吗  1

第三行的 1 是关键。 r = b; 跑完之后，r 的地址跟 a 还是一模一样—— 它压根没动过，从头到尾都跟着 a。

那 r = b; 干了什么？干了这一件事：把 b 里的值 （2）写进 r。而 r 就是 a， 所以 a 变成了 2。

b 自己从头到尾没人碰，还是 2。

为什么写 r = b; 会让人想歪

因为你刚学完「引用是另一个名字」，脑子里 r 还是一个「指着」的东西。 一看 r = b;，很自然读成「让 r 改去指 b」。

但 C++ 里没有这个操作。引用一旦出生就锁死了绑谁， 之后所有对 r 的操作，都自动翻译成对 a 的操作—— 包括赋值。所以 r = b; 只能读成 「把 b 的值给 a」。

想「改去指别人」，得用指针。那是下一课的事。

一个盒子，两个名字

三条规矩都有了一个共同的根：引用不是盒子。 现在用地址来验一验——如果 r 真是新盒子，它的地址就该跟 a 不一样；如果不是，地址就该一模一样。 

#include <iostream>

int main() {
    int a = 3;

    int b = a;      // 新开一个盒子 b，把 a 里的值抄一份放进去
    int& r = a;     // r 不是新盒子，它是 a 的另一个名字

    std::cout << "b 跟 a 是同一个盒子吗  " << (&b == &a) << std::endl;
    std::cout << "r 跟 a 是同一个盒子吗  " << (&r == &a) << std::endl;

    return 0;
}
b 跟 a 是同一个盒子吗  0
r 跟 a 是同一个盒子吗  1

b 是 0，r 是 1。

b 那句是 0——它是新盒子，地址当然不一样。 r 那句是 1——它和 a 的地址一模一样， 因为本来就是同一个盒子。

跟一遍动画，看清 b 和 r 的区别：

这个区别写出来是这么回事： 

int b = a;      // 开了两个盒子，a 和 b 各一个，里面都装 3
int& r = a;     // 只有一个盒子 a，r 只是它的第二个名字

还是同一个盒子、同一份值，改一改看看： 

#include <iostream>

int main() {
    int a = 1;

    int b = a;
    int& r = a;

    b = 100;        // 改抄件
    r = 200;        // 改本人

    std::cout << "a = " << a << "   b = " << b << std::endl;

    return 0;
}
a = 200   b = 100

一个变成了 200，一个还是 100。 b 被改成 100 之后就跟 a 没关系了—— 它俩是两个盒子。r 改到的是 a， 所以 a 成了 200。

例题 · 一次改掉外面两个盒子

想让一个函数把外面的两个盒子一起翻倍。参数表上写成引用，就这么写： 

#include <iostream>

void timesTwo(int& x, int& y) {
    x = x * 2;
    y = y * 2;
}

int main() {
    int a = 3;
    int b = 5;

    timesTwo(a, b);

    std::cout << "a = " << a << "   b = " << b << std::endl;

    return 0;
}
a = 6   b = 10

调用那行写的是 timesTwo(a, b)，一个 & 都没有， 可外面两个盒子都变了。因为参数表上写的是 int&： 函数里的 x 就是 a，y 就是 b， 改 x 就是改 a——6.2 说的「一个盒子，两个名字」，只是这次小名起在函数里。

把参数表改成 int x, int y 再跑一遍就看出区别了： 那时 x、y 是抄件，函数里翻倍白翻， 输出会变回 a = 3 b = 5。

这种「一次改两个」值传递做不到，因为一个函数只能 return 一样东西。 要一次把两个结果都带出去，就得靠引用。

练习

练习 6-3

开一个 int a = 5;，再开一个引用 r 绑到 a 上。 然后通过 r 把值改成 9。 最后分两行打：先打 a，再打 &r == &a。 

9
1

提示：从 r 走，写成 r = 9;， 全程不用提 a。

看答案

五行就够了：

#include <iostream>

int main() {
    int a = 5;
    int& r = a;

    r = 9;

    std::cout << a << std::endl;
    std::cout << (&r == &a) << std::endl;

    return 0;
}

r = 9; 写的不是 r 这个盒子（它压根不是盒子）， 是 a。所以第一行打出 9。

最后那行的 1 是证据：它俩的地址一样， 本来就是同一个盒子。所以「改 r 就是改 a」这件事， 不是规定，是地址本来就重合。

练习 6-4

写两个函数，函数体一模一样，都是 x = x + 1;： 一个参数写 int x，叫 addOneBad； 另一个参数写 int& x，叫 addOne。

main 里 int a = 3;， 先调 addOneBad(a) 打一行 a， 再调 addOne(a) 打一行 a。 

3
4

提示：这题就是 3.4 和 3.5 那两份摆在一起。 第二行要真是 4，说明 & 起作用了。

看答案

两个函数并排，只有参数表差一个字符：

#include <iostream>

void addOneBad(int x) {
    x = x + 1;
}

void addOne(int& x) {
    x = x + 1;
}

int main() {
    int a = 3;

    addOneBad(a);
    std::cout << a << std::endl;

    addOne(a);
    std::cout << a << std::endl;

    return 0;
}

第一次打完还是 3：addOneBad 拿到的是抄件， 它把抄件改成了 4，出了函数就没了。

6.3指针：自己拿着门牌号

上一课最后留了一句话：想「改去指别人」，得用指针。 这一课就讲它。

盒子里装的是地址

引用是「某个盒子的另一个名字」。可名字是虚的—— 你没法把「三儿」这个名字单独拿出来，递给另一个函数， 也没法把它存在一个变量里。

指针（pointer）干的是另一件事：把门牌号本身抄下来， 装进一个盒子里，你自己拿着。 

int a = 3;
int* p = &a;      // p 这个盒子，装的是 a 的地址

一行一行读：

int* p —— 开一个盒子叫 p， 它装的东西是「一个 int 的地址」。 这个类型写作 int*，读作「指向 int 的指针」。

= &a —— 把 a 的地址取出来，装进 p。 & 是 6.1 那个取地址，一个字都没变。

所以现在的样子是：a 盒子里装着 3，p 盒子里装着 「a 住在哪儿」。两个盒子，两种内容。

指针盒子有多大

地址就是一串编号，装它也需要格子。这台机器上： 

sizeof(int*)   →  8

跟 double 一样大。有意思的是， sizeof(char*) 也是 8——指针的大小跟它指的东西没关系， 反正都是「一个编号」，编号的长度是机器定的。

星号是「顺着找过去」

门牌号抄下来了，怎么用？在指针前面加一个 *： 

#include <iostream>

int main() {
    int a = 3;

    int* p = &a;    // p 这个盒子，装的是 a 的地址

    std::cout << "*p = " << *p << std::endl;   // 顺着地址找过去

    *p = 9;                                    // 顺着地址找过去，写进去

    std::cout << "a = " << a << std::endl;
    std::cout << "p 里装的就是 a 的地址吗  " << (p == &a) << std::endl;

    return 0;
}

跑出来： 

*p = 3
a = 9
p 里装的就是 a 的地址吗  1

*p 读作「p 指着的东西」，这个动作叫解引用 （dereference）。说白了就是：顺着 p 里的地址找过去， 把那个盒子打开。

打开之后，跟普通变量完全一样，读也行写也行：

第一行 *p 是在读，读到 3——因为找过去就是 a。

然后 *p = 9; 是在写。写进去的是 a。 所以第三行 a 打出来是 9。

最后那行的 1 是证据：p 里装的确实是 a 的地址。

跟一遍：

对照一下 6.2 的引用，会发现这两个东西干的事一模一样： 

int& r = a;      // 引用
r = 9;           // 直接写，看着就像在改 r

int* p = &a;     // 指针
*p = 9;          // 得写个星号，明确说「顺着找过去再写」

引用是编译器替你保管那个地址，指针是你自己拿在手里。 一个省事，一个灵活。

又是同一个符号，两种用法

int* p 里的 * 是声明的一部分—— 它在说「p 是个指针」。 *p = 9 里的 * 是一个动作—— 「顺着找过去」。

分法跟 & 一样，看它挨着谁： 挨着类型名（int）的时候是声明， 挨着一个现成的变量的时候是动作。

所以 int* p = &a; 这一行里两个符号都出现了， 两个的意思完全不同，别混。

指针能换，引用不能

这就是 6.2 结尾说的那件事。看： 

#include <iostream>

int main() {
    int a = 1;
    int b = 2;

    int* p = &a;
    std::cout << "先指着 a：*p = " << *p << std::endl;

    p = &b;                                  // 换个门牌号装进去
    std::cout << "改指 b：  *p = " << *p << std::endl;

    *p = 20;                                 // 这句改的是 b

    std::cout << "a = " << a << "   b = " << b << std::endl;

    return 0;
}
先指着 a：*p = 1
改指 b：  *p = 2
a = 1   b = 20

p = &b; 这一行，把 p 盒子里的地址换掉了—— 原来装 a 的，现在装 b 的。 这在引用身上是绝对做不到的（6.2 规矩三）。

注意最后 a = 1：a 从头到尾没被动过。 *p = 20; 改的是 b，因为那时候 p 已经改指 b 了。

把这两个东西并排放一次： 

#include <iostream>

int main() {
    int a = 1;
    int b = 2;

    int* p = &a;
    p = &b;             // 指针：换个地址装进去就行了
    *p = 20;            // 顺着新地址写——写的是 b

    int& r = a;
    r = 30;             // 引用：直接写，它就是 a

    std::cout << "a = " << a << "   b = " << b << std::endl;
    std::cout << "p 指着 b 吗  " << (p == &b) << std::endl;
    std::cout << "r 跟着 a 吗  " << (&r == &a) << std::endl;

    return 0;
}
a = 30   b = 20
p 指着 b 吗  1
r 跟着 a 吗  1

同一个 a，被两条完全不同的路改到了。

引用 int&指针 int*

能不能换指谁不能，绑死能，随时改
用的时候直接写名字，跟普通变量一样得写 *p
能不能是空的不能，一定是某个盒子能，见下一节

空指针

指针有个引用没有的本事：它可以谁都不指。 

int* p = nullptr;

nullptr 的意思是「我手里还没有门牌号」。 它是个关键字，C++ 里专门为这件事留的。

这种指针叫空指针（null pointer）。怎么用？先问一句： 

#include <iostream>

int main() {
    int* p = nullptr;

    std::cout << "p 是空的吗  " << (p == nullptr) << std::endl;

    if (p == nullptr) {
        std::cout << "它还没指到任何盒子，现在不能用" << std::endl;
    }

    return 0;
}
p 是空的吗  1
它还没指到任何盒子，现在不能用

p == nullptr 就是在问「它是空的吗」， 跟问「它指着 b 吗」（p == &b）是同一种问法。

那要是不问，直接用呢？

顺着空门牌号找过去，会当场崩掉

就是把 std::cout << *p; 直接写在了判空前面： 

#include <iostream>

int main() {
    int* p = nullptr;

    std::cout << "还没出事" << std::endl;

    std::cout << *p << std::endl;    // 顺着空门牌号找过去

    std::cout << "这一行打不出来了" << std::endl;

    return 0;
}

跑它：

还没出事
段错误（核心已转储）

英文的系统上那句是 Segmentation fault (core dumped)， 意思一样都是段错误。退出码 139。

为什么？空指针的意思是「地址 0」。 内存里 0 号那几格是操作系统自己占着的，专门用来接这种错误—— 你一去碰，它立刻把你拦下来。

而且它崩得很干净：第二个 cout 一个字都没打出来。 程序死在那一行，后面的全没发生。

这份是故意让它崩的，你可以自己跑一下看现场。

但没初始化的指针，不是空的

int* p; 光开盒子不初始化，里面装的是内存里剩下的旧数据—— 一个不知道指着哪儿的地址。基本类型没有构造函数，没人管它 （5.3 讲 int score 为什么不干净，指针是一回事）。

这么写，跑出来的东西就是没法预料的： 

#include <iostream>

int main() {
    int* p;          // 没初始化

    std::cout << "它等于空指针吗  " << (p == nullptr) << std::endl;

    return 0;
}

这台机器上，直接编译跑出来是 0（不是空的）， 加上 -O2 再跑，变成 1。 两个数都出现过，都不是保证——因为「读一个没初始化的指针」 这件事本身就没定义，编译器爱怎么处理怎么处理。

所以别赌。指针一开出来就写清楚： int* p = nullptr;，或者 int* p = &a;。

例题 · 找到就清成 0，没找到就说一声

两个盒子里找一个 5，找到就把那个清成 0。 「可能找不着」这件事，正好用空指针表示： 

#include <iostream>

int main() {
    int a = 3;
    int b = 5;

    int want = 5;
    int* found = nullptr;           // 还没找到

    if (a == want) {
        found = &a;
    } else if (b == want) {
        found = &b;
    }

    if (found == nullptr) {
        std::cout << "没找到 " << want << std::endl;
    } else {
        *found = 0;                 // 改的是 found 指着的那个人
        std::cout << "找到 " << want << " 了，已经清成 0" << std::endl;
        std::cout << "a = " << a << "   b = " << b << std::endl;
    }

    return 0;
}
找到 5 了，已经清成 0
a = 3   b = 0

这一节学的三样，在这儿各占一行：

int* found = nullptr;——一开出来就写清楚， 它的意思是「还没找到」。这是那个 aside 里说的规矩。

found = &b;——找到了就把门牌号装进 found。 装的不是 5，是「5 住在哪儿」。

*found = 0;——先顺着找过去，再改。 所以变成 0 的是 b，a 没动。 那句要是少写一个 *，成了 found = 0;， 就只是把门牌号从 found 里擦掉，b 一点事没有， 跑出来是 a = 3 b = 5。

把 int want = 5; 改成 7 再跑一次，两个 if 都不成立，found 一直是空的，走 else， 打出来是 没找到 7。 「可能没有」是引用做不到的——引用一出生就得绑上谁，没有「空」这一档。 下一节讲三种传参怎么选，就是指望着指针这一手。

6.4值传递 / 地址传递 / 引用传递

这一课不学新东西，把前面学的三样摆在一起看。

三样分别是：3.4 的值传递、3.5 的引用传递、 和上一课的指针——参数写成指针，习惯上叫地址传递。

分开学的时候，每一样都懂。可真到了自己写函数， 参数表那一栏还是会犹豫：这儿到底该写哪个？

三种摆在一起

先看一份最简单的对比。三个函数，函数体一模一样，都是「加一」： 

void byValue(int x)     { x = x + 1; }
void byPointer(int* p)  { *p = *p + 1; }
void byRef(int& x)      { x = x + 1; }

变的只有参数表上那一个符号。int、 int*、int&。

main 里让同一个 a 连着过三道手： 

#include <iostream>

void byValue(int x)     { x = x + 1; }
void byPointer(int* p)  { *p = *p + 1; }
void byRef(int& x)      { x = x + 1; }

int main() {
    int a = 3;

    byValue(a);
    std::cout << "值传递之后    " << a << std::endl;

    byPointer(&a);
    std::cout << "地址传递之后  " << a << std::endl;

    byRef(a);
    std::cout << "引用传递之后  " << a << std::endl;

    return 0;
}

引用传递之后  5

三行读下来就是三种传递的全部区别：

第一行 3——值传递那次白干了。函数里确实加到 4 了， 可加的是抄件，抄件出了函数就没了。

第二行 4——地址传递改到了本人。注意调用那行写的是 byPointer(&a)，得自己把地址递过去。

第三行 5——引用传递也改到了本人。而且调用那行写的是 byRef(a)，跟值传递长得一模一样。

最坑的是第三列和第一列看起来一样。 f(a) 到底是值传递还是引用传递， 光看调用那一行看不出来，得回头看函数怎么定义的。 这是引用传递唯一的缺点，写的时候心里要有数。

该用哪一种

三条就够了，按顺序问下来：

一、函数要不要改外面那个盒子？ 不用改，就用值传递。最简单，最不容易出事， 别人读你的代码也放心——一眼就知道这个函数不会动我的东西。

二、要改，那要不要表达「可能没有」？ 要，就用地址传递。只有指针能是 nullptr （练习 6-8 的 print 就是这种函数： 给它一个盒子就打内容，给它空指针就打「空」）。 不需要表达「没有」，就用引用传递—— 调用处不用写 &，用起来干净。

三、东西很大的时候，别抄。 这一条最容易被忽略，也最值钱。

前面说的「值传递」，代价是抄一份。抄一个 int 无所谓， 可要是抄一个 string、一个装着一万个数的 vector 呢？抄一份就是把这些字符、这些数全搬一遍。

拿 string 试试。函数里把参数的地址打出来， 跟外面那个的地址比一比： 

#include <iostream>
#include <string>

void byValue(std::string s) {
    std::cout << "值传递   函数里的 s 住在 " << &s << std::endl;
    std::cout << "         内容是 " << s << std::endl;
}

void byRef(const std::string& s) {
    std::cout << "引用传递 函数里的 s 住在 " << &s << std::endl;
    std::cout << "         内容是 " << s << std::endl;
}

int main() {
    std::string name = "小明";

    std::cout << "main      name 自己住在 " << &name << std::endl;

    byValue(name);
    byRef(name);

    return 0;
}

跑出来是这样 （地址每次不一样，看的是哪两个相同）： 

main      name 自己住在 0x7ffdca279b50
值传递   函数里的 s 住在 0x7ffdca279b70
         内容是 小明
引用传递 函数里的 s 住在 0x7ffdca279b50
         内容是 小明

第一行和第三行一模一样：byRef 里那个 s 就是 main 里的 name，同一个盒子，没抄。

第二行不一样：byValue 里那个 s 是个新盒子， 住在别的地方，内容是从 name 抄过来的。

这两个函数都只是「打印看看」，谁也不改谁。 那为了不改，就得白抄一遍吗？

不用。给引用加个 const： 

void byRef(const std::string& s)

const 的意思是「只许读，不许改」。 加在引用上，就等于对调用的人说： 我这个函数只是看看，不会动你的东西——而且我也不抄你的。

真想改它，编译器当场拦下 （这儿用 int 写，因为 string 的报错有一大篇， 看着吓人，意思其实一样）： 

#include <iostream>

void show(const int& x) {
    x = 5;                        // 错：x 是只读的
    std::cout << x << std::endl;
}

int main() {
    int a = 3;

    show(a);

    return 0;
}

「assignment of read-only reference」—— 往一个只读的引用里赋值。read-only 就是「只读」。

以后看到 const 加上 &，就这么读

const std::string& s 读作「一个只读的 string 引用」。 它同时说了两件事：不抄（因为是引用）、不改（因为是 const）。

实际代码里这种参数到处都是，现在认得它了。 自己写函数的时候，只要参数是大东西而且不改它，就这么写。

那 int 要不要也写 const int&？

不用。int 只有 4 格，抄一份比递地址还快， 写 const int& 反而绕。

值传递和引用传递在这儿有个分界： 小东西（int、double、char、bool） 直接抄，大东西（string、vector、struct） 传引用。 书上的说法是「要不要抄比抄本身还贵」，就是这个意思。

例题 · 一个函数带回两个结果

#include <string>

}

    int y = 85;

a[i] 和 *(a+i)

既然数组名是首元素的地址，那「第 i 个元素在哪儿」 就能用地址算出来了： 

a 的地址，往后挪 i 个元素，就是 a[i] 的地址

把它写出来，就是这一行： 

a[i]   ==   *(a + i)

右边读作「a 的地址往后挪 i 格，然后把那一格打开」。 左边那个中括号，说白了就是右边的简写。

挪 i 格，是 i 个元素，不是 i 个字节

a + 1 里的那个 1，是「一个元素」的意思， 编译器自己会乘上元素大小——int 就乘 4， double 就乘 8。

拿 6.1 那三个地址对一下： a[0] 在 …dbc，a[1] 在 …dc0。 编号是加了 4，可写的时候写的是 a + 1。 乘 4 这件事编译器替你做了，你别自己乘。 自己乘就成了 *(a + 4)，那是第 4 个元素去了。

所以下面这两行干的事一模一样： 

std::cout << a[i] << std::endl;
std::cout << *(a + i) << std::endl;

这也是 4.2 那句话的完整版。 当时说「下标就是从开头数第几个」， 现在能补全了：数到第几个，就是地址往后挪几格。

字符串：一个地址后面跟着一串字

回到 01 那个老熟人。1.2 你写过 char c = "A"; 被编译器拦下， 它说 invalid conversion from ‘const char*’ to ‘char’， 当时说「那个带星号的东西第 6 部分讲」。就是现在。

双引号里的东西，类型是 const char*—— 一个指针，指着那串字的第一个字符。

int main() {
    const char* s = "abc";

    std::cout << s << std::endl;         // 从 s 指的地方一路打下去
    std::cout << s[1] << std::endl;      // 第二个字符
    std::cout << *(s + 2) << std::endl;  // 跟 s[2] 是一回事

    return 0;
}

s[1] 打出了 b—— 中括号在这儿跟数组里一模一样：往后挪一格打开。

#include <iostream>

int main() {
    const char* s = "abc";

"abc" 只有三个字符，可它占 4 格。 多出来的那一格装着一个 '\0'（读作「空字符」）， 专门用来标「到这儿就完了」。 cout 就是一路打、打到这个记号才停的。

第二行的 8 是 s 这个盒子的大小—— 它只是个指针，跟那串字占几格没关系。

那个 const 是 6.4 学的

const char* s 的意思是「这些字只许读，不许改」。 你试着写 s[0] = 'x';，编译器会拦你。

为什么不让改？因为双引号里那串字是写死在程序里的， 它不在你可以随便写的那块内存里。想改就得换个东西装， 那就是 std::string——第一部分就在用的那个。 std::string 能改，const char* 不能。

「把一个 const char* 变成 char，没有这种转换」。

一个是指针（8 格的盒子），一个是单个字符（1 格）。 拿一个地址往一个字符格子里塞，塞不下也没道理。 那个错误提示最底下还特意写了一行 const char*， 就是告诉你：你递过来的东西是这个类型。

例题 · 自己数一数字符串有多长

那串字末尾藏着一个 '\0'。利用它，可以自己数出这串字有几个字符 ——s[n] 和数组里一样，就是「往后挪 n 格打开」： 

#include <iostream>

int length(const char* s) {
    int n = 0;

    while (s[n] != '\0') {
        n = n + 1;
    }

    return n;
}

int main() {
    const char* a = "hi";
    const char* b = "HelloWorld";

    std::cout << a << " 有 " << length(a) << " 个字符" << std::endl;
    std::cout << b << " 有 " << length(b) << " 个字符" << std::endl;
    std::cout << "sizeof(b) 量出来 " << sizeof(b) << std::endl;

    return 0;
}
hi 有 2 个字符
HelloWorld 有 10 个字符
sizeof(b) 量出来 8

length 里那个循环念一遍就是： 第 n 格还不是结尾记号，就往下一格。 数到碰上 '\0' 停住，n 就是字符个数。 这跟 cout 打那串字时干的事一模一样—— 它就是一路打、打到这个记号才停的。

最后一行是拿来和 sizeof 对一下的： 8 是 b 这个盒子的大小（里面装一个地址，占 8 格）， 10 是那串字本身的长度。两个数之间没有任何关系—— b 只是个门牌号，那串字住在别的地方。

顺带说清一件事：这个 length 是给你看「它是怎么数出来的」， 平时要用直接写 std::string 那个现成的就行（1.1 起就在用了）。

    printAll(a, 3);

    return 0;
}

病根是那一行：

int n = sizeof(a) / sizeof(int);

参数表上写的是 int a[]，看着像个数组， 可它在函数里就是个 int*。 所以 sizeof(a) 是 8，不是 12： 

8 / 4  =  2        // 只走了两圈，第三个数没轮到

编译器其实一直在提醒你：上面那段错着的程序， 一个字不改，就是 6.5 那个框里贴过的那一份， 编出来那句警告也就是那儿的原话—— will return size of ‘int*’， 而且第一行明明白白写着 printAll(int*)。

改法就是 4.x 一直在用的那个：再收一个 n， 个数由调用的人告诉它——所以 main 里传的是 3。

你现在能写什么：第 4 部分留下的那几个坑，你能说清为什么了。 数组名就是首元素的地址，所以 a[i] 等于 *(a + i)， 所以它递进函数会被改到，所以函数里量不出长度、个数得自己递。 你还能读懂 const char* 那一类东西， 也知道 1.2 那个报错到底在说什么。 这一部分从头到尾只讲了两件事：怎么问一个盒子的门牌号，和怎么顺着门牌号找过去。 剩下的全是这两件事的后果。
