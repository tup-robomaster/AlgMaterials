5.1VideoCapture：打开视频

视频文件保存的是按时间排列的一串图像帧，外面还有容器与编码信息。 容器负责把帧、时间戳和索引放在一起，编码器负责压缩每一帧。OpenCV 读文件时不要求调用者处理这些封装细节，读出的每一帧仍然是 cv::Mat，通道顺序仍是 BGR。

视频文件、容器与帧

cv::VideoCapture 负责打开视频源、解码并交出下一帧。打开文件 时给出路径与后端标志： 

cv::VideoCapture cap("../素材/cube.mp4", cv::CAP_ANY);
if (!cap.isOpened()) {
    std::cout << "无法打开视频" << '\n';
    return 1;
}

第二个参数是后端（backend），cv::CAP_ANY 表示让 OpenCV 自行选择。同一台机器上，文件与摄像头可能走不同后端；后端只影响打开方式， 读出的帧仍是 cv::Mat。路径写相对路径时，基准是程序运行时的 工作目录，不是源文件所在目录。从 示例代码 目录运行程序， ../素材/cube.mp4 才指向素材目录。

isOpened() 只在打开动作之后有意义。它返回 true 表示后端已经建立了可读的连接；文件存在但编码器缺失、设备被占用，都会让 它返回 false。打开成功以后，用 cap >> frame 读取下一帧。到达文件末尾、相机断流或解码失败时，frame.empty() 为真。判断结束要用这一条件，不能只看当前帧号。

打开后可以读取元数据。它们都以 double 返回，单位随属性变化：

属性含义单位或说明
CAP_PROP_FRAME_WIDTH帧宽像素
CAP_PROP_FRAME_HEIGHT帧高像素
CAP_PROP_FPS标称帧率帧/秒
CAP_PROP_FRAME_COUNT文件总帧数帧；摄像头通常为 0

属性不被当前后端支持时，get 返回 0，而不是报错。因此看到 宽高为 0，先确认 isOpened()，再确认后端是否提供这项属性。 文件的总帧数也可能因为容器缺少索引而不准确；逐帧读到 empty 才是可靠的结束条件。

元数据与第一帧

素材/cube.mp4 是课程合成的视频：640×480、30 帧每秒、共 90 帧， 画面是一个旋转的线框立方体，位置与颜色固定。下面的程序打开它，打印元数据， 读取第一帧，在帧上写一行摘要并保存为 PNG。

完整程序：

#include <iomanip>
#include <iostream>
#include <string>

#include <opencv2/core.hpp>
#include <opencv2/imgproc.hpp>
#include <opencv2/imgcodecs.hpp>
#include <opencv2/videoio.hpp>

int main() {
    const std::string path = "../素材/cube.mp4";
    cv::VideoCapture cap(path, cv::CAP_ANY);
    if (!cap.isOpened()) {
        std::cout << "无法打开 " << path << '\n';
        return 1;
    }

    const double width = cap.get(cv::CAP_PROP_FRAME_WIDTH);
    const double height = cap.get(cv::CAP_PROP_FRAME_HEIGHT);
    const double fps = cap.get(cv::CAP_PROP_FPS);
    const double frames = cap.get(cv::CAP_PROP_FRAME_COUNT);

    std::cout << "opened=1" << '\n';
    std::cout << "width=" << cvRound(width) << " height=" << cvRound(height)
              << " fps=" << std::fixed << std::setprecision(2) << fps
              << " frames=" << cvRound(frames) << '\n';

    cv::Mat frame;
    cap >> frame;
    if (frame.empty()) {
        std::cout << "读取第一帧失败" << '\n';
        return 1;
    }
    std::cout << "first frame=" << frame.cols << "x" << frame.rows << '\n';
    std::cout << "position=" << cvRound(cap.get(cv::CAP_PROP_POS_FRAMES))
              << '\n';

    cv::Mat shown = frame.clone();
    cv::Mat bar(74, 420, CV_8UC3, cv::Scalar(20, 20, 20));
    bar.copyTo(shown(cv::Rect(14, 14, bar.cols, bar.rows)));
    cv::putText(shown,
                cv::format("%dx%d  %.2f fps  %d frames", frame.cols,
                           frame.rows, fps, cvRound(frames)),
                cv::Point(26, 46), cv::FONT_HERSHEY_SIMPLEX, 0.60,
                cv::Scalar(235, 235, 235), 1, cv::LINE_AA);
    cv::putText(shown, "first frame", cv::Point(26, 76),
                cv::FONT_HERSHEY_SIMPLEX, 0.60, cv::Scalar(120, 220, 255), 1,
                cv::LINE_AA);

    const bool saved = cv::imwrite("../素材/out_first_frame.png", shown);
    std::cout << "saved out_first_frame.png: " << (saved ? "yes" : "no")
              << '\n';
    return 0;
}

opened=1 来自 isOpened()；第二行来自 get：宽 640、高 480、帧率 30.00、总帧数 90；第三行 first frame=640x480 来自 frame.size()。 第一次 cap >> frame 读出第 1 帧，帧尺寸与元数据一致。 position=1 来自 get(CAP_PROP_POS_FRAMES)， 表示下一次读取会从第 2 帧开始：帧号从 0 开始数，读完一帧后位置前进一格。 最后一行来自 imwrite；保存的 out_first_frame.png 是带摘要条的第一帧，不是原视频的副本。

路径与打开失败

打开失败最常见的原因与路径有关。相对路径以运行程序时的目录为基准； 在编辑器里点运行与在终端里先 cd 再运行，工作目录可能不同。 路径中的目录分隔符、文件名大小写与扩展名都要与磁盘一致。文件确实存在， 但当前 OpenCV 构建缺少对应的解码器时，isOpened() 同样返回 false；这类失败不能靠再读一次帧解决。

另一个容易忽略的错误，是把文件路径写成整数。整数会被解释为摄像头索引： cv::VideoCapture cap(0) 尝试打开第 0 号摄像头，而不是名为 0 的文件。反过来，把摄像头索引写成字符串，则会按文件路径 查找。两种写法都能编译，错误只在运行时以 isOpened() == false 的形式出现。

打开失败后不要再调用 get 推测内容，也不要继续读帧。先打印 路径和 isOpened()，确认打开的是预期对象；再检查文件能否被 其他播放器解码。读取循环结束时，VideoCapture 的析构函数会 释放后端资源；需要提前释放或重新打开时，调用 release()。

例题 · 默认构造与打开检查

题目：默认构造一个 VideoCapture，再打开 ../素材/cube.mp4。对两个对象都打印 isOpened()、宽、高、总帧数与帧率，观察未打开对象上的 get 返回什么。

完整程序：

#include <iomanip>
#include <iostream>
#include <string>

#include <opencv2/core.hpp>
#include <opencv2/videoio.hpp>

void report(const std::string& title, cv::VideoCapture& cap) {
    std::cout << title << " opened=" << (cap.isOpened() ? 1 : 0);
    std::cout << " width=" << cvRound(cap.get(cv::CAP_PROP_FRAME_WIDTH));
    std::cout << " height=" << cvRound(cap.get(cv::CAP_PROP_FRAME_HEIGHT));
    std::cout << " frames=" << cvRound(cap.get(cv::CAP_PROP_FRAME_COUNT));
    std::cout << " fps=" << std::fixed << std::setprecision(2)
              << cap.get(cv::CAP_PROP_FPS) << '\n';
}

int main() {
    cv::VideoCapture closed;
    report("closed", closed);

    cv::VideoCapture good("../素材/cube.mp4");
    report("good", good);
    return 0;
}

练习 5-1

打开 ../素材/cube.mp4，打印宽、高、帧率与总帧数；把读取位置 设到第 44 帧，读一帧，打印 set 的返回值、读取后的帧号、 时间戳（毫秒）与画面中心像素的 BGR 值；随后继续读到文件结束，打印从 这一帧起一共解码了多少帧。本题不需要标准输入，数据直接写在 main 里。

预期输出：

seek=1 pos=45 timestamp_ms=1467 center=(51,53,55)
decoded=46
看答案

#include <iostream>

    if (!cap.isOpened()) {
        std::cout << "无法打开视频" << '\n';
        return 1;
    }

    std::cout << "opened=1 width="

              << cvRound(cap.get(cv::CAP_PROP_FRAME_HEIGHT)) << " fps="
              << std::fixed << std::setprecision(2)
              << cap.get(cv::CAP_PROP_FPS) << " frames="
              << cvRound(cap.get(cv::CAP_PROP_FRAME_COUNT)) << '\n';

    cv::Mat frame;
    cap >> frame;
    if (frame.empty()) {
        std::cout << "读取失败" << '\n';
        return 1;

    const cv::Vec3b center =
        frame.at<cv::Vec3b>(frame.rows / 2, frame.cols / 2);
    std::cout << "seek=" << moved
              << " pos=" << cvRound(cap.get(cv::CAP_PROP_POS_FRAMES))
              << " timestamp_ms=" << cvRound(cap.get(cv::CAP_PROP_POS_MSEC))
              << " center=(" << static_cast<int>(center[0]) << ","
              << static_cast<int>(center[1]) << ","
              << static_cast<int>(center[2]) << ")" << '\n';

    while (true) {

        if (frame.empty()) {

5.2摄像头：打开、参数与采集

摄像头与视频文件在代码层几乎是同一个对象：用 VideoCapture 打开，用 operator>> 取下一帧。区别在打开参数与可用属性。 摄像头没有固定的总帧数，分辨率与帧率也由设备支持的模式决定。下面的程序 先尝试摄像头，失败时回退到课程视频，两条路径共用后面的读取、镜像与保存。

设备索引与打开

打开摄像头时，传给构造函数的整数是设备索引。索引 0 表示系统枚举到的第一个 摄像头，1 表示第二个，依此类推。索引不是设备型号，也不保证与机身上的编号 一致。程序不应当假定某个索引一定存在： 

cv::VideoCapture cap;
cap.open(0, cv::CAP_V4L2);
if (!cap.isOpened()) {
    std::cout << "摄像头不可用" << '\n';
}

Linux 上摄像头通常走 V4L2 后端。也可以写 cv::CAP_ANY 让 OpenCV 自选，但部分环境会选中 GStreamer；这些 GStreamer 版本在打开后 设置宽高时可能停掉采集管线，isOpened() 仍为真，后续读取却 全部为空。因此本课先明确指定 CAP_V4L2，打不开时再退回 CAP_ANY。

isOpened() 为真只说明设备已经建立连接，不说明第一帧一定能 按时到达。设备被其他程序占用、索引指向不存在的设备、驱动没有提供可读格式， 都会让打开失败。打开成功但连续读不到帧时，仍要按断流处理，检查 frame.empty()，必要时释放后改用视频文件。

没有摄像头时，后续程序用 --no-camera 跳过设备，直接读取 视频文件；读取、镜像、保存与参数读回的代码与摄像头路径相同。 这样没有硬件的读者也能完成帧循环。

请求参数与实际参数

打开后可以用 set 请求宽、高与帧率。返回值表示后端是否接受了 这次请求，不等同于设备已经按该值输出。设备只支持若干离散分辨率时，请求 1280×720 可能被改成 640×480；自动曝光或带宽限制也可能把实际帧率压低。 因此每次 set 之后都要用 get 读回实际值： 

const bool ok_width = cap.set(cv::CAP_PROP_FRAME_WIDTH, 1280);
const double actual_width = cap.get(cv::CAP_PROP_FRAME_WIDTH);

文件后端通常不支持修改帧尺寸或帧率，set 返回 false，实际值仍是文件本身的值。相机可能接受部分请求，也可能 全部拒绝。后续计算像素坐标、视场或标定参数时，必须使用读回的实际宽高， 不能使用请求值。打印请求值与实际值并排，是排查这类问题最快的方法。

采集、镜像与保存

下面的程序请求 1280×720、30 帧每秒，连续读取 5 帧，保留最后一帧，做左右 镜像，保存单帧快照与两格对比图。没有摄像头或读取不到帧时，程序自动改用 cube.mp4，保证同一段流程可以运行。两条路径默认都会弹出结果 窗口；没有图形界面或做自动核对时，加 --no-window 关闭窗口。

完整程序：

#include <algorithm>
#include <cstring>
#include <iomanip>
#include <iostream>
#include <string>

#include <opencv2/core.hpp>
#include <opencv2/imgproc.hpp>
#include <opencv2/imgcodecs.hpp>
#include <opencv2/highgui.hpp>
#include <opencv2/videoio.hpp>

namespace {

void place(cv::Mat& panel, const cv::Mat& image, int x, int y, int width,
           int height, const std::string& label) {
    const int label_height = 28;
    cv::rectangle(panel, cv::Rect(x, y, width, label_height),
                  cv::Scalar(245, 245, 245), cv::FILLED);
    cv::putText(panel, label, cv::Point(x + 8, y + 20),
                cv::FONT_HERSHEY_SIMPLEX, 0.55, cv::Scalar(30, 30, 30), 1,
                cv::LINE_AA);

    const int inner_width = width - 16;
    const int inner_height = height - label_height - 16;
    const double scale = std::min(static_cast<double>(inner_width) / image.cols,
                                  static_cast<double>(inner_height) / image.rows);
    const int shown_width = std::max(1, cvRound(image.cols * scale));
    const int shown_height = std::max(1, cvRound(image.rows * scale));
    cv::Mat shown;
    cv::resize(image, shown, cv::Size(shown_width, shown_height), 0, 0,
               cv::INTER_AREA);
    const int left = x + (width - shown_width) / 2;
    const int top = y + label_height + (inner_height - shown_height) / 2 + 8;
    shown.copyTo(panel(cv::Rect(left, top, shown_width, shown_height)));
}

}  // namespace

int main(int argc, char** argv) {
    bool try_camera = true;
    bool show_window = true;
    for (int i = 1; i < argc; ++i) {
        if (std::strcmp(argv[i], "--no-camera") == 0) {
            try_camera = false;
        } else if (std::strcmp(argv[i], "--no-window") == 0) {
            show_window = false;
        }
    }

    cv::VideoCapture cap;
    std::string mode = "video";
    if (try_camera) {
        // Linux 上优先用 V4L2。CAP_ANY 可能选中 GStreamer，部分 GStreamer
        // 版本在设置宽高时会停掉采集管线，之后所有帧都为空。
        cap.open(0, cv::CAP_V4L2);
        if (!cap.isOpened()) {
            cap.open(0, cv::CAP_ANY);
        }
        if (cap.isOpened()) {
            mode = "camera";
        } else {
            std::cout << "camera open failed, using video" << '\n';
        }
    }

    if (!cap.isOpened()) {
        mode = "video";
        cap.open("../素材/cube.mp4", cv::CAP_ANY);
    }
    if (!cap.isOpened()) {
        std::cout << "无法打开视频" << '\n';
        return 1;
    }

    const bool set_width = cap.set(cv::CAP_PROP_FRAME_WIDTH, 1280);
    const bool set_height = cap.set(cv::CAP_PROP_FRAME_HEIGHT, 720);
    const bool set_fps = cap.set(cv::CAP_PROP_FPS, 30);

    cv::Mat last;
    int frames = 0;
    for (int i = 0; i < 5; ++i) {
        cv::Mat frame;
        cap >> frame;
        if (frame.empty()) {
            break;
        }
        last = frame.clone();
        ++frames;
    }

    if (frames == 0 && mode == "camera") {
        std::cout << "camera gave no frame, using video" << '\n';
        cap.release();
        cap.open("../素材/cube.mp4", cv::CAP_ANY);
        mode = "video";
        for (int i = 0; i < 5; ++i) {
            cv::Mat frame;
            cap >> frame;
            if (frame.empty()) {
                break;
            }
            last = frame.clone();
            ++frames;
        }
    }

    const double width = cap.get(cv::CAP_PROP_FRAME_WIDTH);
    const double height = cap.get(cv::CAP_PROP_FRAME_HEIGHT);
    const double fps = cap.get(cv::CAP_PROP_FPS);
    std::cout << "mode=" << mode << '\n';
    std::cout << "set width=" << set_width << " height=" << set_height
              << " fps=" << set_fps << '\n';
    std::cout << "requested=1280x720 fps=30.00" << '\n';
    std::cout << "actual=" << cvRound(width) << "x" << cvRound(height)
              << " fps=" << std::fixed << std::setprecision(2) << fps << '\n';
    std::cout << "frames=" << frames << '\n';

    if (last.empty()) {
        std::cout << "没有读到帧" << '\n';
        return 1;
    }

    cv::Mat mirrored;
    cv::flip(last, mirrored, 1);
    const bool saved_jpg = cv::imwrite("../素材/snapshot.jpg", mirrored);

    cv::Mat panel(520, 1280, CV_8UC3, cv::Scalar(255, 255, 255));
    place(panel, last, 0, 0, 640, 520, "last captured frame");
    place(panel, mirrored, 640, 0, 640, 520, "mirrored snapshot");
    const bool saved_png = cv::imwrite("../素材/out_camera.png", panel);

    std::cout << "saved snapshot.jpg: " << (saved_jpg ? "yes" : "no") << '\n';
    std::cout << "saved out_camera.png: " << (saved_png ? "yes" : "no")
              << '\n';

    if (show_window) {
        if (mode == "camera") {
            cv::imshow("snapshot", mirrored);
        } else {
            cv::imshow("camera fallback", panel);
        }
        std::cout << "press any key in the window to close" << '\n';
        cv::waitKey(0);
    }
    return 0;
}

失败处理与释放

摄像头失败通常有四类：设备被其他程序占用，索引指向不存在的设备，请求的 分辨率或像素格式不受支持，以及当前用户没有读取设备的权限。前三类可以在 程序内检测：打开后检查 isOpened()，设置后读回实际值，读取后 检查 empty()。权限问题会表现为打开失败，本课不通过修改系统 配置解决，直接改用视频文件完成同一段流程。

没有摄像头而直接运行 ./camera 时，程序会先尝试设备，失败后 回退到视频。某些后端会把设备错误写到标准错误，终端里因此出现额外的警告； 程序自己的输出仍在标准输出，以 mode=video 开头的那几行为准。 回退不是异常处理的替代品：真实项目应当在界面上说明当前使用的是相机还是 文件，避免把回退画面误当成实时画面。

需要切换设备或重新打开文件时，先调用 release()。同一对象再次 open 也可以，但先释放更容易确认上一路资源已经归还。读取循环 结束后不需要手动释放局部对象，析构函数会处理。

5.3帧循环、按键与帧率

视频处理的主体是一个循环：取一帧，处理一帧，再决定是否继续。循环必须有 明确的结束条件，否则文件读完以后程序会停在原地，或者窗口关不掉。这一课 把读取、显示、按键、暂停与帧率计算放进同一个结构，并用 --no-window 提供一条不依赖窗口的运行路径。

帧循环与退出条件

最基本的循环只依赖 empty()： 

while (true) {
    cv::Mat frame;
    cap >> frame;
    if (frame.empty()) {
        break;
    }
    // 处理 frame
}

文件读到末尾时，operator>> 交出的帧为空；相机断电或断流时 也一样。这个条件同时覆盖正常结束与读取失败，适合作为循环的底线。需要限制 处理数量时，再叠加帧数上限，例如只处理前 100 帧。不要用 CAP_PROP_FRAME_COUNT 作为唯一条件：摄像头通常返回 0，部分容器 的总帧数也不准确。

退出条件还应当包含用户输入。只靠 empty() 的窗口程序，在实时 摄像头下永远不会自己结束，用户必须能按键退出。按键读取与帧读取在同一个 循环里完成，顺序通常是先取帧，再显示，再读键，最后决定是否 break。

按键、暂停与时间戳

cv::waitKey(delay) 等待键盘事件，返回按键的编码；在等待期间 它也让 GUI 有机会刷新窗口。delay 的单位是毫秒：给 1 表示最多 等 1 毫秒，适合连续播放；给 0 表示一直等到有按键。没有按键时返回 -1。 常见按键值是 ESC 的 27、空格 32、字母 q 的 113。

下面的程序播放 cube.mp4。有窗口时按视频帧率控制显示间隔， 按空格切换暂停，按 q 或 ESC 退出；--no-window 跳过显示与按键，只跑解码与计时，用于自动核对。程序在第 1、30、60、90 帧 打印时间戳与帧号，最后打印总耗时与平均帧率。

完整程序：

#include <algorithm>
#include <cmath>
#include <cstring>
#include <iomanip>
#include <iostream>

#include <opencv2/core.hpp>
#include <opencv2/highgui.hpp>
#include <opencv2/videoio.hpp>

int main(int argc, char** argv) {
    bool show_window = true;
    for (int i = 1; i < argc; ++i) {
        if (std::strcmp(argv[i], "--no-window") == 0) {
            show_window = false;
        }
    }

    cv::VideoCapture cap("../素材/cube.mp4", cv::CAP_ANY);
    if (!cap.isOpened()) {
        std::cout << "无法打开视频" << '\n';
        return 1;
    }

    const double fps = cap.get(cv::CAP_PROP_FPS);
    const int total = cvRound(cap.get(cv::CAP_PROP_FRAME_COUNT));
    std::cout << "opened=1 total=" << total << " fps=" << std::fixed
              << std::setprecision(2) << fps << '\n';

    const int delay = std::max(1, cvRound(1000.0 / fps));
    const int64 start = cv::getTickCount();
    int processed = 0;
    bool paused = false;

    while (true) {
        cv::Mat frame;
        cap >> frame;
        if (frame.empty()) {
            break;
        }
        ++processed;

        const int position = cvRound(cap.get(cv::CAP_PROP_POS_FRAMES));
        const int timestamp = cvRound(cap.get(cv::CAP_PROP_POS_MSEC));
        if (position == 1 || position % 30 == 0) {
            std::cout << "sample frame=" << position << " pos=" << position
                      << " timestamp_ms=" << timestamp << '\n';
        }

        if (show_window) {
            cv::imshow("frame loop", frame);
            const int key = cv::waitKey(paused ? 0 : delay);
            if (key == 27 || key == 'q') {
                break;
            }
            if (key == ' ') {
                paused = !paused;
            }
        }
    }

    const int64 end = cv::getTickCount();
    const double elapsed_ms =
        1000.0 * static_cast<double>(end - start) / cv::getTickFrequency();
    const double average_fps =
        elapsed_ms > 0.0 ? processed * 1000.0 / elapsed_ms : 0.0;

    std::cout << "processed=" << processed << " elapsed_ms=" << std::fixed
              << std::setprecision(1) << elapsed_ms
              << " avg_fps=" << std::setprecision(2) << average_fps << '\n';
    if (show_window) {
        cv::destroyAllWindows();
    }
    return 0;
}

窗口模式的操作

直接运行 ./frame_loop 会打开播放窗口。按空格暂停，再按一次 继续；暂停时程序停在 waitKey(0)，不会继续解码。按 q 或 ESC 立即退出。窗口关闭后，程序仍会打印总耗时与平均 帧率。没有图形界面时使用 --no-window，不要反复尝试打开窗口。

waitKey 的返回值要与字符常量比较，不能与字符串比较。窗口没有 获得焦点时，按键可能收不到；这是窗口系统的焦点问题，不是循环写错。若程序 看起来“卡住”，先确认是否在 waitKey(0) 上等待按键。

帧率计算与跳帧

cv::getTickCount() 返回一个单调递增的计数值， cv::getTickFrequency() 返回每秒的计数次数。两者相除得到秒数。 这种计时不依赖系统墙上时钟，适合测量一段代码的耗时。平均帧率用处理的帧数 除以耗时；它统计的是这段循环的吞吐，不是视频文件的标称帧率。

处理速度跟不上输入时，实时相机会在队列里堆积旧帧，导致画面延迟越来越大。 一种做法是主动跳帧：只处理需要的帧，或者每次取最新一帧。文件处理也可以 跳帧，用 cap.set(cv::CAP_PROP_POS_FRAMES, n) 把下一帧的帧号 定位到 n，再读取。定位的单位是帧号，不是毫秒；帧号从 0 开始， 读取得到的是帧号 n 的那一帧，也就是从 1 开始数的第 n+1 帧，读取后位置变为 n+1。

跳帧会改变时间间隔，但不会改变每帧的时间戳。需要真实时间时，仍以 CAP_PROP_POS_MSEC 为准；需要固定处理节奏时，用帧号与标称帧率 计算即可，但要说明这是标称时间。两种时间不要混在同一个变量里。

5.4VideoWriter：保存处理结果

处理完的帧需要按时间顺序存成视频，才能回放或交给下一段程序。 cv::VideoWriter 接收一帧帧 Mat，按指定的编码器、 帧率与尺寸写成文件。写出成功不等于文件可读：编码器是否可用、尺寸是否与帧 一致、是否调用了 release，都会影响最终文件。这一课写出一段 带帧号的视频，再用 VideoCapture 读回核对。

FourCC、尺寸与帧率

FourCC 是四字符编码标识，告诉写入器使用哪一种压缩格式。构造 VideoWriter 时需要四样信息：输出路径、FourCC、帧率与帧尺寸。 路径的扩展名决定容器，FourCC 决定编码器；两者要匹配，例如 mp4v 写 .mp4，MJPG 写 .avi。常用组合如下，能否使用取决于所用机器上 OpenCV 的构建：

FourCC写法常见容器说明
MJPGfourcc('M','J','P','G').avi每帧独立压缩，兼容性好，文件较大
mp4vfourcc('m','p','4','v').mp4MPEG-4 视频，文件较小
XVIDfourcc('X','V','I','D').avi依赖机器上的编码器，可能打不开

帧尺寸必须与后续 write 的每一帧完全相同。写入器不会自动缩放； 尺寸不一致时，有的后端会拒绝写入，有的会写出损坏文件。帧率是写进文件头的 标称值，只影响回放速度，不控制程序实际写得多快。用 15 帧每秒写入 90 帧， 文件播放约 6 秒，与程序运行耗时无关。

构造完成后先检查 isOpened()。返回 false 时， 常见原因是 FourCC 在当前机器上不可用、扩展名与容器不匹配，或者输出目录不可写。 这时不要继续调用 write，否则可能得到空文件而没有明确报错。

录像与常见错误

摄像头录像使用同一套写入流程：先读一帧，取得实际宽高，用这组尺寸构造 VideoWriter，之后每读一帧就写一帧。不要在第一次读取之前用 请求值构造写入器：相机可能给出不同的实际尺寸，写出的第一帧就会尺寸不符。 停止录像时先退出读取循环，再 release 写入器。

常见错误有四种。第一，写入尺寸与帧尺寸不一致；第二，帧率写成 0 或负数， 文件头无效；第三，FourCC 在当前机器上不可用，isOpened() 已经返回 false，程序仍继续写；第四，程序异常退出或提前 return， 没有调用 release，文件尾缺失。前三种可以在写循环之前检查， 第四种要把释放放进所有退出路径。

5.5采集与处理分离

采集一帧和处理一帧的耗时通常不相等。相机按固定节奏出图，处理可能因为 检测、滤波或写文件而变慢。如果读取和处理写在同一个循环里，处理慢就会让 相机缓冲区堆积，画面延迟越来越大。把采集与处理分成两个角色，中间用有界 队列传递帧，是常见的结构。下面说明这两个角色如何分工、帧的所有权如何 转移，以及队列满时怎样取舍。

生产者、消费者与队列

采集端是生产者，负责尽快把相机里的帧取出来；处理端是消费者，按自己的速度 从队列取帧。队列有容量上限，满了以后必须做选择：丢掉最旧的一帧，或者让 生产者等待。前一种选择保持低延迟，但会丢失中间帧；后一种选择不丢帧，但会 把压力传回相机，降低采集帧率。两种选择都没有绝对优劣，取决于任务更在意 实时性还是完整性。 

采集端:
    while running:
        frame = camera.read()
        queue.push(frame.clone())
        if queue.size() > capacity:
            queue.pop_front()

处理端:
    while running:
        if queue.empty():
            continue
        frame = queue.pop_front()
        result = process(frame)

队列里存的是帧的副本或所有权，不是相机缓冲区的裸地址。真实的多线程程序 还需要同步队列的读写。理解上面两段的分工与丢帧条件之后，再学线程、 互斥量与条件变量时，就知道每一步在保护什么。

浅拷贝与 clone

cv::Mat 的赋值与拷贝构造是浅拷贝：两个对象共享同一块像素数据， 只各自保存一份头部。相机后端经常复用同一块缓冲区，下一次取图会覆盖上一帧 的内容。如果把浅拷贝得到的 Mat 放进队列，消费者拿到的对象会 在生产者下一次写入时改变，读到的可能已经不是入队时的那一帧。

下面的程序用一块 Mat 模拟相机缓冲区：先浅拷贝一份放进队列， 再深拷贝一份作为存档；随后修改原缓冲区，比较三个对象看到的像素与 data 指针。

完整程序：

#include <iostream>

#include <opencv2/core.hpp>

int main() {
    cv::Mat camera_buffer(2, 4, CV_8UC3, cv::Scalar(1, 2, 3));
    cv::Mat queued = camera_buffer;
    cv::Mat snapshot = camera_buffer.clone();

    camera_buffer.setTo(cv::Scalar(9, 9, 9));

    const cv::Vec3b camera_pixel = camera_buffer.at<cv::Vec3b>(0, 0);
    const cv::Vec3b queued_pixel = queued.at<cv::Vec3b>(0, 0);
    const cv::Vec3b snapshot_pixel = snapshot.at<cv::Vec3b>(0, 0);

    std::cout << "camera=(" << static_cast<int>(camera_pixel[0]) << ","
              << static_cast<int>(camera_pixel[1]) << ","
              << static_cast<int>(camera_pixel[2]) << ")"
              << " queued=(" << static_cast<int>(queued_pixel[0]) << ","
              << static_cast<int>(queued_pixel[1]) << ","
              << static_cast<int>(queued_pixel[2]) << ")"
              << " snapshot=(" << static_cast<int>(snapshot_pixel[0]) << ","
              << static_cast<int>(snapshot_pixel[1]) << ","
              << static_cast<int>(snapshot_pixel[2]) << ")" << '\n';

    std::cout << "data camera=" << static_cast<const void*>(camera_buffer.data)
              << " queued=" << static_cast<const void*>(queued.data)
              << " snapshot=" << static_cast<const void*>(snapshot.data)
              << '\n';
    std::cout << "share queued="
              << (queued.data == camera_buffer.data ? "yes" : "no")
              << " snapshot="
              << (snapshot.data == camera_buffer.data ? "yes" : "no") << '\n';
    std::cout << "queued size=" << queued.cols << "x" << queued.rows
              << " step=" << queued.step[0] << '\n';
    return 0;
}

丢旧帧与背压

有界队列满时，丢掉最旧的一帧（drop-oldest）可以让消费者总是拿到较新的画面， 代价是丢失中间帧，帧号不连续。让生产者等待（背压，backpressure）可以保留 每一帧，代价是采集节奏被处理速度拖慢，实时相机可能因此丢帧或超时。选择 哪一种，要看下游是“必须看到每一帧”还是“必须看到当前画面”。

队列长度决定允许的延迟上限。容量为 3、每帧处理耗时 30 毫秒时，最坏情况下 消费者手里的帧比相机晚约 90 毫秒。容量越大，抗抖动能力越强，延迟也越大。 帧进入队列时记录帧号与时间戳，消费时就能判断当前帧有多旧；只记录图像而不 记录时间，无法区分“处理慢”和“相机本来就在出旧图”。

例题 · 丢旧帧队列

题目：用容量为 3 的 std::deque<cv::Mat> 模拟有界队列。 依次产生编号 0 到 4 的 5 帧，每帧是一个 1×1 的灰度图，像素值等于编号； 入队前 clone，超过容量时丢掉队首。打印每次入队后的队列长度 与累计丢弃数，最后依次出队并打印帧号与剩余长度。

完整程序：

#include <cstddef>
#include <deque>
#include <iostream>

#include <opencv2/core.hpp>

int main() {
    const std::size_t capacity = 3;
    std::deque<cv::Mat> queue;
    int dropped = 0;

    for (int id = 0; id < 5; ++id) {
        cv::Mat frame(1, 1, CV_8UC1, cv::Scalar(id));
        queue.push_back(frame.clone());
        if (queue.size() > capacity) {
            queue.pop_front();
            ++dropped;
        }
        std::cout << "pushed=" << id << " size=" << queue.size()
                  << " dropped=" << dropped << '\n';
    }

    while (!queue.empty()) {
        const cv::Mat frame = queue.front();
        queue.pop_front();
        std::cout << "pop=" << static_cast<int>(frame.at<uchar>(0, 0))
                  << " left=" << queue.size() << '\n';
    }
    return 0;
}

5.6工业相机 SDK：从取图到 Mat

工业相机的厂商 SDK 接口各不相同，但取图流程大体相同：初始化、枚举设备、 打开、设置参数、开始采集、取一帧、包装成 Mat、停止采集、关闭。 这一课用普通内存模拟相机缓冲区，把流程中最容易出错的两步——缓冲区包装 与 Bayer 转换——写成可以运行的程序。

取图流程

下表列出每一步的作用与常见返回值。不同 SDK 的函数名与错误码不同，顺序与 资源归属基本相同。

包装缓冲区与 Bayer

cv::Mat(rows, cols, type, data, step) 用外部内存构造头部， 不复制像素。第四个参数是数据首地址，第五个参数是每一行占用的字节数 （step），不是像素数。相机为了对齐，常在每行末尾补几个字节；此时 step 大于 cols × elemSize。只按宽度计算步长， 第二行起就会错位。省略 step 时 OpenCV 按连续存储处理，只适用 于没有行填充的缓冲区。

彩色工业相机常输出 Bayer 格式：每个像素只保存 R、G、B 中的一个分量， 排列成 2×2 重复单元。常见排列的首行是 R G、第二行 G B，记为 RGGB。 显示或处理前要用 cvtColor 做去马赛克（demosaicing），把单通道 Bayer 图还原成三通道 BGR。排列顺序必须与相机一致，写错会偏色。

OpenCV 的旧常量名与首行排列并不一致：头文件注明 COLOR_BayerBG2BGR 等价于 RGGB，COLOR_BayerRG2BGR 等价于 BGGR。首行 R G、第二行 G B 的 RGGB 排列应使用 COLOR_BayerBG2BGR；若按首行写成 COLOR_BayerRG2BGR，红蓝通道会互换。OpenCV 还提供按排列命名的 别名 COLOR_BayerRGGB2BGR，它等于 COLOR_BayerBG2BGR。下面的程序使用旧名，便于与常见示例对照。

namespace {

void place(cv::Mat& panel, const cv::Mat& image, int x, int y, int width,
           int height, const std::string& label) {
    const int label_height = 28;
    cv::rectangle(panel, cv::Rect(x, y, width, label_height),
                  cv::Scalar(245, 245, 245), cv::FILLED);
    cv::putText(panel, label, cv::Point(x + 8, y + 20),
                cv::FONT_HERSHEY_SIMPLEX, 0.55, cv::Scalar(30, 30, 30), 1,
                cv::LINE_AA);

    const int inner_width = width - 16;
    const int inner_height = height - label_height - 16;
    const double scale = std::min(static_cast<double>(inner_width) / image.cols,
                                  static_cast<double>(inner_height) / image.rows);
    const int shown_width = std::max(1, cvRound(image.cols * scale));
    const int shown_height = std::max(1, cvRound(image.rows * scale));
    cv::Mat shown;
    cv::resize(image, shown, cv::Size(shown_width, shown_height), 0, 0,
               cv::INTER_NEAREST);
    const int left = x + (width - shown_width) / 2;
    const int top = y + label_height + (inner_height - shown_height) / 2 + 8;
    shown.copyTo(panel(cv::Rect(left, top, shown_width, shown_height)));
}

cv::Mat mosaicRG(const cv::Mat& bgr) {
    cv::Mat bayer(bgr.rows, bgr.cols, CV_8UC1);
    for (int y = 0; y < bgr.rows; ++y) {
        for (int x = 0; x < bgr.cols; ++x) {

                value = pixel[1];
            }

缓冲区归属与错误

借用型缓冲区最常见的错误，是把 Mat 存进队列后继续取图。 SDK 复用同一块内存，队列里的对象会在下一次取图时被覆盖；表面上是队列里的 帧“自己变了”，实际是数据被生产者重写。回调型接口还有一层限制：回调返回后， 地址可能立即失效，不能在回调里只保存裸指针。解决方式是复制、及时处理， 或者使用 SDK 提供的缓冲区引用计数。

第二类错误与步长有关。行填充让 step 大于有效字节数 cols × elemSize()；如果包装时把像素宽度直接当字节步长， 第二行开始就会读到上一行的填充字节，图像出现斜向错位。 第三类错误是 Bayer 顺序写错，红蓝互换或整体偏绿。第四类错误是取图超时 没有处理，程序在等待一帧时永久阻塞。四类错误都不会在编译时暴露，必须靠 尺寸、颜色与超时返回值检查。

5.7相机参数与像素格式

相机输出的像素值不是场景亮度的直接复制。曝光时间决定感光元件积累光量的 时长，增益把电信号放大，白平衡调整三个颜色通道的比例，帧率决定每秒输出 多少帧。像素格式则决定这些数值怎样排布成字节。参数与格式设置错，后面的 阈值、轮廓与测量都会建立在失真的数据上。这一课用合成图模拟这些影响，并 说明常见格式与位深。

曝光、增益与白平衡

曝光时间（exposure time）是传感器积分光信号的时间，单位通常是毫秒或微秒。 时间加倍，画面大致亮一倍；运动目标在长曝光下会出现拖影。增益（gain）在 读出信号后放大数值，能提亮画面，也会把噪声一起放大；增益加倍不等于曝光 时间加倍，后者还能收集更多光子，前者只是放大已有信号。两者都可以设成自动 模式，但自动模式会随场景变化，做阈值或测量时通常锁定。

帧率与曝光时间相互制约：一帧的曝光时间不能超过帧周期。30 帧每秒的帧周期 约 33 毫秒，曝光时间设为 40 毫秒就无法维持 30 帧。提高帧率通常要缩短曝光 或降低分辨率，画面会更暗或细节更少。白平衡（white balance）调整 R、B 通道的相对增益，使白色物体在不同光源下仍接近白色；自动白平衡会让同一块 颜色在画面中缓慢漂移，颜色检测前应固定或记录其状态。

感兴趣区域（ROI，region of interest）让相机只输出画面的一部分，可以提高 帧率、减少传输量。ROI 的左上角成为新的像素原点，主点位置随之改变。之前 在整幅图上得到的相机内参不能直接继续使用；需要按新原点修正，或者重新标定。 改动 ROI 以后，像素坐标、视场与测量结果都要按新的几何关系重新核对。

模拟曝光与增益

下面的程序构造一张合成场景，用 convertTo 模拟曝光变化， 用固定种子的高斯噪声模拟高增益，打印每种情况的平均亮度与过曝像素数， 并把四幅图拼成一张对比图。噪声种子固定，重复运行得到相同结果。

namespace {

void place(cv::Mat& panel, const cv::Mat& image, int x, int y, int width,
           int height, const std::string& label) {
    const int label_height = 28;
    cv::rectangle(panel, cv::Rect(x, y, width, label_height),
                  cv::Scalar(245, 245, 245), cv::FILLED);
    cv::putText(panel, label, cv::Point(x + 8, y + 20),
                cv::FONT_HERSHEY_SIMPLEX, 0.55, cv::Scalar(30, 30, 30), 1,
                cv::LINE_AA);

    const int inner_width = width - 16;
    const int inner_height = height - label_height - 16;
    const double scale = std::min(static_cast<double>(inner_width) / image.cols,
                                  static_cast<double>(inner_height) / image.rows);
    const int shown_width = std::max(1, cvRound(image.cols * scale));
    const int shown_height = std::max(1, cvRound(image.rows * scale));
    cv::Mat shown;
    cv::resize(image, shown, cv::Size(shown_width, shown_height), 0, 0,
               cv::INTER_AREA);
    const int left = x + (width - shown_width) / 2;
    const int top = y + label_height + (inner_height - shown_height) / 2 + 8;
    shown.copyTo(panel(cv::Rect(left, top, shown_width, shown_height)));
}

cv::Mat makeScene() {
    cv::Mat scene(240, 320, CV_8UC3);
    for (int y = 0; y < scene.rows; ++y) {
        const int value = 35 + y * 90 / scene.rows;
        scene.row(y).setTo(cv::Scalar(value, value, value));
    }
    cv::rectangle(scene, cv::Rect(24, 30, 90, 70), cv::Scalar(40, 40, 210),
                  cv::FILLED);
    cv::rectangle(scene, cv::Rect(150, 40, 80, 80), cv::Scalar(40, 200, 60),
                  cv::FILLED);
    cv::circle(scene, cv::Point(95, 170), 44, cv::Scalar(230, 230, 230),
               cv::FILLED, cv::LINE_AA);
    cv::circle(scene, cv::Point(235, 175), 38, cv::Scalar(25, 25, 25),
               cv::FILLED, cv::LINE_AA);
    return scene;
}

void report(const std::string& name, const cv::Mat& image) {
    cv::Mat gray;
    cv::cvtColor(image, gray, cv::COLOR_BGR2GRAY);
    cv::Mat clipped;
    cv::threshold(gray, clipped, 249, 255, cv::THRESH_BINARY);
    std::cout << name << " mean=" << cvRound(cv::mean(gray)[0])
              << " clipped=" << cv::countNonZero(clipped) << '\n';
}

}  // namespace

int main() {
    const cv::Mat scene = makeScene();

    cv::Mat bright;
    scene.convertTo(bright, CV_8UC3, 4.0, 0.0);
    cv::Mat dark;
    scene.convertTo(dark, CV_8UC3, 0.25, 0.0);

    cv::RNG rng(12345);
    cv::Mat noise(scene.size(), CV_32FC3);
    rng.fill(noise, cv::RNG::NORMAL, 0.0, 18.0);
    cv::Mat scene_float;
    scene.convertTo(scene_float, CV_32FC3);
    const cv::Mat noisy_float = scene_float + noise;
    cv::Mat noisy;
    noisy_float.convertTo(noisy, CV_8UC3);

    report("normal", scene);
    report("exposure x4", bright);
    report("exposure x0.25", dark);
    report("gain high", noisy);

    cv::Mat panel(300, 1040, CV_8UC3, cv::Scalar(255, 255, 255));
    place(panel, scene, 0, 0, 260, 300, "normal");
    place(panel, bright, 260, 0, 260, 300, "exposure x4");
    place(panel, dark, 520, 0, 260, 300, "exposure x0.25");
    place(panel, noisy, 780, 0, 260, 300, "gain high + noise");
    const bool saved = cv::imwrite("../素材/out_exposure.png", panel);
    std::cout << "saved out_exposure.png: " << (saved ? "yes" : "no")
              << '\n';

    const cv::Mat mono8(2, 2, CV_8UC1, cv::Scalar(128));
    const cv::Mat mono12(2, 2, CV_16UC1, cv::Scalar(2048));
    const cv::Mat bgr8(2, 2, CV_8UC3, cv::Scalar(10, 20, 30));
    std::cout << "mono8 type=" << mono8.type()
              << " channels=" << mono8.channels() << " elem="
              << mono8.elemSize() << '\n';
    std::cout << "mono12 type=" << mono12.type()
              << " channels=" << mono12.channels() << " elem="
              << mono12.elemSize() << '\n';
    std::cout << "bgr8 type=" << bgr8.type()
              << " channels=" << bgr8.channels() << " elem="
              << bgr8.elemSize() << '\n';

    const std::vector<int> twelve = {0, 1023, 2047, 4095};
    std::cout << "mono12 to mono8:";
    for (const int value : twelve) {
        std::cout << " " << value << "->"
                  << cvRound(value * 255.0 / 4095.0);
    }
    std::cout << '\n';
    return 0;
}

像素格式与位深

像素格式描述每个像素怎样存储。下表列出常见格式与 OpenCV 中的对应类型。 类型值可以打印，但阅读代码时更常用 CV_8UC1 这样的写法：

格式每像素内容常见 Mat 类型说明
Mono81 个 8 位灰度CV_8UC1范围 0–255
Mono10 / Mono121 个 10 或 12 位灰度CV_16UC1常放在 16 位字中，范围 0–1023 或 0–4095
Bayer RG / GR / GB / BG每个像素 1 个颜色分量CV_8UC1需去马赛克还原 BGR

YUV422亮度与色度共用采样CV_8UC2常见 YUYV 排列，转换后才能按 BGR 处理

10 位与 12 位数据有两种存法。非打包（unpacked）格式把每个值放进一个 16 位 字，低 10 位或低 12 位有效，高位补 0；这种数据可以直接用 CV_16UC1 读取，但数值范围不是 0–255，不能直接交给按 8 位 设计的阈值。打包（packed）格式把多个像素的值压进连续字节，例如两个 12 位 值占 3 个字节；这种数据不能直接按 CV_16UC1 解释，必须先解包。

把 12 位数据缩放到 8 位，常用 value × 255 / 4095；10 位用 value × 255 / 1023。直接用 convertTo 指定 CV_8UC1 而不给缩放系数，会把大部分值截成 255，画面几乎全白。 反过来，把 10 位数据当 8 位读，字节会错位，图像出现条纹或噪声。位深、打包 方式与类型三者必须一起确认。

参数与格式的错误

第一类错误是把 10 位或 12 位数据直接当作 0–255 使用。阈值 100 在 12 位 图里只相当于很暗的区域，画面大部分会被判为前景。第二类错误是 Bayer 顺序 与转换常量不匹配，红蓝互换或整体偏绿，类型检查发现不了。第三类错误是 ROI 原点偏移没有计入，像素坐标与之前的内参对不上，测距与投影都会偏。 第四类错误是自动曝光与自动白平衡在采集过程中变化，同一批图的颜色与亮度 不可比。做定量测量前固定这些参数，并记录固定值。

参数不是越高越好。曝光提高会过曝，增益提高会放大噪声，帧率提高会缩短曝光， ROI 缩小会改变几何关系。每次只改一个参数，保存一组对照图，记录平均亮度、 过曝像素比例与噪声水平，再决定下一组值。只凭肉眼在显示器上判断，容易把 亮度变化误当成颜色变化。

例题 · 打包与解包

题目：把 4 个 12 位像素值 100、1000、2000、4095 按每两个值占 3 个字节 打包，打印 6 个字节；再解包回 4 个值，打印并检查是否与原值一致。最后 打印 CV_16UC1 的类型值、通道数与元素大小，以及 10 位、12 位 中间值缩放到 8 位的结果。

完整程序：

#include <iostream>
#include <vector>

#include <opencv2/core.hpp>

namespace {

void packPair(std::vector<uchar>& bytes, std::size_t offset, int first,
              int second) {
    bytes[offset] = static_cast<uchar>(first & 0xFF);
    bytes[offset + 1] = static_cast<uchar>(((first >> 8) & 0x0F) |
                                           ((second & 0x0F) << 4));
    bytes[offset + 2] = static_cast<uchar>((second >> 4) & 0xFF);
}

}  // namespace

int main() {
    const std::vector<int> values = {100, 1000, 2000, 4095};
    std::vector<uchar> packed(6, 0);
    packPair(packed, 0, values[0], values[1]);
    packPair(packed, 3, values[2], values[3]);

    std::cout << "packed bytes:";
    for (const uchar byte : packed) {
        std::cout << " " << static_cast<int>(byte);
    }
    std::cout << '\n';

    const int first = packed[0] | ((packed[1] & 0x0F) << 8);
    const int second = ((packed[1] >> 4) & 0x0F) | (packed[2] << 4);
    const int third = packed[3] | ((packed[4] & 0x0F) << 8);
    const int fourth = ((packed[4] >> 4) & 0x0F) | (packed[5] << 4);
    std::cout << "unpacked=" << first << " " << second << " " << third << " "
              << fourth << '\n';
    std::cout << "match="
              << (first == values[0] && second == values[1] &&
                          third == values[2] && fourth == values[3]
                      ? "yes"
                      : "no")
              << '\n';

    cv::Mat mono12(1, 4, CV_16UC1);
    for (int i = 0; i < 4; ++i) {
        mono12.at<ushort>(0, i) = static_cast<ushort>(values[i]);
    }
    std::cout << "mono12 type=" << mono12.type()
              << " channels=" << mono12.channels()
              << " elem=" << mono12.elemSize() << '\n';
    std::cout << "mono10 512->8bit: " << cvRound(512 * 255.0 / 1023.0) << '\n';
    std::cout << "mono12 2048->8bit: " << cvRound(2048 * 255.0 / 4095.0)
              << '\n';
    return 0;
}
