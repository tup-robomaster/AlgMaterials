服务与参数

服务是一次请求、一次响应的调用；参数是节点在运行期间可以读取与修改的 键值配置。这一部分先写服务端与客户端，再定义自己的服务类型， 最后用命令行与参数文件修改节点行为。

2.1服务端

服务（service）采用请求—响应模型：客户端发送一次请求（request）， 服务端（server）的回调处理这次请求，写回一次响应（response）， 调用结束。与话题不同，服务端不持续发布数据，客户端也不订阅； 一次调用对应一次回调，调用方在收到响应之前一直等待。

请求与响应

服务由名称和类型共同确定。名称是话题图中的标识，类型决定请求与响应 各有哪些字段。课程沿用 example_interfaces/srv/AddTwoInts： 请求有两个 64 位整数字段 a 与 b， 响应有一个 64 位整数字段 sum。 

int64 a
int64 b
---
int64 sum

文件中的 --- 把请求字段与响应字段分开。生成的头文件里， 请求类型是 AddTwoInts::Request，响应类型是 AddTwoInts::Response，两者都可以用 std::make_shared 创建。

创建服务端与回调

create_service<类型>(名称, 回调) 在节点上注册一个服务。 名称 add_two_ints 是相对名称，节点在根命名空间时解析为 /add_two_ints。返回值是 rclcpp::Service<…>::SharedPtr，必须存成节点成员， 否则注册的服务会随局部变量一起销毁。 

service_ = create_service<example_interfaces::srv::AddTwoInts>(
  "add_two_ints",
  [this](
    const std::shared_ptr<example_interfaces::srv::AddTwoInts::Request> request,
    std::shared_ptr<example_interfaces::srv::AddTwoInts::Response> response) {
    response->sum = request->a + request->b;
  });

回调的两个参数都是共享指针。请求由中间件填好，回调只读；响应由回调 写入，回调返回后由中间件发回调用方。回调的返回类型是 void， 结果通过 response 传递。日志在回调里记录请求与响应， 便于对照客户端看到的内容。 

#include <memory>

#include "example_interfaces/srv/add_two_ints.hpp"
#include "rclcpp/rclcpp.hpp"

class AddServer : public rclcpp::Node
{
public:
  AddServer()
  : Node("add_server")
  {
    service_ = create_service<example_interfaces::srv::AddTwoInts>(
      "add_two_ints",
      [this](
        const std::shared_ptr<example_interfaces::srv::AddTwoInts::Request> request,
        std::shared_ptr<example_interfaces::srv::AddTwoInts::Response> response) {
        response->sum = request->a + request->b;
        RCLCPP_INFO(get_logger(), "request: %ld + %ld", request->a, request->b);
        RCLCPP_INFO(get_logger(), "response: %ld", response->sum);
      });
  }

private:
  rclcpp::Service<example_interfaces::srv::AddTwoInts>::SharedPtr service_;
};

int main(int argc, char ** argv)
{
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<AddServer>());
  rclcpp::shutdown();
  return 0;
}

2.2客户端

客户端（client）向服务名发起请求，等待响应。客户端不持有服务端的对象， 只通过名称与类型找到服务；服务端没有启动时，请求无法送达。 这一课写一个请求 5 + 3 的客户端，打印响应后退出。

创建客户端

create_client<类型>(名称) 创建客户端，返回 rclcpp::Client<…>::SharedPtr。名称必须与服务端注册的 名称一致，类型也必须一致；名称相同而类型不同时，两端不会匹配。 

client_ = create_client<example_interfaces::srv::AddTwoInts>("add_two_ints");

创建客户端不会等待服务端。服务端可能尚未启动，也可能在调用过程中退出， 因此发送请求之前要先确认服务可用。

等待与读取响应

wait_for_service(1s) 最多等待 1 秒，返回布尔值。返回 false 说明这段时间内没有发现同名服务，此时应记录明确的 错误并结束，不要继续发送请求。

async_send_request(request) 立即返回一个 future。 spin_until_future_complete(node, future) 让执行器处理回调， 直到 future 就绪或超时；返回 rclcpp::FutureReturnCode::SUCCESS 时，用 future.get() 取出响应。响应字段的读取方式与请求相同。 

#include <chrono>
#include <memory>

#include "example_interfaces/srv/add_two_ints.hpp"
#include "rclcpp/rclcpp.hpp"

using namespace std::chrono_literals;

class AddClient : public rclcpp::Node
{
public:
  AddClient()
  : Node("add_client")
  {
    client_ = create_client<example_interfaces::srv::AddTwoInts>("add_two_ints");
  }

  bool call(int64_t a, int64_t b)
  {
    if (!client_->wait_for_service(1s)) {
      RCLCPP_ERROR(get_logger(), "service /add_two_ints not available after 1s");
      return false;
    }

    auto request = std::make_shared<example_interfaces::srv::AddTwoInts::Request>();
    request->a = a;
    request->b = b;
    auto future = client_->async_send_request(request);
    if (rclcpp::spin_until_future_complete(shared_from_this(), future) !=
      rclcpp::FutureReturnCode::SUCCESS)
    {
      RCLCPP_ERROR(get_logger(), "request failed");
      return false;
    }

    auto response = future.get();
    RCLCPP_INFO(get_logger(), "request: %ld + %ld", a, b);
    RCLCPP_INFO(get_logger(), "response: %ld", response->sum);
    return true;
  }

private:
  rclcpp::Client<example_interfaces::srv::AddTwoInts>::SharedPtr client_;
};

int main(int argc, char ** argv)
{
  rclcpp::init(argc, argv);
  auto node = std::make_shared<AddClient>();
  const bool ok = node->call(5, 3);
  rclcpp::shutdown();
  return ok ? 0 : 1;
}

练习 2-4

写一个客户端：节点名取 missing_client，向不存在的服务 missing_service 请求，等待 1 秒后打印明确错误并正常退出。错误文本为 service /missing_service not available after 1s。

[ERROR] [missing_client]: service /missing_service not available after 1s
看答案

客户端只等待，不发送请求。超时后 wait_for_service 返回 false，程序打印错误并返回 0，因此脚本正常结束。 错误文本与题目一致，服务名带前导斜杠。 

#include <chrono>
#include <memory>

{
public:

  : Node("missing_client")
  {
    client_ = create_client<example_interfaces::srv::AddTwoInts>("missing_service");
  }

  bool wait()
  {
    return client_->wait_for_service(1s);
  }

private:
  rclcpp::Client<example_interfaces::srv::AddTwoInts>::SharedPtr client_;
};

int main(int argc, char ** argv)
{
  rclcpp::init(argc, argv);

2.3自定义服务

自定义服务把请求与响应的字段写进 .srv 文件，由接口包生成 头文件，服务端与客户端都使用生成后的类型。这一课新增矩形面积服务， 并用一次失败的输入说明为什么要在服务端校验。

.srv 文件

.srv 文件分两部分：--- 之前是请求字段， 之后是响应字段。字段的写法与 .msg 相同，每行先写类型， 再写字段名。类型可以是内置类型或消息类型。 

float64 width
float64 height
---
float64 area
string message

这个文件生成 robot_interfaces/srv/ComputeArea 类型。 请求有 width 与 height 两个 float64 字段，响应有 area 与 message。响应同时返回数值与说明，调用方不必只凭数值 猜测失败原因。

构建接口包

在接口包的 CMakeLists.txt 中，把新文件加入 rosidl_generate_interfaces 的列表： 

"srv/ComputeArea.srv"

然后重新构建接口包与节点包。接口包先生成消息、服务与动作的头文件， 节点包编译时才能找到 robot_interfaces/srv/compute_area.hpp。 

# 当前目录：$HOME/ros2_ws
colcon build --symlink-install --packages-select robot_interfaces robot_nodes

生成的头文件路径由包名与文件名决定：srv/ComputeArea.srv 生成 robot_interfaces/srv/compute_area.hpp，类型名保留 驼峰写法 ComputeArea。服务端与客户端使用同一个类型， 字段顺序与 .srv 文件一致。

输入校验

服务端收到的字段来自调用方，不能假定取值合法。矩形面积在宽度或高度 为负数时没有几何意义，在任一维度为零时面积为零。服务端应当在回调里 判断这些情况，把错误写进响应字段，而不是把负面积原样返回。这类检查 称为输入校验（input validation）。

下面的例题先不校验：客户端发送 3.0 × 4.0 与 -2.0 × 3.0 两次请求，第二次得到 -6.00。 练习 2-6 会补上校验。 

#include <memory>

#include "rclcpp/rclcpp.hpp"
#include "robot_interfaces/srv/compute_area.hpp"

class AreaServer : public rclcpp::Node
{
public:
  AreaServer()
  : Node("area_server")
  {
    service_ = create_service<robot_interfaces::srv::ComputeArea>(
      "compute_area",
      [this](
        const std::shared_ptr<robot_interfaces::srv::ComputeArea::Request> request,
        std::shared_ptr<robot_interfaces::srv::ComputeArea::Response> response) {
        response->area = request->width * request->height;
        response->message = "ok";
        RCLCPP_INFO(
          get_logger(), "request: %.2f x %.2f", request->width, request->height);
        RCLCPP_INFO(
          get_logger(), "response: area=%.2f message=%s",
          response->area, response->message.c_str());
      });
  }

private:
  rclcpp::Service<robot_interfaces::srv::ComputeArea>::SharedPtr service_;
};

int main(int argc, char ** argv)
{
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<AreaServer>());
  rclcpp::shutdown();
  return 0;
}
#include <chrono>
#include <memory>

#include "rclcpp/rclcpp.hpp"
#include "robot_interfaces/srv/compute_area.hpp"

using namespace std::chrono_literals;

class AreaClient : public rclcpp::Node
{
public:
  AreaClient()
  : Node("area_client")
  {
    client_ = create_client<robot_interfaces::srv::ComputeArea>("compute_area");
  }

  bool call(double width, double height)
  {
    if (!client_->wait_for_service(1s)) {
      RCLCPP_ERROR(get_logger(), "service /compute_area not available after 1s");
      return false;
    }

    auto request = std::make_shared<robot_interfaces::srv::ComputeArea::Request>();
    request->width = width;
    request->height = height;
    auto future = client_->async_send_request(request);
    if (rclcpp::spin_until_future_complete(shared_from_this(), future) !=
      rclcpp::FutureReturnCode::SUCCESS)
    {
      RCLCPP_ERROR(get_logger(), "request failed");
      return false;
    }

    auto response = future.get();
    RCLCPP_INFO(
      get_logger(), "area: %.2f m^2 message: %s",
      response->area, response->message.c_str());
    return true;
  }

private:
  rclcpp::Client<robot_interfaces::srv::ComputeArea>::SharedPtr client_;
};

{

2.4参数

参数（parameter）是节点上的键值配置，有名称、类型与默认值。参数属于 某个节点，不同节点的同名参数互不影响。节点在启动时声明参数， 运行时可以通过命令行读取与修改。

声明与读取

declare_parameter<T>(名称, 默认值) 声明一个参数并 返回当前值。参数必须先声明才能读取，未声明的名称不会出现在参数列表中。 声明时的类型决定后续赋值允许的类型，例如 int 参数 不能赋字符串。 

rate_ms_ = declare_parameter<int>("rate_ms", 500);
message_ = declare_parameter<std::string>("message", "hello");

已经声明的参数用 get_parameter("名称") 读取， 返回值是 rclcpp::Parameter，用 as_int、 as_string 等方法取值。get_parameter_or 在参数不存在时返回给定的备用值，适合读取可选配置。

命令行读写

ros2 param list 列出节点声明的参数， ros2 param get 读取一个参数的值， ros2 param set 修改一个参数。参数名相对于节点名， 命令行用 /节点名 指定节点。

列表中除了代码声明的 rate_ms 与 message， 还会出现 use_sim_time、start_type_description_service 与若干 qos_overrides。这些由框架在节点创建时声明， 不是本节点的业务参数。

参数回调

add_on_set_parameters_callback 注册一个回调，在参数被修改 之前执行。回调收到本次要修改的参数列表，返回 rcl_interfaces::msg::SetParametersResult：successful 为 true 时修改生效，为 false 时修改被拒绝， reason 会显示给调用方。

回调在参数值写入之前执行，因此拒绝时参数保持原值。回调里可以按名称 分支处理，也可以对一次修改多个参数的情况逐项检查；任何一项不合法， 整个请求都应被拒绝。 

#include <memory>
#include <string>
#include <vector>

#include "rcl_interfaces/msg/set_parameters_result.hpp"
#include "rclcpp/rclcpp.hpp"

class ParameterNode : public rclcpp::Node
{
public:
  ParameterNode()
  : Node("parameter_node"), rate_ms_(500), message_("hello")
  {
    rate_ms_ = declare_parameter<int>("rate_ms", rate_ms_);
    message_ = declare_parameter<std::string>("message", message_);
    RCLCPP_INFO(
      get_logger(), "startup: rate_ms=%d message='%s'", rate_ms_, message_.c_str());

    callback_handle_ = add_on_set_parameters_callback(
      [this](const std::vector<rclcpp::Parameter> & parameters) {
        rcl_interfaces::msg::SetParametersResult result;
        result.successful = true;
        for (const auto & parameter : parameters) {
          RCLCPP_INFO(
            get_logger(), "set: %s=%s",
            parameter.get_name().c_str(), parameter.value_to_string().c_str());
          if (parameter.get_name() == "rate_ms") {
            rate_ms_ = parameter.as_int();
          } else if (parameter.get_name() == "message") {
            message_ = parameter.as_string();
          }
        }
        return result;
      });
  }

private:
  int rate_ms_;
  std::string message_;
  rclcpp::node_interfaces::OnSetParametersCallbackHandle::SharedPtr callback_handle_;
};

int main(int argc, char ** argv)
{
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<ParameterNode>());
  rclcpp::shutdown();
  return 0;
}

2.5参数文件与动态修改

参数文件把多个节点的参数写在同一个 YAML 文件里，启动时一次加载。 参数在运行期间仍可通过命令行修改；节点是否随参数改变行为，取决于 代码是否在回调里使用新值。这一课的节点按 rate_ms 周期发布 message，修改参数后立即生效。

YAML 层级

参数文件的第一层是节点名，第二层固定为 ros__parameters， 第三层是参数键值。节点名要与运行时的节点名一致；缩进用两个空格， 不能用制表符。值的类型由写法决定：整数、浮点数、布尔值与带引号的 字符串分别解析。 

param_demo:
  ros__parameters:
    rate_ms: 200
    message: "from file"

这个文件只配置了 param_demo 一个节点， rate_ms 为 200，message 为 from file。一份文件可以写多个节点，每个节点各有一段 ros__parameters；练习 2-9 会写两个节点。

加载与覆盖

--ros-args --params-file 文件路径 让节点启动时读取参数 文件。节点只读取代码中已经声明的参数，文件里的键要与声明一致。

命令行 -p 名称:=值 与参数文件同名时，命令行优先。 下面的例题同时给出参数文件与 -p message:=changed， 节点最终使用 changed；文件里的 from file 被覆盖。ros2 param dump 导出的是当前值，不是文件原文。

动态修改

参数在运行期间可以修改，这类参数称为动态参数（dynamic parameter）。节点要响应修改， 需要在参数回调里更新成员变量，并让使用该变量的代码重新读取。 例题的节点在 rate_ms 改变时取消旧定时器并按新周期重建， 在 message 改变时更新下一条消息的内容。

若节点只在启动时读取一次参数，之后不再检查，参数虽然能改，节点行为 不会变化。声明参数与使用参数是两件事：前者让参数出现在列表中， 后者决定修改是否产生效果。 

#include <chrono>
#include <memory>
#include <string>
#include <vector>

#include "rcl_interfaces/msg/set_parameters_result.hpp"
#include "rclcpp/rclcpp.hpp"
#include "std_msgs/msg/string.hpp"

class ParamDemo : public rclcpp::Node
{
public:
  ParamDemo()
  : Node("param_demo"), rate_ms_(500), message_("tick")
  {
    rate_ms_ = declare_parameter<int>("rate_ms", rate_ms_);
    message_ = declare_parameter<std::string>("message", message_);
    publisher_ = create_publisher<std_msgs::msg::String>("param_chatter", 10);
    timer_ = create_wall_timer(
      std::chrono::milliseconds(rate_ms_), [this]() { publish_tick(); });
    RCLCPP_INFO(
      get_logger(), "startup: rate_ms=%d message='%s'", rate_ms_, message_.c_str());

    callback_handle_ = add_on_set_parameters_callback(
      [this](const std::vector<rclcpp::Parameter> & parameters) {
        rcl_interfaces::msg::SetParametersResult result;
        result.successful = true;
        for (const auto & parameter : parameters) {
          if (parameter.get_name() == "rate_ms") {
            rate_ms_ = parameter.as_int();
            timer_->cancel();
            timer_ = create_wall_timer(
              std::chrono::milliseconds(rate_ms_), [this]() { publish_tick(); });
            RCLCPP_INFO(get_logger(), "timer reset: rate_ms=%d", rate_ms_);
          } else if (parameter.get_name() == "message") {
            message_ = parameter.as_string();
            RCLCPP_INFO(get_logger(), "message: '%s'", message_.c_str());
          }
        }
        return result;
      });
  }

private:
  void publish_tick()
  {
    std_msgs::msg::String message;
    message.data = message_;
    publisher_->publish(message);
  }

  int rate_ms_;
  std::string message_;
  rclcpp::Publisher<std_msgs::msg::String>::SharedPtr publisher_;
  rclcpp::TimerBase::SharedPtr timer_;
  rclcpp::node_interfaces::OnSetParametersCallbackHandle::SharedPtr callback_handle_;
};

int main(int argc, char ** argv)
{
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<ParamDemo>());
  rclcpp::shutdown();
  return 0;
}

用 2.5 的参数文件启动 param_demo，同时在命令行加 -p message:=command，再用 ros2 param dump 导出当前参数。指出哪一项被命令行覆盖，以及 rate_ms 的来源。

/param_demo:
  ros__parameters:
    message: command
    qos_overrides:
      /parameter_events:
        publisher:
          depth: 1000
          durability: volatile
          history: keep_last
          reliability: reliable
    rate_ms: 200
    start_type_description_service: true
    use_sim_time: false
看答案

参数文件里的 rate_ms 是 200，message 是 from file；命令行用 -p message:=command 覆盖后者。导出结果中 message 为 command， rate_ms 仍为 200，说明单项覆盖只改指定参数。 qos_overrides 与 start_type_description_service 是节点运行时自动登记的，不在参数文件里。 

# 当前目录：$HOME/ros2_ws
params="$(ros2 pkg prefix robot_nodes)/share/robot_nodes/config/params.yaml"
ros2 run robot_nodes param_demo --ros-args \
  --params-file "$params" -p message:=command &
sleep 2
ros2 param dump /param_demo
/param_demo:
  ros__parameters:
    message: command
    qos_overrides:
      /parameter_events:
        publisher:
          depth: 1000
          durability: volatile
          history: keep_last
          reliability: reliable
    rate_ms: 200
    start_type_description_service: true
    use_sim_time: false

你现在能写什么：写参数文件并按节点名分层，用参数文件启动节点，用命令行覆盖其中一项，导出当前参数并解释每个值的来源。
