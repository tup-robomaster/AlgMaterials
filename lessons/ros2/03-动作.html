第 3 部分

动作

动作用于持续一段时间、需要报告进度的任务。客户端发送目标， 服务端周期发布反馈，结束时返回结果；任务进行中可以取消。 这一部分定义动作接口，写服务端与客户端，处理取消与超时， 最后用命令行观察目标、反馈与结果。

3.1动作接口与目标、反馈、结果

话题持续传递数据，服务完成一次短调用；两者都不适合描述“执行一段时间、 期间报告进度、可以中途停止”的任务。动作（action）为这类任务提供目标 （goal）、反馈（feedback）与结果（result）三种消息，并支持取消（cancel） 与抢占（preemption）。

长任务与动作

客户端发送一个目标，服务端在接受后开始执行。执行期间，服务端可以按 固定周期发布反馈，客户端据此更新进度；执行结束后，服务端返回结果。 一个目标只能有一个最终状态：成功、取消或中止。

动作建立在服务与话题之上：发送目标、取消目标与获取结果走服务， 反馈与状态走话题。这些底层端点由 rclcpp_action 创建， 调用方不需要手动管理。

三段结构

动作接口（action interface）由 .action 文件定义，按固定顺序 写三段：第一段是目标字段，第二段是结果字段，第三段是反馈字段，段与段 之间用 --- 分隔。 顺序不能交换：生成器按“目标、结果、反馈”依次读取。 

int32 steps
---
bool success
---
int32 remaining

这个接口描述一次巡逻：目标是要走的步数 steps，结果是 是否成功 success，反馈是剩余步数 remaining。 结果只在结束时发送一次，反馈在执行期间可以发送多次。

查看动作接口

ros2 interface show 打印接口文件的内容， ros2 action list -t 列出当前动作及类型， ros2 action info 显示某个动作的服务端与客户端数量。 生成的头文件位于 robot_interfaces/action/patrol.hpp， 类型名是 robot_interfaces::action::Patrol。

3.2动作服务端

动作服务端（action server）接收目标、决定是否接受、执行任务并返回结果。 rclcpp_action::create_server 注册三个回调：目标到达时调用 handle_goal，取消请求到达时调用 handle_cancel， 目标被接受后调用 handle_accepted。

三个回调

handle_goal 返回 ACCEPT_AND_EXECUTE 或 REJECT。拒绝时目标不会进入执行；接受时继续调用 handle_accepted。这个回调应当快速返回，不能在里执行 长时间任务。

handle_cancel 返回 ACCEPT 或 REJECT。接受取消只是允许取消，真正的停止仍要在 execute 中检查 is_canceling 并退出循环。

handle_accepted 在目标被接受后执行，负责启动任务。 例题把执行放进独立线程，避免长时间循环阻塞执行器处理其它回调； 同时用 busy_ 标记当前有目标在执行。

执行与结果

execute 接收目标句柄（goal handle），按目标参数执行任务。每完成一步， 先检查 is_canceling；没有取消时发布反馈。全部完成后调用 succeed(result)，无法完成时调用 abort(result)， 被取消时调用 canceled(result)。三个调用只能选一个， 并且只能调用一次。

例题的 handle_goal 拒绝步数非正的目标，也拒绝在已有目标 执行时到达的新目标；后者对应 3.4 的“拒绝”策略。 

#include <atomic>
#include <chrono>
#include <memory>
#include <thread>

#include "rclcpp/rclcpp.hpp"
#include "rclcpp_action/rclcpp_action.hpp"
#include "robot_interfaces/action/patrol.hpp"

using namespace std::chrono_literals;

class PatrolServer : public rclcpp::Node
{
public:
  using Patrol = robot_interfaces::action::Patrol;
  using GoalHandlePatrol = rclcpp_action::ServerGoalHandle<Patrol>;

  PatrolServer()
  : Node("patrol_server"), busy_(false)
  {
    server_ = rclcpp_action::create_server<Patrol>(
      this,
      "patrol",
      [this](
        const rclcpp_action::GoalUUID & uuid,
        std::shared_ptr<const Patrol::Goal> goal) {
        return handle_goal(uuid, goal);
      },
      [this](const std::shared_ptr<GoalHandlePatrol> goal_handle) {
        return handle_cancel(goal_handle);
      },
      [this](const std::shared_ptr<GoalHandlePatrol> goal_handle) {
        handle_accepted(goal_handle);
      });
  }

private:
  rclcpp_action::GoalResponse handle_goal(
    const rclcpp_action::GoalUUID &,
    std::shared_ptr<const Patrol::Goal> goal)
  {
    if (goal->steps <= 0) {
      RCLCPP_INFO(get_logger(), "goal rejected: steps=%d", goal->steps);
      return rclcpp_action::GoalResponse::REJECT;
    }
    if (busy_.load()) {
      RCLCPP_INFO(get_logger(), "goal rejected: another patrol is running");
      return rclcpp_action::GoalResponse::REJECT;
    }
    RCLCPP_INFO(get_logger(), "goal accepted: steps=%d", goal->steps);
    return rclcpp_action::GoalResponse::ACCEPT_AND_EXECUTE;
  }

  rclcpp_action::CancelResponse handle_cancel(
    const std::shared_ptr<GoalHandlePatrol> goal_handle)
  {
    RCLCPP_INFO(
      get_logger(), "cancel requested: steps=%d",
      goal_handle->get_goal()->steps);
    return rclcpp_action::CancelResponse::ACCEPT;
  }

  void handle_accepted(const std::shared_ptr<GoalHandlePatrol> goal_handle)
  {
    busy_.store(true);
    std::thread{&PatrolServer::execute, this, goal_handle}.detach();
  }

  void execute(const std::shared_ptr<GoalHandlePatrol> goal_handle)
  {
    const auto goal = goal_handle->get_goal();
    auto feedback = std::make_shared<Patrol::Feedback>();
    auto result = std::make_shared<Patrol::Result>();

    for (int32_t remaining = goal->steps - 1; remaining >= 0; --remaining) {
      std::this_thread::sleep_for(1s);
      if (goal_handle->is_canceling()) {
        result->success = false;
        busy_.store(false);
        goal_handle->canceled(result);
        RCLCPP_INFO(get_logger(), "goal canceled");
        return;
      }
      feedback->remaining = remaining;
      goal_handle->publish_feedback(feedback);
      RCLCPP_INFO(get_logger(), "feedback: remaining=%d", remaining);
    }

    result->success = true;
    busy_.store(false);
    goal_handle->succeed(result);
    RCLCPP_INFO(get_logger(), "goal succeeded");
  }

  rclcpp_action::Server<Patrol>::SharedPtr server_;
  std::atomic<bool> busy_;
};

int main(int argc, char ** argv)
{
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<PatrolServer>());
  rclcpp::shutdown();
  return 0;
}

看答案

练习 3-4

写一个服务端：接受所有目标，但目标步数小于等于 0 时在执行阶段直接中止，结果 success 为 false，并打印 goal aborted: steps=值。用发送 0 步目标的客户端观察最终状态。

看答案

#include <chrono>
#include <memory>

#include "rclcpp/rclcpp.hpp"
#include "rclcpp_action/rclcpp_action.hpp"
#include "robot_interfaces/action/patrol.hpp"

using namespace std::chrono_literals;

class InvalidClient : public rclcpp::Node
{
public:
  using Patrol = robot_interfaces::action::Patrol;
  using GoalHandlePatrol = rclcpp_action::ClientGoalHandle<Patrol>;

  InvalidClient()
  : Node("invalid_client")
  {
    client_ = rclcpp_action::create_client<Patrol>(this, "patrol");
  }

  bool send(int32_t steps)
  {
    if (!client_->wait_for_action_server(2s)) {
      RCLCPP_ERROR(get_logger(), "action server /patrol not available after 2s");
      return false;
    }

    auto goal = Patrol::Goal();
    goal.steps = steps;

    auto options = rclcpp_action::Client<Patrol>::SendGoalOptions();
    options.result_callback = [this](const GoalHandlePatrol::WrappedResult & result) {
      if (result.code == rclcpp_action::ResultCode::ABORTED) {
        RCLCPP_INFO(get_logger(), "result: aborted");
      } else if (result.code == rclcpp_action::ResultCode::CANCELED) {
        RCLCPP_INFO(get_logger(), "result: canceled");
      } else {
        RCLCPP_INFO(get_logger(), "result: success");
      }
    };

    auto goal_future = client_->async_send_goal(goal, options);
    if (rclcpp::spin_until_future_complete(shared_from_this(), goal_future) !=
      rclcpp::FutureReturnCode::SUCCESS)
    {
      RCLCPP_ERROR(get_logger(), "send goal failed");
      return false;
    }
    auto goal_handle = goal_future.get();
    if (!goal_handle) {
      RCLCPP_INFO(get_logger(), "goal rejected");
      return false;
    }
    RCLCPP_INFO(get_logger(), "goal accepted");

    auto result_future = client_->async_get_result(goal_handle);
    if (rclcpp::spin_until_future_complete(shared_from_this(), result_future) !=
      rclcpp::FutureReturnCode::SUCCESS)
    {
      RCLCPP_ERROR(get_logger(), "get result failed");
      return false;
    }
    return true;
  }

private:
  rclcpp_action::Client<Patrol>::SharedPtr client_;
};

int main(int argc, char ** argv)
{
  rclcpp::init(argc, argv);
  auto node = std::make_shared<InvalidClient>();

3.3动作客户端

动作客户端（action client）发送目标，接收反馈，等待结果。与服务客户端 相同，客户端只通过名称与类型找到服务端；不同之处是目标被接受后， 客户端还要等待执行结束，期间持续接收反馈。

发送目标

create_client<动作类型>(名称) 创建客户端； wait_for_action_server(2s) 等待服务端就绪，返回布尔值。 未就绪时不应发送目标。

async_send_goal(goal, options) 返回一个 future，结果为 目标句柄。句柄为空表示目标被拒绝。options 里可以设置 反馈回调与结果回调，两者都在执行器处理消息时调用。

反馈与结果

反馈回调的签名是 (GoalHandle::SharedPtr, std::shared_ptr<const Feedback>)， 第二个参数是本次反馈消息。结果回调收到 WrappedResult，其中 code 是最终状态， result 是结果消息。

发送目标后，用 async_get_result(goal_handle) 取得结果的 future，再调用 spin_until_future_complete 等待。等待期间 执行器同时处理反馈，因此反馈回调会在结果之前多次执行。

3.4取消、超时与抢占

取消（cancel）由客户端发起，服务端决定是否接受，并在执行循环中检查。 客户端还可以为等待结果设定时限，超时（timeout）后取消目标。新目标在 旧目标执行期间到达时，服务端可以选择拒绝、排队或抢占。

取消

客户端调用 async_cancel_goal(goal_handle) 发送取消请求。 服务端的 handle_cancel 返回 ACCEPT 后， execute 中的 is_canceling() 变为真； 执行循环检查到取消即退出，并调用 canceled(result)， 客户端收到 ResultCode::CANCELED。

取消采用协作式（cooperative）机制：服务端不检查 is_canceling 时，取消请求不会让循环停止。检查的位置决定最多多执行多久；例题在每次发布反馈 之前检查，因此取消后最多再等一个周期。

超时

客户端可以在目标接受后计时，到达时限仍未结束就取消。例题在目标接受 后固定等待 100 毫秒再发送取消；服务端第一个周期是 1 秒，因此取消在 第一次反馈之前到达，客户端不会收到反馈，最终状态是 CANCELED。

新目标

同一时间只处理一个目标时，新目标到达需要处理。例题采用拒绝策略： busy_ 为真时 handle_goal 返回 REJECT，并打印 goal rejected: another patrol is running。排队与抢占是 另外两种策略，分别对应等待旧目标结束与中止旧目标。

      if (result.code == rclcpp_action::ResultCode::CANCELED) {
        RCLCPP_INFO(get_logger(), "final status: CANCELED");
      } else if (result.code == rclcpp_action::ResultCode::SUCCEEDED) {
        RCLCPP_INFO(get_logger(), "final status: SUCCEEDED");
      } else {
        RCLCPP_INFO(get_logger(), "final status: ABORTED");
      }
    };

    auto goal_future = client_->async_send_goal(goal, options);
    if (rclcpp::spin_until_future_complete(shared_from_this(), goal_future) !=
      rclcpp::FutureReturnCode::SUCCESS)
    {
      RCLCPP_ERROR(get_logger(), "send goal failed");
      return false;
    }
    auto goal_handle = goal_future.get();
    if (!goal_handle) {
      RCLCPP_ERROR(get_logger(), "goal rejected");
      return false;
    }
    RCLCPP_INFO(get_logger(), "goal accepted");

    std::this_thread::sleep_for(100ms);
    RCLCPP_INFO(get_logger(), "cancel requested after 100ms");
    client_->async_cancel_goal(goal_handle);

    auto result_future = client_->async_get_result(goal_handle);
    if (rclcpp::spin_until_future_complete(shared_from_this(), result_future) !=
      rclcpp::FutureReturnCode::SUCCESS)
    {
      RCLCPP_ERROR(get_logger(), "get result failed");
      return false;
    }
    return true;
  }

private:
  rclcpp_action::Client<Patrol>::SharedPtr client_;
};

int main(int argc, char ** argv)
{
  rclcpp::init(argc, argv);
  auto node = std::make_shared<TimeoutCancelClient>();
  const bool ok = node->send(10);
  rclcpp::shutdown();
  return ok ? 0 : 1;
}

你现在能写什么：在客户端发起取消，在服务端检查取消并返回取消状态，为等待结果设定时限，并说明新目标到达时的三种处理策略。

3.5动作诊断

动作的诊断入口与话题、服务不同：先看动作名称与类型，再看服务端是否 存在，最后用命令行发送目标观察反馈与结果。动作的底层话题与服务端点 由框架管理，通常不直接操作。

命令行工具

ros2 action list -t 列出动作名称与类型； ros2 action info /patrol 显示服务端与客户端数量； ros2 action send_goal 名称 类型 "{字段: 值}" --feedback 发送目标并持续打印反馈。命令行的结果与客户端看到的结果应当一致。

命令行输出中的目标 ID 由运行时生成，每次不同。页面与答案里的输出 把它写成 <goal-id>，其余字段与真实输出一致。

排查顺序

第一步用 ros2 action list -t 确认动作存在且类型正确； 第二步用 ros2 action info 确认服务端数量不为 0； 第三步用 send_goal 观察反馈与结果。动作不存在时，先查 服务端节点是否启动、动作名是否被命名空间改写；类型不匹配时，命令行 无法解析目标字段。

与话题相比，动作多了一层“服务端是否接受目标”的判断：端点存在不代表 目标会被接受，handle_goal 的拒绝也会让调用失败。与服务 相比，动作的反馈是持续到达的，诊断时要同时看反馈顺序与最终状态。
