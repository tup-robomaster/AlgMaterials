第 5 部分

Launch 与组合

一个机器人系统通常由多个节点、参数与启动配置组成。启动文件把启动命令写成 文件，一次启动多个节点；组件把多个节点放入同一个进程，减少进程与通信开销。 这一部分先写 XML 与 Python 两种启动文件，再讲参数、命名空间、条件与包含， 最后加载可组合节点。

终端位置

本页命令默认在课程工作空间 $HOME/ros2_ws 中执行；开头标有 # 当前目录：课程目录 的命令在本页所在目录执行，该目录包含 示例代码/。新开终端先进入工作空间并加载环境：

cd $HOME/ros2_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash
export ROS_DOMAIN_ID=42
export RCUTILS_CONSOLE_OUTPUT_FORMAT='[{severity}] [{name}]: {message}'

需要清掉旧的构建产物时，在 $HOME/ros2_ws 中执行下面的命令， 再重新构建： 

# 当前目录：$HOME/ros2_ws
bash clean.sh
前置

先读过 0.4、1.1、1.2 与 2.4：会创建功能包与节点，会写发布者与订阅者， 会在启动时设置节点参数。启动文件本身不引入新的通信方式。

5.1XML launch

启动文件（launch file）把一组节点的启动方式写成文件：启动哪些可执行文件、 给每个节点取什么名字、设置哪些参数、输出到哪里。一个终端运行 ros2 launch，就能同时启动这些节点，不需要为每个节点各开一个终端。

启动文件

XML 启动文件以 <launch> 为根，里面放节点、参数、 包含与条件等标签。文件放在功能包的 launch/ 目录下， 构建后安装到 share/<包名>/launch/； ros2 launch 按包名与文件名在该目录中查找。

节点动作

<node> 是最常用的标签。pkg 指定功能包， exec 指定可执行文件名，name 指定节点名， output="screen" 把节点的标准输出与标准错误转发到启动终端。 省略 output 时，节点日志默认写入日志文件，终端只看到启动器 自己的提示。

运行与日志

启动器会为每个节点分配一个进程编号，并在日志行前加上 [可执行文件名-序号]。启动器本身还会打印日志目录与进程编号， 这些内容随机器变化，不适合作为教材输出；下面只保留节点自己的日志行， 命令里用 grep 过滤。 

<launch>
  <node pkg="robot_nodes" exec="talker" name="talker" output="screen"/>
</launch>
例题 · talker.launch.xml

启动文件只包含一个节点：运行 robot_nodes 里的 talker，节点名为 talker，输出转发到终端。 节点发布三条消息后自行退出。 

# 当前目录：$HOME/ros2_ws
ros2 launch robot_bringup talker.launch.xml 2>&1 \
  | grep -E '^\[talker-[0-9]+\] \[INFO\]'
[talker-1] [INFO] [talker]: publishing: 'hello 0'
[talker-1] [INFO] [talker]: publishing: 'hello 1'
[talker-1] [INFO] [talker]: publishing: 'hello 2'

三行都以 [talker-1] 开头，说明它们来自同一个节点进程。 talker 的源码在到达计数上限后调用 rclcpp::shutdown， 节点退出，启动器也随之结束。

5.2Python launch

Python 启动文件是一个普通的 Python 模块。启动器导入模块，调用 generate_launch_description()，得到一份启动描述 （launch description）；描述里按顺序列出要执行的动作。

描述对象

LaunchDescription 接收一个动作列表。最常用的动作是 launch_ros.actions.Node，字段与 XML 的 <node> 对应：package、executable、 name、output。

Node 动作

Node 在启动时解析为一个进程动作。启动器为它分配的名称来自 可执行文件名，而不是节点名；节点名只影响节点在 ROS 图中的名称与日志器名。 因此把 name 改成别的值后，日志前缀仍是可执行文件名。

两种写法

XML 与 Python 两种启动文件表达同一组动作。XML 适合结构固定的启动配置； Python 可以在生成描述时做计算、读环境变量或按条件拼接动作列表。 同一个功能包可以同时提供两种文件。 

from launch import LaunchDescription
from launch_ros.actions import Node


def generate_launch_description():
    return LaunchDescription([
        Node(
            package='robot_nodes',
            executable='hello_node',
            name='hello_node',
            output='screen',
        ),
    ])

5.3参数与命名空间

同一个可执行文件可以启动多次。每次启动给一个命名空间（namespace）与节点名， 它们在 ROS 图中的完全限定名就互不相同，订阅、发布与服务也不会重名。 启动文件可以在启动时同时设置这些名称与节点参数。

命名空间

namespace="left" 与 name="param_left" 组合成完全 限定名 /left/param_left。命名空间以斜杠开头时按绝对路径解释； 不以斜杠开头时，拼在父命名空间之后。启动文件里写相对名称， 通常更便于把整组节点放进另一个命名空间。

节点参数

<param name="rate_ms" value="300"/> 给该节点设置参数 rate_ms。启动文件里的 value 写成字符串， 节点声明参数时给出类型，ROS 2 按声明类型解析：声明为整数时 "300" 解析为 300，声明为字符串时保持字符串。

查询

节点运行后，用 ros2 node list 查看完全限定名，用 ros2 param get 读取参数当前值。同一个可执行文件的两个实例 可以给同名参数设置不同的值，参数按节点分开保存。 

<launch>
  <node pkg="robot_nodes" exec="parameter_node"
        name="param_left" namespace="left" output="screen">
    <param name="rate_ms" value="300"/>
    <param name="message" value="left"/>
  </node>
  <node pkg="robot_nodes" exec="parameter_node"
        name="param_right" namespace="right" output="screen">
    <param name="rate_ms" value="500"/>
    <param name="message" value="right"/>
  </node>
</launch>
例题 · 两个参数节点

在一个终端启动这份文件；它在 /left 与 /right 两个命名空间下各运行一个 parameter_node。在另一个终端执行 下面的查询。 

# 终端一（$HOME/ros2_ws）

查询完全限定名与四个参数值：

# 终端二（$HOME/ros2_ws）

ros2 param get /left/param_left rate_ms
ros2 param get /right/param_right message

/left/param_left
/right/param_right
String value is: left
Integer value is: 300
String value is: right

两个节点来自同一个可执行文件，但完全限定名不同，参数也各自保存： /left/param_left 的消息是 left、周期是 300 毫秒， /right/param_right 的消息是 right、周期是 500 毫秒。查询结束后回到启动终端，按 Ctrl+C 停止两个节点。

5.4条件与包含

启动文件可以接受命令行参数，并按参数选择要执行的动作。多个启动文件还可以 互相包含：公共部分写在一份文件里，另一份文件只负责组合。

参数与变量

<arg name="with_hello" default="true"/> 声明一个启动参数， 命令行用 with_hello:=false 覆盖默认值。 $(var with_hello) 取出参数值，作为条件表达式的一部分。

include

<include file="..."/> 把另一份启动文件的内容插入当前位置。 $(find-pkg-share robot_bringup) 在运行时解析为已安装功能包的 共享目录，因此不依赖源码目录的位置。

if 与 unless

if="$(var with_hello)" 在参数为真时执行该动作， unless="$(var with_hello)" 在参数为假时执行。两个条件互斥， 一次启动只会走其中一条分支。条件也可以写在 <node> 上。 

<launch>
  <arg name="with_hello" default="true"/>
  <include file="$(find-pkg-share robot_bringup)/launch/hello.launch.xml"
           if="$(var with_hello)"/>
  <node pkg="robot_nodes" exec="talker" name="talker" output="screen"
        unless="$(var with_hello)"/>
</launch>

被包含的 hello.launch.xml 只启动一个 hello_node： 

<launch>
  <node pkg="robot_nodes" exec="hello_node" name="hello_node" output="screen"/>
</launch>

5.5组件（选学）

组合（composition）把多个节点装进同一个进程。每个节点仍是一个独立的 rclcpp::Node，但共享进程内的执行器与通信中间件资源， 进程间通信的开销因此减少。组件（component）是可按需加载的共享库， 由组件容器（component container）在运行时装入。

组合

容器本身是一个节点进程，提供 /ComponentManager 等管理接口。 启动容器时不指定具体节点；之后用命令行或启动文件把组件加载进去。 一个容器可以先后加载多个组件，每个组件都可以取自己的节点名。

注册与构建

可组合节点与普通节点的区别在构造函数：它接收 const rclcpp::NodeOptions &，并把它传给基类。 源文件用 RCLCPP_COMPONENTS_REGISTER_NODE 注册类名； CMake 用 add_library(... SHARED) 生成共享库， 再用 rclcpp_components_register_nodes 声明插件名。 类放在命名空间里时，注册名要带命名空间，加载命令也用同一个全名。

加载与查看

ros2 component types 列出环境中所有可用组件； ros2 component load <容器> <包名> <插件名> 把组件装入容器；ros2 component list 查看容器与已加载的节点。 加载成功后，组件发布的话题与普通节点相同，可以直接用 ros2 topic echo 订阅。 

#include <chrono>
#include <memory>
#include <string>

#include "rclcpp/rclcpp.hpp"
#include "rclcpp_components/register_node_macro.hpp"
#include "std_msgs/msg/string.hpp"

using namespace std::chrono_literals;

namespace robot_nodes
{

class TalkerComponent : public rclcpp::Node
{
public:
  explicit TalkerComponent(const rclcpp::NodeOptions & options)
  : Node("talker_component", options), count_(0)
  {
    publisher_ = create_publisher<std_msgs::msg::String>("component_chatter", 10);
    timer_ = create_wall_timer(500ms, [this]() {
      std_msgs::msg::String message;
      message.data = "component " + std::to_string(count_);
      publisher_->publish(message);
      ++count_;
    });
  }

private:
  int count_;
  rclcpp::Publisher<std_msgs::msg::String>::SharedPtr publisher_;
  rclcpp::TimerBase::SharedPtr timer_;
};

RCLCPP_COMPONENTS_REGISTER_NODE(robot_nodes::TalkerComponent)

}  // namespace robot_nodes
例题 · 加载 talker_component

在一个终端运行组件容器；在另一个终端确认组件已注册、加载组件， 再订阅它发布的一条消息。 

# 终端一（$HOME/ros2_ws）
ros2 run rclcpp_components component_container
# 终端二（$HOME/ros2_ws）
ros2 component types | sed 's/^ *//' | grep '^robot_nodes::TalkerComponent$'
ros2 component load /ComponentManager robot_nodes robot_nodes::TalkerComponent
ros2 topic echo /component_chatter --once
robot_nodes::TalkerComponent
Loaded component 1 into '/ComponentManager' container node as '/talker_component'
data: component <n>
---

第一行说明插件名是 robot_nodes::TalkerComponent，与注册宏里 写的全名一致。第二行说明组件被装成节点 /talker_component， 编号 1 是容器内的加载序号。第三行是组件发布的消息；计数从 0 开始递增， 每次运行取到的数字不同，页面写成 <n>。末尾的 --- 是 ros2 topic echo 在一条消息之后打印的 分隔线。

ros2 component types | sed 's/^ *//' | grep '^robot_nodes::TalkerComponent$'
robot_nodes::TalkerComponent

你现在能写什么：把节点写成可组合组件，生成共享库，在组件容器中按插件名加载，并用话题命令确认它已经在运行。
