第 9 部分

综合：巡检流程

本部分把前八部分的接口、话题、服务、动作、参数、launch、TF2 与测试 组合成一条可运行的巡检流程：感知节点发布目标，控制节点按模式调度动作， 启动文件统一参数，验收脚本检查最终计数。

前置

先读过 1.1–1.2、2.1–2.3、3.1–3.3、5.1–5.3、7.1–7.4 与 8.4–8.5： 会写话题、服务与动作，会写 launch，会使用 TF2，会写单元测试并 按包检查。工作空间位于 $HOME/ros2_ws。

9.1项目拆分与接口设计

一个可维护的机器人项目按职责拆包：接口包只放消息、服务与动作定义； 节点包放可执行程序；启动包放 launch 文件与参数文件。接口包被其余两个 包依赖，节点包只通过接口通信，启动包不包含业务代码。这样修改接口会 同时触发所有依赖包重新构建，而修改启动参数不会碰节点源码。

包结构

巡检流程沿用已有的三个包。robot_interfaces 提供 Target.msg、Patrol.action，并新增 SetMode.srv 与 PatrolStatus.msg； robot_nodes 提供 target_source、 patrol_controller 与已有的 patrol_server； robot_bringup 提供 launch 文件与验收脚本。

消息与服务

感知节点发布 Target，字段是坐标与标签。控制节点通过 SetMode 服务接收模式字符串，响应报告是否接受。模式只有 三个合法值：idle 表示待机并忽略目标，patrol 表示接受目标并执行，stop 表示停止当前动作并清空队列。 非法值返回 success=false，不改变当前模式。 

string mode
---
bool success
string message

状态消息 PatrolStatus 由控制节点发布。它把模式、当前目标、 坐标与三类计数放在一条消息里，外部工具只订阅一个话题就能看到整体进度。 计数分开记录完成、失败与取消，避免把取消误算成失败。 

string state
string current_target
float64 x
float64 y
int32 completed
int32 failed
int32 canceled

动作与状态

移动一个目标需要持续数秒，期间要报告剩余步数，还要允许取消，因此用 动作而不是服务。服务适合“发一次请求、立即得到响应”的操作，例如切换 模式；动作适合“目标、反馈、结果”三段式的长任务。 Patrol.action 的目标是步数，反馈是剩余步数，结果是是否 成功。

9.2感知节点

感知节点把检测结果转成目标消息。本课的节点不接真实传感器，而是按固定 顺序发布五个目标，其中一个与前面的目标重复。固定序列让后续控制逻辑 可复现，也方便检查去重、过滤与顺序。

目标序列

五个目标依次是 alpha(1.0, 0.0)、 beta(2.0, 1.0)、重复的 beta、 gamma(0.5, −1.0) 与 delta(3.0, 0.5)。 节点每 400 毫秒发布一条，发完最后一条后等待一个周期再关闭，给传输留出 时间。消息类型是第 1 部分定义的 Target。 

#include <chrono>
#include <cmath>
#include <memory>
#include <string>
#include <vector>

#include "rclcpp/rclcpp.hpp"
#include "robot_interfaces/msg/target.hpp"

using namespace std::chrono_literals;

namespace
{
struct TargetSpec
{
  double x;
  double y;
  const char * label;
};
}  // namespace

class TargetSource : public rclcpp::Node
{
public:
  TargetSource()
  : Node("target_source")
  {
    reverse_ = declare_parameter<bool>("reverse", false);
    max_distance_ = declare_parameter<double>("max_distance", 0.0);
    start_delay_ms_ = declare_parameter<int>("start_delay_ms", 0);
    wait_for_subscriber_ = declare_parameter<bool>("wait_for_subscriber", false);

    specs_ = {
      {1.0, 0.0, "alpha"},
      {2.0, 1.0, "beta"},
      {2.0, 1.0, "beta"},
      {0.5, -1.0, "gamma"},
      {3.0, 0.5, "delta"},
    };
    start_time_ = std::chrono::steady_clock::now();

    publisher_ = create_publisher<robot_interfaces::msg::Target>("target", 10);
    timer_ = create_wall_timer(400ms, [this]() {publish_next();});
  }

private:
  void publish_next()
  {
    const auto elapsed =
      std::chrono::duration_cast<std::chrono::milliseconds>(
      std::chrono::steady_clock::now() - start_time_).count();
    if (elapsed < start_delay_ms_) {
      return;
    }
    if (wait_for_subscriber_ && index_ == 0 &&
      publisher_->get_subscription_count() == 0)
    {
      return;
    }
    if (index_ >= specs_.size()) {
      rclcpp::shutdown();
      return;
    }

    const TargetSpec & spec = specs_[reverse_ ? specs_.size() - 1 - index_ : index_];
    ++index_;

    const double distance = std::hypot(spec.x, spec.y);
    if (max_distance_ > 0.0 && distance > max_distance_) {
      RCLCPP_INFO(
        get_logger(), "skip: %s (%.2f, %.2f) distance=%.2f",
        spec.label, spec.x, spec.y, distance);
    } else {
      robot_interfaces::msg::Target target;
      target.x = spec.x;
      target.y = spec.y;
      target.label = spec.label;
      publisher_->publish(target);
      ++published_;
      RCLCPP_INFO(
        get_logger(), "publish: %s (%.2f, %.2f)", spec.label, spec.x, spec.y);
    }

    if (index_ >= specs_.size()) {
      RCLCPP_INFO(get_logger(), "done: published %zu targets", published_);
    }
  }

  bool reverse_{false};
  bool wait_for_subscriber_{false};
  double max_distance_{0.0};
  int start_delay_ms_{0};
  std::size_t index_{0};
  std::size_t published_{0};
  std::vector<TargetSpec> specs_;
  std::chrono::steady_clock::time_point start_time_;
  rclcpp::Publisher<robot_interfaces::msg::Target>::SharedPtr publisher_;
  rclcpp::TimerBase::SharedPtr timer_;
};

int main(int argc, char ** argv)
{
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<TargetSource>());
  rclcpp::shutdown();
  return 0;
}

过滤与顺序

参数 max_distance 按目标到原点的距离过滤，默认 0 表示 不过滤。距离用 hypot(x, y) 计算，超过阈值的目标打印 skip 后跳过。参数 reverse 为真时从最后一个 目标开始发布，用于检查控制节点是否依赖输入顺序。

发布时机

参数 start_delay_ms 让节点启动后先等待一段时间，供控制 节点完成动作客户端连接。参数 wait_for_subscriber 让节点在 第一条消息前等待至少一个订阅者，避免启动瞬间的消息丢失。两者都只影响 发布时机，不改变消息内容。

例题 · 发布五个目标

默认参数下按定义顺序发布五条，重复的 beta 仍出现在输出 中；节点发完后主动打印总数并退出。

[INFO] [target_source]: publish: gamma (0.50, -1.00)

9.3控制节点

控制节点接收目标，按当前模式决定是否入队，为每个目标发送动作，并把 进度发布到状态话题。它同时提供模式服务，让外部在不重启节点的情况下 切换待机、巡检与停止。

模式服务

节点启动时读取参数 initial_mode，默认 patrol。 SetMode 服务只接受三个值；切换到 stop 时清空 等待队列，并对正在执行的目标调用 async_cancel_goal。 切换到 idle 不取消已经执行的目标，只是不再接受新目标。

动作客户端

控制节点是 /patrol 的动作客户端。它用 wait_for_action_server 等服务端出现，然后用 async_send_goal 发送目标。目标响应回调判断服务端是否接受； 反馈回调打印剩余步数；结果回调按 SUCCEEDED、 CANCELED 与其余状态分别计数。

状态与计数

目标按标签与坐标去重，重复项打印 duplicate ignored 后丢弃。 队列为空且最后一个目标到达后超过一秒，节点打印汇总并关闭。汇总里的 received 是收到的消息数，accepted 是去重后 入队的目标数，后三项是动作结果计数。 

#include <chrono>
#include <deque>
#include <memory>
#include <set>
#include <string>

#include "rclcpp/rclcpp.hpp"
#include "rclcpp_action/rclcpp_action.hpp"
#include "robot_interfaces/action/patrol.hpp"
#include "robot_interfaces/msg/patrol_status.hpp"
#include "robot_interfaces/msg/target.hpp"
#include "robot_interfaces/srv/set_mode.hpp"

using namespace std::chrono_literals;
using Patrol = robot_interfaces::action::Patrol;
using GoalHandle = rclcpp_action::ClientGoalHandle<Patrol>;

class PatrolController : public rclcpp::Node
{
public:
  PatrolController()
  : Node("patrol_controller")
  {
    initial_mode_ = declare_parameter<std::string>("initial_mode", "patrol");
    steps_per_target_ = declare_parameter<int>("steps_per_target", 2);
    dedupe_ = declare_parameter<bool>("dedupe", true);
    finish_when_empty_ = declare_parameter<bool>("finish_when_empty", true);
    idle_timeout_sec_ = declare_parameter<double>("idle_timeout", 1.0);

    mode_ = valid_mode(initial_mode_) ? initial_mode_ : "idle";
    if (mode_ != initial_mode_) {
      RCLCPP_WARN(
        get_logger(), "unknown initial_mode '%s', use idle", initial_mode_.c_str());
    }

    target_sub_ = create_subscription<robot_interfaces::msg::Target>(
      "target", 10, [this](const robot_interfaces::msg::Target::SharedPtr msg) {
        on_target(*msg);
      });

    status_pub_ = create_publisher<robot_interfaces::msg::PatrolStatus>(
      "patrol_status", 10);

    mode_srv_ = create_service<robot_interfaces::srv::SetMode>(
      "set_mode",
      [this](
        const std::shared_ptr<robot_interfaces::srv::SetMode::Request> request,
        std::shared_ptr<robot_interfaces::srv::SetMode::Response> response) {
        set_mode(*request, *response);
      });

    action_client_ = rclcpp_action::create_client<Patrol>(this, "patrol");
    if (!action_client_->wait_for_action_server(5s)) {
      RCLCPP_ERROR(get_logger(), "action server /patrol not available");
      rclcpp::shutdown();
      return;
    }

    last_target_time_ = std::chrono::steady_clock::now();
    timer_ = create_wall_timer(100ms, [this]() {tick();});
    publish_status();
  }

private:
  static bool valid_mode(const std::string & mode)
  {
    return mode == "idle" || mode == "patrol" || mode == "stop";
  }

  void on_target(const robot_interfaces::msg::Target & target)
  {
    ++received_;
    last_target_time_ = std::chrono::steady_clock::now();

    if (mode_ != "patrol") {
      RCLCPP_INFO(
        get_logger(), "target ignored: %s mode=%s",
        target.label.c_str(), mode_.c_str());
      publish_status();
      return;
    }

    const std::string key = target.label + "|" + std::to_string(target.x) + "|" +
      std::to_string(target.y);
    if (dedupe_ && seen_.count(key) > 0) {
      ++duplicates_;
      RCLCPP_INFO(get_logger(), "duplicate ignored: %s", target.label.c_str());
      publish_status();
      return;
    }
    seen_.insert(key);
    queue_.push_back(target);
    ++accepted_;
    RCLCPP_INFO(
      get_logger(), "target queued: %s (%.2f, %.2f)",
      target.label.c_str(), target.x, target.y);
    publish_status();
  }

  void set_mode(
    const robot_interfaces::srv::SetMode::Request & request,
    robot_interfaces::srv::SetMode::Response & response)
  {
    if (!valid_mode(request.mode)) {
      response.success = false;
      response.message = "unknown mode: " + request.mode;
      RCLCPP_WARN(get_logger(), "set_mode failed: %s", response.message.c_str());
      return;
    }

    mode_ = request.mode;
    response.success = true;
    response.message = "mode=" + mode_;
    RCLCPP_INFO(get_logger(), "set_mode: %s success=true", mode_.c_str());

    if (mode_ == "stop") {
      queue_.clear();
      if (active_goal_) {
        RCLCPP_INFO(get_logger(), "cancel requested: %s", current_target_.c_str());
        action_client_->async_cancel_goal(active_goal_);
      }
    }
    publish_status();
  }

  void start_next()
  {
    current_target_msg_ = queue_.front();
    queue_.pop_front();
    current_target_ = current_target_msg_.label;
    current_x_ = current_target_msg_.x;
    current_y_ = current_target_msg_.y;
    active_ = true;
    publish_status();

    Patrol::Goal goal;
    goal.steps = steps_per_target_;

    auto options = rclcpp_action::Client<Patrol>::SendGoalOptions();
    options.goal_response_callback =
      [this](GoalHandle::SharedPtr handle) {
        if (!handle) {
          ++failed_;
          active_ = false;
          active_goal_.reset();
          RCLCPP_ERROR(
            get_logger(), "goal rejected: %s", current_target_.c_str());
          publish_status();
          return;
        }
        active_goal_ = handle;
        RCLCPP_INFO(
          get_logger(), "goal accepted: %s steps=%d",
          current_target_.c_str(), steps_per_target_);
      };
    options.feedback_callback =
      [this](GoalHandle::SharedPtr, const std::shared_ptr<const Patrol::Feedback> feedback) {
        RCLCPP_INFO(
          get_logger(), "feedback: %s remaining=%d",
          current_target_.c_str(), feedback->remaining);
      };
    options.result_callback =
      [this](const GoalHandle::WrappedResult & result) {
        active_ = false;
        active_goal_.reset();
        if (result.code == rclcpp_action::ResultCode::SUCCEEDED) {
          ++completed_;
          RCLCPP_INFO(
            get_logger(), "result: %s success=true", current_target_.c_str());
        } else if (result.code == rclcpp_action::ResultCode::CANCELED) {
          ++canceled_;
          RCLCPP_INFO(
            get_logger(), "result: %s canceled=true", current_target_.c_str());
        } else {
          ++failed_;
          RCLCPP_INFO(
            get_logger(), "result: %s success=false", current_target_.c_str());
        }
        publish_status();
      };

    action_client_->async_send_goal(goal, options);
  }

  void tick()
  {
    publish_status();

    if (mode_ == "stop" && !active_) {
      finish();
      return;
    }
    if (mode_ != "patrol") {
      return;
    }
    if (!active_ && !queue_.empty()) {
      start_next();
      return;
    }
    if (finish_when_empty_ && !active_ && queue_.empty() && received_ > 0) {
      const double idle =
        std::chrono::duration<double>(
        std::chrono::steady_clock::now() - last_target_time_).count();
      if (idle >= idle_timeout_sec_) {
        finish();
      }
    }
  }

  void finish()
  {
    if (finished_) {
      return;
    }
    finished_ = true;
    RCLCPP_INFO(
      get_logger(),
      "controller done: received=%d accepted=%zu completed=%d failed=%d canceled=%d",
      received_, accepted_, completed_, failed_, canceled_);
    publish_status();
    rclcpp::shutdown();
  }

  void publish_status()
  {
    robot_interfaces::msg::PatrolStatus status;
    status.state = mode_;
    status.current_target = current_target_.empty() ? "-" : current_target_;
    status.x = current_x_;
    status.y = current_y_;
    status.completed = completed_;
    status.failed = failed_;
    status.canceled = canceled_;
    status_pub_->publish(status);
  }

  std::string initial_mode_;
  std::string mode_;
  std::string current_target_;
  robot_interfaces::msg::Target current_target_msg_;
  double current_x_{0.0};
  double current_y_{0.0};
  int steps_per_target_{2};
  bool dedupe_{true};
  bool finish_when_empty_{true};
  bool active_{false};
  bool finished_{false};
  double idle_timeout_sec_{1.0};
  int received_{0};
  int duplicates_{0};
  int completed_{0};
  int failed_{0};
  int canceled_{0};
  std::size_t accepted_{0};
  std::set<std::string> seen_;
  std::deque<robot_interfaces::msg::Target> queue_;
  std::chrono::steady_clock::time_point last_target_time_;
  GoalHandle::SharedPtr active_goal_;
  rclcpp::Subscription<robot_interfaces::msg::Target>::SharedPtr target_sub_;
  rclcpp::Publisher<robot_interfaces::msg::PatrolStatus>::SharedPtr status_pub_;
  rclcpp::Service<robot_interfaces::srv::SetMode>::SharedPtr mode_srv_;
  rclcpp_action::Client<Patrol>::SharedPtr action_client_;
  rclcpp::TimerBase::SharedPtr timer_;
};

int main(int argc, char ** argv)
{
  rclcpp::init(argc, argv);
  auto node = std::make_shared<PatrolController>();
  // 等待服务端失败时构造函数里已经 shutdown，这时不再进入 spin。
  if (rclcpp::ok()) {
    rclcpp::spin(node);
  }
  rclcpp::shutdown();
  return 0;
}

9.4启动、参数、回放与验收

前面的节点分别启动时要记住终端顺序与参数。启动文件把节点、参数与 退出策略写在一起，验收脚本则在固定时间内等待结果并提取关键日志。 这样同一条命令可以在不同机器上重复执行，输出可以直接放进报告。

启动文件

9.4-patrol.launch.py 启动四个节点：静态坐标广播 map → base_link、动作服务端、控制器与感知节点。控制器加上 on_exit=Shutdown()，控制器退出后 launch 自动关闭其余节点， 不需要手工按 Ctrl+C。 

from launch import LaunchDescription
from launch.actions import DeclareLaunchArgument, Shutdown
from launch.substitutions import LaunchConfiguration
from launch_ros.actions import Node
from launch_ros.parameter_descriptions import ParameterValue


def generate_launch_description():
    steps = LaunchConfiguration("steps_per_target")
    delay = LaunchConfiguration("start_delay_ms")
    max_distance = LaunchConfiguration("max_distance")
    initial_mode = LaunchConfiguration("initial_mode")

    static_tf = Node(
        package="robot_nodes",
        executable="static_tf",
        parameters=[
            {
                "parent_frame": "map",
                "child_frame": "base_link",
                "x": 0.0,
                "y": 0.0,
                "z": 0.0,
                "yaw_deg": 0.0,
            }
        ],
    )

    patrol_server = Node(
        package="robot_nodes",
        executable="patrol_server",
    )

    controller = Node(
        package="robot_nodes",
        executable="patrol_controller",
        parameters=[
            {"initial_mode": initial_mode},
            {"steps_per_target": ParameterValue(steps, value_type=int)},
            {"finish_when_empty": True},
        ],
        on_exit=Shutdown(),
    )

    target_source = Node(
        package="robot_nodes",
        executable="target_source",
        parameters=[
            {"start_delay_ms": ParameterValue(delay, value_type=int)},
            {"max_distance": ParameterValue(max_distance, value_type=float)},
            {"wait_for_subscriber": True},
        ],
    )

    return LaunchDescription(
        [
            DeclareLaunchArgument("steps_per_target", default_value="2"),
            DeclareLaunchArgument("start_delay_ms", default_value="1500"),
            DeclareLaunchArgument("max_distance", default_value="0.0"),
            DeclareLaunchArgument("initial_mode", default_value="patrol"),
            static_tf,
            patrol_server,
            controller,
            target_source,
        ]
    )

参数覆盖

DeclareLaunchArgument 声明可在命令行覆盖的参数。运行 ros2 launch 包名 文件 参数:=值 时，值进入对应的 Node。数值参数用 ParameterValue(..., value_type=int) 转换，否则 launch 会把它们当成字符串。

验收脚本

9.4-verify.sh 运行 launch，把日志写入临时文件，等 launch 返回后提取发布、跳过、去重、目标接受与汇总行，并统一去掉进程编号与 时间戳。退出码由 ros2 launch 决定；节点断言失败或 launch 超时都会让脚本失败。

steps=${1:-2}

  steps_per_target:="$steps" max_distance:="$max_distance" >"$log" 2>&1

grep -E 'publish:|skip:|duplicate ignored:|goal accepted:|controller done:' "$log" |
  sed -E 's/^\[([a-z_]+)-[0-9]+\] \[INFO\] (\[[0-9.]+\] )?\[[a-z_]+\]: /[\1]: /'

练习 9-8

用参数覆盖把 max_distance 设为 1.5，重新运行验收脚本。解释为什么汇总行的 received 与 accepted 都变成 2。

max_distance: 1.5
[patrol_controller]: controller done: received=2 accepted=2 completed=2 failed=0 canceled=0
看答案

第二个位置参数是距离阈值。传 1.5 后，感知节点只发布 alpha 与 gamma，控制节点只收到两条消息， 去重后两个目标都入队并完成。

[patrol_controller]: controller done: received=2 accepted=2 completed=2 failed=0 canceled=0

received 统计控制器收到的话题消息，过滤发生在感知节点 发布之前，因此它降到 2；accepted 也降到 2，因为两条都 不重复。两个目标全部完成，失败与取消都是 0。
