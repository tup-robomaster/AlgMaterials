执行器与回调

执行器决定回调由哪个线程、以什么顺序执行。这一部分从回调队列开始，比较单线程与多线程执行器，说明回调组怎样限制并发，最后处理耗时任务，避免一个回调长时间占用执行器。

4.1执行器与回调队列

执行器（executor）负责把节点上已经就绪的回调取出来，交给线程执行。 节点只声明订阅、定时器与服务，不决定回调在哪个线程运行；回调何时执行、 由哪个线程执行，由执行器安排。

rclcpp::spin(node) 是最短的写法：内部创建一个单线程执行器 （single-threaded executor），把节点加进去，然后循环等待。需要控制执行器时， 可以显式创建 SingleThreadedExecutor 或 MultiThreadedExecutor，逐个调用 add_node， 再调用 spin。

执行器做什么

节点把订阅、定时器、服务端与动作服务端注册给执行器。执行器等待其中任意 一个就绪；就绪后，对应的回调进入回调队列（callback queue），由执行器 分派给工作线程。回调一旦开始执行，就会一直运行到返回，执行器不会在中途 切换。

回调队列

队列里排的是回调，不是原始消息。一条消息到达时，它对应的订阅回调成为一个 待执行的条目；定时器到期时，定时器回调成为一个条目。单线程执行器只有一个 工作线程，因此同一时刻只有一个回调在运行，其余条目按进入队列的先后等待。

这解释了一个常见现象：一个回调里睡眠几百毫秒，队列里排在它后面的回调也会 跟着晚几百毫秒，即使它们来自另一个节点。

一个执行器里的两个节点

下面的程序把发布者与订阅者放进同一个单线程执行器。发布者的定时器每 100 毫秒检查一次订阅者数量；发现订阅者后，连续发布三条延迟值，然后取消 定时器。订阅者每收到一条，打印开始、睡眠对应毫秒数、打印结束。 

#include <chrono>
#include <cstdlib>
#include <memory>
#include <sstream>
#include <string>
#include <vector>

#include "rclcpp/rclcpp.hpp"
#include "std_msgs/msg/int32.hpp"

using namespace std::chrono_literals;

class QueueTalker : public rclcpp::Node
{
public:
  explicit QueueTalker(const std::vector<int> & delays)
  : Node("queue_talker"), delays_(delays)
  {
    publisher_ = create_publisher<std_msgs::msg::Int32>("queue_delay", 10);
    timer_ = create_wall_timer(100ms, [this]() {
      if (publisher_->get_subscription_count() == 0) {
        return;
      }
      std_msgs::msg::Int32 message;
      for (int delay : delays_) {
        message.data = delay;
        publisher_->publish(message);
        RCLCPP_INFO(get_logger(), "sent %d", delay);
      }
      timer_->cancel();
    });
  }

private:
  std::vector<int> delays_;
  rclcpp::Publisher<std_msgs::msg::Int32>::SharedPtr publisher_;
  rclcpp::TimerBase::SharedPtr timer_;
};

class QueueListener : public rclcpp::Node
{
public:
  explicit QueueListener(std::size_t expected)
  : Node("queue_listener"), expected_(expected), count_(0)
  {
    subscription_ = create_subscription<std_msgs::msg::Int32>(
      "queue_delay", 10, [this](const std_msgs::msg::Int32::SharedPtr message) {
        const int delay = message->data;
        RCLCPP_INFO(get_logger(), "begin %d", delay);
        std::this_thread::sleep_for(std::chrono::milliseconds(delay));
        RCLCPP_INFO(get_logger(), "end %d", delay);
        ++count_;
        if (count_ == expected_) {
          RCLCPP_INFO(get_logger(), "all done");
          rclcpp::shutdown();
        }
      });
  }

private:
  std::size_t expected_;
  std::size_t count_;
  rclcpp::Subscription<std_msgs::msg::Int32>::SharedPtr subscription_;
};

int main(int argc, char ** argv)
{
  std::vector<int> delays;
  const std::string text = argc > 1 ? argv[1] : "400,0,0";
  std::stringstream stream(text);
  std::string item;
  while (std::getline(stream, item, ',')) {
    try {
      delays.push_back(std::stoi(item));
    } catch (const std::exception &) {
      return 2;
    }
  }
  if (delays.empty()) {
    return 2;
  }

  rclcpp::init(argc, argv);
  auto talker = std::make_shared<QueueTalker>(delays);
  auto listener = std::make_shared<QueueListener>(delays.size());
  rclcpp::executors::SingleThreadedExecutor executor;
  executor.add_node(talker);
  executor.add_node(listener);
  executor.spin();
  rclcpp::shutdown();
  return 0;
}

4.2单线程与多线程执行器

单线程执行器只有一个工作线程；多线程执行器（multi-threaded executor） 创建工作线程池，从同一个回调队列中取回调。工作线程的数量可以在构造时给出； 不给时由实现按机器的硬件并发能力决定。

两种执行器

SingleThreadedExecutor 保证任意时刻至多一个回调在运行。 MultiThreadedExecutor 允许不同回调同时运行，但能否真的重叠， 还取决于这些回调属于哪个回调组：同一个互斥组里的回调仍然串行。

回调组的影响

每个节点有一个默认的回调组，类型是互斥的（mutually exclusive）。 如果不另建回调组，节点上的定时器、订阅与服务回调都在这个组里； 即使换成多线程执行器，它们也不会并发。把两个定时器分别放进两个互斥组， 多线程执行器才可能让它们同时运行。

测量重叠

下面的探针程序创建两个定时器，周期都是 100 毫秒。每个回调记录开始与结束 时刻，并睡眠 work_ms 毫秒。两个区间有交叠时，程序打印 overlap=yes，否则打印 overlap=no。 命令行第一个参数选择执行器，第二个参数选择两个定时器是否分属不同的组， 第三个参数给出每次工作的毫秒数。 

#include <atomic>
#include <chrono>
#include <future>
#include <iostream>
#include <memory>
#include <string>
#include <thread>

#include "rclcpp/rclcpp.hpp"

using namespace std::chrono_literals;

class OverlapProbe : public rclcpp::Node
{
public:
  OverlapProbe(bool separate_groups, int work_ms)
  : Node("executor_probe"), work_ms_(work_ms)
  {
    auto callback = [this](int index) {
      start_[index] = std::chrono::steady_clock::now();
      std::this_thread::sleep_for(std::chrono::milliseconds(work_ms_));
      end_[index] = std::chrono::steady_clock::now();
      if (++done_ == 2) {
        promise_.set_value();
      }
    };

    if (separate_groups) {
      group_a_ = create_callback_group(rclcpp::CallbackGroupType::MutuallyExclusive);
      group_b_ = create_callback_group(rclcpp::CallbackGroupType::MutuallyExclusive);
      timer_a_ = create_wall_timer(100ms, [callback]() {callback(0);}, group_a_);
      timer_b_ = create_wall_timer(100ms, [callback]() {callback(1);}, group_b_);
    } else {
      timer_a_ = create_wall_timer(100ms, [callback]() {callback(0);});
      timer_b_ = create_wall_timer(100ms, [callback]() {callback(1);});
    }
  }

  std::future<void> done()
  {
    return promise_.get_future();
  }

  bool overlap() const
  {
    return start_[1] < end_[0] && start_[0] < end_[1];
  }

private:
  int work_ms_;
  std::atomic<int> done_{0};
  std::promise<void> promise_;
  std::chrono::steady_clock::time_point start_[2];
  std::chrono::steady_clock::time_point end_[2];
  rclcpp::CallbackGroup::SharedPtr group_a_;
  rclcpp::CallbackGroup::SharedPtr group_b_;
  rclcpp::TimerBase::SharedPtr timer_a_;
  rclcpp::TimerBase::SharedPtr timer_b_;
};

int main(int argc, char ** argv)
{
  const std::string executor_kind = argc > 1 ? argv[1] : "single";
  const std::string group_kind = argc > 2 ? argv[2] : "separate";
  const int work_ms = argc > 3 ? std::stoi(argv[3]) : 200;
  if (executor_kind != "single" && executor_kind != "multi") {
    return 2;
  }
  if (group_kind != "separate" && group_kind != "same") {
    return 2;
  }

  rclcpp::init(argc, argv);
  auto node = std::make_shared<OverlapProbe>(group_kind == "separate", work_ms);
  auto finished = node->done();
  std::thread spinner;
  if (executor_kind == "multi") {
    spinner = std::thread([node]() {
      rclcpp::executors::MultiThreadedExecutor executor;
      executor.add_node(node);
      executor.spin();
    });
  } else {
    spinner = std::thread([node]() {
      rclcpp::executors::SingleThreadedExecutor executor;
      executor.add_node(node);
      executor.spin();
    });
  }

  if (finished.wait_for(3s) != std::future_status::ready) {
    rclcpp::shutdown();
    spinner.join();
    std::cout << executor_kind << " " << group_kind << ": timeout" << std::endl;
    return 1;
  }
  rclcpp::shutdown();
  spinner.join();

  std::cout << executor_kind;
  if (executor_kind == "multi") {
    std::cout << " " << group_kind;
  }
  if (work_ms != 200) {
    std::cout << " work_ms=" << work_ms;
  }
  std::cout << ": overlap=" << (node->overlap() ? "yes" : "no") << std::endl;
  return 0;
}
例题 · 四次对照

依次运行四次：单线程、多线程且分组、多线程且同组、多线程且分组并把 每次工作缩短到 50 毫秒。每条命令只打印一行结果。 

# 当前目录：$HOME/ros2_ws
ros2 run robot_nodes executor_probe single
ros2 run robot_nodes executor_probe multi separate
ros2 run robot_nodes executor_probe multi same
ros2 run robot_nodes executor_probe multi separate 50
single: overlap=no
multi separate: overlap=yes
multi same: overlap=no
multi separate work_ms=50: overlap=yes

第一行没有重叠：单线程执行器只有一个工作线程。第二行有重叠：两个定时器 在不同组里，多线程执行器可以同时运行两个回调。第三行没有重叠：两个定时器 在同一个互斥组里，仍然串行。第四行仍有重叠：把每次工作缩短到 50 毫秒， 没有改变两个回调所属的组，能否并发不取决于工作长短。

关于机器

重叠需要至少两个可用的工作线程。机器只提供一个 CPU 线程时，多线程执行器 也只能串行，第二行会变成 overlap=no。

练习 4-3

用多线程执行器，把两个定时器放在同一个组里，每次工作 200 毫秒。只保留结果行。

multi same: overlap=no
看答案

same 表示两个定时器都留在节点的默认回调组里。默认组是互斥组， 多线程执行器也会让两个回调串行，因此区间不重叠。 

# 当前目录：$HOME/ros2_ws
ros2 run robot_nodes executor_probe multi same
multi same: overlap=no
练习 4-4

用多线程执行器，把两个定时器放在不同的组里，每次工作 50 毫秒。只保留结果行。

multi separate work_ms=50: overlap=yes
看答案

separate 表示两个定时器分属两个互斥组。多线程执行器可以同时 取出两个组的回调，因此两个区间重叠。把每次工作缩短到 50 毫秒没有改变组， 只要两个工作线程可用，结果仍是 overlap=yes。 

# 当前目录：$HOME/ros2_ws
ros2 run robot_nodes executor_probe multi separate 50
multi separate work_ms=50: overlap=yes

你现在能写什么：选择单线程或多线程执行器，并用回调的起止时刻判断两个回调是否真的重叠。

4.3回调组与并发

回调组（callback group）规定一组回调之间的并发关系。执行器在取回调时， 先看它属于哪个组，再看该组当前是否已有回调在运行。组有两种类型： 互斥组（mutually exclusive）与可重入组（reentrant）。

互斥组

互斥组同一时刻最多有一个回调在执行。节点默认使用一个互斥组；用 create_callback_group 创建互斥组时，需要把返回的共享指针保存 下来，并在创建定时器或订阅时传入。组的生命周期必须长于使用它的回调， 局部变量在构造函数结束后就销毁，定时器会失去所属的组。

可重入组

可重入组允许同一个组的多个回调同时执行。多线程执行器可以从可重入组中 取出多个回调，分给不同线程。并发带来共享状态的竞争：多个回调读写同一个 成员时，需要用互斥量（std::mutex）或原子变量保护。

怎样选组

默认的互斥组适合大多数节点：回调之间不会同时改动同一个状态，代码容易 推理。只有确认两个回调互不依赖、并且共享数据已经保护时，才把它们放进 可重入组。回调里做耗时工作仍然会占用一个工作线程，回调组不会把阻塞变成 非阻塞。

下面的程序把两个定时器放进同一个组，并始终使用多线程执行器。命令行参数 选择组的类型，第二个参数给出每次工作的毫秒数。 

#include <atomic>
#include <chrono>
#include <future>
#include <iostream>
#include <memory>
#include <string>
#include <thread>

#include "rclcpp/rclcpp.hpp"

using namespace std::chrono_literals;

class GroupProbe : public rclcpp::Node
{
public:
  GroupProbe(bool reentrant, int work_ms)
  : Node("group_probe"), work_ms_(work_ms)
  {
    group_ = create_callback_group(
      reentrant ? rclcpp::CallbackGroupType::Reentrant :
      rclcpp::CallbackGroupType::MutuallyExclusive);
    auto callback = [this](int index) {
      start_[index] = std::chrono::steady_clock::now();
      std::this_thread::sleep_for(std::chrono::milliseconds(work_ms_));
      end_[index] = std::chrono::steady_clock::now();
      if (++done_ == 2) {
        promise_.set_value();
      }
    };
    timer_a_ = create_wall_timer(100ms, [callback]() {callback(0);}, group_);
    timer_b_ = create_wall_timer(100ms, [callback]() {callback(1);}, group_);
  }

  std::future<void> done()
  {
    return promise_.get_future();
  }

  bool overlap() const
  {
    return start_[1] < end_[0] && start_[0] < end_[1];
  }

private:
  int work_ms_;
  std::atomic<int> done_{0};
  std::promise<void> promise_;
  std::chrono::steady_clock::time_point start_[2];
  std::chrono::steady_clock::time_point end_[2];
  rclcpp::CallbackGroup::SharedPtr group_;
  rclcpp::TimerBase::SharedPtr timer_a_;
  rclcpp::TimerBase::SharedPtr timer_b_;
};

int main(int argc, char ** argv)
{
  const std::string group_kind = argc > 1 ? argv[1] : "exclusive";
  const int work_ms = argc > 2 ? std::stoi(argv[2]) : 200;
  if (group_kind != "exclusive" && group_kind != "reentrant") {
    return 2;
  }

  rclcpp::init(argc, argv);
  auto node = std::make_shared<GroupProbe>(group_kind == "reentrant", work_ms);
  auto finished = node->done();
  std::thread spinner([node]() {
    rclcpp::executors::MultiThreadedExecutor executor;
    executor.add_node(node);
    executor.spin();
  });

  if (finished.wait_for(3s) != std::future_status::ready) {
    rclcpp::shutdown();
    spinner.join();
    std::cout << group_kind << ": timeout" << std::endl;
    return 1;
  }
  rclcpp::shutdown();
  spinner.join();

  std::cout << group_kind << ": overlap=" << (node->overlap() ? "yes" : "no") << std::endl;
  return 0;
}
例题 · 同组两种类型

先运行互斥组，再运行可重入组。两次都使用默认的 200 毫秒工作时间和 多线程执行器。 

# 当前目录：$HOME/ros2_ws
ros2 run robot_nodes group_probe exclusive
ros2 run robot_nodes group_probe reentrant
exclusive: overlap=no
reentrant: overlap=yes

两个定时器属于同一个组，区别只在组的类型。互斥组让第二个回调等待第一个 结束，区间不重叠；可重入组允许两个回调同时运行，区间重叠。执行器相同， 结果由回调组决定。

练习 4-5

使用可重入组，每次工作 100 毫秒。只保留结果行。

reentrant: overlap=yes
看答案

group_probe 的第二个参数是可重入组。两个定时器在同一个可重入组里， 多线程执行器允许两个回调同时运行；每次工作 100 毫秒，区间仍然重叠。 

# 当前目录：$HOME/ros2_ws
ros2 run robot_nodes group_probe reentrant 100
reentrant: overlap=yes
练习 4-6

使用互斥组，每次工作 50 毫秒。只保留结果行。

exclusive: overlap=no
看答案

第二个参数是互斥组。两个定时器属于同一个互斥组，同一时刻只能有一个回调 运行；每次工作 50 毫秒，第二个回调仍要等第一个结束，区间不重叠。 

# 当前目录：$HOME/ros2_ws

你现在能写什么：为节点创建互斥组或可重入组，把定时器与订阅放进指定的组，并说明多线程执行器下哪些回调可以同时运行。

4.4耗时任务与执行器

执行器的工作线程数量有限。一个回调在内部睡眠、等待文件或进行长时间计算时， 它占用的工作线程不会去取别的回调。单线程执行器只有一个线程，所有回调都会 被这个长回调阻塞；多线程执行器能缓解，但工作线程仍会被逐个占满。

阻塞回调

下面的程序有两个定时器：心跳定时器每 50 毫秒触发一次，任务定时器每 100 毫秒触发一次。任务开始时把 working_ 置为真，结束后置回假； 心跳回调只在 working_ 为真时计数。阻塞模式下，任务回调直接 睡眠 300 毫秒。

工作线程

线程模式下，任务回调创建一个 std::thread，把睡眠放到这个线程里， 自己立即返回。执行器线程因此空闲，可以继续处理心跳。线程在析构函数中 调用 join，保证节点销毁前线程已经结束。

边界

工作线程捕获了节点的 this 指针，节点的生命周期必须长于线程。 线程与执行器线程共享的计数使用 std::atomic；如果共享的是容器 或字符串，需要互斥量。把工作移出执行器只是让执行器继续调度，工作本身的 正确性仍要单独保证。 

#include <atomic>
#include <chrono>
#include <future>
#include <iostream>
#include <memory>
#include <string>
#include <thread>

#include "rclcpp/rclcpp.hpp"

using namespace std::chrono_literals;

class LongTaskDemo : public rclcpp::Node
{
public:
  explicit LongTaskDemo(bool threaded)
  : Node("long_task_demo"), threaded_(threaded)
  {
    heartbeat_ = create_wall_timer(50ms, [this]() {
      if (working_.load()) {
        ++heartbeats_;
      }
    });
    task_ = create_wall_timer(100ms, [this]() {
      task_->cancel();
      working_ = true;
      if (threaded_) {
        worker_ = std::thread([this]() {
          while (heartbeats_.load() == 0) {
            std::this_thread::sleep_for(1ms);
          }
          std::this_thread::sleep_for(250ms);
          heartbeats_during_ = heartbeats_.load();
          working_ = false;
          promise_.set_value();
        });
      } else {
        std::this_thread::sleep_for(300ms);
        heartbeats_during_ = heartbeats_.load();
        working_ = false;
        promise_.set_value();
      }
    });
  }

  ~LongTaskDemo() override
  {
    if (worker_.joinable()) {
      worker_.join();
    }
  }

  std::future<void> done()
  {
    return promise_.get_future();
  }

  int heartbeats_during() const
  {
    return heartbeats_during_;
  }

private:
  bool threaded_;
  std::atomic<bool> working_{false};
  std::atomic<int> heartbeats_{0};
  int heartbeats_during_{0};
  std::promise<void> promise_;
  std::thread worker_;
  rclcpp::TimerBase::SharedPtr heartbeat_;
  rclcpp::TimerBase::SharedPtr task_;
};

int main(int argc, char ** argv)
{
  const std::string mode = argc > 1 ? argv[1] : "blocking";
  if (mode != "blocking" && mode != "threaded") {
    return 2;
  }

  rclcpp::init(argc, argv);
  auto node = std::make_shared<LongTaskDemo>(mode == "threaded");
  auto finished = node->done();
  std::thread spinner([node]() {
    rclcpp::executors::SingleThreadedExecutor executor;
    executor.add_node(node);
    executor.spin();
  });

  if (finished.wait_for(3s) != std::future_status::ready) {
    rclcpp::shutdown();
    spinner.join();
    std::cout << mode << ": timeout" << std::endl;
    return 1;
  }
  rclcpp::shutdown();
  spinner.join();

  const int count = node->heartbeats_during();
  if (mode == "threaded") {
    std::cout << "threaded: heartbeats while task="
              << (count > 0 ? "nonzero" : "0") << std::endl;
  } else {
    std::cout << "blocking: heartbeats while task=" << count << std::endl;
  }
  return 0;
}
例题 · 心跳计数

阻塞模式下，任务回调在 300 毫秒内不返回。心跳定时器虽然每 50 毫秒到期， 它的回调却无法进入执行器线程，计数保持 0。 

# 当前目录：$HOME/ros2_ws
ros2 run robot_nodes long_task_demo blocking
blocking: heartbeats while task=0

任务回调结束时把 working_ 置回假，随后才轮到心跳回调； 这时计数条件已经不成立，所以最终计数是 0。线程模式把睡眠移到工作线程， 任务回调很快返回，心跳回调在任务进行期间就能运行，计数不为零。

练习 4-7

运行阻塞模式，只保留结果行。

blocking: heartbeats while task=0
看答案

阻塞模式下，任务回调在 300 毫秒内不返回，心跳定时器的回调虽然每 50 毫秒 到期，却无法进入执行器线程。任务结束时 working_ 已经置回假， 随后运行的心跳回调不计数，最终计数为 0。 

# 当前目录：$HOME/ros2_ws
ros2 run robot_nodes long_task_demo blocking
blocking: heartbeats while task=0
练习 4-8

运行线程模式，只保留结果行。结果只说明计数是否为零，不给出具体次数。

threaded: heartbeats while task=nonzero
看答案

线程模式把睡眠放进 std::thread，任务回调立即返回。执行器线程 继续处理心跳回调，任务进行期间 working_ 为真，计数不为零； 程序只打印计数是否为零，不打印具体次数。 

# 当前目录：$HOME/ros2_ws
ros2 run robot_nodes long_task_demo threaded
threaded: heartbeats while task=nonzero

你现在能写什么：把耗时工作移出执行器线程，用独立的工作线程完成它，并用心跳计数验证执行器在任务期间仍能处理其他回调。
