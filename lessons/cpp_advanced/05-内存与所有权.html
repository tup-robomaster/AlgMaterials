第 5 部分

内存与所有权

这门课一直在用一句话：容器里的元素存放在哪里、什么时候销毁， 容器自己管理，不需要你处理。 这一部分把这件事分开说明：变量有两处存储位置（栈和堆）， 用 new 申请一块内存，用 delete 释放； 这两步为什么最容易出错； 以及最后——怎么把这件事写进类型里，从此一句 delete 都不用写。

5.1栈和堆

到这儿为止，课里的变量都有一个共同点：名字写在代码里， 什么时候创建、什么时候销毁，看花括号就够了。 这一课换个角度：看这些变量的数据存放在哪里。

两处存储位置

程序里能放数据的地方有两处：

  • 栈（stack）——函数一进来，它里面那些变量就分配好了； 函数返回时，变量跟着销毁。名字、分配在哪里、什么时候销毁， 全是编译的时候定好的，你一句都不用写。
  • 堆（heap）——一大块公共内存。要用的时候用 new 申请， 申请到一块就由你管理，什么时候释放也由你决定。代价是： 申请的时候要写一句 new，释放的时候要写一句 delete， 这两句都得你自己记着。

在这之前，课里写过的变量全是栈上的——数组那种「有编号的连续内存」 就是栈。从这一课起，多了一处要管理的地方。

先把两处并列对照： 

int on_stack = 42;          // 栈上：进这个函数就分配好，出这个函数自动释放

int* on_heap = new int;     // 堆上：用 new 申请一块，取得的是一个地址
*on_heap = 42;              // 通过地址，往那块内存写

这两行都成立：on_stack 和 *on_heap 里都是 42， 用起来一模一样。区别在它们存放在哪里—— 前一个存放在栈上，后一个存放在堆上。还有一处容易混淆的： on_heap 这个指针本身（不是它指向的那块内存）也存放在栈上， 它里面保存的只是一个地址。

这一课的例题会把这几处的地址都输出出来，逐一确认一遍 （例题：栈上的和堆上的）。先把两处存储位置各自的性质列清楚：

  • 栈上的变量，由函数管理。函数一进来就分配好，一返回就释放； 名字写在代码里，什么时候销毁看花括号就够了——一件事都不需要你处理。
  • 堆上的内存，由你管理。申请的时候写一句，释放的时候写一句； 它能一直存在到函数返回之后，也可能一直被你忘记释放。

这一部分要讲的全在最后那句「由你管理」上：多出来的这份自由， 代价是两份额外的管理责任——申请和释放都必须由你负责。

在堆上申请一块内存

从堆上申请一块内存，用 new： 

int* p = new int;

这一行做两件事：从堆上分配一块能存放一个 int 的内存， 把它的地址返回给你。这块内存本身没有名字，你得到的是一个地址—— 指针正好接得住。

从那以后，用这块内存和用普通变量一样，只是中间要经过指针： 

*p = 42;              // 往那块内存写
std::cout << *p;      // 从那块内存读

用完了要释放，用 delete： 

delete p;             // 这块内存释放回堆上
p = nullptr;          // 释放后把指针置成空

申请一整块连续内存，两处各加一对中括号： 

int* data = new int[n];     // 申请 n 个元素
data[3] = 7;                // 用起来和数组一样
delete[] data;              // 释放整块内存，中括号不能丢

释放一整块内存的时候写 delete 不写 delete[]， 行为就是未定义的。申请的时候带方括号， 释放的时候也带，两边对应。

出了作用域就没了

栈上的变量有一条固定规则：它所属的函数一旦返回，它就销毁。 这条规则本身没有问题，问题是它的地址可以传出去—— 传出去的地址，指向的是一块马上就要销毁的内存。

下面这份程序演示的就是这件事，函数里那个变量还存在， 把它的地址向外传出： 

#include <iostream>

int* pick() {
    int local = 7;
    return &local;      // 传出去的是地址，可那块内存马上要销毁
}

int main() {
    int* p = pick();

    if (p == nullptr) {
        std::cout << "取得的地址是空的。" << std::endl;
    } else {
        std::cout << "取得一个看上去正常的地址：" << p << std::endl;
    }
    std::cout << "（那块内存已经销毁——不管得到什么地址，都无效）" << std::endl;

    return 0;
}

那句 address of local variable returned 翻译过来就是 「把栈上变量的地址传出去了」。编译器看得出来这件事不对， 但它只警告、不阻止——能编译通过，能运行，这就是它最容易被忽略的地方。

运行起来呢？这一份不去访问那个地址，只看它得到的是什么： 

取得的地址是空的。
（那块内存已经销毁——不管得到什么地址，都无效）

这一步确认了「无效」两个字：这份编译器直接给了一个空地址。 换台机器、换个编译器，也可能是别的结果——哪一种都无效， 因为那条规则已经确定：函数一返回，那个变量就销毁。

容器里的元素存放在哪里

那句话——容器里的元素存放在哪里、什么时候销毁，容器自己管理—— 现在能说清它是怎么办到的了。

一个 std::vector 对象本身很小：元素并不存放在它里面， 堆上另有一块连续的内存保存这些元素，对象内部只保存指向那块内存的 指针（以及元素个数、容量这些信息）。 （std::string 也一样：对象本身很小，字符串的内容存放在堆上， 由对象内部的指针指向它。）

这一条解开两个常见疑问：

  • 为什么「复制一份 vector」需要较大代价。只把指针复制一份不行—— 那样两个对象指向同一块内存，一个修改了另一个也跟着变， 释放的时候还要释放两次。真正的复制是 在堆上另外申请一块同样大的内存，把每个元素逐个复制过去； 元素多，这一步的代价就高。
  • 为什么这份管理工作不需要你处理。vector 自己记录着元素个数和容量， 什么时候该换成一块更大的内存、什么时候该释放这块内存， 都是它自己的事——它在自己的析构函数里完成这件事 （对象销毁的时候自动被调用一次的那个方法）。

同时说明一件一直没有点明的事：vector 的容量会随着元素增加而增长，增长时它要申请一块更大的内存，并把元素移动过去。

例题 · 栈上的和堆上的

栈上的变量和堆上的内存各写一个，输出值和地址。目的只有一个： 亲眼确认它们不在同一处。 

#include <iostream>

int main() {
    int on_stack = 42;              // 栈上：进 main 就分配好，出 main 自动释放
    int* on_heap = new int;         // 堆上：得用 new 申请，它才分配一块内存
    *on_heap = 42;                  // 那块内存没有名字，通过指针写进去

    std::cout << "栈上的变量：值 " << on_stack << "，它存放在 " << &on_stack
              << std::endl;
    std::cout << "堆上的内存：值 " << *on_heap << "，它在 " << on_heap
              << std::endl;
    std::cout << "保存那个地址的指针，存放在 " << &on_heap << std::endl;
    std::cout << "——前两个地址离得远，后两个离得近。" << std::endl;

    delete on_heap;                 // 申请与释放对应：这块内存释放回堆上
    on_heap = nullptr;              // 释放后把指针置成空

    return 0;
}
栈上的变量：值 42，它存放在 0x7ffe8306923c
堆上的内存：值 42，它在 0x5a6ed90f52b0
保存那个地址的指针，存放在 0x7ffe83069240
——前两个地址离得远，后两个离得近。

最后那两行是这份程序想让人记住的全部：栈上的两个变量位置相邻， 堆上那块离得远。地址里的数字每次运行都不一样，不需要记， 记住「相差很远」这一点就够了。

练习

练习 5-1

读一个 n，从堆上申请一块能存放 n 个数的内存， 把 1 到 n 依次存入，求总和，最后整块释放。 

100
1 加到 100 = 5050

释放的时候注意那对方括号：申请的是整块内存，释放的也必须是整块内存。 写完后运行一遍，答案在下面。

看答案

三件事按顺序做：申请一块内存、当普通数组使用、释放。 

#include <iostream>

int main() {
    int n = 0;
    std::cin >> n;

    int* data = new int[n];
    for (int i = 0; i < n; i++) {
        data[i] = i + 1;
    }

    int sum = 0;
    for (int i = 0; i < n; i++) {
        sum = sum + data[i];
    }

    std::cout << "1 加到 " << n << " = " << sum << std::endl;

    delete[] data;
    data = nullptr;

    return 0;
}

最后两行是一对，需要一起看：delete[] 释放的是整块内存， 所以方括号不能丢——delete data 和 delete[] data 不是同一件事。释放之后把 data 置成空，是为了防止再次使用：已释放的地址已经失效，再用就是未定义行为； 置成空以后，如果用空指针读写，程序会立即中止，不会给出一个错误的结果。

还有一处需要对照：data 这个指针变量本身存放在栈上 （函数结束时随之销毁），它指向的那块内存在堆上——需要释放，而且由你负责释放。

练习 5-2

写一个函数，接一个整数 x：从堆上申请一块内存， 把 x × 2 写进去，输出这块内存里的数，然后释放。 主函数里调它三次，参数分别给 6、15、100。 

6 翻一倍是 12
15 翻一倍是 30
100 翻一倍是 200

这道题的重点不在算得对不对，在申请和释放写在同一个函数里—— 两边数目才能直接对应，修改起来也不容易遗漏。

看答案

题面那句「申请和释放写在同一个函数里」，落实到代码上就是这个形式： 申请、使用、释放三件事连在一起。 

#include <iostream>

void show_double(int x) {
    int* p = new int;
    *p = x * 2;

    std::cout << x << " 翻一倍是 " << *p << std::endl;

    delete p;
}

int main() {
    show_double(6);
    show_double(15);
    show_double(100);

    return 0;
}

这一份的价值不在计算结果（乘 2 本身很简单），而在于数目可以直接数清： 这个函数里一个 new、一个 delete， 两边数目对得上。以后修改这个函数（增加一个分支、增加一条提前返回）， 释放的那一句就在相邻几行里可见，不容易遗漏。

反过来：如果申请和释放分散在两个函数里，两边就必须依靠一条约定维持—— 练习 5-4 就是这种情形，那一题讲的就是这条约定。

你现在能写什么：说清一个变量存放在栈上还是堆上； 从堆上申请一块内存（new、new int[n]）并释放 （delete、delete[]，两边对着带方括号）； 把栈上变量的地址向外传出的时候，要立刻想到—— 那个变量马上就会被销毁。

5.2new 和 delete 为什么危险

前面那两步——申请一块内存、释放——各是一行代码，看上去不难。 这一课讲它们为什么是全 C++ 里最容易出错的地方： 申请时得到的是一个地址，释放时依据的也是那个地址； 中间只要记错一步，出错的形式还各不相同。

箭头：p->name

先补一个小写法。指针指着一个对象，想取它里面的字段， 写全了要分两步： 

(*p).name

那对括号不能省：*p.name 的意思是「p 自己身上那个 name」——可 p 是个指针，身上没有这个字段。 括号是给「先通过指针找到对象」这一步划个范围。

这个写法用得多，就有一个简写： 

p->name        // 和 (*p).name 是一回事

下面这份程序把两种写法并列展示，运行输出的每一行都相同： 

#include <iostream>
#include <string>

class Student {
public:
    std::string name;
    int score;

    Student(std::string n, int s) {
        name = n;
        score = s;
    }
};

int main() {
    Student* p = new Student("小李", 92);

    std::cout << "写全了：" << (*p).name << " " << (*p).score << std::endl;
    std::cout << "用箭头：" << p->name << " " << p->score << std::endl;

    p->score = 95;      // 改的是堆上那个对象
    std::cout << "改过之后：" << (*p).score << std::endl;

    delete p;
    p = nullptr;

    return 0;
}
写全了：小李 92
用箭头：小李 92
改过之后：95

以后看到 ->，就当它读成「通过指针找到那个对象，再取它的……」。 这一部分起，用指针碰对象的地方一律写箭头。

错法一：申请了不释放

第一件错事最直接：申请了内存，忘记释放。

申请到的内存一直处于占用状态，别人无法申请、你也无法使用； 直到程序退出，系统才把这块内存收回。程序运行三行就结束，看不出问题； 换成一个运行一整天的程序，占用的内存就一直增加——这种错误有一个名字， 叫内存泄漏（memory leak），没有释放的那些内存叫泄漏的内存。

课里不装检查工具（不要求装新软件），那就自己计数： 每次 new 记一次，每次 delete 记一次， 运行结束后核对这两个数。

例题 · 自己计数

两个计数器，一个记录申请了几次、一个记录释放了几次。第一版申请一个释放一个， 第二版申请十个一个不释放——看最后两个数相差多少。 

#include <iostream>

int created = 0;        // new 了几次
int released = 0;       // delete 了几次

int* make_value(int x) {
    created = created + 1;
    int* p = new int;
    *p = x;
    return p;
}

void release_value(int* p) {
    released = released + 1;
    delete p;
}

int main() {
    std::cout << "—— 第一版：申请一个，释放一个 ——" << std::endl;
    int* a = make_value(1);
    std::cout << "取得 " << *a << std::endl;
    release_value(a);

    std::cout << "—— 第二版：申请十个，一个不释放 ——" << std::endl;
    for (int i = 0; i < 10; i++) {
        int* p = make_value(i);
        std::cout << "取得 " << *p << std::endl;
    }

    std::cout << "申请了 " << created << " 次，释放了 " << released
              << " 次。" << std::endl;
    std::cout << "未释放的内存有 " << created - released << " 块。" << std::endl;

    return 0;
}

最后两行就是这一课要留下的印象：程序运行正常， 一行报错都没有，未释放的内存有十块。离开这个程序之后， 那十块内存谁都无法再取得。

还要看清一件事：泄漏的是第二版那十个——make_value 申请了， 可没有人释放。第一版为什么没有问题？因为申请和释放都写在能直接看到的地方。 下一课起，这一条会变成一条正规的写法。

错法二：释放两次

第二件错事反过来：同一块内存释放两次。

释放的意思是「这块内存我用完了，其他代码可以申请」。 第一次释放之后，那一块就可能已经归别人了；再次释放， 等于释放了属于别人的内存。这件事运行库能检查出来—— 它记录着每一块内存的分配情况，同一块释放两次，立刻就把程序中止。 

#include <iostream>

int main() {
    int* p = new int;
    *p = 7;
    std::cout << "查看：" << *p << std::endl;

    delete p;
    std::cout << "释放完成。" << std::endl;

    delete p;       // 同一块内存释放第二次——错在这一行
    std::cout << "这行到不了。" << std::endl;

    return 0;
}

运行结果是这样——最后那句「这行到不了」一直没有输出，因为程序在上一行就终止了： 

查看：7
释放完成。
free(): double free detected in tcache 2

第三行不是程序输出的，是运行库自己输出的信息，翻译过来就是「发现同一块内存释放了两次」。 到这儿程序被立刻中止，退出码 134——所以最后那句「这行到不了」 一直没有输出。终端通常还会输出一句「已中止（核心已转储）」。

这一种错误至少终止得明确：立即停止，输出的信息也对得上。 真正难查的是下一种。

错法三：释放后继续使用

第三件错事：内存已经释放，地址还保留着，继续用它读写。 释放之后那个地址有一个名字，叫悬空指针（dangling pointer）。 

#include <iostream>

int main() {
    int* p = new int;
    *p = 7;
    std::cout << "写进去的是 " << *p << std::endl;

    delete p;       // 释放完成，从这一刻起 p 是悬空指针

    std::cout << "释放之后又读了一次，读到 " << *p << std::endl;
    std::cout << "——这个数无效：再运行一次，可能就是另一个数。" << std::endl;

    p = nullptr;    // 能做的一件正事：把指针置成空，防止下次再拿它去读写
    return 0;
}

运行结果： 

写进去的是 7
释放之后又读了一次，读到 -169083852
——这个数无效：再运行一次，可能就是另一个数。

看第二行：它不崩溃、不报错，直接给出了一个数。 同一份程序再运行一次，可能是别的数——这块内存已经不由你管理， 里面是什么无法确定。这种「标准不作任何保证」的行为有一个名字， 叫未定义行为（undefined behavior）。

这一种错误最难排查，原因就在这里：它不会立即停止。崩溃的程序你会去检查； 算错了却不报错的程序，可能要过很久才能从结果上发现它不对。

三条纪律

三种错误都源于同一个对象：那个地址。管理好它，三种错误一起减少：

  • 一、配对。有 new 的地方，问一句「谁负责释放」； 有 delete 的地方，问一句「释放的是不是当初申请的那一块」。 两句话写在一起最好——接下来这门课会让你把两句话封装在同一个类里。
  • 二、释放后立即把指针置成空。p = nullptr;。 这一句只解决一件事：释放后继续使用的时候立即就会中止 （空指针一旦被读写，程序会立刻终止），而不是给出一个错误的结果。 在能查到的地方中止，比错了却不报错强。
  • 三、一次只申请一块内存。一个 new 配一个 delete； 申请一整块（new int[n]）配 delete[]。 别让一个 p 同时保存两个地址——保存两个， 迟早会释放错一个。

练习

练习 5-3

读一个 n，跟着读 n 个数（放进 new int[n] 那一块），找出最大的和最小的并输出， 最后整块释放。

6
92 85 77 60 58 100
最高 100
最低 58

两个数都从第一个数开始，不要从 0 开始——否则全为负数的一组数会得到 0。 写完核对答案。

看答案

先把数据读进来，再逐个比较。最大值和最小值都从第一个数开始： 

#include <iostream>

int main() {
    int n = 0;
    std::cin >> n;

    int* data = new int[n];
    for (int i = 0; i < n; i++) {
        std::cin >> data[i];
    }

    int big = data[0];
    int small = data[0];
    for (int i = 1; i < n; i++) {
        if (data[i] > big) {
            big = data[i];
        }
        if (data[i] < small) {
            small = data[i];
        }
    }

    std::cout << "最高 " << big << std::endl;
    std::cout << "最低 " << small << std::endl;

    delete[] data;
    data = nullptr;

    return 0;
}

重点是那两个初始值。如果写成 big = 0; small = 0;， 这份输入里结果仍然正确（数据中有正有负），但换一组全为负数的数据 （例如 -5 -8 -3），最大值会被报告为 0—— 因为 0 从未出现在这组数据中。初始值必须取自数据本身。

循环从 i = 1 开始，是因为第 0 个元素已经作为初始值使用； 从 0 开始再比较一遍也不会出错，只是多比较一次。

顺序上还有一处需要注意：n 必须先读入，内存才能申请 （new int[n] 里的 n 必须先有值）。所以这份程序里 先读 n、后申请内存的次序不能颠倒。

练习 5-4

写一个函数 make_zeros(int n)：从堆上申请一块能存放 n 个元素的内存， 全部写成 0，把那个地址返回。主函数里取得它，把第 3 个元素 （下标 2）改成 7，整块输出，最后整块释放。 

0 0 7 0 0

这道题练的是那句话：谁申请谁释放。函数申请的那块内存， 返回指针的时候，释放的工作也一并交给调用者—— 这道题的释放写在 main 里。想让这句话不再靠人记， 要等后面讲到的现成工具。

看答案

题面那句话是这道题的全部：谁申请谁释放。函数负责申请， 释放的工作交给取得指针的那一方完成。 

#include <iostream>

int* make_zeros(int n) {
    int* data = new int[n];
    for (int i = 0; i < n; i++) {
        data[i] = 0;
    }
    return data;
}

int main() {
    int* data = make_zeros(5);

    data[2] = 7;        // 取得后直接使用

    for (int i = 0; i < 5; i++) {
        std::cout << data[i] << " ";
    }
    std::cout << std::endl;

    delete[] data;      // 用完了，谁取得的谁释放
    data = nullptr;

    return 0;
}

三处值得注意：

  • make_zeros 里没有 delete[]， 这是正确的。它申请的那块内存不是在这里用完，而是要交出去。 函数返回时，data 这个指针变量（存放在栈上）随之销毁， 可它指向的那块内存仍在堆上有效——交出去的就是那个地址。
  • main 里那句 delete[] data; 不是可以省略的。它是「谁申请谁释放」这条约定的落实处。
  • 这条约定由人遵守，编译器不负责检查。把最后那句删掉， 程序仍然能编译通过、正常运行，只是会留下一块未释放的内存（五个元素）—— 上面那份例题统计的就是这种情况。

下一课要讲的写法，解决的正是这个问题：把这条约定写进类型里， 不再依赖人的记忆。

你现在能写什么：读别人的代码时认得出 new 和 delete 的配对；知道不释放、释放两次、释放后继续使用三种错各自 是什么形式、哪一种最难检查；编写一个 new 时同时配一个 delete，释放后就把指针置成 nullptr； 看到 -> 读作「通过指针找到那个对象，再取它的……」。

5.3RAII：把「释放」写进类型里

前面那三条纪律，说到底都是同一个要求：申请和释放都必须由人记住。 这一课换一种办法——「释放」这件事不再靠人记住，而是交给类型负责。 这个办法有个名字，叫 RAII（resource acquisition is initialization， 资源获取即初始化）：资源在对象创建时取得，在对象销毁时释放。

手动管理的代价

先看清「靠人记住」最困难的地方：一个函数不止一条出口。

下面这份程序算一件事：1 加到 n，第一次超过 limit 时用到了几个数。 中途超了就从半路返回，一直没超就一直执行到末尾。那块内存在函数开头申请， 「释放」写在哪里，就是这份程序要暴露的问题。 

#include <iostream>

// 1 到 n 加起来，第一次超过 limit 时用到了几个数。
// 中途就超了，就提前返回；一直没超，就计算到 n。
int count_until_over(int n, int limit) {
    int* data = new int[n];
    for (int i = 0; i < n; i++) {
        data[i] = i + 1;
    }

    int sum = 0;
    for (int i = 0; i < n; i++) {
        sum = sum + data[i];
        if (sum > limit) {
            std::cout << "（中途返回的出口——这里没有写 delete[]）" << std::endl;
            return i + 1;       // 出口一：提前返回，内存没有释放
        }
    }

    std::cout << "（正常结束的出口——这里写了 delete[]）" << std::endl;
    delete[] data;              // 出口二：正常结束，已释放
    return n;
}

int main() {
    std::cout << "限 10：" << count_until_over(10, 10) << " 个数" << std::endl;
    std::cout << "限 100：" << count_until_over(10, 100) << " 个数" << std::endl;
    return 0;
}

运行一遍： 

限 10：（中途返回的出口——这里没有写 delete[]）
5 个数
限 100：（正常结束的出口——这里写了 delete[]）
10 个数

第一次在第 5 个数上超过了，从半路返回——那块内存没有人释放； 第二次执行到末尾，出口前那句 delete[] 完成了释放。 两份输出看上去一样整齐，但第一次有一块内存没有释放。

这不是写这份程序的人疏忽。真正的问题是：出口多一条， 就多一处要写「释放」；以后再加一条出口，还得记得再补一遍。 靠记忆无法保证的事，就应当换一种办法保证。

析构函数

对象销毁的时候，有一个方法会被自动调用一次， 叫析构函数（destructor），名字是类名前加一个 ~，不收参数。

把那块内存和「释放」一起写进一个类里，析构函数就成了「释放」的执行位置： 

class Buffer {
public:
    Buffer(int n) : data(new int[n]), count(n) {}   // 构造时：申请那块内存
    ~Buffer() { delete[] data; }                    // 销毁时：整块释放

private:
    int* data;
    int count;
};

这一下把前面那两条纪律都交给了编译器：

  • 配对——new 和 delete[] 写在同一个类里， 相隔几行就互相可见，不用通篇查找「谁负责释放」。
  • 不重不漏——「释放」的那一句只有一个地方写着， 出口有几条都不影响它：对象销毁的时候，析构函数一定会被调用。

这一套办法的名字就是这一课的标题：RAII。前半句是构造函数， 后半句是析构函数——申请和释放，都由对象的构造与销毁自动完成。

对象什么时候销毁

既然「释放」由对象销毁的时刻决定，就必须知道对象什么时候销毁。三种时刻：

  • 离开它所在的那对花括号。花括号一闭合，里面那些对象就销毁了。 这也是为什么想看清对象的构造与销毁，最直接的办法是把它们放在一对花括号里。
  • 函数从任何一条出口返回。中途返回也好、执行到末尾也好， 函数里那些对象都在这一刻销毁。上一节那条半路出口漏掉 delete[] 的问题，在这条规则下自然就补上了。
  • 存放它的容器销毁的时候。如果一个 vector 里存放着这种对象， 容器被销毁时，里面每一个都会执行自己的析构函数。

顺序上还有一条规则：同时销毁的几个对象，按构造顺序的逆序销毁—— 后构造的先销毁。练习 5-6 会让你亲眼看到这个顺序。

复制那条路要关掉

还有一处没有处理：往容器里添加元素，常常是复制一份进去的—— C++ 里一个对象默认就是可以复制的（编译器自动提供一个拷贝构造函数）。

可 Buffer 这种保存地址的类不能随意复制： 复制一份出来，就是两个对象保存着同一块内存；两个对象又都会销毁， 销毁时各释放一次——同一块释放两次，正是前面那个「释放两次」的错法。

所以这一条要明确写出：禁止复制。写法是在拷贝构造函数后面写 = delete： 

Buffer(const Buffer&) = delete;     // 禁止复制，避免两个对象指向同一处

如果再次尝试复制，编译器会立刻报错： 

#include <iostream>

class Buffer {
public:

    ~Buffer() { delete[] data; }

    Buffer(const Buffer&) = delete;     // 这一条把拷贝关掉了

    int size() const { return count; }

private:
    int* data;
    int count;
};

int main() {
    Buffer a(5);
    Buffer b = a;       // 从 a 复制一个——被阻止在这一行
    std::cout << b.size() << std::endl;
    return 0;
}

那句 use of deleted function 翻译过来就是「你使用的这个函数 已经被删除」。把错误阻止在编译这一步，比让它运行的时候再出错好得多。 报错里那个 note 还直接指回删除声明的那一行，定位非常直接。

例题 · 把「释放」写进析构

把上一节那份程序改一遍：那块内存交给自己写的 Buffer 管理， 两条出口上什么都不写。看它是否会泄漏。 

#include <iostream>

class Buffer {
public:
    Buffer(int n) : data(new int[n]), count(n) {
        std::cout << "（申请一块能存放 " << count << " 个元素的内存）" << std::endl;
    }

    ~Buffer() {
        delete[] data;
        std::cout << "（释放完成）" << std::endl;
    }

    Buffer(const Buffer&) = delete;     // 禁止复制，避免两个对象指向同一处

    void set(int i, int v) {
        data[i] = v;
    }

    int get(int i) const {
        return data[i];
    }

    int size() const {
        return count;
    }

private:
    int* data;
    int count;
};

int count_until_over(int n, int limit) {
    Buffer buf(n);
    for (int i = 0; i < n; i++) {
        buf.set(i, i + 1);
    }

    int sum = 0;
    for (int i = 0; i < n; i++) {
        sum = sum + buf.get(i);
        if (sum > limit) {
            std::cout << "（中途返回的出口——这里没有写任何释放语句）" << std::endl;
            return i + 1;
        }
    }

    std::cout << "（正常结束的出口——这里也没有写任何释放语句）" << std::endl;
    return n;
}

int main() {
    std::cout << "限 10：" << count_until_over(10, 10) << " 个数" << std::endl;
    std::cout << "限 100：" << count_until_over(10, 100) << " 个数" << std::endl;
    return 0;
}
限 10：（申请一块能存放 10 个元素的内存）
（中途返回的出口——这里没有写任何释放语句）
（释放完成）
5 个数
限 100：（申请一块能存放 10 个元素的内存）

两次都出现了「（释放完成）」——中途那条出口上什么都没写，内存照样被释放了。 那一句是析构函数输出的。

  • 「（申请一块能存放 10 个元素的内存）」排在「限 10：」前面。因为 count_until_over 要整个执行完，才轮到 std::cout 把结果输出——对象构造的那一刻， 也包含在「整个执行完」里。

练习 5-5

自己写一个类 IntArray：构造的时候给它一个 n， 它从堆上申请一块能存放 n 个元素的内存（同时都写成 0）；析构的时候整块释放。 再给三个方法：set(i, v) 往第 i 个元素写, at(i) 读第 i 个元素，sum() 把整块加起来。 最后照上面那条纪律，把复制关掉。

主函数里创建一个能装 4 个元素的，依次写进 10、20、30、40，然后输出： 

一共 4 个元素
第 3 个元素是 30
加起来是 100

整份程序里不应该出现一个 delete—— 它只写在类里面那一处。写完后核对答案。

看答案

这道题是把这一课讲的 RAII 手动编写一遍：申请写在构造函数里， 释放写在析构函数里，其他位置一句 delete 都不写。 

#include <iostream>

class IntArray {
public:
    IntArray(int n) : data(new int[n]), count(n) {
        for (int i = 0; i < n; i++) {
            data[i] = 0;
        }
    }

    ~IntArray() {
        delete[] data;
    }

    IntArray(const IntArray&) = delete;

    void set(int i, int v) {
        data[i] = v;
    }

    int at(int i) const {
        return data[i];
    }

    int size() const {
        return count;
    }

    int sum() const {
        int s = 0;
        for (int i = 0; i < count; i++) {
            s = s + data[i];
        }
        return s;
    }

private:
    int* data;
    int count;
};

int main() {
    IntArray a(4);
    a.set(0, 10);
    a.set(1, 20);
    a.set(2, 30);
    a.set(3, 40);

    std::cout << "一共 " << a.size() << " 个元素" << std::endl;
    std::cout << "第 3 个元素是 " << a.at(2) << std::endl;
    std::cout << "加起来是 " << a.sum() << std::endl;

    return 0;
}

几处需要逐一说明：

  • 构造函数里同时把每个元素都写成 0。堆上申请的那块内存里是什么 无法确定，这一步把它处理掉了——申请完立刻给出一个确定的值， 使用的人就不必再关心这件事。
  • at / sum / size 都写成 const 方法。它们只读不修改， 标记为 const 之后，只读的对象也能调用它们 （只读对象不能调用会修改数据的方法）。
  • IntArray(const IntArray&) = delete; 这一行不能遗漏。 漏写也能编译通过，但两份 IntArray 会指向同一块内存， 两个对象一起销毁的时候会把同一块内存释放两次， 程序会立即中止。
  • 整份程序里没有一句 delete。释放只在析构函数里 出现唯一一次，无论从哪条路径退出都不影响。

#include <iostream>

class Marker {

            Marker c("丙");

}

三件事一次说明：

  • 在哪个花括号里创建，就在那个花括号结束时销毁。 丙在里面那一层，所以它是唯一一个在「进内层」和「出内层」 之间出现两次的名字。
  • 同一层里顺序相反。甲先创建、乙后创建，销毁时乙先销毁—— 按构造顺序的逆序。
  • 两次「构造」之间没有其他动作。析构函数不是在某个特定 语句上被调用的，而是在花括号闭合的那一刻自动调用。

记住这两条，以后阅读别人的代码时就能判断：函数中途 提前 return 的时候，其中那些对象是在什么时候销毁的。

你现在能写什么：让一个类来管理「申请」和「释放」—— 构造函数里取得资源，析构函数里释放，从此使用的人一句 delete 都不用写；说得清一个对象在什么时候销毁、 同时销毁的几个谁先销毁；知道保存地址的类要把复制关掉 （= delete），以及被拦住时那句 use of deleted function 是什么意思。

5.4智能指针

上一课那一套是手写的：自己定义一个类，把 new 写进构造函数、 把 delete 写进析构函数。这一课要说的是—— 这件事已经有人写好了，而且是标准库提供的。 现成的工具叫智能指针（smart pointer）。

unique_ptr

最常用的那个叫 std::unique_ptr，定义在 <memory> 头文件里。 用法是这样： 

#include <memory>

std::unique_ptr<Counter> c = std::make_unique<Counter>(10);
c->add(5);      // 用起来和指针一模一样：箭头照旧
// 花括号一结束，它管理的那个对象自动销毁，delete 一句都不用写

三处说清楚：

  • 尖括号里写「它管理什么」。unique_ptr<Counter> 就是一个管理 Counter 对象的指针。上一课那个 Buffer 要自己写，这里省掉了写那个类的工作。
  • make_unique 负责「构造」。括号里的参数原样交给 Counter 的构造函数——make_unique<Counter>(10) 执行的就是 new Counter(10)，只是这一次构造出来的对象立即由智能指针管理。
  • 用起来和普通指针一模一样。c->add(5) 里那个箭头， 和前面学的箭头是同一个。区别只在「谁负责释放」：普通指针要你自己 记得 delete，它不需要。

名字里那个 unique 是「独占」：一个对象， 同一时刻只由一个 unique_ptr 管理。这一条下面马上讲。

只能移动，不能复制

管理同一个对象的两份 unique_ptr，最后会各释放一次—— 又是前面那个「释放两次」的错法。所以这一条写进了类型里：它禁止复制。 

#include <iostream>
#include <memory>

int main() {
    std::unique_ptr<int> a = std::make_unique<int>(7);
    std::unique_ptr<int> b = a;     // 想让两个名字都指向它——被阻止在这一行
    return 0;
}

看上去很长，其实说的还是上一课那一句：= delete。 std::unique_ptr 把复制这条路自己关闭了。 中间那两行 /usr/include/c++/13/… 是标准库的头文件路径， 意思是「这条规则写在标准库里」——不需要去读它。

要换一个持有者，写 std::move： 

std::unique_ptr<Counter> b = std::move(a);   // 交给 b 管理，a 置空

这一句的意思不是「复制一份给它」，而是「这一份由你管理，我这边不再需要」—— 是移动，不是复制。移动之后 a 是空的，这就是「独占」得以保证的方式。 std::move 这个写法下一课专门讲。

整块内存

申请一整块内存，写的是 new int[n]，释放的时候写 delete[]。这一对也能交给它：尖括号里加一对空的方括号， 就表示「管理的是一整块内存」。 

#include <iostream>
#include <memory>

int main() {
    std::unique_ptr<int[]> data = std::make_unique<int[]>(5);

    for (int i = 0; i < 5; i++) {
        data[i] = (i + 1) * 10;
    }

    int sum = 0;
    for (int i = 0; i < 5; i++) {
        sum = sum + data[i];
    }

    std::cout << "加起来：" << sum << std::endl;
    std::cout << "最后一个：" << data[4] << std::endl;

    return 0;
}
加起来：150
最后一个：50

用法和普通数组一样：data[i] 直接下标，不用箭头。 （make_unique<int[]>(5) 括号里那个 5 是「要几个元素」。） 「释放」那一端不需要处理——它记录着自己管理的是一整块内存， 销毁的时候会使用 delete[]，不会用错。

shared_ptr 和 weak_ptr

还有一种情形 unique_ptr 无法处理：一个对象， 真的有两处地方同时要用它，谁都不能先释放。 标准库为这个准备的是 std::shared_ptr（共享指针）： 它可以复制，而且带计数——每一份都算一个「仍然持有」的计数， 最后一个计数归零时，对象才销毁。

还有第三个，叫 std::weak_ptr：跟随 shared_ptr 观察，但不增加计数——只观察，不持有。 它是用来解决循环引用问题的：两个对象互相持有对方的 shared_ptr，两边的计数都无法归零，对象就永远不会销毁。

这两个这门课讲到认识一下为止：见到 shared_ptr， 知道它是「计数的」；见到 weak_ptr，知道它「不增加计数」。 它们怎么用、什么时候选择哪一种，附录 D 列了一张表，用到的时候查阅。 这一部分要讲透的是 unique_ptr—— 日常使用中九成的情况用它即可，而且它更节省、更清楚：谁管理它，可以直接看出。

练习 5-7

写一个类 Student：构造函数里输出一行「（名字 进了名单）」， 析构函数里输出一行「（名字 出了名单）」，另有一个 show() 输出名字和分数。

主函数里用 unique_ptr 创建一个「小李，90 分」， 给他加 5 分、输出一次；然后在返回之前先输出一行「—— 主函数要结束了 ——」。 

（小李 进了名单）
小李 95
—— 主函数要结束了 ——

最后那一行「（小李 出了名单）」是在哪一个时刻输出的，想清楚之后再往下看。 整份程序里不应该出现 delete。

看答案

同一件事交给 unique_ptr：创建、使用、销毁， 三步里没有一步涉及 delete。 

#include <iostream>
#include <memory>
#include <string>

class Student {
public:
    Student(std::string name, int score) : name(name), score(score) {
        std::cout << "（" << name << " 进了名单）" << std::endl;

    ~Student() {
        std::cout << "（" << name << " 出了名单）" << std::endl;
    }

        std::cout << name << " " << score << std::endl;
    }

private:
    std::string name;
    int score;
};

int main() {
    std::unique_ptr<Student> s = std::make_unique<Student>("小李", 90);

练习 5-8

练习 5-1 那道题用新工具重写一遍：读一个 n， 跟着读 n 个数，求和后输出。这一次那块内存交给 std::unique_ptr<int[]> 管理，

看答案

和练习 5-1 是同一件事，改用智能指针完成： 

#include <iostream>
#include <memory>

int main() {
    int n = 0;
    std::cin >> n;

    std::unique_ptr<int[]> data = std::make_unique<int[]>(n);
    for (int i = 0; i < n; i++) {
        std::cin >> data[i];
    }

    int sum = 0;
    for (int i = 0; i < n; i++) {
        sum = sum + data[i];
    }

    std::cout << n << " 个数的和是 " << sum << std::endl;

    return 0;
}

对照 5-1 那份，少了三样：new、 delete[]、还有那句 data = nullptr;。 减少的那三项，就是「释放」这件事原本由编写程序的人承担的部分。

不变的是用法：data[i] 照写， std::cin >> data[i] 照写。它管理的是一块内存， 使用时就是数组的形式；「释放」那一端由它自己使用 delete[] 完成。

有一处容易混淆，需要注意：make_unique<int[]>(n) 括号里那个 n 是元素个数；而 make_unique<int>(7) 括号里那个 7 是 构造它所用的参数（那个元素初始就是 7）。申请整块内存时写元素个数， 单个对象时写给它什么初值——同样是括号，问的是两件事。

你现在能写什么：用 make_unique 创建一个对象交给 unique_ptr 管，用箭头照常调它的方法，从此不写 delete；要换一个持有者就用 std::move； 一整块内存写 std::unique_ptr<int[]>； 看到「复制函数被删除」那类报错知道它在说什么； 见到 shared_ptr / weak_ptr 认得它们是干什么的。

5.5移动与简洁的写法

这一课把三件减少开销的写法集中起来：不复制第二份数据 （std::move）、放进容器时不做多余的构造 （emplace_back）、把内部的各个部分直接命名 （结构化绑定），最后介绍一个一直没有专门说明的小容器（std::array）。

std::move

上一课已经用过一次 std::move 了。它是把一份数据转移出去的表达方式： 

#include <utility>

std::vector<std::string> b = std::move(a);   // a 的元素整批转移给 b

读法很重要。std::move(a) 不是「让 a 移动一下」， 它的意思是「我以后不再使用 a，你可以把它的内容转移走」。 这个表达写出之后，a 里面的数据就整体移动到了别处。

还有一句要紧的话：std::move 自己一个字节都不移动。 它只是把这个意图表达出来；真正执行移动的是接手的一方 （b 的构造函数）。所以「移动」的效果全部落在 b = std::move(a) 这一行上。

移动之后的 a 不是损坏，而是变空：可以再往里添加元素， 也可以重新给它赋值；唯一不能做的，是继续依赖它原来保存的内容。

为什么快

回到前面说过的那件事：一个 std::vector 对象本身很小， 元素并不存放在它里面，而是存放在堆上一块连续的内存里， 由对象内部的指针指向它。

所以「把 a 的元素交给 b」有两种做法：

  • 复制：在堆上另外申请一块同样大的内存，把每一个元素复制过去。 元素多，这一步的代价就高；元素本身要是还各自占用堆上的一块内存 （比如每一个 std::string），那每一份还要再复制一遍。
  • 移动：把指针转移出去。仍然是原来那块内存，一个元素都没有复制。

这就是 std::move 的全部意义：该复制的时候复制， 不该复制的时候不要复制。一份数据在程序里往往要在好几个位置之间传递， 每传递一次复制一遍，累计起来就是不必要的开销。

使用它之前先问自己一句：这份数据我以后还用不用？确定不用了才移动。 往容器里添加元素也一样——下面那个写法省掉的就是这一步。

emplace_back

前面往 vector 里添加元素用的是 push_back。它的做法是： 先创建一个对象，再复制一份放进去；在容器外创建的那个对象，复制完成后就销毁。

如果能直接在它最终所在的位置上构造出来，这一次复制就省掉了。 负责这件事的写法叫 emplace_back： 

#include <iostream>
#include <string>
#include <vector>

class Student {
public:
    std::string name;
    int score;

    Student(std::string n, int s) : name(n), score(s) {
        std::cout << "（构造一个 " << name << "）" << std::endl;
    }

    Student(const Student& other) : name(other.name), score(other.score) {
        std::cout << "（复制一份 " << name << "）" << std::endl;
    }
};

int main() {
    std::vector<Student> by_push;

    std::cout << "—— push_back：先创建，再复制进去 ——" << std::endl;
    by_push.push_back(Student("小李", 90));

    std::vector<Student> by_emplace;

    std::cout << "—— emplace_back：直接在目标位置构造 ——" << std::endl;
    by_emplace.emplace_back("小王", 88);

    std::cout << "—— 两份名单 ——" << std::endl;
    for (const Student& s : by_push) {
        std::cout << s.name << " " << s.score << std::endl;
    }
    for (const Student& s : by_emplace) {
        std::cout << s.name << " " << s.score << std::endl;
    }

    return 0;
}

运行一遍（那个类把「构造」和「复制」各输出一行，就是为了让人看见两条路的区别）： 

—— push_back：先创建，再复制进去 ——
（构造一个 小李）
（复制一份 小李）
—— emplace_back：直接在目标位置构造 ——
（构造一个 小王）
—— 两份名单 ——
小李 90
小王 88

两边的名单一样，中间执行的操作不一样：一条路上「构造」和「复制」各一次， 另一条路上只有「构造」。对象越复杂，省下的这一步越可观。

括号里的写法也跟着变： 

by_push.push_back(Student("小李", 90));   // 在外部先创建一个，再传入
by_emplace.emplace_back("小王", 88);      // 直接把构造参数传入

emplace_back 接收的是构造函数的参数，直接在目标位置构造。 所以往后：要添加一个原地构造的对象，直接写 emplace_back(参数…)；要添加一个已经存在的对象，仍然使用 push_back。

结构化绑定

前面遍历 map 的时候，键和值是这样拿的：it->first、 it->second。可以正常工作，但每一行都要跟着那两个名字， 写代码的人还得记住 first 是键、second 是值。

C++17 起有一个更直接的写法，叫结构化绑定（structured binding）： 把一个对象内部的各个部分，直接分别命名。 

#include <iostream>
#include <map>
#include <string>

int main() {
    std::map<std::string, int> score;
    score["小李"] = 92;
    score["小王"] = 85;
    score["小张"] = 77;

    std::cout << "—— 原名 ——" << std::endl;
    for (const auto& [name, s] : score) {
        std::cout << name << "：" << s << std::endl;
    }

    // 加了 &，这里是 map 里那一份的另一个名字，改的就是它
    for (auto& [name, s] : score) {
        s = s + 5;
    }

    std::cout << "—— 各加 5 分之后 ——" << std::endl;
    for (const auto& [name, s] : score) {
        std::cout << name << "：" << s << std::endl;
    }

    return 0;
}

运行一遍： 

—— 原名 ——
小张：77
小李：92
小王：85
—— 各加 5 分之后 ——
小张：82
小李：97
小王：90

方括号里就是直接命名的各部分：遍历一个 map， 每一轮取出一个「键 + 值」，两个名字正好接收。 顺序和 first / second 一样—— 第一个名字对应键，第二个对应值。

写法从箭头换成了中括号，别的规矩一条没改：

  • const auto&——只读不改，仍然是最节省的方式。
  • auto&——那个名字是容器中对应元素的引用， 修改它，容器中的元素也跟着改变。这份程序末尾那三行分数增加，依靠的就是它。
  • 少了那个 &，得到的是副本——一次迭代结束后它就销毁了， 容器里一个数都不会变。

std::array

std::array 这门课不专门讲，认得就行。 这一节就是它的基本样子。

C 风格的数组 int score[5] 有两个长期存在的问题： 无法取得自己的元素个数，也不能整体复制给其他对象。

std::array 是同一类数据的容器版本：大小写在类型里， 所需的功能都随之提供。 

#include <array>
#include <iostream>

int main() {
    std::array<int, 5> score = {90, 85, 77, 60, 95};

    std::cout << "有几个：" << score.size() << std::endl;

    int sum = 0;
    for (int x : score) {
        sum = sum + x;
    }
    std::cout << "总分：" << sum << std::endl;
    std::cout << "第一个：" << score[0] << "，最后一个：" << score[score.size() - 1]
              << std::endl;

    std::array<int, 5> copy = score;     // 整体复制给另一个对象——C 数组做不到这一条
    copy[0] = 0;
    std::cout << "复制一份、修改之后：原对象 " << score[0] << "，副本 " << copy[0]
              << std::endl;

    return 0;
}
有几个：5
总分：407
第一个：90，最后一个：95
复制一份、修改之后：原对象 90，副本 0

三处和 C 数组不一样：

  • 大小是类型的一部分。std::array<int, 5> 里那个 5 就是「五个元素」，改不了；size() 问得出这个数。
  • 能整体复制。std::array<int, 5> copy = score; 是一份真正的副本——最后两行输出的就是这件事： 修改了副本，原对象没有变化。
  • 它存放在栈上。和 C 数组一样，那五个元素就在对象自身内部， 不涉及堆。所以它适用于「大小在开始时已经确定」的场合—— 需要增加或减少元素个数，使用 vector。

什么时候会遇到它：大小从一开始就确定的地方（棋盘、骰子的六个面、 一周七天）。见到 std::array<int, 5>，读作「五个 int」，就够了。

例题 · 移动一次

std::move 的效果，用一份名单说明：移动之前、移动之后各输出一次。 

#include <iostream>
#include <string>
#include <utility>
#include <vector>

int main() {
    std::vector<std::string> a;
    a.push_back("小李");
    a.push_back("小王");
    a.push_back("小张");

第二行就是全部：元素在 b 那里，a 空了。没有复制出第二份， 也没有丢失——那三个名字整批转移给了新的持有者。

后半段用 std::string 又做了一遍。字符串的内容也存放在堆上， 对象内部同样只保存指向那块内容的指针，所以移动一个字符串和移动一个 vector 是同一件事：转移的是指针，堆上的内容一个字节都没有移动。

练习 5-9

用结构化绑定遍历 map：建一个 std::map<std::string, int>， 装三个人——小李 92、小王 85、小张 77。 先遍历一遍，每个人输出一行「名字 = 分数」； 再遍历一遍，每人加 3 分；最后再输出一遍。 

小张 = 77
小李 = 92
小王 = 85
—— 每人加 3 分 ——
小张 = 80
小李 = 95
小王 = 88

第二遍那个 & 要是漏了，第三段输出会一个数都没有变化—— 先按漏写的方式写一遍观察结果，再改回来。

看答案

两遍遍历的写法只差一个 &，第三段输出的结果差别很大： 

#include <iostream>
#include <map>
#include <string>

int main() {
    std::map<std::string, int> score;
    score["小李"] = 92;
    score["小王"] = 85;
    score["小张"] = 77;

    for (const auto& [name, s] : score) {
        std::cout << name << " = " << s << std::endl;
    }

    std::cout << "—— 每人加 3 分 ——" << std::endl;

    for (auto& [name, s] : score) {
        s = s + 3;
    }

    for (const auto& [name, s] : score) {
        std::cout << name << " = " << s << std::endl;
    }

    return 0;
}

第一遍用 const auto&：只读不修改，不产生副本。

第二遍用 auto&：那个 & 不能少。 少了它，每一轮得到的是从 map 里复制出来的一个临时对象， 修改的是这个副本，一次迭代结束后它就销毁了——第三段输出一个数都不会变化。 题面要求先按漏写 & 的版本写一遍，就是为了记住这个「什么都没有变」的结果。

还有一处容易被忽略：[name, s] 里那两个名字对应 first 和 second 的位置—— 第一个对应键，第二个对应值，位置固定，名字可以任意取。

添加元素用最节省的方式（原地构造，不复制），转移位置也用最节省的方式 （移动，不复制第二份）——这一部分讲的写法，这道题里各用了一次。

看答案

这一部分的收束题：添加元素采用最节省的方式，转移位置也采用最节省的方式。 

#include <iostream>
#include <string>
#include <utility>
#include <vector>

class Student {
public:
    std::string name;
    int score;

    Student(std::string n, int s) : name(n), score(s) {}
};

int main() {
    std::vector<Student> first;
    first.emplace_back("小李", 90);
    first.emplace_back("小王", 85);

    std::cout << "移动之前：first 有 " << first.size() << " 个" << std::endl;

    std::vector<Student> second = std::move(first);

    std::cout << "移动之后：second 有 " << second.size() << " 个，first 有 "
              << first.size() << " 个" << std::endl;

    for (const Student& s : second) {
        std::cout << s.name << " " << s.score << std::endl;
    }

    return 0;
}

三处分别对应这一部分的一个内容：

  • emplace_back("小李", 90) 把构造函数的参数直接传入， 在目标位置上构造一个对象。复制的那一步省掉了——上面那份用 push_back 对照的程序，展示的就是这个区别。
  • std::move(first) 的含义是「first 不再使用， 其中的元素全部转移过去」。所以移动之后 first.size() 是 0——那不是错误，而是预期的结果。
  • 移动之后接着要使用的是 second。这是这条写法唯一 需要留意的地方：移动之后，旧名字不再持有有效内容。

再回顾这一部分的开头：new / delete 那套需要人记住配对的写法，到这道题里一次都没有出现。

你现在能写什么：需要移动的时候写 std::move、 并且说得清它为什么快、移动之后的源为什么是空的； 往容器里添加原地构造的对象用 emplace_back； 遍历 map 的时候用结构化绑定直接为键值命名， 并且分得清加不加那个 & 的区别； 见到 std::array 认得出它是「大小固定在类型里、能整体复制」的定长数组。
