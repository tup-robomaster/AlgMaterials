C++ 进阶课

基础课教的是「在一个文件里写出一个能运行的程序」。这门课从那个终点往下走： 把程序拆成几个文件、让构建工具替你记住怎么编译、看懂一份实际运行的工程。 全部 9 个部分、46 课，已经全部放出。最后一部分是章末检测： 一道例题加五道题，把前面七个部分过一遍。

怎么用这份材料

一、先上完基础课。这门课默认你已经会了：变量与类型、判断与循环、 函数与传参、数组与 vector、struct 与 class、指针与引用。这些一样都不重讲—— 第 1 部分一开始就默认你知道「函数是一段具有明确功能的代码」。 还没上过的话，先去 C++ 基础课。

二、按顺序，不要跳。第 2 部分整部分建立在第 1 部分上： 不先亲手输入一遍命令，就不知道 cmake 在替你做什么。

三、每段代码都自己输入一遍、运行一遍。这一部分之后， 程序不再是一个文件了——漏掉一个文件、少编译一个文件， 屏幕上的报错还非常相似。课里的程序都在 示例代码/ 文件夹里，先自己输入，写不出来再去核对。

示例代码/ 就跟你正看的这一页在同一个文件夹里。 想在终端里查看、编译，先 cd 进去： cd 示例代码，再 ls -1 查看其中有哪些内容。 课里凡是让你「查看目录」的命令，都必须先进入那个目录—— 否则 ls 列出的是你自己的主目录。

课里的 cd 都是从 示例代码/ 这一层往下写的 （比如 cd 示例代码/1.3-两个文件）。 所以一节看完换下一节，要么先 cd .. 退回这一层， 要么直接另开一个终端——否则目录会一层比一层深， 下一节那条 cd 就无法找到对应目录了。

四、每个练习都给了「预期输出」。你的结果要和它逐字符一致， 差一个空格也是差。多文件工程和 cmake 的练习， 对的是最后一条命令运行完之后屏幕上的内容—— 前面几条命令的输出，题面里也一并给了，按照它核对。

五、遇到困难时，按这个顺序查找。

  1. 报错看不懂——先看是谁报的错（编译器、链接器、cmake、make 报错的样式各不一样）。 本课附录 A 头一节就讲这个。
  2. 忘了怎么写——单文件的语法查阅基础课那份附录； CMakeLists.txt 怎么写，查阅本课附录 B；最小模板和常用命令都在那里。
  3. 结果不对——把实际输出和课里的「预期输出」并列对照，逐字符比较。
注

文中部分代码块涉及终端操作。运行这些命令之前，先确认终端所在的位置是 ..（自己存放这个项目的目录）/..(本项目名称)/lessons/cpp_advanced。

第 0 部分 · 开始

不教语法。说清楚这门课从哪里接上，把 g++ 那一行逐段分析一遍。

  • 0.1 这门课从哪里接上 基础课会了什么、这门课要去哪里，以及三样工具在不在（逐个 --version）
  • 0.2 一行 g++ 背后 预处理、编译、汇编、链接——四个中间产物实际列出查看。第 1 部分的地基
  • 0.3 课里的程序怎么编译怎么运行 三种形态：单文件、多文件目录、cmake 目录；以及那份叫「构建.txt」的说明书

第 1 部分 · 一个程序，几个文件

从这一部分起，程序不再是一个文件。只回答两件事：为什么要拆、拆分之后各部分如何对应。

  • 1.1 为什么不能都写在一个文件里 一个真实的错误示例，以及它的问题在哪里
  • 1.2 #include 到底做了什么 就是「原样插入」；重复包含会怎样，#pragma once 解决的是什么
  • 1.3 声明和定义 为什么函数要写两遍：.h 放承诺，.cpp 兑现
  • 1.4 一次编译几个文件 -c 出 .o，再链接起来。中间文件实际列出查看
  • 1.5 链接错误的形式 直接运行一次 undefined reference，讲解如何阅读「谁在查找哪个符号」

第 2 部分 · cmake 基础

把那一组手动输入的命令交给构建工具：先交给 make，再交给 cmake。

  • 2.1 手动输入 g++ 的方式已经不够用 文件一多，那行命令就无法记住。Makefile 逐行看：冒号左边是产物，右边是依赖
  • 2.2 第一份 CMakeLists.txt 四行，替换手动输入的一长串命令。含 cmake 4 那个「版本号不能写得太小」的易错点
  • 2.3 多文件：源文件、头文件目录、标准 两个 .cpp 怎么列、头文件去哪里查找、标准怎么设置。同时查看三种报错
  • 2.4 常用的那十几条命令 组织成一张「命令表」，①–⑩ 逐条实际运行。末尾讲中文可以出现在哪些位置
  • 2.5 读一份真实的 CMakeLists 一百七十五行，实际运行的工程里的那一份。认识的逐段识别，没见过的先跳过

第 3 部分 · 容器

接着基础课那个 vector 往下走：数据应当存放在什么容器里。六种容器，一课一种，最后一课教怎么选择。

  • 3.1 vector 再进一步 基础课 4.1 那个易错点的后续。不使用下标的遍历、副本还是原对象、pop_back 和 clear、尖括号里放什么
  • 3.2 std::string 它也是一种容器。连接、比较、取子串；size 统计的是字节数；读一整行；查找一段、截取一段；两个双引号不能直接相加
  • 3.3 const 一条限定作用于两个位置。三种参数并列、写在变量上的 const、范围 for 里那个变量、写在自己定义的类上
  • 3.4 pair 与 map 两个值组合在一起；键不一定是数字；是否存在用 count 判断；它自身保持有序；中括号会创建元素
  • 3.5 set / queue / stack★ 有动画 只判断是否存在、先进先出、后进先出。末尾那个「pop 不返回元素」的易错点
  • 3.6 这么多容器怎么选择 四句话，从「要查询什么」反推到「该使用哪种容器」。无法确定就先用 vector

第 4 部分 · 时间复杂度与算法

回答第 3 部分留下的两个问题：删除中间元素、插入中间元素，还有「同样是查找一个元素，为什么有快有慢」。衡量标准叫时间复杂度，工具叫迭代器——学完再打开 <algorithm> 那一整套现成的工具。

  • 4.1 怎么估一段代码快不快★ 有动画 统计循环执行几次：一层 O(n)、两层 O(n²)、每次缩小一半 O(log n)。n 翻一倍时步数翻几倍，比记住名称更有用
  • 4.2 迭代器★ 有动画 能表示「第几个位置」的对象：begin / end / ++ / * 四个操作，还有 end() 为什么是「最后一个元素的后面」
  • 4.3 删中间、插中间 erase 需要的是位置而不是编号；删除中间元素要把后面的元素向前移动；「一边遍历一边删除」时 for 循环第三段留空的形式
  • 4.4 现成的工具 find、count、max_element、reverse、sort——每个都是「两个位置 + 一个值」
  • 4.5 lambda 条件也能当参数。_if 结尾的那几个工具接收条件；方括号里要写谁；给 sort 添加一条「谁排前面」的规则
  • 4.6 让 sort 能处理你自己定义的类型 自己定义的 struct 无法排序？给它一条规则；同时学习如何阅读那种很长的模板报错

第 5 部分 · 内存与所有权

回答第 3 部分留下的问题：容器里的元素存放在哪里、什么时候销毁，一直由容器管理。这一部分详细说明这件事——变量有两处存储位置（栈和堆），「申请一块内存、用完释放」为什么最容易出错，以及最后怎么把释放写进类型里，从此不需要直接编写 delete。

  • 5.1 栈和堆 变量有两处存储位置：栈上的由函数管理，进入和离开作用域时自动分配和释放；堆上的由你管理，申请一块内存（new）、用完释放（delete）。同时解释「容器里的元素为什么不存放在容器对象内部」
  • 5.2 new 和 delete 为什么危险★ 有动画 三种错误用法实际运行演示：申请了不释放（未释放的内存持续累积）、释放两次（程序立即中止）、释放后继续使用（不报错，但结果无效）。第一次教 p->name 这个箭头运算符
  • 5.3 RAII：把释放写进类型里 把释放写进析构函数：无论从哪条路径退出都不会遗漏。配一条纪律——内部存着指针的类要把拷贝关掉（= delete）
  • 5.4 智能指针 把 5.3 那件事交给标准库：用 make_unique 创建、离开作用域自动销毁、只能移动不能复制；另外两个（shared_ptr / weak_ptr）先作初步认识，细节查阅附录 D
  • 5.5 移动与简洁的写法 复制与移动的适用场合：std::move 移动一次、emplace_back 直接在目标位置构造而不复制、结构化绑定给键值命名，最后认识 std::array

第 6 部分 · 文件和异常

程序的数据不再只来自键盘和代码。这一部分讲怎么读写文件，以及文件打不开、数据不合格时，怎么用异常把问题交给调用方处理。

  • 6.1 读文件 用 ifstream 打开文件并检查是否成功；用 >> 逐个读取、用 getline 按行读取；解释为什么不能用 eof() 判断结束，以及 >> 之后接 getline 要先处理换行符
  • 6.2 写文件 用 ofstream 创建或覆盖文件；关闭文件后再读回；用 std::ios::app 追加写入；用 std::remove 删除文件
  • 6.3 throw 与 try / catch 用 throw 报告错误、用 try / catch 处理；异常离开函数时局部对象按逆序销毁（栈展开）；几条写法纪律
  • 6.4 标准异常 std::exception 与 what()；常见的标准异常类型；从 std::runtime_error 派生自定义异常；什么时候该用异常

第 7 部分 · 串口（uart）基础

程序开始和外部设备通信。这一部分从字节与位运算讲起，打开并配置串口，按真实裁判系统串口协议的帧格式（A5 帧、CRC8 与 CRC16）组帧、校验，用接收缓冲区处理粘包与半包，最后把收包循环接到一个简易的裁判系统上显示出来。

  • 7.1 十六进制与字节 一个字节用两个十六进制数字表示；用 unsigned char 与 std::uint8_t 保存 0 到 255；用 printf("%02X") 输出两位十六进制
  • 7.2 位运算 &、|、^、~、<<、>>；用掩码置位、清位、翻转、取某一位；用常量给标志位命名
  • 7.3 打开串口 串口是设备文件；open 的 O_RDWR | O_NOCTTY 与返回值检查；close；没有硬件时用 posix_openpt 造伪终端练习
  • 7.4 配置串口 termios 与 8N1；用 cfmakeraw 关掉终端处理；设置波特率；用 VMIN 与 VTIME 控制读的等待；设置后读回核对
  • 7.5 读写字节流 read 与 write 的返回值；一次读不保证拿到一整帧；短读与短写；用 unsigned char 缓冲区保存字节
  • 7.6 一帧长什么样 A5 帧的七个字段与偏移；data_length 只数 data 段；整帧长度为 data_length + 9；多字节字段低字节在前
  • 7.7 CRC 校验 CRC8 校验帧头、CRC16 校验整帧；多项式、初值与覆盖范围；标准算例与帧上的实际值；校验不过的帧整体丢弃
  • 7.8 粘包与半包★ 有动画 串口是字节流，没有消息边界；用接收缓冲区保存尚未处理的字节；一次读到多帧时循环取出；不足一帧时保留并等待
  • 7.9 状态机收包 找帧头、验 CRC8、读长度、等收齐、验 CRC16；任一步失败丢 1 个字节重新找；用模拟板在没有硬件时完成一问一答
  • 7.10 一个简易的裁判系统 把收包循环接到本地网页；总览、机器人状态表、按字段着色的数据包卡片与日志；观察坐标、血量、弹量随帧更新
