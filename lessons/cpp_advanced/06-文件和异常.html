第 6 部分

文件和异常

到第 5 部分为止，程序的数据来源只有两处：写在代码里的值，以及从键盘读入的输入； 结果输出到屏幕。实际使用的程序还要读写文件——数据、配置、运行记录都放在文件里。 文件可能不存在、打不开，读到的内容也可能不符合要求。 这一部分讲两件事：用文件流读写文件； 出错时用异常把问题交给调用它的代码处理。

6.1读文件

读文件的第一步是打开。C++ 标准库在 <fstream> 里提供了文件流： std::ifstream 用于读取，std::ofstream 用于写入， std::fstream 既能读也能写。这一课只使用 std::ifstream。

打开文件

打开一个文件，就是用一个文件名构造一个 std::ifstream 对象： 

#include <fstream>

std::ifstream in("6.1-scores.txt");
if (!in) {
    // 打开失败：文件不存在、路径不对，或者没有读取权限
}

in 是文件流对象。它可以用在 if 的条件里： 打开成功时为真，失败时为假。打开失败的原因通常有三种： 文件不存在、路径写错、当前用户没有读取权限。 每一次打开都要检查。不检查的话，后面的读取会全部失败， 程序拿到的仍然是变量的初始值，输出与预期不一致，却找不到原因。

文件名可以写相对路径，也可以写绝对路径。相对路径是相对于 程序运行时的当前工作目录，不是相对于源代码文件所在的位置。 这一点在实际使用时最重要：在命令行里先 cd 到数据文件所在的目录， 再运行程序；在集成开发环境里，要确认运行配置中的工作目录。 本课的示例程序和数据文件都放在 示例代码/ 里， 在那一层编译、运行即可。

文件流对象离开作用域时会自动关闭文件，所以大多数情况下不必手写关闭。 需要提前关闭、或者关闭之后要重新打开同一个文件时，再调用 in.close()。

用 >> 读取

文件流的读取方式和 std::cin 完全一样：用 >> 把内容读到变量里，它会自动跳过空白字符（空格、制表符、换行）。 

std::string name;
int score = 0;
while (in >> name >> score) {
    std::cout << name << " " << score << std::endl;
}

in >> name >> score 的结果是流本身，流对象可以用在条件里： 这一次读取成功时为真，失败时为假。while 的条件写读取动作， 读取失败时循环自然结束，这是文件读取的标准写法。

读取失败有两种常见原因：到达文件末尾，或者文件里的内容与变量的类型不匹配 （例如要读 int，遇到的却是字母）。两种情况下流都会进入失败状态， 循环结束。本课的数据文件格式都是正确的；需要处理格式错误时， 可以用第 6.4 课的 std::stoi，它会把不合格的内容作为异常报告出来。

例题 · 逐个读取成绩

文件 6.1-scores.txt 每行一个姓名和一个分数： 

张三 92
李四 85
王五 77
赵六 60
钱七 100

下面的程序逐个读入，输出每一条记录，最后计算平均分： 

#include <fstream>
#include <iostream>
#include <string>

int main() {
    std::ifstream in("6.1-scores.txt");
    if (!in) {
        std::cout << "文件打不开" << std::endl;
        return 1;
    }

    std::string name;
    int score = 0;
    int count = 0;
    int sum = 0;
    while (in >> name >> score) {
        std::cout << name << " " << score << std::endl;
        count++;
        sum = sum + score;
    }

    std::cout << "共 " << count << " 人，平均 " << sum / double(count) << std::endl;

    return 0;
}
张三 92
李四 85
王五 77
赵六 60
钱七 100
共 5 人，平均 82.8

sum / double(count) 把 count 转成 double 再相除，避免整数除法把小数部分丢掉。这个程序假定文件里至少有一个人： 如果文件是空的，count 为 0，除法就没有意义。 正式的程序应当在相除之前检查 count，这一点在第 6.4 课的练习里会用到。

不要用 eof() 判断结束

in.eof() 表示「上一次读取是否碰到了文件末尾」。 它只有在读取动作已经尝试越过末尾之后才变为真。 因此下面这种写法会多执行一次循环体： 

while (!in.eof()) {
    in >> name;
    std::cout << "读到：" << name << std::endl;
}

最后一次读取没有读到新内容，流进入失败状态，但循环体已经执行了： 程序把变量里上一次的内容又输出了一遍。正确的写法是把读取本身放进条件， 由读取的结果决定是否继续： 

while (in >> name) {
    std::cout << "读到：" << name << std::endl;
}

eof() 仍然可以用来在循环结束后判断「是不是读到了文件末尾」， 用来区分类似「文件损坏」和「正常读完」的情况；但它不适合用来控制循环。

例题 · 多输出的一行

文件 6.1-names.txt 有三行姓名。下面这份程序使用了 while (!in.eof())： 

#include <fstream>
#include <iostream>
#include <string>

int main() {
    std::ifstream in("6.1-names.txt");
    if (!in) {
        std::cout << "文件打不开" << std::endl;
        return 1;
    }

    std::string name;
    while (!in.eof()) {
        in >> name;
        std::cout << "读到：" << name << std::endl;
    }

    return 0;
}
读到：张三
读到：李四
读到：王五
读到：王五

最后一行出现了两次。第四次进入循环时，文件已经读完，in >> name 没有读到新内容；但循环体仍然执行了一次，把 name 中上一次的 「王五」又输出了一遍。把循环条件改成 while (in >> name) 以后，这次失败的读取会直接结束循环，重复的一行就消失了。

一次读一整行

>> 以空白字符分隔，适合读一个个单词或数字。 要读一整行（行内可能包含空格），用 std::getline： 

std::string line;
while (std::getline(in, line)) {
    std::cout << line << std::endl;
}

std::getline(in, line) 从流中读到换行符为止， 把换行符之前的内容存入 line，并丢弃换行符本身。 它返回流对象，所以同样可以放进 while 的条件里。 空行也是有效的一行：getline 会把空字符串存入 line 并返回成功， 这和「到达文件末尾」不是一回事。

两种读法混用时有一个必须处理的地方：in >> n 读完数字以后， 换行符还留在流里；紧接着调用 getline，它读到的就是这个换行符， 得到的是一行空字符串。解决办法是在两者之间加一句 in.ignore()， 它会读取并丢弃一个字符（默认就是一个字符，正好是那个换行符）： 

int n = 0;
in >> n;
in.ignore();          // 丢弃数字后面的换行符

std::string line;
std::getline(in, line);
旁注：size() 数的是字节

std::string::size() 返回的是字节数，不是字符数。 对只含英文字符的文件，两者相同；UTF-8 编码下，一个汉字通常占三个字节， size() 会把一个汉字算作三。需要按字符计数时， 要使用能识别 UTF-8 的工具，这不在本课范围内。

例题 · 按行读取

文件 6.1-lines.txt 的每一行都包含空格或标点： 

第一行 有空格
第二行：有标点
第三行

下面的程序按行读取，并在每一行前面加上行号： 

#include <fstream>
#include <iostream>
#include <string>

int main() {
    std::ifstream in("6.1-lines.txt");
    if (!in) {
        std::cout << "文件打不开" << std::endl;
        return 1;
    }

    std::string line;
    int no = 1;
    while (std::getline(in, line)) {
        std::cout << no << ": " << line << std::endl;
        no++;
    }

    return 0;
}
1: 第一行 有空格
2: 第二行：有标点
3: 第三行

如果改用 in >> word，第一行只会读到「第一行」， 后面的「有空格」会被当成下一段内容；getline 则保留了行内的空格。

练习

练习 6-1

文件 6-1-in.txt 的第一行是一个整数 n， 第二行是 n 个整数。读入这些数并求和，输出一行。 文件内容是： 

5
10 20 30 40 60
5 个数的和是 160

把程序保存为 6-1.cpp，与 6-1-in.txt 放在同一目录， 从那个目录运行。答案会把文件打开失败的检查也写进去，可以对照。

看答案

先打开文件并检查是否成功；第一行读 n，随后循环 n 次，每次读一个整数并累加。 

#include <fstream>
#include <iostream>

int main() {
    std::ifstream in("6-1-in.txt");
    if (!in) {
        std::cout << "文件打不开" << std::endl;
        return 1;
    }

    int n = 0;
    in >> n;

    int sum = 0;
    for (int i = 0; i < n; i++) {
        int x = 0;
        in >> x;
        sum = sum + x;
    }

    std::cout << n << " 个数的和是 " << sum << std::endl;
    return 0;
}

in >> n 与后面的 in >> x 使用同一种读取方式， 空格和换行都会被跳过，所以第二行的多个整数可以连续读完。

打开失败时直接 return 1：调用方可以从退出码知道程序没有正常完成。 这道题的 n 与文件内容一致，所以不需要检查读取次数； 练习 6-10 会检查这一点。

练习 6-2

文件 6-2-in.txt 有三行文字。逐行读入，统计一共有多少行、 一共有多少个字符，输出一行。文件内容是： 

abc
hello world
C++
3 行，共 17 个字符

统计时按行读入，不要用 >>：这些行里有空格， 按空白分隔会把一行拆成好几段。

看答案

按行读取，每读一行就把行数加一，并把这一行的长度加入字符总数。 

#include <fstream>
#include <iostream>
#include <string>

int main() {
    std::ifstream in("6-2-in.txt");
    if (!in) {
        std::cout << "文件打不开" << std::endl;
        return 1;
    }

    std::string line;
    int lines = 0;
    int chars = 0;
    while (std::getline(in, line)) {
        lines++;
        chars = chars + int(line.size());
    }

    std::cout << lines << " 行，共 " << chars << " 个字符" << std::endl;
    return 0;
}

std::getline 会把行内的空格保留下来， 所以「hello world」这一行算作 11 个字符，而不是两个单词。 line.size() 返回字节数；这份文件只含英文字符， 字节数与字符数相同。

练习 6-3

文件 6-3-in.txt 的第一行是一个整数 n， 后面有 n 行文字。先读 n，再逐行读取后面的内容， 输出时在每一行前面加上行号。文件内容是： 

3
第一 行
第二 行
第三 行
1: 第一 行
2: 第二 行
3: 第三 行

关键在于 in >> n 之后留下的那个换行符： 不先处理掉，第一次 getline 会读到空行。

看答案

先读数量，再用 in.ignore() 丢弃数字后面的换行符， 然后逐行读取。 

#include <fstream>
#include <iostream>
#include <string>

int main() {
    std::ifstream in("6-3-in.txt");
    if (!in) {
        std::cout << "文件打不开" << std::endl;
        return 1;
    }

    int n = 0;
    in >> n;
    in.ignore();

    for (int i = 1; i <= n; i++) {
        std::string line;
        std::getline(in, line);
        std::cout << i << ": " << line << std::endl;
    }

    return 0;
}

如果去掉 in.ignore()，第一次 getline 读到的就是那个残留的换行符，输出会从「1: 」开头的一行空内容开始， 后面的行号全部错开一位。

你现在能写什么：打开一个文件并检查是否成功； 用 while (in >> x) 逐个读取； 用 while (std::getline(in, line)) 按行读取； 知道 eof() 不能用来控制循环， 知道 >> 之后接 getline 要先处理换行符。

6.2写文件

读和写是一对。程序的计算结果、运行记录、下一阶段要读的输入，都可能需要写进文件。 写入使用 std::ofstream，它也在 <fstream> 里。

创建与写入

用一个文件名构造 std::ofstream，文件不存在时会创建； 文件已经存在时，默认会清空原有内容，从头开始写： 

std::ofstream out("6.2-report.txt");
if (!out) {
    // 创建失败：目录不存在、没有写入权限，或者磁盘已满
}
out << "总分 414" << std::endl;
out << "平均 82.8" << std::endl;

out << ... 的写法和 std::cout 完全一样， 数字、字符串、std::endl 都可以直接写。 同样要检查打开是否成功：目录不存在或没有写入权限时， 后面的写入会全部失败，而程序不会自动报告。

关闭文件

std::endl 只负责换行并刷新这一行，写入的内容可能还在 缓冲区（buffer）里，尚未到达磁盘上的文件。 调用 out.close() 会把缓冲区的内容写入文件并关闭文件。 在同一个程序里紧接着重新打开这个文件读取，或者要让别的程序看到写入结果时， 必须先关闭。

文件流对象离开作用域时也会自动关闭，所以函数结束时不必特意写 close()。需要提前关闭，或者关闭后要重新打开同一个文件时，才手写这一句。

例题 · 写入后读回

下面的程序写一份两行的报告，关闭文件后重新打开读回，确认写入的内容； 最后删除这份文件，方便重复运行： 

#include <cstdio>
#include <fstream>
#include <iostream>
#include <string>

int main() {
    std::ofstream out("6.2-report.txt");
    if (!out) {
        std::cout << "文件创建失败" << std::endl;
        return 1;
    }
    out << "总分 414" << std::endl;
    out << "平均 82.8" << std::endl;
    out.close();

    std::ifstream in("6.2-report.txt");
    if (!in) {
        std::cout << "文件打不开" << std::endl;
        return 1;
    }
    std::string line;
    while (std::getline(in, line)) {
        std::cout << line << std::endl;
    }

    std::remove("6.2-report.txt");
    return 0;
}
总分 414
平均 82.8

注意先后顺序：写入之后先 out.close()，再用新的 std::ifstream 打开同一个文件。如果不关闭就读取， 缓冲区里的内容可能还没有写入文件，读到的内容会不完整。 最后的 std::remove 在 6.2.4 说明。

追加写入

默认方式会清空原有内容。要在文件末尾继续写、保留原有内容， 构造时加上第二个参数 std::ios::app： 

std::ofstream out("6.2-log.txt", std::ios::app);
out << "新的一行" << std::endl;

app 是 append（追加）的缩写。文件不存在时会创建； 已经存在时，每一次写入都落到文件末尾。日志文件通常用这种方式： 每次运行追加一段记录，不覆盖以前的记录。

例题 · 两次追加

下面的程序用追加方式打开同一个文件两次，每次写一行，最后读回全部内容： 

#include <cstdio>
#include <fstream>
#include <iostream>
#include <string>

int main() {
    std::remove("6.2-log.txt");

    std::ofstream first("6.2-log.txt", std::ios::app);
    first << "第一次写入" << std::endl;
    first.close();

    std::ofstream second("6.2-log.txt", std::ios::app);
    second << "第二次写入" << std::endl;
    second.close();

    std::ifstream in("6.2-log.txt");
    if (!in) {
        std::cout << "文件打不开" << std::endl;
        return 1;
    }
    std::string line;
    while (std::getline(in, line)) {
        std::cout << line << std::endl;
    }

    std::remove("6.2-log.txt");
    return 0;
}
第一次写入
第二次写入

如果第二次打开时去掉 std::ios::app，第二次写入会清空文件， 读回时就只剩「第二次写入」一行。这个对比说明了打开方式的作用。 程序开头和结尾的 std::remove 让每次运行都从空文件开始。

删除文件

<cstdio> 里的 std::remove("文件名") 用于删除文件， 成功时返回 0，失败时返回非 0。本课的示例程序在结尾删除自己创建的文件， 这样重复运行不会受到上一次留下的内容影响： 

#include <cstdio>

std::remove("6.2-report.txt");

删除之前要确认文件确实已经关闭，并且确实是要删除的那一份。 删除操作不可撤销，正式程序里通常不会在正常流程中随意删除数据文件； 这里只是为了保持示例目录干净。

练习

练习 6-4

读入一个整数 n，把 1 到 n 每个数写一行到文件 6-4-out.txt。关闭文件后重新打开， 把文件里的数逐个读回并求和，输出一行。

5
写入 5 个数，读回来的和是 15

写完以后关闭文件，再重新打开读取；两次打开之间，缓冲区的内容才会写入文件。 这道题也练习了 std::remove 的用法。

看答案

写入和读取分两步：先用 std::ofstream 写， 关闭之后再用 std::ifstream 打开同一个文件。 

#include <cstdio>
#include <fstream>
#include <iostream>

int main() {
    int n = 0;
    std::cin >> n;

    std::ofstream out("6-4-out.txt");
    if (!out) {
        std::cout << "文件创建失败" << std::endl;
        return 1;
    }
    for (int i = 1; i <= n; i++) {
        out << i << std::endl;
    }
    out.close();

    std::ifstream in("6-4-out.txt");
    if (!in) {
        std::cout << "文件打不开" << std::endl;
        return 1;
    }

    int sum = 0;
    int x = 0;
    while (in >> x) {
        sum = sum + x;
    }

    std::cout << "写入 " << n << " 个数，读回来的和是 " << sum << std::endl;

    std::remove("6-4-out.txt");
    return 0;
}

out.close() 不能省略：不关闭的话，缓冲区里的内容可能还没有 写入文件，紧接着读到的内容会不完整。

最后调用 std::remove 删除这个临时文件， 让程序可以反复运行；删除失败不影响程序结果，所以这里没有检查返回值。

练习 6-5

文件 6-5-in.txt 里有一组整数。读入全部整数，统计个数与总和， 计算平均值，把这三项写成三行到 6-5-out.txt： 个数、总和、平均 各占一行。 关闭文件后再读回来，每一行前面加上「读回：」输出。文件内容是： 

90 80 70 60 100
读回：个数 5
读回：总和 400
读回：平均 80

6.3throw 与 try / catch

文件可能打不开，数据可能不符合要求，除数可能为 0。 函数遇到自己无法处理的情况时，需要把问题报告给调用它的代码。 这一课讲 C++ 的异常机制：用 throw 抛出，用 try / catch 捕获。

出错时怎么通知调用方

不用异常时，函数通常用一个特殊的返回值表示失败，例如返回 -1， 或者额外增加一个表示成功与否的参数。这种写法有两个问题： 调用方可能忘记检查返回值；失败的原因不容易表达清楚， 一个 -1 无法说明是「文件不存在」还是「格式不对」。

异常把这两件事分开：函数在出错的位置直接抛出一个对象， 正常的返回路径保持干净；调用方在需要处理的地方捕获， 不需要在每一层都写检查。没有捕获的异常会一直向外传递， 如果最终没有人捕获，程序会终止——失败不会被悄悄忽略。

throw 与 try / catch

抛出一个异常用 throw，抛出的是一个对象。 最常用的是 <stdexcept> 里的 std::runtime_error， 构造时给一段说明文字： 

#include <stdexcept>

throw std::runtime_error("除数不能为 0");

捕获异常用 try / catch。把可能出错的代码放进 try 块，后面跟一个或多个 catch 块： 

try {
    double result = divide(a, b);
    std::cout << "结果 " << result << std::endl;
} catch (const std::exception& e) {
    std::cout << "出错：" << e.what() << std::endl;
}

catch 的参数写成 const std::exception&： std::exception 是标准库中所有异常类型的基类，前面抛出的 std::runtime_error 也从它派生；what() 是它的成员函数， 返回异常对象携带的说明文字。 参数按引用接收，避免复制异常对象；如果按值接收基类对象， 派生类新增的部分会被丢掉，这种情况叫对象切片（object slicing）。 加上 const，因为捕获方只读取，不修改。 捕获之后，程序从整个 try / catch 后面的第一条语句继续执行， 不会回到 try 块中出错的位置。 这里只用到这两个概念最基本的含义，想进一步了解， 可以自行搜索「C++ std::exception」「C++ 对象切片」学习。

例题 · 除数为 0

divide 检查除数，为 0 时抛出 std::runtime_error； 主函数捕获并输出错误信息，然后继续执行： 

#include <iostream>
#include <stdexcept>

double divide(int a, int b) {
    if (b == 0) {
        throw std::runtime_error("除数不能为 0");
    }
    return a / double(b);
}

int main() {
    int a = 10;
    int b = 0;

    try {
        double result = divide(a, b);
        std::cout << "结果 " << result << std::endl;
    } catch (const std::exception& e) {
        std::cout << "出错：" << e.what() << std::endl;
    }

    std::cout << "程序继续执行" << std::endl;
    return 0;
}
出错：除数不能为 0
程序继续执行

divide 中 throw 之后的代码不会执行， 函数立即结束并把异常交给调用方。主函数捕获以后， try 块里剩下的语句（输出结果那一行）被跳过， 程序从 catch 之后继续，所以最后一行仍然输出。

异常离开函数时发生什么

异常从抛出的位置向外传递，经过的每一层函数都会提前结束。 函数结束时，它的局部对象会按照构造的逆序销毁，析构函数正常执行。 这个过程叫作栈展开（stack unwinding）。

栈展开解释了第 5 部分 RAII 的意义：资源在构造函数中获得、在析构函数中释放， 即使函数因为异常提前结束，析构函数仍然会被调用，资源不会遗漏。 如果不用 RAII，而是手写 new / delete， 异常一跳过释放语句，内存就会泄漏。

例题 · 沿途对象依次销毁

Guard 在构造和析构时各输出一行。inner 中抛出异常， 观察 outer 与 inner 的局部对象以什么顺序销毁： 

#include <iostream>
#include <stdexcept>
#include <string>

class Guard {
public:
    Guard(const std::string& name) : name(name) {
        std::cout << "创建 " << name << std::endl;
    }
    ~Guard() {
        std::cout << "销毁 " << name << std::endl;
    }

private:
    std::string name;
};

void inner() {
    Guard g1("内层对象");
    throw std::runtime_error("内层出错");
}

void outer() {
    Guard g2("外层对象");
    inner();
    std::cout << "这一行不会执行" << std::endl;
}

int main() {
    try {
        outer();
    } catch (const std::exception& e) {
        std::cout << "捕获：" << e.what() << std::endl;
    }

    return 0;
}
创建 外层对象
创建 内层对象
销毁 内层对象
销毁 外层对象
捕获：内层出错

输出顺序说明了三件事：对象按构造的逆序销毁； inner 中 throw 之后的语句不执行； outer 中 inner() 之后的语句也不执行。 两个析构函数都执行了，异常最终在 main 中被捕获。

几条写法纪律

  • 抛出时按值抛出，捕获时按 const 引用捕获。 throw std::runtime_error("...") 抛出一个临时对象； catch (const std::exception& e) 接收它，不复制。
  • 先捕获具体的类型，再捕获基类。 catch 按书写顺序匹配，前面的块一旦匹配就不会再看后面的。 如果把 std::exception 写在最前面，后面针对具体类型的 catch 永远不会执行。
  • 异常用于异常情况，不用于正常的流程控制。 循环结束、查找不到元素这类预期之内的情况，用返回值或迭代器表示； 文件打不开、数据格式错误、参数越界这类无法在当前层处理的情况，才使用异常。
  • 析构函数中不要让异常向外传播。 栈展开过程中如果析构函数又抛出异常，程序会直接终止。 析构函数应当只做不会失败的操作，或者在内部处理掉可能出现的错误。

练习 6-7

写一个函数 safeDivide(int a, int b)：b 为 0 时 抛出 std::runtime_error("除数为 0")，否则返回 a / b。主函数反复读入成对的整数，每一对调用一次， 捕获异常后输出「出错：除数为 0」，然后继续读下一对。

10 2 7 0 9 3

出错：除数为 0
9 / 3 = 3

注意 try 写在循环里面：一组输入出错后，循环继续处理下一组。 如果写在循环外面，第一次异常就会结束整个循环。

看答案

检查放在 safeDivide 里，捕获放在主函数的循环里： 每一组输入单独处理，出错不影响下一组。 

#include <iostream>
#include <stdexcept>

int safeDivide(int a, int b) {
    if (b == 0) {
        throw std::runtime_error("除数为 0");
    }
    return a / b;
}

int main() {
    int a = 0;
    int b = 0;
    while (std::cin >> a >> b) {
        try {
            int result = safeDivide(a, b);
            std::cout << a << " / " << b << " = " << result << std::endl;

            std::cout << "出错：" << e.what() << std::endl;
        }
    }
    return 0;
}

先调用 safeDivide 取得结果，再输出； 如果先输出「a / b = 」再调用，异常发生时屏幕上会留下半行内容。 这也是把可能失败的调用放在输出之前的原因。

写一个函数 checkAge(int age)：年龄小于 0 或大于 150 时 抛出 std::out_of_range("年龄不在 0 到 150 之间")， 否则输出「年龄 N 有效」。主函数反复读入年龄，捕获异常后输出 「拒绝：」加上异常中的说明文字。

年龄 150 有效
拒绝：年龄不在 0 到 150 之间

函数只负责检查和抛出，输出由调用方决定。这样同一个检查函数可以用在不同的程序里， 错误信息的写法也可以随调用方调整。

看答案

checkAge 只负责检查：合法就输出一行，不合法就抛出 std::out_of_range。主函数负责捕获并输出拒绝信息。 

#include <iostream>
#include <stdexcept>

void checkAge(int age) {
    if (age < 0 || age > 150) {
        throw std::out_of_range("年龄不在 0 到 150 之间");
    }
    std::cout << "年龄 " << age << " 有效" << std::endl;
}

int main() {
    int age = 0;
    while (std::cin >> age) {
        try {
            checkAge(age);
        } catch (const std::out_of_range& e) {
            std::cout << "拒绝：" << e.what() << std::endl;
        }
    }
    return 0;
}

std::out_of_range 的说明文字通过构造函数传入， 捕获方用 e.what() 取得。检查条件写成 age < 0 || age > 150，两个边界都包含在合法范围内。

你现在能写什么：用 throw 抛出异常，用 try / catch 捕获； 按 const 引用捕获并读取 what()； 说清异常离开函数时局部对象按逆序销毁； 遵守抛出与捕获的基本写法，按具体类型安排 catch 的顺序。

6.4标准异常

第 6.3 课用的 std::runtime_error 来自标准库。 标准库里的容器、字符串转换函数、内存分配等，在出错时也会抛出异常。 这一课先看这些标准异常的共同基类，再看怎么定义自己的异常类型。

std::exception 与 what()

标准库中所有的异常类型都从 std::exception 派生 （<exception>）。它提供一个虚函数（virtual function） what()，返回一段说明文字。虚函数是基类中声明、允许派生类重新定义， 调用时按对象的实际类型选择版本的成员函数；本课只用到 what() 这一个用途，具体写法不展开，需要时可以自行搜索「C++ 虚函数」学习。 按基类捕获，就能用一个 catch 接住所有标准异常： 

try {
    // 可能抛出标准异常的代码
} catch (const std::exception& e) {
    std::cout << "出错：" << e.what() << std::endl;
}

what() 返回的文字由标准库实现决定，不同的编译器、 不同的标准库版本可能给出不同的内容。可以依赖的是异常的类型和它是否被抛出， 不要依赖具体文字来做判断或输出格式。

例题 · 接住标准库抛出的异常

std::vector::at 在下标越界时抛出 std::out_of_range； std::stoi 在字符串无法转换时抛出 std::invalid_argument， 在数字超出 int 范围时抛出 std::out_of_range。 下面的程序用同一个基类分别捕获： 

#include <iostream>
#include <stdexcept>
#include <string>
#include <vector>

int main() {
    std::vector<int> v = {10, 20, 30};

    try {
        std::cout << v.at(5) << std::endl;
    } catch (const std::exception& e) {
        std::cout << "at 出错：" << e.what() << std::endl;
    }

    try {
        int x = std::stoi("abc");
        std::cout << x << std::endl;
    } catch (const std::exception& e) {
        std::cout << "stoi 出错：" << e.what() << std::endl;
    }

    return 0;
}
at 出错：vector::_M_range_check: __n (which is 5) >= this->size() (which is 3)
stoi 出错：stoi

这两行文字来自本机使用的标准库实现，换一个环境可能不同； 但两处抛出的异常类型是标准规定的： at 抛出 std::out_of_range， stoi 对「abc」抛出 std::invalid_argument。 程序真正应当处理的是类型，而不是这段文字。

几种常见的标准异常

标准异常大致分成两类：逻辑错误（程序本身的用法有问题，理论上可以避免） 和运行时错误（运行环境或输入导致，程序无法完全避免）。 常用的几种如下：

  • std::invalid_argument——参数值不符合要求。 std::stoi 遇到不能转换的字符串时抛出。
  • std::out_of_range——下标或数值超出允许范围。 std::vector::at、std::stoi 都可能抛出。
  • std::runtime_error——运行时出现的、没有更具体分类的错误。 自定义异常通常从它派生。
  • std::bad_alloc——内存分配失败，new 申请不到内存时抛出。

这些类型都从 std::exception 派生，前两个属于逻辑错误分支， 后两个属于运行时错误分支。需要按类别处理时，可以捕获 std::logic_error 或 std::runtime_error； 只需要统一报告时，捕获 std::exception 就够了。

自定义异常类型

标准异常类型表达的是通用的问题，程序自己的业务错误往往需要携带更多信息： 哪个文件、哪一行、哪个值不合格。这时可以定义一个自己的异常类型， 从 std::runtime_error 派生： 

#include <stdexcept>
#include <string>

class FileError : public std::runtime_error {
public:
    FileError(const std::string& filename, const std::string& reason)
        : std::runtime_error(filename + "：" + reason) {}
};

class FileError : public std::runtime_error 表示 FileError 以 std::runtime_error 为基础： 它拥有基类的行为（包括 what()），并增加了自己的构造函数。 构造函数后面的 : std::runtime_error(...) 调用基类的构造函数， 把拼好的说明文字交给基类保存。

抛出和捕获的写法和标准异常一样。因为 FileError 是 std::runtime_error 的派生类型，按基类捕获也能接住它； 但要针对这个类型做不同处理时，应当先写 catch (const FileError&)， 再写基类的 catch。

例题 · 带文件名与原因的异常

下面的程序尝试打开一个不存在的文件，失败时抛出自定义的 FileError，异常对象中带有文件名和原因： 

#include <fstream>
#include <iostream>
#include <stdexcept>
#include <string>

class FileError : public std::runtime_error {
public:
    FileError(const std::string& filename, const std::string& reason)
        : std::runtime_error(filename + "：" + reason) {}
};

void openOrThrow(const std::string& filename) {
    std::ifstream in(filename);
    if (!in) {
        throw FileError(filename, "无法打开");
    }
    std::cout << "打开成功" << std::endl;
}

int main() {
    try {
        openOrThrow("6.4-missing.txt");
    } catch (const std::exception& e) {
        std::cout << "捕获：" << e.what() << std::endl;
    }

    return 0;
}
捕获：6.4-missing.txt：无法打开

说明文字在 FileError 的构造函数中拼好，交给基类保存， 捕获方通过 e.what() 取得。调用方只需要处理 std::exception，不必了解这个类型内部保存了哪些字段。

什么时候该用异常

这一部分出现的错误大致有三类，处理方式各不相同：

  • 可以当场处理的：例如读入的年龄不合法，输出提示后继续读下一个。 在离出错位置最近的地方用 try / catch 处理。
  • 当前层无法处理、需要调用方决定的：例如打开配置文件失败。 抛出异常，让调用方决定是重试、换一个文件，还是终止程序。
  • 程序逻辑错误：例如下标越界、对空指针解引用。 这类问题应当在编写和测试阶段解决，异常只用于在出错时给出明确的报告， 不应当作为正常运行的一部分。

异常让「出错的路径」和「正常的路径」分开写，调用方可以选择在合适的层级处理。 代价是程序的执行路径多了一条：阅读代码时要同时考虑正常返回和异常退出， 这也是第 6.3 课强调栈展开和 RAII 的原因。

        try {
            int x = std::stoi(s);
            std::cout << s << " -> " << x << std::endl;
        } catch (const std::invalid_argument& e) {
            std::cout << s << " 不是数字" << std::endl;
        } catch (const std::out_of_range& e) {
            std::cout << s << " 超出 int 范围" << std::endl;
        }
    }
    return 0;
}

std::invalid_argument 表示内容不是数字， std::out_of_range 表示数字本身合法，但超出了 int 能表示的范围。两者都是 std::logic_error 的派生类型，彼此没有继承关系，所以 catch 的先后顺序 不影响结果；按具体类型分别书写，读起来更清楚。

练习 6-10

文件 6-10-in.txt 的第一行是记录数量，后面是若干行整数。 程序要读入全部整数并计算平均值，同时检查两件事： 文件打不开时抛出自定义异常 MissingFile； 实际读到的数量与第一行写的不一致时抛出 std::runtime_error("数量不符")。 文件内容是： 

4
80 90 70
数据错误：数量不符（文件写的是 4 个，实际读到 3 个）

这道题把前面几课的内容合在一起：打开文件、检查数量、抛出自定义异常、 按类型分别捕获。文件里的数量写成 4，实际只有 3 个数，程序应当报告数量不符。

看答案

程序分两层检查：打开文件失败时抛出 MissingFile； 读到内容后核对数量，不一致时抛出 std::runtime_error。 

#include <fstream>
#include <iostream>
#include <stdexcept>
#include <string>

class MissingFile : public std::runtime_error {
public:
    explicit MissingFile(const std::string& name)
        : std::runtime_error("找不到文件：" + name) {}
};

int main() {
    int n = 0;
    int count = 0;
    int sum = 0;

    try {
        std::ifstream in("6-10-in.txt");
        if (!in) {
            throw MissingFile("6-10-in.txt");
        }

        in >> n;
        int x = 0;
        while (in >> x) {
            count++;
            sum = sum + x;
        }

        if (count != n) {
            throw std::runtime_error("数量不符");
        }

        std::cout << "共 " << n << " 个，平均 " << double(sum) / n << std::endl;
    } catch (const MissingFile& e) {
        std::cout << "文件错误：" << e.what() << std::endl;
    } catch (const std::runtime_error& e) {
        std::cout << "数据错误：" << e.what()
                  << "（文件写的是 " << n << " 个，实际读到 " << count << " 个）"
                  << std::endl;
    }

    return 0;
}

MissingFile 的构造函数前面写了 explicit， 它表示禁止用 std::string 隐式构造 MissingFile； 这个关键字本课不展开，需要时可以自行搜索「C++ explicit」学习。 MissingFile 从 std::runtime_error 派生， 所以两个 catch 的顺序必须是先 MissingFile、 后 std::runtime_error；反过来写的话， 第一个 catch 会把所有 MissingFile 也接走。

这份数据的第一行写的是 4，后面只有 3 个数，所以走「数量不符」这一条。 把第一行改成 3，程序会输出平均值 80；把文件名改成不存在的文件， 会走第一个 catch，输出「文件错误：找不到文件：……」。

你现在能写什么：认出 std::exception 及其常见派生类型； 用 catch (const std::exception&) 统一捕获； 从 std::runtime_error 派生自定义异常类型并携带信息； 按具体类型安排 catch 的顺序。
