第 4 部分

时间复杂度与算法

第 3 部分结尾留下了两个问题：想删除中间的元素、想往中间插入一个元素，怎么办； 还有同样是查找一个元素，为什么有快有慢。 这一部分把这两个问题都解决。解决前一个问题的工具是迭代器， 衡量步数的标准是时间复杂度—— 一个说「位置」，一个说「步数」。 学会这两样，再打开 <algorithm> 那一整套现成的工具， 以后排序、找最大，都不用自己写循环了。

4.1怎么估一段代码快不快

到这儿为止，写程序的标准一直是「能运行、结果正确」。 从这一课起多问一句：同样的结果，要花多少步。

这不是找事。第 3 部分留了两句话没说透—— 3.6 里那句「凭什么 map 按名字就能直接取值」， 4.1 末尾那句「vector 报个下标就能跳到第 5 个」。 这两句话说的是同一件事：步数。 没有这个标准，就只能说「感觉 map 快一点」，说不清快在哪里。

先数一数

最直接的做法是计时：运行一遍，查看花费了多少秒。可计时有两个问题—— 跟机器有关（同一份程序，旧电脑上就是慢）， 跟当时忙不忙也有关（后台运行着其他程序，数值就会波动）。 换台机器、换个编译器，同一个问题能报出三个数，无法在课上说明。

有一个标准与机器无关：统计那行代码执行了几遍。 执行一遍算一步。步数只跟「n 有多大」有关，跟你用哪台电脑无关—— 这是三项中唯一可以事先计算的内容。

下面这份程序，全部的工作只有一项：把一个计数加 1。两个循环都执行这件事， 差的只是套了几层。输入第一行是 n： 

5

程序是这样：

#include <iostream>

int main() {
    int n = 0;
    std::cin >> n;

    int one = 0;
    for (int i = 0; i < n; i++) {
        one = one + 1;
    }

    int two = 0;
    for (int i = 0; i < n; i++) {
        for (int j = 0; j < n; j++) {
            two = two + 1;
        }
    }

    std::cout << "一层：" << one << " 次" << std::endl;
    std::cout << "两层：" << two << " 次" << std::endl;

    return 0;
}
一层：5 次
两层：25 次

看这两个数：一层那个执行了 5 次，两层那个执行了 25 次。 n 是 5，一层就是 5——它跟着 n 走，n 有多大就执行多少次。 两层是 5 × 5：外层执行一次，内层从头到尾遍历一遍， 外层执行五次，内层就遍历五遍。

这就是全部的做法：数一数这行代码会执行几遍。 不需要实际逐行计数——确认循环嵌套了几层就够了。下面那个动画，是把这两句话 一步一步放给你看。

跟着动画执行一遍

n 还是 5。点「下一步」，观察 one 和 two 这两个变量怎样递增：

有两处值得停下来确认：

  • 第一个循环结束时 one 停在 5。 不是 4 也不是 6——i 从 0 到 4 是五次，执行次数与 n 相同。 动画里那一句「i 加到 5，5 < 5 不成立」，说的就是最后一次由谁终止。
  • 第二个循环每完成一次外层循环，two 增加 5。 外层执行五次，每次增加 5，最后停在 25。 一层是「执行次数」，两层是「执行次数乘执行次数」——25 是这样得到的。

把 n 换成 1000：一层那个一千步，两层那个是一百万步。 这就是为什么两个循环看上去只差一层，执行时间却相差悬殊—— 下一节把这件事摆成一张表。

n 翻一倍，步数翻几倍

5 和 25 看上去差不多，是因为 5 太小了。让 n 一千一千地增加， 把次数输出并排比较： 

#include <iostream>

int main() {
    for (int n = 1000; n <= 8000; n = n * 2) {
        int one = 0;
        for (int i = 0; i < n; i++) {
            one = one + 1;
        }

        int two = 0;
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < n; j++) {
                two = two + 1;
            }
        }

        std::cout << "n = " << n << "：一层 " << one
                  << " 步，两层 " << two << " 步" << std::endl;
    }

    return 0;
}
n = 1000：一层 1000 步，两层 1000000 步
n = 2000：一层 2000 步，两层 4000000 步
n = 4000：一层 4000 步，两层 16000000 步
n = 8000：一层 8000 步，两层 64000000 步

一行一行读：

  • n 从 1000 翻到 2000，一层那个从 1000 变 2000—— 跟着翻一倍。
  • 同一行，两层那个从一百万变四百万——翻了四倍。
  • 再翻一次，一层四千，两层一千六百万。再翻一次， 一层八千，两层六千四百万。

n 每翻一倍，两层那个就翻四倍。 n 才涨到 8 倍，步数已经涨了 64 倍。再翻几次，两层那个的数字就大到 你不想看了——而真正的程序里，n 常常是几十万。

这就是为什么「能运行就行」不够用。写的时候多套一层循环， 只多写两行；执行时的代价却完全不同。

给它一个名称

「步数跟着 n 怎么长」这件事，说全了太长，所以有一套简写。 这套简写你现在天天见，只是没认出来——时间复杂度（time complexity） 和那个大写的 O。

写法是把「增长最快的那一项」选取出来，写进 O 的括号里， n 前面的常数一律不要：

记号 读作 什么样的代码长这样
O(1) 常数时间 不管 n 多大，步数都不变。取 v[3]、v.size()、 问 set 里有没有某个数（3.5）都算
O(n) 线性时间 一层循环从头走到尾。n 翻倍，步数翻倍
O(n²) 平方时间 两层嵌套的循环。n 翻倍，步数翻四倍
O(log n) 对数时间 每次循环把范围缩小一半。n 翻倍，步数只增加一步——下一节讲

三个地方要提醒：

  • 常数不管。2n 和 100n 都写成 O(n)。n 一大，前面那个数是 2 还是 100 就不重要了—— n 自己才是决定性的。两个循环并排（前一个走完再走后一个） 也是 O(n)：它执行 2n 步，仍然按 n 增长。
  • 只看最大的那一项。一段代码里既有 O(n²) 的部分又有 O(n) 的部分，合起来写 O(n²)： n 大了以后，平方那一项把别的全盖住了。
  • O 说的是「上界」，不是秒数。O(n) 的程序 不一定比 O(n²) 的先执行完——n 很小时， 常数项起决定作用。它管的是n 变大以后谁增长得更快。
O 是给谁看的

读懂真实代码、跟人讨论「这个写法行不行」时，它是通用语言—— 一句「这层里面又套了一层，变成 n² 了」比长时间解释更清楚。 平时写程序不用去算它，只要认得出两种最需要注意的形式： 循环里套循环、和循环里夹着一个 find 或 count。 见到这两样，先停一下，问问 n 能有多大。

第三种：每次缩小一半

一层、两层都是循环逐个执行，慢和快的差别只是执行次数。 还有一类循环形式完全不同：每次循环，需要检查的范围就缩小一半。

一千个排好序的数里查找一个数。直接的方法是从头逐个比较，最坏要比较一千次。 另一种方法每次都从中间分开：检查中间的元素，比目标大就排除右半部分， 比目标小就排除左半部分。一千个数，十次就查找完成： 

#include <iostream>
#include <vector>

int main() {
    std::vector<int> v;
    for (int i = 0; i < 1000; i++) {
        v.push_back(i * 2);          // 0 2 4 … 1998，从小到大排好的
    }

    int target = 0;
    std::cin >> target;

    int linear = 0;
    int linear_at = -1;
    for (int i = 0; i < int(v.size()); i++) {
        linear = linear + 1;
        if (v[i] == target) {
            linear_at = i;
            break;
        }
    }

    int steps = 0;
    int lo = 0;
    int hi = int(v.size()) - 1;
    int pos = -1;
    while (lo <= hi) {
        steps = steps + 1;
        int mid = (lo + hi) / 2;
        if (v[mid] == target) {
            pos = mid;
            break;
        }
        if (v[mid] < target) {
            lo = mid + 1;
        } else {
            hi = mid - 1;
        }
    }

    std::cout << "一千个数里找 " << target << "：" << std::endl;
    std::cout << "  从头逐个比较：" << linear << " 次";
    if (linear_at >= 0) {
        std::cout << "，在第 " << linear_at << " 个";
    }
    std::cout << std::endl;
    std::cout << "  每次缩小一半：" << steps << " 次";
    if (pos >= 0) {
        std::cout << "，在第 " << pos << " 个";
    }
    std::cout << std::endl;

    return 0;
}

输入是要找的那个数 1998——表里最后一个，对「从头找」 来说是最坏的情况： 

一千个数里找 1998：
  从头逐个比较：1000 次，在第 999 个
  每次缩小一半：10 次，在第 999 个

一千次对十次。结果一模一样，步数差一百倍。这就是 O(n) 和 O(log n) 的距离。

为什么是十次？因为每缩小一次范围，剩下的个数就除以 2： 1000 → 500 → 250 → …，除到 1 大约需要十次。 所以这个次数跟 n 的关系是「n 要除几次 2 才到 1」—— n 翻一倍只是多执行一次，也就是 O(log n)，增长幅度几乎可以忽略。 一千要十步，一百万也才二十步。

它有一个前提：数据必须已经排好序

「缩小一半」为什么可以排除一半？因为你已经知道左边的都比中间小。 这些数只要是无序的，排除错误的一半后就再也无法找回。 排好序是这种方法成立的全部前提——排序本身要花步数（4.4 会讲）， 所以只有「找很多次」的时候这笔账才划算。

现在能回答 3.6 那句了：map 按名字就能直接取值，是因为它内部 一直是有序的（3.4 里见过它自动排序后输出）， 它在内部使用的就是这种「缩小一半」的查找方法。 而 vector 从头找到尾，是逐个比较—— 这就是快慢的出处。

例题 · 名单里的重名

读入 n 个名字，判断有没有重名。这题本身不难，难的是两种写法—— 两份程序使用同一份输入，把它们统计出来的步数放在一起比较： 

6
小李
小王
小张
小李
小赵
小钱

写法一：两两比较。每个名字都跟后面的比较一遍， 比较到相同就记录下来。这是最直接的写法： 

#include <iostream>
#include <string>
#include <vector>

int main() {
    int n = 0;
    std::cin >> n;

    std::vector<std::string> name;
    for (int i = 0; i < n; i++) {
        std::string s;
        std::cin >> s;
        name.push_back(s);
    }

    int count = 0;
    bool found = false;
    for (int i = 0; i < int(name.size()); i++) {
        for (int j = i + 1; j < int(name.size()); j++) {
            count = count + 1;
            if (name[i] == name[j]) {
                found = true;
            }
        }
    }

    std::cout << n << " 个名字，两两比了 " << count << " 次" << std::endl;
    if (found) {
        std::cout << "有重名" << std::endl;
    } else {
        std::cout << "没有重名" << std::endl;
    }

    return 0;
}
6 个名字，两两比了 15 次
有重名

写法二：一边读一边查询 set。3.5 那个只判断存在性的容器正好用于这个目的—— 每读一个名字，先判断「其中是否已经有它」，没有就插入： 

#include <iostream>
#include <set>
#include <string>

int main() {
    int n = 0;
    std::cin >> n;

    std::set<std::string> seen;
    int ask = 0;
    bool found = false;
    for (int i = 0; i < n; i++) {
        std::string s;
        std::cin >> s;

        ask = ask + 1;
        if (seen.count(s) > 0) {
            found = true;
        }
        seen.insert(s);
    }

    std::cout << n << " 个名字，问了 " << ask << " 次" << std::endl;
    if (found) {
        std::cout << "有重名" << std::endl;
    } else {
        std::cout << "没有重名" << std::endl;
    }

    return 0;
}
6 个名字，问了 6 次
有重名

两份程序说的是同一件事，答案也一样，可一个进行了 15 次比较， 另一个只进行了 6 次查询。把 n 换成一千：

  • 两两比较：1000 × 999 ÷ 2， 差不多 五十万次。这是 O(n²)—— 名单再长一倍，次数翻四倍。
  • 问 set：一千次「问」，每次问内部还要走 log n 步（大约 10 步），合起来是 一万步上下。 名单再长一倍，只多三分之一。这是 O(n log n)。

把 n 改成 1000 个名字，两种写法各运行一遍， 那个「五十万次」可以直接看到。

总结一句：选择写法的时候，先考虑「数据量增长后会怎样」， 而不是「这几十个数据运行得快不快」。 手边的数据永远小，学生的名单也就几十个人； 真实的数据长起来，才见分晓。

练习

练习 4-1

写一个程序：读一个 n，用一层循环把 1 加到 n 的和算出来，然后把这段代码执行了几次也输出。

100
1 加到 100 = 5050
循环执行了 100 次

写完之后再想一个问题（不用写程序）：不算循环，直接算 n × (n + 1) / 2，那样是几步？ 两种写法各是什么时间复杂度？

看答案

一层循环在累加的同时计数，round 每执行一轮增加 1： 

#include <iostream>

int main() {
    int n = 0;
    std::cin >> n;

    int sum = 0;
    int round = 0;
    for (int i = 1; i <= n; i++) {
        sum = sum + i;
        round = round + 1;
    }

    std::cout << "1 加到 " << n << " = " << sum << std::endl;
    std::cout << "循环执行了 " << round << " 次" << std::endl;

    return 0;
}

round 不是把 n 原样输出作为结果，而是真正统计出来的—— 让你直接看到「执行了 100 轮」和「n 是 100」是同一个数。

后面那个不用写程序的问题，答案是：

  • 循环那份是 O(n)：n 翻一倍，轮数翻一倍。 这一步的代价跟着 n 长。
  • 公式那份是 O(1)：n * (n + 1) / 2 只需要几次乘法与除法，与 n 的大小无关。这一部分是它唯一一次出场， 记住有这样一个公式即可。

两个都能算对，区别在 n 变大以后：n 增大到一亿，循环那一份需要等待一段时间， 公式那一份仍然只需要几次运算。

练习 4-2

下面几段代码，n 都是 1000。先自行估算每一段里 标了记号那一行会执行几次，估完再写成程序运行，对照结果。 

// 一
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        for (int k = 0; k < n; k++) {
            work();          // 这条执行几次？
        }
    }
}

// 二
for (int i = 0; i < n; i++) {
    work();                  // 这条执行几次？
}
for (int j = 0; j < 5; j++) {
    work();                  // 这条执行几次？
}

// 三
int x = n;
while (x > 1) {
    x = x / 2;
    work();                  // 这条执行几次？
}

三个答案分别是 n³、n + 5、log₂n 的取整。第三段那个 x = x / 2 就是 4.1 那个「每次缩小一半」 的另一种写法。

看答案

三段都是数出来的，估的时候不用写程序：

  • 一：三层循环嵌套。外层执行 n 次，每执行一次中层执行 n 次， 每执行一次内层再执行 n 次——乘起来是 n³， 1000 的三次方，十亿。
  • 二：两个循环并列，不是嵌套。 一个执行 n 次、一个执行 5 次，加起来 n + 5，1005 次。 并列是加法，嵌套是乘法——这一条是这一课最容易混淆的地方。
  • 三：每执行一轮 x 缩小一半，执行几轮就是「1000 缩小几次到 1」。 2^9 = 512 不够、2^10 = 1024 够了， 所以是 9 轮，也就是 log₂n 取整。 写法上是 while 加一句 x = x / 2， 不再是 for 了——4.1 那个「每次缩小一半」的另一种写法。

估算完再让程序运行一遍，核对这三个数： 

#include <iostream>

int main() {
    const int n = 1000;

    long long one = 0;
    for (int i = 0; i < n; i++) {
        for (int j = 0; j < n; j++) {
            for (int k = 0; k < n; k++) {
                one = one + 1;
            }
        }
    }

    int two = 0;
    for (int i = 0; i < n; i++) {
        two = two + 1;
    }
    for (int j = 0; j < 5; j++) {
        two = two + 1;
    }

    int three = 0;
    int x = n;
    while (x > 1) {
        x = x / 2;
        three = three + 1;
    }

    std::cout << "一：" << one << " 次（n 的三次方）" << std::endl;
    std::cout << "二：" << two << " 次（n 加 5）" << std::endl;
    std::cout << "三：" << three << " 次（log2n 取整）" << std::endl;

    return 0;
}
一：1000000000 次（n 的三次方）
二：1005 次（n 加 5）
三：9 次（log2n 取整）

第一段那十亿是实际运行得到的，不是计算出来的：运行时需要等待半秒左右， 就是它。把 n 改成 2000 再运行一遍——等待的时间变成八倍 （2000 的三次方正好是 1000 的三次方的八倍）， 这半秒和四秒的差别，就是 O(n³) 要让你记住的结论。

练习 4-3

把 4.1 那两份找数的程序改一改：表里放 一百万个数 （还是 0、2、4……这么排好），要找的数还是最后一个。 先估算两份程序各需要执行多少次，估算完成后运行查看。

提示：一百万个数的表太大，不要把次数逐行输出， 只要最后那一句总结。std::vector<int> 装一百万个 int 是没问题的（3.1 讲过它是按需长的）。 

一百万个数里找 1999998：
  从头逐个比较：1000000 次
  每次缩小一半：20 次

重点不是写对程序，是先估算后运行：估算 1000000 和 20 这两个数， 靠的就是这一课教的「数一数」。

看答案

4.1 正文那份找数的程序改两个数就是这一题：表长改成一百万， 要找的 1999998 正好在最后一个位置——两种找法里最耗时的情况。 两个数都是估出来的：

  • 从头逐个比较：最坏的情况就是遍历整张表，1000000 次。 要找的正好在最后一个位置，所以这就是最坏情况。
  • 每次缩小一半：需要 2 的几次方才覆盖 1000000。 2^19 = 524288 不够，2^20 = 1048576 够了， 所以 20 次。

估算完再运行，让计数器把这两个数验证一遍： 

#include <iostream>
#include <vector>

int main() {
    std::vector<int> v;
    for (int i = 0; i < 1000000; i++) {
        v.push_back(i * 2);          // 0 2 4 … 1999998，从小到大排好的
    }

    int target = 1999998;            // 最后一个元素的位置

    int linear = 0;
    for (int i = 0; i < int(v.size()); i++) {
        linear = linear + 1;
        if (v[i] == target) {
            break;
        }
    }

    int steps = 0;
    int lo = 0;
    int hi = int(v.size()) - 1;
    while (lo <= hi) {
        steps = steps + 1;
        int mid = (lo + hi) / 2;
        if (v[mid] == target) {
            break;
        }
        if (v[mid] < target) {
            lo = mid + 1;
        } else {
            hi = mid - 1;
        }
    }

    std::cout << "一百万个数里找 " << target << "：" << std::endl;
    std::cout << "  从头逐个比较：" << linear << " 次" << std::endl;
    std::cout << "  每次缩小一半：" << steps << " 次" << std::endl;

    return 0;
}

  从头逐个比较：1000000 次
  每次缩小一半：20 次

1000000 比 20——差了五万倍。这个对比就是 4.1 那一节的全部重点， 也是「估算运行速度」这件事的用处：两个数估算出来放在一起， 差多少可以直接看出，不必把程序运行完才能判断。

估算的时候不要去统计「第二轮第三轮分别执行了哪些位置」， 只看「每执行一轮，需要查看的范围缩小多少」：每执行一轮缩小一半， 所以是 20 次。这也是 4.1 那个「每次缩小一半」之所以快的全部原因。

你现在能写什么：取得一段代码，能数出它里面的循环要执行多少步， 能说出「n 翻倍它翻几倍」——一层是 O(n)， 套两层是 O(n²)，每次缩小一半是 O(log n)。 更重要的是知道什么时候该停下来想这一步： 循环里套循环、循环里夹着查找一个元素，就是那种时候。

4.2迭代器

这一课把 3.1 那句「想删中间那个，还做不到」补上。 补上它需要一个新的概念，这个概念也是第 4 部分的正题—— 能指向「某一个位置」的对象，叫迭代器（iterator）。

一个指向位置的对象

先说清楚为什么需要它。3.1 里删除元素只有一个函数 v.pop_back()——「删除最后一个」。 它的问题不是不够用，而是它不会说明「第几个」： 你想删除第 3 个，需要一个对象能指向第 3 个的位置， 才能告诉它「就是这个」。

下标不行吗？v[2] 得到的不是位置，是那个元素—— 一个 int。给 erase 一个 30，它无法知道 你说的是「第 2 个」还是「值等于 30 的那个」。 位置和值是两回事，需要一个专门表示位置的对象。

迭代器的四句话，先记住，下面的动画逐个演示：

  • v.begin()——第一个元素的位置。
  • v.end()——最后一个元素的后面的位置。 这一条最容易记错：它不是最后一个元素。 后面会讲为什么非得这么定。
  • ++it——向后移动一个位置。
  • *it——它指向那个元素。 基础课 6.3 那个 *p 也是这个星号，含义相同。

下面这份程序，就是把这三个元素（存放的是 3、1、4）从头遍历到尾。 第 3 行那个 auto 是 3.4.5 学的，这里用它省略一长组类型名： 

#include <iostream>
#include <vector>

int main() {
    std::vector<int> v = {3, 1, 4};

    auto it = v.begin();
    std::cout << *it << std::endl;

    ++it;
    std::cout << *it << std::endl;

    ++it;
    std::cout << *it << std::endl;

    ++it;
    if (it == v.end()) {
        std::cout << "已到达末尾" << std::endl;
    }

    return 0;
}

四次输出里前三次是 *it，第四次是「已到达末尾」—— 因为第四次 ++it 之后，it 已经越过了最后一个元素， 正好等于 v.end()。这就是 end() 的用处： 它是「没有元素了」的标记，跟 3.2 里 find 找不到时给的那个 npos 是一个角色。

跟着动画执行一遍

观察两处：

  • it = v.begin() 那一步，它取得的是位置，不是 3。 它里面写的是「→ v[0]」，那个箭头的意思就是「指向」。 真要问它指着的位置上是什么，才写 *it。
  • 最后一步它指向「尾后」。三个位置走完，第四个位置是不存在的—— 可它仍然可以指向那个「不存在的位置」。 有了这个位置，循环就好写了： 没到头就继续，到头了就停。

写成 for 就是一行

上一份那样逐个手动移动，写起来比较繁琐。移动位置这件事其实有固定模式， 写成 for 就是一行： 

#include <iostream>
#include <vector>

int main() {
    std::vector<int> score = {90, 85, 77};

    for (auto it = score.begin(); it != score.end(); ++it) {
        std::cout << *it << std::endl;
    }

    return 0;
}

这一行请记住，它出现的频率非常高： 

for (auto it = v.begin(); it != v.end(); ++it)

四段各管一件事：起点 begin()； 终点 end()——注意是 it != v.end()，不是 <， 因为 map 那种迭代器根本无法比较大小（下一节说明）； 每次循环移动一个位置 ++it； 循环体中使用 *it。

跟 3.1 那个范围 for 放在一起比较： 

for (int x : score) {
    std::cout << x << std::endl;
}

两者是一回事。范围 for 是这套写法的另一种形式：编译器把它展开， 就是上面那个 begin / != end / ++。 所以什么时候用哪个：从头到尾走完、不需要位置——用范围 for， 短、不容易错；中途要停、要记住遍历到了哪里、要对位置做操作—— 用迭代器，因为范围 for 隐藏的正是这些操作。

它能记住一个位置

「记住一个位置」才是迭代器真正值钱的地方。看这一份： 

#include <iostream>
#include <vector>

int main() {
    std::vector<int> score = {45, 52, 68, 91, 73};

    auto it = score.begin();
    while (it != score.end() && *it < 60) {
        ++it;
    }

    if (it == score.end()) {
        std::cout << "一个及格的都没有" << std::endl;
    } else {
        std::cout << "第一个及格的是 " << *it << std::endl;
        std::cout << "它在第 " << (it - score.begin()) << " 个" << std::endl;
    }

    return 0;
}

它在第 2 个

循环出来之后，it 停在第一个及格的那个元素上—— 它记住的是位置，所以在循环外面仍然可以使用。这就是 3.1 需要的 「指向某一个位置」。

那一句 it - score.begin() 也是新内容：两个位置相减， 得到的是「隔着几个元素」，也就是它的编号。起点是 score.begin()，所以这个差就是「它在第几个（从 0 数）」。 68 在第 2 个，答案正是 2。

跟下标对一下

同一个位置，下标说 score[2]，迭代器说 score.begin() + 2——加法就是「从某个位置往后跨几个元素」。 两个说法是一回事，可迭代器多一项能力： 它能指向 end()，下标做不到（score[5] 是越界）。 下一课删、插要用的正是这一点。

别的容器也有

  • string 也能这样遍历，取得的是一个字符。 需要逐个字符查看的时候，这是 3.2 那些 substr、find 之外的另一条路。

报错里那个又长又复杂的名字 std::_Rb_tree_iterator<…>， 就是「map 的迭代器」的真名——它底下是一棵红黑树 （Rb 是 red-black 的缩写），所以迭代器名字里带着树。

为什么 vector 能加、map 不能？因为两者的元素排列方式不同：

  • vector 的元素在内存里连续存放，说「往后跨 3 个位置」， 它一步就跳过去了——这种能力叫随机访问（random access）。
  • map 是树结构，元素之间没有「相邻」这回事， 从一个到下一个要沿树的结构移动。所以它只支持 ++， 一次移动一个位置，想跨三个位置就写三遍 ++it。

例题 · 最高分在谁身上

一组「名字 + 分数」（3.4 学的 pair，正好存放两项数据）。 要求：找出最高分，并说出是谁、排在第几个。

这道题的关键是：遍历的过程中不能只看分数，还得把「最高分在哪里」 记下来——否则遍历结束后就找不到它了。 

#include <iostream>
#include <string>
#include <utility>
#include <vector>

int main() {
    std::vector<std::pair<std::string, int>> roster = {{"小李", 90},
                                                       {"小王", 77},
                                                       {"小张", 95},
                                                       {"小赵", 85}};

    auto best = roster.begin();
    for (auto it = roster.begin(); it != roster.end(); ++it) {
        if (it->second > best->second) {
            best = it;
        }
    }

    std::cout << "最高分是 " << best->second << std::endl;
    std::cout << "他是 " << best->first << "（第 " << (best - roster.begin())
              << " 个）" << std::endl;

    return 0;
}
最高分是 95
他是 小张（第 2 个）

分开分析：

  • best 是个迭代器，一开始指向第一个元素。 它不是「目前最高的分数」，而是「目前最高的那个位置」。
  • 每次循环取得 it->second（当前分数）跟 best->second（目前最高的分数）比较。 比较的是分数，替换的是位置——best = it; 这一句的作用就是「记住它在这里」。
  • 循环结束后，best 仍然指向那个位置。 三个问题一次答完：分数 best->second、 名字 best->first、第几个 best - roster.begin()。

要是只记分数（用一个 int top），走完就只剩一个 95， 人是谁、在第几个，都得再找一遍。「记住位置」这件事， 就是迭代器跟普通变量最大的区别。

练习 4-4

用迭代器把一个 vector 倒序输出，

3

提示：v.end() 指向最后一个元素的后面， 所以第一件要做的事是先 --it 退回来。 循环写成 for (auto it = v.end(); it != v.begin(); ) 这种形式，向后移动改成向前移动。 第一次编写时容易多输出一个或者少输出一个，对照预期输出核对。

看答案

起点是 v.end()，它指向最后一个元素的后面。所以每一轮 先把 it 回退一个位置、再输出——先回退后输出，顺序就反过来了： 

#include <iostream>
#include <vector>

int main() {
    int n = 0;
    std::cin >> n;

    std::vector<int> v;
    for (int i = 0; i < n; i++) {
        int x = 0;
        std::cin >> x;
        v.push_back(x);
    }

    for (auto it = v.end(); it != v.begin();) {
        --it;
        std::cout << *it << std::endl;
    }

    return 0;
}

三个地方值得停一下：

  • 先回退，后输出。一开始 it 指向 end()，这个位置不能解引用，先输出就会出错。
  • 停止的条件是「到达第一个元素」，不是「到达 end()」—— 循环写成 it != v.begin()。第一个元素正好是最后要输出的 那个，所以「后退、输出、检查是否停止」这一组操作执行完，一个元素都没有遗漏。
  • 空表也安全：n 是 0 的时候 v.end() 就是 v.begin()，条件一开始就不成立，一次都不执行。

把 --it 和 std::cout 那两行对调一下， 就能看见「先输出后回退」为什么会出错——输出了不该访问的位置上的值。 这一部分讲解的 end() 是什么，实际写错一次，理解最清楚。

#include <iostream>
#include <vector>

int main() {
    int n = 0;
    std::cin >> n;

    std::vector<int> score;
    for (int i = 0; i < n; i++) {
        int x = 0;
        std::cin >> x;
        score.push_back(x);
    }

    int pos = 0;
    for (int i = 1; i < int(score.size()); i++) {
        if (score[i] < score[pos]) {
            pos = i;
        }

    std::cout << "它在第 " << pos << " 个（从 0 数），是第 " << pos + 1

  • 记的是位置，不是分数。pos 里装的是 「第几个」，分数用 score[pos] 去取。 好处是「最低分是几分」和「它在第几个」两个问题一起答了。
  • < 不是 <=。 这题的 62 出现两次，用严格小于，第一个 62 站稳了不动， 所以是「第 1 个」。换成 <=，后一个 62 会替换它， 答案变成第 3 个。并列的时候要哪一个，必须自己决定， 定完在注释里写清楚。

看答案

三个人的年龄写在 map 里，名字从输入读取，用 find 查找： 

#include <iostream>
#include <map>
#include <string>

int main() {
    std::map<std::string, int> age;
    age["小李"] = 19;
    age["小王"] = 20;
    age["小张"] = 18;

    std::string name;
    std::cin >> name;

    auto it = age.find(name);
    if (it == age.end()) {
        std::cout << "名单里没有 " << name << std::endl;

        std::cout << it->first << "的年龄是 " << it->second << std::endl;

find 返回的内容有两种用法，这是 map 上的 find 跟 vector 上那个不同的地方：

  • 没找到的时候：它给的是 m.end()。 「最后一个元素的后面」在这儿不当位置用，当记号用—— 跟 end() 比较一下，就知道是否找到。4.2 讲过 end() 就是那个「没找到」的记号，这题用上了。

4.3删中间、插中间

3.1 留的那句「想删中间那个、想往中间插一个，还做不到」， 这一课解决这个问题。需要的内容上一课已经具备——能指向位置的对象。

删中间那个

函数叫 erase，它要求的是位置，不是编号，也不是值。 想删第 2 个，就把「第 2 个的位置」给它： 

#include <iostream>
#include <vector>

int main() {
    std::vector<int> v = {10, 20, 30, 40, 50};

    std::cout << "删之前：" << std::endl;
    for (int i = 0; i < int(v.size()); i++) {
        std::cout << "第 " << i << " 个：" << v[i] << std::endl;
    }

    v.erase(v.begin() + 2);

    std::cout << "删之后：" << std::endl;
    for (int i = 0; i < int(v.size()); i++) {
        std::cout << "第 " << i << " 个：" << v[i] << std::endl;
    }

    return 0;
}
删之前：
第 0 个：10
第 1 个：20
第 2 个：30
第 3 个：40
第 4 个：50
删之后：
第 0 个：10
第 1 个：20
第 2 个：40
第 3 个：50

看 v.begin() + 2 那个 + 2： 它说的是「起点往后两个元素」，也就是第 2 个——被删掉的是 30。 想删第 1 个就写 + 1，第一个元素就写 v.begin()， 不加任何偏移。

删除完成以后，后面的编号全部向前移动一位：40 从「第 3 个」变成了 「第 2 个」，50 从「第 4 个」变成了「第 3 个」。

后面的元素向前移动

上面那个编号的变化不是巧合，是删的代价。 vector 的元素在内存里连续存放，中间删除一个，后面的元素就必须逐个向前移动 填补——否则中间就会空出一个位置。 

10  20  30  40  50      v.erase(v.begin() + 2);

10  20  40  40  50      40 向前移动一个位置，覆盖 30
10  20  40  50  50      50 向前移动一个位置，覆盖 40
10  20  40  50          最后一个被丢弃，size 减 1

这个动作决定了一件事：删除的位置越靠前，需要移动的元素越多。 删除第 0 个，后面全部要向前移动一遍——那是 O(n)； 删除最后一个，一个都不需要移动——那是 O(1)。 4.1 那个标准在这里第一次发挥实际作用。

（3.1 里 pop_back() 的代价很低，就是这个原因： 它删除的正好是最后一个，不需要移动任何元素。）

往中间插一个

插入是同一种操作的相反过程：必须先把后面的元素向后移动，空出一个位置。 函数叫 insert，第一个参数是插在哪个位置， 第二个是插什么： 

#include <iostream>
#include <vector>

int main() {
    std::vector<int> v = {10, 20, 40};

    v.insert(v.begin() + 2, 30);

    std::cout << "插在中间之后：" << std::endl;
    for (int i = 0; i < int(v.size()); i++) {
        std::cout << "第 " << i << " 个：" << v[i] << std::endl;
    }

    v.insert(v.begin(), 0);

    std::cout << "又插在最前面：" << std::endl;
    for (int i = 0; i < int(v.size()); i++) {
        std::cout << "第 " << i << " 个：" << v[i] << std::endl;
    }

    return 0;
}
插在中间之后：
第 0 个：10
第 1 个：20
第 2 个：30
第 3 个：40
又插在最前面：
第 0 个：0
第 1 个：10
第 2 个：20
第 3 个：30
第 4 个：40

v.insert(v.begin() + 2, 30) 的意思是：在「第 2 个」 那个位置上，先开辟空间，把 30 写入。原来的 40 就向后移动了一个位置， 从「第 2 个」变成了「第 3 个」。

位置是「插在谁前面」。v.begin() + 2 指向 40， 所以 30 插在 40 前面。插在最前面就写 v.begin()—— 一样，是「插在第 0 个前面」。

插入的代价跟删除一样：插入位置越靠前，需要向后移动的元素越多。 插在最前面是 O(n)，插在最后面一个都不需要移动。 想在最后面加，用 3.1 那个 push_back—— 它就是「插在末尾」的专用函数。

一边走一边删

现在最需要注意的一个易错点。想「把不及格的删掉」，于是在遍历中删除—— 这样写是错误的： 

for (auto it = score.begin(); it != score.end(); ++it) {
    if (*it < 60) {
        score.erase(it);        // 删除之后 it 还有效吗？
    }
}

问题出在 erase(it) 之后：它指向的那个位置已经不存在， 后面的元素也都向前移动了。这个 it 现在指向哪里 无法确定——更严重的是，循环随后还要执行 ++it， 在刚移动过的元素上再向后移动一步，就会遗漏一个元素。

换一种写法：erase 会把「下一个位置的迭代器」 返回给你，继续使用它即可。 

#include <iostream>
#include <vector>

int main() {
    std::vector<int> score = {45, 90, 52, 68, 30, 91};

    for (auto it = score.begin(); it != score.end(); ) {
        if (*it < 60) {
            it = score.erase(it);
        } else {
            ++it;
        }
    }

    std::cout << "及格的：";
    for (int x : score) {
        std::cout << x << " ";
    }
    std::cout << std::endl;

    return 0;
}
及格的：90 68 91

这份程序里有三处跟平常的 for 不一样，一处都不能少：

  1. it = score.erase(it);—— 接收它返回的「下一个」，it 就处在正确的位置。
  2. 删除后就不执行 ++it。因为接收的那个位置 已经是「下一个」了，再增加就会跳过一个元素。
  3. for 的第三个空着不写——for (…; …;)。 平常那句 ++it 移动到循环体里了：及格就移动一个位置， 没及格就接收 erase 返回的下一个位置。两种情况都只前进一个位置， 不会遗漏。

这种形式（it = v.erase(it) 加一个空着的第三段） 是「边走边删」的标准写法，以后会反复见到。

string 也能这么删

erase 不只 vector 有。string 本身就是存放字符的容器—— 4.2 里它已经有 begin() 和 end()， 所以这一课的这两种工具它同样可以使用。把电话里的横线去掉， 就是把上面那个「一边遍历一边删除」原样应用到 string 上： 

#include <iostream>
#include <string>

int main() {
    std::string phone = "138-0013-8000";

    for (auto it = phone.begin(); it != phone.end(); ) {
        if (*it == '-') {
            it = phone.erase(it);
        } else {
            ++it;
        }
    }

    std::cout << "去掉横线：" << phone << std::endl;

    phone.insert(phone.begin() + 3, '-');

    std::cout << "再插回去：" << phone << std::endl;

    return 0;
}
去掉横线：13800138000
再插回去：138-00138000

三处新内容，其实一处都不新：

  • 那个循环一个字都没改——就是上面那个 it = phone.erase(it)、for 第三段空着的形式， 只是容器从 vector 换成了 string。 138-0013-8000 里有两个横线，两个都会删掉。
  • *it == '-'：迭代器取得的是一个字符， 所以用它和字符比较。单引号那对是字符、双引号是字符串（3.2 学的）。
  • 插回去那句给的是位置——phone.begin() + 3， 跟 vector 完全相同，不是编号。

string 另有一套用编号的写法，处理「中间那一段」的时候更方便： 

s.erase(3, 1);      // 从第 3 个开始，删掉 1 个字符
s.insert(3, "-");   // 从第 3 个开始，插一段进去

这套写法前面见过——3.2 的 substr(3, 1) 就是它： 「从第 3 个开始，截取 1 个」。编号在前、数字在后， string 从头到尾用的都是这套；vector 那边没有，只有位置版。

例题 · 插进去还得是有序的

给你一组已经排好序的数，再给一个数，把它插进去， 插完还得是有序的。输入是： 

6
10 20 30 50 60 70
40

40 应该插在 30 和 50 之间。这题的难点是必须先找到应该插在哪里， 再执行插入。而「查找」这一步，正好使用 4.2 学的迭代器： 

#include <iostream>
#include <vector>

int main() {
    int n = 0;
    std::cin >> n;

    std::vector<int> v;
    for (int i = 0; i < n; i++) {
        int x = 0;
        std::cin >> x;
        v.push_back(x);
    }

    int fresh = 0;
    std::cin >> fresh;

    auto it = v.begin();
    while (it != v.end() && *it < fresh) {
        ++it;
    }

    v.insert(it, fresh);

    for (int x : v) {
        std::cout << x << " ";
    }
    std::cout << std::endl;

    return 0;
}
10 20 30 40 50 60 70

那段 while 是全部的关键：从头向后遍历， 只要还比要插入的那个数小就继续，一旦遇到不小于它的就停止。 停止时 it 指向第一个不小于 40 的数，也就是 50—— 40 正好应该插在它前面。所以 v.insert(it, fresh) 一次完成。

两种边界情况这个写法都对，值得自己验一遍：

  • 要插的数比所有数都大（比如输入 99）：循环会一直走到 it == v.end() 才停，而 v.insert(v.end(), 99) 就是「插在最后面」——结果正确。
  • 要插的数比所有数都小（比如输入 5）：第一个数就比它大， 一次都没有执行就停止了，it 还是 begin()—— 插在最前面，也对。

把输入换成 99 和 5 各运行一遍，上面这两条自行确认。

练习

练习 4-7

读一组整数（第一行 n，第二行 n 个数），读一个 k， 删除第 k 个（从 0 计数），然后把剩下的输出。

5
10 20 30 40 50
2
删掉第 2 个（原来是 30）之后：10 20 40 50

提示：v.erase(v.begin() + k)。 这句和「删第 k 个」的对应关系是这一课的重点， 写完自己把 k 改成 0 和 4 各运行一遍查看。

看答案

先把要删的那个数复制下来，再删除——删除后就无法找到它了， 而输出里要报「原来是 30」： 

#include <iostream>
#include <vector>

int main() {
    int n = 0;
    std::cin >> n;

    std::vector<int> v;
    for (int i = 0; i < n; i++) {
        int x = 0;
        std::cin >> x;
        v.push_back(x);
    }

    int k = 0;
    std::cin >> k;

    int gone = v[k];
    v.erase(v.begin() + k);

    std::cout << "删掉第 " << k << " 个（原来是 " << gone << "）之后：";
    for (int x : v) {
        std::cout << x << " ";
    }
    std::cout << std::endl;

    return 0;
}

v.begin() + k 是这一课的中心句： 「第 k 个的位置」就是「从第一个元素的位置往后移 k 个元素」。 begin() 指向第 0 个，所以 + 2 指向第 2 个， 删掉的正是 30。k 从 0 计数，与下标一致。

把 k 改成 0 运行一遍（10 没了），再改成 4 运行一遍（50 没了）—— 三个位置各试一次，begin() + k 以后就不会记错。

练习 4-8

读一组整数，把所有偶数删除，只保留奇数。

8
3 8 5 12 7 4 9 6
剩下的奇数：3 5 7 9

提示：用「一边遍历一边删除」那个标准形式—— it = v.erase(it)，for 的第三段空着。 别写 for (…; …; ++it)， 那样删除后再 ++it 会遗漏一个数。

看答案

4.3 那个标准写法，条件是「是不是偶数」： 

#include <iostream>
#include <vector>

int main() {
    int n = 0;
    std::cin >> n;

    std::vector<int> v;
    for (int i = 0; i < n; i++) {
        int x = 0;
        std::cin >> x;
        v.push_back(x);
    }

    for (auto it = v.begin(); it != v.end();) {
        if (*it % 2 == 0) {
            it = v.erase(it);
        } else {
            ++it;
        }
    }

    std::cout << "剩下的奇数：";
    for (int x : v) {
        std::cout << x << " ";
    }
    std::cout << std::endl;

    return 0;
}

这个写法是这一课唯一值得记住的，分两点说明：

  • it = v.erase(it)——erase 把「下一个该看的位置」返回给你，接收它后继续遍历。 必须接收返回值：删除之后那个位置上已经是别的数了， 旧的 it 再用来遍历就是错误的。
  • for 的第三段空着。移动迭代器这件事已经移入循环体—— 删除时接收 erase 返回的位置，没有删除时执行 ++it。 第三段要是再填一个 ++it，删除完那一轮会多遍历一个元素， 正好漏掉紧跟着的那个数。这一条是这题唯一的易错点。

漏掉的那个数查看输入就知道：8 后面跟着 5，删除 8 之后 要是多走一个元素，5 就会被遗漏。这也是它难以检查的地方—— 漏掉的数不会报错，只是留在结果里。

练习 4-9

把上面那个「去除横线」的任务换一种做法： 不将位置 3 直接写入代码，先用 3.2 的 find 找出横线在第几个，再用那个编号去 erase。 

138-00138000
原来：138-00138000
横线在第 3 个
去掉横线：13800138000

提示：find 找不到时给的是 npos （3.2 学的），记得判一下—— 用户完全可能输入一个本来就没有横线的电话。

看答案

跟 4.3 正文那份的区别只有一个：那份将 3 直接写入代码， 这份先用 find 查找。find 给的是位置， erase 要的正好也是位置，两个接得上： 

#include <iostream>
#include <string>

int main() {
    std::string phone;
    std::cin >> phone;

    std::cout << "原来：" << phone << std::endl;

    if (phone.find('-') == std::string::npos) {
        std::cout << "这串里没有横线" << std::endl;
        return 0;
    }

    int pos = int(phone.find('-'));
    std::cout << "横线在第 " << pos << " 个" << std::endl;

    phone.erase(pos, 1);

    std::cout << "去掉横线：" << phone << std::endl;

    return 0;
}

npos 那一句不能省（3.2 学的）：用户完全可能输入一个 本来就没有横线的号码，那时候 find 给的是一组 「没有这个位置」的记号，用它去 erase 就会出错。 先判断「在不在」，再操作它——这个顺序在 3.2 就定下了。

输入换成 13800138000 运行一遍，输出的是 「这串里没有横线」，程序正常运行。那一句判断的就是这个。

练习 4-10

读一组整数，读一个 x，在所有奇数前面各插入一个 0。 

5
2 3 6 7 8
0

上面这个输入的格式比较复杂，改成下面这样更清楚：第一行 n， 第二行 n 个数，要插入的内容直接写在程序里（只插入 0）： 

5
2 3 6 7 8
2 0 3 6 0 7 8

提示：这也是「一边遍历一边插入」，而且比删除更复杂—— insert 同样会把「指向新插入元素的迭代器」返回给你。 插入 0 之后，你的 it 指向那个 0，还必须向后跨两个元素才能继续检查下一个数 （跨过 0，再跨过原来的奇数）。写完对照预期输出核对。

看答案

仍然是遍历过程中修改容器，只是这一次是插入而不是删除： 

#include <iostream>
#include <vector>

int main() {
    int n = 0;
    std::cin >> n;

    std::vector<int> v;
    for (int i = 0; i < n; i++) {
        int x = 0;
        std::cin >> x;
        v.push_back(x);
    }

    for (auto it = v.begin(); it != v.end();) {
        if (*it % 2 != 0) {
            it = v.insert(it, 0);
            it = it + 2;
        } else {
            ++it;
        }
    }

    for (int x : v) {
        std::cout << x << " ";
    }
    std::cout << std::endl;

    return 0;
}

insert 跟 erase 一样，会返回位置—— 返回的是刚插入的那个 0 的位置。所以插完不能直接 ++it：那样下一个访问的仍然是原来那个奇数（它仍然是奇数）， 又会在它前面插入一个 0，无法结束。 要 it = it + 2，一次跨过两个元素：跨过刚插的 0， 再跨过原来那个奇数，才能到达下一个需要访问的数。

按照输入执行一遍：2 不是奇数，跳过；3 是奇数，前面插 0， 现在 it 指向那个 0，跨过两个元素到达 6（0 和 3 都跨过了）； 6 跳过；7 前面插 0，跨过两个元素就到达末尾——end()，循环停止。 那个 2 的来源，从输入推算一遍就清楚了， 比死记硬背可靠。

你现在能写什么：erase 和 insert 都能用了，知道它们要的是位置、以及那个 v.begin() + k 该怎么写； 知道删除中间、插入中间要移动整段，所以都比删除末尾代价高； 还会写「一边遍历一边删除」那个 it = v.erase(it) 加空着第三段的形式。

4.4现成的工具

4.2 那个 for (auto it = v.begin(); …) 还有个用处—— 它是这一课那些工具的共同入口。

它们都要两个位置

C++ 自带一大批现成的工具，都在一个叫 <algorithm> 的头文件里。查找、计数、取最大最小、排序，这些经常重复编写的循环， 里面全都有现成的，不用自己写。

用它们的方法都一样：每个工具都需要两个位置——从哪里开始， 到哪里为止。而那两个位置正是迭代器： 

#include <algorithm>

std::find(v.begin(), v.end(), 要查找的元素);
std::count(v.begin(), v.end(), 要统计的元素);
std::sort(v.begin(), v.end());

所以上一课讲迭代器的那一段是有用的。先有迭代器，才用得上这一批工具—— 记住这一条，这一课的语法就没有多少新内容了，全是「两个位置 + 一个元素」。

到哪里为止是「不含」的

第二个位置给的都是 v.end()，而它指向最后一个元素的后面， 所以最后一个元素是包含在其中的——end() 本身指向的位置上 没有元素。
这个「含头不含尾」的规矩等一下用得上： 想让工具只处理前三个，就写 v.begin(), v.begin() + 3，第四个不在范围内。

find：找得到，找不到

find 在范围里查找一个值，找到就把那个位置返回给你， 找不到就把 end() 返回给你——跟 3.2 里 string 的 find 相同的性质，只是一个返回编号一个返回位置： 

#include <algorithm>
#include <iostream>
#include <vector>

int main() {

两处要说一下：

  • max_element 给的是位置，所以要加星号取值—— *std::max_element(…)。 4.2 例题里那个 best 就是你手动编写的版本； 这个工具完成的功能完全相同，只是已经写好。 它给位置也有好处：想知道「最高分在第几个」， 把星号换成 - score.begin() 就行。

sort：一句话排好

这一批工具里最常用的一个： 

#include <algorithm>
#include <iostream>
#include <string>
#include <vector>

int main() {
    std::vector<int> v = {45, 52, 68, 91, 73};
    std::sort(v.begin(), v.end());
    std::cout << "排完：";
    for (int x : v) {
        std::cout << x << " ";
    }
    std::cout << std::endl;

    std::vector<std::string> words = {"banana", "apple", "cherry"};
    std::sort(words.begin(), words.end());
    std::cout << "英文排完：";
    for (const std::string& w : words) {
        std::cout << w << " ";
    }
    std::cout << std::endl;

    std::vector<std::string> names = {"小李", "小王", "小张"};
    std::sort(names.begin(), names.end());
    std::cout << "中文排完：";
    for (const std::string& w : names) {
        std::cout << w << " ";
    }
    std::cout << std::endl;

    return 0;
}
排完：45 52 68 73 91 
英文排完：apple banana cherry 
中文排完：小张 小李 小王

三行说明白：

  • 默认从小到大。数字按大小；字符串按字节比较—— 英文那边 apple 在最前面看上去很自然， 中文那行的顺序就是 3.4 里 map 自动排出来的那个顺序， 一个字都没变。这不是按拼音排的（3.2 埋的那颗种子， 在这儿结的果）。
  • const std::string& 是 6.5 的引用， 意思是「只读取，不复制」。 排序之后用范围 for 输出，加上它可以省去一次复制——数据量大时有区别。
  • 代价是 O(n log n)。比一遍 find 那种 O(n) 贵，比两层循环那种 O(n²) 便宜得多。排序是一个分界点：排完之后，find 那些工具仍然是 O(n)，但「每次缩小一半」那种方法可以使用了 （那是后面进阶的内容，这里先知道这个结论）。

想知道「从大到小」怎么办？sort 接受第三个参数—— 一条「谁该排在前面」的规矩。那正是下一课的正题。

例题 · 一份成绩单的统计报告

读 n 个分数，输出一份简要报告：最高、最低、平均、中位数。 输入是： 

7
90 77 95 85 60 72 88
最高 95 分
最低 60 分
平均 567 / 7 = 81 分（整数除法，抹掉小数）
从小到大：60 72 77 85 88 90 95 
中位数是第 3 个（从 0 数）：85 分

这一课的四样工具在这里都用上了——而且每个都只用一行： 

#include <algorithm>
#include <iostream>
#include <vector>

int main() {
    int n = 0;
    std::cin >> n;

    std::vector<int> score;
    int sum = 0;
    for (int i = 0; i < n; i++) {
        int x = 0;
        std::cin >> x;
        score.push_back(x);
        sum = sum + x;
    }

    std::cout << "最高 " << *std::max_element(score.begin(), score.end())
              << " 分" << std::endl;
    std::cout << "最低 " << *std::min_element(score.begin(), score.end())
              << " 分" << std::endl;

    std::cout << "平均 " << sum << " / " << n << " = "
              << sum / n << " 分（整数除法，抹掉小数）" << std::endl;

    std::sort(score.begin(), score.end());

    std::cout << "从小到大：";
    for (int x : score) {
        std::cout << x << " ";
    }
    std::cout << std::endl;

    std::cout << "中位数是第 " << n / 2 << " 个（从 0 数）："
              << score[n / 2] << " 分" << std::endl;

    return 0;
}

三个地方值得停一下：

  • 中位数为什么要先排？因为中位数就是「排好之后正当中那个」。 排序这一步是它的前提，不是可有可无的一步。 正当中那个的下标是 n / 2——7 个数是 7 / 2 = 3， 第 3 个（从 0 数）就是四个小的、三个大的中间那个 85。 （个数是偶数时中位数取哪一个是另一回事，这儿不管。）
  • 求和是在读取时一并完成的，没有另外写一遍循环。 一次遍历能完成的事不要分成两次——这也是 4.1 那个标准的用法。
  • 平均那一行把算式也输出了（567 / 7 = 81）， 为的是直接展示一件事：sum / n 是整数除法—— 两个 int 相除，小数直接省略，不四舍五入。这份成绩单正好整除， 换个数据就看出来了：删掉最后那个 88 再运行，六个数是 479 / 6 = 79.8…，程序输出的是 79。要得到真小数得用 double，那是另一回事。

把输入换成偶数个数（比如删掉最后那个 88）： 查看 n / 2 算出来的中位数是哪个，也查看平均那一行的 除法省略了多少小数。

练习 4-11

读一组分数，求出最高分，并说出它在第几个。 

5
88 62 95 62 70
最高分是 95
它在第 2 个

提示：max_element 给的是位置—— 不要急于加星号。先用这个位置减去 v.begin() 得到编号，再通过 * 取得分数， 两个问题一起回答。

看答案

这题只有一个需要注意的地方：max_element 给的是位置， 不是分数。两个问题都从这一个位置得到答案： 

#include <algorithm>
#include <iostream>
#include <vector>

int main() {
    int n = 0;
    std::cin >> n;

    std::vector<int> score;
    for (int i = 0; i < n; i++) {
        int x = 0;
        std::cin >> x;
        score.push_back(x);
    }

    auto it = std::max_element(score.begin(), score.end());

    std::cout << "最高分是 " << *it << std::endl;
    std::cout << "它在第 " << (it - score.begin()) << " 个" << std::endl;

    return 0;
}

两句话对着看：

  • *it——那个位置上的值，也就是 95。 星号表示取出该位置上的值。
  • it - score.begin()——那个位置在第几个。 两个位置一减，得到的是「隔着几个元素」，也就是 2。 4.2 讲过 begin() 是第 0 个，所以「第 2 个」输出的就是 2。

换成 min_element 就是「最低分在第几个」， 形式一个字符都不需要改。另外记住一条：并列最大（好几个 95）的时候， 它给的是最先出现的那个——要最后一个必须自己遍历一遍。

练习 4-12

读一组整数，统计其中大于 60 的有几个，并把它们从小到大输出。 

7
90 77 95 85 60 72 88
大于 60 的有 6 个：72 77 85 88 90 95

提示：这一课的工具里，只有 count 是「等于某个值」的， 没有现成的「大于 60 的」。所以先自己统计（一个循环加一个 if，4.1 学过的那种），排序再用 sort。 统计那部分下一课有现成的写法，先手动编写一遍正好。

看答案

现成的工具里没有「大于 60 的」这种说法（count 只认 「等于」），所以两件事都自己遍历一遍，最后用 sort 完成排序： 

#include <algorithm>
#include <iostream>
#include <vector>

int main() {
    int n = 0;
    std::cin >> n;

    std::vector<int> score;
    for (int i = 0; i < n; i++) {
        int x = 0;
        std::cin >> x;
        score.push_back(x);
    }

    int count = 0;
    for (int x : score) {
        if (x > 60) {
            count = count + 1;
        }
    }

    std::vector<int> pass;
    for (int x : score) {
        if (x > 60) {
            pass.push_back(x);
        }
    }

    std::sort(pass.begin(), pass.end());

    std::cout << "大于 60 的有 " << count << " 个：";
    for (int x : pass) {
        std::cout << x << " ";
    }
    std::cout << std::endl;

    return 0;
}

两处可以留意：

  • 统计的那一遍和挑选的那一遍用的是同一个条件（x > 60）， 写了两遍。下一课的 count_if 能把统计的那一遍省去—— 先手动编写一遍，到时候才知道它替你省去的是什么， 也知道它无法省略的（把元素挑选出来）仍然需要自己编写。
  • 原表没有改动。挑选出来的是一个新 vector，sort 排序的是它，原来那份分数的顺序保持不变。

补充一点：count 那个数其实用 pass.size() 也能得到。写成两条路径是为了让你看清「统计」和「挑选」是两件事， 实际编写的时候挑选完再查看大小，可以少遍历一遍。

练习 4-13

把 4.1 那道「名单里的重名」用这一课的工具重写一遍： 先 sort，然后只看相邻的两个有没有一样的。 输入还是那六行： 

6
小李
小王
小张
小李
小赵
小钱
排完：小张 小李 小李 小王 小赵 小钱
有重名

提示：排完之后，两个一样的名字一定相邻—— 所以只要比 v[i] 和 v[i+1]， 一遍就够，不用两两比较。 这一版是什么时间复杂度？（跟 4.1 那两个写法比一比： 这一版比「两两比较」快多少？比「问 set」呢？）

看答案

4.1 那两版都是「两两比较」，这一版使用排序：排序完之后， 一样的两个名字必然相邻，所以遍历一遍、每次只看相邻的两个就够： 

#include <algorithm>
#include <iostream>
#include <string>
#include <vector>

int main() {
    int n = 0;
    std::cin >> n;

    std::vector<std::string> name;
    for (int i = 0; i < n; i++) {
        std::string s;
        std::cin >> s;
        name.push_back(s);
    }

    std::sort(name.begin(), name.end());

    std::cout << "排完：";
    for (const std::string& s : name) {
        std::cout << s << " ";
    }
    std::cout << std::endl;

    bool dup = false;
    for (int i = 0; i + 1 < int(name.size()); i++) {
        if (name[i] == name[i + 1]) {
            dup = true;
        }
    }

    std::cout << (dup ? "有重名" : "没有重名") << std::endl;

    return 0;
}

三个版本放在一起比较——这才是这道题要说明的内容：

  • 两两比较：O(n²)。六个名字比 15 次， 一万个名字比五千万次，名字一多就慢到不可接受。
  • 问 set：O(n log n) 上下，代价是多占一份 set 的内存。
  • 这一版：排序 O(n log n) 加一遍 O(n)，合起来还是 O(n log n)， 不用多开一份容器。跟「问 set」一个量级，原地做。

「排序完成后再查看相邻元素」这个思路很有用：凡是「有没有两个一样」 「有没有距离太近的」这类问题，多半可以先排一遍再检查相邻元素。

你现在能写什么：打开 <algorithm> 这一批工具了——find、count、 max_element、min_element、reverse、 sort，每个都是「两个位置 + 一个元素」； 知道 max_element 给的是位置所以要加星号； 也知道 sort 默认按字节从小到大， 代价是 O(n log n)。

4.5lambda

上一课最后留下了一个问题：「想知道从大到小怎么办？sort 接受第三个参数——那条『谁该排在前面』的规矩。」 这一课讲的就是那条规矩怎么写。

条件也能当参数

先说一个 4.4 留下的不方便。find 只会问一件事： 「等于这个吗」。可实际想问的常常不是相等—— 「第一个及格的在哪」「第一个比他高的在哪」。

4.4 那个 find 帮不上忙。得自己开个循环， 一边遍历一边判断条件，还得记住遍历到了哪里——4.2 例题那种形式。

有一个现成的：find_if（那个 _if 就是「带条件的」意思）。它跟 find 的用法一样， 只是第二个参数不收「一个值」，收一条条件： 

#include <algorithm>
#include <iostream>
#include <vector>

int main() {
    std::vector<int> score = {45, 52, 68, 91, 73};

    auto it = std::find_if(score.begin(), score.end(),
                           [](int x) { return x >= 60; });

    if (it == score.end()) {
        std::cout << "一个及格的都没有" << std::endl;
    } else {
        std::cout << "第一个及格的是 " << *it << std::endl;
    }

    return 0;
}
第一个及格的是 68

跟 4.2 例题那份手动编写的循环比较：同一个答案，循环不用写了。 「及格」这件事缩成了方括号后面那一小段。那一小段就是这一课的主题。

那段小代码长什么样

把那一部分单独拿出来查看： 

[](int x) { return x >= 60; }

它叫 lambda，是一个没有名字的小函数—— 直接写在调用处，写在它要被使用的地方，不需要在外面另外定义名称。 四段逐个看：

这一段 是什么
[] 开头必须是它，告诉编译器「这儿开始是一个 lambda」。 跟下标、跟数组都没关系，就是 lambda 的记号。 里面稍后要写内容（见下面「方括号里写谁」）
(int x) 参数，跟普通函数的参数一模一样。 这儿是「我把容器里的一个元素交给你看」—— 所以类型是元素类型：分数是 int，写 int x
{ … } 函数体。里面要返回 true 或 false： 合条件就 true，不合就 false
return 跟普通函数一样。短的话能写成一行

所以 [](int x) { return x >= 60; } 这句话的含义就是： 「传入一个 x，计算它是否大于等于 60」。 find_if 使用它，从第一个数开始逐个判断， 判断到哪个元素返回 true，就停在那个位置上。

find_if 找的是第一个答 true 的。45 答 false，52 答 false， 68 答 true——所以停在 68，正好是「第一个及格的」。

为什么需要这个机制

想给 find 换一个条件，本来只有两个办法： 修改 find 的代码（那是标准库，无法修改）， 或者自己写一遍循环（每换一个条件写一遍）。 lambda 把「条件」变成了一个可以传递的参数—— 传入「及格」就是查找及格，传入「比 60 大」就是查找…… 逻辑完全没有变化，只是条件换了。

它是 C++11 才有的。老代码里见不到，新代码里到处都是。

count 与 count_if

count 也有带 _if 的兄弟，区别一模一样： 

#include <algorithm>
#include <iostream>
#include <vector>

int main() {
    std::vector<int> score = {45, 52, 68, 91, 73};

    std::cout << "等于 52 的有 "
              << std::count(score.begin(), score.end(), 52) << " 个" << std::endl;

    int pass = std::count_if(score.begin(), score.end(),
                             [](int x) { return x >= 60; });
    std::cout << "及格的（>= 60）有 " << pass << " 个" << std::endl;

    return 0;
}
等于 52 的有 1 个
及格的（>= 60）有 3 个

这一对写法很好记：名字后面带 _if 的那个，第三个参数 接收的是条件；不带 _if 的那个，接收的是值。

  • find(v.begin(), v.end(), 68)——找等于 68 的那个。
  • find_if(v.begin(), v.end(), [](int x) { return x >= 60; }) ——找第一个及格的。
  • count(v.begin(), v.end(), 60)——数等于 60 的有几个。
  • count_if(v.begin(), v.end(), [](int x) { return x >= 60; }) ——数及格的有几个。

回到练习 4-12：那道题里「大于 60 的有几个」要手动编写循环， 就是因为当时还没有 count_if。现在可以直接换成一行。

方括号里写谁

[](int x) { return x >= 60; } 里那个 60 是直接写入代码的。 想把 60 换成一个可以修改的界限，就得把那个变量从外面引入—— 方法是在方括号里写上它的名字： 

#include <algorithm>
#include <iostream>
#include <vector>

int main() {
    std::vector<int> score = {45, 52, 68, 91, 73};

    int line = 60;
    auto it = std::find_if(score.begin(), score.end(),
                           [line](int x) { return x >= line; });
    std::cout << "及格线定为 " << line << "：第一个达到的是 " << *it << std::endl;

    line = 90;
    auto high = std::find_if(score.begin(), score.end(),
                             [line](int x) { return x >= line; });
    std::cout << "及格线定为 " << line << "：第一个达到的是 " << *high << std::endl;

    return 0;
}
及格线定为 60：第一个达到的是 68
及格线定为 90：第一个达到的是 91

[line] 就是把外面那个 line 引入 lambda 使用。 这个动作叫捕获（capture），捕获的对象是外面那个变量。

查看第二段：line 改成 90 之后，新写的那个 lambda 用 [line] 捕获的是当时的 90， 所以第二个问题查找的是「第一个达到 90 的」，答案是 91。 同一段代码，界限设在哪里就按哪个界限查找——这就是把条件抽取出来的好处。

两个常问的：

  • 为什么没有捕获就不能直接使用？可以理解为一条规则： 方括号里没有写的名字，lambda 就当作不存在。 这是有意设计的——写明了才能知道这段代码依赖外面的哪些变量， 之后阅读代码的人查看方括号就能知道它依赖谁。
  • 捕获进来的变量能修改吗？这里是用来比较大小（只读），所以什么都不需要加。 想在 lambda 里修改外面那个变量是另一回事，需要写 [&line] （前面加一个 &，表示引用原变量而不是复制副本）—— 这是引用的用法（6.5），现阶段不需要，知道有这种写法即可。

三句话，一句比一句有用：

  1. error: 'line' is not captured—— 直译是「line 没有被捕获」。也就是说「你使用了外面那个 line， 可是方括号里没有写它」。看到 not captured， 就去补方括号，没有第二种可能。
  2. note: the lambda has no capture-default—— 「这个 lambda 没有默认捕获」。意思是方括号里空空如也， 什么也没有捕获。它是在告诉你：问题就出在那对空的方括号上。
  3. note: 'int line' declared here，底下还指向 int line = 60;——「你所说的这个 line 是在这里声明的」。 名字重复、或者记不清是哪个 line 的时候，这一句能节省一些查找时间。

这个报错的好处是不需要猜测：哪里错了、错在哪个方括号、 那个变量在哪里声明，三句话全部给出了答案。

给 sort 一条规矩

回到上一课留的那个问题：sort 从大到小怎么办。 第三个参数就是那条 lambda——它回答的问题是「a 该排在 b 前面吗」： 

#include <algorithm>
#include <iostream>
#include <vector>

int main() {
    std::vector<int> score = {45, 52, 68, 91, 73};

    std::sort(score.begin(), score.end(), [](int a, int b) { return a > b; });

    std::cout << "从高到低：";
    for (int x : score) {
        std::cout << x << " ";
    }
    std::cout << std::endl;

    return 0;
}
从高到低：91 73 68 52 45

看那个 lambda 跟前面几个不一样的地方：它有两个参数。 find_if 是「给你一个元素，你说是还不是」， 所以一个参数；sort 是「给你两个元素， 你说谁该在前面」，所以两个。

return a > b; 的意思：a 比 b 大的时候答 true—— 也就是「大的排前面」。默认那条规矩是 a < b（小的排前面）， 所以从小到大；把它反过来写，就倒过来了。

这条规矩要守得住

写 a >= b 会出错。相等的时候它返回 true—— 等于说「a 和 b 谁在前都行」，可它两边都这么返回。 sort 按这个规矩可能无法正常结束（运行时报错，或者排序结果错乱）。 规矩只保留一条：严格大于就写 >，严格小于就写 <， 不要加那个等号。

读一整行（可能带空格），数出里面有几个数字字符、几个大写字母。 输入是：

#include <algorithm>

#include <algorithm>
#include <iostream>

#include <algorithm>
#include <iostream>
#include <vector>

int main() {
    int n = 0;
    std::cin >> n;

    std::vector<int> v;
    for (int i = 0; i < n; i++) {
        int x = 0;
        std::cin >> x;
        v.push_back(x);

    auto in_range = [](int x) { return x >= 10 && x <= 20; };

  • 条件有了名称。auto in_range = [](int x) {...}; 这一句把 lambda 存进一个变量（4.5 讲过 lambda 本身就是一个值）。 统计一遍、挑选一遍用的是同一条条件，只写了一份， 以后要改「10 到 20」只改这一处。

为什么 sort 里会出现「查找 <」

报错里那句是 { return *__it1 < *__it2; }—— 库里面的一个小函数，作用就是「比较两个元素」。 sort 排序的时候不断执行这件事：它只会用 < 来判断谁该在前面，没有别的能力。 int 和 string 都会 <，所以一切正常； Student 不会，所以它就停在这里了。

给它一条规矩

改法就是上一课学的那个：给 sort 第三个参数—— 一条「谁该排在前面」的规矩。这时它不再需要自己比较 <，而由你指定规则： 

#include <algorithm>
#include <iostream>
#include <string>
#include <vector>

struct Student {
    std::string name;
    int score;
};

void print(const std::vector<Student>& roster) {
    for (const Student& s : roster) {
        std::cout << s.name << " " << s.score << std::endl;
    }
}

int main() {
    std::vector<Student> roster = {{"小李", 90}, {"小王", 77},
                                   {"小张", 95}, {"小赵", 85}};

    std::cout << "原来的顺序：" << std::endl;
    print(roster);

    std::sort(roster.begin(), roster.end(),
              [](const Student& a, const Student& b) { return a.score > b.score; });

    std::cout << "按分数从高到低：" << std::endl;
    print(roster);

    std::sort(roster.begin(), roster.end(),
              [](const Student& a, const Student& b) { return a.name < b.name; });

    std::cout << "按名字排：" << std::endl;
    print(roster);

    return 0;
}

三处值得说：

  • 参数写成 const Student&，不是 Student。 & 是引用（6.5），意思是「只读取，不复制」—— 比 int 大得多的类型（Student 里有一个 string）， 每比较一次都复制一遍代价太高。const 表示「只读取，不修改」。 这两个关键字一起写上，是这类参数的标准写法，以后照写即可。
  • 规矩决定排序结果。按分数排完，小王 77 排在最后； 再按名字排，最后两个的位置又交换了——同一个 vector， 换了规矩就是另一种排法，这就是把规矩当作参数传入的好处。
  • 两个规矩排出来的结果差在最后两个。 按分数，小赵 85 排在小王 77 前面；按名字，反过来—— 小王在小赵前面，因为「王」的字节比「赵」小。 名字的字节顺序跟分数的高低本来是两回事， 前两个恰好排成一样，不要以为它们总是一样：换几个名字再运行， 差异会出现得更多。

那一份 print 是单独抽取出来的：同一段操作（输出三遍名单） 写第二遍的时候就应该定义名称了。参数写成 const std::vector<Student>& 也是同一个道理。

pair 不用给规矩

有个例外值得知道：pair 本身就会比较，不用给规矩。 它的规矩是现成的—— 

先比 first；first 一样，再比 second。

所以 pair 的 vector 直接 sort 就能排， 一行 lambda 都不用写： 

#include <algorithm>
#include <iostream>
#include <string>
#include <utility>
#include <vector>

int main() {
    std::vector<std::pair<std::string, int>> v = {{"小李", 90}, {"小王", 77},
                                                  {"小李", 60}};

    std::sort(v.begin(), v.end());

    for (const std::pair<std::string, int>& p : v) {
        std::cout << p.first << " " << p.second << std::endl;
    }

    return 0;
}

小李 90
小王 77

看那个顺序：两个「小李」相邻，而且分数小的那个在前面 （60 在 90 前）——first 一样的时候它接着比了 second。 这就是那条现成的规则在起作用。

例题 · 排行榜

按分数从高到低给这五个人排名次，输出结果。名单直接写在程序里： 

小李 90
小张 95
小王 90
小赵 85
小陈 95
第 1 名  小张 95
第 2 名  小陈 95
第 3 名  小李 90
第 4 名  小王 90
第 5 名  小赵 85

这道题有两个易错点：同分的怎么办，还有名次怎么输出。 先看程序： 

#include <algorithm>
#include <iostream>
#include <string>
#include <vector>

struct Student {
    std::string name;
    int score;
};

int main() {
    std::vector<Student> roster = {{"小李", 90}, {"小张", 95}, {"小王", 90},
                                   {"小赵", 85}, {"小陈", 95}};

    std::sort(roster.begin(), roster.end(),
              [](const Student& a, const Student& b) {
                  if (a.score != b.score) {
                      return a.score > b.score;
                  }
                  return a.name < b.name;
              });

    for (int i = 0; i < int(roster.size()); i++) {
        std::cout << "第 " << i + 1 << " 名  " << roster[i].name << " "
                  << roster[i].score << std::endl;
    }

    return 0;
}

两处：

  • 那条 lambda 里写了两句。 分数不一样，就比分数（大的在前）； 分数一样，就比名字（a.name < b.name，按字节）。 第二句不是可有可无的——没有它，两个同分的人谁在前就无法确定， 同一份输入多运行几次，名单可能不一样。 写排序规矩的时候，「一样的时候怎么办」永远要考虑到。
  • 名次就是「它在第几个」：循环里的 i 从 0 计数， 名次从 1 计数，所以输出的是 i + 1。 这就是 4.2 那句「位置换编号」的另一个用法。

还有个细节：同分的人里面，小陈排在小张后面，因为 「小陈」的字节比「小张」小。要是想让同分的按输入顺序排， 那得再记住「第几个输入的」——那道题留给你自己试。

把两个名字改成排列顺序相反的（比如把「小张」改成「小赵」）， 查看同分的那一对如何交换位置——那句 a.name < b.name 的作用就显现出来了。

        std::cout << s.name << " " << s.score << std::endl;
    }

    return 0;
}

第二句（分数一样比名字）一个字符没有改动，这正是这题要看的地方： 整张表的顺序相反了，但两对同分的内部顺序没有变化—— 小李还是排在小王前面，小张还是排在小陈前面。 决定它俩谁先谁后的是名字那句话，跟分数那句怎么写没关系。

读一组「名字 分数」，找出分数最高的那个人的名字； 同分的话，名字靠前的那个（按字节）。输入用例题那份名单 （小张和小陈都是 95）：

提示：这一部分学的内容在这里都用上了—— 先排（规矩跟例题一样，两句话），排完第 0 个就是答案。 换一种写法也可以：自己逐个比较一遍（4.2 例题那种形式）， 或者用 max_element（4.4）， 但同分时的取舍得自己写规矩。三种写法都写一遍， 这一部分的内容就联系起来了。

看答案

最直接的一条路径：先排序，再取第 0 个元素。规矩跟例题一样两句话： 

#include <algorithm>
#include <iostream>
#include <string>
#include <vector>

struct Student {
    std::string name;
    int score;
};

int main() {
    int n = 0;
    std::cin >> n;

    std::vector<Student> roster;
    for (int i = 0; i < n; i++) {
        Student s;
        std::cin >> s.name >> s.score;
        roster.push_back(s);
    }

    std::sort(roster.begin(), roster.end(),
              [](const Student& a, const Student& b) {
                  if (a.score != b.score) {
                      return a.score > b.score;
                  }
                  return a.name < b.name;
              });

    std::cout << "最高分是 " << roster[0].score << std::endl;
    std::cout << "他是 " << roster[0].name << std::endl;

    return 0;
}

排序完成后 roster[0] 就是答案。题面要求的「同分时名字靠前」 已经在第二条规矩里交代清楚了：小张和小陈都是 95， 「张」的字节比「陈」小，所以小张排在前面。

题面说另外两条路径也各写一遍。两条路径的要点在这里：

  • 自己逐个比较一遍（4.2 例题那个形式）：记住「目前最高的 位置」，遇到更高的就换。同分怎么办要写清楚——只写 score[i] > score[best] 的话，同分时先出现的那个 会被保留，这份输入里恰好是小张，但那是巧合： 把小陈放在小张前面，答案就不是小张了。 要它无论怎么排都正确，比较必须写成「分数更高，或者分数一样而名字更靠前」。
  • 用 max_element（4.4）：它默认按分数比， 同分给最先出现的那个，仍然要处理上面那个问题——同分的取舍 仍然需要自己编写一条比较规则传入。

三条路径比较完能看出一个结论：「同分怎么算」这件事， 只有先排序这条路径有一处专门的地方书写它（规矩的第二句）。 这就是这一部分最后要留下的结论——排序不仅决定顺序， 它还是把「谁先谁后」这件事明确说明的地方。

你现在能写什么：自己定义的 struct 也能排序了—— 给它一条 lambda 说明「谁该排在前面」，规矩里 「分数一样时怎么办」也必须交代清楚； 还学会了阅读那种篇幅很长的模板报错： 先找 required from here 指向你的哪一行、 再看那句 error:、candidate 那一组不看。
