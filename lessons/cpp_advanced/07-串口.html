第 7 部分

串口（uart）基础

串口（serial port）是两块电路板之间最常用的一种连接方式：一根线发，一根线收， 数据按字节依次通过。机器人上的主控板、电源管理模块、图传、自定义控制器， 很多都通过串口交换信息。这一部分从最基本的字节表示讲起， 依次讲打开串口、配置串口、读写字节流、一帧数据的格式、校验、粘包与半包， 最后写出一个能持续收包的循环。

课上使用的帧格式来自 2026 赛季官方通信协议 V1.3.0：帧头为 0xA5，帧内包含长度、序号、命令码、数据与两段 CRC 校验。 本课按这份协议讲；其他赛季以当季官方协议为准。 页面上的命令码 0x0001、0x0002、0x0003 是课程自己编的练习用命令，不对应任何官方业务。

手边没有板子也可以练：Linux 提供了伪终端（pseudo terminal，pty）， 程序可以用它造出一对互相连通的“软件串口”，再用一个 Python 小程序扮演对面那块板子。 字节收发、组帧、校验、粘包与半包都能在没有硬件的情况下跑通。 真实波特率、校验位与电气信号只有在真板子上才成立，页面上会逐处写清楚。

7.1十六进制与字节

串口一次传送一个字节（byte）。一个字节由 8 位（bit）组成， 每一位是 0 或 1，合起来可以表示 0 到 255 之间的一个整数。 协议里的帧头、长度、命令码、校验值，最终都是这样一个个字节。

字节与十六进制

直接写十进制数字，看不出字节内部的位是怎么排列的；写成十六进制就方便得多： 一个字节正好用两位十六进制数字表示，每一位十六进制数字对应 4 位二进制。 例如 0xA5 的二进制是 1010 0101， 0x02 的二进制是 0000 0010。

C++ 里用 0x 开头写十六进制常量。0xA5 和 165 是同一个数，写哪一个都可以，讲协议时通常写十六进制。 在 C++ 中表示一个字节，用 unsigned char：它占 1 个字节，范围是 0 到 255。 标准库的 <cstdint> 里还提供了 std::uint8_t，它是“无符号 8 位整数”的别名，范围与 unsigned char 相同，名字更直接。这个类型在本课后面会用到， 需要了解细节时可以自行搜索「C++ uint8_t」。

printf 的 %02X

输出字节时，常用 printf 的 %02X 格式： X 表示用大写十六进制输出，2 表示至少占两位， 0 表示不足两位时在前面补 0。这样 0x0F 会输出成 0F，而不是一位的 F，所有字节的宽度就一致了。 十六进制数字用大写还是小写都可以，本课统一用大写。

有符号与无符号

char 是否带符号由编译器决定：在常见的 x86 Linux 上， char 是有符号的，范围是 -128 到 127；unsigned char 的范围是 0 到 255。同一个字节 0xFF，按有符号 char 读出来是 -1，按 unsigned char 读出来是 255。 传输和处理字节时一律使用 unsigned char；需要打印数值时， 先把 char 转成 unsigned char，才不会出现负数。

例题 · 同一批字节的两种写法

下面这个程序把同一批字节分别按十进制和两位十六进制输出， 用来对照两种写法： 

#include <cstdio>

int main() {
    unsigned char bytes[5] = {0x00, 0x0F, 0x7F, 0x80, 0xFF};

    for (int i = 0; i < 5; i++) {
        printf("%3d  %02X\n", bytes[i], bytes[i]);
    }

    return 0;
}
  0  00
 15  0F
127  7F
128  80
255  FF

%3d 表示十进制至少占三位，不足三位时在前面补空格， 这样两列数字可以对齐。字节的内容没有变化，只是显示方式不同。

例题 · char 与 unsigned char

同一个值 0xFF，放进有符号的 char 和无符号的 unsigned char，打印出来不一样： 

#include <cstdio>

int main() {
    char a = (char)0xFF;
    unsigned char b = 0xFF;

    printf("char: %d\n", a);
    printf("unsigned char: %d\n", b);
    printf("转成无符号之后: %d\n", (unsigned char)a);

    return 0;
}
char: -1
unsigned char: 255
转成无符号之后: 255

最后一行先把 a 转成 unsigned char 再打印， 结果就与 b 相同。串口程序里的缓冲区、比较、校验都用 unsigned char，原因就在这里。

练习

练习 7-1

先读一个整数 n，再读 n 个 0 到 255 之间的整数。 把这些数当成字节，先输出一行「n 个字节」， 再输出一行两位十六进制，字节之间用一个空格隔开。 

5
0 15 127 128 255
5 个字节
00 0F 7F 80 FF

第一个数表示后面有几个字节，不参与输出。写完后运行一遍，答案在下面。

看答案

读入 n 之后循环 n 次，每次把数转成 unsigned char 存进 std::vector， 再用 %02X 输出。 

#include <cstdio>
#include <iostream>

int main() {
    int n = 0;
    if (!(std::cin >> n)) {
        return 1;
    }

    unsigned char bytes[100] = {0};
    for (int i = 0; i < n; i++) {
        int value = 0;
        std::cin >> value;
        bytes[i] = (unsigned char)value;
    }

    printf("%d 个字节\n", n);
    for (int i = 0; i < n; i++) {
        printf(i == 0 ? "%02X" : " %02X", bytes[i]);
    }
    printf("\n");

    return 0;
}

输出时用 i == 0 ? "%02X" : " %02X"，保证第一个字节前面 没有多余空格。若每次都先输出一个空格，行首会多出一个空格。

练习 7-2

读入一行十六进制字节，直到输入结束；输出一行「共 n 个字节」， 再把每个字节按十进制输出，字节之间用一个空格隔开。

A5 02 00 00 8C
共 5 个字节
165 2 0 0 140

读十六进制要用 std::cin >> std::hex。这个操纵符会让后面的 >> 按十六进制解释输入；它属于输入输出库的格式控制， 本课只用到这一种写法，需要了解细节时可以自行搜索「C++ std::hex」。

看答案

用 std::cin >> std::hex 把输入按十六进制读入， 读到的整数逐个转成 unsigned char 保存。 

#include <cstdio>
#include <iostream>
#include <vector>

int main() {
    std::vector<unsigned char> bytes;
    int value = 0;

    while (std::cin >> std::hex >> value) {
        bytes.push_back((unsigned char)value);
    }

    printf("共 %d 个字节\n", (int)bytes.size());
    for (int i = 0; i < (int)bytes.size(); i++) {
        printf(i == 0 ? "%d" : " %d", bytes[i]);
    }
    printf("\n");

    return 0;
}

输入结束后输出个数，再按十进制打印每个字节。十六进制的 A5 读成 165，8C 读成 140。

你现在能写什么：用 unsigned char 保存一个字节； 用 %02X 输出两位十六进制；判断 char 与 unsigned char 打印结果不同的原因。

7.2位运算

一个字节的 8 位可以分别使用。协议里经常把几个开关状态压进同一个字节， 每一位表示一个状态；也可能用某几位表示一个小范围的数。 要单独取出、设置或清除这些位，就要用位运算。

六个运算符

C++ 提供六个按位运算符：按位与 &、按位或 |、 按位异或 ^、按位取反 ~、左移 <<、 右移 >>。前四个逐位运算，规则如下：

  • &：两位都是 1 时结果为 1，否则为 0；
  • |：两位中有一个是 1 时结果为 1，否则为 0；
  • ^：两位不同时结果为 1，相同时为 0；
  • ~：把每一位取反，0 变 1，1 变 0。

左移 x << n 把 x 的每一位向左移动 n 位，右边补 0，相当于乘以 2 的 n 次方； 右移 x >> n 把每一位向右移动 n 位。 对于无符号数，右移时左边补 0。

掩码与四种操作

只关心某一位时，先造一个“只有这一位是 1”的数，称为掩码（mask）。 第 k 位的掩码是 1 << k，位从 0 开始编号， 最低位是第 0 位。有了掩码，四种常用操作可以这样写：

  • 置位：x = x | mask;，把这一位设为 1；
  • 清位：x = x & ~mask;，把这一位设为 0；
  • 翻转：x = x ^ mask;，这一位由 0 变 1、由 1 变 0；
  • 取位：(x & mask) != 0，判断这一位是不是 1。

取位时外面那对括号不能省。在 C++ 里，== 和 != 的优先级高于 &，写成 x & mask != 0 会先算 mask != 0，再算按位与，结果不是想要的意思。 位运算与比较、逻辑运算混用时，一律加括号。

协议里的标志位

真实协议里常见这样的写法：一个字节的每一位代表一个状态， 用常量给每一位起名字，读代码时就不必记数字。例如： 

const unsigned char FLAG_READY = 0x01;
const unsigned char FLAG_ARMED = 0x02;
const unsigned char FLAG_ERROR = 0x04;

用 | 把几个标志合起来，用 & 检查其中一个， 用 &= ~ 清除其中一个。这样写出的条件判断比数字直接可读。

例题 · 对一个字节做四种操作

下面的程序从 0x00 开始，依次置位、清位、翻转、取位： 

#include <cstdio>

int main() {
    unsigned char x = 0x00;

    x = x | 0x01;
    x = x | 0x08;
    printf("置位后: %02X\n", x);

    x = x & (unsigned char)~0x01;
    printf("清位后: %02X\n", x);

    x = x ^ 0x08;
    printf("翻转后: %02X\n", x);

    unsigned char m = x & 0x04;
    printf("第 2 位: %d\n", m != 0 ? 1 : 0);

    return 0;
}
置位后: 09
清位后: 08
翻转后: 00
第 2 位: 0

清位时写成 (unsigned char)~0x01：~0x01 在 int 里会得到很多高位为 1 的数，转回 unsigned char 后只保留低 8 位，才是想要的 0xFE。

例题 · 用一位表示一个状态

三个标志位分别表示就绪、武装、错误，组合之后逐项检查，再清除其中一项： 

#include <cstdio>

int main() {
    const unsigned char FLAG_READY = 0x01;
    const unsigned char FLAG_ARMED = 0x02;
    const unsigned char FLAG_ERROR = 0x04;

    unsigned char status = 0;
    status = status | FLAG_READY;
    status = status | FLAG_ERROR;
    printf("状态: %02X\n", status);

    if ((status & FLAG_READY) != 0) printf("已就绪\n");
    if ((status & FLAG_ARMED) != 0) printf("已武装\n");
    if ((status & FLAG_ERROR) != 0) printf("有错误\n");

    status = status & (unsigned char)~FLAG_ERROR;
    printf("清除错误后: %02X\n", status);

    return 0;
}
状态: 05
已就绪
有错误
清除错误后: 01

状态值是 0x05，二进制是 0000 0101： 第 0 位和第 2 位是 1，所以「已就绪」和「有错误」成立， 「已武装」不成立。

练习 7-3

读一个非负整数，数出它的二进制表示里有几个 1，输出一行。 

13
13 的二进制里有 3 个 1

每次取最低位判断，再把数右移一位，直到这个数变成 0。写完后核对答案。

看答案

每次用 value & 1 判断最低位，再把 value 右移一位，直到它变成 0。 

#include <cstdio>

int main() {
    unsigned int x = 0;
    if (scanf("%u", &x) != 1) {
        return 1;
    }

    int count = 0;
    unsigned int t = x;
    while (t != 0) {
        if ((t & 1u) != 0) {
            count++;
        }
        t = t >> 1;
    }

    printf("%u 的二进制里有 %d 个 1\n", x, count);

    return 0;
}

循环次数等于二进制位数。13 的二进制是 1101， 其中有 3 个 1。

练习 7-4

读两个 0 到 15 之间的整数，前一个作为高 4 位，后一个作为低 4 位， 拼成一个字节；再把拼好的字节拆回两个 4 位数。 

10 5
拼成 0xA5
拆开 10 5

拼接用左移与按位或，拆分用右移与掩码 0x0F。 写完后分别核对拼和拆的结果。

看答案

高 4 位移到低 4 位左边：high << 4； 再与低 4 位按位或，得到完整字节。拆分时右移 4 位取高半， 与 0x0F 按位与取低半。 

#include <cstdio>

int main() {
    int high = 0;
    int low = 0;
    if (scanf("%d %d", &high, &low) != 2) {
        return 1;
    }

    unsigned char b = (unsigned char)((high << 4) | low);

    printf("拼成 0x%02X\n", b);
    printf("拆开 %d %d\n", (b >> 4) & 0x0F, b & 0x0F);

    return 0;
}

高半是 10（0xA），低半是 5，拼成 0xA5； 拆开仍然是 10 和 5。

你现在能写什么：用 &、|、^、 ~、<<、>> 处理一个字节的各个位； 用掩码置位、清位、翻转、取位；用常量给标志位命名。

7.3打开串口

在 Linux 上，串口不是一种特殊的函数库对象，而是一个设备文件。 打开这个文件、向它写入字节、从它读出字节，就是使用串口。

串口是设备文件

常见的串口设备名有两种：主板自带的串口通常是 /dev/ttyS0、/dev/ttyS1 这一类； USB 转 TTL 模块插上后，通常出现为 /dev/ttyUSB0。 同一个模块插在不同的 USB 口上，编号可能变化，所以实际工程里会先确认设备名， 或者用固定别名指向它。

设备文件需要读权限和写权限。普通用户没有权限时， open 会失败；把用户加入 dialout 组是常见的解决办法。 这一课不展开权限配置，先按能打开的情况讲。

open 与 close

打开设备文件用 open，它在 <fcntl.h> 里声明： 

int fd = open("/dev/ttyUSB0", O_RDWR | O_NOCTTY);
if (fd == -1) {
    // 打开失败
}

O_RDWR 表示同时要读和写的权限。O_NOCTTY 表示不要把打开的设备当成这个进程的控制终端：串口设备有可能被系统当成终端， 不加这个标志时，某些终端控制信号会作用到程序上，收发数据时会受到干扰。 返回值是一个文件描述符（file descriptor），是一个非负整数； 失败时返回 -1。后面所有的读写都用这个描述符，不再用设备名。

用完以后调用 close(fd) 关闭。程序退出时系统也会回收， 但长期运行的工程应当在结束处显式关闭，避免描述符越积越多。

没有硬件：伪终端

手边没有板子时，可以用伪终端（pseudo terminal，pty）练习。 伪终端是一对互相连通的设备：主端（master）和从端（slave）。 向主端写入的字节可以从从端读出，向从端写入的字节也可以从主端读出。 从端有一个像 /dev/pts/7 这样的设备名，可以像串口一样 open、配置、读写。

创建伪终端用 posix_openpt，再用 grantpt、 unlockpt 做准备，用 ptsname 取得从端的路径。 这一组函数是 Linux 提供的，属于本课“没有硬件怎么练”的辅助手段； 正课要学的 open、read、write、 termios 与它无关。需要了解细节时可以自行搜索 「Linux 伪终端 posix_openpt」。

伪终端只模拟字节的传递，不模拟真实串口的波特率、校验位和电气信号。 用它可以把收发的程序逻辑完整跑通，但“这段程序在 115200 的板子上是否来得及” 这类问题，仍然要插上板子才能回答。

例题 · 打开伪终端的从端

下面的程序创建一对伪终端，打开从端，然后关闭： 

#include <cstdio>
#include <cstdlib>
#include <fcntl.h>
#include <unistd.h>

int main() {
    int master = posix_openpt(O_RDWR | O_NOCTTY);
    if (master == -1) {
        printf("创建伪终端失败\n");
        return 1;
    }
    if (grantpt(master) != 0 || unlockpt(master) != 0) {
        printf("准备伪终端失败\n");
        close(master);
        return 1;
    }

    const char* slave_path = ptsname(master);
    if (slave_path == nullptr) {
        printf("取得从端路径失败\n");
        close(master);
        return 1;
    }

    int slave = open(slave_path, O_RDWR | O_NOCTTY);
    if (slave == -1) {
        printf("打开从端失败\n");
        close(master);
        return 1;
    }

    printf("伪终端创建成功，从端已打开\n");

    close(slave);
    close(master);
    return 0;
}
伪终端创建成功，从端已打开

程序不打印从端的路径，也不打印文件描述符的具体数值： 这两样在不同机器、不同时刻会变化，打印出来对学习没有帮助。 真正的串口程序也是同样的结构，只是把 posix_openpt 那一套 换成 open("/dev/ttyUSB0", ...)。

/dev/null 是系统里一定存在的设备，用来确认成功分支； 第二个路径故意不存在，用来确认失败分支。 open 需要 C 风格字符串，std::string 要用 c_str() 交出内部的字符指针；这个函数本课只用到这一种写法， 需要了解细节时可以自行搜索「C++ string c_str」。

看答案

两行各读一个路径，用 path.c_str() 交给 open。 成功时关闭描述符，失败时不需要关闭。 

#include <cstdio>
#include <fcntl.h>
#include <iostream>
#include <string>
#include <unistd.h>

int main() {
    for (int i = 0; i < 2; i++) {
        std::string path;
        if (!std::getline(std::cin, path)) {
            return 1;
        }

        int fd = open(path.c_str(), O_RDWR | O_NOCTTY);
        if (fd == -1) {
            printf("打开失败 %s\n", path.c_str());

7.4配置串口

打开设备之后、收发数据之前，还要告诉系统这个串口的工作方式： 每秒传多少位、数据位有几位、有没有校验位、停止位有几位。 这些参数由 termios 结构保存，通过 tcgetattr 和 tcsetattr 读取与设置。

termios 与 8N1

termios 结构定义在 <termios.h> 里， 包含输入、输出、控制、本地四个标志字段，以及一个控制字符数组。 最常用的配置是 8N1：8 位数据位、无校验位（None）、1 位停止位。 2026 赛季 V1.3.0 协议规定的串口参数就是 8 位数据位、1 位停止位、 无校验位、无硬件流控。

对应的设置是：把 CSIZE 掩掉之后置 CS8； 清除 PARENB 表示无校验；清除 CSTOPB 表示 1 位停止位； 清除 CRTSCTS 表示不使用硬件流控； 置 CLOCAL 和 CREAD 表示忽略调制解调器控制线并允许接收。

用 cfmakeraw 关掉终端处理

串口设备默认按终端的方式工作：输入的字节先放进行缓冲区，等到换行才交给程序； 收到的字节会自动回显；输出的换行会被改写。这些处理对文本终端有用， 对二进制帧则是干扰。协议帧里任何一个字节都可能等于换行符或控制字符， 被终端处理之后内容就变了。

cfmakeraw 把结构设置成原始模式：关闭规范模式 ICANON、回显 ECHO、信号字符 ISIG、 输出处理 OPOST 等，并把 VMIN 设为 1、 VTIME 设为 0。配置二进制串口时，先调用它，再按需要改波特率 和 VMIN / VTIME，是常见做法。

波特率

波特率（baud rate）表示每秒传送多少位。8N1 每传一个字节要 10 位 （1 位起始位、8 位数据位、1 位停止位），所以 115200 波特率下每秒最多传 约 11520 个字节。2026 赛季 V1.3.0 协议的表 1-1 里， 电源管理模块与机器人之间、自定义控制器与选手端之间使用 115200， 图传发送端与机器人之间使用 921600。

设置波特率用 cfsetispeed 和 cfsetospeed， 参数是常量 B9600、B115200 这一类； B921600 是否可用取决于系统的头文件与驱动。 设置之后可以用 cfgetispeed、cfgetospeed 读回来核对。也可以在终端里用 stty -F /dev/ttyUSB0 -a 查看当前设置； 这条命令读的是真实设备，伪终端上的输出与真串口不完全相同。

伪终端会接受波特率设置并原样读回，但字节的传递速度由程序决定， 不会真的按 115200 或 921600 来。用伪终端练习时，能验证的只是 “设置项写对没有”，不能验证真实速率。

VMIN 与 VTIME

VMIN 和 VTIME 决定 read 什么时候返回。 常用的组合有三种：

  • VMIN = 1、VTIME = 0：一直等到至少读到 1 个字节；
  • VMIN = 0、VTIME = 10：最多等 1 秒 （VTIME 的单位是 0.1 秒），有数据就返回，没有数据也返回 0；
  • VMIN = n、VTIME = 0：一直等到读满 n 个字节。

普通例题用第一种，读到数据就返回；联调程序用第二种，等不到应答时 read 会返回 0，程序据此判断超时，不会一直停在那里。

7.5读写字节流

配置完成之后就可以收发了。读用 read，写用 write， 两者都在 <unistd.h> 里声明，参数都是文件描述符、 缓冲区指针和字节数。

write 的返回值

write(fd, buf, n) 尝试写入 n 个字节， 返回实际写入的字节数。返回值类型是 ssize_t：这是一个带符号的 整数类型，用来表示“字节数或 -1”。失败时返回 -1。 返回的数目可能小于 n，称为短写（short write）； 少量字节的写入通常一次完成，但工程代码应当检查返回值， 没有写完时把剩下的部分接着写。

read 的返回值

read(fd, buf, n) 最多读 n 个字节，返回实际读到的字节数。 返回值同样是 ssize_t。三种情况要分开处理：

  • 大于 0：读到了这么多字节；
  • 等于 0：在 VMIN = 0、VTIME > 0 的设置下表示等待超时； 在阻塞设置下通常表示设备已经断开；
  • 等于 -1：读取出错。若错误是信号中断（EINTR），可以重新读一次。

缓冲区用 unsigned char 数组。读到的字节数由返回值决定， 不能假设一定读满 n 个；缓冲区里超过返回值的位置没有意义。

读写不保留消息边界

串口是字节流（byte stream）：系统只保证字节的先后顺序， 不保证一次 write 对应一次 read。 发送方分三次写出的字节，接收方可能一次读到；发送方一次写出的字节， 接收方也可能分几次读到。程序不能把“一次读写”当成“一条消息”。 怎样从字节流里切出一条完整的消息，是 7.6 到 7.9 的内容。

先把全部十六进制字节读进 std::vector，再按每 3 个一组 处理；最后一组取剩余的全部字节。 

#include <cstdio>
#include <iostream>
#include <vector>

int main() {
    std::vector<unsigned char> bytes;
    int value = 0;

    while (std::cin >> std::hex >> value) {
        bytes.push_back((unsigned char)value);
    }

    int group = 1;
    for (int start = 0; start < (int)bytes.size(); start += 3) {
        int count = (int)bytes.size() - start;
        if (count > 3) {
            count = 3;
        }

        printf("第 %d 组 %d 字节:", group, count);
        for (int i = 0; i < count; i++) {
            printf(" %02X", bytes[start + i]);
        }
        printf("\n");
        group++;
    }

    return 0;
}

组号从 1 开始，每组的长度由剩余字节数与 3 的较小值决定。 最后一组只有 2 个字节，长度按实际剩余输出。

7.6一帧长什么样

串口只负责把字节按顺序送到对面，字节本身没有含义。 通信双方要交换一条消息，就得事先约定这条消息由哪些字段组成、 每个字段占几个字节、按什么顺序排列。这样一组按约定排好的字节称为一帧 （frame）。本课按 2026 赛季 V1.3.0 协议的帧格式讲； 其他赛季以当季官方协议为准。

帧的字段

这一版协议的帧由七个部分组成，依次是帧头、长度、序号、CRC8、 命令码、数据和 CRC16：

偏移 字节数 字段 内容
0 1 SOF 帧的起点，固定为 0xA5
1 2 data_length data 段的字节数，低字节在前
3 1 seq 序号，每发一帧加一，到 255 之后回到 0
4 1 CRC8 前 4 个字节的校验
5 2 cmd_id 命令码，低字节在前
7 data_length data 数据本身
7 + data_length 2 CRC16 从帧头到 data 末尾的校验，低字节在前

表中的偏移从 0 开始数，单位是字节。以帧 A 为例： 

A5 02 00 00 8C 01 00 12 34 D9 34

开头 A5 是帧头；接下来两个字节 02 00 是长度， 按低字节在前读作 2；00 是序号；8C 是 CRC8； 01 00 是命令码 0x0001；长度为 2， 所以 data 是 12 34 两个字节；最后 D9 34 是 CRC16。

长度只数 data

data_length 数的是 data 段的字节数，不包括命令码， 也不包括帧头和帧尾的其他字段。整帧长度等于 

总长度 = data_length + 9

这里的 9 是帧头 1 字节、长度 2 字节、序号 1 字节、CRC8 1 字节、 命令码 2 字节、CRC16 2 字节之和。帧 A 的 data_length 是 2， 整帧就是 11 个字节。收包时先读出长度，再据此算出还差多少字节， 不能把长度字段的值当成整帧长度。

小端

一个字段占两个字节时，就有先后顺序的问题。本课的帧统一采用小端 （little-endian）：低字节在前，高字节在后。数 0x0001 写成两个字节是 01 00，0x0102 写成 02 01，0x34D9 写成 D9 34。

V1.3.0 协议没有用文字逐条规定这两个字段的字节序；本课按协议的 结构体示例与常见实现的做法，统一按小端处理。对接其他设备时， 以对端协议或双方约定为准。把两个字节拼成一个数，写成： 

int value = low | (high << 8);

反过来，把一个数拆成两个字节，写成： 

unsigned char low = (unsigned char)(value & 0xFF);
unsigned char high = (unsigned char)((value >> 8) & 0xFF);

7.7CRC 校验

串口线上可能出现干扰：某个字节的某一位翻转，或者收发的字节数对不上。 接收方需要一个办法判断“这一帧是不是完整、正确的”。 本课的帧用两段 CRC 校验：帧头后面一个字节的 CRC8，帧尾两个字节的 CRC16。 CRC 是 cyclic redundancy check（循环冗余校验）的缩写。

为什么需要校验

长度字段能告诉接收方一帧有多长，但长度本身也可能被干扰改掉。 如果接收方无条件相信长度，一个被改大的长度会让它一直等下去， 一个被改小的长度会让它把后面帧的字节当成这一帧的内容。 校验值的作用是：收齐之后先算一遍，与帧里携带的校验值比较， 不相等就说明这一帧在传输中出了问题，应当丢掉。

本课把校验放在两个位置。CRC8 只覆盖前 4 个字节，接收方在读到长度之后、 相信这个长度之前就能先验一次；CRC16 覆盖从帧头到 data 末尾的全部内容， 在整帧收齐之后验证数据与命令是否完好。

CRC8

CRC8 的结果是一个字节。V1.3.0 协议规定的参数是：多项式 x^8 + x^5 + x^4 + 1，反射写法为 0x8C， 初值 0xFF，校验范围是帧的前 4 个字节。逐位计算的写法是：

  • 把校验值设为 0xFF；
  • 对每个字节，先把它异或进校验值；
  • 再重复 8 次：若最低位是 1，右移一位后异或 0x8C； 否则只右移一位；
  • 所有字节处理完，校验值就是一个字节的结果。

“反射”是指运算从最低位开始处理，代码里表现为右移而不是左移。 这个算法的每一步都只依赖当前校验值和当前字节，适合用循环写。

例题 · 逐位算 CRC8

下面的程序先算标准算例 "123456789" 的 CRC8， 再算帧 A 前 4 个字节的 CRC8： 

#include <cstdio>

unsigned char crc8(const unsigned char* data, int len) {
    unsigned char crc = 0xFF;
    for (int i = 0; i < len; i++) {
        crc = (unsigned char)(crc ^ data[i]);
        for (int bit = 0; bit < 8; bit++) {
            if ((crc & 0x01) != 0) {
                crc = (unsigned char)((crc >> 1) ^ 0x8C);
            } else {
                crc = (unsigned char)(crc >> 1);
            }
        }
    }
    return crc;
}

int main() {
    const unsigned char check[9] = {
        '1', '2', '3', '4', '5', '6', '7', '8', '9'
    };
    printf("算例 %02X\n", crc8(check, 9));

    const unsigned char head[4] = {0xA5, 0x02, 0x00, 0x00};
    printf("帧 A 的 CRC8 %02X\n", crc8(head, 4));

    return 0;
}
算例 0B
帧 A 的 CRC8 8C

"123456789" 是校验算法常用的标准算例，很多资料都给出 它的结果，可以用来确认自己写的参数没有弄错。帧 A 的前 4 个字节是 A5 02 00 00，算出的 8C 正好是帧里的第 5 个字节。

CRC16

CRC16 的结果是两个字节。V1.3.0 协议规定的参数是：反射多项式 0x8408，初值 0xFFFF，校验范围从帧头 SOF 一直到 data 的最后一个字节，不包括帧尾的两个校验字节。 算法与 CRC8 相同，只是校验值有 16 位，移位与异或的对象不同。

结果用 std::uint16_t 保存。它是 16 位无符号整数， 范围是 0 到 65535，定义在 <cstdint> 里， 与 unsigned short 同为 16 位无符号整数，名字更直接。 写进帧尾时低字节在前：结果 0x34D9 写成 D9 34。

例题 · 逐位算 CRC16

下面的程序算标准算例与帧 A 的 CRC16，并按低字节在前的顺序打印帧尾： 

#include <cstdint>
#include <cstdio>

std::uint16_t crc16(const unsigned char* data, int len) {
    std::uint16_t crc = 0xFFFF;
    for (int i = 0; i < len; i++) {
        crc = (std::uint16_t)(crc ^ data[i]);
        for (int bit = 0; bit < 8; bit++) {
            if ((crc & 0x0001) != 0) {
                crc = (std::uint16_t)((crc >> 1) ^ 0x8408);
            } else {
                crc = (std::uint16_t)(crc >> 1);
            }
        }
    }
    return crc;
}

int main() {
    const unsigned char check[9] = {
        '1', '2', '3', '4', '5', '6', '7', '8', '9'
    };
    printf("算例 %04X\n", crc16(check, 9));

    const unsigned char body[9] = {
        0xA5, 0x02, 0x00, 0x00, 0x8C, 0x01, 0x00, 0x12, 0x34
    };
    std::uint16_t value = crc16(body, 9);
    printf("帧 A 的 CRC16 %04X\n", value);
    printf("低字节在前 %02X %02X\n", value & 0xFF, (value >> 8) & 0xFF);

    return 0;
}

帧 A 的 CRC16 34D9
低字节在前 D9 34

帧 A 参与 CRC16 计算的是前 9 个字节：从 A5 到 data 的 34，不含最后两个字节 D9 34。 算出的数值是 0x34D9，按低字节在前写出来正好与帧尾一致。

查表与算例

逐位算法每处理一个字节要做 8 次循环。真实工程常用查表法： 把一个字节的 256 种取值对应的结果提前算好，运行时每字节查一次表。 表可以由逐位算法生成，也可以直接写在源文件里；两种做法的结果相同。 本课用逐位算法，因为它把每一步都写在代码里，便于核对参数； 课程中的帧只有十几个字节，逐位计算的时间可以忽略。

两段校验的分工可以用帧 B 的坏版本来验证。帧 B 是 A5 02 00 01 D2 02 00 56 78 8B A8，把 data 的第一个字节 78 改成 79，得到 A5 02 00 01 D2 02 00 56 79 8B A8。 帧头四个字节没有变化，CRC8 仍然是 D2，所以 CRC8 通过； 参与 CRC16 的字节变了，CRC16 就不再等于帧尾的 8B A8。 接收方据此丢掉这一帧。

前两个数是序号与命令码，用十进制读；后面的 56 78 是 data 的十六进制字节。CRC8 在长度与序号写完之后计算， 因为它只覆盖前 4 个字节；CRC16 在 data 全部写入之后计算。

看答案

7.8粘包与半包

前面的例题都是“写一次、读一次”，读写次数恰好对上。 真实串口不会这样配合：发送方连续发几帧，接收方可能一次读到两帧； 发送方发了一帧，接收方也可能先读到半帧，过一会儿才读到剩下的一半。 这两种情况分别称为粘包与半包。

字节流没有消息边界

read 返回多少字节，取决于内核缓冲区里当时有多少数据， 与发送方调用了几次 write 没有对应关系。发送方分两次写出的 11 个字节，接收方可能一次读全；发送方一次写出的 22 个字节， 接收方也可能分两次读到。串口只保证字节的先后顺序， 不保留“哪几个字节属于同一次写”的信息。

所以接收程序不能把一次 read 当成一条消息。正确的做法是 准备一个接收缓冲区，把每次读到的字节接在尾部，再反复检查缓冲区里 有没有完整的一帧；有就取走，没有就继续等下一批字节。

接收缓冲区

缓冲区用 std::vector<unsigned char>。每读到一批字节， 就全部追加到缓冲区尾部，一个也不丢： 

std::vector<unsigned char> buf;
// 读到 n 个字节之后
buf.insert(buf.end(), chunk, chunk + n);

处理过的字节才从缓冲区头部删除。取出一帧时，删除的是整帧的 total 个字节；丢弃一个无效字节时，只删除头部的 1 个字节。 缓冲区里尚未处理的字节必须保留，下一次读到的字节接在它们后面。

取帧的顺序

从缓冲区取一帧，按下面的顺序检查：

  1. 缓冲区首字节不是 0xA5：丢掉这 1 个字节，继续检查；
  2. 缓冲区不足 5 个字节：还无法验证 CRC8，返回等待；
  3. 用前 4 个字节算 CRC8，与第 5 个字节比较：不相等就丢掉首字节，继续检查；
  4. CRC8 通过后，才读 data_length，算出整帧长度 data_length + 9；
  5. 缓冲区不足整帧长度：返回等待；
  6. 收齐后算 CRC16，与帧尾两个字节比较：不相等就丢掉首字节，继续检查；
  7. 两项校验都通过：记下命令与数据，从缓冲区删除整帧，返回“取到一帧”。

第 3 步必须在第 4 步之前。CRC8 覆盖的正好是帧头和长度字段； 先验 CRC8，才能确认这个 0xA5 与后面的长度不是干扰产生的。 如果先信长度，一个假的帧头配上很大的长度，会让接收方一直等下去。 校验失败时丢 1 个字节而不是整帧，也是同样的考虑：在确认这是一帧之前， “整帧长度”并不可信；丢 1 个字节后重新找帧头，才能从错位中恢复。

7.9状态机收包

上一课的取帧函数已经把收包过程写成了一个循环。把循环内部看作几个 依次推进的阶段，就是收包状态机（state machine）：每收到一批字节， 状态向前推进；某个检查不通过，就退回找帧头的状态。 这一课把各阶段整理清楚，并写出一个持续收包的程序。

五个状态

接收方的处理可以分为五个状态：

  1. 找帧头。缓冲区首字节不是 0xA5 时，丢掉这一个字节， 继续找；
  2. 验 CRC8。缓冲区至少有 5 个字节时，用前 4 个字节算 CRC8， 与第 5 个字节比较；失败就丢掉首字节，回到找帧头；
  3. 读长度。CRC8 通过后，读出 data_length， 算出整帧长度；
  4. 等收齐。缓冲区不足整帧长度时，保留全部字节，等待下一次读；
  5. 验 CRC16。收齐后计算 CRC16，与帧尾比较；通过就交出这一帧， 并从缓冲区删除整帧。

代码里不必为每个状态写一个 switch 分支。上一课的 take_frame 用一个 while 循环加几个 if 就完成了同样的顺序：循环负责“找帧头”和“失败后重试”， 几个 if 依次对应 CRC8、长度、收齐与 CRC16。

失败时丢一个字节

校验失败时只丢 1 个字节，而不是丢掉“整帧”。原因是：在 CRC8 通过之前， 这个 0xA5 和它后面的长度都还没有被确认，按这个长度丢字节 可能把下一帧的开头一起丢掉；在 CRC16 失败时，帧内的长度虽然通过了 CRC8，但内容已经损坏，按损坏的长度删除也可能误删后面的好帧。 丢 1 个字节后重新扫描，最坏情况也只是多扫描几个字节，不会漏掉后面的帧。

长度上限

还要给整帧长度设一个上限。如果干扰恰好造出一个 0xA5， 而它后面的两个字节又恰好通过了 CRC8，读出的长度可能很大； 接收方会一直等这么多字节，正常的数据都排在后面处理不了。 本课练习里的帧最长 11 个字节，把上限定为 100 字节： 超过上限就按坏帧处理，丢 1 个字节重新找帧头。 真实工程按协议规定的最大数据长度确定这个上限。

例题 · 带垃圾与坏帧的字节流

下面的程序把一段字节逐个送入缓冲区：开头两个字节是无效字节， 然后是帧 A、一个校验被破坏的帧 B、帧 C。每送入一个字节就尝试取帧：

#include <cstdio>
#include <vector>

bool check_crc8(const std::vector<unsigned char>& buf) {
    unsigned char crc = 0xFF;
    for (int i = 0; i < 4; i++) {
        crc = (unsigned char)(crc ^ buf[i]);
        for (int bit = 0; bit < 8; bit++) {
            if ((crc & 0x01) != 0) {
                crc = (unsigned char)((crc >> 1) ^ 0x8C);
            } else {
                crc = (unsigned char)(crc >> 1);
            }
        }
    }
    return crc == buf[4];
}

bool check_crc16(const std::vector<unsigned char>& buf, int total) {
    std::uint16_t crc = 0xFFFF;
    for (int i = 0; i < total - 2; i++) {
        crc = (std::uint16_t)(crc ^ buf[i]);
        for (int bit = 0; bit < 8; bit++) {
            if ((crc & 0x0001) != 0) {
                crc = (std::uint16_t)((crc >> 1) ^ 0x8408);
            } else {
                crc = (std::uint16_t)(crc >> 1);
            }
        }
    }
    return (crc & 0xFF) == buf[total - 2] && (crc >> 8) == buf[total - 1];
}

// 从缓冲区取出一帧。校验不过时记一次坏帧，丢掉一个字节继续找。
bool take_frame(std::vector<unsigned char>& buf, int& cmd, int& bad) {
    while (!buf.empty()) {
        if (buf[0] != 0xA5) {
            buf.erase(buf.begin());
            continue;
        }
        if ((int)buf.size() < 5) {
            return false;
        }
        if (!check_crc8(buf)) {
            bad++;
            buf.erase(buf.begin());
            continue;
        }

        int data_length = buf[1] | (buf[2] << 8);
        int total = data_length + 9;
        if (total > 100) {
            bad++;
            buf.erase(buf.begin());
            continue;
        }
        if ((int)buf.size() < total) {
            return false;
        }
        if (!check_crc16(buf, total)) {
            bad++;
            buf.erase(buf.begin());
            continue;
        }

        cmd = buf[5] | (buf[6] << 8);
        buf.erase(buf.begin(), buf.begin() + total);
        return true;
    }
    return false;
}

int main() {

        0x00, 0xFF,
        0xA5, 0x02, 0x00, 0x00, 0x8C, 0x01, 0x00, 0x12, 0x34, 0xD9, 0x34,
        0xA5, 0x02, 0x00, 0x01, 0xD2, 0x02, 0x00, 0x56, 0x79, 0x8B, 0xA8,
        0xA5, 0x02, 0x00, 0x02, 0x30, 0x03, 0x00, 0x9A, 0xBC, 0x01, 0x66

    int cmd = 0;
    int bad = 0;

没有硬件也能联调

收包逻辑可以用字节数组测试，发送与等待应答的部分还需要一个“对面”。 没有板子时，可以用伪终端加一个 Python 模拟板把整条链路跑通。 模拟板创建一对伪终端，扮演串口的另一端：读 C++ 程序发来的请求帧， 验两段 CRC，然后回一帧应答，并且故意分两批写出（先 3 个字节， 隔 0.05 秒再写 8 个字节），让接收方真的遇到半包。

联调程序用 main 的两个参数接收设备路径：argc 是参数的个数，argv[0] 是程序名，argv[1] 是第一个参数。 本课只用 argv[1] 取得模拟板给出的从端路径； 需要了解细节时可以自行搜索「C++ main 参数 argc argv」。 程序用 VMIN = 0、VTIME = 50：一次 read 最多等 5 秒（VTIME 的单位是 0.1 秒）， 等不到数据就返回 0，程序据此打印超时并退出，不会一直停在那里。

程序把收到的每个字节追加到缓冲区，再循环取帧。应答帧 B 被模拟板分成 3 个字节与 8 个字节两批写出，实际的 read 可能一次拿到全部 11 个字节，也可能先拿到 3 个、再拿到 8 个；两种情况都由同一个收包循环 处理。收到命令 0x0002 后打印两行并结束。

这份程序与模拟板放在同一个目录里，目录中还有一份 构建.txt， 里面是编译与运行两条命令： 

g++ -std=c++17 -Wall -o demo main.cpp

也可以手动运行：先执行 python3 fake_board.py， 它会打印一个从端路径并等待最多 60 秒；在另一个终端里执行 ./demo 加上那个路径。手动模式会把设备路径打印出来， 自动模式则不打印，避免把每次不同的路径写进程序的输出。

设备路径要用模拟板打印的那一个，不要把自己终端所在的 /dev/pts/N 传进去：程序会把它设成原始模式， Ctrl+C 不再产生中断。若终端已经进入原始模式， 在该终端执行 stty sane 恢复。

伪终端只传递字节。它接受波特率设置，但不会按 115200 或 921600 的速度 限制发送；它也不模拟校验位与电气信号。这一节能验证的是收发流程、 组帧、校验、半包处理与超时分支；真实波特率下的时序、 电气层的连接质量，仍然要插上板子才能确认。 Windows 上的串口是 COM 口，打开与配置用另一套 API，本课的代码按 Linux 写。

7.10一个简易的裁判系统

前面几节的程序把收到的字节打印成十六进制。真实的串口对面不是终端， 而是另一块板子：它收到帧，先验 CRC，再把 data 段按字段拆开， 显示成坐标、血量、弹量这样的数值。机器人比赛里，承担这个角色的是 裁判系统（referee system）。这一节给出一个简易的接收端， 把前面写的帧真正显示出来，便于观察发送的字节与字段之间的对应关系。

接收端做什么

接收端的工作可以分成四步：从字节流里取出完整的帧；验 CRC8 与 CRC16； 按命令码解释 data 段；把结果写到界面上。前两步与上一节的收包循环相同， 后两步由每条命令的数据格式决定。

这一节的工具是一个 Python 程序。它用伪终端或真实串口接收数据， 在本机启动一个网页，把收到的内容显示出来。网页每 0.25 秒向本地服务 取一次状态（轮询，polling），数据用 JSON（一种文本数据格式）传递。 Python、HTTP 与页面脚本都不是本课的内容，这里只说明它们的作用； 需要了解时可以自行搜索「Python http.server」「JavaScript fetch」。 工具只在本机监听，不连接外部网络。

页面上的四块内容

页面从上到下分四块：

  • 接收信息总览：已收帧数、坏帧数、已收字节数与最后收帧时间， 以及当前使用的设备。坏帧数包括 CRC8 错误、CRC16 错误与长度异常。
  • 机器人状态：每个机器人一行，显示 X、Y、HP、弹量与最近更新时间。 还没有收到过数据的机器人显示“等待数据”。
  • 接收数据包：每条命令一张卡片。卡片上方是按字段着色的字节， 颜色与字段的对应关系写在图例里；下方是长度、seq、命令、数据与 两段 CRC 的数值。多字节字段已经按小端拼好，直接显示十进制结果。
  • 日志（log）：最近 10 条记录，包含时间、命令、seq、长度、 校验结果与原始字节。校验失败的帧也记在这里，便于对照。

为了让页面上的数值有意义，这一节给三条命令规定了简单的数据格式。 它们和前面的例题一样，是课程自己编的，不对应任何官方业务命令； 帧格式与两段 CRC 仍按 2026 赛季 V1.3.0 协议。

命令含义data 段长度

有板子时，可以用 --device 指定真实串口，用 --baud 指定波特率： 

python3 referee_system.py --device /dev/ttyUSB0 --baud 115200

这时发送端要在另一块板子上运行。两个程序不能打开同一个串口设备。

边界

  • 这一节的命令码与数据格式是课程自编的；真实裁判系统的命令与字段 以当季官方协议为准。
  • 伪终端不按真实波特率走，也不模拟校验位与电气信号；它验证的是 收包、校验与显示。真实波特率下的时序与连接质量要插上板子才能确认。
  • 这个接收端只接收，不发送。真实裁判系统还会向机器人发送比赛状态、 易伤标志、飞镖目标等数据。
  • 页面只监听 127.0.0.1，其他机器访问不到，也不联网。

你现在能写什么：把收包循环接到一个显示端；按命令码解释 data 段； 用字段宽度、字节序与 CRC 校验一帧数据；在没有硬件时用伪终端观察 从发送到显示的完整过程。
